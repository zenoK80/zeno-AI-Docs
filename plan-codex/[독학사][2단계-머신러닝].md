# 독학사 2단계 머신러닝

## 초보 설명과 문제 설계 기준

- 본편은 독자가 이 과목을 처음 본다고 가정한다. 처음 나오는 핵심 용어는 `먼저 알아둘 말`에서 일상어로 풀고, 본문에서는 기본 개념과 이해에 필요한 주변 개념을 함께 설명한다.
- 약어·기호·명령어·수식은 뜻과 역할을 먼저 설명한 뒤 사용한다. 독자가 모르는 단어를 다시 검색해야만 다음 문장을 이해할 수 있게 쓰지 않는다.
- 비슷한 용어는 차이와 경계를 표·반례·사례로 구분하고, 설명은 `왜 필요한가 -> 쉬운 뜻 -> 정식 용어 -> 예시 -> 시험 적용` 순서를 우선한다.
- 복습편은 최소 5개의 4지선다 문제로 구성한다. 각 문제는 정답이 하나인 네 선택지와 별도의 `정답 보기`, `해설 보기` Collapse를 갖는다.
- 해설에는 정답 근거와 모든 오답 선지가 틀린 이유를 쓴다. 계산·실기 주제는 직접 풀거나 수행하는 적용 문제를 1개 이상 추가한다.
- 본편의 설명만으로 같은 번호의 복습편을 풀 수 있는지 본편과 복습편을 서로 대조해 검수한다.

## 본편과 복습 문서 구성

- 목차의 일반 본편 `NN_slug.mdx`마다 바로 뒤에 `NN_slug-review.mdx`를 한 쌍으로 작성한다.
- 본편은 개념과 예제 중심, 복습편은 회상 질문·퀴즈·실습·오류 진단·정답 해설 중심으로 구성한다.
- 복습편은 10~15분 안에 끝낼 수 있게 만들고 `_meta.js`에서도 본편 바로 다음에 배치한다.
- 기출문제, 실전 모의고사, 종합 프로젝트, 정답·해설 전용 문서, 시험 직전 체크리스트에는 별도 복습편을 만들지 않는다.

## 시리즈 설계

- **정체성**: 모델 이름 암기보다 데이터·목표·손실·평가의 연결을 이해하는 과정이다.
- **완주 목표**: 문제 유형에 맞는 학습 방법과 평가 지표를 고르고 과적합·데이터 누수를 설명한다.
- **일관된 예제**: 주택 가격 회귀와 고객 이탈 분류를 같은 데이터 흐름으로 비교한다.
- **작성 원칙**: 직관 -> 최소 수식 -> 작은 계산 -> 모델 비교 -> 오답 선지 분석 순서를 따른다.

## 독자 기준

- 머신러닝 개념과 주요 알고리즘을 시험 기준으로 공부하는 학습자
- 초보자가 혼자 읽고 실습하거나 문제 풀이로 연결할 수 있게 쓴다.
- 너무 길게 늘이지 않고, 핵심 개념과 시험/실무에서 쓰이는 포인트를 우선한다.

## 공통 작성 지침

- MDX 상단 frontmatter는 'title', 'description'만 넣는다.
- 본문 제목은 '##'부터 시작한다. '#'은 쓰지 않는다.
- 설명 순서는 가능하면 '개념 -> 왜 필요한가 -> 예시 -> 흔한 실수 -> 정리'로 잡는다.
- 처음 나오는 용어는 한 줄로 정의한다.
- 공식이나 명령어는 외우기 전에 의미를 먼저 설명한다.
- 실습이 가능한 주제는 작은 예제와 직접 확인할 수 있는 절차를 넣는다.
- 마지막에는 항상 '## 참고 자료'를 두고 관련 웹사이트를 링크로 정리한다.

## Nextra 사용 지침

- import 없이 전역 컴포넌트를 사용한다.
- 'Callout': 중요한 정의, 시험 포인트, 주의사항에 사용한다.
- 'Steps': 설치, 실습, 풀이 절차처럼 순서가 중요한 곳에 사용한다.
- 'Tabs': 비교 예시나 여러 풀이/환경을 나눌 때 사용한다.
- 'FileTree': 폴더 구조나 파일 배치를 설명할 때 사용한다.
- 'Cards': 관련 문서 묶음이나 다음 학습 경로를 보여줄 때 사용한다.
- 'Table': 용어 비교, 명령어 비교, 공식 비교에 사용한다.
- 컴포넌트를 과하게 쓰지 말고 읽기 흐름이 좋아질 때만 쓴다.

## _meta.js 규칙

- 새 MDX를 만들면 같은 폴더의 '_meta.js'에 반드시 추가한다.
- 새 하위 분류 폴더를 만들면 해당 폴더에도 '_meta.js'를 만든다.
- 루트 메뉴는 실제 Nextra 구조와 맞춘다. 예: '자격증 -> SQLD', '독학사 -> 1단계 기초통계학'.
- 없는 파일을 가리키는 오래된 meta 항목은 남기지 않는다.
