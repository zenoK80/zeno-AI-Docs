  **이번 문서의 목표:** SPA(싱글 페이지 앱)가 페이지 새로고침 없이 주소창을 바꾸는 원리를 이해하고, URL을 안전하게 다룰 수 있습니다.
</Callout>

## 왜 History API가 필요한가?

일반적으로 브라우저는 주소가 바뀌면 서버에 새 페이지를 요청하고 화면을 통째로 다시 그립니다. 하지만 React 같은 SPA는 페이지를 새로고침하지 않고 **JavaScript가 화면 일부만 바꾸면서, 주소창의 URL도 함께 바꾸고 싶어합니다.** 이때 사용하는 것이 **History API**입니다.

## pushState — 새로고침 없이 주소 바꾸기

```js
console.log(location.pathname)  // 예: '/home'

history.pushState({ page: 'about' }, '', '/about')
// 1. 주소창이 '/about'으로 바뀜(새로고침 없이!)
// 2. 브라우저의 방문 기록에 새 항목이 추가됨
// 3. 서버로는 아무 요청도 보내지 않음

console.log(location.pathname)  // '/about' — 바뀌었지만 페이지는 새로고침 안 됨
```

`pushState(state, title, url)`의 세 인수:
- `state`: 이 기록과 함께 저장할 임의의 데이터(나중에 popstate에서 꺼낼 수 있음)
- `title`: 대부분의 브라우저가 무시함(관례상 빈 문자열 전달)
- `url`: 바꿀 새 주소

## replaceState — 기록을 남기지 않고 주소만 교체

```js
history.replaceState({ page: 'login' }, '', '/login')
// pushState와 달리 새 기록을 "추가"하지 않고 현재 기록을 "덮어씀"
// 뒤로가기를 눌러도 이 상태로는 돌아오지 않음
```

리다이렉트처럼 "뒤로가기 버튼을 눌렀을 때 이 페이지로 돌아오면 안 되는" 상황에 사용합니다.

<Callout type="warning">
  `pushState`로 주소를 바꾸는 것 자체는 **`popstate` 이벤트를 발생시키지 않습니다.** `popstate`는 오직 사용자가 브라우저의 뒤로가기/앞으로가기 버튼(또는 `history.back()` 등)을 눌렀을 때만 발생합니다. React Router 같은 라이브러리가 이 두 가지 경우를 모두 처리해 화면을 갱신해주는 이유가 여기에 있습니다.
</Callout>

## URL 객체 — 주소를 안전하게 분해·조립하기

문자열을 직접 자르고 합치는 대신, `URL` 객체를 쓰면 실수 없이 주소를 다룰 수 있습니다.

```js
const url = new URL('https://shop.example.com:8080/products?category=shoes&page=2#reviews')

console.log(url.protocol)   // 'https:'
console.log(url.hostname)   // 'shop.example.com'
console.log(url.port)       // '8080'
console.log(url.pathname)   // '/products'
console.log(url.search)     // '?category=shoes&page=2'
console.log(url.hash)       // '#reviews'
```

## URLSearchParams — 쿼리 파라미터 다루기

```js
const params = new URLSearchParams(url.search)

console.log(params.get('category'))   // 'shoes'
console.log(params.get('page'))       // '2'

params.set('page', '3')       // 값 변경
params.append('sort', 'price') // 새 파라미터 추가
params.delete('category')     // 파라미터 제거

console.log(params.toString())  // 'page=3&sort=price'

// 모든 파라미터 순회
for (const [key, value] of params) {
  console.log(key, value)
}
```

`URLSearchParams`는 특수문자를 자동으로 URL 인코딩/디코딩해줘서, `?name=철수 김`처럼 공백이 포함된 값을 직접 `encodeURIComponent`로 처리할 필요가 없습니다.

## 실전 패턴 — 현재 페이지의 쿼리 파라미터 읽기

```js
// 현재 페이지 주소: https://example.com/search?q=자바스크립트&page=1
const params = new URLSearchParams(window.location.search)
console.log(params.get('q'))     // '자바스크립트'
console.log(params.get('page'))  // '1'
```

## 핵심 정리

- pushState는 새 기록을 추가하며 새로고침 없이 주소를 바꾸고, replaceState는 현재 기록을 덮어쓴다.
- popstate는 사용자가 뒤로가기/앞으로가기를 누를 때만 발생하며, pushState 호출 자체로는 발생하지 않는다.
- URL 객체로 주소를 protocol, hostname, pathname 등으로 안전하게 분해할 수 있다.
- URLSearchParams로 쿼리 파라미터를 get/set/append/delete하며 자동으로 URL 인코딩을 처리한다.
