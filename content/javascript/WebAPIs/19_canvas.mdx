## Canvas 기본 설정

```html
<canvas id="canvas" width="600" height="400"></canvas>
```

```js
const canvas = document.querySelector('#canvas')
const ctx = canvas.getContext('2d')  // 2D 렌더링 컨텍스트 — 그리기 명령을 담은 객체
```

canvas 태그 자체는 빈 사각형일 뿐입니다. `getContext('2d')`로 얻은 **컨텍스트 객체**의 메서드를 호출해야 실제로 그림이 그려집니다.

## 경로(Path)와 원 그리기

<CodePlayground
  template="vanilla"
  activeFile="/index.js"
  label="경로와 원 그리기 실습"
  files={{
    '/index.html': `<canvas id="canvas" width="600" height="300"></canvas>
<script src="/index.js"></script>`,
    '/index.js': `const canvas = document.querySelector('#canvas')
const ctx = canvas.getContext('2d')

// 삼각형 경로
ctx.beginPath()
ctx.moveTo(100, 200)     // 펜을 시작 위치로 이동(선은 안 그려짐)
ctx.lineTo(200, 100)     // 직선을 그으며 이동
ctx.lineTo(300, 200)
ctx.closePath()          // 시작점으로 되돌아가는 선을 자동으로 그림
ctx.fillStyle = 'coral'
ctx.fill()
ctx.strokeStyle = 'darkred'
ctx.stroke()

// 원(arc)
ctx.beginPath()
ctx.arc(450, 150, 80, 0, Math.PI * 2)  // 중심(450,150), 반지름 80, 0~360도
ctx.fillStyle = 'gold'
ctx.fill()`,
  }}
/>

**경로 그리기의 3단계**: `beginPath()`로 새 경로 시작 → `moveTo`/`lineTo`/`arc`로 경로 정의 → `fill()` 또는 `stroke()`로 실제 그리기. `beginPath()`를 빠뜨리면 이전 경로에 계속 이어붙여 그려집니다.

## 좌표계 — Canvas는 y축이 반대다

일반 수학 좌표계와 달리, Canvas는 **왼쪽 위가 원점**(0, 0)**이고 y값이 커질수록 아래로** 내려갑니다.

```js
ctx.fillRect(0, 0, 50, 50)      // 캔버스의 왼쪽 위 모서리
ctx.fillRect(0, canvas.height - 50, 50, 50)  // 캔버스의 왼쪽 아래 모서리
```

## 변환(Transform) — translate, rotate, scale

```js
ctx.save()  // 현재 상태(색상, 변환 등)를 스택에 저장

ctx.translate(canvas.width / 2, canvas.height / 2)  // 원점을 캔버스 중앙으로 이동
ctx.rotate(Math.PI / 4)   // 45도(라디안) 회전
ctx.scale(1.5, 1.5)       // 1.5배 확대

ctx.fillRect(-50, -50, 100, 100)  // 이동된 원점 기준으로 그림

ctx.restore()  // save() 시점의 상태로 되돌림
```

<Callout type="warning">
  `translate`, `rotate`, `scale`은 캔버스 전체의 **좌표계 자체**를 바꾸는 명령입니다. 한 번 호출하면 그 이후의 모든 그리기가 영향을 받습니다. `save()`로 현재 상태를 저장하고 `restore()`로 되돌리는 습관을 들이지 않으면, 이전 변환이 계속 누적되어 그림이 점점 이상한 위치에 그려지는 버그가 생깁니다.
</Callout>

## 텍스트와 그라디언트

```js
ctx.font = 'bold 32px sans-serif'
ctx.fillStyle = 'black'
ctx.textAlign = 'center'
ctx.fillText('Hello Canvas!', canvas.width / 2, canvas.height / 2)

const gradient = ctx.createLinearGradient(0, 0, 600, 0)
gradient.addColorStop(0, 'red')
gradient.addColorStop(0.5, 'yellow')
gradient.addColorStop(1, 'blue')
ctx.fillStyle = gradient
ctx.fillRect(0, 0, 600, 100)
```

## canvas 속성 vs CSS 크기 — 흔한 함정

```html
<canvas id="c" width="300" height="200" style="width: 600px; height: 400px;"></canvas>
```

<Callout type="warning">
  `width`/`height` **속성**(HTML attribute)은 캔버스의 **내부 해상도**(실제 그림을 그릴 수 있는 픽셀 격자 크기)를 결정합니다. CSS의 `width`/`height`는 화면에 **표시되는 크기**만 결정합니다. 두 값이 다르면(위 예시처럼) 내부 해상도가 낮은 그림이 억지로 늘어나 흐릿하게 보입니다. 항상 두 값을 일치시키거나, 고해상도 화면을 위해 의도적으로 속성값을 CSS보다 크게(예: `devicePixelRatio` 배수로) 설정해야 합니다.
</Callout>

## 핵심 정리

- getContext('2d')로 얻은 컨텍스트 객체의 메서드로 실제 그리기가 이루어진다.
- beginPath()로 새 경로를 시작하지 않으면 이전 경로에 계속 이어붙여 그려진다.
- Canvas의 y축은 아래로 갈수록 커지며, (0,0)은 왼쪽 위다.
- translate/rotate/scale은 좌표계 자체를 바꾸므로, save()/restore()로 상태를 안전하게 관리해야 한다.
- canvas의 width/height 속성(내부 해상도)과 CSS 크기(표시 크기)는 별개이며, 다르면 흐릿하게 보인다.
