## 왜 Worker가 필요한가?

ECMAScript 30번 문서에서 배운 대로, 자바스크립트는 **싱글 스레드**입니다. 무거운 계산(수백만 개의 데이터 처리 등)이 메인 스레드에서 실행되면, 그 계산이 끝날 때까지 화면이 멈추고 클릭도 반응하지 않습니다.

```js
// 이 계산이 5초 걸린다면, 그동안 화면 전체가 얼어붙는다
function heavyCalculation() {
  let result = 0
  for (let i = 0; i < 10_000_000_000; i++) {
    result += i
  }
  return result
}
```

**Web Worker**는 이런 무거운 작업을 **메인 스레드와 별도의 스레드**에서 실행해, 계산이 오래 걸려도 화면(UI)은 계속 반응하게 해줍니다.

## Web Worker 기본 사용법

```js
// main.js — 워커 생성
const worker = new Worker('/worker.js')

worker.postMessage({ type: 'calculate', data: [1, 2, 3, 4, 5] })  // 워커에 메시지 전송

worker.onmessage = (event) => {
  console.log('결과:', event.data)  // 워커로부터 결과 수신
}

worker.onerror = (error) => console.error('워커 오류:', error.message)
worker.terminate()  // 워커 종료
```

```js
// worker.js — 별도 파일, 별도 스레드에서 실행됨
self.onmessage = (event) => {
  const { type, data } = event.data
  if (type === 'calculate') {
    const result = data.reduce((sum, n) => sum + n, 0)
    self.postMessage(result)  // 결과를 메인 스레드로 전송
  }
}
```

메인 스레드와 워커는 **직접 변수를 공유하지 않고**, `postMessage()`로 메시지를 주고받으며 통신합니다. 이 통신 방식은 데이터를 복사해서 전달하므로(구조화된 복제 알고리즘), 메인 스레드의 변수를 워커가 직접 수정하는 일은 일어나지 않습니다.

## Service Worker 개요

**Service Worker**는 Web Worker와 이름은 비슷하지만 목적이 완전히 다릅니다. 브라우저와 네트워크 **사이에 위치하는 프록시** 역할을 하며, 오프라인 지원, 캐싱, 푸시 알림 같은 기능의 기반이 됩니다.

## Service Worker 등록

```js
// main.js
if ('serviceWorker' in navigator) {
  window.addEventListener('load', async () => {
    try {
      const registration = await navigator.serviceWorker.register('/sw.js')
      console.log('SW 등록됨:', registration.scope)
    } catch (err) {
      console.error('SW 등록 실패:', err)
    }
  })
}
```

## Service Worker 파일 — 캐시 우선 전략

```js
// sw.js
const CACHE_NAME = 'my-app-v1'
const CACHED_URLS = ['/', '/index.html', '/style.css', '/app.js']

// 설치 단계: 필요한 리소스를 미리 캐시에 저장
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then(cache => cache.addAll(CACHED_URLS))
  )
})

// 활성화 단계: 이전 버전의 캐시 정리
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then(keys =>
      Promise.all(keys.filter(key => key !== CACHE_NAME).map(key => caches.delete(key)))
    )
  )
})

// 네트워크 요청 가로채기: 캐시에 있으면 캐시를, 없으면 네트워크를 사용
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then(cached => cached || fetch(event.request))
  )
})
```

이 "캐시 우선(Cache First)" 전략 덕분에, 사용자가 인터넷 연결 없이 페이지에 다시 접속해도 캐시된 리소스로 기본적인 화면이 표시됩니다. 이것이 **PWA**(Progressive Web App, 프로그레시브 웹 앱)의 오프라인 지원 핵심 기술입니다.

<Callout type="warning">
  Service Worker는 `https://`(또는 `localhost`) 환경에서만 등록됩니다. 네트워크 요청을 가로채는 강력한 권한을 가지므로, 중간자 공격을 방지하기 위한 보안 요구사항입니다.
</Callout>

## 핵심 정리

- Web Worker는 무거운 계산을 메인 스레드와 별도로 처리해 화면이 멈추지 않게 한다.
- 메인 스레드와 워커는 postMessage()로 메시지를 주고받으며 통신하고, 변수를 직접 공유하지 않는다.
- Web Worker는 DOM에 직접 접근할 수 없어, 계산 결과를 메인 스레드로 보내 DOM 업데이트를 위임해야 한다.
- Service Worker는 네트워크 요청을 가로채는 프록시로, 캐싱과 오프라인 지원의 기반이 된다.
- Service Worker는 HTTPS(또는 localhost) 환경에서만 등록 가능하다.
