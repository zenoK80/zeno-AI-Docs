## 이벤트 등록 — addEventListener

```js
const button = document.querySelector('button')

function handleClick(event) {
  console.log('클릭됨', event.target)
}

button.addEventListener('click', handleClick)
button.removeEventListener('click', handleClick)  // 제거 — 반드시 같은 함수 참조가 필요
```

<Callout type="warning">
  `removeEventListener`로 리스너를 제거하려면 `addEventListener`에 넘긴 것과 **정확히 같은 함수**를 넘겨야 합니다. `button.addEventListener('click', () => {})`처럼 익명 함수로 등록하면, 나중에 그 함수를 다시 참조할 방법이 없어 제거할 수 없습니다.
</Callout>

## 이벤트 객체 살펴보기

```js
button.addEventListener('click', (event) => {
  console.log(event.type)            // 'click'
  console.log(event.target)          // 실제로 이벤트가 발생한 요소
  console.log(event.currentTarget)   // 리스너가 등록된 요소(target과 다를 수 있음)
  console.log(event.clientX, event.clientY)  // 클릭한 화면 좌표

  event.preventDefault()   // 기본 동작 취소(링크 이동, 폼 제출 등)
  event.stopPropagation()  // 버블링 중단
})
```

## 이벤트 전파 — 캡처링, 타겟, 버블링

이벤트는 발생하는 순간 한 지점에만 머무르지 않고, DOM 트리를 따라 **세 단계**로 전파됩니다.

<Steps>
### 캡처링 단계 (내려감)
최상위(document)에서 실제 이벤트가 발생한 요소를 향해 내려간다.

### 타겟 단계
이벤트가 실제로 발생한 요소에서 처리된다.

### 버블링 단계 (올라감)
이벤트가 발생한 요소에서 다시 최상위(document)까지 올라간다.
</Steps>

    '/index.js': `const parent = document.querySelector('.parent')
const child = document.querySelector('.child')

// 버블링 단계 처리(기본값)
parent.addEventListener('click', () => console.log('2. parent 버블링'))
child.addEventListener('click', () => console.log('1. child 버블링'))
// child 클릭 시: child 버블링 → parent 버블링 순으로 출력

// 캡처링 단계 처리(세 번째 인수 true)
parent.addEventListener('click', () => console.log('0. parent 캡처링'), true)
// child 클릭 시 전체 순서: parent 캡처링 → child 버블링 → parent 버블링`,
  }}
/>

기본적으로 `addEventListener(type, fn)`은 **버블링** 단계에서 리스너를 실행합니다. 세 번째 인수로 `true`(또는 `{ capture: true }`)를 주면 **캡처링** 단계에서 실행됩니다.

## stopPropagation vs preventDefault — 헷갈리기 쉬운 두 메서드

```js
// stopPropagation: 이벤트가 부모로 전파되는 것을 막음(버블링/캡처링 중단)
child.addEventListener('click', (e) => {
  e.stopPropagation()   // 여기서 전파가 끊김 — parent의 클릭 리스너는 실행 안 됨
})

// preventDefault: 브라우저의 "기본 동작"만 취소. 전파는 그대로 계속됨
const link = document.querySelector('a')
link.addEventListener('click', (e) => {
  e.preventDefault()    // 페이지 이동은 취소되지만
  // 버블링은 정상적으로 계속 일어남
})
```

## 이벤트 위임(Event Delegation) — 부모 하나로 여러 자식 처리하기

개별 요소마다 리스너를 달지 않고, **부모 요소 하나**에만 리스너를 달아 버블링을 활용해 자식들의 이벤트를 처리하는 패턴입니다.

<CodePlayground
  template="vanilla"
  activeFile="/index.js"
  label="이벤트 위임 실습 — 항목을 클릭해보세요"
  files={{
    '/index.html': `<ul id="list">
  <li>할 일 1</li>
  <li>할 일 2</li>
  <li>할 일 3</li>
</ul>
<style>.done { text-decoration: line-through; color: #999; }</style>
<script src="/index.js"></script>`,
    '/index.js': `const list = document.querySelector('#list')

list.addEventListener('click', (event) => {
  // 실제 클릭된 요소가 li인지 closest로 확인(04번 문서에서 배운 메서드)
  const li = event.target.closest('li')
  if (li) {
    li.classList.toggle('done')
  }
})`,
  }}
/>

**왜 이렇게 할까?** `<li>` 100개에 리스너 100개를 각각 등록하면 메모리를 많이 씁니다. 부모(`#list`)에 리스너 1개만 등록하고, 이벤트가 버블링되어 올라올 때 `event.target`으로 "정확히 어떤 자식이 클릭됐는지" 판단하면 리스너 수를 크게 줄일 수 있습니다. 게다가 **나중에 동적으로 추가된 `<li>`**에도 별도 등록 없이 자동으로 적용됩니다.

## once 옵션과 커스텀 이벤트

```js
button.addEventListener('click', handler, { once: true })  // 한 번 실행 후 자동 제거

// 커스텀 이벤트 만들기
const myEvent = new CustomEvent('userLogin', {
  detail: { username: '철수' },  // 이벤트에 담을 데이터
  bubbles: true,
})
document.dispatchEvent(myEvent)

document.addEventListener('userLogin', (e) => {
  console.log(e.detail.username)  // '철수'
})
```

## 핵심 정리

- addEventListener(type, handler)로 등록하고, removeEventListener는 같은 함수 참조가 있어야 제거할 수 있다.
- 이벤트는 캡처링 → 타겟 → 버블링 순서로 전파되며, 기본은 버블링 단계에서 리스너가 실행된다.
- stopPropagation()은 전파를, preventDefault()는 브라우저 기본 동작을 각각 별도로 막는다.
- 이벤트 위임은 부모 하나에 리스너를 달아 target으로 자식을 구분하는 패턴으로, 메모리 절약과 동적 요소 대응이 장점이다.
- CustomEvent로 자신만의 이벤트를 만들어 dispatchEvent로 발생시킬 수 있다.
