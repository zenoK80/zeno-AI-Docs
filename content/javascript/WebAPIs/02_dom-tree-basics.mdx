<Callout type="info">
  **이번 문서의 목표:** DOM이 왜 "트리"라고 불리는지, HTML 태그가 어떻게 조작 가능한 객체로 바뀌는지 이해합니다.
</Callout>

## DOM이라는 이름 풀어보기

**DOM**(Document Object Model)도 단어별로 뜻을 나누면 이해가 쉬워집니다.

<Table>
  <thead>
    <tr><th>단어</th><th>뜻</th></tr>
  </thead>
  <tbody>
    <tr><td>Document</td><td>문서(우리가 작성한 HTML 파일)</td></tr>
    <tr><td>Object</td><td>객체(속성과 기능을 가진 프로그래밍 단위)</td></tr>
    <tr><td>Model</td><td>모형(실제 구조를 표현한 것)</td></tr>
  </tbody>
</Table>

DOM = "문서를 객체로 표현한 모형". 즉, 브라우저가 HTML 텍스트 파일을 읽고, JavaScript가 다루기 편한 **객체들의 구조**로 바꿔놓은 결과물입니다.

## 왜 HTML을 그대로 안 쓰고 DOM으로 바꿀까?

> **쉽게 말하면:** HTML 파일은 그냥 "글자로 적힌 문서"일 뿐입니다. JavaScript가 "이 제목을 바꿔라", "이 버튼을 찾아라" 같은 명령을 내리려면, 문서가 코드로 다룰 수 있는 형태(객체)여야 합니다.

```html
<body>
  <h1>제목</h1>
  <p>내용</p>
</body>
```

이 HTML 텍스트를 브라우저가 읽으면, 각 태그가 **노드**(node)라는 객체가 되어 서로 부모-자식 관계로 연결된 구조를 만듭니다. 이 구조가 나뭇가지처럼 뻗어나가는 모양이라 **DOM 트리**(tree, 나무)라고 부릅니다.

<Steps>
### document (문서 노드, 최상위)
### html
### body (html의 자식)
### h1과 p (body의 자식, 서로 형제)
- h1 안에는 '제목' 텍스트 노드가 들어있다
- p 안에는 '내용' 텍스트 노드가 들어있다
</Steps>

## 노드의 종류

DOM 트리를 이루는 노드는 한 종류만 있는 것이 아닙니다.

<Table>
  <thead>
    <tr><th>노드 종류</th><th>설명</th><th>예시</th></tr>
  </thead>
  <tbody>
    <tr><td>문서 노드(Document)</td><td>트리 전체의 최상위, 단 하나만 존재</td><td>document</td></tr>
    <tr><td>요소 노드(Element)</td><td>HTML 태그 하나하나</td><td>&lt;h1&gt;, &lt;p&gt;, &lt;div&gt;</td></tr>
    <tr><td>텍스트 노드(Text)</td><td>태그 안의 순수 글자 내용</td><td>'제목'이라는 글자 자체</td></tr>
    <tr><td>속성 노드(Attribute)</td><td>태그의 속성</td><td>class="title"의 class 부분</td></tr>
    <tr><td>주석 노드(Comment)</td><td>HTML 주석</td><td>&lt;!-- 주석 --&gt;</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  `<h1>제목</h1>`은 사실 **두 개의 노드**로 이루어집니다: `<h1>`이라는 **요소 노드**와, 그 안의 '제목'이라는 **텍스트 노드**입니다. 요소 노드 자체는 글자를 담는 "그릇"이고, 실제 글자는 그 안의 별도 텍스트 노드에 있습니다. 이 구분은 나중에 `children`과 `childNodes`의 차이(04번 문서)를 이해하는 데 중요합니다.
</Callout>

## 실제로 눈으로 확인하기

<CodePlayground
  template="vanilla"
  activeFile="/index.js"
  showConsole
  label="DOM 트리 구조 실습"
  files={{
    '/index.html': `<div id="container">
  <h1>제목</h1>
  <p>내용</p>
</div>
<script src="/index.js"></script>`,
    '/index.js': `console.log(document)  // 문서 노드 전체 출력 — 콘솔에서 트리 구조를 펼쳐보세요

const container = document.querySelector('#container')
console.log(container.nodeType)  // 1 — 요소 노드(Element)를 의미하는 숫자
console.log(container.nodeName)  // 'DIV'

const h1 = document.querySelector('h1')
console.log(h1.firstChild.nodeType)  // 3 — 텍스트 노드(Text)를 의미하는 숫자
console.log(h1.firstChild.textContent)  // '제목'`,
  }}
/>

`nodeType`은 노드의 종류를 숫자로 알려줍니다. `1`은 요소 노드, `3`은 텍스트 노드입니다. `<h1>제목</h1>`을 찾은 뒤 그 `firstChild`(첫 번째 자식)을 확인하면, `<h1>` 요소 노드가 아니라 그 안의 텍스트 노드가 나옵니다.

## window.document — 진입점

브라우저는 현재 페이지의 DOM 트리 전체를 `document`라는 하나의 전역 객체로 제공합니다. 이 시리즈 전체에서 `document.querySelector(...)`처럼 항상 `document`에서 시작하는 이유가 이것입니다. `document`가 DOM 트리의 뿌리(최상위 문서 노드)이기 때문입니다.

## DOM은 HTML의 "실시간 사본"이다

DOM은 원본 HTML 파일과 다릅니다. JavaScript로 DOM을 변경하면(05번 문서), **화면에는 즉시 반영**되지만 원본 `.html` 파일 자체는 바뀌지 않습니다. "보기 → 페이지 소스"는 원본 HTML을, 개발자 도구의 "Elements" 탭은 현재 DOM(변경 사항이 반영된 상태)을 보여줍니다.

<Callout type="warning">
  이 차이 때문에, JavaScript로 화면 내용을 바꾼 뒤 "페이지 소스 보기"를 하면 바뀐 내용이 안 보여서 당황하는 경우가 많습니다. **개발자 도구의 Elements 탭**을 확인해야 현재 DOM 상태를 정확히 볼 수 있습니다.
</Callout>

## 핵심 정리

- DOM(Document Object Model)은 HTML 문서를 JavaScript가 다룰 수 있는 객체 구조로 표현한 것이다.
- DOM은 노드들이 부모-자식 관계로 연결된 트리 구조를 이룬다.
- 요소 노드, 텍스트 노드, 속성 노드, 주석 노드 등 여러 노드 종류가 있다.
- `<h1>제목</h1>`은 h1 요소 노드와 '제목' 텍스트 노드, 두 개의 노드로 이루어진다.
- DOM은 원본 HTML 파일과 별개이며, JavaScript로 변경해도 원본 파일은 바뀌지 않고 화면(현재 DOM 상태)만 바뀐다.
