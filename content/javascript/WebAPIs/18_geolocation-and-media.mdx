## 왜 이런 API들은 항상 "권한"이 필요할까?

위치, 카메라, 마이크는 모두 사용자의 **매우 민감한 개인 정보**입니다. 웹사이트가 코드 한 줄로 몰래 이런 정보에 접근할 수 있다면 심각한 사생활 침해가 됩니다. 그래서 이 API들은 공통적으로 **브라우저가 사용자에게 팝업으로 명시적 허가를 구하고**, 사용자가 "허용"을 눌러야만 동작합니다.

## Geolocation API — 위치 정보

```js
navigator.geolocation.getCurrentPosition(
  (position) => {
    const { latitude, longitude, accuracy } = position.coords
    console.log(`위도: ${latitude}, 경도: ${longitude}`)
    console.log(`정확도: ${accuracy}m`)
  },
  (error) => {
    switch (error.code) {
      case error.PERMISSION_DENIED:
        console.error('위치 접근 권한이 거부되었습니다')
        break
      case error.POSITION_UNAVAILABLE:
        console.error('위치 정보를 가져올 수 없습니다')
        break
      case error.TIMEOUT:
        console.error('요청 시간이 초과되었습니다')
        break
    }
  },
  { enableHighAccuracy: true, timeout: 5000, maximumAge: 0 }
)
```

`getCurrentPosition`은 성공 콜백과 실패 콜백을 각각 별도로 받는 **콜백 기반 API**입니다(Promise가 아님 — 오래전에 설계된 API의 흔적입니다).

## 위치 변화 지속 감시

```js
const watchId = navigator.geolocation.watchPosition(
  (position) => console.log('위치 변경:', position.coords),
  (error) => console.error(error)
)

navigator.geolocation.clearWatch(watchId)  // 감시 중단
```

`getCurrentPosition`은 한 번만, `watchPosition`은 사용자가 이동할 때마다 계속 콜백을 호출합니다.

## MediaDevices API — 카메라·마이크

```js
async function startCamera() {
  try {
    const stream = await navigator.mediaDevices.getUserMedia({
      video: { width: 1280, height: 720 },
      audio: true,
    })

    const video = document.querySelector('video')
    video.srcObject = stream
    await video.play()

    // 사용이 끝나면 반드시 트랙을 정지해야 카메라 표시등이 꺼짐
    stream.getTracks().forEach(track => track.stop())
  } catch (err) {
    if (err.name === 'NotAllowedError') {
      console.error('카메라 권한이 거부되었습니다')
    }
  }
}
```

<Callout type="warning">
  `getUserMedia`가 반환한 `stream`을 다 사용한 뒤 `track.stop()`을 호출하지 않으면, 카메라·마이크가 계속 활성 상태로 남아 브라우저 탭의 녹화 표시등이 꺼지지 않습니다. 사용이 끝나면 반드시 정리해야 합니다.
</Callout>

## File API — 사용자가 선택한 파일 다루기

```js
const fileInput = document.querySelector('#file')

fileInput.addEventListener('change', (e) => {
  const file = e.target.files[0]
  if (!file) return

  console.log('파일명:', file.name)
  console.log('크기:', file.size, 'bytes')
  console.log('타입:', file.type)

  const reader = new FileReader()
  reader.onload = (event) => {
    console.log('내용:', event.target.result)
  }
  reader.readAsText(file, 'UTF-8')
})
```

## FileReader의 다양한 읽기 메서드

<Table>
  <thead>
    <tr><th>메서드</th><th>결과</th></tr>
  </thead>
  <tbody>
    <tr><td>readAsText(file)</td><td>텍스트 문자열</td></tr>
    <tr><td>readAsDataURL(file)</td><td>base64로 인코딩된 Data URL(이미지 미리보기에 유용)</td></tr>
    <tr><td>readAsArrayBuffer(file)</td><td>ArrayBuffer(이진 데이터 처리용)</td></tr>
  </tbody>
</Table>

```js
const reader = new FileReader()
reader.onload = (e) => { /* e.target.result에 결과가 담김 */ }
reader.onprogress = (e) => { /* e.loaded / e.total로 진행률 계산 */ }
reader.onerror = (e) => { /* 읽기 실패 처리 */ }

reader.readAsDataURL(file)  // 이미지 즉시 미리보기에 자주 사용
```

```js
// 이미지 미리보기 실전 패턴
const img = document.querySelector('#preview')
img.src = URL.createObjectURL(file)  // 파일에 대한 임시 브라우저 URL(blob:) 생성
```

`URL.createObjectURL()`은 `FileReader.readAsDataURL()`보다 더 가볍고 빠릅니다. 파일 전체를 base64 문자열로 변환하지 않고, 브라우저 메모리 안의 파일을 가리키는 짧은 URL만 만들기 때문입니다.

## 핵심 정리

- Geolocation, 카메라·마이크, 클립보드 같은 민감한 API는 공통적으로 사용자의 명시적 허가가 필요하다.
- getCurrentPosition은 한 번, watchPosition은 위치가 바뀔 때마다 계속 콜백을 호출한다.
- getUserMedia로 얻은 스트림은 사용이 끝나면 track.stop()으로 반드시 정리해야 한다.
- FileReader로 사용자가 선택한 파일을 텍스트, Data URL, ArrayBuffer 등으로 읽을 수 있다.
- URL.createObjectURL()은 base64 변환 없이 가볍게 파일 미리보기 URL을 만든다.
