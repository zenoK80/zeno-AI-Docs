## ECMAScript와 Web API의 경계 — 실전 편

1편에서 "브라우저가 주는 능력이 Web API"라는 경계선을 그었다.
이번 편은 그 경계선이 **실무에서 왜 중요한지**를 구체적인 사례로 확인한다.

## 자바스크립트를 실행하는 곳은 브라우저만이 아니다

지금 실행 환경을 나열해 보면 이렇다.

| 실행 환경 | 정체 |
| --- | --- |
| Chrome, Firefox, Safari | 브라우저 |
| Node.js | 서버용 런타임 |
| Deno, Bun | Node의 대안 런타임 |
| Cloudflare Workers | 엣지 서버 런타임 |

<Callout type="important">
이들 전부 **ECMAScript 언어 부분은 100% 동일하게 동작한다.** `class`, `Promise`, `Array.map`은 어디서 실행하든 똑같다.
**다른 건 각자가 추가로 얹어주는 "호스트 API"** 뿐이다.
</Callout>

브라우저의 호스트 API가 Web API이듯, Node.js는 `fs`(파일 시스템), `process` 같은 자기만의 API를 얹는다.
Node.js 시리즈에서 다루는 내용이 바로 이것이다.

## 같은 이름, 다른 정체 — setTimeout 사례

`setTimeout`은 브라우저에도, Node.js에도 있다. 이름과 기본 동작은 같지만 **반환값의 정체가 다르다.**

<Tabs items={['브라우저', 'Node.js']}>
<Tabs.Tab>

```js
const id = setTimeout(() => {}, 1000)
console.log(id)          // 숫자, 예: 3
console.log(typeof id)   // 'number'
```

</Tabs.Tab>
<Tabs.Tab>

```js
const id = setTimeout(() => {}, 1000)
console.log(id)          // Timeout 객체
console.log(typeof id)   // 'object'
```

</Tabs.Tab>
</Tabs>

<Callout type="warning">
`setTimeout`의 반환값을 숫자로 가정하고 연산을 하면(`id + 1` 같은) 브라우저에서는 되고 Node.js에서는 의도와 다르게 동작할 수 있다.
**왜 이런 일이 생기나?** `setTimeout` 자체가 ECMAScript 명세에 없는 호스트 API이기 때문이다.
각 실행 환경이 "타이머를 어떻게 표현할지"는 **각자의 자유**다. WHATWG가 브라우저용 규격을 정했을 뿐, Node.js는 자체적으로 다르게 구현했다.
</Callout>

## "이 환경에서 이 코드가 돌아가는가?" 확인하는 법

라이브러리 코드를 짜다 보면 브라우저에서도, Node.js에서도 돌아가야 하는 경우가 있다.
이런 코드를 **유니버설 코드**<sup>Universal Code</sup> 또는 **아이소몰픽 코드**<sup>Isomorphic Code</sup>라 부른다.

이때 쓰는 패턴이 **존재 여부로 환경을 판별하는 것**이다.

```js
if (typeof window !== 'undefined') {
  // 브라우저에서만 실행됨 — window는 브라우저 전용 전역 객체
  console.log('브라우저 환경')
} else {
  console.log('브라우저가 아닌 환경 (Node.js 등)')
}
```

<Callout type="info">
`window`가 브라우저 전용인 이유는 다음 편에서 다룬다. 지금은 **"브라우저에만 있는 걸로 알려진 이름의 존재 여부로 환경을 구분한다"** 는 패턴만 기억하면 된다.
</Callout>

## 경계를 헷갈리면 생기는 실제 문제

Next.js 같은 프레임워크로 만든 앱은 코드 일부가 **서버(Node.js와 비슷한 환경)에서도 실행**된다.
이때 아래처럼 짜면 바로 에러가 난다.

```js
function getPageTitle() {
  return document.title   // ReferenceError: document is not defined
}
```

`document`는 브라우저 전용 Web API다. 서버에는 애초에 존재하지 않는다.
이 에러를 만났을 때 "이건 언어 문법 에러가 아니라, **호스트 API가 없는 환경에서 그 API를 부르려 한 것**"이라고 진단할 수 있어야 한다.

<Callout type="important">
이 진단 능력이 이 시리즈 전체가 노리는 것이다. 앞으로 새 API가 나올 때마다
**"이건 언어인가, 브라우저인가?"** 를 스스로 판별할 수 있게 된다.
</Callout>

## 정리

<Callout type="default">
- 자바스크립트는 브라우저 · Node.js · Deno · Bun 등 여러 곳에서 돌아간다
- **언어(ECMAScript) 부분은 어디서든 동일**하고, 호스트 API만 환경마다 다르다
- 이름이 같아도(`setTimeout`) 반환값 같은 세부 동작은 환경마다 다를 수 있다
- `typeof window !== 'undefined'` 같은 패턴으로 실행 환경을 구분한다
- "이 코드가 왜 이 환경에서만 에러가 나는가?"는 대개 호스트 API 문제다
</Callout>

다음 편에서는 브라우저 안으로 더 깊이 들어가, **브라우저가 내부적으로 어떤 구조(프로세스)** 로 이루어져 있는지 본다.
