## setTimeout — 지연 후 한 번 실행

```js
const timerId = setTimeout(() => {
  console.log('1초 후 실행')
}, 1000)

clearTimeout(timerId)  // 실행 전이라면 취소 가능
```

ECMAScript 30번 문서(이벤트 루프)에서 배운 대로, `setTimeout`의 콜백은 태스크 큐에 등록되며 지정한 시간은 "최소 대기 시간"일 뿐 정확히 그 시점에 실행된다고 보장하지 않습니다.

## setInterval — 반복 실행

```js
let count = 0
const intervalId = setInterval(() => {
  count++
  console.log(`${count}초 경과`)
  if (count >= 5) clearInterval(intervalId)  // 반드시 멈춰야 함
}, 1000)
```

<Callout type="warning">
  `setInterval`은 이전 콜백의 실행이 끝나지 않아도 다음 실행을 예약합니다. 콜백 실행 시간이 간격(1000ms)보다 길어지면 콜백들이 쌓이거나 겹칠 수 있습니다. 이런 상황에서는 `setTimeout`을 재귀적으로 호출하는 패턴이 더 안전합니다.
  ```js
  function tick() {
    console.log('작업 실행')
    setTimeout(tick, 1000)  // 이전 작업이 "완료된 후" 다음을 예약
  }
  setTimeout(tick, 1000)
  ```
</Callout>

`setTimeout`으로 애니메이션을 만들면 화면 주사율과 어긋나 뚝뚝 끊기거나(jank), 탭이 백그라운드에 있어도 계속 실행되어 배터리를 낭비합니다. `requestAnimationFrame`은 보통 초당 60번(60fps, 모니터에 따라 다름) 호출되며, **탭이 비활성화되면 자동으로 일시정지**되어 리소스를 절약합니다.

## 타임스탬프로 경과 시간 기반 애니메이션 만들기

`requestAnimationFrame` 콜백은 고정밀 타임스탬프를 인수로 받습니다. 매 프레임 고정값(2px)만큼 움직이는 대신, **실제 경과 시간**을 기준으로 움직이면 화면 주사율이 다른 기기에서도 일정한 속도를 유지할 수 있습니다.

```js
let start = null

function animate(timestamp) {
  if (!start) start = timestamp
  const elapsed = timestamp - start
  const progress = Math.min(elapsed / 2000, 1)  // 2초에 걸쳐 0에서 1까지

  box.style.opacity = progress
  box.style.transform = `translateX(${progress * 200}px)`

  if (progress < 1) {
    requestAnimationFrame(animate)
  }
}

requestAnimationFrame(animate)
```

## cancelAnimationFrame — 애니메이션 취소

```js
const rafId = requestAnimationFrame(animate)
cancelAnimationFrame(rafId)
```

## 핵심 정리

- setTimeout은 지연 후 한 번, setInterval은 지정 간격마다 반복 실행한다.
- setInterval은 이전 실행이 끝나지 않아도 다음 실행을 예약해 콜백이 쌓일 수 있어, setTimeout 재귀 패턴이 더 안전할 때가 있다.
- requestAnimationFrame은 화면 갱신 직전에 호출되어 애니메이션에 최적이며, 탭 비활성화 시 자동으로 일시정지된다.
- 타임스탬프 인수로 경과 시간 기반 애니메이션을 만들면 기기 성능과 무관하게 일정한 속도를 유지할 수 있다.
