## AJAX와 fetch — 이름부터 이해하기

**AJAX**(Asynchronous JavaScript and XML)는 "페이지를 새로고침하지 않고 서버와 데이터를 주고받는 기법" 전체를 가리키는 오래된 용어입니다. 예전에는 `XMLHttpRequest`라는 객체로 이를 구현했지만, 지금은 훨씬 사용하기 쉬운 **`fetch()`** 함수가 표준으로 자리잡았습니다.

`fetch()`는 Promise를 반환합니다. `await`으로 응답 객체를 받고, `response.json()`으로 실제 데이터를 꺼냅니다. `json()` 역시 비동기 메서드라 한 번 더 `await`이 필요합니다.

## Response 객체 자세히 보기

```js
const response = await fetch('/api/data')

console.log(response.status)      // 200, 404, 500 등 HTTP 상태 코드
console.log(response.ok)          // 200~299 범위면 true
console.log(response.statusText)  // 'OK', 'Not Found' 등
console.log(response.headers.get('content-type'))

// 응답 본문 파싱(스트림이라 한 번만 읽을 수 있음)
const json = await response.json()      // JSON으로 파싱
// const text = await response.text()   // 순수 텍스트로
// const blob = await response.blob()   // 파일·이미지 등 바이너리로
```

<Callout type="warning">
  **`fetch()`는 네트워크 오류**(연결 실패, CORS 차단 등)**일 때만 reject됩니다.** 404, 500 같은 HTTP 오류 상태는 정상적인 응답으로 취급되어 **resolve**됩니다. 반드시 `response.ok`를 확인해야 진짜 실패를 감지할 수 있습니다.
  ```js
  const response = await fetch('/api/missing')  // 404여도 여기서 에러가 안 남!
  if (!response.ok) {
    throw new Error('요청 실패: ' + response.status)  // 직접 확인 후 에러를 던져야 함
  }
  ```
</Callout>

## POST 요청 — 데이터 전송

```js
async function createUser(userData) {
  const response = await fetch('/api/users', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(userData),  // 객체를 JSON 문자열로 변환(ECMAScript 23번 문서)
  })
  return response.json()
}

await createUser({ name: '철수', email: 'chul@example.com' })
```

`Content-Type: application/json` 헤더로 "본문이 JSON 형식임"을 서버에 알려야, 서버가 `body`를 올바르게 해석합니다.

## 에러 처리 패턴

```js
async function fetchData(url) {
  try {
    const response = await fetch(url)
    if (!response.ok) {
      throw new Error(`서버 오류: ${response.status}`)
    }
    return await response.json()
  } catch (error) {
    if (error instanceof TypeError) {
      console.error('네트워크 오류:', error.message)  // 연결 자체 실패
    } else {
      console.error('서버 오류:', error.message)
    }
    throw error
  }
}
```

## AbortController — 요청 취소하기

```js
const controller = new AbortController()

setTimeout(() => controller.abort(), 3000)  // 3초 후 강제 취소

try {
  const response = await fetch('/api/slow', { signal: controller.signal })
  const data = await response.json()
} catch (err) {
  if (err.name === 'AbortError') {
    console.log('요청이 취소되었습니다')
  }
}
```

너무 오래 걸리는 요청을 강제로 중단하거나, 사용자가 검색어를 계속 바꿀 때 이전 요청을 취소하고 최신 요청만 유지하는 데 자주 쓰입니다.

## 병렬 요청 — Promise.all과 함께

여러 요청이 서로 의존하지 않는다면, ECMAScript 28번 문서에서 배운 `Promise.all`로 동시에 처리하는 것이 훨씬 빠릅니다.

```js
async function loadAll() {
  const [users, posts, comments] = await Promise.all([
    fetch('/api/users').then(r => r.json()),
    fetch('/api/posts').then(r => r.json()),
    fetch('/api/comments').then(r => r.json()),
  ])
  return { users, posts, comments }
}
```

## FormData 전송

```js
const form = document.querySelector('form')
const formData = new FormData(form)

const response = await fetch('/api/upload', {
  method: 'POST',
  body: formData,  // Content-Type 헤더가 자동으로 multipart/form-data로 설정됨
})
```

`FormData`를 body로 넘길 때는 `Content-Type` 헤더를 **직접 설정하면 안 됩니다.** 파일 경계 정보(boundary)를 브라우저가 자동으로 계산해 넣기 때문입니다.

## 핵심 정리

- fetch(url, options)는 Promise를 반환하며, 응답 파싱(json 등)도 비동기라 각각 await이 필요하다.
- fetch는 네트워크 오류에서만 reject되고, 404·500 같은 HTTP 오류는 resolve되므로 response.ok를 직접 확인해야 한다.
- POST 요청은 method, headers의 Content-Type, JSON.stringify한 body 세 가지가 함께 필요하다.
- AbortController로 signal을 넘겨 진행 중인 요청을 취소할 수 있다.
- 서로 의존하지 않는 여러 요청은 Promise.all로 병렬 처리하는 것이 빠르다.
