  **이번 문서의 목표:** 폴링(반복 확인) 없이 DOM 변화가 일어나는 즉시 감지하는 방법을 익힙니다.
</Callout>

## 왜 DOM 변화를 "감지"해야 할까?

> **쉽게 말하면:** 내가 만들지 않은 코드(광고 스크립트, 다른 라이브러리 등)가 DOM을 바꿀 때도 있습니다. 이럴 때 "언제 바뀌었는지" 직접 감시할 방법이 필요합니다.

MutationObserver가 없다면, DOM 변화를 감지하려고 `setInterval`로 계속 확인(polling, 폴링)하는 방법밖에 없었습니다.

```js
// ❌ 옛날 방식 — 계속 확인해야 해서 비효율적
setInterval(() => {
  const count = document.querySelectorAll('.item').length
  console.log('현재 항목 수:', count)  // 100ms마다 불필요하게 계속 확인
}, 100)
```

**MutationObserver**(변형을 감시하는 관찰자)는 실제로 변화가 일어난 **그 순간에만** 콜백을 실행해, 불필요한 반복 확인 없이 훨씬 효율적으로 동작합니다.

## observe()의 옵션 — 무엇을 감시할지 선택

MutationObserver는 기본적으로 아무것도 감시하지 않습니다. `observe(대상, 옵션)`의 옵션으로 **정확히 무엇을 감시할지** 지정해야 합니다.

<Table>
  <thead>
    <tr><th>옵션</th><th>감시 대상</th></tr>
  </thead>
  <tbody>
    <tr><td>childList</td><td>자식 요소의 추가·삭제</td></tr>
    <tr><td>attributes</td><td>속성(class, style, data-* 등) 변경</td></tr>
    <tr><td>characterData</td><td>텍스트 내용 변경</td></tr>
    <tr><td>subtree</td><td>대상 요소뿐 아니라 모든 하위 자손까지 감시 범위 확장</td></tr>
  </tbody>
</Table>

```js
observer.observe(targetElement, {
  childList: true,
  attributes: true,
  subtree: true,       // 자손 요소들의 변화까지 모두 감시
  attributeFilter: ['class', 'data-status'],  // 특정 속성만 감시(선택 사항)
})
```

## 속성 변화 감지 실전 예시

```js
const box = document.querySelector('.box')

const observer = new MutationObserver((mutations) => {
  mutations.forEach((mutation) => {
    if (mutation.type === 'attributes') {
      console.log(`${mutation.attributeName} 속성이 변경됨`)
      console.log('이전 값:', mutation.oldValue)
      console.log('현재 값:', box.getAttribute(mutation.attributeName))
    }
  })
})

observer.observe(box, {
  attributes: true,
  attributeOldValue: true,  // 이전 값도 함께 기록
})

box.className = 'box active'  // 콜백 실행됨
```

## disconnect() — 감시 중단

```js
observer.disconnect()  // 더 이상 감시하지 않음 — 메모리 누수 방지를 위해 필요 없어지면 반드시 호출
```

<Callout type="warning">
  컴포넌트나 기능이 화면에서 사라질 때 `disconnect()`를 호출하지 않으면, observer가 계속 살아있는 요소를 감시하며 콜백을 실행해 메모리 누수의 원인이 될 수 있습니다. React 같은 프레임워크를 배울 때 "cleanup 함수"에서 정리해야 할 대표적인 대상입니다.
</Callout>

## 실전 활용 사례

- 광고 차단 확장 프로그램이 새로 삽입된 광고 요소를 실시간으로 감지해 제거
- 채팅 앱에서 새 메시지 요소가 추가되는 순간을 감지해 자동 스크롤
- 서드파티 위젯이 DOM을 변경했는지 감시해 우리 코드와의 충돌 방지

## 핵심 정리

- MutationObserver는 DOM 변화가 일어난 순간에만 콜백을 실행해, setInterval 폴링보다 효율적으로 변화를 감지한다.
- observe(대상, 옵션)에서 childList, attributes, characterData, subtree 등으로 감시 범위를 지정해야 한다.
- 콜백은 발생한 변화들의 배열(mutations)을 받으며, 각 항목의 type으로 변화 종류를 구분한다.
- 더 이상 필요 없어지면 disconnect()를 호출해 감시를 중단해야 메모리 누수를 방지한다.
