## fetch의 한계 — 항상 클라이언트가 먼저 물어봐야 한다

10번 문서에서 배운 `fetch()`는 **요청-응답**(request-response) 방식입니다. 클라이언트가 "데이터 주세요"라고 요청해야만 서버가 응답합니다. 서버가 먼저 클라이언트에게 "새 메시지 왔어요!"라고 알려줄 방법이 없습니다.

```js
// 새 메시지가 왔는지 계속 물어봐야 하는 비효율적인 방식(폴링)
setInterval(async () => {
  const res = await fetch('/api/messages/new')
  const messages = await res.json()
  // 메시지가 없어도 계속 요청을 보냄 — 낭비
}, 1000)
```

## WebSocket — 연결을 유지한 채 양방향으로 통신

**WebSocket**은 클라이언트와 서버 사이에 **한 번 연결을 맺으면 계속 유지되는 통로**를 만듭니다. 이 통로를 통해 서버든 클라이언트든 **원하는 시점에 먼저 메시지를 보낼 수 있습니다**.

## WebSocket 기본 사용법

```js
const socket = new WebSocket('wss://echo.websocket.org')  // wss:// — 암호화된 WebSocket(https와 짝)

// 연결이 열렸을 때
socket.addEventListener('open', () => {
  console.log('연결됨')
  socket.send('안녕하세요')  // 서버로 메시지 전송
})

// 서버로부터 메시지를 받았을 때
socket.addEventListener('message', (event) => {
  console.log('받은 메시지:', event.data)
})

// 연결이 닫혔을 때
socket.addEventListener('close', () => {
  console.log('연결 종료')
})

// 오류가 발생했을 때
socket.addEventListener('error', (error) => {
  console.error('오류:', error)
})
```

`ws://`는 일반 HTTP와 짝을 이루는 암호화되지 않은 프로토콜이고, `wss://`(WebSocket Secure)는 HTTPS와 짝을 이루는 암호화된 프로토콜입니다. 실무에서는 항상 `wss://`를 사용합니다.

## WebSocket의 상태 — readyState

```js
console.log(socket.readyState)
// 0: CONNECTING(연결 중)
// 1: OPEN(연결됨, 통신 가능)
// 2: CLOSING(닫는 중)
// 3: CLOSED(닫힘)
```

메시지를 보내기 전에 연결이 실제로 열려 있는지(`readyState === WebSocket.OPEN`) 확인하는 것이 안전합니다.

```js
function sendSafely(socket, message) {
  if (socket.readyState === WebSocket.OPEN) {
    socket.send(message)
  } else {
    console.warn('연결이 아직 준비되지 않았습니다')
  }
}
```

## 실전 패턴 — 재연결 로직

네트워크가 불안정하면 WebSocket 연결이 끊길 수 있습니다. 실무에서는 연결이 끊기면 자동으로 재연결을 시도하는 로직을 함께 구현합니다.

```js
function connect() {
  const socket = new WebSocket('wss://example.com/chat')

  socket.addEventListener('close', () => {
    console.log('연결 끊김, 3초 후 재연결 시도')
    setTimeout(connect, 3000)  // 재귀적으로 다시 연결 시도
  })

  socket.addEventListener('message', (event) => {
    console.log('메시지:', event.data)
  })

  return socket
}

connect()
```

## JSON으로 구조화된 메시지 주고받기

WebSocket은 문자열만 보낼 수 있으므로, 객체를 보내려면 JSON으로 직렬화해야 합니다(ECMAScript 23번 문서에서 배운 JSON.stringify/parse가 여기서도 그대로 쓰입니다).

```js
// 보내기
socket.send(JSON.stringify({ type: 'chat', text: '안녕하세요', userId: 1 }))

// 받기
socket.addEventListener('message', (event) => {
  const data = JSON.parse(event.data)
  if (data.type === 'chat') {
    console.log(`${data.userId}: ${data.text}`)
  }
})
```

## 연결 종료

```js
socket.close(1000, '정상 종료')  // 코드 1000: 정상 종료를 의미하는 표준 코드
```

## 핵심 정리

- fetch는 클라이언트가 매번 요청해야 하는 단방향 요청-응답 방식이라 실시간 알림에 부적합하다.
- WebSocket은 한 번 연결을 맺으면 유지되는 통로를 통해 서버·클라이언트 모두 원하는 시점에 메시지를 보낼 수 있는 양방향 통신이다.
- readyState로 현재 연결 상태(CONNECTING, OPEN, CLOSING, CLOSED)를 확인할 수 있다.
- WebSocket은 문자열만 전송 가능하므로, 객체 데이터는 JSON.stringify/parse로 변환해서 주고받는다.
- 네트워크 단절에 대비해 close 이벤트에서 재연결 로직을 구현하는 것이 실전 패턴이다.
