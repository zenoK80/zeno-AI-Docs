## 03편 복습

## 핵심 퀴즈

**Q1. 옛날 브라우저(프로세스 하나짜리 구조)의 가장 큰 문제는?**

<Collapse title="정답 보기">
탭 하나의 스크립트가 무한 루프에 빠지면 다른 탭까지 전부 멈췄다. 프로세스가 하나라 격리가 안 됐기 때문이다.
</Collapse>

**Q2. 우리가 짜는 자바스크립트 코드는 어느 프로세스에서 실행되나?**

<Collapse title="정답 보기">
렌더러 프로세스(Renderer Process). 탭마다 별도로 뜬다.
</Collapse>

**Q3. 멀티 프로세스 구조의 대가(트레이드오프)는 무엇인가?**

<Collapse title="정답 보기">
메모리 사용량이 늘어난다. 프로세스마다 별도의 메모리를 차지하기 때문이다. 대신 안정성과 보안을 얻는다.
</Collapse>

## 실습 — 작업 관리자로 직접 확인하기

<Steps>

### 크롬 작업 관리자를 연다

<kbd>Shift</kbd>+<kbd>Esc</kbd> 또는 메뉴 → 도구 더보기 → 작업 관리자

### 탭 3개를 새로 연다

각기 다른 사이트를 열어본다.

### 프로세스 목록에서 `탭:`으로 시작하는 항목 개수를 센다

새로 연 탭 수만큼 늘어났는지 확인한다.

### 탭 하나를 닫아본다

작업 관리자 목록에서도 해당 프로세스가 사라지는지 확인한다.

</Steps>

이 실습으로 "탭 = 별도 프로세스"라는 걸 눈으로 직접 확인했다.

## 정리 체크리스트
