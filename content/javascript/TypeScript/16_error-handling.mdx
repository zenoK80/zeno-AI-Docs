## catch 절의 타입 — unknown vs any

```ts
// TypeScript 4.0 이전 — catch 변수가 any
try {
  riskyOperation()
} catch (error) {
  console.log(error.message)  // any라서 타입 오류 없음 (위험)
}

// TypeScript 4.0+ 기본값 — catch 변수가 unknown
// tsconfig.json useUnknownInCatchVariables: true (strict에 포함)
try {
  riskyOperation()
} catch (error) {
  // error는 unknown
  console.log(error.message)  // 오류: unknown에는 접근 불가

  // 타입 좁히기 필요
  if (error instanceof Error) {
    console.log(error.message)  // OK
    console.log(error.stack)    // OK
  } else {
    console.log(String(error))
  }
}
```

## 에러 처리 유틸리티

```ts
// 에러 메시지를 안전하게 추출
function getErrorMessage(error: unknown): string {
  if (error instanceof Error) return error.message
  if (typeof error === 'string') return error
  return '알 수 없는 오류가 발생했습니다.'
}

// 에러인지 확인
function isError(error: unknown): error is Error {
  return error instanceof Error
}

// 사용
try {
  await fetchData()
} catch (error) {
  console.error(getErrorMessage(error))
}
```

type Err<E> = { ok: false; error: E }
type Result<T, E = Error> = Ok<T> | Err<E>

function ok<T>(value: T): Ok<T> {
  return { ok: true, value }
}

function err<E>(error: E): Err<E> {
  return { ok: false, error }
}

// 사용
async function parseJson(text: string): Promise<Result<unknown, SyntaxError>> {
  try {
    return ok(JSON.parse(text))
  } catch (e) {
    return err(e as SyntaxError)
  }
}

async function main() {
  const success = await parseJson('{"name": "Alice"}')
  if (success.ok) {
    console.log('성공:', success.value)
  }

  const failure = await parseJson('{invalid json}')
  if (!failure.ok) {
    console.error('파싱 실패:', failure.error.message)
  }
}

main()`,
  }}

## 커스텀 에러 클래스

```ts
class HttpError extends Error {
  constructor(
    public readonly status: number,
    message: string,
    public readonly data?: unknown
  ) {
    super(message)
    this.name = 'HttpError'
    // ES5 호환성을 위해 필요
    Object.setPrototypeOf(this, HttpError.prototype)
  }
}

class NetworkError extends Error {
  constructor(message: string, public readonly cause?: Error) {
    super(message)
    this.name = 'NetworkError'
    Object.setPrototypeOf(this, NetworkError.prototype)
  }
}

// 에러 처리
async function fetchUser(id: number) {
  try {
    const res = await fetch(`/api/users/${id}`)
    if (!res.ok) {
      throw new HttpError(res.status, `사용자 조회 실패`)
    }
    return res.json()
  } catch (error) {
    if (error instanceof HttpError) {
      if (error.status === 404) {
        console.log('사용자를 찾을 수 없습니다.')
      } else {
        throw error
      }
    }
    throw new NetworkError('네트워크 오류', isError(error) ? error : undefined)
  }
}

function isError(value: unknown): value is Error {
  return value instanceof Error
}
```

## 비동기 에러 처리 패턴

```ts
// Promise를 Result로 변환하는 유틸리티
async function tryCatch<T>(promise: Promise<T>): Promise<Result<T>> {
  try {
    const value = await promise
    return { ok: true, value }
  } catch (error) {
    return {
      ok: false,
      error: error instanceof Error ? error : new Error(String(error)),
    }
  }
}

// 사용
const result = await tryCatch(fetch('/api/users'))
if (result.ok) {
  const users = await result.value.json()
} else {
  console.error(result.error.message)
}

// 여러 비동기 작업 병렬 처리
const [usersResult, postsResult] = await Promise.all([
  tryCatch(fetchUsers()),
  tryCatch(fetchPosts()),
])

if (usersResult.ok && postsResult.ok) {
  // 두 작업 모두 성공
}
```

## 에러 경계 (React)

```tsx
import { Component, ErrorInfo } from 'react'

interface Props {
  children: React.ReactNode
  fallback: React.ReactNode
}

interface State {
  hasError: boolean
  error: Error | null
}

class ErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false, error: null }

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, info: ErrorInfo): void {
    console.error('에러 경계 포착:', error, info.componentStack)
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback
    }
    return this.props.children
  }
}
```

## 핵심 정리

- catch 절의 error 변수는 TypeScript 4.0+에서 기본적으로 unknown입니다.
- `instanceof Error` 체크 후 에러 프로퍼티에 접근해야 합니다.
- Result 패턴으로 에러를 타입으로 표현하면 처리를 강제할 수 있습니다.
- 커스텀 에러 클래스는 `Object.setPrototypeOf`로 instanceof 체크를 보장합니다.
