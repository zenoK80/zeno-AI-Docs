## Builder 패턴

메서드 체이닝으로 복잡한 객체를 단계별로 구성합니다.

```ts
class QueryBuilder {
  private table: string = ''
  private conditions: string[] = []
  private orderByField: string = ''
  private limitCount: number = 0

  from(table: string): this {
    this.table = table
    return this
  }

  where(condition: string): this {
    this.conditions.push(condition)
    return this
  }

  orderBy(field: string): this {
    this.orderByField = field
    return this
  }

  limit(count: number): this {
    this.limitCount = count
    return this
  }

  build(): string {
    let query = `SELECT * FROM ${this.table}`
    if (this.conditions.length) {
      query += ` WHERE ${this.conditions.join(' AND ')}`
    }
    if (this.orderByField) {
      query += ` ORDER BY ${this.orderByField}`
    }
    if (this.limitCount) {
      query += ` LIMIT ${this.limitCount}`
    }
    return query
  }
}

const query = new QueryBuilder()
  .from('users')
  .where('age > 18')
  .where('active = true')
  .orderBy('name')
  .limit(10)
  .build()
```

## 타입 안전한 API 클라이언트

```ts
// API 엔드포인트와 요청/응답 타입을 연결
interface ApiEndpoints {
  'GET /users': {
    request: { page?: number; limit?: number }
    response: { users: User[]; total: number }
  }
  'GET /users/:id': {
    request: { id: number }
    response: User
  }
  'POST /users': {
    request: { name: string; email: string }
    response: User
  }
}

type Method = 'GET' | 'POST' | 'PUT' | 'DELETE'

class ApiClient {
  private baseUrl: string

  constructor(baseUrl: string) {
    this.baseUrl = baseUrl
  }

  async get<T>(path: string, params?: Record<string, unknown>): Promise<T> {
    const url = new URL(this.baseUrl + path)
    if (params) {
      Object.entries(params).forEach(([k, v]) =>
        url.searchParams.set(k, String(v))
      )
    }
    const res = await fetch(url.toString())
    if (!res.ok) throw new Error(`HTTP ${res.status}`)
    return res.json()
  }

  async post<T>(path: string, body: unknown): Promise<T> {
    const res = await fetch(this.baseUrl + path, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(body),
    })
    if (!res.ok) throw new Error(`HTTP ${res.status}`)
    return res.json()
  }
}
```

## Result 패턴

에러를 타입 시스템으로 표현합니다.

```ts
type Result<T, E = Error> =
  | { success: true; data: T }
  | { success: false; error: E }

// 사용
async function fetchUser(id: number): Promise<Result<User>> {
  try {
    const res = await fetch(`/api/users/${id}`)
    if (!res.ok) return { success: false, error: new Error(`HTTP ${res.status}`) }
    const data = await res.json()
    return { success: true, data }
  } catch (error) {
    return { success: false, error: error instanceof Error ? error : new Error('Unknown') }
  }
}

// 호출 측에서 에러 처리 강제
async function displayUser(id: number) {
  const result = await fetchUser(id)
  if (result.success) {
    console.log(result.data.name)   // data 접근 가능
  } else {
    console.error(result.error.message)  // error 접근 가능
  }
}
```

## 에러 타입 설계

```ts
// 도메인 에러 클래스 계층
class AppError extends Error {
  constructor(
    message: string,
    public readonly code: string,
    public readonly statusCode: number = 500
  ) {
    super(message)
    this.name = 'AppError'
  }
}

class NotFoundError extends AppError {
  constructor(resource: string, id: string | number) {
    super(`${resource}(${id})를 찾을 수 없습니다.`, 'NOT_FOUND', 404)
    this.name = 'NotFoundError'
  }
}

class ValidationError extends AppError {
  constructor(
    message: string,
    public readonly fields: Record<string, string>
  ) {
    super(message, 'VALIDATION_ERROR', 400)
    this.name = 'ValidationError'
  }
}

// 에러 타입 유니온으로 모든 케이스 처리
type DomainError = NotFoundError | ValidationError | AppError

function handleError(error: DomainError) {
  if (error instanceof NotFoundError) {
    console.log('찾을 수 없음:', error.code)
  } else if (error instanceof ValidationError) {
    console.log('유효성 오류:', error.fields)
  } else {
    console.log('서버 오류:', error.message)
  }
}
```

## 브랜드 타입 (Branded Types)

동일한 기본 타입이지만 의미적으로 다른 타입을 구별합니다.

```ts
type Brand<T, B> = T & { __brand: B }

type UserId = Brand<number, 'UserId'>
type ProductId = Brand<number, 'ProductId'>

function getUser(id: UserId): User { /* ... */ return {} as User }
function getProduct(id: ProductId): Product { /* ... */ return {} as Product }

const userId = 1 as UserId
const productId = 2 as ProductId

getUser(userId)    // OK
getUser(productId) // 오류: ProductId를 UserId에 할당 불가
// 같은 number이지만 브랜드 타입으로 구별

interface Product { id: ProductId; name: string }
```

## 핵심 정리

- Builder 패턴은 `return this`로 메서드 체이닝을 지원합니다.
- Result 패턴으로 에러를 타입 시스템에서 표현해 처리를 강제합니다.
- 도메인 에러 클래스 계층으로 에러 종류를 명확히 구분합니다.
- Branded Types로 같은 기본 타입이지만 의미가 다른 값을 구별합니다.
