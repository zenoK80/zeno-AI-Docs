<Callout type="info">
  **이번 문서의 목표:** 모든 배열이 `.map()`을 쓸 수 있는 이유를 프로토타입 체인으로 설명할 수 있게 됩니다.
</Callout>

## 궁금증에서 시작하기

```js
const arr = [1, 2, 3]
console.log(arr.map(n => n * 2))  // [2, 4, 6]
```

`arr`는 그냥 `[1, 2, 3]`이라는 데이터를 담은 배열일 뿐인데, 어떻게 `.map()`이라는 기능을 쓸 수 있을까요? `arr` 안에 `map`이라는 함수를 직접 넣은 적이 없는데 말입니다. 이 답이 **프로토타입**(prototype)입니다.

## 프로토타입이란?

> **쉽게 말하면:** 프로토타입은 "모든 객체가 공유하는, 원본 기능이 저장된 참고서"입니다. 객체 자신에게 없는 기능을 요청받으면, 자바스크립트는 이 참고서를 찾아봅니다.

모든 자바스크립트 객체는 **자신의 프로토타입**이라는 다른 객체를 내부적으로 연결하고 있습니다. 원하는 프로퍼티나 메서드가 객체 자신에게 없으면, 자바스크립트 엔진은 자동으로 그 객체의 프로토타입을 찾아봅니다. 거기에도 없으면 프로토타입의 프로토타입을 찾고, 이 과정을 계속 반복합니다. 이 연결 고리를 **프로토타입 체인**(prototype chain)이라고 부릅니다.

## 프로토타입 체인 눈으로 확인하기

    '/index.js': `const arr = [1, 2, 3]

console.log(arr.hasOwnProperty('map'))  // false — arr 자신은 map을 갖고 있지 않음!

// arr의 프로토타입을 확인
console.log(Object.getPrototypeOf(arr) === Array.prototype)  // true

console.log(Array.prototype.hasOwnProperty('map'))  // true — 여기 있다!`,
  }}
/>

`arr` 자신에게는 `map`이 없지만(`hasOwnProperty`가 false), `arr`의 프로토타입인 `Array.prototype`에는 `map`이 있습니다. `arr.map()`을 호출하면 자바스크립트는 다음 순서로 찾습니다.

<Steps>
### arr 자신에게 map이 있는가?
없음 → 다음 단계로

### arr의 프로토타입(Array.prototype)에 map이 있는가?
있음! → 이 함수를 사용

### 만약 여기도 없었다면
Array.prototype의 프로토타입(Object.prototype)까지 계속 찾아 올라간다
</Steps>

이렇게 배열 백만 개를 만들어도, `map`이라는 함수 자체는 `Array.prototype`에 **딱 하나만** 존재하고 모든 배열이 이를 공유합니다. 배열 하나하나에 `map` 함수를 복사해 넣지 않아도 되므로 메모리를 절약할 수 있습니다.

## 직접 프로토타입 체인 만들어보기

```js
const animalPrototype = {
  makeSound() {
    console.log(`${this.name}가 소리를 냅니다`)
  },
}

const dog = Object.create(animalPrototype)  // dog의 프로토타입을 animalPrototype으로 지정
dog.name = '멍멍이'

dog.makeSound()  // '멍멍이가 소리를 냅니다' — dog 자신에게 makeSound가 없지만 프로토타입에서 찾음

console.log(dog.hasOwnProperty('makeSound'))  // false
console.log(dog.hasOwnProperty('name'))       // true
```

`Object.create(부모객체)`는 "이 객체의 프로토타입을 부모객체로 지정하며 새 객체를 만들어라"는 뜻입니다. 이렇게 만든 `dog`는 자신에게 없는 기능(`makeSound`)을 프로토타입(`animalPrototype`)에서 빌려 씁니다.

## 생성자 함수와 프로토타입

객체를 여러 개 찍어낼 때는, 생성자 함수와 `prototype` 프로퍼티를 함께 씁니다.

```js
function Animal(name) {
  this.name = name  // 각 인스턴스마다 고유하게 가질 데이터
}

// Animal로 만들어질 모든 객체가 공유할 기능은 prototype에 붙인다
Animal.prototype.makeSound = function () {
  console.log(`${this.name}가 소리를 냅니다`)
}

const dog = new Animal('멍멍이')
const cat = new Animal('야옹이')

dog.makeSound()  // '멍멍이가 소리를 냅니다'
cat.makeSound()  // '야옹이가 소리를 냅니다'

console.log(dog.makeSound === cat.makeSound)  // true — 같은 함수를 공유! 각자 복사본이 아님
```

`this.name`은 `new Animal(...)`로 만들어질 때마다 각 인스턴스에 **개별적으로** 저장되지만(14번 문서에서 배운 `new`의 규칙 3), `makeSound`는 `Animal.prototype`에 **딱 하나만** 존재하고 `dog`와 `cat`이 이를 공유합니다.

## `__proto__`와 `Object.getPrototypeOf` — 프로토타입 확인 방법

```js
const dog = new Animal('멍멍이')

console.log(dog.__proto__ === Animal.prototype)              // true (비표준이지만 널리 쓰임)
console.log(Object.getPrototypeOf(dog) === Animal.prototype)  // true (표준 방법, 이걸 권장)
```

<Callout type="warning">
  `__proto__`는 오랫동안 비공식적으로 쓰였지만, 표준 방법은 `Object.getPrototypeOf()`입니다. 실무 코드에서는 `__proto__`를 직접 조작하지 말고, 이 문서에서 배운 `Object.create()`나 19번 문서의 `class`를 사용하는 것이 안전합니다.
</Callout>

## 왜 지금은 class를 더 많이 쓰나?

지금까지 본 프로토타입 문법(`function` + `.prototype`)은 동작 원리를 이해하는 데는 좋지만, 코드가 장황하고 상속 관계를 표현하기 번거롭습니다. ES6에서 등장한 `class` 문법(19번 문서)은 **이 프로토타입 체인 위에서 동작하는 더 읽기 쉬운 문법**일 뿐, 완전히 다른 새로운 개념이 아닙니다.

```js
class Animal {
  constructor(name) {
    this.name = name
  }
  makeSound() {
    console.log(`${this.name}가 소리를 냅니다`)
  }
}

const dog = new Animal('멍멍이')
console.log(Object.getPrototypeOf(dog) === Animal.prototype)  // true — class도 결국 프로토타입 체인!
```

## 핵심 정리

- 프로토타입은 객체가 자신에게 없는 프로퍼티·메서드를 찾을 때 참조하는 연결된 객체다.
- 자신 → 자신의 프로토타입 → 그 프로토타입의 프로토타입… 순서로 찾아가는 것이 프로토타입 체인이다.
- `Object.create(부모)`로 프로토타입을 직접 지정해 객체를 만들 수 있다.
- 생성자 함수의 `prototype`에 메서드를 붙이면, 그 함수로 만든 모든 인스턴스가 메서드를 공유한다(메모리 절약).
- ES6의 `class`는 프로토타입 체인 위에서 동작하는 더 읽기 쉬운 문법이다.
