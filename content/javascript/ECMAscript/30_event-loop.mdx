`setTimeout`을 0ms로 설정했는데도, 왜 즉시 실행되지 않고 동기 코드보다 나중에 실행될까요? 그리고 `setTimeout(0)`과 `Promise.then` 중 어느 것이 먼저 실행될까요? 이 답을 이해하려면 **이벤트 루프**(Event Loop)의 동작 원리를 알아야 합니다.

## 자바스크립트는 싱글 스레드다

> **쉽게 말하면:** 자바스크립트 엔진은 **한 번에 딱 한 가지 일만** 할 수 있습니다. 여러 작업을 동시에 처리하는 것처럼 보이는 건, 사실 아주 빠르게 작업을 번갈아 처리하기 때문입니다.

자바스크립트는 **싱글 스레드**(single thread, 하나의 실행 흐름)로 동작합니다. 그런데 `setTimeout`, `fetch`, 이벤트 리스너처럼 "시간이 걸리는" 작업들이 어떻게 프로그램 전체를 멈추지 않고 처리될까요? 이 비밀이 **콜 스택** + **브라우저**(또는 Node.js)**의 도움** + **큐**(대기열)**로 이루어진 이벤트 루프 구조**에 있습니다.

## 이벤트 루프의 규칙

<Steps>
### 콜 스택의 코드를 모두 실행한다 (동기 코드 우선)

`console.log`처럼 즉시 실행 가능한 코드는 만나는 즉시 실행된다.

### 콜 스택이 완전히 비면, 마이크로태스크 큐를 확인한다

마이크로태스크 큐에 있는 모든 작업(Promise의 then 등)을 **큐가 빌 때까지 전부** 처리한다.

### 마이크로태스크 큐가 다 비면, 태스크 큐에서 하나를 꺼내 실행한다

setTimeout 콜백처럼 태스크 큐에 있던 작업을 **딱 하나만** 콜 스택으로 가져와 실행한다.

### 2번으로 돌아간다

이 과정이 프로그램이 끝날 때까지 무한히 반복된다. 이것이 "이벤트 루프"라는 이름의 이유다.
</Steps>

**핵심 규칙:** 마이크로태스크 큐는 태스크 큐보다 **항상 먼저, 그리고 완전히 비워질 때까지** 처리됩니다.

## 위 예제의 실행 순서 분석

```js
console.log('1. 동기 코드')          // 콜 스택에서 즉시 실행

setTimeout(() => {                   // 콜백을 "태스크 큐"에 등록만 하고 넘어감
  console.log('2. setTimeout(0ms)')
}, 0)

Promise.resolve().then(() => {       // 콜백을 "마이크로태스크 큐"에 등록만 하고 넘어감
  console.log('3. Promise then')
})

console.log('4. 동기 코드')          // 콜 스택에서 즉시 실행
```

<Steps>
### 동기 코드부터 순서대로 실행

'1. 동기 코드', '4. 동기 코드'가 먼저 출력된다. (setTimeout과 then은 콜백을 큐에 등록만 하고 즉시 다음 줄로 넘어간다)

### 콜 스택이 비었으니 마이크로태스크 큐 확인

Promise.then의 콜백이 마이크로태스크 큐에 있으므로 실행 → '3. Promise then' 출력

### 마이크로태스크 큐가 비었으니 태스크 큐 확인

setTimeout의 콜백을 실행 → '2. setTimeout(0ms)' 출력
</Steps>

**최종 순서: 1 → 4 → 3 → 2**

`setTimeout(fn, 0)`이라고 해서 0ms 후 "즉시" 실행되는 것이 아니라, "지금 실행 중인 모든 동기 코드와 모든 마이크로태스크가 끝난 뒤에" 실행됩니다.

## async/await도 결국 Promise다

29번 문서의 `await`는 마이크로태스크 큐를 사용하는 Promise 기반 문법입니다.

```js
console.log('A')

async function test() {
  console.log('B')
  await null              // 여기서 함수가 일시 정지되고, 이후 코드는 마이크로태스크로 예약됨
  console.log('C')        // 이 줄은 마이크로태스크 큐에서 나중에 실행됨
}

test()
console.log('D')

// 실행 순서: A → B → D → C
// (test 함수 안의 await 이전 코드는 동기적으로 즉시 실행되지만,
//  await를 만나는 순간 그 이후 코드는 마이크로태스크로 미뤄진다)
```

## 실전 교훈 — 왜 이 지식이 필요한가?

<Callout type="warning">
  **자주 만나는 실수:** 반복문 안에서 `setTimeout`으로 순서를 제어하려 하거나, Promise와 setTimeout이 섞인 코드의 실행 순서를 잘못 예측해서 생기는 버그가 많습니다. "동기 코드 → 마이크로태스크(Promise) → 매크로태스크(setTimeout)" 순서를 기억해두면, 복잡한 비동기 코드의 실행 순서를 정확히 예측할 수 있습니다.
</Callout>

이 지식은 13번 문서에서 다룬 "클로저와 반복문의 stale closure 문제", 07번 React 문서의 "useEffect 타이밍 문제" 같은 여러 실전 버그를 이해하는 토대가 됩니다.

## 핵심 정리

- 자바스크립트는 싱글 스레드로, 콜 스택에서 한 번에 하나의 작업만 처리한다.
- setTimeout 콜백은 태스크 큐(매크로태스크 큐)에, Promise의 then 콜백은 마이크로태스크 큐에 등록된다.
- 이벤트 루프는 콜 스택이 빌 때마다 마이크로태스크 큐를 모두 비운 뒤, 태스크 큐에서 하나씩 꺼내 처리한다.
- 마이크로태스크가 항상 매크로태스크보다 먼저 처리되므로, setTimeout(fn, 0)보다 Promise.then이 먼저 실행된다.
- async/await도 내부적으로 Promise와 마이크로태스크 큐를 사용한다.
