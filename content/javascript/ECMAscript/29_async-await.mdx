## async/await가 필요한 이유

28번 문서에서 배운 `.then()` 체이닝은 단계가 많아지면 코드가 옆으로 계속 늘어져 읽기 어려워집니다.

```js
// then 체이닝 — 단계가 늘어날수록 들여쓰기가 깊어짐
function loadUserData(id) {
  return fetchUser(id)
    .then(user => {
      return fetchPosts(user.id).then(posts => {
        return { user, posts }
      })
    })
}
```

**`async`/`await`**는 이 코드를 **동기 코드처럼 보이게** 재작성할 수 있게 해주는 문법입니다. 내부 동작은 Promise와 완전히 같습니다.

```js
// async/await — 위에서 아래로 순서대로 읽힘
async function loadUserData(id) {
  const user = await fetchUser(id)
  const posts = await fetchPosts(user.id)
  return { user, posts }
}
```

## async — 함수를 Promise를 반환하는 함수로 만들기

함수 앞에 `async`를 붙이면, 그 함수는 **항상 Promise를 반환**하게 됩니다.

```js
async function greet() {
  return '안녕하세요'
}

console.log(greet())  // Promise {<fulfilled>: '안녕하세요'} — 문자열이 아닌 Promise!
greet().then(result => console.log(result))  // '안녕하세요'
```

## await — Promise가 끝날 때까지 기다리기

`await`는 **async 함수 안에서만** 사용할 수 있습니다. Promise 앞에 붙이면, 그 Promise가 fulfilled될 때까지 함수 실행을 멈추고 기다린 뒤, 결과값을 꺼내줍니다.

## try/catch로 에러 처리하기

`.catch()` 대신, 일반 동기 코드처럼 `try/catch`(24번 문서)로 에러를 처리합니다.

```js
async function loadUserData(id) {
  try {
    const user = await fetchUser(id)
    const posts = await fetchPosts(user.id)
    return { user, posts }
  } catch (error) {
    console.log('데이터 로딩 실패:', error.message)
    return null
  }
}
```

`await`한 Promise가 reject되면, 그 지점에서 즉시 `catch` 블록으로 넘어갑니다. 여러 `await`를 하나의 `try` 블록으로 감싸면, 어느 단계에서 실패하든 한 곳에서 처리할 수 있습니다.

## 흔한 실수 — await 없이 쓰기

```js
async function loadUser(id) {
  const user = fetchUser(id)  // await를 빠뜨림!
  console.log(user)  // Promise {<pending>} — 아직 완료되지 않은 Promise 객체 자체가 출력됨
}
```

<Callout type="warning">
  `await`를 빠뜨리면 실제 결과값이 아니라 **아직 완료되지 않은 Promise 객체**를 얻게 됩니다. "왜 결과가 이상한 객체로 나오지?"라는 버그의 대부분은 `await`를 빠뜨린 경우입니다.
</Callout>

## 병렬 처리 — Promise.all과 함께 쓰기

28번 문서에서 배운 병렬 실행 원칙은 `async/await`에서도 그대로 적용됩니다. **서로 의존하지 않는 작업을 `await`로 하나씩 순서대로 기다리면 불필요하게 느려집니다.**

```js
// ❌ 느림 — 서로 의존하지 않는데 순차적으로 기다림 (총 2초)
async function loadSlowly() {
  const user = await fetchUser(1)      // 1초
  const config = await fetchConfig()   // 1초 (user와 무관한데도 순서대로 기다림)
  return { user, config }
}

// ✅ 빠름 — 동시에 시작해서 병렬로 처리 (총 1초)
async function loadFast() {
  const [user, config] = await Promise.all([fetchUser(1), fetchConfig()])
  return { user, config }
}
```

## async 화살표 함수

`async`는 화살표 함수 앞에도 붙일 수 있습니다.

```js
const loadUserData = async (id) => {
  const user = await fetchUser(id)
  return user
}
```

## 핵심 정리

- async 함수는 항상 Promise를 반환하며, 반환값은 자동으로 Promise로 감싸진다.
- await는 async 함수 안에서만 사용 가능하며, Promise가 끝날 때까지 기다린 뒤 결과값을 꺼낸다.
- try/catch로 await한 작업의 실패를 동기 코드와 같은 방식으로 처리할 수 있다.
- await를 빠뜨리면 결과값이 아닌 완료되지 않은 Promise 객체를 얻게 된다.
- 서로 의존하지 않는 작업은 await를 순서대로 여러 번 쓰지 말고 Promise.all로 병렬 처리해야 빠르다.
