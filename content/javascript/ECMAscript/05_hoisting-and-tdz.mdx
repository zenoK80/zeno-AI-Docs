</Callout>

## 왜 이 개념이 필요한가?

다음 코드를 예상해보세요.

```js
console.log(message)
var message = '안녕'
```

변수를 선언하기도 **전에** 사용했는데, 이 코드는 오류가 나지 않고 `undefined`를 출력합니다. 왜 그럴까요? 이 현상을 이해하려면 **호이스팅**(hoisting)이라는 개념이 필요합니다.

## 호이스팅이란?

> **쉽게 말하면:** 자바스크립트 엔진이 코드를 실행하기 전에, 변수와 함수의 "선언부"를 미리 코드 맨 위로 끌어올려(hoist, 끌어올리다) 놓고 시작하는 것처럼 동작하는 현상입니다.

실제로 코드가 물리적으로 이동하는 것은 아닙니다. 엔진이 코드를 실행하기 전, **먼저 코드를 훑으며 선언들을 미리 인식**해두기 때문에 마치 끌어올려진 것처럼 보이는 것입니다.

```js
// 우리가 쓴 코드
console.log(message)
var message = '안녕'

// 엔진이 인식하는 방식 (개념적으로)
var message      // 선언만 미리 끌어올려짐 (undefined로 초기화)
console.log(message)  // undefined
message = '안녕'  // 실제 대입은 원래 위치에서 실행
```

## var, let, const의 호이스팅 차이

세 키워드 모두 호이스팅이 일어나지만, **초기화되는 방식**이 다릅니다. 이 차이가 실제 동작의 차이를 만듭니다.

## TDZ(Temporal Dead Zone, 일시적 사각지대)란?

> **쉽게 말하면:** let·const로 선언된 변수는 "선언된 줄"에 도달하기 전까지, 이름은 존재하지만 손댈 수 없는 "죽은 구역"에 갇혀 있습니다.

```js
{
  // 이 지점부터 TDZ 시작 — score라는 이름은 이미 예약되어 있음
  console.log(score)  // ReferenceError: Cannot access 'score' before initialization
  let score = 90       // 이 줄에서 TDZ 종료, score 사용 가능해짐
  console.log(score)  // 90 — 정상 출력
}
```

**왜 TDZ가 존재할까?** `var`처럼 선언 전 접근 시 조용히 `undefined`를 내어주면, 오타나 순서 실수를 발견하기 어렵습니다. `let`/`const`는 대신 즉시 오류를 내서, "이 변수를 아직 쓸 준비가 안 됐다"는 사실을 개발자에게 바로 알려줍니다. TDZ는 버그를 숨기지 않고 드러내기 위한 안전장치입니다.

## 함수 선언의 호이스팅 — 완전히 다르다

**함수 선언문**(function declaration)은 변수와 달리 **선언과 내용 전체**가 호이스팅됩니다. 그래서 함수 선언 전에 호출해도 정상 동작합니다.

```js
greet()  // 정상 실행됨! '안녕하세요'

function greet() {
  console.log('안녕하세요')
}
```

반면 **함수 표현식**(function expression)은 변수에 담긴 값이므로, 변수 호이스팅 규칙을 그대로 따릅니다.

```js
greet2()  // TypeError: greet2 is not a function (var라서 undefined 상태로 호출 시도)

var greet2 = function () {
  console.log('안녕하세요')
}
```

## 자주 틀리는 점

<Callout type="warning">
  "let과 const는 호이스팅되지 않는다"는 설명을 흔히 보지만, 정확하지 않습니다. **호이스팅은 되지만, TDZ 때문에 초기화 전까지 접근할 수 없을 뿐**입니다. "호이스팅이 안 된다"가 아니라 "호이스팅은 되는데 안전장치가 걸려 있다"고 이해하는 것이 정확합니다.
</Callout>

## 실전 교훈 — 왜 이걸 알아야 하나?

이 지식의 실용적 결론은 간단합니다: **변수와 함수는 사용하기 전에 선언하세요.** 호이스팅에 의존해서 순서를 뒤죽박죽으로 쓰는 것은 코드를 읽기 어렵게 만들 뿐입니다. 다만 다음과 같은 상황에서는 이 지식이 실제로 버그를 해결하는 데 필요합니다.

- 오래된 `var` 기반 코드에서 "왜 undefined가 나오지?"를 디버깅할 때
- `let`/`const` 사용 중 `ReferenceError: Cannot access before initialization`를 만났을 때, 원인이 순서 문제임을 즉시 알아채기 위해

## 핵심 정리

- 호이스팅은 선언을 코드 실행 전에 미리 인식해두는 엔진의 동작 방식이다.
- `var`는 호이스팅되며 `undefined`로 자동 초기화된다.
- `let`/`const`도 호이스팅되지만 TDZ에 갇혀, 초기화 전 접근 시 `ReferenceError`가 발생한다.
- 함수 선언문은 본문 전체가 호이스팅되어 선언 전 호출이 가능하다. 함수 표현식은 변수 규칙을 따른다.
