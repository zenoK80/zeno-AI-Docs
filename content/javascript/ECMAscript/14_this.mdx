## this가 헷갈리는 이유

> **쉽게 말하면:** 다른 언어의 `this`(또는 `self`)는 보통 "그 클래스의 인스턴스"로 고정되어 있지만, 자바스크립트의 `this`는 **함수가 정의된 곳이 아니라 함수가 "호출되는 방식"에 따라 매번 달라집니다.**

이것이 자바스크립트 `this`가 유독 어렵게 느껴지는 이유입니다. 같은 함수라도 어떻게 호출하느냐에 따라 `this`가 다른 값을 가리킵니다.

## this를 결정하는 4가지 규칙

호출 방식을 보고 아래 순서대로 판단하면 `this`를 정확히 알 수 있습니다.

### 규칙 1 — 단독 호출: this는 전역 객체(또는 undefined)

```js
function showThis() {
  console.log(this)
}
showThis()  // 브라우저: window / strict mode: undefined
```

함수를 어떤 객체에도 속하지 않은 채로 그냥 호출하면, `this`는 전역 객체(브라우저의 `window`)를 가리킵니다. `'use strict'` 모드에서는 `undefined`입니다. 현재 자바스크립트 모듈은 기본적으로 strict mode이므로, 실무에서는 대부분 `undefined`를 보게 됩니다.

### 규칙 2 — 메서드 호출: this는 그 메서드를 호출한 객체

```js
const user = {
  name: '철수',
  greet() {
    console.log(this.name)  // this는 user를 가리킴
  },
}
user.greet()  // '철수'
```

**핵심은 "누가 점**(`.`) **앞에 있는가"입니다.** `user.greet()`처럼 호출하면, 점 앞의 `user`가 `this`가 됩니다.

```js
const admin = {
  name: '관리자',
  greet: user.greet,  // 같은 함수를 admin에도 연결
}
admin.greet()  // '관리자' — 같은 함수인데 호출 주체가 바뀌면 this도 바뀜!
```

<Callout type="warning">
  **메서드를 변수에 따로 빼서 호출하면 this를 잃어버립니다.**
  ```js
  const greetFn = user.greet
  greetFn()  // undefined — 점 앞에 아무 객체도 없이 "단독 호출"이 되어버림 (규칙 1 적용)
  ```
  이벤트 핸들러에 `onClick={user.greet}`처럼 메서드를 그대로 넘길 때 이 문제가 자주 발생합니다. React를 배울 때 다시 만나게 될 함정입니다.
</Callout>

### 규칙 3 — new로 호출: this는 새로 만들어지는 객체

```js
function Person(name) {
  this.name = name  // this는 new로 새로 생성되는 객체를 가리킴
}

const p1 = new Person('철수')
console.log(p1.name)  // '철수'
```

`new` 키워드로 함수를 호출하면, 자바스크립트는 빈 객체를 새로 만들고 `this`가 그 객체를 가리키게 합니다. (19번 클래스 문서에서 더 자세히 다룹니다.)

### 규칙 4 — 화살표 함수: this가 없다, 바깥 스코프의 this를 그대로 물려받는다

10번 문서에서 이미 배운 내용을 다시 확인합니다. 화살표 함수는 자신만의 `this`를 만들지 않고, **자신이 정의된 위치의 바깥 스코프 this를 그대로 사용**합니다.

## call, apply, bind — this를 직접 지정하기

자바스크립트는 `this`를 개발자가 **직접 지정**할 수 있는 방법도 제공합니다.

```js
function introduce() {
  console.log(`저는 ${this.name}입니다`)
}

const user1 = { name: '철수' }
const user2 = { name: '영희' }

// call: 인수를 하나씩 나열
introduce.call(user1)  // '저는 철수입니다'

// apply: 인수를 배열로 전달
introduce.apply(user2)  // '저는 영희입니다'

// bind: this가 고정된 새 함수를 반환 (즉시 실행 아님)
const boundIntroduce = introduce.bind(user1)
boundIntroduce()  // '저는 철수입니다' — 나중에 호출해도 항상 user1
```

`bind`는 특히 이벤트 핸들러에서 `this`를 고정할 때 자주 쓰입니다.

```js
const user = {
  name: '철수',
  greet() {
    console.log(this.name)
  },
}

const boundGreet = user.greet.bind(user)  // this를 user로 영구 고정
setTimeout(boundGreet, 1000)  // 1초 후에도 this는 여전히 user
```

## this 판단 순서 요약

<Steps>
### new로 호출되었는가?
→ this는 새로 생성된 객체 (규칙 3)

### call/apply/bind로 this가 명시적으로 지정되었는가?
→ this는 지정된 그 값

### 어떤 객체의 메서드로 호출되었는가? (점 앞에 객체가 있는가)
→ this는 점 앞의 그 객체 (규칙 2)

### 화살표 함수인가?
→ this가 없으며, 정의된 위치의 바깥 this를 그대로 사용 (규칙 4)

### 위 어느 것도 아니라면 (단독 호출)
→ this는 undefined(strict mode) 또는 전역 객체 (규칙 1)
</Steps>

## 핵심 정리

- this는 함수가 정의된 곳이 아니라 **호출되는 방식**에 따라 결정된다.
- 메서드로 호출하면(`obj.method()`) this는 점 앞의 객체다.
- 메서드를 변수에 빼서 단독 호출하면 this를 잃어버려 undefined가 된다.
- 화살표 함수는 자신만의 this가 없고, 정의된 위치의 바깥 this를 그대로 물려받는다.
- call/apply/bind로 this를 직접 지정할 수 있으며, bind는 this가 고정된 새 함수를 반환한다.
