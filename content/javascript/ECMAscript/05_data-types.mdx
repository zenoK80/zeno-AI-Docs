## 5. 데이터 타입

### 5.1 타입은 값의 종류다

숫자 `1`과 문자열 `'1'`은 화면에는 비슷하게 보여도 전혀 다른 값이다. 하나는 계산하려고 만든 값이고, 다른 하나는 글자로 보여주려고 만든 값이다. 이렇게 **값의 종류**를 데이터 타입, 줄여서 타입이라 한다.

> **데이터 타입(data type)**: 값의 종류. 자바스크립트의 모든 값은 반드시 하나의 타입을 가진다.

엔진이 타입을 구별하는 이유는 실용적이다. 값을 메모리에 저장할 때 **얼마만큼의 공간을 확보할지**, 저장된 값을 읽을 때 **그 비트를 어떻게 해석할지**가 타입에 따라 달라지기 때문이다. 같은 비트라도 숫자로 읽으면 `65`, 문자로 읽으면 `'A'`가 된다. 타입이 그 해석을 결정한다.

자바스크립트의 타입은 크게 두 갈래다. **원시 타입** 7가지와 **객체 타입**이다.

| 구분 | 타입 | 설명 |
| --- | --- | --- |
| 원시 타입 | number | 숫자. 정수·실수 구분 없이 하나뿐 |
| | string | 문자열(텍스트) |
| | boolean | `true` / `false` |
| | undefined | 값이 아직 없음(엔진이 초기화에 쓰는 값) |
| | null | 값이 없음을 의도적으로 나타냄 |
| | symbol | 절대 중복되지 않는 유일한 값 |
| | bigint | 아주 큰 정수 |
| 객체 타입 | object | 객체, 배열, 함수 등 원시 타입이 아닌 모든 것 |

원시 타입과 객체 타입은 값을 저장하고 다루는 방식이 근본적으로 다르다. 그 차이는 **13편(원시 값 vs 객체)** 에서 본격적으로 파고들고, 여기서는 각 타입이 어떤 값인지부터 익힌다.

### 5.2 숫자 타입 (number)

C나 자바는 정수용(`int`)과 실수용(`float`, `double`) 타입을 나누지만, 자바스크립트의 숫자 타입은 **하나뿐**이다. 내부적으로 모든 숫자를 64비트 실수(부동소수점) 형식으로 다룬다. 그래서 정수처럼 보이는 값도 사실은 실수다.

```js
console.log(1 === 1.0); // true — 1과 1.0은 같은 값이다
console.log(4 / 2);     // 2
console.log(3 / 2);     // 1.5 — 정수끼리 나눠도 실수가 나올 수 있다
```

숫자 타입에는 특별한 값 세 가지가 있다.

```js
console.log(10 / 0);     // Infinity   — 양의 무한대
console.log(-10 / 0);    // -Infinity  — 음의 무한대
console.log(1 * 'text'); // NaN        — Not a Number, 숫자로 계산할 수 없음
```

> **NaN(Not a Number)**: 숫자로 계산할 수 없는 연산의 결과를 나타내는 값. 이름과 달리 NaN 자체의 타입은 `number`다. NaN을 다루는 자세한 규칙은 **6편(연산자)**, **7편(타입 변환)** 에서 이어 본다.

### 5.3 문자열 타입 (string)

문자열은 텍스트를 나타내는 값이며, 작은따옴표(`''`), 큰따옴표(`""`), 백틱(`` `` ``) 중 하나로 감싼다. 실무에서는 작은따옴표를 가장 많이 쓴다.

```js
const single = 'Hello';
const double = "Hello";
const backtick = `Hello`;
```

따옴표로 감싸는 이유는 그것이 **글자 그대로의 값**임을 엔진에 알리기 위해서다. 감싸지 않으면 엔진은 그것을 변수 이름(식별자)으로 해석해 버린다.

```js
const greeting = hello; // ReferenceError — hello를 변수 이름으로 착각한다
```

한 가지 기억해 둘 점은, 문자열이 **변경 불가능한(immutable)** 값이라는 것이다. 한번 만들어진 문자열의 일부 글자만 바꾸는 것은 불가능하다.

```js
let str = 'hello';
str[0] = 'H';     // 조용히 무시된다 (엄격 모드에서는 에러)
console.log(str); // 'hello' — 그대로다
```

글자를 바꾸고 싶다면 새 문자열을 만들어 다시 할당하는 수밖에 없다. 이 "원시 값은 못 바꾼다"는 성질도 13편에서 객체와 비교하며 다시 다룬다.

### 5.4 템플릿 리터럴

백틱(`` `` ``)으로 감싼 문자열을 템플릿 리터럴이라 하며, 일반 문자열에 없는 두 가지 편의 기능을 제공한다.

첫째, **여러 줄 문자열**을 그대로 쓸 수 있다. 일반 문자열에서는 줄바꿈에 `\n` 같은 이스케이프 시퀀스를 써야 하지만, 템플릿 리터럴 안에서는 줄을 바꾼 모양 그대로 저장된다.

```js
// 일반 문자열 — 줄바꿈을 \n으로 표현
const a = '첫째 줄\n둘째 줄';

// 템플릿 리터럴 — 보이는 그대로 줄바꿈이 반영된다
const b = `첫째 줄
둘째 줄`;
```

> 자주 쓰는 이스케이프 시퀀스: `\n`(줄바꿈), `\t`(탭), `\'` `\"`(따옴표 자체), `\\`(백슬래시 자체).

둘째, **표현식 삽입(interpolation)** 이다. `${ }` 안에 표현식을 넣으면 평가된 값이 문자열에 끼워 넣어진다.

```js
const first = 'Ada';
const last = 'Lovelace';

// 예전 방식: + 로 이어 붙이기
console.log('My name is ' + first + ' ' + last + '.');

// 템플릿 리터럴: 훨씬 읽기 쉽다
console.log(`My name is ${first} ${last}.`);
console.log(`1 + 2 = ${1 + 2}`); // 1 + 2 = 3 — 안에서 계산도 된다
```

`${ }`는 **템플릿 리터럴 안에서만** 동작한다. 일반 따옴표 문자열 안의 `${ }`는 그냥 글자로 취급된다.

### 5.5 불리언 타입 (boolean)

불리언은 참과 거짓을 나타내며 값은 `true`와 `false` 둘뿐이다. 주로 조건을 판단해 프로그램의 흐름을 나누는 데 쓰인다. 이 값들이 실제로 어떻게 흐름을 제어하는지는 **8편(제어문)** 에서 본다.

```js
const isOpen = true;
const isEmpty = false;
```

### 5.6 undefined와 null

이 둘은 모두 "값이 없다"는 상황을 나타내지만, 성격이 다르다.

**undefined** 는 변수를 선언만 하고 값을 넣지 않았을 때 엔진이 자동으로 채워 넣는 값이다. 즉 "아직 값이 할당된 적 없음"을 뜻한다.

```js
let name;
console.log(name); // undefined — 선언만 했을 뿐 값을 넣지 않았다
```

undefined는 엔진이 쓰라고 마련해 둔 값이므로, 개발자가 직접 할당하는 것은 권장하지 않는다. "값이 없음"을 **의도적으로** 표현하고 싶을 때는 대신 **null** 을 쓴다.

```js
let selectedUser = null; // "지금은 선택된 사용자가 없다"를 의도적으로 표현
```

값을 찾지 못했음을 알리려고 null을 반환하는 함수도 많다. 예를 들어 화면에서 특정 요소를 찾는 기능은, 찾지 못하면 에러 대신 null을 돌려준다.

> **undefined vs null**
> - `undefined`: "아직 값이 할당된 적 없음" — 엔진이 알려주는 상태
> - `null`: "값이 없음을 내가 의도했음" — 개발자가 밝히는 의도

### 5.7 symbol과 bigint

나머지 두 원시 타입은 특수한 상황에서 쓰인다. 지금은 "이런 게 있다" 정도만 알아두면 된다.

**symbol** 은 생성할 때마다 세상에 하나뿐인, 절대 중복되지 않는 값을 만들어낸다. 설명 라벨이 같아도 서로 다른 값이다.

```js
const a = Symbol('id');
const b = Symbol('id');
console.log(a === b); // false — 라벨이 같아도 서로 다른 유일한 값이다
```

주로 다른 이름과 충돌하지 않는 객체의 프로퍼티 키를 만들 때 쓰이며, 자세한 쓰임새는 **29편(Symbol과 이터러블)** 에서 다룬다.

**bigint** 는 숫자 타입이 안전하게 표현할 수 있는 범위를 넘어서는, 아주 큰 정수를 다루기 위한 타입이다. 정수 뒤에 `n`을 붙여 만든다.

```js
const big = 9007199254740993n;
console.log(typeof big); // bigint
```

일반적인 계산에서는 거의 만날 일이 없으므로, 지금은 존재만 기억하면 충분하다.

### 5.8 객체 타입

지금까지 본 7가지 원시 타입을 제외한 나머지 값은 **모두 객체 타입**이다. 객체는 물론이고 배열도, 함수도 전부 객체다.

```js
const user = { name: 'Ada', age: 30 }; // 객체
const nums = [1, 2, 3];                // 배열도 객체
function greet() {}                    // 함수도 객체
```

> 자바스크립트는 객체 기반의 언어이며, 이를 이루는 거의 모든 것이 객체다.

원시 타입과 객체 타입은 **저장 방식과 변경 가능 여부**가 근본적으로 다르다. 원시 값은 바꿀 수 없고 값 자체가 복사되지만, 객체는 내용을 바꿀 수 있고 그 위치(참조)가 공유된다. 이 차이를 모르면 "객체를 복사했는데 원본까지 바뀌었다" 같은 버그의 원인을 찾지 못한다. 객체의 구조와 사용법은 **12편(객체 리터럴)**, 원시 값과의 결정적 차이는 **13편(원시 값 vs 객체)** 에서 이어서 본다.

### 5.9 동적 타이핑

C나 자바 같은 언어는 변수를 선언할 때 그 변수에 담길 값의 타입을 미리 정해야 한다. 반면 자바스크립트는 타입을 미리 선언하지 않는다. `let`이나 `const`로 선언만 하면, 어떤 타입의 값이든 자유롭게 담을 수 있다.

```js
let x = 3;        // 지금은 number
x = 'three';      // 이제 string
x = true;         // 이제 boolean
```

값의 타입은 `typeof` 연산자로 확인할 수 있다.

```js
console.log(typeof 3);              // 'number'
console.log(typeof 'hi');           // 'string'
console.log(typeof true);           // 'boolean'
console.log(typeof undefined);      // 'undefined'
console.log(typeof {});             // 'object'
console.log(typeof []);             // 'object'    — 배열도 객체
console.log(typeof function () {}); // 'function'
console.log(typeof null);           // 'object'    — null인데 'object'가 나온다
```

마지막 줄은 언어 초기부터 있던 유명한 버그다. `null`은 원시 값인데도 `typeof`가 `'object'`를 돌려준다. 고치면 기존 코드가 깨지기 때문에 지금까지 그대로 남아 있다. 이런 특이 동작이 있다는 정도만 기억해 두자.

여기서 이 편의 결론이 나온다. `typeof`가 돌려주는 것은 **변수의 타입이 아니라, 변수에 담긴 값의 타입**이다.

<Callout type="default">
변수는 타입을 갖지 않는다. **값이 타입을 가진다.** 변수의 타입은 담긴 값에 따라 정해지고, 재할당에 따라 언제든 바뀐다. 이것을 **동적 타이핑**이라 한다.
</Callout>

이 유연함은 편리하지만, 값의 타입이 도중에 바뀔 수 있어 프로그램이 커질수록 값을 추적하기 어려워진다는 단점도 있다. 그래서 **3편**에서 본 "기본은 `const`" 원칙과 "의미가 드러나는 이름 짓기"가 이 유연함을 다루는 안전장치가 된다.

## 이번 편 핵심 요약

1. 타입은 값의 종류다. 자바스크립트에는 **원시 타입 7가지(number, string, boolean, undefined, null, symbol, bigint)** 와 **객체 타입**이 있다.
2. 숫자 타입은 하나뿐이며 모든 수를 실수로 다룬다. `Infinity`, `-Infinity`, `NaN`이라는 특별한 값이 있다.
3. 문자열은 따옴표로 감싸며 **변경 불가능**하다. 백틱으로 감싼 **템플릿 리터럴**은 여러 줄 문자열과 `${ }` 표현식 삽입을 지원한다.
4. **`undefined`** 는 "값이 할당된 적 없음"(엔진의 상태), **`null`** 은 "값이 없음을 의도함"(개발자의 의도)이다.
5. 원시 타입을 제외한 모든 값은 객체다. 원시 값과 객체의 저장·변경 방식 차이는 13편에서 다룬다.
6. 변수는 타입을 갖지 않고 **값이 타입을 가진다.** 값에 따라 타입이 정해지고 재할당으로 바뀌는 것이 **동적 타이핑**이며, `typeof`는 담긴 값의 타입을 알려준다.
