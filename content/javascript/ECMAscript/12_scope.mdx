## 스코프란?

> **쉽게 말하면:** 스코프(scope, 범위)는 "변수를 사용할 수 있는 코드상의 영역"입니다. 변수는 아무 데서나 보이는 게 아니라, 정해진 범위 안에서만 보입니다.

```js
function sayHello() {
  const message = '안녕'
  console.log(message)  // OK — message가 선언된 함수 내부
}

sayHello()
console.log(message)  // ReferenceError! — message는 함수 밖에서 안 보임
```

### 전역 스코프

함수나 블록 밖에서 선언된 변수는 파일 어디서든 접근할 수 있습니다.

```js
const siteName = 'Zeno Docs'  // 전역

function printSiteName() {
  console.log(siteName)  // 함수 안에서도 접근 가능
}
printSiteName()  // 'Zeno Docs'
```

### 함수 스코프

함수 안에서 선언한 변수는 그 함수 내부에서만 유효합니다.

```js
function calculate() {
  const result = 100  // 함수 스코프
  console.log(result)
}
calculate()
console.log(result)  // ReferenceError
```

### 블록 스코프 — let/const만 해당

`{ }`로 둘러싸인 모든 곳(if, for, while, 또는 단독 블록)이 블록 스코프를 만듭니다. `let`, `const`만 이 규칙을 따르고, 4번 문서에서 배웠듯 `var`는 블록을 무시합니다.

## 스코프 체인 — 바깥에서 안쪽으로 찾는다

함수가 중첩되면, 안쪽 함수는 자신의 스코프에 없는 변수를 **바깥 스코프에서 순서대로** 찾습니다. 이 연결 구조를 **스코프 체인**(scope chain)이라고 부릅니다.

```js
const level1 = '전역'

function outer() {
  const level2 = '외부 함수'

  function inner() {
    const level3 = '내부 함수'
    console.log(level3)  // 자기 스코프에서 바로 찾음
    console.log(level2)  // 자기 스코프에 없음 → 바깥(outer)에서 찾음
    console.log(level1)  // outer에도 없음 → 더 바깥(전역)에서 찾음
  }

  inner()
}

outer()
```

> **비유:** 스코프 체인은 집 안에서 물건을 찾는 것과 비슷합니다. 내 방(inner)에 없으면 거실(outer)을 보고, 거실에도 없으면 집 전체(전역)를 봅니다. 하지만 **반대는 안 됩니다** — 거실에 있는 사람이 내 방 서랍 속 물건을 마음대로 못 보는 것처럼, 바깥 스코프는 안쪽 스코프의 변수를 볼 수 없습니다.

```js
function outer() {
  const secret = '외부의 비밀'

  function inner() {
    const innerSecret = '내부의 비밀'
  }

  inner()
  console.log(innerSecret)  // ReferenceError! — outer는 inner 내부를 볼 수 없음
}
```

## 스코프는 "어디서 정의됐는지"로 정해진다 — 렉시컬 스코프

자바스크립트의 스코프는 함수가 **호출된 위치**가 아니라 **정의된 위치**를 기준으로 결정됩니다. 이를 **렉시컬 스코프**(lexical scope, 정적 스코프)라고 부릅니다.

```js
const x = '전역 x'

function printX() {
  console.log(x)  // printX가 "정의된" 위치(전역) 기준으로 x를 찾음
}

function wrapper() {
  const x = 'wrapper의 x'
  printX()  // 여기서 "호출"되지만, x는 여전히 '전역 x'가 출력됨
}

wrapper()  // '전역 x' — wrapper 안에서 호출했지만 wrapper의 x는 무시됨
```

`printX`가 `wrapper` 안에서 **호출**되었다고 해서 `wrapper`의 `x`를 쓰지 않습니다. `printX`가 **정의**된 위치(전역)의 스코프 체인을 그대로 따릅니다. 이 원리는 다음 문서인 클로저를 이해하는 핵심 토대가 됩니다.

## 변수 섀도잉(Shadowing)

안쪽 스코프에서 바깥과 같은 이름의 변수를 선언하면, 안쪽에서는 안쪽 변수가 바깥 것을 "가립니다".

```js
const color = '빨강'

function printColor() {
  const color = '파랑'  // 바깥의 color를 가림(shadow)
  console.log(color)    // '파랑' — 가까운 스코프의 것을 먼저 찾음
}

printColor()
console.log(color)  // '빨강' — 바깥 color는 영향받지 않음
```

## 핵심 정리

- 전역 스코프는 파일 전체, 함수 스코프는 함수 내부, 블록 스코프는 `{}` 내부를 범위로 갖는다.
- `let`/`const`는 블록 스코프를 따르지만 `var`는 블록을 무시하고 함수 스코프를 따른다.
- 스코프 체인은 안쪽에서 바깥쪽으로만 변수를 찾을 수 있고, 반대는 불가능하다.
- 자바스크립트는 렉시컬 스코프를 사용해 함수가 **정의된** 위치를 기준으로 스코프가 결정된다(호출 위치 아님).
- 안쪽 스코프의 같은 이름 변수는 바깥 변수를 가린다(섀도잉).
