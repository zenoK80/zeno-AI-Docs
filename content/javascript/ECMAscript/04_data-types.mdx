## JavaScript의 타입 시스템

JavaScript는 **동적 타이핑**(dynamic typing) 언어입니다. 변수에 타입을 선언하지 않고, 값 자체가 타입을 가집니다. 같은 변수에 다른 타입의 값을 재할당할 수도 있습니다.

```js
let value = 42        // number
value = '마흔둘'      // string
value = true          // boolean
```

## 원시 타입 7가지

ECMAScript는 7가지 **원시 타입**(primitive type) 을 정의합니다.

| 타입 | 예 | 설명 |
| --- | --- | --- |
| `number` | `42`, `3.14`, `NaN`, `Infinity` | 정수와 실수, 특수 숫자 |
| `string` | `'hello'`, `"world"`, `` `이름: ${name}` `` | 문자 시퀀스 |
| `boolean` | `true`, `false` | 참·거짓 |
| `null` | `null` | 값이 없음을 의도적으로 표현 |
| `undefined` | `undefined` | 값이 할당되지 않음 |
| `symbol` | `Symbol('id')` | 고유하고 변경 불가능한 식별자 |
| `bigint` | `9007199254740991n` | 아주 큰 정수 |

원시 값은 **불변**(immutable) 입니다. 문자열 `'hello'`의 첫 글자를 직접 바꿀 수 없습니다.

```js
let str = 'hello'
str[0] = 'H'         // 조용히 무시됨
console.log(str)     // 'hello'
```

## typeof 연산자

`typeof` 연산자는 값의 타입을 문자열로 반환합니다. 아래 코드를 직접 수정해가며 각 값의 타입을 확인해보세요.

<Callout type="warning">
  `typeof null`이 `'object'`를 반환하는 것은 JavaScript의 오래된 버그입니다. `null`인지 확인하려면 `=== null`을 사용합니다.
</Callout>

## null vs undefined

두 값 모두 "없음"을 나타내지만 의미가 다릅니다.

```js
let a             // 선언만 하면 undefined
let b = null      // 개발자가 의도적으로 없음을 표현

console.log(a)    // undefined
console.log(b)    // null
```

| | null | undefined |
| --- | --- | --- |
| 의미 | 의도적으로 비워 둔 값 | 아직 값이 없음 |
| 할당 | 개발자가 직접 | 엔진이 자동으로 |
| typeof | `'object'` | `'undefined'` |

## 동적 타이핑의 주의점

```js
console.log(1 + '2')    // '12' (number + string → string)
console.log('5' - 3)    // 2 (string → number 암묵 변환)
```

타입이 자동으로 변환되기 때문에 예상치 못한 결과가 나올 수 있습니다. 타입 변환에 대해서는 07번 문서에서 자세히 다룹니다.

## 핵심 정리

- JavaScript는 값 자체가 타입을 가지는 동적 타이핑 언어입니다.
- 원시 타입은 number, string, boolean, null, undefined, symbol, bigint 7가지입니다.
- `typeof null`은 역사적 버그로 `'object'`를 반환하므로 null 검사에는 `=== null`을 씁니다.
