## 변수와 상수

1편에서 자판기 예시로 "합계를 기억해야 한다"고 했다.
값을 기억해 두는 상자, 그게 **변수**<sup>Variable</sup>다.

## 변수 선언하기

자바스크립트에서 변수는 `let`으로 만든다.

```js
let age = 20
console.log(age)   // 20

age = 21            // 값을 바꿀 수 있다
console.log(age)   // 21
```

- `let age = 20` — **선언**<sup>Declaration</sup>(상자를 만듦)과 **초기화**<sup>Initialization</sup>(값을 넣음)를 동시에 했다
- `age = 21` — `let` 없이 다시 쓰면 **값을 바꾸는 것**(재할당)이다

<Callout type="info">
`=`는 수학의 "같다"가 아니라 **"오른쪽 값을 왼쪽 이름에 넣어라"** 는 명령이다. `age = age + 1`이 수학적으로는 성립하지 않지만 코드에서는 자연스러운 이유다.
</Callout>

## 상수 선언하기

바뀌지 않아야 하는 값에는 `const`를 쓴다.

```js
const MAX_USERS = 100
MAX_USERS = 200   // TypeError: Assignment to constant variable.
```

<Callout type="important">
**기본은 `const`, 값이 바뀌어야 할 때만 `let`으로 바꾼다.**

이렇게 하면 두 가지 이점이 생긴다.
- 나중에 코드를 읽는 사람이 "이 값은 절대 안 바뀐다"고 안심할 수 있다
- 실수로 값을 덮어써서 생기는 버그를 애초에 차단한다
</Callout>

## 왜 var는 쓰지 않는가

오래된 코드에는 `let`, `const` 대신 `var`가 보인다. ES6(2015) 이전에는 이것밖에 없었기 때문이다.

```js
var age = 20   // 옛날 방식 — 지금은 쓰지 않는다
```

<Callout type="warning">
`var`는 두 가지 문제가 있다.

1. **같은 이름으로 여러 번 선언해도 에러가 안 난다** — 실수로 변수를 덮어써도 알 수 없다
2. **블록(`{ }`) 안에서 선언해도 밖에서 접근된다** — 의도치 않은 범위까지 값이 새어 나간다

```js
var x = 1
var x = 2   // 에러 없이 그냥 덮어써진다

if (true) {
  var y = 10
}
console.log(y)   // 10 — 블록 밖인데도 접근된다
```

`let`/`const`는 둘 다 막아준다. `var`가 왜 이렇게 동작하는지, 그리고 정말 필요한 경우가 있는지는 45편(레거시 패턴)에서 자세히 다룬다. 지금은 **"쓰지 않는다"** 정도만 기억하면 된다.
</Callout>

## 변수 이름 짓는 규칙

### 문법적으로 지켜야 하는 것

```js
let name = 'A'       // OK
let _private = 'B'   // OK — 밑줄로 시작 가능
let $element = 'C'   // OK — 달러 기호로 시작 가능
let 이름 = 'D'         // OK — 한글도 가능하지만 권장하지 않는다

let 1st = 'E'         // 에러 — 숫자로 시작 불가
let my-name = 'F'     // 에러 — 하이픈은 뺄셈으로 해석됨
let const = 'G'       // 에러 — 예약어는 이름으로 못 씀
```

### 관례적으로 지키는 것

문법 오류는 아니지만, 실무에서 거의 예외 없이 따르는 규칙이 있다.

| 대상 | 스타일 | 예시 |
| --- | --- | --- |
| 일반 변수·함수 | camelCase | `userName`, `getTotal` |
| 상수(진짜 안 바뀌는 값) | UPPER_SNAKE_CASE | `MAX_USERS`, `API_KEY` |
| 클래스 | PascalCase | `UserProfile` (18편에서 다룸) |

<Callout type="info">
`const`로 선언했다고 전부 `UPPER_SNAKE_CASE`로 쓰는 건 아니다. 함수 안에서 잠깐 쓰는 `const total = ...`은 그냥 camelCase다.
UPPER_SNAKE_CASE는 **프로그램 전체에서 의미가 고정된 값**(설정값, 상한선 등)에 관례적으로 쓴다.
</Callout>

## 선언만 하고 나중에 값 넣기

`let`은 선언과 초기화를 분리할 수 있다. `const`는 안 된다.

```js
let score          // 선언만
score = 0          // 나중에 초기화

const total        // SyntaxError: Missing initializer in const declaration
```

<Callout type="important">
`const`는 "재할당 금지"이지 "선언 즉시 값이 필요 없음"이 아니다. **선언과 동시에 반드시 값을 줘야 한다.**
</Callout>

## const인데 내용이 바뀐다?

`const`가 막는 건 **"상자 자체를 다른 상자로 바꾸는 것"** 이지, 상자 안 내용물까지 얼리는 게 아니다.

```js
const user = { name: '지민' }
user.name = '민준'          // OK — 객체 내부 값 변경은 가능
console.log(user)            // { name: '민준' }

user = { name: '다른 사람' }  // TypeError — 상자 자체를 바꾸려 함
```

<Callout type="info">
왜 이렇게 동작하는지는 객체와 원시 값의 차이를 알아야 정확히 이해된다. 13편(원시 값 vs 객체)에서 원리부터 다룬다.
지금은 "`const`는 객체의 내용까지 막지는 않는다"는 사실만 기억해 두자.
</Callout>

## 정리

<Callout type="default">
- 변수는 값을 담는 상자다. `let`으로 선언한다
- 값이 바뀌지 않아야 하면 `const`를 쓴다 — **기본은 `const`**
- `var`는 예상치 못한 동작이 많아 더 이상 쓰지 않는다
- 이름은 camelCase가 기본이고, 숫자로 시작할 수 없다
- `const`는 재할당만 막을 뿐, 객체 내부 값 변경은 막지 않는다
</Callout>

다음 편에서는 `age + 1`처럼 값을 계산하는 **표현식**과, 그 계산을 담는 **문**의 차이를 본다.
