## 3. 변수와 상수

### 3.1 값에 이름 붙이기

프로그램은 결국 값을 계산하고 옮기는 일이다. 그런데 계산으로 만들어낸 값을 나중에 다시 쓰려면 그 값을 어딘가에 담아두고 부를 이름이 있어야 한다. 이름이 없으면 방금 구한 결과에 다시 손을 뻗을 방법이 없다.

```js
console.log(2 + 3); // 5
// 방금 만든 5를 다시 쓰고 싶어도 부를 이름이 없다
```

이때 쓰는 것이 변수다. 값에 이름을 붙여두면, 그 이름으로 값을 몇 번이고 꺼내 쓸 수 있다.

> **변수(variable)**: 값을 저장해 두고 재사용하기 위해 붙인 이름. 값은 컴퓨터의 메모리에 저장되고, 변수는 그 값이 놓인 자리를 가리키는 이름표라고 보면 된다.

이름표라는 점이 중요하다. 변수는 값 자체가 아니라 **값이 있는 위치**를 가리킨다. 그래서 같은 값에 여러 이름을 붙일 수도 있고, 이름이 가리키는 대상을 나중에 바꿀 수도 있다.

### 3.2 변수 선언과 할당

변수를 쓰려면 먼저 "이런 이름의 변수를 만들겠다"고 알려야 한다. 이것을 **선언**이라 하고, 모던 자바스크립트에서는 `let` 키워드를 쓴다.

```js
let message; // 선언: message라는 변수를 만든다
```

> **키워드(keyword)**: 자바스크립트에 미리 약속된 명령어. `let`을 만나면 엔진은 뒤에 오는 이름으로 새 변수를 만든다.

선언한 변수에 값을 넣는 것은 **할당**이며, 등호(`=`)를 쓴다. 등호 오른쪽 값이 왼쪽 변수로 들어간다.

```js
let message;        // 선언
message = 'Hello';  // 할당
console.log(message); // 참조 → 'Hello'
```

저장된 값을 꺼내 읽는 것은 **참조**다. 위에서 `console.log(message)`가 하는 일이 참조다.

선언과 할당은 한 줄로 합칠 수 있고, 실무에서는 대부분 이렇게 쓴다.

```js
let message = 'Hello'; // 선언과 할당을 한 번에
```

이미 값이 있는 변수에 다른 값을 다시 넣는 것은 **재할당**이다.

```js
let message = 'Hello';
message = 'Goodbye'; // 재할당
console.log(message); // 'Goodbye'
```

값을 이렇게 바꿀 수 있어서 "변하는 수", 곧 변수다. 참고로 변수 이름은 **식별자(identifier)** 라고도 부른다. 어떤 값을 다른 값과 구별해 가리키는 고유한 이름이라는 뜻이다.

한 줄에 여러 변수를 쉼표로 선언할 수도 있지만, 읽기 어려워지므로 한 줄에 하나씩 선언하는 편이 낫다.

```js
let a = 1, b = 2, c = 3; // 가능하지만 비권장

let a = 1;
let b = 2;
let c = 3;
```

### 3.3 상수: const

값 중에는 프로그램이 도는 동안 절대 바뀌면 안 되는 것들이 있다. 원주율, 세율, 최대 재시도 횟수 같은 고정값이다. 이런 값은 `const`로 선언한다.

```js
const PI = 3.14;
```

`const`로 선언한 변수는 **재할당이 금지**된다. 다시 값을 넣으려 하면 에러가 난다.

```js
const PI = 3.14;
PI = 3; // TypeError: Assignment to constant variable.
```

이렇게 재할당이 막혀 값이 고정되는 변수를 **상수(constant)** 라 부른다. 값이 하나로 정해져 있으므로, `const`는 선언과 동시에 반드시 값을 넣어줘야 한다.

```js
const answer; // SyntaxError: Missing initializer in const declaration
```

상수의 진짜 쓸모는 안전함과 가독성이다. 코드 곳곳에 흩어진 숫자에 이름을 붙이면 의미가 드러나고, 값을 한곳에서만 관리하게 된다.

```js
// 0.1이 무슨 값인지 코드만 봐서는 알 수 없다
const price = base + base * 0.1;

// 이름을 붙이면 의미가 분명해지고, 세율이 바뀌어도 한 줄만 고치면 된다
const TAX_RATE = 0.1;
const price = base + base * TAX_RATE;
```

> `const`에 객체를 넣으면 이야기가 조금 달라진다. 재할당은 여전히 막히지만 객체 **내부** 값은 바꿀 수 있다. 이 미묘한 차이는 값의 종류를 다루는 **13편(원시 값 vs 객체)** 에서 자세히 본다. 지금은 "숫자·문자열 같은 값을 `const`에 넣으면 그대로 고정된다"까지만 기억하면 된다.

### 3.4 const를 기본으로

변수를 선언하는 방법은 사실 `let`, `const` 말고 `var`도 있다. `var`는 예전에 쓰던 방식인데 헷갈리기 쉬운 함정이 많아, 지금은 특별한 이유가 없으면 쓰지 않는다. `var`의 정체와 문제점은 **45편(var와 레거시 패턴)** 에서 따로 다룬다. 이 시리즈에서는 `let`과 `const`만 쓴다.

그럼 둘 중 언제 무엇을 쓸까. 실전 규칙은 간단하다.

| 키워드 | 재할당 | 언제 쓰나 |
| --- | --- | --- |
| `const` | 불가 | **기본값.** 값이 바뀌지 않는 대부분의 경우 |
| `let` | 가능 | 값이 **재할당되어야** 하는 경우에만 |
| `var` | 가능 | 쓰지 않는다 (45편) |

<Callout type="default">
**일단 `const`로 선언하고, 재할당이 꼭 필요할 때만 `let`으로 바꾼다.**
</Callout>

이렇게 하는 이유가 있다. 재할당을 막아두면 실수로 값이 바뀌는 버그가 줄고, 코드를 읽는 사람도 "이 값은 앞으로 안 바뀐다"는 것을 한눈에 알 수 있다. 선언하는 순간에는 나중에 값을 바꿀지 아닐지 애매한 경우가 많은데, 그럴 때는 더 안전한 `const`로 시작하면 된다. 정말 재할당이 필요해지는 순간 `let`으로 고쳐도 전혀 늦지 않다.

```js
const name = 'Ada'; // 안 바뀌는 값 → const

let count = 0; // 반복하며 늘어나는 값 → let
count = count + 1;
```

### 3.5 선언보다 먼저 쓸 수 없다

`let`과 `const`로 선언한 변수는 **선언하는 줄에 도달하기 전에는 사용할 수 없다.** 선언보다 먼저 참조하면 에러가 난다.

```js
console.log(message); // ReferenceError: Cannot access 'message' before initialization
let message = 'Hello';
```

그래서 규칙은 단순하다. **변수는 위에서 선언하고, 아래에서 사용한다.** 코드를 위에서 아래로 읽는 순서대로 작성하면 이 문제를 겪을 일이 거의 없다.

```js
let message = 'Hello'; // 먼저 선언
console.log(message);  // 그다음 사용 → 'Hello'
```

> 왜 그냥 "값 없음"이 아니라 에러가 나는지는 자바스크립트가 코드를 실행하기 전에 선언을 먼저 훑는 **호이스팅**이라는 동작과 관련이 있다. 이 원리는 **10편(스코프)** 과 **19편(실행 컨텍스트)** 에서 제대로 파고든다. 지금은 "선언보다 먼저 쓰면 에러"라는 결과만 알아두면 충분하다.

### 3.6 이름 짓기: 규칙과 컨벤션

변수 이름은 아무렇게나 지을 수 없다. 먼저 **반드시 지켜야 하는 규칙**이 있고, 어기면 문법 에러(SyntaxError)가 난다.

- 문자, 숫자, 언더스코어(`_`), 달러 기호(`$`)만 쓸 수 있다.
- **숫자로 시작할 수 없다.**
- **예약어**(`let`, `const`, `if`, `for`, `return`, `class` 등 자바스크립트가 이미 쓰는 단어)는 이름으로 쓸 수 없다.
- **대소문자를 구별한다.** `age`, `Age`, `AGE`는 서로 다른 변수다.

```js
let 1st;     // SyntaxError: 숫자로 시작 불가
let my-name; // SyntaxError: 하이픈 사용 불가
let return;  // SyntaxError: 예약어
```

규칙을 지켰다면, 그다음은 **좋은 이름**을 고르는 문제다. 좋은 이름은 그 변수에 무엇이 들었는지 이름만 보고도 알 수 있는 이름이다.

```js
let x = 100;     // x가 뭔지 알 수 없다
let score = 100; // 점수라는 게 바로 보인다
```

주석을 달아야만 뜻이 통하는 이름이라면, 그 이름은 아직 제 역할을 못 하고 있는 것이다.

마지막으로, 여러 단어를 이어 붙일 때의 표기 방식인 **컨벤션**이 있다. 문법이 강제하는 규칙은 아니지만, 자바스크립트 세계에서 널리 통용되는 약속이라 따르는 편이 좋다.

| 대상 | 표기 방식 | 예시 |
| --- | --- | --- |
| 변수, 함수 | 카멜 케이스 (`camelCase`) | `userName`, `getTotal` |
| 클래스, 생성자 | 파스칼 케이스 (`PascalCase`) | `User`, `OrderList` |
| 고정 설정값(상수) | 대문자 스네이크 케이스 | `TAX_RATE`, `MAX_COUNT` |

카멜 케이스는 첫 단어는 소문자로, 이어지는 단어의 첫 글자만 대문자로 쓰는 방식이다. 변수와 함수에는 이 방식을 기본으로 쓴다. 클래스와 생성자에 쓰는 파스칼 케이스는 **9편(함수 기초)** 과 **18편(클래스)** 에서, 대문자 스네이크로 쓰는 상수는 앞서 3.3에서 본 세율 예시처럼 "절대 바뀌지 않는 설정값"에 주로 쓴다.

## 이번 편 핵심 요약

1. **변수**는 값에 붙인 이름이다. 값 자체가 아니라 값이 놓인 위치를 가리키며, 그래서 재할당으로 가리키는 값을 바꿀 수 있다.
2. **선언**(`let`), **할당**(`=`), **참조**(값 읽기), **재할당**(값 다시 넣기)은 서로 다른 동작이다.
3. **`const`** 는 재할당이 금지된 변수(상수)이며, 선언과 동시에 값을 넣어야 한다. 고정값에 이름을 붙이면 안전성과 가독성이 함께 올라간다.
4. 실전 규칙: **기본은 `const`, 재할당이 꼭 필요할 때만 `let`, `var`는 쓰지 않는다.**
5. `let`/`const` 변수는 **선언보다 먼저 쓸 수 없다.** 변수는 위에서 선언하고 아래에서 사용한다.
6. 이름은 규칙(숫자 시작·예약어 금지, 대소문자 구별)을 지키되, **주석 없이도 뜻이 통하는 이름**을 고르고 컨벤션(`camelCase` 등)을 따른다.
