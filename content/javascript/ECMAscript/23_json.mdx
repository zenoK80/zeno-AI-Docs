## JSON이 필요한 이유

> **쉽게 말하면:** 자바스크립트 객체는 자바스크립트 안에서만 이해되는 형태입니다. 다른 프로그램(서버, 다른 언어)과 데이터를 주고받으려면, 모두가 이해할 수 있는 "공통 텍스트 형식"이 필요합니다. 그 형식이 JSON입니다.

**JSON**(JavaScript Object Notation)은 이름 그대로 자바스크립트 객체 문법에서 유래했지만, 지금은 언어에 상관없이 데이터를 주고받는 **표준 텍스트 형식**입니다. 웹에서 서버와 브라우저가 데이터를 주고받을 때 거의 항상 JSON을 사용합니다.

## JSON.stringify — 객체를 JSON 문자열로

```js
const user = {
  name: '철수',
  age: 25,
  isActive: true,
  hobbies: ['독서', '등산'],
}

const jsonString = JSON.stringify(user)
console.log(jsonString)
// '{"name":"철수","age":25,"isActive":true,"hobbies":["독서","등산"]}'
console.log(typeof jsonString)  // 'string' — 객체가 아닌 문자열!
```

<Callout type="warning">
  `JSON.stringify()`의 결과는 **문자열**입니다. 겉모습이 객체처럼 보여도 `jsonString.name`으로 접근할 수 없습니다. 문자열이기 때문입니다.
</Callout>

### 보기 좋게 들여쓰기

```js
console.log(JSON.stringify(user, null, 2))
// {
//   "name": "철수",
//   "age": 25,
//   ...
// }
```

세 번째 인수(`2`)는 들여쓰기 칸 수입니다. 콘솔에 데이터를 예쁘게 출력하거나 디버깅할 때 유용합니다.

## JSON.parse — JSON 문자열을 객체로

```js
const jsonString = '{"name":"철수","age":25}'
const user = JSON.parse(jsonString)

console.log(user)        // { name: '철수', age: 25 } — 진짜 객체
console.log(user.name)   // '철수' — 이제 프로퍼티 접근 가능
console.log(typeof user) // 'object'
```

## JSON으로 변환되지 않는 값들

JSON은 자바스크립트의 모든 값을 표현할 수 없습니다. 함수, `undefined`, `Symbol`은 `JSON.stringify` 과정에서 **조용히 사라집니다**.

```js
const data = {
  name: '철수',
  greet: function () { console.log('안녕') },  // 함수
  nickname: undefined,                          // undefined
  id: Symbol('id'),                             // Symbol
}

console.log(JSON.stringify(data))
// '{"name":"철수"}' — greet, nickname, id 모두 사라짐!
```

<Callout type="warning">
  이 동작은 에러 없이 조용히 일어나기 때문에 자주 놓치는 버그의 원인이 됩니다. 서버로 객체를 보내기 전에는 어떤 값이 포함되는지 `console.log(JSON.stringify(...))`로 먼저 확인하는 습관이 안전합니다.
</Callout>

## Date 객체는 문자열로 변환된다

```js
const event = { date: new Date('2026-01-01') }
console.log(JSON.stringify(event))
// '{"date":"2026-01-01T00:00:00.000Z"}' — Date가 ISO 문자열로 바뀜

const parsed = JSON.parse(JSON.stringify(event))
console.log(parsed.date instanceof Date)  // false! — 문자열로 남아있음, 자동으로 Date로 안 돌아옴
```

`JSON.parse`는 `Date`를 자동으로 복원해주지 않습니다. 다시 `Date` 객체가 필요하다면 `new Date(parsed.date)`처럼 직접 변환해야 합니다.

## 실전 활용 — 16번 문서의 깊은 복사

16번 문서에서 소개했던 `JSON.parse(JSON.stringify(obj))` 패턴이 바로 이 두 메서드를 연달아 쓴 깊은 복사 트릭입니다. 객체를 문자열로 만들었다가 다시 객체로 만들면, 원본과 완전히 분리된 새로운 객체가 만들어집니다. 단, 위에서 배운 대로 함수·undefined·Symbol·Date는 이 과정에서 온전히 보존되지 않는다는 한계가 있습니다.

## 핵심 정리

- JSON은 서로 다른 프로그램·언어가 데이터를 주고받기 위한 표준 텍스트 형식이다.
- `JSON.stringify()`는 객체를 문자열로(직렬화), `JSON.parse()`는 문자열을 객체로(역직렬화) 변환한다.
- 함수, undefined, Symbol은 stringify 과정에서 조용히 사라진다.
- Date는 문자열로 변환되며, parse해도 자동으로 Date 객체로 복원되지 않는다.
