## 4. 표현식과 문

코드를 읽다 보면 값, 리터럴, 표현식, 문 같은 말이 계속 나온다. 이 단어들은 자바스크립트만의 용어가 아니라 프로그래밍 전반에서 쓰이는 기본 용어라, 여기서 정확히 잡아두면 앞으로 문서를 읽거나 남과 이야기할 때 두고두고 도움이 된다.

### 4.1 값

> **값(value)**: 표현식이 평가되어 만들어진 결과. 프로그램이 다루는 데이터의 기본 단위다.

여기서 **평가(evaluation)** 란 코드를 해석해 하나의 값을 만들어내는 것을 말한다. 예를 들어 `10 + 20`은 평가되어 숫자 값 `30`이 된다.

```js
10 + 20; // 평가되어 숫자 값 30이 된다
```

**3편**에서 변수에는 값이 저장된다고 했는데, 정확히 말하면 변수에 담기는 것은 식 자체가 아니라 **식이 평가된 결과**다.

```js
const sum = 10 + 20;
// sum에 담기는 것은 '10 + 20'이라는 식이 아니라, 그것이 평가된 값 30이다
```

즉 오른쪽 식은 할당되기 **전에** 먼저 평가되어 값이 되고, 그 값이 변수로 들어간다.

### 4.2 리터럴

코드에 값을 직접 적어 넣는 표기법을 리터럴이라 한다. 우리가 `3`이라고 쓰면 그것은 단순한 숫자가 아니라, 엔진에게 "숫자 3이라는 값을 만들라"고 지시하는 **숫자 리터럴**이다.

> **리터럴(literal)**: 값을 만들기 위해 코드에 직접 써넣는 표기법. 사람이 읽을 수 있는 문자나 약속된 기호로 값을 나타낸다.

```js
3          // 숫자 리터럴
'Hello'    // 문자열 리터럴
true       // 불리언 리터럴
null       // null 리터럴
[1, 2, 3]  // 배열 리터럴
{ x: 1 }   // 객체 리터럴
```

엔진은 코드를 실행하는 시점에 이 표기를 읽어 실제 값을 만들어낸다. 어떤 값이 어떤 리터럴로 표현되는지는 값의 종류를 다루는 **5편(데이터 타입)** 에서 자세히 본다.

### 4.3 표현식

> **표현식(expression)**: 값으로 평가될 수 있는 코드. 평가하면 하나의 값이 된다.

리터럴은 그 자체로 값이 되므로 표현식이다. 표현식의 형태는 다양하지만, **"평가하면 하나의 값이 된다"** 는 점은 모두 같다.

```js
10          // 리터럴 표현식
sum         // 변수(식별자) 표현식 → 저장된 값으로 평가된다
10 + 20     // 연산자 표현식
square(5)   // 함수 호출 표현식
```

핵심은 표현식과 그것이 평가된 값이 **서로 같다**는 점이다. 수학에서 `1 + 2`가 `3`과 같은 것과 마찬가지다. 그래서 **값이 올 수 있는 자리에는 표현식도 올 수 있다.**

```js
const x = 1 + 2;    // 1 + 2는 3과 같으므로 x에는 3이 담긴다
console.log(x + 3); // x는 3으로 평가된다 → 6
```

이렇게 표현식은 다른 표현식의 일부가 되어 더 큰 값을 만들어낸다. 표현식을 조합하는 방법은 **6편(연산자)** 에서 본격적으로 다룬다.

### 4.4 문

> **문(statement)**: 프로그램을 이루는 하나의 실행 단위. 컴퓨터에 내리는 하나의 명령이다.

프로그램은 문이 순서대로 나열된 것이고, 프로그래밍은 이 문을 알맞은 순서로 써나가는 일이다. 문이 실행되면 무언가 일이 일어난다.

문은 여러 개의 **토큰**으로 이루어진다.

> **토큰(token)**: 문법적으로 더 이상 나눌 수 없는 코드의 최소 조각. 키워드, 식별자, 연산자, 리터럴, 그리고 세미콜론이나 마침표 같은 기호가 모두 토큰이다.

```js
let sum = 1 + 2;
// let  sum  =  1  +  2  ;  → 각각이 하나의 토큰이다
```

문에는 여러 종류가 있다.

```js
let x;                          // 선언문
x = 5;                          // 할당문
if (x > 1) { console.log(x); }  // 조건문
for (let i = 0; i < 2; i++) {}  // 반복문
```

### 4.5 세미콜론과 자동 삽입

세미콜론(`;`)은 **문이 끝났다**는 표시다. 엔진은 이 표시를 기준으로 문을 구분해 하나씩 실행한다. 단, 코드 블록(`{ }`)으로 끝나는 문(`if`, `for`, 함수 등) 뒤에는 세미콜론을 붙이지 않는다. 블록은 그 자체로 끝이 분명하기 때문이다.

사실 세미콜론은 생략할 수도 있다. 엔진이 문이 끝났다고 판단되는 자리에 세미콜론을 자동으로 넣어주기 때문인데, 이 기능을 **세미콜론 자동 삽입(ASI, Automatic Semicolon Insertion)** 이라 한다.

문제는 ASI가 넣는 위치가 내 의도와 어긋날 때가 있다는 것이다.

```js
function foo() {
  return
    10;
}

console.log(foo()); // undefined
// ASI가 return 바로 뒤에 세미콜론을 넣어버려 'return;'이 되었다
// 아래의 10은 실행되지 못하고, 함수는 아무 값도 반환하지 않는다
```

이런 함정 때문에 세미콜론을 직접 붙이는 편이 안전하다. ESLint 같은 도구들도 기본적으로 세미콜론 사용을 권장한다.

### 4.6 표현식인 문 vs 표현식이 아닌 문

앞에서 표현식은 "값으로 평가되는 코드", 문은 "실행 단위"라고 했다. 그렇다면 어떤 문은 그 자체로 값이 될 수 있고, 어떤 문은 그럴 수 없다. 이 기준으로 문은 두 종류로 나뉜다.

- **표현식인 문**: 값으로 평가되는 문 (예: 할당문)
- **표현식이 아닌 문**: 값으로 평가되지 않는 문 (예: 선언문)

둘을 구별하는 가장 쉬운 방법은 **변수에 할당해 보는 것**이다. 값으로 평가되면 할당할 수 있고, 아니면 문법 에러가 난다.

```js
let x;
const result = (x = 100); // 할당문 'x = 100'은 100으로 평가된다
console.log(result);      // 100 → 값이 되므로 표현식인 문
```

```js
const y = let z; // SyntaxError
// 선언문은 값으로 평가되지 않으므로 할당할 수 없다 → 표현식이 아닌 문
```

> **완료 값(completion value)**: 브라우저 콘솔에서 선언문처럼 표현식이 아닌 문을 실행하면 언제나 `undefined`가 찍히는데, 이를 완료 값이라 한다. 완료 값은 표현식이 평가된 결과가 **아니므로** 변수에 담거나 참조할 수 없다. 반면 표현식인 문을 실행하면 평가된 값이 그대로 찍힌다. 콘솔에서 `const a = 1;`은 `undefined`를, `10 + 20`은 `30`을 보여주는 이유가 이것이다.

## 이번 편 핵심 요약

1. **값**은 표현식이 평가되어 만들어진 결과다. 변수에 담기는 것은 식이 아니라 평가된 값이다.
2. **리터럴**은 값을 코드에 직접 적는 표기법이고, 엔진은 이를 읽어 실제 값을 만든다.
3. **표현식**은 값으로 평가되는 코드다. 표현식은 평가된 값과 같으므로, 값이 올 자리에는 표현식도 올 수 있다.
4. **문**은 하나의 실행 단위이며 **토큰**들로 이루어진다. 문에는 값이 되는 것(할당문 등)과 되지 않는 것(선언문 등)이 있고, **변수에 할당해 보면** 구별된다.
5. **세미콜론**은 문의 끝을 나타낸다. ASI가 대신 넣어주긴 하지만 의도와 어긋날 수 있으므로, 직접 붙이는 습관을 들인다.
