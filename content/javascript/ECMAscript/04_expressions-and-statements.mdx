## 표현식과 문

`let age = 20`을 다시 보자. 이 한 줄 안에 사실 두 가지 다른 개념이 섞여 있다.
이 둘을 구분하면 앞으로 나올 함수, 화살표 함수, 조건문이 왜 그렇게 생겼는지 이해하기 쉬워진다.

## 표현식 — 값으로 평가되는 것

**표현식**<sup>Expression</sup>은 **평가되어 하나의 값을 만들어내는 코드**다.

```js
1 + 1        // 평가하면 2
'a' + 'b'    // 평가하면 'ab'
age          // 평가하면 age에 담긴 값
age > 18     // 평가하면 true 또는 false
```

판별법은 간단하다. **"이걸 콘솔에 쳐서 값이 나오면 표현식이다."**

```js
console.log(1 + 1)      // 2 — 표현식이라 값이 나온다
```

## 문 — 표현식을 담아 동작을 지시하는 것

**문**<sup>Statement</sup>은 **하나의 실행 단위**다. 문은 값으로 평가되지 않는다. "이 동작을 하라"는 지시일 뿐이다.

```js
let age = 20      // 변수 선언문
if (age > 18) {  // 조건문
  console.log('성인')
}
```

`let age = 20` 전체는 문이다. 하지만 그 안의 `20`은 표현식이다.
**문은 표현식을 재료로 쓴다.**

```
let age = 20 + 5;
└─┬─┘  └┬┘  └──┬──┘
  |     |      표현식 (평가하면 25)
  |     변수 이름
  문 전체
```

## 표현식 vs 문 — 실전 구분

가장 헷갈리는 지점은 **"둘 다 비슷하게 생겼는데 쓸 수 있는 자리가 다르다"** 는 것이다.

```js
console.log(if (true) { 1 })   // SyntaxError
```

`if문`은 값이 아니기 때문에, 값이 와야 하는 자리(함수의 괄호 안)에 넣을 수 없다.

대신 값을 만들어내는 **표현식 버전**이 따로 있다.

```js
const result = true ? 1 : 2   // 삼항 조건 연산자 — 표현식이다
console.log(result)            // 1
```

`? :` 는 `if`와 비슷한 일을 하지만 **값으로 평가되는 표현식**이라 이런 자리에 쓸 수 있다. (자세한 문법은 8편 제어문에서 다룬다.)

<Callout type="info">
함수도 마찬가지다. `function foo() {}`처럼 선언하면 **문**이지만,
`const foo = function() {}`처럼 값 자리에 쓰면 **표현식**이 된다. 9편(함수 기초)과 11편(함수는 값이다)에서 이 차이를 자세히 다룬다.
</Callout>

## 표현식 문 — 값을 버리는 표현식

표현식 뒤에 세미콜론만 붙이면 그 자체로 문이 될 수 있다. 이를 **표현식 문**<sup>Expression Statement</sup>이라 한다.

```js
age + 1;         // 문법적으로는 유효하다 — 하지만 계산 결과를 버린다
console.log(age) // 흔히 쓰는 표현식 문 — 함수 호출도 표현식이다
```

`age + 1;`은 문법 오류는 아니지만 계산만 하고 결과를 아무 데도 담지 않아 사실상 의미가 없다.
반면 `console.log(age)`처럼 **부수 효과**(화면 출력 등)가 있는 표현식 문은 실무에서 매우 흔하다.

## 세미콜론과 ASI

문 끝에는 세미콜론(`;`)을 붙이는 게 원칙이다. 그런데 자바스크립트는 세미콜론을 생략해도 대부분 알아서 넣어준다.
이걸 **ASI**<sup>Automatic Semicolon Insertion, 자동 세미콜론 삽입</sup>라 한다.

```js
let a = 1
let b = 2
console.log(a + b)   // 세미콜론 없이도 잘 동작한다
```

<Callout type="warning">
**ASI를 완전히 믿으면 안 되는 경우가 있다.**

```js
function getValue() {
  return
  {
    value: 1
  }
}

console.log(getValue())   // undefined — { value: 1 }이 아니다!
```

`return` 다음 줄바꿈이 있으면 ASI가 그 자리에 세미콜론을 넣어 **`return;`으로 끝나버린다.**
그 아래 객체는 실행되지 않는 죽은 코드가 된다.

**실무 규칙**: `return`, 여는 괄호 `(`, 대괄호 `[`로 시작하는 줄은 항상 **같은 줄 또는 세미콜론을 명시**해서 ASI 함정을 피한다.
</Callout>

<Callout type="default">
이 시리즈의 예제는 세미콜론을 명시적으로 붙이는 스타일을 기본으로 한다. 팀·프로젝트마다 컨벤션(ESLint 설정)이 다를 수 있으니, 실무에서는 그 프로젝트의 규칙을 따르면 된다.
</Callout>

## 정리

<Callout type="default">
- **표현식**은 평가되어 값이 되는 코드다. `1 + 1`, `age`, `age > 18`
- **문**은 하나의 실행 지시다. 문은 표현식을 재료로 쓴다
- 값이 필요한 자리에는 표현식만 올 수 있다 — `if문`이 아니라 `? :` 를 쓰는 이유다
- 세미콜론은 생략해도 ASI가 채워주지만, **`return` 다음 줄바꿈** 같은 함정이 있다
</Callout>

다음 편에서는 표현식이 만들어내는 값, 즉 자바스크립트의 **데이터 타입**을 하나씩 살펴본다.
