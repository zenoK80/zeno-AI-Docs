## 비동기가 필요한 이유

> **쉽게 말하면:** 서버에 데이터를 요청하면 답이 올 때까지 몇 초가 걸릴 수 있습니다. 이 몇 초 동안 프로그램 전체가 멈춰서 기다리게 하면 안 되므로, "지금은 모르지만 나중에 결과가 나올 것"이라는 개념이 필요합니다. 그것이 **비동기**(asynchronous)입니다.

```js
console.log('1. 시작')
setTimeout(() => console.log('2. 3초 후 실행'), 3000)
console.log('3. 바로 실행됨')

// 출력 순서: '1. 시작' → '3. 바로 실행됨' → (3초 후) '2. 3초 후 실행'
```

`setTimeout`은 3초를 "기다리며 멈추는" 것이 아니라, 3초 후에 실행할 작업을 예약해두고 **즉시 다음 코드로 넘어갑니다**. 이 동작 원리는 30번 문서(이벤트 루프)에서 더 깊게 다룹니다.

## Promise란?

> **쉽게 말하면:** Promise(약속)는 "지금 당장은 결과가 없지만, 나중에 성공하거나 실패할 것"이라는 상태를 표현하는 객체입니다.

## Promise의 세 가지 상태

<Table>
  <thead>
    <tr><th>상태</th><th>의미</th></tr>
  </thead>
  <tbody>
    <tr><td>pending(대기)</td><td>아직 결과가 나오지 않은 초기 상태</td></tr>
    <tr><td>fulfilled(이행)</td><td>작업이 성공적으로 끝남</td></tr>
    <tr><td>rejected(거부)</td><td>작업이 실패로 끝남</td></tr>
  </tbody>
</Table>

한 번 fulfilled나 rejected가 되면, 그 Promise의 상태는 다시는 바뀌지 않습니다.

## Promise 만들기

```js
const myPromise = new Promise((resolve, reject) => {
  const success = true

  setTimeout(() => {
    if (success) {
      resolve('작업 성공!')   // 성공 시 resolve 호출 → fulfilled 상태로
    } else {
      reject(new Error('작업 실패'))  // 실패 시 reject 호출 → rejected 상태로
    }
  }, 1000)
})
```

`resolve`와 `reject`는 Promise 생성자가 자동으로 넘겨주는 함수입니다. 둘 중 하나를 호출하면 pending 상태가 끝나고 결과가 확정됩니다.

## then, catch, finally로 결과 처리

<CodePlayground
  template="vanilla"

    '/index.js': `function checkAge(age) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (age >= 18) {

      } else {
        reject(new Error('미성년자는 입장 불가'))
      }

  })
}

checkAge(20)
  .then(result => console.log('성공:', result))
  .catch(error => console.log('실패:', error.message))
  .finally(() => console.log('처리 완료 (성인)'))

checkAge(15)
  .then(result => console.log('성공:', result))
  .catch(error => console.log('실패:', error.message))
  .finally(() => console.log('처리 완료 (미성년)'))`,
  }}
/>

- `.then(콜백)`: Promise가 **fulfilled**되면 실행되며, resolve에 넘긴 값을 인수로 받는다.
- `.catch(콜백)`: Promise가 **rejected**되면 실행되며, reject에 넘긴 에러를 인수로 받는다.
- `.finally(콜백)`: 성공/실패와 상관없이 항상 실행된다(24번 문서의 finally와 같은 개념).

## Promise 체이닝 — then을 연결하기

`.then()`은 새로운 Promise를 반환하므로, 여러 개를 이어붙일 수 있습니다.

```js
function fetchUser(id) {
  return new Promise(resolve => {
    setTimeout(() => resolve({ id, name: '철수' }), 500)
  })
}

function fetchPosts(userId) {
  return new Promise(resolve => {
    setTimeout(() => resolve(['게시글1', '게시글2']), 500)
  })
}

fetchUser(1)
  .then(user => {
    console.log('사용자:', user.name)
    return fetchPosts(user.id)  // then 안에서 또 다른 Promise를 반환하면 체이닝됨
  })
  .then(posts => {
    console.log('게시글:', posts)  // 앞의 then이 반환한 Promise의 결과를 받음
  })
```

각 `.then()`은 이전 `.then()`이 반환한 값을 다음 `.then()`으로 전달합니다. Promise를 반환하면, 그 Promise가 끝날 때까지 기다렸다가 결과를 넘겨줍니다.

## Promise.all — 여러 작업을 동시에 기다리기

여러 비동기 작업을 **병렬로** 실행하고, **모두 끝나면** 한 번에 결과를 받고 싶을 때 사용합니다.

```js
const p1 = new Promise(resolve => setTimeout(() => resolve('결과1'), 1000))
const p2 = new Promise(resolve => setTimeout(() => resolve('결과2'), 2000))
const p3 = new Promise(resolve => setTimeout(() => resolve('결과3'), 1500))

Promise.all([p1, p2, p3]).then(results => {
  console.log(results)  // ['결과1', '결과2', '결과3'] — 2초 후(가장 느린 것 기준) 한 번에 출력
})
```

<Callout type="warning">
  `Promise.all()`은 배열 안의 **하나라도 reject되면 전체가 즉시 reject**됩니다. 일부만 실패해도 나머지 성공한 결과까지 모두 잃게 됩니다. 각각의 성공/실패를 개별적으로 알고 싶다면 `Promise.allSettled()`를 사용합니다.
  ```js
  Promise.allSettled([p1, p2, p3]).then(results => {
    // 각 결과가 { status: 'fulfilled', value } 또는 { status: 'rejected', reason } 형태
    console.log(results)
  })
  ```
</Callout>

## 순차 실행 vs 병렬 실행 — 성능 차이

```js
// 순차 실행 — 하나씩 기다림 (총 소요 시간: 1+1+1 = 3초)
async function sequential() {
  await delay(1000)
  await delay(1000)
  await delay(1000)
}

// 병렬 실행 — 동시에 시작 (총 소요 시간: 가장 긴 것 1초)
async function parallel() {
  await Promise.all([delay(1000), delay(1000), delay(1000)])
}
```

서로 의존하지 않는 여러 비동기 작업이라면, `Promise.all`로 동시에 실행하는 것이 훨씬 빠릅니다. (`async`/`await` 문법은 29번 문서에서 자세히 다룹니다.)

## 핵심 정리

- Promise는 pending, fulfilled, rejected 세 가지 상태를 가지며 한 번 확정되면 바뀌지 않는다.
- `.then()`은 성공 결과를, `.catch()`는 실패 이유를, `.finally()`는 항상 실행되는 콜백을 등록한다.
- `.then()` 안에서 새 Promise를 반환하면 다음 then으로 체이닝된다.
- `Promise.all()`은 여러 작업을 병렬로 실행하고 모두 끝나면 결과 배열을 받으며, 하나라도 실패하면 전체가 실패한다.
- 서로 의존하지 않는 비동기 작업은 순차 실행보다 Promise.all로 병렬 실행하는 것이 빠르다.
