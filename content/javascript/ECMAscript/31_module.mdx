## 모듈이 필요한 이유

> **쉽게 말하면:** 모든 코드를 파일 하나에 몰아 쓰면 금방 수천 줄이 되어 관리가 어려워집니다. 모듈은 코드를 기능별 파일로 나누고, 필요한 부분만 서로 빌려 쓸 수 있게 하는 시스템입니다.

옛날 방식(모듈 없이)에서는 `<script>` 태그를 여러 개 나열해 파일을 순서대로 로딩했고, 모든 변수가 **전역 스코프**를 공유해서 이름 충돌이 잦았습니다. 모듈은 각 파일이 **자신만의 스코프**를 갖게 하고, `export`한 것만 밖으로 공개합니다.

## Named Export — 이름을 가진 여러 개 내보내기

```js
// math.js — 내보내기(export)
export function add(a, b) {
  return a + b
}

export function subtract(a, b) {
  return a - b
}

export const PI = 3.14159
```

```js
// main.js — 가져오기(import)
import { add, subtract, PI } from './math.js'

console.log(add(2, 3))       // 5
console.log(subtract(5, 2))  // 3
console.log(PI)               // 3.14159
```

한 파일에서 `export`는 **여러 번** 할 수 있고, 가져올 때는 **중괄호 `{}`** 안에 정확한 이름을 씁니다.

## Default Export — 파일당 하나만 내보내기

```js
// Button.js — 기본 내보내기
export default function Button() {
  console.log('버튼')
}
```

```js
// main.js — 기본 가져오기 (중괄호 없음, 이름은 자유롭게 지정 가능)
import Button from './Button.js'
import MyButton from './Button.js'  // 다른 이름으로 가져와도 동일한 것을 가리킴

Button()     // '버튼'
MyButton()   // '버튼' — 같은 함수
```

## 두 방식을 함께 쓰기

```js
// utils.js
export default function mainFunction() { /* ... */ }
export const helperA = () => {}
export const helperB = () => {}
```

```js
// main.js
import mainFunction, { helperA, helperB } from './utils.js'
```

## 네임스페이스 가져오기 — 한 번에 모두

```js
import * as MathUtils from './math.js'

console.log(MathUtils.add(1, 2))     // 5
console.log(MathUtils.PI)            // 3.14159
```

`* as 이름`으로 가져오면, 그 파일의 모든 named export가 하나의 객체(`MathUtils`) 안에 프로퍼티로 모입니다.

## 가져오면서 이름 바꾸기(as)

```js
import { add as sum, subtract as diff } from './math.js'

console.log(sum(1, 2))  // 3 — add를 sum이라는 이름으로 사용
```

다른 파일에서 가져온 이름이 이미 쓰이고 있거나, 더 명확한 이름을 쓰고 싶을 때 유용합니다.

## 모듈의 특별한 성질 — 한 번만 실행되고 캐시된다

```js
// counter.js
console.log('counter.js 실행됨')
export let count = 0
export function increment() { count++ }
```

```js
// a.js
import { count, increment } from './counter.js'  // 'counter.js 실행됨' 출력
increment()

// b.js
import { count } from './counter.js'  // 다시 출력되지 않음! 이미 로딩된 모듈을 재사용
console.log(count)  // 1 — a.js에서 증가시킨 값이 그대로 유지됨(같은 모듈 인스턴스를 공유)
```

같은 모듈을 여러 파일에서 import해도, 그 모듈의 코드는 **처음 한 번만 실행**되고 이후에는 캐시된 결과(같은 값·같은 함수)를 공유합니다.

## ESM vs CommonJS — 간단 비교

지금까지 배운 `import`/`export`는 **ESM**(ECMAScript Modules, ES6에서 표준화)입니다. Node.js 초기부터 쓰이던 **CommonJS**(`require`/`module.exports`) 방식도 여전히 많은 코드에 남아 있습니다.

```js
// CommonJS (예전 Node.js 방식)
const { add } = require('./math.js')
module.exports = { add, subtract }

// ESM (현재 표준)
import { add } from './math.js'
export { add, subtract }
```

<Callout type="warning">
  두 방식은 문법이 호환되지 않으므로 한 파일 안에서 섞어 쓸 수 없습니다. 새로 작성하는 코드는 **ESM**(import/export)**을 사용**하는 것이 현재 표준입니다.
</Callout>

## 핵심 정리

- named export는 파일당 여러 개 가능하며, import 시 중괄호와 정확한 이름이 필요하다.
- default export는 파일당 하나만 가능하며, import 시 중괄호 없이 자유로운 이름을 쓸 수 있다.
- `* as 이름`으로 모든 named export를 하나의 객체로 가져올 수 있다.
- 같은 모듈은 여러 곳에서 import해도 코드가 딱 한 번만 실행되고 결과가 캐시되어 공유된다.
- ESM(import/export)이 현재 표준이며, CommonJS(require)는 예전 Node.js 코드에 남아있는 방식이다.
