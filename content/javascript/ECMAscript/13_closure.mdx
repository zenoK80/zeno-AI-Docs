## 클로저를 이해하기 전에 — 이상한 현상 관찰하기

다음 코드를 먼저 실행해봅시다.

<CodePlayground
  template="vanilla"

    '/index.js': `function makeCounter() {

  return function () {
    count = count + 1
    return count
  }

const counter = makeCounter()  // makeCounter는 이미 실행이 끝났다!

`makeCounter()`는 이미 실행이 끝났습니다. 함수가 끝나면 그 안의 지역 변수(`count`)는 보통 사라집니다. 그런데 `counter()`를 호출할 때마다 `count` 값이 **계속 기억**되고 있습니다. 어떻게 이런 일이 가능할까요?

## 클로저란?

> **쉽게 말하면:** 클로저는 함수가 "자신이 태어난 곳(정의될 당시의 스코프)"을 기억하고, 그 함수가 바깥으로 옮겨져도 그 기억을 계속 가지고 다니는 현상입니다.

**클로저**(closure)는 함수와 그 함수가 선언될 당시의 렉시컬 스코프(12번 문서에서 배운 개념)가 **함께 묶여서** 유지되는 것을 말합니다.

`makeCounter` 함수 안에서 정의된 익명 함수(`return function() {...}`)는 `count` 변수를 참조합니다. 이 익명 함수가 `makeCounter` 밖으로 반환되어 나가도, **자신이 정의될 때 볼 수 있었던 스코프**(count가 있는 곳)**를 계속 붙잡고** 있습니다. 그래서 `makeCounter`의 실행이 끝난 뒤에도 `count`는 사라지지 않고 살아남습니다.

> **비유:** 클로저는 "이사 갈 때 가져가는 배낭"과 같습니다. 함수가 원래 있던 장소(스코프)를 떠나 다른 곳에서 호출되어도, 자신이 필요로 하는 변수를 배낭에 담아 어디든 들고 다닙니다.

## 클로저가 실제로 하는 일 — 독립된 상태 유지

`makeCounter()`를 여러 번 호출하면, 각각 **독립적인** count를 갖습니다.

```js
const counterA = makeCounter()
const counterB = makeCounter()

console.log(counterA())  // 1
console.log(counterA())  // 2
console.log(counterB())  // 1 — counterA와 완전히 별개! 새로운 count가 만들어짐
```

`makeCounter()`를 호출할 때마다 **새로운 스코프**(그리고 그 안의 새로운 `count`)가 만들어지고, 반환된 함수는 각자 자신만의 스코프를 기억합니다.

## 실전 활용 1 — 프라이빗 변수(데이터 숨기기)

클로저의 가장 흔한 실전 용도는 외부에서 직접 건드릴 수 없는 "숨겨진" 데이터를 만드는 것입니다.

```js
function createBankAccount(initialBalance) {
  let balance = initialBalance  // 이 변수는 함수 밖에서 직접 접근 불가능

  return {
    deposit(amount) {
      balance += amount
      return balance
    },
    withdraw(amount) {
      if (amount > balance) {
        console.log('잔액 부족')
        return balance
      }
      balance -= amount
      return balance
    },
    getBalance() {
      return balance
    },
  }
}

const account = createBankAccount(1000)
console.log(account.getBalance())  // 1000
account.deposit(500)
console.log(account.getBalance())  // 1500
account.withdraw(2000)             // '잔액 부족'

console.log(account.balance)  // undefined — balance는 직접 접근 불가! 오직 메서드로만 조작 가능
```

`balance`는 `createBankAccount` 함수의 지역 변수라서, `account.balance`처럼 직접 접근할 수 없습니다. 오직 `deposit`, `withdraw`, `getBalance`라는 정해진 통로로만 조작할 수 있습니다. 이것이 다른 언어의 `private`(비공개) 필드와 비슷한 효과를 냅니다.

## 실전 활용 2 — 함수 팩토리(Function Factory)

같은 로직에서 다른 값만 바꿔 여러 함수를 만들어낼 수 있습니다.

```js
function makeMultiplier(factor) {
  return function (number) {
    return number * factor  // factor를 기억하는 클로저
  }
}

const double = makeMultiplier(2)
const triple = makeMultiplier(3)

console.log(double(5))  // 10 — factor=2를 기억
console.log(triple(5))  // 15 — factor=3을 기억
```

## 클로저와 반복문 — 흔한 함정

`for`문에서 `var`를 쓰면 클로저와 관련한 유명한 버그가 발생합니다.

```js
// ❌ var를 쓰면 예상과 다르게 동작
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var i:', i), 100)
}
// 결과: 'var i: 3'이 세 번 출력됨! (0, 1, 2가 아니라)

// ✅ let을 쓰면 의도대로 동작
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let j:', j), 100)
}
// 결과: 'let j: 0', 'let j: 1', 'let j: 2' 순서대로 출력됨
```

**왜 이런 차이가 날까?** `var`는 함수 스코프이므로, 반복문 전체에서 **단 하나의 `i`**를 모든 클로저가 공유합니다. `setTimeout` 콜백이 실행될 시점(100ms 후)에는 이미 반복문이 끝나 `i`가 3이 되어 있어서, 모든 콜백이 같은 값(3)을 보게 됩니다.

`let`은 블록 스코프이므로, **매 반복마다 새로운 `j`가 만들어져** 각 클로저가 자신만의 `j`를 기억합니다. 그래서 0, 1, 2가 각각 올바르게 출력됩니다.

<Callout type="warning">
  이 문제는 07번 문서에서 배운 useEffect의 stale closure(오래된 클로저) 문제와 같은 원리입니다. 반복문이나 비동기 콜백에서 값이 "그때 그 순간"이 아니라 "나중에 바뀐 값"으로 보이는 버그는 대부분 이 클로저·스코프 문제에서 비롯됩니다.
</Callout>

## 핵심 정리

- 클로저는 함수가 자신이 정의될 당시의 스코프를 기억해, 바깥 함수 실행이 끝난 뒤에도 그 변수에 접근할 수 있게 하는 현상이다.
- 클로저를 만드는 함수를 여러 번 호출하면 각각 독립된 스코프(독립된 상태)를 갖는다.
- 클로저로 외부에서 직접 접근할 수 없는 "프라이빗" 변수를 만들 수 있다.
- `var`로 만든 반복문에서 클로저를 쓰면 모든 클로저가 같은 변수를 공유해 예상과 다른 결과가 나온다. `let`을 쓰면 매 반복마다 독립된 변수가 생겨 이 문제가 해결된다.
