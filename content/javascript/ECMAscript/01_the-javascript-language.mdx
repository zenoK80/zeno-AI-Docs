## 자바스크립트라는 언어

첫 편에서는 코드를 거의 쓰지 않는다.
대신 **"내가 지금부터 배우는 게 정확히 무엇인가"** 를 잡고 간다.

이걸 짚고 넘어가면 나중에 "이건 자바스크립트 문법인가, 브라우저 기능인가?" 같은 혼란이 크게 줄어든다.

## 프로그래밍은 "정확하게 시키는 일"이다

프로그래밍은 컴퓨터에게 일을 시키는 것이다.
그런데 컴퓨터에는 사람과 결정적으로 다른 점이 있다. **눈치가 전혀 없다.**

친구에게 "목마른데 뭐 좀 사다 줘"라고 하면 친구는 알아서 편의점에 가서 알아서 음료를 골라 온다.
컴퓨터에게는 이 "알아서"가 하나도 통하지 않는다.

그래서 프로그래밍의 첫 단계는 코드를 치는 게 아니라 **시키고 싶은 일을 스스로 정확하게 정의하는 것**이다.

자판기를 예로 들어 보자. 사람의 말로는 한 문장이다.

> 돈 받고 음료를 준다.

컴퓨터가 실행할 수 있는 수준으로 쪼개면 이렇게 된다.

<Steps>

### 금액을 기억한다

투입된 금액의 합계를 어딘가에 저장해 둔다.

### 버튼 입력을 판단한다

버튼이 눌리면 합계가 음료 가격 이상인지 확인한다.

### 조건에 따라 나눈다

충분하면 음료를 내보내고 합계에서 가격을 뺀다. 부족하면 아무 일도 하지 않는다.

### 반환을 처리한다

반환 레버가 당겨지면 남은 금액을 돌려주고 합계를 0으로 만든다.

</Steps>

여기서 중요한 변화가 하나 일어났다.
"돈이 충분하면"이라는 모호한 말이 **"합계 ≥ 가격"이라는 판단 가능한 조건**으로 바뀌었다.

큰 문제를 작은 단계로 쪼개고, 모호한 표현을 판단 가능한 조건으로 바꾸는 것.
이 사고방식이 프로그래밍의 본체다.

앞으로 배울 문법은 전부 이 설계를 표현하기 위한 도구다.

| 설계에서 필요한 것 | 그것을 표현하는 문법 | 배우는 편 |
| --- | --- | --- |
| 값을 저장한다 (합계) | 변수 | 3편 |
| 판단하고 반복한다 (합계 ≥ 가격?) | 제어문 | 8편 |
| 절차를 묶어 재사용한다 | 함수 | 9편 |
| 관련된 값을 하나로 묶는다 | 객체 | 12편 |

## 자바스크립트는 왜 이렇게 생겼나

언어의 성격은 태어난 배경에서 나온다.

### 10일 만에 만들어진 언어

1995년, 넷스케이프사의 브렌던 아이크가 브라우저에 넣을 스크립트 언어를 만들었다.
목표는 거창하지 않았다. **"웹 페이지에 간단한 동작을 넣는 것"** 정도였다.

개발 기간은 열흘 남짓이었다고 알려져 있다.
이 짧은 기간이 오늘날 우리가 만나는 자바스크립트의 여러 특이한 점들을 남겼다.

<Callout type="info">
`typeof null`이 `'object'`를 반환하거나 `==` 비교가 예상 밖으로 동작하는 것 같은 유명한 "이상한 부분"들이 여기서 왔다.
이미 전 세계 웹이 그 동작에 의존하고 있어서 지금은 고칠 수가 없다.
</Callout>

### 이름은 마케팅의 결과다

당시 인기 있던 언어는 **Java**였다. 넷스케이프는 그 인기에 편승하려고 이름을 "자바스크립트"로 정했다.

<Callout type="warning">
**자바와 자바스크립트는 아무 관계가 없다.**
"인도와 인도네시아" 정도의 관계라는 농담이 있을 만큼 다른 언어다. 이름만 비슷하다.
</Callout>

### 표준이 필요해졌다

자바스크립트가 인기를 끌자 마이크로소프트가 인터넷 익스플로러에 비슷하지만 미묘하게 다른 **JScript**를 넣었다.
그 결과 같은 코드가 브라우저마다 다르게 동작하는 지옥이 펼쳐졌다.

그래서 1997년, **ECMA International**이라는 표준화 기구가 이 언어의 표준 명세를 만들었다.
이 표준의 이름이 **ECMAScript**다.

## ECMAScript와 자바스크립트의 관계

여기가 초보자가 가장 많이 헷갈리는 지점이다. 한 문장으로 정리하면 이렇다.

> **ECMAScript는 규격이고, 자바스크립트는 그 규격을 따르는 실제 언어다.**

ECMAScript는 **"콘센트 규격 문서"**, 자바스크립트는 **"그 규격에 맞게 만들어진 실제 콘센트"** 라고 보면 된다.

### 언어와 실행 환경은 다르다

더 중요한 구분이 하나 있다.

<Callout type="important">
**ECMAScript(언어) ≠ 실행 환경이 제공하는 기능**

`const`, `function`, `class`, `Promise` 같은 건 **언어 자체**의 문법이다. 어디서 실행하든 똑같이 동작한다.

`document.querySelector()`, `alert()`, `localStorage` 같은 건 **브라우저가 제공하는 기능**이다. 언어의 일부가 아니다.
</Callout>

같은 코드라도 실행하는 곳에 따라 쓸 수 있는 게 달라진다.

<Tabs items={['브라우저', 'Node.js']}>
<Tabs.Tab>

```js
// 언어 기능 — 어디서나 동작한다
const message = '안녕'

// 브라우저가 주는 기능 — 브라우저에서만 동작한다
document.title = message
localStorage.setItem('greeting', message)
```

</Tabs.Tab>
<Tabs.Tab>

```js
// 언어 기능 — 똑같이 동작한다
const message = '안녕'

// Node.js가 주는 기능 — 브라우저에는 없다
const fs = require('node:fs')
fs.writeFileSync('greeting.txt', message)

// document는 없다 → ReferenceError
```

</Tabs.Tab>
</Tabs>

이 시리즈는 **언어(ECMAScript) 자체**를 다룬다.
브라우저 전용 기능은 35편부터 기초만 짚고, 본격적인 내용은 Browser 시리즈에서 다룬다.

## 버전은 어떻게 붙나

ECMAScript는 버전으로 관리된다. 그런데 이름 붙이는 방식이 중간에 바뀌었다.

| 버전 | 연도 | 기억할 점 |
| --- | --- | --- |
| ES1 ~ ES3 | 1997~1999 | 초창기 |
| ES5 | 2009 | strict mode, 배열 메서드 추가 |
| **ES6 (ES2015)** | 2015 | **대격변.** `let`/`const`, 화살표 함수, 클래스, `Promise`, 모듈 |
| ES2016 이후 | 매년 | 연도로 부르고, 매년 조금씩 추가 |

<Callout type="info">
**"모던 자바스크립트"는 보통 ES6(2015) 이후를 가리킨다.**

ES6 이전과 이후는 코드 생김새가 확연히 다르다. 오래된 블로그 글을 보다가 "왜 내가 배운 거랑 다르지?" 싶으면
대부분 ES6 이전 코드다. 이 시리즈는 모던 문법을 기준으로 쓰고, 레거시 패턴은 45편에서 따로 정리한다.
</Callout>

2015년부터는 **매년 한 번씩** 정기 릴리스한다.
그래서 "최신 문법을 다 외워야 하나?" 걱정할 필요는 없다. 매년 추가되는 건 몇 개 안 되고, 대부분 기존 문법을 더 편하게 쓰는 것들이다.

## 자바스크립트는 어떤 성격의 언어인가

앞으로 계속 마주칠 특성 세 가지만 미리 짚어둔다. **지금 다 이해할 필요는 없다.**

### 인터프리터 언어다

코드를 미리 통째로 기계어로 번역해 두는 게 아니라, **실행하면서 처리한다.**

- 장점: 컴파일 과정 없이 바로 실행해 볼 수 있다
- 단점: 실수가 있어도 **실행 전에는 모른다.** 그 줄에 도달해야 에러가 난다

```js
console.log('여기는 실행된다')
존재하지않는함수()      // 여기서 에러 발생
console.log('여기는 실행 안 된다')
```

<Callout type="info">
"인터프리터 언어라 느리다"는 말은 이제 사실이 아니다. 요즘 엔진(크롬의 V8 등)은 실행 중에 자주 쓰이는 코드를
기계어로 컴파일하는 **JIT**<sup>Just-In-Time</sup> 기법을 쓴다.
</Callout>

### 동적 타입 언어다

변수에 타입을 미리 정하지 않는다. 넣는 값에 따라 타입이 정해지고, 도중에 바뀔 수도 있다.

```js
let x = 10        // 지금은 숫자
x = '열'          // 이제 문자열. 에러가 아니다
x = true          // 이제 불리언. 여전히 에러가 아니다
```

자유롭지만 그만큼 실수를 잡아주지 않는다.
이 문제를 해결하려고 나온 게 **TypeScript**다. 지금은 이름만 알아두면 된다.

### 멀티 패러다임 언어다

절차적으로도, 객체지향으로도, 함수형으로도 쓸 수 있다.
정답 스타일이 하나로 정해져 있지 않다는 뜻이다. 이 시리즈에서는 실무에서 널리 쓰이는 방식 위주로 배운다.

## 이 언어를 배우면 뭘 할 수 있나

원래 브라우저 전용이었지만, 2009년 **Node.js**가 등장하면서 브라우저 밖에서도 돌게 됐다.

여기에 모바일 앱(React Native), 데스크톱 앱(Electron)까지 더하면 활동 범위가 상당히 넓다.
**하나의 언어로 이만큼 커버할 수 있는 언어는 흔치 않다.**

## 정리

<Callout type="default">
- 프로그래밍의 본체는 문법이 아니라 **문제를 판단 가능한 단계로 쪼개는 사고**다
- **ECMAScript는 표준 규격**, 자바스크립트는 그 규격을 따르는 언어다
- **자바 ≠ 자바스크립트**
- **ES6(2015)가 분기점**이다. 그 이후를 "모던 자바스크립트"라 부른다
- `document`, `alert` 같은 건 **언어가 아니라 브라우저가 주는 기능**이다
- 자바스크립트는 인터프리터 · 동적 타입 · 멀티 패러다임 언어다
</Callout>

다음 편에서는 실제로 코드를 실행해 볼 수 있는 환경을 만든다.
