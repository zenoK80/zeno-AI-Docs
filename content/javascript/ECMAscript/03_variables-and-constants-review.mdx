## 03편 복습

## 문제 1

새 변수를 선언할 때, 특별한 이유가 없다면 기본적으로 무엇을 먼저 고려해야 하나?

- A. `var`
- B. `let`
- C. `const`
- D. 셋 다 아무거나 똑같다

<Collapse title="정답 보기">
정답: **C**
</Collapse>

<Collapse title="해설 보기">
**기본은 `const`, 값이 바뀌어야 할 필요가 생겼을 때만 `let`으로 바꾼다.** `const`(재할당이 안 되는 상자)로 시작하면 코드를 읽는 사람이 "이 값은 절대 안 바뀐다"고 안심할 수 있고, 실수로 값을 덮어써서 생기는 버그도 애초에 막을 수 있다. `var`(D 포함)는 문제가 많아 지금은 아예 쓰지 않는다.
</Collapse>

## 문제 2

다음 코드를 실행하면 어떻게 되나?

```js
const user = { name: '지민' }
user.name = '민준'
```

- A. 에러가 난다. `const`로 선언한 건 절대 못 바꾸기 때문이다
- B. 에러 없이 정상 동작한다. `user.name`이 `'민준'`으로 바뀐다
- C. 에러가 나지만 코드는 계속 실행된다
- D. `user`가 자동으로 `let`으로 바뀐다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
`const`가 막는 건 **"상자 자체를 다른 상자로 바꾸는 것"**(`user = {...}`처럼 통째로 재할당하는 것)이지, **상자 안 내용물을 바꾸는 것**(`user.name = '민준'`처럼 객체 내부의 값만 고치는 것)이 아니다. 그래서 A는 틀렸다 — `const`는 "절대 못 바꾼다"가 아니라 "재할당만 못 한다"가 정확한 설명이다. 왜 이렇게 동작하는지 원리는 13편(원시 값 vs 객체)에서 더 자세히 배운다.
</Collapse>

## 문제 3

`var`가 가진 문제로 옳은 것을 모두 포함한 것은?

- A. 같은 이름으로 여러 번 선언해도 에러가 안 난다
- B. 블록(`{ }`) 안에서 선언해도 밖에서 접근된다
- C. A와 B 둘 다
- D. 둘 다 아니다 — `var`는 사실 아무 문제가 없다

<Collapse title="정답 보기">
정답: **C**
</Collapse>

<Collapse title="해설 보기">
`var`는 두 가지 문제가 있다. ① 이미 같은 이름의 변수가 있어도 다시 `var`로 선언하면 아무 경고 없이 조용히 덮어써져서, 실수로 변수를 겹쳐 쓴 걸 알아채기 어렵다. ② **블록**(`if`, `for` 등의 `{ }`로 감싼 범위)이라는 개념을 무시하고, 블록 안에서 선언해도 블록 밖에서 그 값이 그대로 보인다. `let`/`const`는 이 두 문제를 둘 다 막아준다. 자세한 원리는 10편(스코프)과 45편(레거시 패턴)에서 다룬다.
</Collapse>

## 실습 — 직접 에러를 내보기

콘솔에서 아래를 순서대로 실행하며 결과를 먼저 예상해 보고, 실제 결과와 비교한다.

```js
const MAX = 10
MAX = 20   // ① 예상 결과는?
```

```js
let score
console.log(score)   // ② 예상 결과는?
score = 100
```

```js
if (true) {
  var leaked = 'var는 샌다'
}
console.log(leaked)   // ③ 예상 결과는?

if (true) {
  let safe = 'let은 안 샌다'
}
console.log(safe)   // ④ 예상 결과는?
```

<Collapse title="정답 확인">
① `TypeError: Assignment to constant variable.` (상수에 재할당하려 했다는 에러)
② `undefined` (선언만 하고 값을 안 넣은 상태라 "아직 값 없음"이 자동으로 채워진다)
③ `'var는 샌다'` — 블록 밖인데도 접근된다
④ `ReferenceError: safe is not defined` — 블록 밖에서는 그런 이름이 없다는 에러
</Collapse>
