## 왜 React가 필요한가?

웹 앱은 사용자의 행동(클릭, 입력)에 따라 화면이 바뀌어야 합니다. 예를 들어 소셜 미디어 피드는 실시간으로 업데이트되고, 쇼핑 카트는 상품을 추가할 때마다 숫자가 바뀝니다. 이를 순수 JavaScript(Vanilla JS)로 구현하면 이런 코드를 직접 짜야 합니다.

```js
// 버튼 클릭 시 숫자를 바꾸는 명령형 코드
let count = 0
const btn = document.getElementById('btn')
const display = document.getElementById('display')

btn.addEventListener('click', () => {
  count++
  display.textContent = count  // DOM을 직접 찾아서 바꿔야 함
})
```

화면이 복잡해질수록 "어떤 DOM을 어떻게 바꿀지"를 하나하나 명령해야 합니다. 요소가 수십 개라면 코드가 금방 뒤엉킵니다.

> **쉽게 말하면:** Vanilla JS는 "1번 서랍을 열어, 종이를 꺼내, 지우개로 지워, 새로 써, 다시 넣어"처럼 단계를 일일이 지시해야 합니다. React는 "이 서랍엔 항상 이 종이가 있어야 해"라고 결과만 선언하면 됩니다.

## React란?

**React**는 Meta(구 Facebook)가 2013년에 오픈소스로 공개한 **JavaScript UI 라이브러리**입니다. UI를 **컴포넌트(component)** 단위로 쪼개고, 데이터(상태)가 바뀌면 화면을 자동으로 갱신합니다.

핵심 특징 세 가지:

| 특징 | 설명 |
| --- | --- |
| **선언형(Declarative)** | "이런 UI를 보여줘"라고 선언하면 React가 DOM 조작을 알아서 처리 |
| **컴포넌트 기반** | UI를 독립적인 조각으로 분리해 재사용 가능하게 구성 |
| **단방향 데이터 흐름** | 부모 → 자식으로만 데이터가 흐르므로 예측 가능 |

```jsx
// 선언형: count 상태만 바꾸면 React가 화면을 알아서 업데이트
function Counter() {
  const [count, setCount] = useState(0)
  return (
    <button onClick={() => setCount(count + 1)}>
      클릭 횟수: {count}
    </button>
  )
}
```

## 가상 DOM (Virtual DOM)

브라우저의 실제 DOM은 조작 비용이 비쌉니다. React는 이 문제를 **가상 DOM**으로 해결합니다.

```
상태 변화 발생
     ↓
새 가상 DOM 트리 생성 (메모리에서만)
     ↓
이전 가상 DOM과 비교 (Diffing)
     ↓
달라진 부분만 실제 DOM에 반영 (Reconciliation)
```

예를 들어 리스트 100개 중 하나만 바뀌면, 실제 DOM에서는 해당 1개 요소만 수정합니다. 전체를 다시 그리지 않습니다.

<Callout type="warning">
  가상 DOM이 항상 빠른 건 아닙니다. 단순한 앱은 오히려 순수 JS가 빠를 수 있습니다. React의 진짜 이점은 **복잡한 상태 관리를 쉽게 해주는 개발자 경험**입니다.
</Callout>

## 컴포넌트란?

컴포넌트는 **화면의 일부를 담당하는 함수**입니다. 버튼 하나도 컴포넌트, 페이지 전체도 컴포넌트입니다.

```jsx
// 버튼 컴포넌트
function Button({ label, onClick }) {
  return <button onClick={onClick}>{label}</button>
}

// 카드 컴포넌트 — Button을 포함
function UserCard({ name, email }) {
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>{email}</p>
      <Button label="프로필 보기" onClick={() => alert(name)} />
    </div>
  )
}
```

컴포넌트를 조합해서 UI를 만드는 방식은 레고 블록과 같습니다. 작은 블록(Button)을 조합해 큰 구조물(UserCard)을 만들고, 여러 UserCard를 조합해 UserList를 만드는 방식입니다.

## React 프로젝트 시작

**Vite** 사용을 권장합니다. Create React App보다 훨씬 빠릅니다.

```bash
npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev
```

생성된 폴더 구조:

```
my-app/
├── public/          ← 정적 파일 (favicon 등)
├── src/
│   ├── App.jsx      ← 루트 컴포넌트
│   ├── main.jsx     ← 앱 진입점 (ReactDOM.createRoot)
│   └── index.css
├── index.html       ← HTML 진입점
└── package.json
```

```jsx
// main.jsx — React 앱을 DOM에 연결
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
)
```

## 핵심 정리

- React는 UI 라이브러리로, 상태가 바뀌면 화면을 자동으로 갱신해 준다.
- **선언형**: "이런 화면이어야 해"라고 결과를 선언하면 React가 DOM 조작을 처리한다.
- **가상 DOM**: 변경된 부분만 실제 DOM에 반영해 불필요한 조작을 줄인다.
- **컴포넌트**: UI를 독립 조각으로 분리해 재사용하는 기본 단위.
- `npm create vite@latest`로 빠르게 프로젝트를 시작한다.
