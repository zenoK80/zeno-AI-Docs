## Context API의 한계

Context API는 간단한 전역 상태에는 좋지만 다음 한계가 있습니다.

```
1. 성능: Context 값이 바뀌면 해당 Context를 구독하는 모든 컴포넌트가 리렌더링됩니다.
2. 분리 어려움: 여러 상태를 하나의 Context에 넣으면 관련 없는 컴포넌트도 리렌더링됩니다.
3. 미들웨어 없음: 비동기 처리, 로깅, 사이드이펙트 관리에 추가 작업이 필요합니다.
4. 개발 도구 없음: Redux DevTools 같은 전용 디버깅 도구가 없습니다.
```

## Zustand — 경량 상태 관리

```bash
npm install zustand
```

```js
import { create } from 'zustand'

// 스토어 생성
const useCounterStore = create((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),
  reset: () => set({ count: 0 }),
}))

// 컴포넌트에서 사용
function Counter() {
  const { count, increment, decrement } = useCounterStore()
  return (
    <div>
      <p>{count}</p>
      <button onClick={increment}>+</button>
      <button onClick={decrement}>-</button>
    </div>
  )
}
```

## Zustand — 비동기 액션

```js
const useUserStore = create((set) => ({
  user: null,
  loading: false,
  error: null,

  fetchUser: async (id) => {
    set({ loading: true, error: null })
    try {
      const res = await fetch(`/api/users/${id}`)
      const user = await res.json()
      set({ user, loading: false })
    } catch (err) {
      set({ error: err.message, loading: false })
    }
  },

  logout: () => set({ user: null }),
}))

function Profile() {
  const { user, loading, fetchUser } = useUserStore()

  useEffect(() => {
    fetchUser(1)
  }, [fetchUser])

  if (loading) return <p>로딩...</p>
  return <p>{user?.name}</p>
}
```

## Zustand — 선택적 구독 (리렌더링 최적화)

```js
// count만 구독 — 다른 상태가 바뀌어도 리렌더링 안 됨
function CountDisplay() {
  const count = useCounterStore((state) => state.count)
  return <p>{count}</p>
}

// 액션만 구독 — 상태가 바뀌어도 리렌더링 안 됨
function CountButtons() {
  const { increment, decrement } = useCounterStore(
    (state) => ({ increment: state.increment, decrement: state.decrement })
  )
  return (
    <div>
      <button onClick={increment}>+</button>
      <button onClick={decrement}>-</button>
    </div>
  )
}
```

## Redux Toolkit 개념

Redux Toolkit(RTK)은 Redux의 공식 권장 방식으로 보일러플레이트를 크게 줄였습니다.

```bash
npm install @reduxjs/toolkit react-redux
```

```js
import { createSlice, configureStore } from '@reduxjs/toolkit'

// Slice — 상태 + 리듀서 + 액션을 한 곳에서 정의
const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1 },    // Immer 덕분에 직접 수정 가능
    decrement: (state) => { state.value -= 1 },
    incrementByAmount: (state, action) => {
      state.value += action.payload
    },
  },
})

export const { increment, decrement, incrementByAmount } = counterSlice.actions

// Store 생성
const store = configureStore({
  reducer: { counter: counterSlice.reducer },
})

// React와 연결
import { Provider, useSelector, useDispatch } from 'react-redux'

function App() {
  return (
    <Provider store={store}>
      <Counter />
    </Provider>
  )
}

function Counter() {
  const count = useSelector((state) => state.counter.value)
  const dispatch = useDispatch()
  return (
    <div>
      <p>{count}</p>
      <button onClick={() => dispatch(increment())}>+</button>
      <button onClick={() => dispatch(decrement())}>-</button>
    </div>
  )
}
```

## 라이브러리 선택 기준

```
Zustand
- 적은 보일러플레이트
- 작은~중간 규모 프로젝트
- Context API보다 성능 좋음
- 러닝커브 낮음

Redux Toolkit
- 대규모 팀/프로젝트
- 강력한 DevTools 필요
- 예측 가능한 상태 흐름 중요
- 비동기 처리(RTK Query) 통합 필요
```

## 핵심 정리

- Context API는 값 변경 시 모든 구독 컴포넌트를 리렌더링해 성능 문제가 생깁니다.
- Zustand는 선택적 구독으로 리렌더링을 최소화하고 코드가 간결합니다.
- Redux Toolkit은 `createSlice`와 `configureStore`로 보일러플레이트를 줄인 공식 Redux 방식입니다.
- 프로젝트 규모와 팀 상황에 맞게 라이브러리를 선택합니다.
