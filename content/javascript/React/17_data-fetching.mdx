## 기본 데이터 패칭 패턴

07장 useEffect에서 패칭 기본을 익혔습니다. 여기서는 실무 패턴을 더 자세히 다룹니다.

```jsx
function useData(url) {
  const [data, setData] = useState(null)
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState(null)

  useEffect(() => {
    let cancelled = false  // 경쟁 조건 방지

    async function fetchData() {
      try {
        setLoading(true)
        setError(null)
        const res = await fetch(url)
        if (!res.ok) throw new Error(`HTTP ${res.status}`)
        const json = await res.json()
        if (!cancelled) setData(json)
      } catch (err) {
        if (!cancelled) setError(err.message)
      } finally {
        if (!cancelled) setLoading(false)
      }
    }

    fetchData()

    return () => { cancelled = true }  // 클린업: 응답 무시
  }, [url])

  return { data, loading, error }
}
```

## 경쟁 조건 (Race Condition)

사용자가 빠르게 탭을 바꾸면 두 개의 요청이 동시에 진행됩니다. 두 번째 요청이 첫 번째보다 먼저 도착하면 잘못된 데이터가 표시됩니다.

```
클릭 A → 요청 A 시작 (느림)
클릭 B → 요청 B 시작 (빠름)
요청 B 완료 → B 데이터 표시
요청 A 완료 → ⚠️ A 데이터가 B 위에 덮여씀
```

**해결책: `cancelled` 플래그 또는 `AbortController`**

```jsx
useEffect(() => {
  const controller = new AbortController()

  async function fetchData() {
    try {
      const res = await fetch(url, { signal: controller.signal })
      const data = await res.json()
      setData(data)
    } catch (err) {
      if (err.name !== 'AbortError') setError(err.message)
    }
  }

  fetchData()
  return () => controller.abort()  // 이전 요청 취소
}, [url])
```

`AbortController`를 쓰면 클린업 시 네트워크 요청 자체를 취소합니다.

## 재시도 패턴

API 요청 실패 시 재시도 버튼을 제공합니다.

```jsx
function RetryExample() {
  const [data, setData] = useState(null)
  const [loading, setLoading] = useState(false)
  const [error, setError] = useState(null)
  const [retryCount, setRetryCount] = useState(0)

  useEffect(() => {
    async function load() {
      try {
        setLoading(true)
        setError(null)
        const res = await fetch('/api/data')
        const json = await res.json()
        setData(json)
      } catch (err) {
        setError(err.message)
      } finally {
        setLoading(false)
      }
    }
    load()
  }, [retryCount])  // retryCount가 바뀌면 다시 실행

  if (loading) return <p>로딩 중...</p>
  if (error) return (
    <div>
      <p>오류: {error}</p>
      <button onClick={() => setRetryCount(c => c + 1)}>다시 시도</button>
    </div>
  )
  return <pre>{JSON.stringify(data, null, 2)}</pre>
}
```

## POST 요청 — 데이터 전송

`GET`이 아닌 `POST`로 데이터를 보낼 때:

```jsx
function CreatePostForm() {
  const [title, setTitle] = useState('')
  const [submitting, setSubmitting] = useState(false)
  const [error, setError] = useState(null)

  async function handleSubmit(e) {
    e.preventDefault()
    setSubmitting(true)
    setError(null)

    try {
      const res = await fetch('/api/posts', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ title }),
      })
      if (!res.ok) throw new Error('게시물 생성 실패')
      const newPost = await res.json()
      console.log('생성됨:', newPost)
      setTitle('')
    } catch (err) {
      setError(err.message)
    } finally {
      setSubmitting(false)
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={title}
        onChange={e => setTitle(e.target.value)}
        placeholder="제목"
      />
      <button type="submit" disabled={submitting}>
        {submitting ? '저장 중...' : '게시물 작성'}
      </button>
      {error && <p>{error}</p>}
    </form>
  )
}
```

## TanStack Query 소개

실무에서는 직접 useEffect로 패칭하는 대신 **TanStack Query(구 React Query)** 를 많이 씁니다.

```jsx
// 설치: npm install @tanstack/react-query

import { useQuery } from '@tanstack/react-query'

function UserList() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'],
    queryFn: () => fetch('/api/users').then(r => r.json()),
  })

  if (isLoading) return <p>로딩 중...</p>
  if (error) return <p>에러: {error.message}</p>

  return <ul>{data.map(u => <li key={u.id}>{u.name}</li>)}</ul>
}
```

TanStack Query는 캐싱, 자동 재시도, 백그라운드 업데이트, 경쟁 조건 처리를 자동으로 해줍니다.

---

## 핵심 정리

- 패칭 패턴: `loading` + `error` + `data` 세 상태로 관리.
- **경쟁 조건**: `cancelled` 플래그 또는 `AbortController`로 이전 요청 무효화.
- 재시도: 별도 `retryCount` state를 의존성에 넣어 이펙트 재실행.
- POST 요청: `fetch`의 `method`, `headers`, `body` 옵션 사용.
- 실무: TanStack Query 같은 라이브러리로 복잡성 줄이기.
