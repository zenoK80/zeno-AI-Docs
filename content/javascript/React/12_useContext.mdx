## Props Drilling — 문제 상황

앱이 커지면 데이터를 부모 → 자식 → 손자 → 증손자까지 props로 계속 전달해야 할 때가 생깁니다. 이를 **Props Drilling**이라 합니다.

```jsx
// user 데이터를 3단계 아래까지 전달
function App() {
  const user = { name: '김철수', theme: 'dark' }
  return <Page user={user} />
}

function Page({ user }) {
  return <Header user={user} />  // 자신은 안 쓰는데 전달만 함
}

function Header({ user }) {
  return <UserInfo user={user} />  // 자신은 안 쓰는데 전달만 함
}

function UserInfo({ user }) {
  return <p>{user.name}</p>  // 여기서 비로소 사용
}
```

중간 컴포넌트들은 user를 쓰지도 않으면서 전달만 합니다.

---

## Context API 해결책

Context는 "공유 저장소"입니다. 어떤 컴포넌트든 직접 값을 꺼낼 수 있습니다.

### 1단계: Context 만들기

```jsx
import { createContext } from 'react'

const UserContext = createContext(null)  // 기본값 = null
```

### 2단계: Provider로 값 공급

```jsx
function App() {
  const user = { name: '김철수', theme: 'dark' }

  return (
    <UserContext.Provider value={user}>
      <Page />
    </UserContext.Provider>
  )
}
```

`Provider`의 `value`에 넘긴 값이 하위 모든 컴포넌트에서 접근 가능합니다.

### 3단계: useContext로 값 소비

```jsx
import { useContext } from 'react'

function UserInfo() {
  const user = useContext(UserContext)  // 직접 꺼내 사용

  return <p>{user.name}</p>
}
```

이제 중간 컴포넌트(Page, Header)는 user를 전달받지 않아도 됩니다.

---

## 실전 예제 — 다크 모드

```jsx
import { createContext, useContext, useState } from 'react'

const ThemeContext = createContext('light')

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light')

  function toggleTheme() {
    setTheme(prev => prev === 'light' ? 'dark' : 'light')
  }

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  )
}

// 어디서든 테마 접근
function Header() {
  const { theme, toggleTheme } = useContext(ThemeContext)

  return (
    <header style={{ background: theme === 'dark' ? '#333' : '#fff' }}>
      <button onClick={toggleTheme}>
        {theme === 'dark' ? '라이트 모드' : '다크 모드'}
      </button>
    </header>
  )
}

function App() {
  return (
    <ThemeProvider>
      <Header />
      <main>본문</main>
    </ThemeProvider>
  )
}
```

## 커스텀 훅으로 감싸기

`useContext(SomeContext)` 를 반복 쓰는 대신, 커스텀 훅으로 감싸면 실수를 방지합니다.

```jsx
function useTheme() {
  const context = useContext(ThemeContext)
  if (!context) {
    throw new Error('useTheme는 ThemeProvider 안에서만 사용할 수 있습니다.')
  }
  return context
}

// 사용 — useContext를 직접 쓰지 않아도 됨
function Button() {
  const { theme } = useTheme()
  return <button className={theme}>클릭</button>
}
```

## Context의 한계

Context는 Provider의 value가 바뀌면 해당 Context를 구독하는 **모든 컴포넌트가 리렌더링**됩니다. 자주 바뀌는 데이터(예: 매 초 바뀌는 타이머)를 Context에 두면 성능 문제가 생길 수 있습니다.

자주 쓰는 Context 용도:
- 로그인 사용자 정보
- 테마 (다크/라이트)
- 언어(다국어)
- 전역 알림·토스트

자주 바뀌는 데이터는 Zustand 같은 상태 관리 라이브러리가 적합합니다 (19장).

### 흔한 실수 — value에 매번 새 객체를 전달

```jsx
// ❌ 렌더링마다 새 객체가 생성됨
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light')
  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {/* value={{...}} 는 매 렌더링마다 "새로운" 객체입니다 */}
      {children}
    </ThemeContext.Provider>
  )
}
```

`{ theme, toggleTheme }`처럼 객체 리터럴을 직접 넘기면, `ThemeProvider`가 리렌더링될 때마다(예: 부모의 다른 이유로) **내용은 같아도 매번 새로운 객체**가 만들어집니다. React는 참조(메모리 주소)가 다르면 "값이 바뀌었다"고 판단하므로, 모든 구독 컴포넌트가 불필요하게 리렌더링됩니다.

```jsx
// ✅ useMemo로 값이 실제로 바뀔 때만 새 객체 생성
const value = useMemo(() => ({ theme, toggleTheme }), [theme])

return (
  <ThemeContext.Provider value={value}>
    {children}
  </ThemeContext.Provider>
)
```

(`useMemo`는 15번 문서에서 자세히 다룹니다. 지금은 "Context에 객체를 넘길 때는 이 문제를 조심해야 한다"는 것만 기억해도 충분합니다.)

---

## 핵심 정리

- **Props Drilling**: 중간 컴포넌트를 통해 데이터를 계속 전달하는 문제.
- **Context API**: `createContext` → `Provider`로 값 공급 → `useContext`로 어디서든 접근.
- `value`가 바뀌면 구독 컴포넌트 전체가 리렌더링됨. 자주 안 바뀌는 전역 데이터에 적합.
- 커스텀 훅으로 감싸면 Provider 밖 사용 시 오류를 미리 잡을 수 있다.
