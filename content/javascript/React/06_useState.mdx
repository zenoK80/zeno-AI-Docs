## 왜 일반 변수로는 화면이 바뀌지 않나?

React 컴포넌트는 함수입니다. 화면에 변화가 필요하면 함수를 다시 실행(리렌더링)합니다. 하지만 함수 안의 일반 변수는 함수가 다시 실행될 때마다 초기화됩니다.

```jsx
// ❌ 일반 변수 — 화면이 바뀌지 않음
function Counter() {
  let count = 0  // 리렌더링 시 항상 0으로 초기화

  function handleClick() {
    count++  // 값은 바뀌지만 리렌더링이 일어나지 않음
    console.log(count)  // 숫자는 올라가지만 화면은 그대로
  }

  return <button onClick={handleClick}>{count}</button>
}
```

React가 화면을 다시 그리려면 두 가지가 필요합니다.
1. **값을 기억하는 공간** (리렌더링 후에도 유지)
2. **값이 바뀌었다는 신호** (React가 리렌더링을 실행하도록)

`useState`가 이 두 가지를 모두 제공합니다.

---

## useState 기본 사용법

```jsx
import { useState } from 'react'

function Counter() {
  const [count, setCount] = useState(0)
  //    [현재값, 변경함수]  초기값

  return (
    <div>
      <p>클릭 횟수: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count - 1)}>-1</button>
      <button onClick={() => setCount(0)}>초기화</button>
    </div>
  )
}
```

`useState(0)` 이 반환하는 배열을 구조 분해 해서 `[count, setCount]` 로 받습니다.
- `count`: 현재 상태 값 (초기에는 0)
- `setCount(새값)`: 상태를 바꾸고 리렌더링을 요청하는 함수

> **쉽게 말하면:** `useState`는 React가 관리하는 "기억 공간"입니다. 값을 바꾸면 React가 자동으로 화면을 다시 그려줍니다.

## 다양한 타입의 상태

숫자 뿐만 아니라 어떤 값이든 상태로 관리할 수 있습니다.

```jsx
function Examples() {
  const [text, setText] = useState('')              // 문자열
  const [isVisible, setIsVisible] = useState(false) // 불리언
  const [items, setItems] = useState([])            // 배열
  const [user, setUser] = useState(null)            // null
  const [form, setForm] = useState({                // 객체
    name: '',
    email: '',
  })

  return (
    <div>
      <input value={text} onChange={e => setText(e.target.value)} />
      <button onClick={() => setIsVisible(!isVisible)}>
        {isVisible ? '숨기기' : '보이기'}
      </button>
    </div>
  )
}
```

## 불변성(Immutability) — 배열·객체 상태 업데이트

React는 상태가 바뀌었는지 참조(메모리 주소)를 비교합니다. 배열이나 객체를 **직접 수정하면 React가 변화를 감지하지 못합니다.**

```jsx
const [items, setItems] = useState(['사과', '바나나'])

// ❌ 직접 수정 — React가 변화를 감지 못함
function addItem() {
  items.push('포도')  // 원본 배열을 변경
  setItems(items)     // 참조가 같아 리렌더링 안 됨
}

// ✅ 새 배열/객체를 만들어서 교체
function addItem() {
  setItems([...items, '포도'])  // 새 배열 생성
}

function removeItem(index) {
  setItems(items.filter((_, i) => i !== index))  // filter로 새 배열
}
```

**객체 상태도 마찬가지:**

```jsx
const [user, setUser] = useState({ name: '김철수', age: 25 })

// ❌ 직접 수정
user.age = 26
setUser(user)

// ✅ 스프레드로 새 객체 생성
setUser({ ...user, age: 26 })
```

## 함수형 업데이트 — 이전 값 기반으로 업데이트

`setCount(count + 1)` 대신 **함수를 전달**하면, 이전 상태를 확실히 받아 사용할 수 있습니다. 연속 업데이트나 비동기 상황에서 안전합니다.

```jsx
// 일반 업데이트 — 클릭이 빠르면 최신 count가 아닐 수도 있음
setCount(count + 1)

// 함수형 업데이트 — prev는 항상 최신 상태
setCount(prev => prev + 1)
```

버튼을 여러 번 빠르게 클릭하거나 `setCount`를 연달아 호출할 때는 함수형 업데이트가 더 안전합니다.

---

## 상태 초기값 지연 초기화

초기값 계산이 무거운 경우, 함수를 전달하면 처음 마운트될 때 한 번만 실행됩니다.

```jsx
// ❌ 매 렌더링마다 heavyCalculation()이 호출됨
const [data, setData] = useState(heavyCalculation())

// ✅ 첫 렌더링에만 호출됨
const [data, setData] = useState(() => heavyCalculation())
```

---

## 핵심 정리

- 일반 변수는 리렌더링 시 초기화되고, 변경해도 화면이 갱신되지 않는다.
- `useState(초기값)`은 `[현재값, 변경함수]` 배열을 반환한다.
- 변경 함수를 호출하면 React가 리렌더링을 트리거한다.
- **불변성**: 배열·객체는 직접 수정하지 않고 스프레드 `...`나 `filter`, `map`으로 새 값을 만든다.
- 이전 값 기반 업데이트에는 `setState(prev => prev + 1)` 형태가 안전하다.
