## 리렌더링이 발생하는 경우

```
1. state가 변경될 때
2. props가 변경될 때
3. 부모 컴포넌트가 리렌더링될 때
4. context 값이 변경될 때
```

## React.memo — 컴포넌트 메모이제이션

부모가 리렌더링되어도 props가 바뀌지 않으면 자식을 리렌더링하지 않습니다.

```jsx
// memo 없이 — 부모 리렌더링 시 항상 리렌더링됨
function ExpensiveChild({ name }) {
  console.log('렌더링')
  return <p>{name}</p>
}

// memo 적용 — props가 바뀔 때만 리렌더링
const ExpensiveChild = React.memo(function ExpensiveChild({ name }) {
  console.log('렌더링')
  return <p>{name}</p>
})

function Parent() {
  const [count, setCount] = useState(0)
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>카운트: {count}</button>
      <ExpensiveChild name="고정값" /> {/* count 변경 시 리렌더링 안 됨 */}
    </div>
  )
}
```

## useMemo — 계산 결과 메모이제이션

의존성이 바뀔 때만 무거운 계산을 재실행합니다.

```jsx
function ProductList({ products, filter }) {
  // filter가 바뀔 때만 재계산
  const filteredProducts = useMemo(
    () => products.filter(p => p.category === filter),
    [products, filter]
  )

  return (
    <ul>
      {filteredProducts.map(p => <li key={p.id}>{p.name}</li>)}
    </ul>
  )
}
```

## useCallback — 함수 메모이제이션

의존성이 바뀔 때만 새 함수를 생성합니다. React.memo와 함께 쓸 때 효과적입니다.

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  // count가 바뀌어도 handleClick은 동일한 참조 유지
  const handleClick = useCallback(() => {
    console.log('클릭')
  }, []) // 의존성 없음 → 항상 같은 함수

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>{count}</button>
      <MemoizedButton onClick={handleClick} />
    </div>
  )
}

const MemoizedButton = React.memo(function MemoizedButton({ onClick }) {
  console.log('버튼 렌더링')
  return <button onClick={onClick}>클릭</button>
})
```

## 코드 분할 (Code Splitting)

초기 번들 크기를 줄여 첫 로딩 속도를 개선합니다.

```jsx
import { lazy, Suspense } from 'react'

// 컴포넌트를 동적으로 임포트
const HeavyChart = lazy(() => import('./HeavyChart'))
const AdminPanel = lazy(() => import('./AdminPanel'))

function App() {
  return (
    <Suspense fallback={<div>로딩 중...</div>}>
      <HeavyChart />
    </Suspense>
  )
}

// React Router와 함께 라우트별 코드 분할
const Home = lazy(() => import('./pages/Home'))
const About = lazy(() => import('./pages/About'))

function Router() {
  return (
    <Suspense fallback={<Spinner />}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </Suspense>
  )
}
```

## 최적화 적용 기준

```
언제 최적화해야 하나?

React.memo: 자식 컴포넌트가 무겁고 props가 자주 바뀌지 않을 때
useMemo: 계산 비용이 크고 의존성이 자주 바뀌지 않을 때
useCallback: React.memo 적용 컴포넌트에 핸들러를 전달할 때

경고:
- 모든 컴포넌트에 React.memo를 쓰면 메모이제이션 비교 비용이 더 클 수 있음
- useMemo/useCallback의 과도한 사용은 코드 복잡도만 높임
- 먼저 프로파일러로 병목을 찾은 후 최적화 적용
```

## React DevTools Profiler

```
1. React DevTools 설치
2. Profiler 탭 클릭 → 녹화 시작
3. 인터랙션 수행
4. 녹화 중지 → 리렌더링 이유와 시간 확인
5. 문제가 있는 컴포넌트에만 최적화 적용
```

## 핵심 정리

- `React.memo`는 props가 바뀌지 않으면 컴포넌트 리렌더링을 건너뜁니다.
- `useMemo`는 의존성이 바뀔 때만 무거운 계산을 재실행합니다.
- `useCallback`은 의존성이 바뀔 때만 새 함수 참조를 생성합니다.
- `lazy + Suspense`로 코드를 분할해 초기 로딩 속도를 개선합니다.
- 최적화는 Profiler로 병목을 먼저 확인한 후 적용합니다.
