## 조건부 렌더링 패턴 정리

04장 JSX에서 기본을 익혔습니다. 여기서는 더 복잡한 상황을 다룹니다.

### 삼항 연산자

두 가지 중 하나를 선택할 때 씁니다.

```jsx
function LoginButton({ isLoggedIn }) {
  return (
    <button>
      {isLoggedIn ? '로그아웃' : '로그인'}
    </button>
  )
}
```

### 논리 AND(`&&`) — 하나만 있을 때

```jsx
function Notification({ count }) {
  return (
    <div>
      <p>메일함</p>
      {count > 0 && <span className="badge">{count}</span>}
    </div>
  )
}
```

### 변수로 꺼내기 — 복잡한 조건일 때

JSX가 길어지면 변수에 먼저 담습니다.

```jsx
function UserStatus({ user, isLoading, error }) {
  let content

  if (isLoading) {
    content = <p>불러오는 중...</p>
  } else if (error) {
    content = <p className="error">오류: {error}</p>
  } else if (!user) {
    content = <p>사용자를 찾을 수 없습니다.</p>
  } else {
    content = (
      <div>
        <h2>{user.name}</h2>
        <p>{user.email}</p>
      </div>
    )
  }

  return <div className="status">{content}</div>
}
```

### 즉시 실행 함수 패턴

JSX 안에서 바로 if 로직을 쓰고 싶을 때 사용합니다.

```jsx
function Example({ status }) {
  return (
    <div>
      {(() => {
        if (status === 'loading') return <Spinner />
        if (status === 'error') return <ErrorMessage />
        return <Content />
      })()}
    </div>
  )
}
```

## 리스트 렌더링 심화

### 중첩 리스트

```jsx
const categories = [
  {
    id: 1,
    name: '과일',
    items: ['사과', '바나나', '포도'],
  },
  {
    id: 2,
    name: '채소',
    items: ['당근', '브로콜리'],
  },
]

function CategoryList() {
  return (
    <ul>
      {categories.map(category => (
        <li key={category.id}>
          <h3>{category.name}</h3>
          <ul>
            {category.items.map(item => (
              <li key={item}>{item}</li>
            ))}
          </ul>
        </li>
      ))}
    </ul>
  )
}
```

### filter + map 조합 — 조건부 리스트

```jsx
function ActiveUserList({ users }) {
  return (
    <ul>
      {users
        .filter(user => user.isActive)
        .map(user => (
          <li key={user.id}>{user.name}</li>
        ))
      }
    </ul>
  )
}
```

### map 안에서 여러 요소를 반환해야 할 때 — key가 있는 Fragment

`.map()` 콜백은 하나의 JSX만 반환해야 하지만, 항목마다 형제 요소 두 개(예: 용어와 설명)를 나란히 렌더링해야 할 때가 있습니다. 이때 일반 Fragment(`<>`)는 `key`를 받을 수 없으므로, 축약형이 아닌 **풀네임 `<Fragment key={...}>`**를 씁니다.

```jsx
import { Fragment } from 'react'

function Glossary({ terms }) {
  return (
    <dl>
      {terms.map(term => (
        <Fragment key={term.id}>
          <dt>{term.word}</dt>
          <dd>{term.definition}</dd>
        </Fragment>
      ))}
    </dl>
  )
}
```

`<>...</>`는 `<Fragment>...</Fragment>`의 축약형인데, 축약형 문법에는 props(key 포함)를 전달할 방법이 없습니다. key가 필요한 리스트 안에서는 반드시 `Fragment`를 명시적으로 import해서 씁니다.

## 빈 상태 처리 (Empty State)

리스트가 비었을 때 아무것도 표시 안 하면 사용자는 오류인지 정상인지 알 수 없습니다. 빈 상태 메시지를 항상 제공하세요.

```jsx
function TodoList({ todos }) {
  if (todos.length === 0) {
    return (
      <div className="empty-state">
        <p>아직 할 일이 없습니다.</p>
        <p>새 할 일을 추가해 보세요!</p>
      </div>
    )
  }

  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  )
}
```

              {product.name} — {product.price.toLocaleString()}원

            </li>
          ))}
        </ul>
      )}
    </section>
  )
}`,
  }}
/>

## 로딩·에러·빈 상태 삼중 처리

실무에서 가장 흔한 리스트 컴포넌트 패턴입니다.

```jsx
function ArticleList() {
  const [articles, setArticles] = useState([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState(null)

  useEffect(() => {
    async function load() {
      try {
        const res = await fetch('/api/articles')
        const data = await res.json()
        setArticles(data)
      } catch {
        setError('기사를 불러오지 못했습니다.')
      } finally {
        setLoading(false)
      }
    }
    load()
  }, [])

  if (loading) return <p>로딩 중...</p>
  if (error) return <p>{error}</p>
  if (articles.length === 0) return <p>기사가 없습니다.</p>

  return (
    <ul>
      {articles.map(article => (
        <li key={article.id}>{article.title}</li>
      ))}
    </ul>
  )
}
```

## 핵심 정리

- 간단한 조건 → 삼항(`? :`), 있을 때만 렌더링 → `&&`, 복잡한 조건 → 변수로 꺼내기.
- 리스트 렌더링: `.map()` + `key` prop. 중첩 리스트도 중첩 `.map()` 사용.
- `.filter()` + `.map()` 조합으로 조건부 리스트 렌더링.
- **빈 상태**(empty state): 리스트가 비었을 때 사용자에게 알려주는 UI를 항상 제공.
- 실무 패턴: 로딩 → 에러 → 빈 상태 → 데이터 순서로 처리.
