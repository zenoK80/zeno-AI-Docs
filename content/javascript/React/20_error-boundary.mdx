## Error Boundary란?

React에서 컴포넌트가 렌더링 중 오류를 던지면 앱 전체가 흰 화면이 됩니다. **Error Boundary**는 오류를 감지해 앱 전체 대신 해당 영역만 대체 UI를 보여줍니다.

```
앱 전체 렌더링 트리
├── Header (정상)
├── Sidebar (정상)
└── [Error Boundary]
    └── WeatherWidget (오류 발생!)
        → WeatherWidget 대신 "날씨 정보를 불러올 수 없습니다" 표시
        → Header, Sidebar는 정상 유지
```

> **쉽게 말하면:** Error Boundary는 "이 구역에서 화재가 나면 다른 구역으로 번지지 않게 막는 방화벽"입니다.

## Error Boundary 구현

Error Boundary는 아직 **클래스 컴포넌트**로만 구현 가능합니다.

  template="react"
  activeFile="/App.js"
  showConsole
  label="Error Boundary 실습 — 버튼을 눌러 오류를 발생시켜보세요"
  files={{
    '/App.js': `import { Component, useState } from 'react'

class ErrorBoundary extends Component {
  constructor(props) {
    super(props)
    this.state = { hasError: false, error: null }
  }

  // 오류 발생 시 state 업데이트
  static getDerivedStateFromError(error) {
    return { hasError: true, error }
  }

  // 오류 로깅
  componentDidCatch(error, info) {
    console.error('오류 발생:', error, info.componentStack)
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || <p>오류가 발생했습니다.</p>
    }
    return this.props.children
  }
}

function BuggyWidget() {
  const [crash, setCrash] = useState(false)
  if (crash) {
    throw new Error('위젯 렌더링 실패!')
  }
  return <button onClick={() => setCrash(true)}>오류 발생시키기</button>
}

// 사용
export default function App() {
  return (
    <div>
      <h3>Header (정상 유지됨)</h3>
      <ErrorBoundary fallback={<p>날씨 정보를 불러올 수 없습니다.</p>}>
        <BuggyWidget />
      </ErrorBoundary>
    </div>
  )
}`,
  }}
/>

## react-error-boundary 라이브러리

직접 클래스를 작성하지 않고 라이브러리를 씁니다.

```bash
npm install react-error-boundary
```

```jsx
import { ErrorBoundary } from 'react-error-boundary'

function FallbackComponent({ error, resetErrorBoundary }) {
  return (
    <div>
      <p>오류: {error.message}</p>
      <button onClick={resetErrorBoundary}>다시 시도</button>
    </div>
  )
}

function App() {
  return (
    <ErrorBoundary FallbackComponent={FallbackComponent}>
      <SomeComponent />
    </ErrorBoundary>
  )
}
```

## Suspense — 비동기 로딩 선언

`Suspense`는 자식 컴포넌트가 준비되기 전까지 `fallback`을 보여줍니다. React.lazy로 코드를 분할할 때 씁니다.

```jsx
import { lazy, Suspense } from 'react'

// 동적 임포트 — 필요할 때 로드
const HeavyChart = lazy(() => import('./HeavyChart'))

function Dashboard() {
  return (
    <div>
      <h1>대시보드</h1>
      <Suspense fallback={<p>차트 로딩 중...</p>}>
        <HeavyChart />
      </Suspense>
    </div>
  )
}
```

초기 번들 크기를 줄여 첫 로딩 속도를 개선합니다. HeavyChart는 실제로 필요할 때만 다운로드됩니다.

## Error Boundary가 잡지 못하는 오류

```
✅ 잡을 수 있음:
- 렌더링 중 발생하는 오류
- 생명주기 메서드의 오류
- 자식 컴포넌트의 생성자 오류

❌ 잡을 수 없음:
- 이벤트 핸들러 오류 (try-catch로 처리)
- 비동기 코드 오류 (async/await, setTimeout)
- Error Boundary 자체의 오류
```

이벤트 핸들러 오류는 직접 try-catch로 처리해야 합니다.

```jsx
function Button() {
  async function handleClick() {
    try {
      await doSomethingRisky()
    } catch (err) {
      setError(err.message)
    }
  }

  return <button onClick={handleClick}>클릭</button>
}
```

---

## 핵심 정리

- **Error Boundary**: 렌더링 오류를 감지해 대체 UI를 보여주는 클래스 컴포넌트. 오류가 앱 전체로 퍼지는 것을 막는다.
- `react-error-boundary` 라이브러리로 더 편하게 사용 가능. 오류 재시도 기능 포함.
- **Suspense**: `lazy()`로 코드 분할 시 로딩 중 fallback UI 표시.
- Error Boundary는 이벤트 핸들러·비동기 오류를 잡지 못함. 직접 try-catch 처리 필요.
