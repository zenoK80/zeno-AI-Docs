## 왜 컴포넌트가 필요한가?

웹 페이지를 보면 같은 UI 조각이 반복됩니다. 쇼핑몰의 상품 카드, 인스타그램의 게시물, 유튜브의 영상 목록. 매번 같은 HTML을 복사 붙여넣기 하면 내용 하나를 바꿀 때 수십 군데를 모두 수정해야 합니다.

> **쉽게 말하면:** 컴포넌트는 재사용 가능한 UI 틀(template)입니다. 틀 하나를 만들어 놓으면 데이터만 바꿔서 여러 번 찍어낼 수 있습니다.

---

## 함수형 컴포넌트

React 컴포넌트는 **JSX를 반환하는 함수**입니다. 컴포넌트 이름은 반드시 **대문자**로 시작해야 합니다.

```jsx
// ✅ 올바른 컴포넌트 — 이름이 대문자로 시작
function Greeting() {
  return <h1>안녕하세요!</h1>
}

// ❌ 소문자로 시작 — HTML 태그로 인식됨
function greeting() {
  return <h1>안녕하세요!</h1>
}
```

```jsx
// 화살표 함수로도 작성 가능
const Greeting = () => {
  return <h1>안녕하세요!</h1>
}

// 반환이 JSX 하나뿐이면 더 짧게
const Greeting = () => <h1>안녕하세요!</h1>
```

## Props — 컴포넌트에 데이터 전달하기

**Props(properties)** 는 부모 컴포넌트가 자식 컴포넌트에게 전달하는 데이터입니다. HTML의 속성(attribute)처럼 작성하고, 컴포넌트 함수에서 객체로 받습니다.

```jsx
// 자식 컴포넌트 — props 객체를 매개변수로 받음
function UserCard(props) {
  return (
    <div className="card">
      <h2>{props.name}</h2>
      <p>{props.email}</p>
      <p>나이: {props.age}세</p>
    </div>
  )
}

// 부모 컴포넌트 — props 전달
function App() {
  return (
    <div>
      <UserCard name="김철수" email="kim@example.com" age={25} />
      <UserCard name="이영희" email="lee@example.com" age={30} />
    </div>
  )
}
```

### Props 구조 분해

`props.name`, `props.email`처럼 매번 쓰는 대신, 구조 분해로 더 깔끔하게 씁니다.

```jsx
function UserCard({ name, email, age }) {
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>{email}</p>
      <p>나이: {age}세</p>
    </div>
  )
}
```

### 기본값 설정

Props가 없을 때 쓸 기본값을 정의할 수 있습니다.

```jsx
function Button({ label = '버튼', color = 'blue', onClick }) {
  return (
    <button
      style={{ backgroundColor: color }}
      onClick={onClick}
    >
      {label}
    </button>
  )
}

// label, color 없이 쓰면 기본값 사용
<Button onClick={() => alert('클릭!')} />
// → label: '버튼', color: 'blue' 적용
```

### props 객체 통째로 펼치기(spread)

전달받은 props 중 일부만 쓰고, 나머지는 그대로 밑으로 흘려보내고 싶을 때 스프레드 문법을 씁니다.

```jsx
function CustomInput({ label, ...rest }) {
  return (
    <label>
      {label}
      {/* type, placeholder, value, onChange 등 나머지 props를 그대로 input에 전달 */}
      <input {...rest} />
    </label>
  )
}

// 사용
<CustomInput label="이메일" type="email" placeholder="이메일 입력" value={email} onChange={handleChange} />
```

`{ label, ...rest }`로 `label`만 따로 꺼내고, 나머지 모든 props(`type`, `placeholder`, `value`, `onChange`)는 `rest` 객체에 자동으로 모입니다. `<input {...rest} />`는 그 객체의 모든 키-값을 다시 개별 props로 풀어서 전달합니다. 재사용 가능한 UI 라이브러리 컴포넌트를 만들 때 매우 자주 쓰는 패턴입니다.

## Props는 읽기 전용

Props는 자식에서 직접 수정할 수 없습니다. 수정이 필요하면 부모에게 콜백 함수로 요청해야 합니다.

```jsx
// ❌ 절대 안 됨
function BadComponent({ name }) {
  name = '다른 이름'  // props를 직접 바꾸면 안 됨
  return <p>{name}</p>
}

// ✅ 상태로 관리하거나 부모에게 콜백으로 요청
function GoodComponent({ name, onChangeName }) {
  return (
    <div>
      <p>{name}</p>
      <button onClick={() => onChangeName('새 이름')}>이름 변경</button>
    </div>
  )
}
```

**왜 React가 이렇게 강제할까?** props가 자유롭게 수정 가능하다면, 같은 데이터를 참조하는 다른 형제 컴포넌트가 "누가 언제 이 값을 바꿨는지" 추적할 수 없게 됩니다. 데이터가 오직 부모 → 자식으로만 흐르고, 변경은 항상 데이터의 "주인"(원래 상태를 가진 컴포넌트)에서만 일어나야 흐름을 예측할 수 있습니다.

> **비유:** props는 계약서 사본과 같습니다. 사본을 받은 사람이 마음대로 내용을 고쳐 쓰면 원본과 달라져 혼란이 생깁니다. 내용을 바꾸고 싶으면 원본을 가진 사람(부모)에게 "이렇게 바꿔주세요"(콜백 함수 호출)라고 요청해야 합니다.

### Prop Drilling — props 전달의 한계

컴포넌트 트리가 깊어지면, 최상위에서 최하위까지 props를 계속 한 단계씩 전달해야 하는 문제가 생깁니다. 이를 **Prop Drilling(props 구멍 뚫기)**이라고 부릅니다.

```jsx
function App() {
  const user = { name: '김철수' }
  return <Layout user={user} />
}
function Layout({ user }) {
  return <Sidebar user={user} />   // Layout은 user를 쓰지도 않는데 그냥 전달만 함
}
function Sidebar({ user }) {
  return <UserBadge user={user} /> // Sidebar도 마찬가지
}
function UserBadge({ user }) {
  return <p>{user.name}</p>        // 실제로 user를 쓰는 곳은 여기뿐
}
```

`Layout`과 `Sidebar`는 `user`를 실제로 쓰지 않는데도 중간 전달자 역할만 합니다. 이 문제는 12번 문서에서 배울 **Context API**로 해결합니다.

## children prop — 컴포넌트 안에 콘텐츠 넣기

`children`은 컴포넌트 태그 사이에 넣은 내용을 받는 특별한 prop입니다.

```jsx
// children을 받아 사용하는 컴포넌트
function Card({ title, children }) {
  return (
    <div className="card">
      <h2 className="card-title">{title}</h2>
      <div className="card-body">
        {children}
      </div>
    </div>
  )
}

// 사용 — 태그 사이의 내용이 children이 됨
function App() {
  return (
    <Card title="회원 정보">
      <p>이름: 김철수</p>
      <p>이메일: kim@example.com</p>
      <button>수정</button>
    </Card>
  )
}
```

`Card` 컴포넌트는 내부 내용이 무엇인지 몰라도 됩니다. 어떤 JSX든 `children`으로 받아서 렌더링합니다.

### children은 사실 그냥 하나의 prop이다

`children`은 마법이 아니라, JSX가 태그 사이의 내용을 자동으로 `children`이라는 이름의 prop으로 채워주는 것뿐입니다. 아래 두 코드는 완전히 동일합니다.

```jsx
// 일반적으로 쓰는 방식
<Card title="정보">
  <p>내용</p>
</Card>

// 완전히 같은 의미 — children을 직접 prop으로 전달
<Card title="정보" children={<p>내용</p>} />
```

여러 개의 "구멍(슬롯)"이 필요하면, `children` 대신 일반 props로 JSX를 여러 개 전달할 수도 있습니다.

```jsx
function SplitLayout({ left, right }) {
  return (
    <div style={{ display: 'flex' }}>
      <div className="left">{left}</div>
      <div className="right">{right}</div>
    </div>
  )
}

// 사용 — JSX를 prop 값으로 그대로 전달
<SplitLayout
  left={<Sidebar />}
  right={<MainContent />}
/>
```

## 다양한 타입의 Props 전달

```jsx
function Example({ 
  text,       // 문자열
  count,      // 숫자
  isActive,   // 불리언
  items,      // 배열
  user,       // 객체
  onAction,   // 함수
}) {
  return <div>...</div>
}

<Example
  text="안녕하세요"
  count={42}
  isActive={true}
  items={['a', 'b', 'c']}
  user={{ name: '김철수', age: 25 }}
  onAction={() => console.log('클릭!')}
/>
```

<Callout type="info">
  `isActive={true}` 는 `isActive` 처럼 값 없이 쓸 수 있습니다. JSX에서 boolean 속성은 이름만 써도 true입니다.
</Callout>

## 핵심 정리

- 컴포넌트는 **JSX를 반환하는 함수**. 이름은 반드시 **대문자**로 시작.
- **Props**: 부모 → 자식으로 데이터를 전달하는 방법. HTML 속성처럼 작성.
- Props는 구조 분해로 받고, 기본값을 설정할 수 있다.
- **Props는 읽기 전용** — 자식에서 props를 직접 변경할 수 없다.
- **children**: 컴포넌트 태그 사이의 내용이 자동으로 전달되는 특별한 prop. 여러 슬롯이 필요하면 일반 props로 JSX를 전달.
- **스프레드(`{...rest}`)**: 일부 props만 꺼내 쓰고 나머지는 자식 요소로 그대로 흘려보낼 때 사용.
- **Prop Drilling**: 중간 컴포넌트가 쓰지도 않는 props를 계속 전달만 하는 문제. 깊어지면 Context로 해결.
