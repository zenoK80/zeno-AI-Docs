## 왜 메모이제이션이 필요한가?

React는 상태나 props가 바뀌면 컴포넌트를 리렌더링합니다. 리렌더링 시 컴포넌트 함수가 다시 실행되면서:

1. 함수 안의 모든 **계산**이 다시 실행됩니다.
2. 함수 안의 **함수 정의**가 새로 생성됩니다.
3. **자식 컴포넌트**도 다시 렌더링됩니다.

대부분의 경우 이는 문제 없습니다. 하지만 계산이 매우 무겁거나 자식 컴포넌트가 많을 때는 불필요한 작업이 됩니다.

> **쉽게 말하면:** 메모이제이션은 "이미 계산한 결과를 메모해 두고, 입력이 같으면 다시 계산하지 않는다"는 최적화 기법입니다.

## React.memo — 컴포넌트 리렌더링 방지

부모가 리렌더링돼도 **props가 바뀌지 않으면** 자식을 다시 렌더링하지 않습니다.

```jsx
// memo로 감싼 컴포넌트 — props가 같으면 리렌더링 안 함
const ExpensiveList = React.memo(function ExpensiveList({ items }) {
  console.log('ExpensiveList 렌더링')
  return (
    <ul>
      {items.map(item => <li key={item.id}>{item.name}</li>)}
    </ul>
  )
})

function App() {
  const [count, setCount] = useState(0)
  const items = [{ id: 1, name: '항목 1' }]  // ⚠️ 렌더링마다 새 배열 생성

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>count: {count}</button>
      <ExpensiveList items={items} />  {/* count가 바뀌면 items도 새 배열이라 리렌더링 됨 */}
    </div>
  )
}
```

이 예제에서 `items` 배열이 렌더링마다 새로 생성되므로 React.memo가 있어도 리렌더링됩니다. 여기서 `useMemo`가 필요합니다.

## useMemo — 계산 결과 메모이제이션

의존성이 바뀔 때만 재계산합니다.

```jsx
function App() {
  const [count, setCount] = useState(0)

  // items가 렌더링마다 새 배열로 만들어지는 문제 해결
  const items = useMemo(() => [
    { id: 1, name: '항목 1' },
    { id: 2, name: '항목 2' },
  ], [])  // 의존성 없음 → 처음 한 번만 생성

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>count: {count}</button>
      <ExpensiveList items={items} />  {/* 이제 items가 바뀌지 않아 리렌더링 안 함 */}
    </div>
  )
}
```

무거운 계산에도 씁니다.

```jsx
function FilteredList({ todos, filter }) {
  // filter나 todos가 바뀔 때만 재계산
  const filteredTodos = useMemo(
    () => todos.filter(todo => todo.category === filter),
    [todos, filter]
  )

  return <ul>{filteredTodos.map(t => <li key={t.id}>{t.text}</li>)}</ul>
}
```

## useCallback — 함수 메모이제이션

`useMemo`가 값을 메모이제이션하듯, `useCallback`은 **함수**를 메모이제이션합니다.

```jsx
function App() {
  const [count, setCount] = useState(0)
  const [text, setText] = useState('')

  // text가 바뀌어도 handleClick은 새로 생성되지 않음
  const handleClick = useCallback(() => {
    console.log('클릭:', count)
  }, [count])  // count가 바뀔 때만 새 함수 생성

  return (
    <div>
      <input value={text} onChange={e => setText(e.target.value)} />
      <button onClick={() => setCount(count + 1)}>count: {count}</button>
      <ExpensiveButton onClick={handleClick} />
    </div>
  )
}

const ExpensiveButton = React.memo(function({ onClick }) {
  console.log('버튼 렌더링')
  return <button onClick={onClick}>클릭</button>
})
```

`text`가 바뀌어도 `handleClick`은 재생성되지 않아 `ExpensiveButton`이 리렌더링되지 않습니다.

## 언제 쓰고 언제 안 쓰나?

<Callout type="warning">
  메모이제이션은 항상 이점이 있는 것이 아닙니다. 메모이제이션 자체도 비용(메모리, 비교 연산)이 있습니다. 실제로 느린 부분에만 적용하세요.
</Callout>

**써야 할 때:**
- React.memo로 감싼 자식에게 props로 객체/함수를 전달할 때
- 계산 비용이 큰 필터링, 정렬, 집계 연산
- 의존성 배열에 함수를 넣어야 하는 useEffect

**안 써도 될 때:**
- 단순한 값 계산
- 렌더링 횟수가 적은 컴포넌트
- 성능 문제가 없는 곳

---

## 핵심 정리

- `React.memo(컴포넌트)`: props가 같으면 리렌더링 스킵.
- `useMemo(() => 계산, [의존성])`: 의존성 변경 시에만 재계산.
- `useCallback(() => 함수, [의존성])`: 의존성 변경 시에만 새 함수 생성.
- 과도한 메모이제이션은 오히려 성능을 해친다. 측정 후 필요한 곳에만 사용.
