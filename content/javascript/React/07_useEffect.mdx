## 사이드 이펙트란?

React 컴포넌트는 기본적으로 "상태를 받아서 화면을 그리는" 순수한 역할을 합니다. 하지만 실제 앱에서는 화면 그리기 외에도 여러 작업이 필요합니다.

- 서버에서 데이터 가져오기 (fetch)
- 타이머 설정 (setInterval, setTimeout)
- 이벤트 리스너 등록 (addEventListener)
- 로컬 스토리지 읽고 쓰기

이런 작업들을 **사이드 이펙트**(side effect) 라고 합니다. 컴포넌트 안에서 직접 실행하면 렌더링마다 실행되거나 예상치 못한 문제가 생깁니다.

> **쉽게 말하면:** `useEffect`는 "화면이 그려진 뒤에 이 코드를 실행해줘"라고 React에게 예약하는 훅입니다.

### useEffect는 "언제" 실행되는가?

`useEffect`의 콜백은 컴포넌트 함수가 실행되어 반환값(JSX)이 나온 **직후가 아니라, 브라우저가 실제 화면에 그림을 그린 뒤**(paint 이후) 비동기적으로 실행됩니다.

```
1. 컴포넌트 함수 실행 → JSX 반환
2. React가 실제 DOM에 반영
3. 브라우저가 화면에 그림을 그림 (paint)
4. useEffect 콜백 실행    ← 여기!
```

이 때문에 `useEffect` 안에서 `document.title`을 바꾸거나 `fetch`를 호출해도 사용자가 화면을 보는 데 지장이 없습니다. (반대로, 화면이 그려지기 *전에* 동기적으로 처리해야 하는 드문 경우에는 `useLayoutEffect`를 씁니다. 15번 문서 이후에서 다시 다룹니다.)

## useEffect 기본 사용법

```jsx
import { useState, useEffect } from 'react'

function Timer() {
  const [seconds, setSeconds] = useState(0)

  useEffect(() => {
    // 컴포넌트가 화면에 나타난 뒤 실행
    console.log('화면에 나타났다!')
  })

  return <p>{seconds}초</p>
}
```

`useEffect(콜백, 의존성배열)` 형태입니다. 의존성 배열 없이 쓰면 **매 렌더링마다** 실행됩니다.

## 의존성 배열로 실행 시점 제어

```jsx
useEffect(() => {
  // 실행 코드
}, 의존성배열)
```

| 의존성 배열 | 언제 실행되나 |
| --- | --- |
| 없음 (생략) | 매 렌더링마다 |
| `[]` (빈 배열) | 처음 마운트될 때 한 번만 |
| `[a, b]` | 처음 + a 또는 b가 바뀔 때마다 |

```jsx
function UserProfile({ userId }) {
  const [user, setUser] = useState(null)

  // userId가 바뀔 때마다 새로운 사용자 데이터를 불러옴
  useEffect(() => {
    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => setUser(data))
  }, [userId])  // userId 가 의존성

  if (!user) return <p>로딩 중...</p>
  return <p>{user.name}님의 프로필</p>
}
```

```jsx
// 마운트될 때 한 번만 실행 — 이벤트 리스너 등록
useEffect(() => {
  window.addEventListener('resize', handleResize)
}, [])  // 빈 배열
```

### 클로저(Closure)와 오래된 값(Stale State) 문제

`useEffect` 안에서 참조하는 state·props는 **그 이펙트가 등록될 당시의 값에 고정**됩니다. 의존성 배열에 넣지 않으면 값이 바뀌어도 이펙트 안에서는 옛날 값을 계속 참조하는 버그가 생깁니다.

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    const id = setInterval(() => {
      console.log(count) // ❌ 항상 0만 출력됨 (등록 당시의 count가 "갇혀버림")
    }, 1000)
    return () => clearInterval(id)
  }, []) // count가 의존성에 없음 — 첫 렌더링의 count=0을 계속 참조

  return <button onClick={() => setCount(c => c + 1)}>{count}</button>
}
```

`count`를 화면에서 계속 증가시켜도, `setInterval` 콜백은 이펙트가 처음 등록될 때의 `count`(0)를 계속 참조합니다. 이를 **오래된 클로저**(Stale Closure)라고 부릅니다. 해결하려면 `count`를 의존성 배열에 추가하거나(그러면 count가 바뀔 때마다 이전 타이머를 정리하고 새로 등록), 함수형 업데이트(`setCount(c => c + 1)`)처럼 이전 값에 의존하지 않는 형태로 작성합니다.

<Callout type="warning">
  **자주 틀리는 점:** "이펙트 안에서 쓰는 state나 props는 전부 의존성 배열에 넣어야 한다"가 원칙입니다. React의 ESLint 플러그인(`eslint-plugin-react-hooks`)이 누락된 의존성을 자동으로 경고해 줍니다. 경고를 임의로 무시하면 이런 stale closure 버그가 생기기 쉽습니다.
</Callout>

## 클린업 함수 — 이펙트 뒤처리

`useEffect`가 타이머나 이벤트 리스너를 등록하면, 컴포넌트가 사라질 때 **정리**(cleanup) 가 필요합니다. 정리하지 않으면 메모리 누수나 오류가 발생합니다.

클린업 함수는 두 가지 경우에 실행됩니다.
1. 컴포넌트가 화면에서 사라질 때 (언마운트)
2. 의존성이 바뀌어 이펙트가 다시 실행되기 직전

## 데이터 패칭 패턴

가장 흔한 useEffect 사용 패턴입니다.

```jsx
function PostList() {
  const [posts, setPosts] = useState([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState(null)

  useEffect(() => {
    async function fetchPosts() {
      try {
        setLoading(true)
        const res = await fetch('https://jsonplaceholder.typicode.com/posts?_limit=5')
        const data = await res.json()
        setPosts(data)
      } catch (err) {
        setError('데이터를 불러오지 못했습니다.')
      } finally {
        setLoading(false)
      }
    }

    fetchPosts()
  }, [])

  if (loading) return <p>로딩 중...</p>
  if (error) return <p>{error}</p>

  return (
    <ul>
      {posts.map(post => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}
```

<Callout type="warning">
  `useEffect` 콜백 자체에 `async`를 붙이지 마세요. `async` 함수는 Promise를 반환하는데, useEffect의 반환값은 클린업 함수여야 합니다. 내부에 별도 async 함수를 만들어 호출하세요.
</Callout>

## 핵심 정리

- **사이드 이펙트**: 화면 그리기 외의 작업 (fetch, 타이머, 이벤트 리스너 등). `useEffect`로 처리.
- 의존성 배열 없음 → 매 렌더링, `[]` → 마운트 시 1회, `[a]` → a 변경 시마다.
- **클린업**: 이펙트가 등록한 타이머·리스너를 `return () => {정리코드}`로 정리한다.
- 데이터 패칭은 내부 async 함수를 선언해서 호출하는 패턴을 사용한다.
- useEffect 콜백은 화면에 paint가 끝난 뒤 비동기로 실행된다(즉시 동기 실행이 필요하면 useLayoutEffect).
- 이펙트 안의 state·props는 등록 시점 값에 고정된다(클로저). 쓰는 값은 반드시 의존성 배열에 넣는다.
