## Canvas 요소와 2D 렌더링 컨텍스트

지금까지 배운 HTML 요소는 전부 **선언적**이었다. `<h1>제목</h1>`이라 쓰면 그게 곧 결과였다.

`<canvas>`는 다르다.

```html
<canvas width="300" height="150"></canvas>
```

이렇게만 써두면 **텅 빈 사각형**이 나온다. `<canvas>`는 그림 그릴 **도화지**만 마련해줄 뿐, 무엇을 그릴지는
전부 JavaScript로 지시해야 한다. HTML 시리즈에서 유일하게 "코드로 그리는" 요소다.

## 왜 img나 SVG로는 안 되나

이미지를 화면에 띄우는 방법은 이미 여러 개 배웠다. `<img>`, 인라인 `<svg>` 모두 가능하다.
그런데 왜 Canvas가 따로 필요한가?

| 방식 | 특징 | 적합한 경우 |
| --- | --- | --- |
| `<img>` | 완성된 파일을 그대로 표시 | 정적 이미지 |
| `<svg>` | 도형을 **객체**로 유지, DOM 요소처럼 다룰 수 있음 | 아이콘, 다이어그램, 확대해도 안 깨지는 그래픽 |
| **`<canvas>`** | 픽셀을 **직접** 찍어 그림, 그린 뒤엔 도형 정보가 남지 않음 | 게임, 실시간 데이터 시각화, 이미지 처리 |

<Callout type="important">
**핵심 차이: SVG는 기억하고, Canvas는 잊는다.**

SVG로 원을 그리면 `<circle>`이라는 요소가 DOM에 남는다. 나중에 `circle.setAttribute('r', 50)`처럼
그 도형을 다시 찾아 수정할 수 있다.

Canvas에 원을 그리면 그 순간 **픽셀 값만 도화지에 찍히고 끝**이다. "방금 그린 원"이라는 개념 자체가 남지 않는다.
움직이려면 지우고 처음부터 다시 그려야 한다. 이 차이가 이번 파트 전체를 관통하는 전제다.
</Callout>

그래서 Canvas는 **초당 수십 번씩 다시 그려야 하는 것**(게임, 애니메이션, 실시간 차트)에 강하고,
SVG는 **개별 요소를 계속 유지하고 조작해야 하는 것**(아이콘, 로고, 인터랙티브 다이어그램)에 강하다.

## canvas 요소 자체는 그냥 상자다

```html
<canvas id="stage" width="300" height="150"></canvas>
```

여기서 주의할 속성이 하나 있다.

<Callout type="warning">
**`width`/`height`는 CSS로 주면 안 된다 (적어도 그것만으로는 안 된다)**

```css
/* 이렇게 하면 그림이 흐릿해진다 */
canvas { width: 300px; height: 150px; }
```

CSS로 크기를 주면 **캔버스 내부 좌표계는 기본값(300×150)인 채로 화면에서만 늘어난다.** 저해상도 이미지를 확대한 것과 같은 원리로 흐려진다.

**HTML 속성** `width`/`height`는 캔버스의 **실제 그리기 해상도**(좌표계 크기)를 정한다. CSS 크기와 반드시 일치시켜야 선명하다. 고해상도(레티나) 디스플레이 대응은 별도 편에서 다룬다.
</Callout>

`width`/`height`를 아예 생략하면 기본값 300×150이 적용된다. 값을 주지 않고 있다가 나중에 그림이 이상하게 나오면 이 점부터 의심하자.

## 렌더링 컨텍스트 — 진짜 시작점

`<canvas>` 요소를 손에 넣었다고 바로 그림을 그릴 수 있는 게 아니다.
**"어떤 방식으로 그릴지"를 먼저 요청**해야 한다. 이 방식을 **렌더링 컨텍스트**<sup>Rendering Context</sup>라 한다.

```js
const canvas = document.querySelector('#stage')
const ctx = canvas.getContext('2d')
```

`getContext()`가 이 시리즈에서 가장 중요한 한 줄이다. **실제로 그림을 그리는 모든 메서드(`fillRect`, `drawImage`, `fillText` …)는 `canvas`가 아니라 이 `ctx` 객체에 들어있다.**

```mermaid
flowchart LR
  A["canvas 요소<br/>(빈 도화지)"] -->|getContext('2d')| B["ctx 객체<br/>(그리기 도구 모음)"]
  B --> C["fillRect(), drawImage(),<br/>fillText() 등"]
```

<Callout type="info">
`getContext('2d')`가 실패하면(아주 오래된 환경 등) `null`을 반환한다. 실무 코드에서는 존재를 확인하고 쓴다.

```js
const ctx = canvas.getContext('2d')
if (!ctx) {
  console.error('이 브라우저는 Canvas 2D를 지원하지 않습니다.')
}
```
</Callout>

### 컨텍스트는 하나만 고를 수 있다

같은 캔버스에 `getContext('2d')`와 `getContext('webgl')`을 둘 다 쓸 수는 없다.
**한 캔버스는 하나의 컨텍스트 타입에 묶인다.**

| 컨텍스트 값 | 용도 |
| --- | --- |
| `'2d'` | 2D 도형·텍스트·이미지 — 이 파트에서 다루는 것 |
| `'webgl'` / `'webgl2'` | 3D 그래픽, GPU 가속 |
| `'bitmaprenderer'` | 다른 곳에서 만든 비트맵을 표시만 함 |

3D는 5편(WebGL 소개)에서 개념만 짚는다.

### 컨텍스트 옵션 — 지금은 이런 게 있다는 것만

`getContext()`의 두 번째 인자로 성능 관련 옵션을 줄 수 있다.

```js
const ctx = canvas.getContext('2d', {
  alpha: false,              // 배경이 항상 불투명하면 true → false로 최적화
  willReadFrequently: false, // getImageData()를 자주 호출할 예정이면 true
})
```

- `alpha: false` — 이 캔버스에 투명 영역이 없다고 브라우저에 알려주면 합성 연산을 줄여준다
- `willReadFrequently` — 나중에(고급 단계에서) 픽셀을 자주 읽어야 할 때 소프트웨어 렌더링으로 전환해 유리해지는 옵션

<Callout type="info">
지금은 외울 필요 없다. 기본값 그대로 써도 충분하고, 성능이 실제로 문제될 때 다시 찾아보면 된다.
</Callout>

## 첫 그림 그려보기

지금까지 배운 것만으로 사각형 하나를 그릴 수 있다.

```html
<canvas id="stage" width="300" height="150"></canvas>
```

```js
const canvas = document.querySelector('#stage')
const ctx = canvas.getContext('2d')

ctx.fillStyle = 'crimson'      // 채울 색을 정하고
ctx.fillRect(20, 20, 100, 60)  // (x, y, 너비, 높이) 위치에 채운 사각형을 그린다
```

<Steps>

### 캔버스를 찾는다

`document.querySelector`로 `<canvas>` 요소를 가져온다. 지금까지 DOM 요소를 찾던 것과 동일하다.

### 컨텍스트를 요청한다

`getContext('2d')`로 "2D 그리기 도구 세트"를 받는다.

### 스타일을 정한다

`ctx.fillStyle`에 색을 지정한다. 이후의 채우기 그리기 명령에 계속 적용된다.

### 그린다

`ctx.fillRect(x, y, 너비, 높이)`를 호출하는 순간 픽셀이 찍힌다.

</Steps>

<Callout type="important">
**좌표계는 왼쪽 위가 원점(0, 0)이다.** 아래로 갈수록 y가 커지고, 오른쪽으로 갈수록 x가 커진다.
수학 시간에 배운 좌표평면과 y축 방향이 반대라는 점을 꼭 기억하자. 다음 편(도형과 경로)에서 좌표계를 더 자세히 다룬다.
</Callout>

## 흔한 실수 — 스크립트 실행 순서

```html
<canvas id="stage"></canvas>
<script>
  const ctx = document.querySelector('#stage').getContext('2d')
  // ...
</script>
```

`<script>`가 `<canvas>`**보다 먼저** 나오면 아직 만들어지지 않은 요소를 찾으려다 `null`을 받는다.

```html
<script>
  const ctx = document.querySelector('#stage').getContext('2d')
  // TypeError: Cannot read properties of null
</script>
<canvas id="stage"></canvas>
```

<Callout type="warning">
캔버스보다 스크립트가 먼저 오거나, `<script defer>`/모듈(`type="module"`)을 안 쓴 상태로 `<head>`에 스크립트를 두면 이 에러를 만난다. ECMAScript 시리즈에서 다룬 스크립트 로딩 시점(`defer`) 지식이 여기서 그대로 쓰인다.
</Callout>

## 정리

<Callout type="default">
- `<canvas>`는 도화지일 뿐이다. **그림은 전부 JavaScript로 지시**한다
- SVG는 도형을 요소로 **기억**하고, Canvas는 픽셀만 찍고 **잊는다**
- 크기는 **HTML 속성**(`width`/`height`)으로 준다. CSS로만 주면 흐려진다
- 실제 그리기 메서드는 `canvas`가 아니라 `getContext('2d')`로 받은 **컨텍스트 객체**에 있다
- 좌표계 원점은 **왼쪽 위 (0, 0)** 이다
</Callout>

다음 편에서는 사각형을 넘어 선·경로·색·그라디언트로 다양한 도형을 그린다.
