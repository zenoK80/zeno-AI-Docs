## 01편 복습

## 문제 1

`<canvas>` 태그만 HTML에 써두면 화면에 무엇이 나타나나?

- A. 회색 격자무늬
- B. 아무것도 없는 빈 사각형(투명한 도화지)
- C. "여기에 그림을 그리세요"라는 안내 문구
- D. 브라우저마다 기본 그림이 다르게 나타난다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
`<canvas>`는 그림을 그릴 수 있는 빈 도화지만 마련해줄 뿐, 무엇을 그릴지는 전부 JavaScript로 지시해야 한다. HTML 요소 중 유일하게 "코드로 그리는" 요소라는 점이 이 편의 핵심이었다.
</Collapse>

## 문제 2

캔버스 크기를 CSS(`width`, `height` 속성이 아니라 CSS 스타일)로만 지정하면 안 되는 이유는?

- A. CSS로는 아예 크기 지정이 안 된다
- B. CSS로 크기를 주면 내부 좌표계(실제 해상도)는 그대로인 채 화면에서만 늘어나서 그림이 흐릿해진다
- C. CSS로 지정하면 캔버스가 사라진다
- D. 속도가 느려질 뿐 화질에는 문제가 없다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
캔버스에는 **두 가지 크기**가 있다 — HTML `width`/`height` 속성이 정하는 "실제 그리기 해상도(좌표계)"와, CSS가 정하는 "화면에 보이는 크기"다. CSS로만 크기를 키우면, 원래 해상도의 그림을 억지로 확대하는 셈이 되어 저해상도 이미지를 확대한 것처럼 흐려진다. 그래서 실제 해상도는 HTML 속성으로 지정해야 한다.
</Collapse>

## 문제 3

실제로 도형을 그리는 메서드(`fillRect` 등)는 어디에 있나?

- A. `canvas` 요소 자신에게 있다
- B. `canvas.getContext('2d')`로 받은 컨텍스트 객체(`ctx`)에 있다
- C. `document` 객체에 있다
- D. 별도로 설치해야 하는 라이브러리에 있다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
`<canvas>` 요소 자체는 그림을 그릴 "도화지"일 뿐이고, 실제로 선을 긋고 색을 칠하는 도구들(`fillRect`, `arc`, `fillText` 등)은 `getContext('2d')`로 요청해서 받은 **렌더링 컨텍스트**<sup>Rendering Context, "어떤 방식으로 그릴지"를 정하는 도구 모음</sup> 객체 안에 들어있다. 이 컨텍스트를 받는 한 줄이 캔버스 작업의 진짜 시작점이다.
</Collapse>

## 실습 — 사각형 두 개 나란히 그리기

아래 뼈대를 완성해서, 빨간 채워진 사각형과 파란 테두리 사각형을 나란히 그려보자.

```html
<canvas id="stage" width="300" height="150"></canvas>
```

```js
const canvas = document.querySelector('#stage')
const ctx = canvas.getContext('2d')

// 여기에 코드를 채워보자
// 1. fillStyle을 'crimson'으로, (20, 20) 위치에 80x60 채워진 사각형
// 2. strokeStyle을 'navy'로, (120, 20) 위치에 80x60 테두리 사각형
```

<Collapse title="정답 보기">

```js
ctx.fillStyle = 'crimson'
ctx.fillRect(20, 20, 80, 60)

ctx.strokeStyle = 'navy'
ctx.strokeRect(120, 20, 80, 60)
```

</Collapse>
