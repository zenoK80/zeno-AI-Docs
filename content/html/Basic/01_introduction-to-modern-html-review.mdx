## 01편 복습

본문을 다시 열기 전에 HTML이 무엇을 표현하는 언어인지 먼저 떠올려 보자.

## 핵심 퀴즈

**Q1. HTML이 프로그래밍 언어가 아니라 마크업 언어인 이유는 무엇인가?**

<Collapse title="정답 보기">
HTML은 계산이나 조건 판단을 수행하는 대신 콘텐츠의 구조와 의미를 표시하기 때문이다.
</Collapse>

**Q2. 제목처럼 크게 보이는 `<p>`와 `<h1>`은 기계에게도 같은 의미인가?**

<Collapse title="정답 보기">
아니다. `<h1>`은 최상위 제목이라는 의미를 전달하지만, 스타일만 키운 `<p>`는 여전히 일반 문단이다.
</Collapse>

**Q3. HTML6이 나오지 않는 이유는 무엇인가?**

<Collapse title="정답 보기">
현재 HTML은 버전을 끊어 발표하지 않고 WHATWG의 HTML Living Standard로 계속 갱신되기 때문이다.
</Collapse>

**Q4. `<div onclick="...">`보다 `<button>`을 우선해야 하는 이유를 두 가지 말해 보자.**

<Collapse title="정답 보기">
`button`은 기본적으로 키보드 포커스와 활성화 동작을 제공하고, 보조 기술에 버튼이라는 의미를 전달한다.
</Collapse>

## 실습 — 의미만 보고 태그 고르기

다음 구조를 `div`만 사용하지 말고 의미에 맞는 요소로 작성해 보자.

```text
사이트 제목
주요 메뉴
독립적으로 배포 가능한 뉴스 글
글 작성자와 게시일
```

<Collapse title="예시 답안 보기">

```html
<header>
  <h1>오늘의 뉴스</h1>
  <nav aria-label="주요 메뉴">...</nav>
</header>
<main>
  <article>
    <h2>새 소식</h2>
    <p>기사 본문...</p>
    <footer>작성자 김제노 · 2026-08-08</footer>
  </article>
</main>
```

태그 이름보다 각 영역의 실제 역할이 선택 기준이다.
</Collapse>
