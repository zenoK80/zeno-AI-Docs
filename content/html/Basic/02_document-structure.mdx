## 가장 작은 HTML 문서

앞 장에서 브라우저가 HTML을 읽어 DOM 트리로 만든다고 했습니다. 그렇다면 그 트리의 **뿌리와 큰 가지**는 어떤 모습일까요? 유효한 HTML 문서는 아래 네 가지 조각으로 이루어진 골격을 갖습니다.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>내 첫 페이지</title>
  </head>
  <body>
    <h1>안녕하세요</h1>
  </body>
</html>
```

이 짧은 코드 안에 문서 구조의 핵심이 모두 들어 있습니다. 하나씩 뜯어보겠습니다.

<Callout type="info">
  이 골격을 트리로 보면 이렇습니다. `<html>`이 최상위 뿌리이고, 그 밑에 `<head>`와 `<body>` 두 개의 큰 가지가 있으며, 실제 콘텐츠 요소들은 그 가지에 매달립니다. 개발자 도구 Elements 탭에서 본 그 구조가 바로 이것입니다.
</Callout>

## `<!DOCTYPE html>` — 문서 타입 선언

문서의 **맨 첫 줄**에 오는 선언입니다. 언뜻 HTML 태그처럼 보이지만 태그가 아니라, "이 문서는 표준 HTML로 해석해 달라"고 브라우저에 알리는 신호입니다.

```html
<!DOCTYPE html>
```

이 짧은 형태는 HTML Living Standard의 공식 표기이며, 과거 HTML4나 XHTML에서 쓰던 길고 복잡한 DOCTYPE은 더 이상 필요 없습니다. 대소문자는 구분하지 않으므로 `<!doctype html>`도 동일하게 동작합니다.

<Callout type="warning">
  DOCTYPE을 빠뜨리면 브라우저가 **쿼크 모드(Quirks Mode)**로 전환됩니다. 이는 90년대 옛 브라우저와의 호환을 위한 특수 모드로, CSS 박스 모델 등 여러 동작이 표준과 다르게 작동해 레이아웃이 예기치 않게 깨질 수 있습니다. `<!DOCTYPE html>` 한 줄이 브라우저를 **표준 모드(Standards Mode)**로 유지해 줍니다.
</Callout>

## `<html>` — 루트 요소

DOCTYPE 다음에 오는 `<html>`은 문서 전체를 감싸는 **최상위(루트) 요소**입니다. 모든 다른 요소는 이 안에 들어갑니다. 자식은 정확히 `<head>`와 `<body>` 두 개입니다.

### `lang` 속성은 꼭 붙이세요

`<html>`에는 문서의 주 언어를 나타내는 `lang` 속성을 지정하는 것이 좋습니다.

```html
<html lang="ko">
```

`lang` 속성은 생김새를 바꾸지 않지만 다음과 같은 실질적 효과가 있습니다.

- **스크린 리더**가 올바른 발음/억양으로 내용을 읽어 줍니다. (접근성)
- **검색 엔진**이 문서 언어를 파악해 적절한 사용자에게 노출합니다. (SEO)
- 브라우저의 **번역·맞춤법 검사** 기능이 더 정확하게 동작합니다.

한국어 문서라면 `lang="ko"`, 영어 문서라면 `lang="en"`을 사용합니다.

## `<head>` — 눈에 보이지 않는 정보

`<head>`는 문서에 **대한** 정보, 즉 메타데이터를 담는 영역입니다. 여기 담긴 내용은 대부분 페이지 화면에 직접 표시되지 않지만, 브라우저·검색엔진·소셜 미디어가 문서를 올바르게 다루는 데 꼭 필요합니다.

최소 골격에서 `<head>`에 들어간 두 요소만 짚고 넘어가겠습니다. (자세한 메타데이터는 다음 장에서 다룹니다.)

- `<meta charset="UTF-8" />` — 문서의 **문자 인코딩**을 지정합니다. UTF-8은 한글을 포함한 전 세계 문자를 표현할 수 있어 사실상 표준입니다. 이게 없거나 틀리면 한글이 `�` 같은 깨진 글자로 보일 수 있습니다.
- `<title>...</title>` — 브라우저 **탭·창 제목**, 북마크 이름, 검색 결과 제목으로 쓰입니다. 모든 문서가 반드시 가져야 하는 요소입니다.

<Callout type="tip">
  `<meta charset>`은 가급적 `<head>`의 **맨 처음**에 두세요. 명세는 문자 인코딩 선언이 문서의 **첫 1024바이트 안**에 있어야 한다고 규정합니다. 브라우저가 나머지 내용을 어떤 인코딩으로 읽을지 가장 먼저 알아야 하기 때문입니다.
</Callout>

## `<body>` — 실제 콘텐츠

`<body>`에는 사용자가 화면에서 실제로 보고 상호작용하는 모든 것 — 제목, 문단, 이미지, 링크, 버튼, 폼 등 — 이 들어갑니다. 우리가 이 커리큘럼에서 다룰 대부분의 태그는 이 `<body>` 안에 자리 잡습니다.

```html
<body>
  <h1>안녕하세요</h1>
  <p>이 문단은 화면에 보입니다.</p>
</body>
```

## 실전 보일러플레이트

이제 실무에서 새 페이지를 시작할 때 쓰는, 조금 더 현실적인 기본 틀을 보겠습니다. 앞의 최소 골격에 **뷰포트 설정**과 **스타일시트·스크립트 연결**을 더한 형태입니다.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>페이지 제목</title>
    <link rel="stylesheet" href="styles.css" />
  </head>
  <body>
    <!-- 여기에 콘텐츠가 들어갑니다 -->

    <script src="main.js"></script>
  </body>
</html>
```

이 틀의 각 줄이 하는 일을 정리하면 다음과 같습니다.

<Steps>

### 문서 타입과 언어 선언

`<!DOCTYPE html>`로 표준 모드를 켜고, `<html lang="ko">`로 문서 언어를 알립니다.

### 문자 인코딩과 뷰포트 설정

`charset`으로 UTF-8을 지정하고, `viewport` 메타로 모바일 화면에서 적절한 크기로 렌더링되도록 합니다. (뷰포트는 다음 장에서 자세히 다룹니다.)

### 제목과 스타일 연결

`<title>`로 문서 제목을 정하고, `<link>`로 외부 CSS를 연결합니다.

### 콘텐츠와 스크립트 배치

`<body>` 안에 실제 콘텐츠를 넣고, `<script>`는 보통 `</body>` 직전에 두어 콘텐츠가 먼저 그려지도록 합니다.

</Steps>

<Callout type="tip">
  VS Code에서 `.html` 파일을 만든 뒤 빈 파일 첫 줄에 느낌표(`!`)를 입력하고 `Enter`(또는 `Tab`)를 누르면 이 보일러플레이트가 자동으로 생성됩니다. Emmet이라는 기능이 만들어 주는 것으로, 매번 손으로 타이핑할 필요가 없습니다.
</Callout>

## 흔한 오해 바로잡기

모던 HTML을 배울 때 옛 자료에서 넘어온 습관 몇 가지를 정리하고 갑니다.

- **`<meta http-equiv="X-UA-Compatible" content="IE=edge">`는 이제 필요 없습니다.** 이건 옛 인터넷 익스플로러 전용 설정으로, 지원이 끝난 지금은 넣지 않는 것이 맞습니다.
- **빈 요소의 슬래시(`<meta ... />`)는 필수가 아닙니다.** 일반 HTML 직렬화에서는 `<meta charset="UTF-8">`처럼 슬래시 없이 써도 완전히 유효합니다. 슬래시를 붙이든 말든 취향의 문제이며, 다만 한 프로젝트 안에서는 스타일을 일관되게 유지하는 것이 좋습니다.
- **`<head>`와 `<body>` 태그 자체는 문법상 생략 가능하지만**, 명시적으로 적어 주는 것이 가독성과 실수 방지에 훨씬 낫습니다. 이 커리큘럼에서는 항상 명시합니다.

## 정리

- 모든 HTML 문서는 `<!DOCTYPE html>` → `<html>` → (`<head>`, `<body>`)의 골격을 갖는다.
- **DOCTYPE**은 브라우저를 표준 모드로 유지하는 첫 줄 신호다.
- **`<html lang>`**은 접근성·SEO·번역을 위해 문서 언어를 알린다.
- **`<head>`**는 보이지 않는 메타데이터(문자 인코딩, 제목 등), **`<body>`**는 보이는 콘텐츠를 담는다.
- 실무에서는 뷰포트·스타일·스크립트를 더한 보일러플레이트로 시작하며, VS Code의 `!` 단축키로 빠르게 생성할 수 있다.

다음 장에서는 `<head>` 안을 본격적으로 파고들어, `charset`·`viewport`를 비롯한 각종 `<meta>` 태그와 `<link>`·`<base>` 등 문서 메타데이터를 자세히 다룹니다.
