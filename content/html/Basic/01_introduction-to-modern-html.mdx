## 모던 HTML 시작하기

"HTML은 쉽다"는 말을 자주 듣는다. 절반만 맞다.

태그를 외워 화면에 글자를 띄우는 건 하루면 된다.
하지만 **어떤 태그를 왜 골라야 하는지**는 그렇지 않다. 그게 이 시리즈의 주제다.

## HTML은 프로그래밍 언어가 아니다

**HTML**<sup>HyperText Markup Language</sup>은 **마크업 언어**다.
계산도 판단도 반복도 하지 않는다. 오직 **"이 내용이 무엇인지 표시"** 할 뿐이다.

```html
<h1>오늘의 뉴스</h1>
<p>비가 온다.</p>
```

여기서 `<h1>`은 "글자를 크게 하라"는 명령이 아니다.
**"이건 제목이다"** 라는 의미 표시다. 크게 보이는 건 브라우저가 그렇게 그리기로 한 결과일 뿐이다.

<Callout type="important">
**의미와 모양은 다르다.**

제목처럼 보이게 하고 싶다고 `<p>`에 큰 글씨를 주면, 화면상으로는 같아 보여도 **기계에게는 그냥 문단**이다.

```html
<p style="font-size: 32px; font-weight: bold;">오늘의 뉴스</p>  <!-- 나쁨 -->
<h1>오늘의 뉴스</h1>                                              <!-- 좋음 -->
```

이 차이가 만드는 결과가 뒤에 나온다.
</Callout>

## 태그의 생김새

```
<a href="https://example.com">링크</a>
 ↑   ↑         ↑                ↑    ↑
시작 속성명    속성값           내용  종료 태그
```

- **요소**<sup>Element</sup> — 시작 태그부터 종료 태그까지 전체
- **속성**<sup>Attribute</sup> — 요소에 주는 추가 정보. 시작 태그 안에만 쓴다

내용이 없어 종료 태그가 없는 것들도 있다. **빈 요소**<sup>Void Element</sup>라 부른다.

```html
<img src="cat.png" alt="고양이">
<br>
<input type="text">
```

<Callout type="info">
`<br />`처럼 슬래시를 붙인 걸 본 적 있을 것이다. XHTML 시절의 흔적이고, 지금 HTML에서는 **있어도 없어도 똑같이 동작한다.** 팀에서 쓰는 스타일을 따르면 된다.
</Callout>

## "HTML5 다음 버전"은 없다

HTML을 검색하면 "HTML5"라는 말이 계속 나온다. 그럼 HTML6은 언제 나오나?

**나오지 않는다.** 버전 개념이 사라졌기 때문이다.

### 어쩌다 이렇게 됐나

<Steps>

### 1990년대 — 브라우저 전쟁

넷스케이프와 인터넷 익스플로러가 서로 다른 태그를 마음대로 만들었다. 같은 페이지가 브라우저마다 다르게 보였다.

### 2000년대 초 — XHTML의 실패

W3C는 문법을 엄격하게 조이는 XHTML을 밀었다. 문법 오류 하나면 페이지 전체가 안 뜨는 방식이었고, 현실의 웹과 맞지 않아 외면당했다.

### 2004년 — WHATWG의 등장

브라우저 제조사들이 모여 WHATWG를 만들고, 현실적인 방향의 명세를 따로 쓰기 시작했다.

### 2019년 — 정리

W3C가 WHATWG의 명세를 공식 표준으로 인정했다. 이제 HTML 표준은 하나다.

</Steps>

### 지금의 HTML — Living Standard

현재 HTML 표준의 이름은 **HTML Living Standard**다. "살아있는 표준"이라는 뜻 그대로,
버전을 끊지 않고 **필요할 때마다 계속 갱신된다.**

<Callout type="info">
그래서 이 시리즈는 "HTML5를 배운다"고 하지 않고 **"모던 HTML을 배운다"** 고 한다.
`dialog`, `popover` 같은 최신 요소도 "HTML5에 없던 것"이 아니라 **그냥 HTML의 일부**다.
</Callout>

## 시맨틱 — 이 시리즈를 관통하는 원칙

**시맨틱**<sup>Semantic, 의미론적</sup> HTML이란 **내용의 의미에 맞는 태그를 쓰는 것**이다.

```html
<!-- 의미 없음 -->
<div class="header">
  <div class="nav">...</div>
</div>

<!-- 시맨틱 -->
<header>
  <nav>...</nav>
</header>
```

둘은 화면에서 똑같이 보인다. 그런데 왜 아래가 나은가?

| 이유 | 설명 |
| --- | --- |
| **접근성** | 스크린 리더가 "탐색 영역"이라고 안내한다. `div`는 아무 정보도 못 준다 |
| **SEO** | 검색 엔진이 문서 구조를 이해한다 |
| **협업** | `<article>`은 누가 봐도 본문이다. `<div class="art">`는 물어봐야 안다 |
| **기본 기능** | `<button>`은 키보드로 눌리고 포커스도 받는다. `<div>`는 전부 직접 만들어야 한다 |

<Callout type="important">
마지막 항목이 특히 중요하다. `<div onclick="...">`으로 버튼을 만들면 마우스로는 되지만
**Tab 키로 접근할 수 없고, Enter로 눌리지 않고, 스크린 리더가 버튼이라고 알려주지 않는다.**

`<button>`을 쓰면 이 전부가 공짜다. **"직접 만들지 말고 있는 걸 쓴다"** 가 모던 HTML의 첫 번째 원칙이다.
</Callout>

## 브라우저는 HTML을 어떻게 화면으로 바꾸나

전체 흐름을 미리 봐 두면 이후 편들이 잘 이어진다.

<Steps>

### 파싱 — HTML을 읽어 DOM을 만든다

태그를 순서대로 읽어 **DOM 트리**(문서 구조를 나타내는 객체 트리)를 만든다.

### 스타일 계산 — CSS를 붙인다

CSS를 읽어 각 요소의 최종 스타일을 계산한다.

### 레이아웃 — 위치와 크기를 정한다

각 요소가 어디에 얼마만 한 크기로 놓일지 계산한다.

### 페인트 — 픽셀을 칠한다

색, 텍스트, 이미지를 실제로 그린다.

</Steps>

<Callout type="warning">
**HTML은 문법이 틀려도 에러를 내지 않는다**

닫는 태그를 빼먹어도 브라우저는 알아서 고쳐서 렌더링한다. XHTML의 실패에서 배운 관용성이다.

편해 보이지만 함정이다. **브라우저가 짐작한 구조가 내 의도와 다를 수 있다.**
"분명 닫았는데 레이아웃이 이상하다" 싶으면 개발자 도구의 Elements 탭에서 **실제 DOM 구조**를 확인하는 습관을 들이자.
</Callout>

## HTML · CSS · JavaScript의 역할

| 언어 | 담당 | 없으면 |
| --- | --- | --- |
| **HTML** | 구조와 의미 | 아무것도 없다 |
| CSS | 모양과 배치 | 못생겼지만 읽을 수는 있다 |
| JavaScript | 동작 | 정적이지만 볼 수는 있다 |

HTML만 없으면 **아무것도 남지 않는다.** 그래서 HTML이 토대다.

<Callout type="info">
이 순서로 만드는 방식을 **점진적 향상**<sup>Progressive Enhancement</sup>이라 한다.
의미 있는 HTML을 먼저 갖추고, 그 위에 CSS와 JS를 얹는다. 그러면 JS가 실패해도 페이지는 최소한 읽을 수 있다.
</Callout>

## 정리

<Callout type="default">
- HTML은 프로그래밍 언어가 아니라 **의미를 표시하는 마크업 언어**다
- **모양이 아니라 의미로 태그를 고른다**
- "HTML5 다음 버전"은 없다. 지금은 **HTML Living Standard**로 계속 갱신된다
- 시맨틱 태그는 접근성·SEO·협업·기본 기능을 공짜로 준다
- **직접 만들지 말고 있는 요소를 쓴다** — `<div>` 버튼 대신 `<button>`
- HTML은 문법 오류를 관용한다. 그래서 **실제 DOM을 확인하는 습관**이 필요하다
</Callout>
