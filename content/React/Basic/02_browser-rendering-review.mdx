## 02편 복습

## 핵심 퀴즈

**Q1. 브라우저가 화면을 그리는 다섯 단계를 순서대로 말하면?**

<Collapse title="정답 보기">
DOM 생성 → CSSOM 생성 → 렌더 트리 생성 → 레이아웃 → 페인트
</Collapse>

**Q2. "DOM 조작이 느리다"는 말의 정확한 의미는?**

<Collapse title="정답 보기">
DOM 자체를 읽고 쓰는 건 빠르다. 느려지는 건 DOM을 바꾼 뒤 브라우저가 다시 계산해야 하는 레이아웃·페인트 쪽이다.
</Collapse>

**Q3. React의 Virtual DOM과 일괄 반영(batching)이 하는 일은?**

<Collapse title="정답 보기">
"언제, 얼마나 자주 브라우저에 재계산을 요청할지"를 개발자 대신 관리해 준다. 여러 변경을 모아 최소한으로 반영한다.
</Collapse>

## 실습 — Performance 탭으로 리플로우 직접 관찰하기

<Steps>

### 아무 웹페이지에서 개발자 도구를 연다

<kbd>F12</kbd> → **Performance** 탭

### 녹화 버튼을 누른다

빨간 원 버튼을 클릭한다.

### 페이지를 스크롤하거나 버튼을 몇 번 클릭한다

3~5초 정도면 충분하다.

### 녹화를 멈추고 결과를 본다

그래프에서 **노란색(Scripting)**, **보라색(Rendering)**, **초록색(Painting)** 구간의 비율을 확인한다.

</Steps>

어느 색이 가장 큰 비중을 차지했는가? 그 이유를 이 편의 내용으로 설명해 보자.
