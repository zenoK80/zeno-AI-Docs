## JSX 완전 정복

4편에서 JSX가 Babel을 거쳐 `React.createElement` 호출로 변환된다는 걸 봤다.
이번 편은 그 사실을 기억한 채로 JSX의 세부 규칙을 하나씩 짚는다. **"왜 이렇게 써야 하지?"** 싶은 규칙들이
전부 "결국 함수 호출로 변환되기 때문"이라는 한 가지 이유로 설명된다.

## JSX는 HTML이 아니다

생김새는 HTML을 닮았지만, JSX는 **자바스크립트 표현식**이다.

```jsx
const element = <h1>안녕</h1>
```

이 한 줄은 사실 아래와 똑같다. (JSX 없이 4편에서처럼 직접 쓴 것)

```js
const element = React.createElement('h1', null, '안녕')
```

<Callout type="important">
JSX가 표현식이라는 사실이 중요하다. 4편에서 다룬 "표현식은 값이 되는 자리에 쓸 수 있다"는 원칙 그대로,
JSX도 변수에 담거나, 함수에서 반환하거나, 조건문의 결과로 쓸 수 있다. 이게 13편 조건부 렌더링의 기반이 된다.
</Callout>

## 규칙 1 — 최상위 요소는 하나여야 한다

```jsx
// 에러 — 최상위에 요소가 두 개
function Profile() {
  return (
    <h1>이름</h1>
    <p>소개</p>
  )
}
```

<Callout type="warning">
**왜 안 되는가?** `React.createElement`는 **하나의 객체**만 반환할 수 있다. `<h1>`과 `<p>`를 나란히 반환하는 건
자바스크립트 함수가 `return a, b`처럼 값을 두 개 반환하려는 것과 같아서 애초에 불가능하다.
</Callout>

감싸는 태그가 필요하다.

```jsx
function Profile() {
  return (
    <div>
      <h1>이름</h1>
      <p>소개</p>
    </div>
  )
}
```

굳이 `<div>`를 화면에 남기고 싶지 않다면 **Fragment**를 쓴다.

```jsx
function Profile() {
  return (
    <>
      <h1>이름</h1>
      <p>소개</p>
    </>
  )
}
```

`<>...</>`는 **아무 DOM 요소도 만들지 않으면서** 여러 요소를 하나로 묶어주는 특수 문법이다.

## 규칙 2 — 태그는 반드시 닫는다

```jsx
<img src="cat.png">        // 에러
<img src="cat.png" />      // OK — 셀프 클로징 필수
```

HTML에서는 `<img>`처럼 안 닫아도 브라우저가 관대하게 처리해줬다(2편에서 본 HTML의 관용성).
JSX는 자바스크립트 문법의 일부로 파싱되기 때문에 **이 관용성이 없다.** 내용이 없는 태그는 반드시 `/>`로 닫는다.

## 규칙 3 — 속성은 camelCase, 일부는 이름이 다르다

```jsx
<div class="box" onclick="handleClick()">   // HTML 방식 — 동작 안 함
<div className="box" onClick={handleClick}>  // JSX 방식
```

<Callout type="important">
**왜 `class`가 아니라 `className`인가?** `class`는 자바스크립트에서 **클래스를 선언하는 예약어**다(18편에서 다룸).
JSX는 결국 자바스크립트 코드로 변환되므로, 예약어와 충돌하는 이름은 쓸 수 없다. 그래서 DOM의 `className` 프로퍼티 이름을 그대로 가져다 썼다.

같은 이유로 `for`(반복문 예약어)도 `htmlFor`로 바뀐다.
</Callout>

여러 단어로 된 속성은 대부분 **camelCase**를 쓴다.

```jsx
<div tabIndex={0} onMouseEnter={handleEnter} />
```

## 규칙 4 — 중괄호로 자바스크립트 값을 끼워 넣는다

JSX 안에서 순수한 텍스트가 아니라 **변수나 계산된 값**을 넣고 싶으면 `{ }`로 감싼다.

```jsx
const name = '지민'
const element = <h1>안녕, {name}</h1>
```

<Callout type="info">
`{ }` 안에는 **표현식만** 들어갈 수 있다. 4편에서 구분한 "표현식 vs 문"이 여기서 그대로 적용된다.

```jsx
<div>{1 + 1}</div>            // OK — 표현식
<div>{if (true) { 1 }}</div>  // 에러 — if문은 표현식이 아니다
<div>{true ? '참' : '거짓'}</div>  // OK — 삼항 연산자는 표현식이다
```

조건에 따라 다른 내용을 보여주고 싶을 때 `if` 대신 삼항 연산자나 `&&`를 쓰는 이유가 바로 이거다. 13편에서 패턴을 자세히 다룬다.
</Callout>

속성 값에도 똑같이 쓸 수 있다.

```jsx
const imageUrl = 'cat.png'
const element = <img src={imageUrl} alt="고양이" />
```

<Callout type="warning">
**따옴표와 중괄호를 혼동하지 않는다.**

```jsx
<img src="imageUrl" />   // 문자열 'imageUrl' 그 자체 — 변수가 아니다
<img src={imageUrl} />   // 변수 imageUrl의 값
```

`"..."`는 순수 문자열이고, `{...}`는 자바스크립트 표현식을 평가한 값이다.
</Callout>

## 규칙 5 — 인라인 스타일은 객체로 준다

```jsx
<div style="color: red; font-size: 20px;">   // 에러 — 문자열이 아니다
<div style={{ color: 'red', fontSize: 20 }}>  // OK
```

바깥 `{ }`는 "자바스크립트 값을 넣겠다"는 표시고, 안쪽 `{ }`는 **그 값이 객체**라는 뜻이다.
CSS 속성 이름도 `font-size` → `fontSize`처럼 camelCase로 바뀌고, 숫자는 기본적으로 `px`로 취급된다.

<Callout type="info">
인라인 스타일은 이 시리즈 뒷부분(52편)에서 다루는 여러 스타일링 방법 중 하나일 뿐이다. 지금은 문법만 봐 둔다.
</Callout>

## Babel이 실제로 만드는 코드 — React 19 기준

4편에서 JSX가 `React.createElement`로 변환된다고 간단히 말했는데, 정확히는 React 17부터 **새로운 변환 방식**이 기본이 됐다.

```jsx
// 우리가 쓰는 JSX
const element = <h1 className="title">안녕</h1>
```

```js
// React 17 이전 방식
React.createElement('h1', { className: 'title' }, '안녕')

// React 17+ 새 변환 방식 (지금 기본값)
import { jsx as _jsx } from 'react/jsx-runtime'
_jsx('h1', { className: 'title', children: '안녕' })
```

<Callout type="info">
결과적으로 하는 일은 같다 — **"이런 요소를 만들어 달라"** 는 객체를 반환하는 함수를 호출하는 것.
새 방식은 파일마다 `import React from 'react'`를 안 써도 되게 최적화한 것뿐이다. 지금 프로젝트를 세팅하면(9편) 자동으로 이 새 방식이 적용된다.
</Callout>

## 정리

<Callout type="default">
- JSX는 HTML이 아니라 **`React.createElement` 호출로 변환되는 자바스크립트 표현식**이다
- 최상위 요소는 하나여야 한다 — 여러 개를 반환하려면 `<>...</>`(Fragment)로 감싼다
- 태그는 반드시 닫는다 (`<img />`)
- `class` → `className`, `for` → `htmlFor` — 자바스크립트 예약어를 피하려고 이름이 바뀌었다
- `{ }`로 자바스크립트 값을 끼워 넣는다. 안에는 **표현식만** 올 수 있다
- 인라인 스타일은 `style={{ ... }}` — 객체로 전달한다
</Callout>

다음 편에서는 React가 이렇게 만들어진 요소들을 실제 DOM에 어떻게, 그리고 얼마나 효율적으로 반영하는지 — **Virtual DOM의 원리**를 본다.
