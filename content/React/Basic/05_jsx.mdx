## JSX는 HTML이 아니다

JSX는 HTML처럼 생겼지만 HTML이 아니다. 브라우저는 JSX를 전혀 이해하지 못한다. JSX는 **JavaScript 문법 확장**일 뿐이고, 4번 챕터에서 봤듯 **Babel이 평범한 JS로 바꿔준다.**

그 "평범한 JS"의 정체를 알면 React가 훨씬 덜 신비로워진다. 이 챕터의 목표는 하나다 — JSX 한 줄이 최종적으로 **무엇이 되는지** 끝까지 따라가 보는 것.

## Babel이 실제로 만드는 것

이 JSX 한 줄이:

```jsx
const element = <h1 className="title">Hello</h1>;
```

Babel을 거치면 이렇게 바뀐다:

```js
const element = React.createElement(
  "h1",
  { className: "title" },
  "Hello"
);
```

즉 **JSX 태그 하나 = `React.createElement` 호출 하나**다. 태그가 중첩되면 호출도 중첩된다.

<Tabs items={['JSX', '변환 결과']}>
  <Tabs.Tab>
    ```jsx
    const box = (
      <div className="box">
        <h1>제목</h1>
        <p>본문</p>
      </div>
    );
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```js
    const box = React.createElement(
      "div",
      { className: "box" },
      React.createElement("h1", null, "제목"),
      React.createElement("p", null, "본문")
    );
    ```
  </Tabs.Tab>
</Tabs>

## createElement의 정체

`createElement`의 형태는 이렇다.

```js
React.createElement(type, props, ...children);
```

- **type** — 태그 이름 문자열(`"h1"`) 또는 컴포넌트 함수(`App`)
- **props** — 속성 객체(`{ className: "title" }`). 없으면 `null`
- **children** — 자식들. 세 번째 인자부터 쭉 나열된다

그리고 이 함수가 반환하는 건, 놀랍게도 **그냥 JavaScript 객체**다.

## React 엘리먼트 — 결국 객체 하나

위 `element`를 콘솔에 찍으면 대략 이런 객체가 나온다.

```js
{
  type: "h1",
  props: { className: "title", children: "Hello" },
  key: null,
  ref: null,
  // 내부적으로 $$typeof 같은 필드도 있다 (위조 방지용)
}
```

이 객체를 **React 엘리먼트**라고 부른다. 중요한 사실:

<Callout type="info">
  React 엘리먼트는 **진짜 DOM이 아니다.** "화면이 이렇게 생겨야 한다"를 적어둔 **가벼운 설명서**일 뿐이다. 실제 DOM으로 바꾸는 건 `ReactDOM`의 몫이다.
</Callout>

이게 왜 중요하냐면 — 이 "설명서 객체"를 진짜 DOM보다 훨씬 싸게 만들고 비교할 수 있기 때문이다. 이 아이디어가 다음 챕터의 **Virtual DOM**(6번)으로 그대로 이어진다.

전체 흐름을 정리하면:

<Steps>

### 작성

개발자가 JSX를 쓴다.

### 변환

Babel이 JSX를 `createElement`(또는 뒤에 나올 `_jsx`) 호출로 바꾼다.

### 실행

그 호출이 실행되면 **React 엘리먼트 객체**가 만들어진다.

### 렌더

`ReactDOM`이 그 객체를 읽어 **실제 DOM**으로 그린다.

</Steps>

## 구버전 → 새 문법: JSX 변환의 변화

여기서 옛날 코드와 요즘 코드가 갈린다. **React 17(2020)** 부터 JSX 변환 방식이 바뀌었다.

### 예전 방식 (classic) — React 16 이하

JSX는 `React.createElement`로 변환됐다. 그래서 JSX를 쓰는 **모든 파일** 맨 위에 아래 import가 반드시 있어야 했다. 코드에서 `React`를 직접 안 써도 그랬다.

```jsx
import React from "react"; // 안 쓰는 것 같지만 필수였다

function App() {
  return <h1>Hi</h1>; // → React.createElement(...) 로 변환되므로
}
```

이걸 빠뜨리면 `React is not defined` 에러가 났다.

### 새 방식 (automatic) — React 17 이상

React 17부터 **새 JSX 변환(automatic runtime)** 이 도입됐다. 이제 Babel이 필요한 함수를 `react/jsx-runtime`에서 **자동으로 가져온다.** 그래서 `import React`가 더 이상 필요 없다.

<Tabs items={['❌ 예전 변환 결과', '✅ 새 변환 결과']}>
  <Tabs.Tab>
    ```js
    // React import가 있어야 동작
    import React from "react";
    const el = React.createElement("h1", null, "Hi");
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```js
    // Babel이 이 import를 자동으로 삽입 — 개발자는 안 써도 됨
    import { jsx as _jsx } from "react/jsx-runtime";
    const el = _jsx("h1", { children: "Hi" });
    ```
  </Tabs.Tab>
</Tabs>

<Callout type="warning">
  요즘 Vite·Next 프로젝트에서 `import React` 없이도 JSX가 돌아가는 이유가 이것이다. 반대로 오래된 강의는 파일마다 `import React`를 붙이는데, 그대로 따라 할 필요 없다. 다만 4번 챕터의 CDN 방식은 전역 `React`에 의존하므로 예전(classic) 방식으로 동작한다는 점만 기억하자.
</Callout>

## JSX 문법 규칙

JSX는 결국 JS 함수 호출이 되기 때문에, HTML과 다른 규칙이 몇 개 있다.

### 최상위 요소는 하나

`return`은 값을 하나만 내보낸다. 그래서 여러 요소를 나란히 반환할 수 없다. 감싸거나 **Fragment**(`<>...</>`)로 묶는다.

```jsx
// ❌ 형제 둘을 그대로 반환 불가
return (
  <h1>제목</h1>
  <p>본문</p>
);

// ✅ Fragment로 묶기 — 불필요한 div를 안 만든다
return (
  <>
    <h1>제목</h1>
    <p>본문</p>
  </>
);
```

### 속성 이름이 다르다

일부 HTML 속성은 JS 예약어이거나 DOM 프로퍼티 이름을 따르기 때문에 이름이 바뀐다.

| HTML | JSX | 이유 |
| --- | --- | --- |
| `class` | `className` | `class`는 JS 예약어 |
| `for` | `htmlFor` | `for`는 JS 예약어 |
| `onclick` | `onClick` | 이벤트는 camelCase |
| `tabindex` | `tabIndex` | 속성도 camelCase |
| `style="color:red"` | `style={{ color: "red" }}` | 문자열이 아니라 **객체** |

### 중괄호로 JS를 넣는다

`{}` 안에는 JavaScript **표현식**을 넣을 수 있다.

```jsx
const name = "React";
return <h1>Hello, {name}!</h1>; // Hello, React!
```

<Callout type="error">
  `{}` 안에는 **표현식(값이 되는 것)** 만 들어간다. `if`, `for` 같은 **문(statement)** 은 못 넣는다. 결국 `createElement`의 **인자**로 들어가기 때문이다 — 인자 자리엔 값만 올 수 있다. 그래서 조건은 삼항 연산자(`? :`)나 `&&`로, 반복은 `map`으로 처리한다. (각각 13번, 14번 챕터.)
</Callout>

### 태그는 반드시 닫는다

HTML에선 `<img>`, `<br>`처럼 열기만 해도 되지만, JSX에선 전부 닫아야 한다.

```jsx
<img src="logo.png" />
<br />
<input type="text" />
```

### 주석

JSX 안에서는 `{/* ... */}` 형태로 쓴다.

```jsx
return (
  <div>
    {/* 이건 JSX 주석 */}
    <h1>Hi</h1>
  </div>
);
```

## Fragment 한 걸음 더

`<>...</>`는 `React.Fragment`의 축약형이다. 화면에 아무 DOM도 남기지 않고 자식만 묶는다. 단, Fragment에 `key`를 줘야 할 때(리스트 렌더링, 14번)는 축약형 대신 정식 표기를 쓴다.

```jsx
<React.Fragment key={item.id}>
  <dt>{item.term}</dt>
  <dd>{item.desc}</dd>
</React.Fragment>
```
