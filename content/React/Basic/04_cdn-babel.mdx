## 왜 CDN으로 시작하나

실무에선 Vite 같은 빌드 도구로 프로젝트를 만든다(9번 챕터). 하지만 빌드 도구는 **너무 많은 걸 숨긴다.** JSX가 어떻게 변환되는지, React와 ReactDOM이 왜 따로인지, 화면이 실제로 어떻게 그려지는지 — 이걸 안 보고 넘어가면 나중에 설정이 꼬였을 때 손을 못 댄다.

그래서 이 챕터에선 **설치 없이 HTML 파일 하나**로 React를 굴려본다. 목표는 "실무 세팅"이 아니라 **원리를 눈으로 보는 것**이다.

<Callout type="info">
  여기서 만든 방식은 학습용이다. 실제 프로젝트에는 쓰지 않는다. 이유는 이 챕터 뒷부분에서 설명한다.
</Callout>

## React를 굴리는 세 조각

CDN에서 스크립트 3개를 불러온다. 각자 역할이 다르다.

<Tabs items={['React', 'ReactDOM', 'Babel']}>
  <Tabs.Tab>
    **코어 라이브러리.** 컴포넌트와 엘리먼트를 "정의"하는 기능만 들어 있다. 화면에 그리는 일은 하지 않는다. `useState` 같은 훅도 여기 있다.
  </Tabs.Tab>
  <Tabs.Tab>
    **렌더러.** React가 정의한 걸 받아 실제 브라우저 **DOM**에 그린다. React가 웹·모바일(React Native) 등 여러 환경에서 쓰이기 때문에, "그리는 부분"을 코어와 분리해 둔 것이다.
  </Tabs.Tab>
  <Tabs.Tab>
    **트랜스파일러.** 브라우저는 JSX(`<h1>Hi</h1>` 같은 문법)를 이해하지 못한다. Babel이 이걸 브라우저가 아는 `React.createElement(...)` 호출로 바꿔준다. (JSX의 진짜 정체는 5번 챕터에서 판다.)
  </Tabs.Tab>
</Tabs>

## 가장 작은 React 페이지

아래 내용을 `index.html`로 저장하고 브라우저로 열면 끝이다. 서버도, 설치도 없다.

```html filename="index.html"
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>React CDN 체험</title>
  </head>
  <body>
    <div id="root"></div>

    <!-- 1. React 코어 -->
    <script crossorigin src="https://unpkg.com/react@18/umd/react.development.js"></script>
    <!-- 2. ReactDOM 렌더러 -->
    <script crossorigin src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"></script>
    <!-- 3. Babel (JSX 변환기) -->
    <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

    <!-- type="text/babel" 이어야 Babel이 이 스크립트를 변환한다 -->
    <script type="text/babel">
      function App() {
        return <h1>Hello, React!</h1>;
      }

      const root = ReactDOM.createRoot(document.getElementById("root"));
      root.render(<App />);
    </script>
  </body>
</html>
```

## 코드 한 줄씩 뜯어보기

<Steps>

### `<div id="root">`

React가 그림을 그릴 **빈 컨테이너**. 여기 안쪽이 통째로 React의 관할이 된다. HTML엔 이 빈 div 하나뿐이고, 나머지는 전부 JS가 채운다.

### 스크립트 순서

`react` → `react-dom` → `babel` 순서가 중요하다. ReactDOM은 React에 의존하고, Babel은 나머지 코드를 변환해야 하므로 마지막 실행 흐름에 걸린다. 순서가 틀리면 `React is not defined` 같은 에러가 난다.

### `type="text/babel"`

일반 `<script>`가 아니라 `type="text/babel"`이다. 이 표시가 있어야 Babel이 "이건 내가 변환할 코드"라고 인식한다. 이게 없으면 브라우저가 JSX를 그대로 실행하려다 문법 에러를 낸다.

### `createRoot(...).render(...)`

`ReactDOM.createRoot`로 root div를 React가 관리할 "루트"로 만들고, `.render(<App />)`로 컴포넌트를 그 안에 그린다. 이 시점에 화면에 `Hello, React!`가 뜬다.

</Steps>

## 구버전 → 새 문법

옛날 강의·블로그를 그대로 따라 하면 안 되는 지점이 두 군데 있다.

### ① 렌더링 API — `render` → `createRoot`

React 17까지는 `ReactDOM.render`를 썼다. React 18부터 `createRoot`로 바뀌었고, 지금은 이게 표준이다.

<Tabs items={['❌ 구버전 (React 17-)', '✅ 현재 (React 18+)']}>
  <Tabs.Tab>
    ```js
    // React 17 이하 — 지금은 쓰지 않는다
    ReactDOM.render(
      <App />,
      document.getElementById("root")
    );
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```js
    // React 18 이상 — 동시성 기능(Concurrent)을 켜는 새 진입점
    const root = ReactDOM.createRoot(
      document.getElementById("root")
    );
    root.render(<App />);
    ```
  </Tabs.Tab>
</Tabs>

`render` 방식이 보이면 오래된 자료다. 이 변화의 배경(동시성·배치)은 각각 7번, 20번, 55번 챕터에서 이어진다.

### ② React 19는 UMD 빌드를 없앴다

위 예제는 `react@18`로 고정돼 있다. 이유가 있다. **React 19부터 UMD 빌드가 제거**됐다. 그래서 `@18`을 `@19`로 바꾸면 전역 `React`·`ReactDOM`이 안 잡혀 그대로 깨진다.

React 19를 빌드 도구 없이 쓰려면 **ESM + import map** 방식으로 가야 한다.

```html filename="react19-esm.html"
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <!-- 모듈 이름 → CDN 주소 매핑 -->
    <script type="importmap">
      {
        "imports": {
          "react": "https://esm.sh/react@19",
          "react-dom/client": "https://esm.sh/react-dom@19/client"
        }
      }
    </script>
  </head>
  <body>
    <div id="root"></div>

    <!-- 모듈 + JSX를 함께 쓰려면 data-type="module" -->
    <script type="text/babel" data-type="module">
      import { createRoot } from "react-dom/client";

      function App() {
        return <h1>Hello, React 19!</h1>;
      }

      createRoot(document.getElementById("root")).render(<App />);
    </script>
    <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>
  </body>
</html>
```

<Callout type="warning">
  전역 `ReactDOM.createRoot`(구방식)와 `import { createRoot } from "react-dom/client"`(신방식)는 결과는 같지만 불러오는 방법이 다르다. React 19 자료가 `import`를 쓰는 이유가 이것이다. 그리고 보다시피 — 설정이 눈에 띄게 번거로워졌다. 그게 다음 이야기로 이어진다.
</Callout>

## 왜 실무에선 이렇게 안 쓰나

CDN + Babel은 원리 체험엔 좋지만 실무엔 부적합하다.

- **느리다.** Babel이 브라우저에서 **매번** JSX를 변환한다. 페이지를 열 때마다 변환 비용이 든다. 콘솔에 "프로덕션용이 아니다"라는 경고도 뜬다.
- **최적화가 없다.** 번들링·코드 분할·트리 셰이킹 같은 게 하나도 없다.
- **관리가 안 된다.** 파일이 늘어나면 `<script>`로 일일이 끼워 넣을 수 없다.

그래서 실제 프로젝트는 변환을 **미리(빌드 타임)** 끝내는 도구를 쓴다. 그 도구가 왜 필요하고 왜 빠른지는 8번(번들러와 모듈 시스템의 원리), 실제 세팅은 9번(Vite)에서 다룬다.
