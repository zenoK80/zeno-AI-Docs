## 01편 복습

## 문제 1

직접 DOM(화면을 이루는 요소들의 구조)을 조작하는 방식의 근본적인 문제는?

- A. 코드가 너무 짧아서 오히려 이해하기 어렵다
- B. 데이터가 바뀔 때마다 화면 곳곳을 개발자가 손으로 맞춰야 한다
- C. 브라우저마다 전혀 실행이 안 된다
- D. 특별한 문제는 없고 단지 유행이 지났을 뿐이다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
좋아요 숫자가 바뀌면 숫자 텍스트도 바꾸고, 배지도 켜고, 버튼 색도 바꾸는 식으로 **"바뀐 데이터"를 화면 곳곳에 일일이 손으로 반영**해야 한다. 반영할 곳을 하나라도 빠뜨리면 화면과 실제 데이터가 어긋나는 버그가 생긴다. 화면 조각이 많아질수록 이걸 사람이 다 추적하기 어려워지는 게 React 등장 이전 프론트엔드의 가장 큰 골칫거리였다.
</Collapse>

## 문제 2

**명령형**과 **선언형**의 차이를 가장 정확히 설명한 것은?

- A. 명령형은 "결과만 선언"하고, 선언형은 "과정을 하나하나 지시"한다
- B. 명령형은 "과정을 하나하나 지시"하고, 선언형은 "결과만 선언"한다
- C. 둘은 완전히 같은 말이다
- D. 명령형은 최신 방식이고 선언형은 옛날 방식이다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
**명령형**<sup>Imperative, "어떻게 할지" 하나하나 지시하는 방식</sup>은 "숫자를 바꾸고, 배지를 켜라"처럼 절차를 순서대로 지시한다. **선언형**<sup>Declarative, "무엇을 원하는지" 결과만 말하는 방식</sup>은 "count가 100 초과면 배지가 있는 화면"처럼 원하는 최종 결과만 말한다. React의 핵심은 이 선언형으로 UI를 짜는 것이다.
</Collapse>

## 문제 3

React는 **프레임워크**인가 **라이브러리**인가?

- A. 프레임워크다. 전체 구조를 강제로 정해준다
- B. 라이브러리다. 화면을 그리는 일만 담당하고 나머지는 개발자가 선택한다
- C. 둘 다 아니다. 그냥 하나의 프로그래밍 언어다
- D. 상황에 따라 둘 다 될 수 있다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
**라이브러리**<sup>Library, 필요한 기능만 가져다 쓰는 도구</sup>는 어떤 기능을 쓸지 개발자가 자유롭게 고른다. **프레임워크**<sup>Framework, 전체 구조를 미리 정해두고 그 틀 안에서 개발하게 하는 것</sup>는 반대로 정해진 틀을 따라야 한다. React는 "화면을 그리는 일"만 맡고, 라우팅(페이지 이동)이나 데이터 요청 방식은 강제하지 않으므로 라이브러리다. (Next.js처럼 이런 조합을 미리 갖춰둔 것이 프레임워크에 가깝다.)
</Collapse>

## 실습 — 명령형 코드를 선언형으로 바꿔보기

아래는 "좋아요 수가 100 넘으면 배지를 보여주는" 명령형 코드다.

```js
function increaseLike() {
  const countEl = document.querySelector('#count')
  let count = Number(countEl.textContent) + 1
  countEl.textContent = count

  if (count > 100) {
    document.querySelector('#badge').style.display = 'block'
  }
}
```

이걸 "count가 이 값이면 화면은 이렇다"는 선언형 문장으로 말로 풀어써 보자. (코드로 짤 필요는 없다 — 5편에서 JSX로 직접 짜본다.)

<Collapse title="예시 답안">
"좋아요 개수를 화면에 보여준다. count가 100보다 크면, 배지도 함께 보여준다."

이렇게 **"어떻게 바꿀지"가 아니라 "지금 상태에서 화면이 어떤 모습인지"** 로 표현하는 게 선언형 사고다. 10편(컴포넌트)부터 이걸 실제 코드로 만든다.
</Collapse>
