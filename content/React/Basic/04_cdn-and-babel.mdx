## React 개발 환경 이해하기

React를 검색하면 대부분 `npm create vite@latest` 같은 명령부터 시작한다.
그런데 그 명령이 **정확히 뭘 준비해 주는지** 모른 채 따라 치면, 나중에 설정이 꼬였을 때 손을 못 댄다.

이번 편은 그 반대로 간다. **아무 도구 없이, HTML 파일 하나로 React를 직접 띄워본다.**
느리고 실무용은 아니지만, "React를 돌리려면 최소한 무엇이 필요한가"가 뼈대만 남아 훨씬 선명하게 보인다.

## 최소 구성 — HTML 파일 하나

```html filename="index.html"
<!DOCTYPE html>
<html>
<body>
  <div id="root"></div>

  <script src="https://unpkg.com/react@19/umd/react.development.js"></script>
  <script src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>

  <script>
    const element = React.createElement('h1', null, '안녕, React')
    const root = ReactDOM.createRoot(document.getElementById('root'))
    root.render(element)
  </script>
</body>
</html>
```

이 파일을 브라우저로 열면 "안녕, React"가 화면에 뜬다. **설치도, 빌드 도구도 없다.**

## 코드 한 줄씩 뜯어보기

```html
<script src="https://unpkg.com/react@19/umd/react.development.js"></script>
```

**unpkg**는 npm에 올라간 패키지를 CDN(외부 서버)에서 바로 파일로 내려주는 서비스다.
`npm install react`로 내려받는 대신, 이 `<script>` 태그가 그 역할을 대신한다.

```js
const element = React.createElement('h1', null, '안녕, React')
```

`React.createElement(태그, props, 내용)`은 **"이런 모습의 요소를 하나 만들어 달라"** 는 요청이다.
결과물을 콘솔에 찍어보면 이렇게 생겼다.

```js
console.log(element)
// { type: 'h1', props: { children: '안녕, React' }, ... }
```

<Callout type="important">
진짜 DOM 요소가 아니라 **평범한 자바스크립트 객체**다. "이런 요소를 그리고 싶다"는 설계도일 뿐이다.
이게 바로 1편에서 예고한 **Virtual DOM**의 가장 작은 단위다. 6편에서 이 객체가 어떻게 실제 DOM으로 바뀌는지 자세히 다룬다.
</Callout>

```js
const root = ReactDOM.createRoot(document.getElementById('root'))
root.render(element)
```

`ReactDOM`이 그 설계도(`element`)를 받아 **실제 DOM에 반영**하는 역할을 한다.
`document.getElementById('root')`는 Web APIs 시리즈에서 다룬 순수 DOM API다 — **React가 최종적으로 손대는 대상은 결국 평범한 DOM**이라는 걸 보여준다.

## createElement로 여러 층 쌓아보기

```js
const element = React.createElement(
  'div',
  null,
  React.createElement('h1', null, '제목'),
  React.createElement('p', null, '내용')
)
```

이렇게 중첩할 수 있다. 그런데 벌써 눈이 아프다. 태그가 몇 겹만 되어도 `createElement` 호출이 손으로 짜기 괴로워진다.

<Callout type="warning">
실제 React 코드에서 `createElement`를 직접 쓰는 걸 거의 못 봤을 것이다. 대신 HTML처럼 생긴 **JSX**를 쓴다.
그런데 브라우저는 JSX를 모른다. 이 간극을 메우는 게 다음 도구다.
</Callout>

## Babel — JSX를 브라우저가 아는 코드로 바꾸기

**Babel**은 최신/특수 문법으로 짠 코드를 브라우저가 이해할 수 있는 코드로 **변환**해 주는 도구다.
CDN으로 Babel의 브라우저용 버전(`standalone`)을 가져오면, HTML 파일 안에서 바로 JSX를 쓸 수 있다.

```html filename="index.html"
<!DOCTYPE html>
<html>
<body>
  <div id="root"></div>

  <script src="https://unpkg.com/react@19/umd/react.development.js"></script>
  <script src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>
  <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

  <script type="text/babel">
    const element = (
      <div>
        <h1>제목</h1>
        <p>내용</p>
      </div>
    )

    const root = ReactDOM.createRoot(document.getElementById('root'))
    root.render(element)
  </script>
</body>
</html>
```

바뀐 부분은 두 가지다.

1. `<script type="text/babel">` — 이 스크립트는 일반 JS가 아니라 **Babel이 먼저 처리해야 하는 코드**라고 표시한다
2. `<div>...</div>` — HTML처럼 생긴 이 문법이 **JSX**다

<Callout type="info">
브라우저는 `type="text/babel"`인 스크립트를 그냥 실행하지 않는다. 페이지가 로드되면 Babel 라이브러리가
이 스크립트 내용을 읽어 **JSX를 `React.createElement` 호출로 변환**한 뒤에야 실제로 실행한다.
즉 우리가 위에서 손으로 짰던 코드를, JSX를 쓰면 **Babel이 대신 만들어준다.**
</Callout>

개발자 도구에서 확인해 볼 수도 있다. [Babel 공식 REPL](https://babeljs.io/repl)에 위 JSX를 붙여넣으면,
오른쪽에 변환된 `React.createElement(...)` 코드가 그대로 뜬다. JSX 문법 자체는 5편에서 자세히 다룬다.

## 이 방식은 왜 실무에서 안 쓰나

<Callout type="warning">
이 HTML 파일을 그대로 실무에 쓰면 안 되는 이유가 있다.

- **매번 브라우저에서 JSX → JS 변환이 일어난다** — 페이지를 열 때마다 이 변환 작업을 반복해서, 코드가 커질수록 느려진다
- **`react.development.js`는 개발용**이다 — 실제 배포에는 더 작고 빠른 프로덕션 버전이 필요하다
- **여러 파일로 나누기 힘들다** — 컴포넌트가 몇 개만 늘어도 관리가 안 된다

실무에서는 이 변환(JSX → JS)과 파일 묶기를 **미리, 컴퓨터에서** 해두는 도구를 쓴다.
그게 **번들러**다. 8편에서 번들러의 원리를, 9편에서 실제 도구(Vite) 설정을 다룬다.
</Callout>

## 이 편에서 얻어야 할 것

<Callout type="default">
지금 실무 세팅법을 몰라도 된다. 이 편의 목적은 **"Vite가 자동으로 해주는 일이 정확히 무엇인지"** 감을 잡는 것이다.

- React 라이브러리를 코드에 연결하는 것 (CDN → 실무에서는 npm 설치)
- JSX를 실행 가능한 JS로 바꾸는 것 (Babel → 실무에서도 여전히 Babel 계열 도구가 이 일을 함)
- 여러 파일을 하나로 묶어 브라우저에 최적화된 형태로 만드는 것 (지금 안 함 → 번들러가 담당)
</Callout>

## 정리

<Callout type="default">
- React를 돌리는 데 최소한으로 필요한 건 **React 라이브러리 + DOM에 그릴 대상**뿐이다
- `React.createElement(태그, props, 내용)`은 실제 DOM이 아니라 **"그리고 싶은 모습"을 담은 객체**를 만든다
- JSX는 사람이 짜기 편한 문법일 뿐, 결국 `React.createElement` 호출로 **변환**된다
- 이 변환을 담당하는 도구가 **Babel**이다
- 실무에서는 이 과정을 미리 처리해 두는 **번들러**를 쓴다
</Callout>

다음 편에서는 지금 눈으로 확인한 JSX 문법 자체를 규칙부터 제대로 파헤친다.
