## 핵심 퀴즈

**Q1. 콜 스택은 어떤 순서로 함수를 처리하나? (LIFO가 무슨 뜻인가)**

<Collapse title="정답 보기">
Last In, First Out — 나중에 들어온 함수가 먼저 끝난다. 스택의 가장 위(마지막에 쌓인 것)가 먼저 완료돼야 그 아래가 이어서 끝난다.
</Collapse>

**Q2. JIT 컴파일이 하는 일은?**

<Collapse title="정답 보기">
자주 반복 호출되는(뜨거운) 코드를 실행 중에 감지해서 더 빠른 기계어로 다시 컴파일하는 것.
</Collapse>

**Q3. "Maximum call stack size exceeded" 에러는 왜 나나?**

<Collapse title="정답 보기">
함수가 멈추지 않고 스스로를 계속 호출해서(재귀 종료 조건이 없어서) 콜 스택이 한계를 넘었을 때 난다. 스택 오버플로우라 부른다.
</Collapse>

## 실습 — 스택 트레이스 직접 읽기

아래 코드를 파일이나 콘솔에 그대로 실행해 보자.

```js
function step3() {
  throw new Error('여기서 문제 발생')
}
function step2() { step3() }
function step1() { step2() }

step1()
```

콘솔에 찍히는 에러 메시지의 스택 트레이스를 위에서부터 읽으며, 어떤 함수를 거쳐 에러가 발생했는지 순서대로 말해보자.

<Collapse title="읽는 법">
가장 위 줄이 **에러가 실제로 발생한 지점**(`step3`)이고, 아래로 갈수록 그 함수를 호출한 쪽(`step2` → `step1`)이다. "누가 누구를 호출해서 여기까지 왔는지"가 위에서 아래로 순서대로 보인다.
</Collapse>
