## 03편 복습

## 문제 1

콜 스택은 어떤 순서로 함수를 처리하나?

<Quiz>
  <Quiz.Option>FIFO — 먼저 들어온 함수가 먼저 끝난다</Quiz.Option>
  <Quiz.Option correct>LIFO — 나중에 들어온 함수가 먼저 끝난다</Quiz.Option>
  <Quiz.Option>무작위 순서로 처리한다</Quiz.Option>
  <Quiz.Option>가장 짧은 함수부터 처리한다</Quiz.Option>

  <Quiz.Explanation>
  **콜 스택**<sup>Call Stack, 지금 실행 중인 함수 호출을 순서대로 쌓아 관리하는 구조</sup>은 **LIFO**<sup>Last In, First Out, 나중에 들어온 게 먼저 나가는 방식</sup>로 동작한다. 접시를 쌓아 올렸다가 위에서부터 하나씩 빼는 모습을 떠올리면 쉽다. 스택의 가장 위(마지막에 쌓인 함수)가 먼저 끝나야, 그 아래(먼저 쌓인 함수)가 이어서 끝날 수 있다.
  </Quiz.Explanation>
</Quiz>

## 문제 2

JIT 컴파일이 하는 일은?

<Quiz>
  <Quiz.Option>코드를 사람이 읽기 좋게 정리해준다</Quiz.Option>
  <Quiz.Option correct>자주 반복 호출되는(뜨거운) 코드를 실행 중에 감지해서 더 빠른 기계어로 다시 컴파일한다</Quiz.Option>
  <Quiz.Option>에러가 있는 코드를 자동으로 고쳐준다</Quiz.Option>
  <Quiz.Option>코드를 다른 프로그래밍 언어로 번역해준다</Quiz.Option>

  <Quiz.Explanation>
  **JIT**<sup>Just-In-Time, "그때그때 바로" 컴파일한다는 뜻</sup>는, 처음엔 코드를 빠르게 대충 실행하다가 같은 함수가 반복해서 많이 호출되는 걸 감지하면 그 부분만 더 빠른 기계어로 바꿔치기하는 최적화 기법이다. 이 덕분에 자바스크립트가 "인터프리터 언어라 느리다"는 옛말이 더 이상 맞지 않게 됐다.
  </Quiz.Explanation>
</Quiz>

## 문제 3

"Maximum call stack size exceeded"(콜 스택 최대 크기 초과) 에러는 왜 나나?

<Quiz>
  <Quiz.Option>인터넷 연결이 끊겨서</Quiz.Option>
  <Quiz.Option correct>함수가 멈추지 않고 스스로를 계속 호출해서 콜 스택이 한계를 넘었기 때문에</Quiz.Option>
  <Quiz.Option>변수 이름을 잘못 지어서</Quiz.Option>
  <Quiz.Option>코드에 오타가 있어서</Quiz.Option>

  <Quiz.Explanation>
  **스택 오버플로우**<sup>Stack Overflow, 콜 스택이 넘칠 만큼 함수 호출이 쌓인 상태</sup>라고 부르는 이 에러는, 함수가 끝나는 조건 없이 자기 자신을 계속 호출할 때(무한 재귀) 발생한다. 콜 스택은 무한정 쌓을 수 있는 게 아니라 정해진 한계가 있어서, 그 한계를 넘으면 이 에러가 난다.
  </Quiz.Explanation>
</Quiz>

## 실습 — 스택 트레이스 직접 읽기

아래 코드를 파일이나 콘솔에 그대로 실행해 보자.

```js
function step3() {
  throw new Error('여기서 문제 발생')
}
function step2() { step3() }
function step1() { step2() }

step1()
```

콘솔에 찍히는 에러 메시지의 **스택 트레이스**<sup>Stack Trace, 에러가 난 순간의 콜 스택을 그대로 보여주는 목록</sup>를 위에서부터 읽으며, 어떤 함수를 거쳐 에러가 발생했는지 순서대로 말해보자.

<Collapse title="읽는 법">
가장 위 줄이 **에러가 실제로 발생한 지점**(`step3`)이고, 아래로 갈수록 그 함수를 호출한 쪽(`step2` → `step1`)이다. "누가 누구를 호출해서 여기까지 왔는지"가 위에서 아래로 순서대로 보인다.
