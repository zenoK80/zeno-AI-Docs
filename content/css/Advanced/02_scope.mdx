## @scope로 스타일 범위 제한

큰 프로젝트에서 CSS가 지저분해지는 대표적인 이유는 **"이 스타일이 어디까지 영향을 주는지 알 수 없어서"** 다.
`.card p { color: gray; }` 라고 쓰면, 페이지 어디에 있는 `.card`든 그 안의 `p`는 전부 영향을 받는다.
`@scope`는 이 범위를 **명시적으로 선언**할 수 있게 해준다.

<Callout type="info">
**Baseline 2026 (Newly available)**

Chrome, Safari, Firefox 146부터 모든 주요 브라우저가 지원한다. 방금 전 브라우저 지원이 갖춰진 상태라
구형 브라우저까지 지원해야 하는 프로젝트라면 폴백(이 편 마지막 참고)을 함께 고려한다.
</Callout>

## 기본 문법

```css
@scope (.card) {
  p { color: gray; }
  h2 { font-size: 1.5rem; }
}
```

이 규칙은 **`.card` 요소 안에 있는 `p`, `h2`에만** 적용된다. 겉보기엔 1편에서 배운 중첩과 비슷해 보이지만 결정적으로 다르다.

```css
/* 중첩 — 그냥 .card p로 풀어 쓴 것과 같다. 명시도가 계속 쌓인다 */
.card {
  p { color: gray; }
}

/* @scope — 범위를 규칙 자체에 선언한다 */
@scope (.card) {
  p { color: gray; }
}
```

## 왜 이게 필요한가 — 선택자 vs @scope

지금까지는 특정 영역에만 스타일을 주려면 선택자를 구체적으로 쌓는 수밖에 없었다.

```css
/* 기존 방식 */
.article .content p { margin-bottom: 1rem; }
```

문제는 **이 선택자가 우연히 다른 곳과 겹칠 수 있다**는 것이다. `.article` 안에 다른 컴포넌트가 들어오고
그 안에도 `p`가 있다면, 의도치 않게 스타일이 새어 들어간다.

`@scope`는 범위의 **시작(위쪽 경계)** 을 선언에 명시하므로, 그 블록 안의 선택자는 항상 그 범위로 한정된다.

## 하한선도 정할 수 있다 — to

`@scope`의 진짜 힘은 **범위의 끝(아래쪽 경계)** 도 정할 수 있다는 데 있다.

```css
@scope (.card) to (.card-footer) {
  p { color: gray; }
}
```

```html
<div class="card">
  <p>이 문단은 회색이다</p>
  <div class="card-footer">
    <p>이 문단은 회색이 아니다 — 경계 밖이다</p>
  </div>
</div>
```

`.card-footer`를 만나는 순간 그 **하위는 범위에서 제외**된다. 카드 안에 중첩된 다른 컴포넌트(예: 다른 카드, 푸터)의
스타일이 실수로 섞이는 걸 막을 때 유용하다.

<Callout type="important">
`to (.card-footer)` 자체, 즉 `.card-footer` 요소는 범위에 **포함되지 않는다.** "여기서부터는 제외"라는 경계선이라고 생각하면 된다.
</Callout>

## :scope — 범위의 기준점 가리키기

`@scope` 블록 안에서 `:scope`는 **범위를 연 그 요소 자신**을 가리킨다.

```css
@scope (.card) {
  :scope {
    border: 1px solid gray;   // .card 자신에게 적용
  }
  :scope > h2 {
    margin-top: 0;             // .card의 직계 자식 h2
  }
}
```

## 명시도 — & 중첩과 같은 방식

1편에서 CSS 중첩의 `&`가 `:is()`처럼 명시도를 계산한다고 했다. `@scope`의 범위 선택자도 같은 방식이다.

```css
@scope (#sidebar, .card) {
  p { color: gray; }
}
```

이때 `p`의 명시도는 `#sidebar`와 `.card` 중 **더 높은 쪽**을 기준으로 계산된다.
1편에서 다룬 명시도 함정과 동일한 원리이므로, 여러 선택자를 섞을 땐 `:where()`로 감싸는 습관을 유지한다.

## 캐스케이드에서 @scope의 위치

`@scope`는 명시도와는 별개로, **캐스케이드 우선순위 계산에 새 기준을 하나 추가**한다.
같은 명시도라면, **범위(scope)가 더 좁게(더 가깝게) 선언된 규칙이 이긴다.**

```css
@scope (body) {
  .card p { color: black; }
}

@scope (.card) {
  p { color: gray; }   // 이긴다 — .card가 body보다 더 좁은 범위
}
```

<Callout type="info">
이 우선순위 규칙은 `@layer`(기초 4편)보다 나중에 적용된다. 즉 레이어 순서가 먼저 정해지고,
같은 레이어 안에서 범위 근접도가 비교되는 식이다. 두 기능을 함께 쓸 일이 있다면 레이어 구조를 먼저 설계하자.
</Callout>

## 실무에서 언제 쓰나

<Callout type="default">
- **서드파티 위젯이나 마크다운 렌더링 결과**처럼, 내부 구조를 통제할 수 없는 HTML에 스타일을 입힐 때
- **BEM 같은 네이밍 규칙 없이도** 컴포넌트 스타일을 격리하고 싶을 때
- Shadow DOM(Web APIs 시리즈 Part 4)만큼 강력한 격리는 필요 없지만, **일반 DOM 안에서 범위만 확실히 하고 싶을 때**
</Callout>

## 구형 브라우저 폴백

`@scope`를 모르는 브라우저는 이 규칙 전체를 무시한다. 스타일이 아예 적용되지 않는다는 뜻이므로,
지원 여부가 불확실하다면 `@supports`로 감싸 최소한의 기본 스타일을 보장하는 편이 안전하다.

```css
@supports (@scope (.card) {}) {
  @scope (.card) {
    p { color: gray; }
  }
}
```

## 정리

<Callout type="default">
- `@scope (시작)`은 그 안의 선택자를 **특정 DOM 범위로 한정**한다
- `@scope (시작) to (끝)`으로 하한선도 지정할 수 있다 — 중첩된 컴포넌트로 스타일이 새는 걸 막는다
- `:scope`는 범위를 연 요소 자신을 가리킨다
- 명시도는 `&`와 마찬가지로 `:is()` 방식으로 계산된다
- 같은 명시도라면 **범위가 더 좁은 규칙이 이긴다**
</Callout>

다음 편에서는 계산 자체를 CSS 안에서 처리하는 수학 함수들(`calc()`, `clamp()` 등)을 다룬다.
