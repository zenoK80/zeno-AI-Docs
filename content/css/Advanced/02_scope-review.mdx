## 02편 복습

## 문제 1

`@scope (.card) to (.card-footer)`에서, `.card-footer` 요소 자신은 스타일 범위에 포함되나?

- A. 포함된다
- B. 포함되지 않는다 — "여기서부터는 제외"라는 경계선일 뿐이다
- C. 브라우저마다 다르게 처리한다
- D. `.card-footer`의 자식 요소만 포함되고 자신은 제외된다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
`to (.card-footer)`는 "이 요소를 만나는 순간부터는 범위 밖"이라는 **하한선**을 정하는 것이다. `.card-footer` 자기 자신과 그 하위 요소 모두 범위에서 제외된다. 중첩된 다른 컴포넌트로 스타일이 새어 들어가는 걸 막을 때 이 문법을 쓴다.
</Collapse>

## 문제 2

`@scope (.card) { ... }` 블록 안에서 `:scope`는 무엇을 가리키나?

- A. 문서 전체(`<body>`)
- B. 범위를 연 그 요소 자신, 즉 `.card`
- C. `.card`의 모든 자식 요소
- D. 브라우저 창 전체

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
`:scope`는 `@scope`로 지정한 **범위의 시작점이 되는 그 요소 자신**을 가리키는 특수 선택자다. `@scope (.card) { :scope { border: 1px solid gray; } }`라고 쓰면 `.card` 요소 자신에 테두리가 적용된다.
</Collapse>

## 문제 3

같은 명시도를 가진 두 `@scope` 규칙이 충돌하면 무엇이 이기나?

- A. 나중에 작성된 규칙이 항상 이긴다
- B. 범위가 더 좁게(더 가깝게) 선언된 규칙이 이긴다
- C. 알파벳 순서가 빠른 선택자가 이긴다
- D. 무작위로 결정된다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
`@scope`는 명시도와는 별개로 **범위의 근접도**라는 새로운 우선순위 기준을 추가한다. 같은 명시도라면, 스타일을 적용하려는 요소와 더 가까운(더 좁은) 범위에서 선언된 규칙이 이긴다. 예를 들어 `@scope (body)`보다 `@scope (.card)`가 더 좁은 범위이므로, 둘이 충돌하면 `.card` 쪽이 이긴다.
</Collapse>

## 실습 — 범위에 하한선 추가하기

아래는 `.widget` 안의 모든 `p`에 회색을 주는 규칙이다. 그런데 `.widget` 안에 중첩된 `.nested-card`의 `p`에는 영향을 주면 안 된다고 하자. `to`를 추가해서 고쳐보자.

```css
@scope (.widget) {
  p { color: gray; }
}
```

```html
<div class="widget">
  <p>회색이어야 함</p>
  <div class="nested-card">
    <p>회색이면 안 됨</p>
  </div>
</div>
```

<Collapse title="정답 보기">

```css
@scope (.widget) to (.nested-card) {
  p { color: gray; }
}
```

</Collapse>
