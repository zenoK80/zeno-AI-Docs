## 01편 복습

## 문제 1

네이티브 CSS 중첩에서 `&__title`처럼 문자열을 이어 붙일 수 있나? (Sass에서는 이게 가능했다)

- A. 가능하다. Sass와 완전히 똑같이 동작한다
- B. 불가능하다. `&`는 문자열이 아니라 선택자 자체를 가리키는 값이기 때문이다
- C. 가능은 하지만 별도의 설정이 필요하다
- D. 브라우저에 따라 되기도 하고 안 되기도 한다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
**`&`**는 Sass 전처리기에서는 "문자열처럼" 이어 붙일 수 있었지만, 네이티브 CSS 중첩에서는 **부모 선택자 자리에 그대로 대입되는 값**일 뿐이다. `&__title`처럼 뒤에 글자를 덧붙이는 건 지원하지 않는다. BEM(`card__title`처럼 이름 짓는 방식) 클래스를 쓴다면, 중첩을 포기하고 그냥 풀어서 써야 한다.
</Collapse>

## 문제 2

`.card { .active { ... } }`와 `.card { &.active { ... } }`의 차이는?

- A. 완전히 같은 뜻이다
- B. `.active`(공백)는 `.card .active`(자손 요소)를, `&.active`는 `.card.active`(같은 요소)를 가리킨다
- C. `&.active`가 더 최신 문법이라 더 빠르게 동작한다
- D. `.active`는 에러가 나는 잘못된 문법이다

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
공백이 있으면 **자손 선택자**(`.card` 안에 들어있는 `.active` 요소)가 되고, `&`를 붙이면 **같은 요소**(`.card`이면서 동시에 `.active`인 요소)를 가리키는 선택자가 된다. 공백 하나 차이로 완전히 다른 요소를 고르게 되는, 중첩에서 가장 흔한 실수 포인트다.
</Collapse>

## 문제 3

실무에서 권장하는 중첩의 최대 단계는?

- A. 제한 없이 필요한 만큼
- B. 2단계까지
- C. 5단계까지
- D. 1단계까지(중첩 자체를 쓰지 않는다)

<Collapse title="정답 보기">
정답: **B**
</Collapse>

<Collapse title="해설 보기">
중첩이 깊어질수록 **명시도**(CSS 규칙끼리 충돌했을 때 누가 이길지 정하는 점수)가 계속 올라가서 나중에 덮어쓰기 어려워지고, HTML 구조가 조금만 바뀌어도 CSS가 깨지기 쉬워진다. `.card` 안에 `h2` 정도(2단계)면 충분하고, 그 이상 깊어진다면 새 클래스를 만드는 게 낫다는 신호로 받아들이는 게 좋다.
</Collapse>

## 실습 — 반복되는 CSS를 중첩으로 리팩터링하기

아래 CSS를 네이티브 중첩을 써서 다시 써보자.

```css
.card { padding: 1rem; border: 1px solid #ddd; }
.card h2 { font-size: 1.5rem; }
.card p { color: gray; }
.card:hover { box-shadow: 0 2px 8px rgb(0 0 0 / 0.15); }
```

<Collapse title="정답 보기">

```css
.card {
  padding: 1rem;
  border: 1px solid #ddd;

  h2 { font-size: 1.5rem; }
  p  { color: gray; }

  &:hover { box-shadow: 0 2px 8px rgb(0 0 0 / 0.15); }
}
```

</Collapse>

## 정리 체크리스트

<Callout type="default">
- [ ] `&`가 부모 선택자 자리에 대입된다는 걸 안다
- [ ] Sass와 다른 점(문자열 결합 불가)을 설명할 수 있다
- [ ] 반복되는 CSS를 중첩으로 리팩터링할 수 있다
