## 01편 복습

코드를 보지 않고 CSS가 누구에게 무엇을 적용하는 언어인지 먼저 설명해 보자.

## 핵심 퀴즈

**Q1. `h1 { color: navy; }`에서 선택자, 속성, 값은 각각 무엇인가?**

<Quiz>
  <Quiz.Option>선택자는 `color`, 속성은 `h1`, 값은 `navy`다</Quiz.Option>
  <Quiz.Option>선택자는 `h1`, 속성은 `navy`, 값은 `color`다</Quiz.Option>
  <Quiz.Option correct>선택자는 `h1`, 속성은 `color`, 값은 `navy`다</Quiz.Option>
  <Quiz.Option>`h1`, `color`, `navy` 모두 "속성"이라고 부르며 따로 구분하지 않는다</Quiz.Option>

  <Quiz.Explanation>
  선택자는 스타일을 적용할 대상(`h1`)을 고르고, 속성은 무엇을 바꿀지(`color`), 값은 그걸 어떻게 바꿀지(`navy`)를 정한다. 이 세 가지 역할을 구분하지 못하면 `속성: 값;` 순서를 자꾸 헷갈리게 된다.
  </Quiz.Explanation>
</Quiz>

**Q2. HTML과 CSS를 분리하면 어떤 점이 좋아지는가?**

<Quiz>
  <Quiz.Option>브라우저가 HTML을 더 빨리 해석해서 무조건 실행 속도가 빨라진다</Quiz.Option>
  <Quiz.Option correct>구조와 표현을 독립적으로 수정할 수 있어 중복이 줄고, 사이트 전체 스타일을 한곳에서 일관되게 관리할 수 있다</Quiz.Option>
  <Quiz.Option>CSS 파일을 따로 두면 자바스크립트 없이도 애니메이션이 자동으로 생긴다</Quiz.Option>
  <Quiz.Option>분리해도 결과는 똑같으므로 실질적인 이득은 없다</Quiz.Option>

  <Quiz.Explanation>
  관심사의 분리(구조는 HTML, 표현은 CSS로 나누는 것)의 핵심 이득은 **유지보수성**이다. 스타일이 문서 곳곳에 흩어져 있지 않고 한곳에 모여 있으면, 디자인을 바꿀 때 HTML을 건드리지 않고도 전체 사이트를 일관되게 고칠 수 있다. 속도나 애니메이션 자동 생성과는 관련이 없다.
  </Quiz.Explanation>
</Quiz>

**Q3. 브라우저가 DOM과 CSSOM을 만든 다음 거치는 주요 단계는 무엇인가?**

<Quiz>
  <Quiz.Option>CSSOM은 버리고 DOM만으로 곧바로 화면에 그린다</Quiz.Option>
  <Quiz.Option>페인트를 먼저 하고 나중에 레이아웃을 계산한다</Quiz.Option>
  <Quiz.Option correct>두 트리를 바탕으로 렌더 트리를 만들고, 레이아웃으로 위치와 크기를 계산한 뒤 페인트 단계에서 픽셀을 그린다</Quiz.Option>
  <Quiz.Option>자바스크립트 엔진이 렌더 트리를 직접 실행해서 화면을 만든다</Quiz.Option>

  <Quiz.Explanation>
  DOM(문서 구조)과 CSSOM(스타일 정보)을 합쳐 화면에 실제로 그려질 요소만 남긴 **렌더 트리**를 만들고, 그다음 각 요소의 위치·크기를 계산하는 **레이아웃**, 마지막으로 실제 픽셀을 그리는 **페인트** 순서로 진행된다. 이 순서가 바뀌면 애초에 계산할 정보가 없는 상태라 그릴 수 없다.
  </Quiz.Explanation>
</Quiz>

**Q4. 나중에 작성한 `p` 규칙이 앞의 `#intro` 규칙을 이기지 못할 수 있는 이유는 무엇인가?**

<Quiz>
  <Quiz.Option>CSS는 항상 마지막에 적힌 규칙이 무조건 이기기 때문에</Quiz.Option>
  <Quiz.Option>`p` 선택자는 브라우저 기본 스타일이라 커스텀 CSS보다 우선순위가 낮기 때문에</Quiz.Option>
  <Quiz.Option correct>캐스케이드는 작성 순서뿐 아니라 명시도도 비교하는데, ID 선택자 `#intro`가 요소 선택자 `p`보다 명시도가 높기 때문에</Quiz.Option>
  <Quiz.Option>`#intro`에 보이지 않는 `!important`가 자동으로 붙기 때문에</Quiz.Option>

  <Quiz.Explanation>
  "나중에 쓴 규칙이 이긴다"는 규칙은 **명시도**<sup>Specificity, 선택자가 얼마나 구체적인지를 점수로 매긴 것</sup>가 같을 때만 적용된다. ID 선택자(`#intro`)는 요소 선택자(`p`)보다 명시도 점수가 훨씬 높아서, 작성 순서와 상관없이 항상 이긴다.
  </Quiz.Explanation>
</Quiz>

## 실습 — 적용되지 않는 스타일 설명하기

다음 HTML과 CSS에서 문단이 왜 파란색인지 설명하고, `!important` 없이 빨간색으로 바꿔 보자.

```html
<p id="intro">CSS 복습</p>
```

```css
#intro { color: blue; }
p { color: red; }
```

<Collapse title="예시 답안 보기">
`#intro`의 명시도가 `p`보다 높아 파란색이 적용된다. 같은 ID 선택자를 사용해 뒤에서 덮어쓸 수 있다.

```css
#intro { color: blue; }
#intro { color: red; }
```

실제 코드에서는 불필요하게 강한 선택자를 계속 추가하기보다 처음의 선택자 설계도 함께 점검한다.
</Collapse>
