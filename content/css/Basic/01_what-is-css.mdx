## CSS란 무엇인가

HTML만으로 만든 페이지를 본 적이 있는가?
검은 글씨, 파란 링크, 위에서 아래로 쭉 쌓인 문단. 정보는 다 있지만 아무도 읽고 싶어 하지 않는다.

**CSS**<sup>Cascading Style Sheets</sup>는 그 문서에 **생김새를 입히는 언어**다.

## 역할 분담 — 왜 따로 있나

웹 페이지는 세 가지 언어가 역할을 나눠 만든다.

| 언어 | 담당 | 비유 |
| --- | --- | --- |
| HTML | 구조와 의미 | 집의 뼈대 |
| **CSS** | **모양과 배치** | **인테리어** |
| JavaScript | 동작 | 전기 배선 |

이렇게 나누는 이유는 **바꿀 때 따로 바꾸기 위해서**다.

사이트 전체의 링크 색을 바꾼다고 하자. CSS가 없다면 HTML 파일을 전부 열어 태그마다 색을 고쳐야 한다.
CSS가 있으면 스타일 파일 **한 줄**만 고치면 끝난다.

```css
a {
  color: crimson;
}
```

이 한 줄이 사이트의 모든 링크에 적용된다.

<Callout type="info">
이 분리를 **관심사의 분리**<sup>Separation of Concerns</sup>라 부른다. 웹 개발 전반을 관통하는 원칙이라 앞으로 계속 만나게 된다.
</Callout>

## CSS는 어떻게 생겼나

CSS의 기본 단위는 **규칙**<sup>Rule</sup>이다. 딱 두 부분으로 되어 있다.

```css
h1 {
  color: navy;
  font-size: 32px;
}
```

- `h1` — **선택자**<sup>Selector</sup>. "누구에게 적용할지"
- `{ ... }` 안 — **선언 블록**<sup>Declaration Block</sup>. "무엇을 어떻게 바꿀지"

선언 하나는 `속성: 값;` 형태다.

```
color : navy ;
  ↑      ↑    ↑
 속성    값   세미콜론
```

문법은 이게 전부다. **CSS의 어려움은 문법이 아니라 "왜 내 스타일이 적용 안 되는가"에 있다.**
그 답이 다음 편들의 주제다.

<Callout type="info">
문법의 자세한 내용과 HTML에 연결하는 세 가지 방법은 다음 편에서 다룬다.
</Callout>

## 브라우저는 CSS를 어떻게 처리하나

"스타일이 적용되지 않는" 문제를 스스로 풀려면 이 흐름을 알아야 한다.
브라우저가 페이지를 그리는 과정은 대략 이렇다.

<Steps>

### HTML을 읽어 DOM을 만든다

태그를 파싱해 **DOM 트리**(문서의 구조를 나타내는 객체 트리)를 만든다.

### CSS를 읽어 CSSOM을 만든다

스타일시트를 파싱해 **CSSOM 트리**(스타일 규칙의 트리)를 만든다.

### 둘을 합쳐 렌더 트리를 만든다

각 요소에 최종 스타일을 계산해 붙인다. 이때 `display: none`인 요소는 빠진다.

### 레이아웃 — 위치와 크기를 계산한다

각 요소가 화면 어디에 얼마만 한 크기로 놓일지 계산한다. **리플로우**<sup>Reflow</sup>라고도 한다.

### 페인트 — 픽셀을 칠한다

색, 배경, 그림자, 텍스트를 실제로 그린다.

</Steps>

여기서 알아둘 게 두 가지 있다.

<Callout type="warning">
**CSS는 렌더링을 막는다**

브라우저는 CSSOM이 완성될 때까지 화면을 그리지 않는다. 스타일이 반쯤 적용된 화면이 번쩍이는 걸 막기 위해서다.
그래서 CSS 파일이 크거나 느리면 **페이지 전체가 늦게 뜬다.** CSS를 `head`에 넣고 용량을 줄이라는 조언이 여기서 나온다.
</Callout>

<Callout type="info">
**모든 속성의 비용이 같지 않다**

`width`를 바꾸면 주변 요소 위치가 다 흔들리므로 레이아웃부터 다시 한다. 반면 `color`만 바꾸면 페인트만 하면 된다.
애니메이션이 버벅일 때 `transform`과 `opacity`를 쓰라는 이유가 이것이다. 자세한 건 고급 단계의 성능 편에서 다룬다.
</Callout>

## Cascading — 이름의 절반이 여기 있다

CSS의 C는 **Cascading(폭포처럼 흘러내리는)** 이다.
같은 요소에 여러 규칙이 적용될 수 있고, 그중 무엇이 이길지 정하는 규칙이 있다는 뜻이다.

```css
p { color: black; }
p { color: red; }   /* 나중 것이 이긴다 → 빨강 */
```

그런데 항상 "나중 것"이 이기는 건 아니다.

```css
#intro { color: blue; }
p      { color: red; }   /* 나중이지만 진다 → 파랑 */
```

`#intro`가 더 **구체적**이기 때문이다.

<Callout type="important">
스타일이 적용되지 않을 때 초보가 가장 먼저 하는 일이 `!important`를 붙이는 것이다.
당장은 되지만 나중에 손댈 수 없는 코드가 된다.

**왜 졌는지를 이해하는 게 먼저다.** 이 원리는 기초 단계의 캐스케이드·명시도 편에서 제대로 다룬다.
</Callout>

## CSS는 지금도 자라고 있다

CSS를 "다 배웠다"고 말하기 어려운 이유는 **계속 커지기 때문**이다.

| 시기 | 등장한 것 |
| --- | --- |
| 1996 | CSS1 — 색, 폰트, 여백 |
| 1998 | CSS2 — 위치 지정, 미디어 타입 |
| 2011~ | CSS3 — 모듈 단위로 쪼개져 각자 발전 |
| 최근 | 중첩, 컨테이너 쿼리, `:has()`, `oklch()`, 앵커 포지셔닝 … |

<Callout type="info">
**"CSS4"는 없다**

CSS3 이후로는 버전 번호를 붙이지 않는다. 대신 Selectors, Grid, Color처럼 **모듈별로 따로 버전을 매기고 따로 발전한다.**
그래서 "CSS 몇 버전을 배워야 하나요?"라는 질문은 성립하지 않는다.
</Callout>

이 시리즈는 **지금 쓸 수 있는 최신 CSS**를 기준으로 쓴다.
새 기능마다 브라우저 지원 현황을 함께 표기하니 실무에 바로 쓸지 판단할 수 있다.

<Callout type="default">
**Baseline이란?**

주요 브라우저(Chrome · Edge · Firefox · Safari)에서 그 기능을 언제부터 쓸 수 있게 됐는지 알려주는 지표다.

- **Widely available** — 30개월 이상 지나 안정적. 마음 놓고 써도 된다
- **Newly available** — 방금 전 브라우저에 들어옴. 구형 기기는 확인 필요
- **Limited** — 일부 브라우저만. 폴백 필수
</Callout>

## 정리

<Callout type="default">
- CSS는 HTML 문서에 **모양과 배치**를 입히는 언어다
- 구조(HTML) · 표현(CSS) · 동작(JS)을 나누면 **고칠 때 한 곳만 고치면 된다**
- 문법은 `선택자 { 속성: 값; }` 이 전부다
- 브라우저는 **DOM + CSSOM → 렌더 트리 → 레이아웃 → 페인트** 순으로 그린다
- CSS는 렌더링을 막으므로 **크기와 위치가 성능에 직결**된다
- 여러 규칙이 충돌하면 **캐스케이드**가 승자를 정한다. `!important`가 아니라 원리를 이해해야 한다
- CSS3 이후 버전 번호는 없다. **모듈별로 발전**하며 지금도 커지고 있다
</Callout>

다음 편에서는 CSS 문법을 자세히 보고, HTML에 연결하는 세 가지 방법을 비교한다.
