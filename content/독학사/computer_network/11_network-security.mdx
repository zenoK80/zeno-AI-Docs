## 암호화의 기본 개념

**암호화(Encryption)**는 평문(Plaintext)을 암호문(Ciphertext)으로 변환하여 무단 접근을 방지하는 기술입니다.

- **암호화 키(Encryption Key):** 평문을 암호문으로 변환하는 데 사용
- **복호화 키(Decryption Key):** 암호문을 평문으로 복원하는 데 사용

## 대칭키 암호화 vs 공개키 암호화

| 특성 | 대칭키(비밀키) 암호화 | 공개키(비대칭키) 암호화 |
|------|---------------------|----------------------|
| 키 관계 | 암호화 키 = 복호화 키 | 암호화 키 ≠ 복호화 키 |
| 대표 알고리즘 | DES, 3DES, AES | RSA, ECC |
| 속도 | 빠름 | 느림 |
| 키 배포 | 어려움 (사전 공유 필요) | 쉬움 (공개키 공개 가능) |
| 용도 | 대량 데이터 암호화 | 키 교환, 디지털 서명 |

<Callout type="warning">
  시험에서 "암호화 키와 복호화 키가 서로 같은" 방식은 **대칭키(비밀키) 암호화**이며 DES가 대표적입니다. "키가 서로 다른" 방식은 **공개키(비대칭키) 암호화**이며 RSA가 대표적입니다.
</Callout>

## 디지털 서명과 인증서

**디지털 서명:** 송신자가 개인키로 메시지를 서명하고, 수신자가 공개키로 서명을 검증합니다. 무결성과 부인 방지를 제공합니다.

**디지털 인증서(공인인증서):** CA(인증 기관)가 공개키의 소유자를 보증하는 전자 문서입니다. X.509 표준을 사용합니다.

## SSL/TLS

**SSL(Secure Sockets Layer)/TLS(Transport Layer Security)**는 인터넷 통신을 암호화하는 프로토콜입니다. HTTPS는 HTTP 위에 TLS를 적용한 것입니다.

### TLS Handshake 과정

1. **ClientHello:** 클라이언트가 지원하는 암호화 방식 목록 전송
2. **ServerHello:** 서버가 암호화 방식 선택 + 인증서 전송
3. **인증서 검증:** 클라이언트가 CA 서명을 확인
4. **키 교환:** 공개키 암호화로 세션 키를 안전하게 공유
5. **대칭키 암호화 통신 시작:** 공유된 세션 키로 빠르게 통신

## VPN (Virtual Private Network)

**VPN**은 공용 인터넷을 통해 사설 네트워크처럼 안전하게 통신하는 기술입니다.

- **터널링(Tunneling):** 데이터를 캡슐화하여 암호화된 터널로 전송
- **주요 프로토콜:** IPSec, SSL/TLS VPN, OpenVPN
- **용도:** 원격 근무, 지사 연결, 프라이버시 보호

## 방화벽 (Firewall)

**방화벽**은 네트워크 트래픽을 필터링하여 허가되지 않은 접근을 차단하는 보안 장치입니다.

| 유형 | 특징 |
|------|------|
| **패킷 필터링** | IP 주소, 포트, 프로토콜 기반 필터링 (3, 4계층) |
| **상태 기반(Stateful)** | 연결 상태를 추적하여 필터링 |
| **응용 계층 방화벽(WAF)** | HTTP 트래픽을 분석하여 애플리케이션 공격 차단 |

## 주요 네트워크 공격 유형

| 공격 | 설명 |
|------|------|
| **DoS/DDoS** | 대량 트래픽으로 서비스 마비 |
| **스니핑(Sniffing)** | 네트워크 트래픽 도청 |
| **스푸핑(Spoofing)** | IP/MAC 주소 위조 |
| **중간자 공격(MITM)** | 통신 중간에서 도청/변조 |
| **피싱(Phishing)** | 사용자를 속여 정보 탈취 |

## 핵심 정리

- 대칭키: 같은 키로 암호화·복호화 (DES, AES), 빠름
- 공개키: 다른 키 쌍 (RSA), 키 배포 용이, 느림
- SSL/TLS: 핸드셰이크로 세션 키 공유 후 대칭키 통신
- VPN: 공용망에서 사설 네트워크 구성, 터널링
- 방화벽: 패킷 필터링으로 허가되지 않은 트래픽 차단
