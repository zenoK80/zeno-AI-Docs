## 전송 계층의 역할

**전송 계층**(Transport Layer)은 종단 간(End-to-End) 데이터 전달을 담당합니다.

- **포트 번호:** 동일 호스트 내 여러 프로세스를 식별 (0~65535)
- **분할과 재조합:** 큰 데이터를 세그먼트로 분할하고, 수신 측에서 재조합
- **흐름 제어:** 수신 측 처리 능력에 맞게 전송 속도 조절
- **오류 제어:** 손실·손상된 세그먼트 재전송

## TCP vs UDP 비교

| 특성 | TCP | UDP |
|------|-----|-----|
| 연결 방식 | 연결 지향형 | 비연결형 |
| 신뢰성 | 보장 (재전송) | 미보장 |
| 순서 보장 | 있음 | 없음 |
| 흐름 제어 | 있음 (윈도우) | 없음 |
| 혼잡 제어 | 있음 | 없음 |
| 헤더 크기 | 20바이트 이상 | 8바이트 |
| 전송 속도 | 느림 | 빠름 |
| 사용 예 | HTTP, FTP, SMTP | DNS, DHCP, 스트리밍, VoIP |

## TCP 3-way Handshake (연결 수립)

TCP 연결을 수립하는 과정입니다.

```
클라이언트                    서버
    |   --- SYN (seq=x) --->  |   1단계: 클라이언트가 연결 요청
    |   <-- SYN+ACK --------  |   2단계: 서버가 요청 수락 + 자신의 SYN
    |   --- ACK ----------->  |   3단계: 클라이언트가 확인 응답
    |   [연결 수립 완료]       |
```

**TCP 4-way Handshake (연결 해제):**

```
클라이언트                    서버
    |   --- FIN ----------->  |   1단계: 클라이언트 연결 종료 요청
    |   <-- ACK ------------  |   2단계: 서버 확인
    |   <-- FIN ------------  |   3단계: 서버 연결 종료 요청
    |   --- ACK ----------->  |   4단계: 클라이언트 확인
```

## 흐름 제어 (Flow Control)

수신 측의 버퍼 오버플로를 방지하기 위해 송신 속도를 조절합니다.

**슬라이딩 윈도우(Sliding Window):** 수신 측이 Window Size를 송신 측에 알리면, 송신 측은 ACK를 받지 않고도 그 크기만큼 연속 전송할 수 있습니다. ACK를 받으면 윈도우가 앞으로 이동(slide)합니다.

```
윈도우 크기 = 4
[1][2][3][4] [5][6][7][8]
 └── 전송 가능 ──┘  대기 중
ACK 1 수신 후:
   [2][3][4][5] [6][7][8][9]
    └── 전송 가능 ──┘
```

## 포트 번호 범위

| 범위 | 명칭 | 설명 |
|------|------|------|
| 0 ~ 1023 | Well-Known Port | 표준 프로토콜 전용 |
| 1024 ~ 49151 | Registered Port | 등록된 애플리케이션 |
| 49152 ~ 65535 | Dynamic/Private Port | 클라이언트 임시 포트 |

## 핵심 정리

- TCP: 연결 지향, 신뢰성·순서·흐름·혼잡 제어 제공
- UDP: 비연결형, 빠른 전송, 오버헤드 적음
- 3-way handshake: SYN → SYN+ACK → ACK
- 4-way handshake: FIN → ACK → FIN → ACK
- 슬라이딩 윈도우: ACK 없이 윈도우 크기만큼 연속 전송
