## 혼잡 제어 vs 흐름 제어

| 구분 | 목적 | 주체 |
|------|------|------|
| **흐름 제어(Flow Control)** | 수신 측 버퍼 오버플로 방지 | 송신자-수신자 간 |
| **혼잡 제어(Congestion Control)** | 네트워크 전체의 혼잡 방지 | 송신자-네트워크 간 |

## TCP 혼잡 제어 알고리즘

### Slow Start (느린 시작)

처음에는 혼잡 윈도우(cwnd)를 1 MSS로 시작하여, ACK를 받을 때마다 지수적으로 증가합니다. 임계값(ssthresh)에 도달하면 혼잡 회피 단계로 전환합니다.

```
cwnd: 1 → 2 → 4 → 8 → ... (지수 증가)
      ssthresh 도달 시 선형 증가로 전환
```

### Congestion Avoidance (혼잡 회피)

ssthresh에 도달한 후, ACK를 받을 때마다 cwnd를 1씩 증가(선형 증가)합니다.

### AIMD (Additive Increase Multiplicative Decrease)

- **선형 증가(AI):** 혼잡이 없으면 cwnd를 선형으로 증가
- **배감(MD):** 혼잡(패킷 손실) 감지 시 cwnd를 절반으로 감소

### Fast Retransmit / Fast Recovery

3개의 중복 ACK를 받으면 타임아웃을 기다리지 않고 즉시 재전송합니다. Fast Recovery에서는 ssthresh를 현재 cwnd의 절반으로 설정하고 ssthresh부터 재시작합니다.

## TCP 혼잡 제어 상태 전이

```
[Slow Start]
cwnd < ssthresh: 지수 증가
cwnd = ssthresh 도달 → [Congestion Avoidance]

[Congestion Avoidance]
타임아웃 발생: ssthresh = cwnd/2, cwnd = 1 → [Slow Start]
3 duplicate ACK: ssthresh = cwnd/2, cwnd = ssthresh → [Fast Recovery]
```

## 오류 제어

TCP는 다음 메커니즘으로 오류를 검출하고 복구합니다.

| 메커니즘 | 설명 |
|---------|------|
| **체크섬(Checksum)** | 헤더와 데이터의 오류 검출 |
| **확인 응답(ACK)** | 수신 확인, 순서 번호 기반 |
| **재전송(Retransmission)** | ACK 미수신 시 타임아웃 후 재전송 |
| **순서 번호(Sequence Number)** | 패킷 순서 추적 및 중복 검출 |

## 타임아웃과 RTT

TCP는 **RTT(Round-Trip Time)**를 측정하여 동적으로 타임아웃 값을 조정합니다.

$\text{Timeout} = \text{EstimatedRTT} + 4 \times \text{DevRTT}$

여기서 DevRTT는 RTT의 편차를 나타냅니다. 이 방식으로 네트워크 상태 변화에 유연하게 대응합니다.

## 핵심 정리

- 혼잡 제어: 네트워크 전체의 혼잡 방지 (흐름 제어와 구분)
- Slow Start: cwnd를 1부터 지수적으로 증가
- Congestion Avoidance: ssthresh 이후 선형 증가
- AIMD: 증가는 선형, 감소는 절반 (곱산 감소)
- Fast Retransmit: 3 duplicate ACK 시 즉시 재전송
