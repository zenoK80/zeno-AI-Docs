## 왜 IP 주소만으로는 부족한가?

09번 문서에서 배운 IP 주소는 네트워크 계층(3계층)의 주소이지만, 08번 문서에서 배운 것처럼 실제로 같은 네트워크 안에서 데이터를 주고받으려면 데이터 링크 계층(2계층)의 **MAC 주소**가 필요합니다. 이 두 주소 체계를 연결해주는 것이 ARP입니다.

## ARP(Address Resolution Protocol, 주소 결정 프로토콜)

> **쉽게 말하면:** ARP는 "이 IP 주소를 가진 장치의 MAC 주소가 무엇인가요?"라고 네트워크 전체에 물어보고 답을 얻는 프로토콜입니다.

**동작 과정:**

<Steps>
### 1단계: ARP 요청(브로드캐스트)
장치 A가 IP 주소 B를 가진 장치와 통신하고 싶지만 B의 MAC 주소를 모를 때, "IP 주소 B를 가진 사람, MAC 주소를 알려주세요"라는 요청을 같은 네트워크의 **모든** 장치에게 브로드캐스트로 보냅니다.

### 2단계: ARP 응답(유니캐스트)
자신의 IP 주소가 B인 장치만 "제 MAC 주소는 이것입니다"라고 A에게 직접(유니캐스트) 응답합니다.

### 3단계: ARP 캐시에 저장
장치 A는 이 결과를 ARP 캐시(임시 저장 표)에 저장해두어, 다음에 같은 B와 통신할 때는 다시 물어보지 않고 바로 사용합니다.
</Steps>

<Callout type="info">
  **왜 ARP 캐시가 중요한가?** 매번 통신할 때마다 ARP 요청을 브로드캐스트로 보내면 네트워크 전체에 불필요한 트래픽이 발생합니다. ARP 캐시는 한 번 알아낸 IP-MAC 대응 관계를 잠시 기억해두어 이런 낭비를 줄여줍니다(단, 일정 시간이 지나면 캐시는 만료되어 다시 요청해야 함).
</Callout>

## RARP(Reverse ARP, 역순 주소 결정 프로토콜)

> **쉽게 말하면:** RARP는 ARP와 정반대로, "제 MAC 주소는 이것인데, 제 IP 주소는 무엇인가요?"라고 물어보는 프로토콜입니다.

**용도:** 디스크가 없어 자신의 IP 주소를 저장해둘 수 없는 초기 장치들이, 부팅할 때 자신의 MAC 주소만 가지고 서버에 IP 주소를 물어보기 위해 사용되었습니다(오늘날에는 훨씬 발전된 DHCP가 이 역할을 대신함).

## ICMP(Internet Control Message Protocol, 인터넷 제어 메시지 프로토콜)

> **쉽게 말하면:** ICMP는 네트워크에서 발생한 문제(예: 목적지에 도달할 수 없음)를 알리거나, 네트워크 상태를 점검하는 데 사용되는 "메신저" 프로토콜입니다.

**대표 활용 사례 — ping 명령어:**

<Steps>
### 1단계: Echo Request 전송
`ping 목적지주소` 명령을 실행하면, ICMP Echo Request 메시지를 목적지로 보냅니다.

### 2단계: Echo Reply 수신
목적지가 정상적으로 동작 중이면 ICMP Echo Reply로 응답합니다.

### 3단계: 결과 확인
응답이 오면 "목적지가 살아있고 응답 시간이 얼마나 걸리는지"를 알 수 있고, 응답이 없으면 네트워크에 문제가 있음을 짐작할 수 있습니다.
</Steps>

<Callout type="info">
  **09번 문서와의 연결:** `traceroute`(경로 추적) 명령어도 ICMP를 활용합니다. 09번 문서에서 배운 TTL 필드를 1부터 하나씩 늘려가며 패킷을 보내, TTL이 0이 되어 폐기되는 지점(각 라우터)마다 돌아오는 ICMP 메시지를 이용해 경로 전체를 알아냅니다.
</Callout>

## IGMP(Internet Group Management Protocol, 인터넷 그룹 관리 프로토콜)

> **쉽게 말하면:** IGMP는 "같은 그룹에 속한 여러 호스트에게 동시에 메시지를 보내는" 멀티캐스트(Multicast) 통신을 관리하는 프로토콜입니다.

<Table>
  <thead>
    <tr><th>전송 방식</th><th>대상</th></tr>
  </thead>
  <tbody>
    <tr><td>유니캐스트(Unicast)</td><td>1대1(하나의 특정 목적지)</td></tr>
    <tr><td>브로드캐스트(Broadcast)</td><td>1대전체(네트워크의 모든 장치)</td></tr>
    <tr><td>멀티캐스트(Multicast)</td><td>1대그룹(가입한 특정 그룹의 장치들만)</td></tr>
  </tbody>
</Table>

**예시:** 인터넷 화상회의나 IPTV 방송에서, 신청한 사람들에게만 동일한 영상 스트림을 효율적으로 전달할 때 IGMP 기반의 멀티캐스트가 활용됩니다.

## NAT(Network Address Translation, 네트워크 주소 변환)

> **쉽게 말하면:** NAT는 09번 문서에서 배운 사설 IP 주소를, 인터넷과 통신할 수 있는 공인 IP 주소로 자동으로 바꿔주는 기능입니다.

**동작 원리:** 가정용 공유기(라우터)는 보통 하나의 공인 IP 주소만 인터넷 서비스 제공자로부터 할당받습니다. 집 안의 여러 기기(사설 IP)가 동시에 인터넷에 접속할 수 있는 것은, 라우터가 각 기기의 요청을 자신의 공인 IP 주소로 "대신 변환"해서 내보내고, 응답이 오면 다시 원래 기기로 정확히 돌려주기 때문입니다.

<Callout type="warning">
  **자주 틀리는 점:** NAT가 단순히 "주소를 숨기는" 기능이라고만 이해하면 부족합니다. NAT의 가장 실용적인 목적은 **한정된 공인 IP 주소 자원을 절약**하는 것입니다. 전 세계의 모든 기기가 저마다 고유한 공인 IPv4 주소를 가지기에는 주소 개수(약 43억 개)가 부족한데, NAT 덕분에 하나의 공인 IP로 여러 사설 기기가 함께 인터넷을 사용할 수 있습니다.
</Callout>

## 핵심 정리

- **ARP**: IP 주소로 MAC 주소를 알아내는 프로토콜(브로드캐스트 요청 → 유니캐스트 응답 → 캐시 저장).
- **RARP**: ARP의 반대(MAC→IP), 오늘날에는 DHCP가 대체.
- **ICMP**: 네트워크 상태 점검·오류 알림(ping, traceroute의 기반).
- **IGMP**: 멀티캐스트(그룹 전송) 관리.
- **NAT**: 사설 IP ↔ 공인 IP 변환. 한정된 공인 IP 자원을 절약하는 실용적 목적.
