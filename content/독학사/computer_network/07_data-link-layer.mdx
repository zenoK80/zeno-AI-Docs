## 데이터 링크 계층(Data Link Layer)의 역할

> **쉽게 말하면:** 데이터 링크 계층은 05번 문서의 OSI 2계층으로, 06번 문서에서 배운 "물리적인 신호"를 의미 있는 데이터 묶음(프레임)으로 조립하고, 같은 네트워크 안에서 오류 없이 다음 장치로 전달하는 역할을 담당합니다.

## 프레임(Frame) 구조

> **쉽게 말하면:** 프레임은 데이터 링크 계층이 다루는 데이터 단위로, 전송할 실제 데이터 앞뒤에 "봉투"(헤더·트레일러)를 붙인 형태입니다.

## 오류 검출(Error Detection) — CRC

> **쉽게 말하면:** 오류 검출은 "전송 중에 데이터가 잡음 등으로 훼손되지 않았는지"를 확인하는 방법입니다.

**CRC**(Cyclic Redundancy Check, 순환 중복 검사)**의 직관적 원리:**

<Steps>
### 1단계: 송신 측이 검사값 계산
전송할 데이터를 미리 약속된 수식(다항식 나눗셈)에 넣어 "나머지"에 해당하는 검사값을 계산합니다.

### 2단계: 검사값을 데이터에 붙여 전송
원본 데이터 뒤에 이 검사값(트레일러)을 붙여 함께 보냅니다.

### 3단계: 수신 측이 같은 계산을 반복
수신 측도 받은 데이터로 같은 계산을 수행해, 자신이 계산한 나머지와 전달받은 검사값이 일치하는지 비교합니다.

### 4단계: 판정
일치하면 "오류 없음"으로 간주하고, 불일치하면 "오류 발생"으로 판단해 재전송을 요청합니다.
</Steps>

<Callout type="warning">
  **자주 틀리는 점:** 오류 검출(Error Detection)과 오류 수정(Error Correction)을 같은 것으로 혼동하기 쉽습니다. CRC 같은 오류 검출 기법은 "오류가 있는지 없는지"만 알려줄 뿐, 그 오류를 스스로 고쳐주지는 못합니다. 오류를 검출하면 보통 재전송을 요청하는 방식(ARQ, 아래에서 다룸)으로 대응합니다. 반면 해밍 코드(Hamming Code) 같은 **오류 수정** 코드는 별도의 추가 정보를 이용해 수신 측이 스스로 오류를 고칠 수 있습니다.
</Callout>

## 흐름제어(Flow Control)

> **쉽게 말하면:** 흐름제어는 "송신 측이 수신 측의 처리 속도를 넘어서는 양의 데이터를 한꺼번에 쏟아부어, 수신 측이 감당하지 못하는 상황"을 막는 것입니다.

**비유:** 빠르게 말하는 사람과 천천히 받아 적는 사람이 대화할 때, 듣는 사람이 "잠깐, 천천히 말해주세요"라고 신호를 보내는 것과 같습니다. 흐름제어가 없으면 수신 측의 버퍼(임시 저장 공간)가 넘쳐 데이터가 유실될 수 있습니다.

## ARQ(Automatic Repeat reQuest, 자동 재전송 요청)

> **쉽게 말하면:** ARQ는 오류가 검출된 데이터를 자동으로 다시 보내달라고 요청하는 재전송 방식입니다.

### Stop-and-Wait ARQ

> **쉽게 말하면:** 프레임을 하나 보내고, 상대방의 확인 응답(ACK)을 받을 때까지 기다렸다가 다음 프레임을 보내는 가장 단순한 방식입니다.

**단점:** 매번 확인 응답을 기다려야 해서 전송 효율이 낮습니다.

### Go-Back-N ARQ

> **쉽게 말하면:** 여러 프레임을 확인 응답 없이 연속으로 보내다가, 특정 프레임에서 오류가 발생하면 **그 오류가 난 프레임부터 이후 모든 프레임을** 다시 전송하는 방식입니다.

**예시:** 프레임 1, 2, 3, 4, 5를 연속으로 보냈는데 3번 프레임에서 오류가 발생하면, 3, 4, 5번을 모두 다시 보냅니다(이미 정상적으로 도착한 4, 5번도 다시 보내야 하는 비효율이 있음).

### Selective-Repeat ARQ

> **쉽게 말하면:** Go-Back-N과 달리, 오류가 발생한 **그 프레임만** 선택적으로 다시 전송하는 더 효율적인 방식입니다.

**예시:** 3번 프레임에서만 오류가 발생했다면, 3번만 재전송하고 이미 잘 도착한 4, 5번은 그대로 둡니다(수신 측이 순서가 뒤섞인 프레임들을 임시로 저장해뒀다가 재조립해야 하므로 더 복잡한 구현이 필요함).

<Table>
  <thead>
    <tr><th>방식</th><th>재전송 범위</th><th>효율</th><th>구현 복잡도</th></tr>
  </thead>
  <tbody>
    <tr><td>Stop-and-Wait</td><td>-(한 번에 하나씩만 전송)</td><td>낮음</td><td>매우 단순</td></tr>
    <tr><td>Go-Back-N</td><td>오류 프레임 이후 전체</td><td>중간</td><td>단순</td></tr>
    <tr><td>Selective-Repeat</td><td>오류 프레임만</td><td>높음</td><td>복잡(수신 버퍼 필요)</td></tr>
  </tbody>
</Table>

## 핵심 정리

- **데이터 링크 계층**: 물리 신호를 프레임으로 조립하고, 같은 네트워크 내에서 오류 없이 전달.
- **오류 검출**(CRC 등, 오류 유무만 판별)과 **오류 수정**(해밍 코드 등, 스스로 고침)은 다른 개념.
- **흐름제어**: 송신 측이 수신 측의 처리 속도를 넘지 않도록 조절.
- **ARQ 방식**: Stop-and-Wait(단순, 저효율), Go-Back-N(오류 이후 전체 재전송), Selective-Repeat(오류 프레임만 재전송, 고효율·복잡).
