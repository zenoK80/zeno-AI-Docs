## 네트워크 계층(Network Layer)의 역할

> **쉽게 말하면:** 네트워크 계층은 05번 문서의 OSI 3계층으로, 서로 다른 네트워크에 있는 두 장치 사이의 **최적 경로**를 찾아 데이터를 전달하는 역할을 담당합니다. 이때 사용하는 주소가 바로 IP 주소입니다.

## IP 주소(IP Address)의 구조

> **쉽게 말하면:** 01번 문서에서 배운 것처럼, IPv4 주소는 32비트를 8비트씩(옥텟) 4묶음으로 나눠 10진수로 표기합니다. 이 32비트는 다시 "네트워크 부분"과 "호스트 부분"으로 나뉩니다.

**예시:** `192.168.1.10`이라는 주소에서, 앞부분(`192.168.1`)은 "어느 네트워크에 속하는지"를, 뒷부분(`10`)은 "그 네트워크 안의 몇 번째 장치인지"를 나타냅니다.

## IP 주소 클래스(Class) 체계

> **쉽게 말하면:** 클래스는 IP 주소의 첫 부분을 보고, 네트워크 부분과 호스트 부분의 경계를 미리 정해둔 전통적인 분류 방식입니다.

<Table>
  <thead>
    <tr><th>클래스</th><th>첫 옥텟 범위</th><th>네트워크:호스트 비트</th><th>용도</th></tr>
  </thead>
  <tbody>
    <tr><td>A</td><td>1–126</td><td>8:24(적은 네트워크, 각 네트워크에 매우 많은 호스트)</td><td>대규모 기관</td></tr>
    <tr><td>B</td><td>128–191</td><td>16:16</td><td>중간 규모 기관</td></tr>
    <tr><td>C</td><td>192–223</td><td>24:8(많은 네트워크, 각 네트워크에 적은 호스트)</td><td>소규모 네트워크(가정·소기업)</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **왜 사설 IP 대역이 정해져 있는가?** `192.168.x.x`(C클래스), `10.x.x.x`(A클래스), `172.16.x.x~172.31.x.x`(B클래스)는 인터넷에서 직접 사용하지 않기로 약속된 **사설 IP 대역**입니다. 가정용 공유기 뒤의 각 기기들은 보통 이런 사설 IP를 사용하며, 실제 인터넷(공인 IP)과 통신할 때는 라우터가 주소를 변환(NAT, 10번 문서에서 다룸)해줍니다.
</Callout>

## 서브넷 마스크(Subnet Mask)

> **쉽게 말하면:** 서브넷 마스크는 IP 주소에서 "여기까지는 네트워크 부분, 여기부터는 호스트 부분"이라는 경계를 표시해주는 또 다른 32비트 숫자입니다.

**표기 예시:** `255.255.255.0`은 이진수로 `11111111.11111111.11111111.00000000`이며, 1로 채워진 앞 24비트가 네트워크 부분, 0으로 채워진 뒤 8비트가 호스트 부분임을 나타냅니다.

## CIDR(Classless Inter-Domain Routing) 표기법

> **쉽게 말하면:** CIDR은 서브넷 마스크를 매번 길게 적는 대신, "네트워크 부분이 몇 비트인지"를 슬래시(`/`) 뒤에 숫자로 간단히 표기하는 방법입니다.

**예시:** `192.168.1.0/24`는 "네트워크 부분이 24비트"라는 뜻이며, 서브넷 마스크 `255.255.255.0`과 정확히 같은 의미입니다.

## 서브넷팅(Subnetting) — 네트워크를 잘게 나누기

> **쉽게 말하면:** 서브넷팅은 하나의 큰 네트워크를, 호스트 부분의 비트 일부를 "빌려와" 네트워크 부분으로 바꿔서 여러 개의 작은 네트워크로 쪼개는 작업입니다.

**계산 예시:** `192.168.1.0/24`(호스트 256개 가능)를 4개의 작은 네트워크로 나눕니다.

<Steps>
### 1단계: 필요한 서브넷 개수 확인
4개로 나눠야 하므로, $2^n \ge 4$를 만족하는 최소 $n=2$비트를 호스트 부분에서 빌려옵니다.

### 2단계: 새 서브넷 마스크 결정
기존 /24에서 2비트를 더 빌리면 /26($24+2=26$)이 됩니다. 서브넷 마스크는 `255.255.255.192`가 됩니다.

### 3단계: 각 서브넷의 범위 계산
남은 호스트 비트는 $8-2=6$비트이므로, 서브넷 하나당 $2^6=64$개의 주소를 가집니다.
</Steps>

<Table>
  <thead>
    <tr><th>서브넷</th><th>네트워크 주소</th><th>사용 가능 호스트 범위</th></tr>
  </thead>
  <tbody>
    <tr><td>1번째</td><td>192.168.1.0/26</td><td>192.168.1.1 – 192.168.1.62</td></tr>
    <tr><td>2번째</td><td>192.168.1.64/26</td><td>192.168.1.65 – 192.168.1.126</td></tr>
    <tr><td>3번째</td><td>192.168.1.128/26</td><td>192.168.1.129 – 192.168.1.190</td></tr>
    <tr><td>4번째</td><td>192.168.1.192/26</td><td>192.168.1.193 – 192.168.1.254</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** 각 서브넷에서 첫 번째 주소(예: `192.168.1.0`)는 "네트워크 주소"(그 네트워크 자체를 가리키는 예약된 주소), 마지막 주소(예: `192.168.1.63`)는 "브로드캐스트 주소"(그 네트워크의 모든 호스트에게 동시에 보내는 예약된 주소)로 예약되어 있어, 실제 호스트에는 할당할 수 없습니다. 그래서 $2^6=64$개 중 실제 사용 가능한 호스트는 $64-2=62$개입니다.
</Callout>

## 핵심 정리

- **IP 주소**: 네트워크 부분+호스트 부분으로 구성. 클래스 A(대규모)·B(중간)·C(소규모).
- **서브넷 마스크**·**CIDR 표기**(`/24` 등): 네트워크·호스트 부분의 경계를 표시.
- **서브넷팅**: 호스트 비트를 빌려와 네트워크를 여러 개로 분할. 각 서브넷은 네트워크 주소·브로드캐스트 주소를 제외한 나머지만 실제 호스트에 할당 가능.
- **IP 패킷**: 출발지·목적지 주소, TTL(무한 루프 방지), 프로토콜 필드 등을 포함.
