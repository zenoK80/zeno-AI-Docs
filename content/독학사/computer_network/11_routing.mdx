## 라우팅(Routing)이란?

> **쉽게 말하면:** 라우팅은 02번 문서에서 배운 라우터가, 09번 문서에서 배운 IP 패킷을 목적지까지 보내기 위해 "다음에 어느 라우터로 넘겨줄지"를 결정하는 과정입니다.

**비유:** 내비게이션이 목적지까지 가는 여러 경로 중 최적의 길을 찾아주듯, 라우터도 패킷마다 "이 목적지로 가려면 어느 방향(다음 라우터)으로 보내야 하는지"를 판단합니다.

## 라우팅 테이블(Routing Table)

> **쉽게 말하면:** 라우팅 테이블은 라우터가 가지고 있는 "이 목적지 네트워크로 가려면 이쪽으로 보내라"는 규칙들이 정리된 표입니다.

<Table>
  <thead>
    <tr><th>목적지 네트워크</th><th>다음 홉(Next Hop)</th><th>인터페이스</th></tr>
  </thead>
  <tbody>
    <tr><td>192.168.1.0/24</td><td>직접 연결됨</td><td>eth0</td></tr>
    <tr><td>10.0.0.0/8</td><td>192.168.1.254</td><td>eth0</td></tr>
    <tr><td>0.0.0.0/0(기본 경로)</td><td>203.0.113.1</td><td>eth1</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **기본 경로**(Default Route)**란?** `0.0.0.0/0`은 "테이블의 다른 어떤 항목과도 일치하지 않는 목적지"를 처리하는 특수한 규칙입니다. 마치 "이 목록에 없는 곳은 일단 이 방향으로 보내라"는 안전망과 같으며, 보통 인터넷으로 나가는 방향을 가리킵니다.
</Callout>

## 정적 라우팅(Static Routing)과 동적 라우팅(Dynamic Routing)

<Table>
  <thead>
    <tr><th>구분</th><th>정의</th><th>장단점</th></tr>
  </thead>
  <tbody>
    <tr><td>정적 라우팅</td><td>관리자가 라우팅 테이블을 직접 수동으로 설정</td><td>단순한 소규모 네트워크에 적합. 네트워크 구조가 바뀌면 수동으로 다시 설정해야 함</td></tr>
    <tr><td>동적 라우팅</td><td>라우터들이 서로 정보를 주고받아 자동으로 최적 경로를 계산·갱신</td><td>대규모·복잡한 네트워크에 적합. 네트워크 장애 시 자동으로 우회 경로를 찾음</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** 동적 라우팅이 항상 정적 라우팅보다 "무조건 더 좋다"고 오해하기 쉽습니다. 실제로는 라우터가 계속 다른 라우터들과 정보를 주고받아야 하므로 추가적인 네트워크 자원과 라우터의 처리 능력이 필요합니다. 라우터가 몇 대 안 되는 단순한 소규모 네트워크에서는 오히려 정적 라우팅이 더 간단하고 안정적일 수 있습니다.
</Callout>

## 동적 라우팅 프로토콜 — RIP, OSPF, BGP

> **쉽게 말하면:** 동적 라우팅 프로토콜은 라우터들이 "최적 경로가 무엇인지" 서로 대화하는 데 사용하는 공통 언어(03번 문서의 프로토콜 개념)입니다.

<Table>
  <thead>
    <tr><th>프로토콜</th><th>경로 결정 기준</th><th>사용 범위</th><th>특징</th></tr>
  </thead>
  <tbody>
    <tr><td>RIP(Routing Information Protocol)</td><td>홉 수(경유하는 라우터 개수)</td><td>소규모 네트워크</td><td>가장 단순하지만, 최대 홉 수(15) 제한이 있어 대규모 네트워크에는 부적합</td></tr>
    <tr><td>OSPF(Open Shortest Path First)</td><td>회선 속도 등을 고려한 비용(Cost)</td><td>중–대규모 단일 조직 네트워크</td><td>RIP보다 정교하고 빠르게 최적 경로를 재계산. 대규모 기업망에서 널리 사용</td></tr>
    <tr><td>BGP(Border Gateway Protocol)</td><td>정책 기반 경로 선택(단순 최단 경로가 아님)</td><td>인터넷 전체(서로 다른 조직 간)</td><td>전 세계 인터넷을 연결하는 핵심 프로토콜. ISP(인터넷 서비스 제공자)들 사이에서 사용</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **RIP와 OSPF의 근본적 차이:** RIP는 "몇 개의 라우터를 거치는지"(홉 수)만 단순하게 세지만, OSPF는 각 구간의 실제 속도·상태를 반영한 비용을 계산합니다. 예를 들어 홉 수는 2개로 적지만 매우 느린 회선을 거치는 경로보다, 홉 수는 3개로 많아도 빠른 회선을 거치는 경로가 실제로는 더 빠를 수 있는데, RIP는 이런 차이를 구분하지 못하고 무조건 홉 수가 적은 경로(느린 경로)를 선택하는 한계가 있습니다.
</Callout>

## RIP와 OSPF의 사용 범위 — AS(Autonomous System) 개념

> **쉽게 말하면:** AS(자율 시스템)는 하나의 조직이 관리하는 네트워크 전체의 묶음입니다.

<Table>
  <thead>
    <tr><th>구분</th><th>사용 위치</th></tr>
  </thead>
  <tbody>
    <tr><td>IGP(Interior Gateway Protocol, 내부 게이트웨이 프로토콜)</td><td>하나의 AS(조직) 내부에서 사용. RIP, OSPF가 여기 속함</td></tr>
    <tr><td>EGP(Exterior Gateway Protocol, 외부 게이트웨이 프로토콜)</td><td>서로 다른 AS(조직) 사이에서 사용. BGP가 대표적</td></tr>
  </tbody>
</Table>

**비유:** 한 회사 안에서 부서끼리 업무를 조율하는 것(IGP, 회사 내부 규칙)과, 서로 다른 회사끼리 계약을 맺는 것(EGP, 대외 협상 규칙)은 성격이 다른 것처럼, 네트워크 내부 경로 결정과 인터넷 전체의 경로 결정도 서로 다른 종류의 프로토콜을 사용합니다.

## 핵심 정리

- **라우팅**: 라우터가 라우팅 테이블을 참고해 패킷의 다음 경로(다음 홉)를 결정하는 과정.
- **정적 라우팅**(수동 설정, 소규모에 적합) vs. **동적 라우팅**(자동 갱신, 대규모·장애 대응에 유리).
- **RIP**(홉 수 기준, 단순, 소규모), **OSPF**(비용 기준, 정교함, 중~대규모 내부망), **BGP**(정책 기반, 인터넷 전체 연결).
- **IGP**(조직 내부, RIP·OSPF)와 **EGP**(조직 간, BGP)는 적용 범위가 다르다.
