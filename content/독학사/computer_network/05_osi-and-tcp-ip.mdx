## OSI 참조모델(OSI Reference Model)

**단어 풀이:**

| 단어 | 뜻 |
|------|-----|
| Open | 개방된, 공개된 |
| Systems | 시스템들 |
| Interconnection | 상호 연결 |

> **쉽게 말하면:** OSI는 03번 문서에서 배운 "왜 계층으로 나누는가"라는 원칙을, ISO(국제표준화기구)가 정확히 7개의 계층으로 구체화해 만든 표준 설계도입니다.

## OSI 7계층 — 아래에서 위로

> **쉽게 말하면:** 각 계층은 "물리적인 전기 신호"에서 시작해 점점 "사람이 이해하는 의미"에 가까워지는 방향으로 쌓여 있습니다.

<Table>
  <thead>
    <tr><th>계층</th><th>이름</th><th>핵심 역할</th></tr>
  </thead>
  <tbody>
    <tr><td>1</td><td>물리 계층(Physical Layer)</td><td>비트(0/1)를 실제 전기 신호·광 신호·전파로 변환해 전송(06번 문서)</td></tr>
    <tr><td>2</td><td>데이터 링크 계층(Data Link Layer)</td><td>같은 네트워크 내에서 프레임 단위로 전송, 오류 검출, MAC 주소 사용(07번 문서)</td></tr>
    <tr><td>3</td><td>네트워크 계층(Network Layer)</td><td>서로 다른 네트워크 사이의 경로 설정(라우팅), IP 주소 사용(09–11번 문서)</td></tr>
    <tr><td>4</td><td>전송 계층(Transport Layer)</td><td>출발지-목적지 간 신뢰성 있는 데이터 전달, 포트 번호 사용(12번 문서)</td></tr>
    <tr><td>5</td><td>세션 계층(Session Layer)</td><td>통신 연결(세션)의 시작·유지·종료 관리</td></tr>
    <tr><td>6</td><td>표현 계층(Presentation Layer)</td><td>데이터의 형식 변환, 암호화·압축</td></tr>
    <tr><td>7</td><td>응용 계층(Application Layer)</td><td>사용자가 실제로 사용하는 프로그램에 서비스 제공(13번 문서)</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **암기 팁:** "물다네전세표응"(물리-데이터링크-네트워크-전송-세션-표현-응용)처럼 앞글자를 따서 순서를 암기하는 방법이 흔히 쓰입니다. 시험에서는 계층의 순서를 정확히 아는 것이 특히 중요합니다.
</Callout>

## 각 계층이 주고받는 데이터 단위(PDU)

> **쉽게 말하면:** 같은 "데이터"라도 어느 계층에서 다루는지에 따라 부르는 이름(PDU, Protocol Data Unit)이 다릅니다.

<Table>
  <thead>
    <tr><th>계층</th><th>데이터 단위</th></tr>
  </thead>
  <tbody>
    <tr><td>전송 계층</td><td>세그먼트(Segment, TCP) / 데이터그램(Datagram, UDP)</td></tr>
    <tr><td>네트워크 계층</td><td>패킷(Packet)</td></tr>
    <tr><td>데이터 링크 계층</td><td>프레임(Frame)</td></tr>
    <tr><td>물리 계층</td><td>비트(Bit)</td></tr>
  </tbody>
</Table>

**계산 예시**(캡슐화, Encapsulation): 응용 계층에서 만들어진 데이터가 전송되는 과정을 생각해봅시다. 전송 계층은 여기에 포트 번호 등을 담은 "헤더"를 앞에 붙여 세그먼트로 만들고, 네트워크 계층은 다시 IP 주소 헤더를 붙여 패킷으로, 데이터 링크 계층은 MAC 주소 헤더를 붙여 프레임으로 만듭니다. 마치 러시아 인형(마트료시카)처럼 데이터가 각 계층의 헤더로 겹겹이 포장되는 이 과정을 **캡슐화**라고 합니다.

## TCP/IP 참조모델

> **쉽게 말하면:** TCP/IP 모델은 OSI보다 먼저 실제 인터넷에서 사용되던 프로토콜(IETF 표준, 03번 문서 참고)을 기반으로 만들어진, 더 단순한 4계층(또는 5계층으로 세분화하기도 함) 모델입니다.

<Table>
  <thead>
    <tr><th>TCP/IP 계층</th><th>대응하는 OSI 계층</th></tr>
  </thead>
  <tbody>
    <tr><td>응용 계층</td><td>OSI 5(세션)+6(표현)+7(응용) 계층을 하나로 통합</td></tr>
    <tr><td>전송 계층</td><td>OSI 4(전송) 계층과 동일</td></tr>
    <tr><td>인터넷 계층</td><td>OSI 3(네트워크) 계층과 동일</td></tr>
    <tr><td>네트워크 접근 계층</td><td>OSI 1(물리)+2(데이터 링크) 계층을 하나로 통합</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** OSI 모델과 TCP/IP 모델을 "서로 다른 두 개의 실제 시스템"이라고 오해하기 쉽습니다. 실제로 우리가 매일 사용하는 인터넷은 **TCP/IP 모델을 기반으로 동작**하며, OSI 7계층은 주로 통신을 이해하고 설계할 때 참고하는 **개념적인 참조모델**로 널리 쓰입니다. 즉 OSI는 "이론적 설계도", TCP/IP는 "실제 구현체"에 더 가깝습니다.
</Callout>

## 왜 두 모델을 모두 알아야 하는가?

> **쉽게 말하면:** OSI 7계층은 각 기능을 세분화해서 설명하기 좋아 **학습·문제 진단**에 유리하고, TCP/IP 4계층은 실제 **인터넷 프로토콜 구조**와 정확히 일치해 실무에 유리합니다.

**예시:** "웹사이트가 안 열려요"라는 문제가 생겼을 때, OSI 관점에서 "물리 계층(케이블은 꽂혀 있나?) → 데이터 링크 계층(스위치는 정상인가?) → 네트워크 계층(IP는 할당됐나?) → ... → 응용 계층(DNS는 정상인가?)" 순서로 하나씩 점검하는 것이 실제 네트워크 문제 해결(트러블슈팅)의 표준적인 접근 방식입니다.

## 핵심 정리

- **OSI 7계층**: 물리 → 데이터 링크 → 네트워크 → 전송 → 세션 → 표현 → 응용. 순서 암기가 중요.
- **캡슐화**: 상위 계층의 데이터에 각 계층의 헤더가 순서대로 덧붙여지는 과정. 세그먼트 → 패킷 → 프레임 → 비트.
- **TCP/IP 4계층**: 응용(OSI 5~7 통합), 전송(OSI 4), 인터넷(OSI 3), 네트워크 접근(OSI 1~2 통합).
- OSI는 개념적 참조모델, TCP/IP는 실제 인터넷에서 동작하는 구현 모델.
