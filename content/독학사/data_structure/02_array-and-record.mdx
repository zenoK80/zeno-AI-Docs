## 왜 배열이 필요한가?

학생 100명의 시험 점수를 저장한다고 상상해 보세요. 변수를 하나씩 만들면 `score1`, `score2`, ..., `score100`처럼 100개의 변수가 필요합니다. 이건 너무 번거롭죠.

이럴 때 **배열**(Array, 어레이)을 사용합니다. 배열은 같은 종류의 데이터를 한 줄로 줄 세워 번호(인덱스)로 관리하는 방법입니다.

생활 비유: 아파트를 떠올려 보세요. 같은 건물에 101호, 102호, 103호처럼 번호가 붙어 있고, 모두 같은 구조(같은 자료형)입니다. 배열이 바로 그런 구조입니다.

## 배열의 개념

**배열**(Array)은 같은 자료형의 데이터를 연속된 메모리 공간에 순서대로 저장하는 선형 자료구조입니다.

핵심 특징:
- **인덱스**(Index, 인덱스): 각 원소의 번호. 보통 0부터 시작합니다.
- **임의 접근**(Random Access, 랜덤 액세스): 인덱스만 알면 어디든 즉시 접근 가능합니다.

쉽게 말하면: 인덱스로 직접 찾아가므로, 찾는 속도가 항상 일정합니다.

| 연산 | 시간 복잡도 | 설명 |
| --- | --- | --- |
| 접근(읽기) | $O(1)$ | 인덱스로 직접 접근 |
| 삽입/삭제 | $O(n)$ | 뒤의 원소들을 모두 이동해야 함 |
| 탐색 | $O(n)$ | 처음부터 끝까지 확인 |

삽입/삭제가 느린 이유: 중간에 새 원소를 끼워 넣으면, 뒤에 있는 원소들을 모두 한 칸씩 밀어야 합니다. 극장 좌석에서 중간에 앉은 사람이 비켜 줘야 하는 것과 같습니다.

## 1차원 배열의 주소 계산

컴퓨터 메모리는 집의 주소처럼 번호가 붙어 있습니다. 배열의 첫 번째 원소가 어느 주소에 있는지 알면, 나머지 원소들의 주소도 계산할 수 있습니다.

1차원 배열 A에서:
- 시작 주소(첫 번째 원소의 주소): $\alpha$ (알파)
- 각 원소의 크기: $d$ 바이트(byte)
- $A[i]$의 주소를 구하는 공식:

$$\text{addr}(A[i]) = \alpha + i \times d$$

**예시:** 시작 주소 100, 원소 크기 4바이트인 배열에서 `A[3]`의 주소는?

$$100 + 3 \times 4 = 112$$

## 2차원 배열의 주소 계산

2차원 배열은 표처럼 행(row, 가로줄)과 열(column, 세로줄)로 구성됩니다. 하지만 컴퓨터 메모리는 1차원(일렬)이므로, 2차원 배열을 1차원으로 펼쳐서 저장합니다.

펼치는 방법에 따라 두 가지 방식이 있습니다.

**행 우선(Row-major order):** 행 단위로 차례로 저장 (C 언어 방식)

$$\text{addr}(A[i][j]) = \alpha + (i \times n + j) \times d$$

여기서 $n$은 열(column)의 수입니다.

**열 우선(Column-major order):** 열 단위로 차례로 저장 (Fortran 언어 방식)

$$\text{addr}(A[i][j]) = \alpha + (j \times m + i) \times d$$

여기서 $m$은 행(row)의 수입니다.

**예시 (행 우선):** 3행 4열 배열, 시작 주소 100, 원소 크기 2바이트에서 `A[1][2]`의 주소는?

$$100 + (1 \times 4 + 2) \times 2 = 100 + 6 \times 2 = 112$$

## 레코드

### 배열과 레코드의 차이

- **배열**: 같은 자료형만 저장 (예: 점수 배열은 숫자만)
- **레코드**(Record, 레코드): 다른 자료형을 묶어서 저장 (예: 이름(문자) + 나이(숫자) + 점수(숫자))

쉽게 말하면: 레코드는 여러 종류의 정보를 하나로 묶는 "명함"같은 것입니다.

C 언어의 `struct`(구조체), Java/Python의 클래스가 레코드에 해당합니다.

```
학생 레코드 예시:
- 이름: "홍길동" (문자열)
- 나이: 20 (정수)
- 점수: 95.5 (실수)
```

## 희소행렬

### 왜 희소행렬을 특별히 처리하는가?

100×100 행렬(10,000개 칸)에서 실제로 값이 있는 칸이 10개뿐이라면? 나머지 9,990개는 모두 0입니다. 이 0들을 메모리에 저장하는 건 낭비입니다.

이처럼 **대부분의 원소가 0인 행렬**을 **희소행렬**(Sparse Matrix, 스파스 매트릭스)이라고 합니다.

쉽게 말하면: 희소행렬 = 0이 대부분인 행렬 → 0이 아닌 것만 따로 저장하자!

**저장 방법:** 0이 아닌 원소만 `(행, 열, 값)` 형태로 저장합니다.

예) 4×5 행렬에서 값이 있는 원소만 저장:

| 행(row) | 열(col) | 값(value) |
| --- | --- | --- |
| 0 | 2 | 5 |
| 1 | 4 | 3 |
| 3 | 0 | 7 |

원래 20칸 → 3개 레코드만 저장! 메모리 절약이 큽니다.

## 전치행렬

**전치행렬**(Transpose Matrix, 트랜스포즈 매트릭스)은 행과 열을 서로 바꾼 행렬입니다.

원래 행렬 A에서 $A[i][j]$에 있던 값이 전치행렬 $A^T$에서는 $A^T[j][i]$로 이동합니다.

예시:
```
원래 행렬 A (2×3):    전치행렬 A^T (3×2):
1  2  3               1  4
4  5  6               2  5
                      3  6
```

## 핵심 정리

- **배열**: 같은 자료형, 연속 메모리, 인덱스로 $O(1)$ 접근, 삽입/삭제는 $O(n)$
- **1차원 배열 주소 공식**: $\alpha + i \times d$
- **2차원 배열 행 우선 주소 공식**: $\alpha + (i \times n + j) \times d$
- **레코드**: 다른 자료형들을 묶어 저장 (C의 struct)
- **희소행렬**: 0이 아닌 원소만 (행, 열, 값) 형태로 저장하여 메모리 절약
- **전치행렬**: 행과 열을 바꾼 행렬, $A^T[j][i] = A[i][j]$
