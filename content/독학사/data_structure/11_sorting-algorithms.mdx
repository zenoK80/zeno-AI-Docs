## 왜 정렬이 중요한가?

10만 명의 고객 데이터에서 특정 고객을 찾아야 한다고 해봅시다. 정렬이 안 되어 있으면 처음부터 끝까지 모두 뒤져야 합니다($O(n)$). 하지만 이름 순으로 정렬되어 있다면 이진 탐색으로 훨씬 빠르게 찾을 수 있습니다($O(\log n)$).

정렬은 모든 데이터 처리의 기본입니다!

**정렬(Sorting, 소팅)**은 데이터를 특정 기준(오름차순, 내림차순)에 따라 배열하는 연산입니다.

## 정렬 알고리즘 한눈에 비교

| 알고리즘 | 최선 | 평균 | 최악 | 추가 공간 | 안정성 |
| --- | --- | --- | --- | --- | --- |
| 버블(Bubble) | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 안정 |
| 선택(Selection) | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 불안정 |
| 삽입(Insertion) | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 안정 |
| 쉘(Shell) | $O(n \log n)$ | $O(n^{1.3})$ | $O(n^2)$ | $O(1)$ | 불안정 |
| 퀵(Quick) | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | 불안정 |
| 합병(Merge) | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | 안정 |
| 힙(Heap) | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | 불안정 |
| 기수(Radix) | $O(nk)$ | $O(nk)$ | $O(nk)$ | $O(n+k)$ | 안정 |

**안정 정렬(Stable Sort, 스태이블 소트)**: 같은 키 값을 가진 원소들의 **상대적 순서**가 정렬 후에도 유지되는 정렬.

쉽게 말하면: 안정 정렬 = "같은 점수를 받은 학생들의 원래 순서가 바뀌지 않는" 정렬

**안정 정렬**: 버블, 삽입, 합병, 기수
**불안정 정렬**: 선택, 쉘, 퀵, 힙

## 버블 정렬 (Bubble Sort, 버블 소트)

인접한 두 원소를 비교하여 순서가 맞지 않으면 교환합니다. 가장 큰 원소가 매 패스마다 끝으로 "떠오릅니다(Bubble Up)".

비유: 탄산음료의 거품이 위로 올라오는 것처럼, 큰 값이 끝으로 이동합니다.

```
[5, 3, 8, 1] 정렬 과정:
1패스: 5↔3 교환, 5↔8 패스, 8↔1 교환 → [3, 5, 1, 8]  (8 확정)
2패스: 3↔5 패스, 5↔1 교환 → [3, 1, 5, 8]  (5 확정)
3패스: 3↔1 교환 → [1, 3, 5, 8]  (완료)
```

개선 버블 정렬: 한 패스에서 교환이 없으면 이미 정렬된 것이므로 즉시 종료 → 최선 $O(n)$

## 선택 정렬 (Selection Sort, 셀렉션 소트)

매 패스마다 남은 원소 중 **최솟값**을 찾아 맨 앞 원소와 교환합니다.

비유: 카드 중에서 가장 작은 것을 골라 앞으로 보내는 것을 반복.

```
[5, 3, 8, 1]:
1패스: 최솟값 1 선택 → 5와 교환 → [1, 3, 8, 5]
2패스: 최솟값 3 선택 → 3 제자리 → [1, 3, 8, 5]
3패스: 최솟값 5 선택 → 8과 교환 → [1, 3, 5, 8]
```

항상 $O(n^2)$이며, 교환 횟수는 최대 $n-1$번으로 적습니다.

## 삽입 정렬 (Insertion Sort, 인서션 소트)

현재 원소를 앞의 **이미 정렬된 부분**에 올바른 위치로 삽입합니다.

비유: 카드 게임에서 패를 뽑을 때마다 손에 든 카드들 사이에 올바른 위치로 끼워 넣는 것.

```
[5, 3, 8, 1]:
i=1: 3 뽑기, 5 뒤로 밀기 → [3, 5, 8, 1]
i=2: 8 뽑기, 제자리 → [3, 5, 8, 1]
i=3: 1 뽑기, 8, 5, 3 뒤로 밀기 → [1, 3, 5, 8]
```

거의 정렬된 데이터에서 매우 효율적입니다 (최선 $O(n)$).

## 퀵 정렬 (Quick Sort, 퀵 소트)

**피벗(Pivot, 피벗)**을 선택하여 피벗보다 작은 원소는 왼쪽, 큰 원소는 오른쪽으로 분할하고 각각을 재귀 정렬합니다.

비유: 중간값 기준으로 "이것보다 작은 것 왼쪽, 큰 것 오른쪽"으로 나누는 것을 반복.

- 평균 $O(n \log n)$으로 실제로 가장 빠른 정렬
- 최악(이미 정렬된 데이터 + 첫 원소를 피벗으로 선택): $O(n^2)$
- 불안정 정렬

**최악 방지법:** 중간값(Median-of-Three, 미디언 오브 쓰리) - 첫, 중간, 마지막 원소 중 중앙값을 피벗으로 선택

## 합병 정렬 (Merge Sort, 머지 소트)

배열을 절반으로 나누어 각각 정렬한 후 합병합니다. **분할 정복(Divide and Conquer)** 기법.

```
[5, 3, 8, 1]
→ [5, 3] + [8, 1]  (분할)
→ [3, 5] + [1, 8]  (각각 정렬)
→ [1, 3, 5, 8]     (합병)
```

- 항상 $O(n \log n)$ 보장 (안정 정렬)
- 단점: 합병을 위한 추가 메모리 $O(n)$ 필요

## 기수 정렬 (Radix Sort, 래딕스 소트)

원소 간 직접 비교 없이 **자릿수(Digit)**별로 정렬합니다. 비교 기반 알고리즘이 아닙니다.

예시: [170, 45, 75, 90, 802, 24, 2, 66] 정렬
```
일의 자리 기준: [170, 90, 802, 2, 24, 45, 75, 66]
십의 자리 기준: [802, 2, 24, 45, 66, 170, 75, 90]
백의 자리 기준: [2, 24, 45, 66, 75, 90, 170, 802]
```

- 자릿수 $k$가 작으면 $O(nk) \approx O(n)$에 가까운 성능
- 안정 정렬

## 정렬 알고리즘 선택 가이드

| 상황 | 추천 알고리즘 |
| --- | --- |
| 데이터가 거의 정렬되어 있음 | 삽입 정렬 |
| 빠른 평균 속도 필요 | 퀵 정렬 |
| 최악 보장이 필요함 | 합병 정렬 또는 힙 정렬 |
| 안정 정렬이 필요함 | 합병 정렬 |
| 추가 메모리 없이 정렬 필요 | 힙 정렬 |
| 숫자 자릿수가 적음 | 기수 정렬 |

## 핵심 정리

- **버블, 선택, 삽입**: $O(n^2)$, 구현 간단
- **퀵, 합병, 힙**: $O(n \log n)$
- **합병 정렬**: 안정 정렬, 추가 메모리 $O(n)$ 필요
- **퀵 정렬**: 평균 가장 빠르나 최악 $O(n^2)$, 불안정 정렬
- **힙 정렬**: 항상 $O(n \log n)$, 제자리 정렬, 불안정 정렬
- **기수 정렬**: 비교 기반 아님, 특수 조건에서 빠름
- **안정 정렬**: 버블, 삽입, 합병, 기수
