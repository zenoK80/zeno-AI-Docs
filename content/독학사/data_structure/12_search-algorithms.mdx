## 탐색 알고리즘 개요

**탐색(Search)** 은 데이터 집합에서 특정 값을 찾는 연산입니다.

| 알고리즘 | 전제 조건 | 시간 복잡도 |
| --- | --- | --- |
| 순차 탐색 | 없음 | $O(n)$ |
| 이진 탐색 | 정렬된 배열 | $O(\log n)$ |
| 해싱 | 해시 테이블 | $O(1)$ 평균 |

## 순차 탐색 (Sequential/Linear Search)

처음부터 끝까지 순서대로 비교하며 탐색합니다.

- 시간 복잡도: $O(n)$
- 정렬 여부 상관없이 사용 가능
- 데이터가 적거나 정렬이 안 된 경우 사용

## 이진 탐색 (Binary Search)

**정렬된 배열**에서 중간 원소와 비교하여 탐색 범위를 절반씩 줄여가는 방법입니다.

**과정:** 배열 [1, 3, 5, 7, 9, 11, 13]에서 7 탐색

```
left=0, right=6, mid=3 → arr[3]=7 → 탐색 성공!
```

배열에서 5 탐색:
```
step1: left=0, right=6, mid=3, arr[3]=7 > 5 → right=2
step2: left=0, right=2, mid=1, arr[1]=3 < 5 → left=2
step3: left=2, right=2, mid=2, arr[2]=5 → 탐색 성공!
```

시간 복잡도: $O(\log n)$ (반드시 정렬된 배열이어야 함)

## 해싱 (Hashing)

**해싱**은 키(key)를 해시 함수(hash function)로 변환하여 해시 테이블의 특정 위치(버킷)에 직접 접근합니다.

$$h(\text{key}) = \text{key} \mod M$$

여기서 $M$은 해시 테이블의 크기(소수 권장)입니다.

### 해시 함수의 종류

| 방법 | 설명 |
| --- | --- |
| 나머지 연산법(Division) | key % M |
| 곱셈법(Multiplication) | $\lfloor M \times (key \times A \mod 1) \rfloor$ |
| 폴딩법(Folding) | 키를 여러 부분으로 나누어 더함 |
| 제곱법(Mid-Square) | 키를 제곱하여 중간 자리 추출 |

### 충돌(Collision)과 처리 방법

서로 다른 키가 같은 해시 주소를 가지는 경우 **충돌(Collision)** 이 발생합니다.

**개방 주소법(Open Addressing):**

| 방법 | 설명 |
| --- | --- |
| 선형 조사법 | 충돌 시 다음 빈 슬롯 순서대로 탐색 |
| 이차 조사법 | 충돌 시 $1^2, 2^2, 3^2, ...$ 간격으로 탐색 |
| 이중 해싱 | 두 번째 해시 함수로 간격 결정 |

**체이닝(Chaining):** 같은 주소의 모든 원소를 연결 리스트로 연결합니다.

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 개방 주소법 | 추가 메모리 불필요 | 클러스터링 문제 |
| 체이닝 | 충돌 처리 유연 | 추가 메모리(포인터) 필요 |

### 적재율 (Load Factor)

$$\lambda = \frac{\text{저장된 원소 수}}{\text{해시 테이블 크기}}$$

$\lambda$가 증가할수록 충돌 확률이 높아집니다. 일반적으로 0.7 이하를 유지합니다.

## 핵심 정리

- 순차 탐색: $O(n)$, 정렬 불필요
- 이진 탐색: $O(\log n)$, 반드시 정렬된 배열 필요
- 해싱: 평균 $O(1)$, 최악 $O(n)$ (충돌 많을 때)
- 충돌 처리: 개방 주소법(선형/이차 조사), 체이닝
