## 왜 이진 탐색 트리가 필요한가?

전화번호부에서 "홍길동"을 찾는다고 해봅시다. 순서 없이 뒤섞여 있다면 처음부터 끝까지 모두 봐야 합니다($O(n)$). 하지만 가나다 순으로 정렬되어 있다면 중간부터 열어서 빠르게 찾을 수 있습니다($O(\log n)$).

**이진 탐색 트리(Binary Search Tree, BST, 비에스티)**는 이 "가나다 순 전화번호부"의 원리를 트리 구조에 적용한 것입니다. 삽입, 삭제, 탐색을 모두 빠르게 할 수 있습니다.

쉽게 말하면: BST = 왼쪽 작은 것, 오른쪽 큰 것을 반복해 쌓은 트리

## 이진 탐색 트리 (BST)

**이진 탐색 트리(Binary Search Tree, BST)**는 다음 세 가지 성질을 만족하는 이진트리입니다.

1. 왼쪽 서브트리의 모든 키 값 **작음** 루트 키 값
2. 오른쪽 서브트리의 모든 키 값 **큼** 루트 키 값
3. 각 서브트리도 이진 탐색 트리 (재귀적으로 동일한 규칙 적용)

예시 BST (50, 30, 70, 20, 40을 순서대로 삽입):

```
      50
     /  \
    30   70
   /  \
  20   40
```

- 50의 왼쪽은 모두 50보다 작음 (30, 20, 40)
- 50의 오른쪽은 모두 50보다 큼 (70)

## BST 탐색

키 값 k를 탐색하는 과정:

1. 루트에서 시작
2. k == 현재 노드 키: 탐색 성공!
3. k 가 현재 노드 키보다 작음: 왼쪽 서브트리로 이동
4. k 가 현재 노드 키보다 큼: 오른쪽 서브트리로 이동
5. NULL(빈 곳)에 도달: 탐색 실패

**예시:** 위 BST에서 40 탐색
```
루트 50 확인: 40 < 50 → 왼쪽 이동
30 확인: 40 > 30 → 오른쪽 이동
40 확인: 40 == 40 → 탐색 성공!
```

**시간 복잡도:**
- 평균: $O(\log n)$ (균형 잡힌 트리)
- 최악: $O(n)$ (편향 트리 - 한쪽으로만 치우친 경우)

## BST 삽입

새 키를 삽입할 위치를 탐색으로 찾은 뒤 리프 노드로 추가합니다.

규칙: 탐색 실패한 위치가 바로 삽입할 자리!

예시: 50, 30, 70, 20, 40 순서로 삽입

```
50 삽입 → 루트: 50
30 삽입 → 30 < 50이므로 50의 왼쪽
70 삽입 → 70 > 50이므로 50의 오른쪽
20 삽입 → 20 < 50(왼), 20 < 30(왼) → 30의 왼쪽
40 삽입 → 40 < 50(왼), 40 > 30(오) → 30의 오른쪽

결과:
      50
     /  \
    30   70
   /  \
  20   40
```

## BST 삭제

삭제할 노드의 자식 수에 따라 세 가지 경우로 처리합니다.

| 경우 | 처리 방법 |
| --- | --- |
| 자식 없음(리프 노드) | 노드를 단순 삭제 |
| 자식 1개 | 자식 노드로 대체 |
| 자식 2개 | 중위 후속자(또는 중위 전임자)로 대체 후 해당 노드 삭제 |

**중위 후속자(In-order Successor, 인오더 석세서)**: 삭제할 노드의 오른쪽 서브트리에서 **가장 작은 값**

쉽게 말하면: "나를 삭제하면 누가 내 자리를 차지해야 BST 성질을 유지할까?" 그게 바로 중위 후속자입니다.

**예시:** 위 BST에서 30 삭제 (자식 2개: 20, 40)
```
30의 오른쪽 서브트리 {40}에서 최솟값 = 40
30을 40으로 대체하고 원래 40 삭제

결과:
      50
     /  \
    40   70
   /
  20
```

## AVL 트리

BST의 문제점: 데이터를 오름차순으로 삽입하면 트리가 한쪽으로 치우칩니다(편향 트리).

```
1 삽입: 1
2 삽입: 1 → 2
3 삽입: 1 → 2 → 3   (연결 리스트처럼 됨! 탐색 O(n))
```

이 문제를 해결한 것이 **AVL 트리(AVL Tree, 에이비엘 트리)**입니다. 발명자 Adelson-Velsky, Landis의 이름 앞 글자를 딴 이름입니다.

**AVL 트리**는 모든 노드에서 왼쪽과 오른쪽 서브트리의 높이 차이(**균형 인수**)가 최대 1인 자기 균형 이진 탐색 트리입니다.

$$\text{균형 인수(Balance Factor)} = h(\text{왼쪽 서브트리}) - h(\text{오른쪽 서브트리})$$

- 균형 상태: 균형 인수가 **-1, 0, 1** 중 하나
- 불균형 상태: 균형 인수가 **-2 또는 2** → 회전으로 복구 필요

### AVL 회전의 종류

불균형이 발생하면 **회전(Rotation)**으로 균형을 복구합니다.

| 불균형 유형 | 발생 원인 | 회전 방법 |
| --- | --- | --- |
| LL형 | 왼쪽 자식의 왼쪽에 삽입 | 오른쪽 단순 회전 |
| RR형 | 오른쪽 자식의 오른쪽에 삽입 | 왼쪽 단순 회전 |
| LR형 | 왼쪽 자식의 오른쪽에 삽입 | 왼쪽 회전 후 오른쪽 회전 |
| RL형 | 오른쪽 자식의 왼쪽에 삽입 | 오른쪽 회전 후 왼쪽 회전 |

AVL 트리는 항상 $O(\log n)$의 탐색/삽입/삭제 시간을 보장합니다!

## BST vs AVL 트리 비교

| 항목 | BST | AVL 트리 |
| --- | --- | --- |
| 탐색 평균 | $O(\log n)$ | $O(\log n)$ |
| 탐색 최악 | $O(n)$ | $O(\log n)$ |
| 삽입 후 균형 | 보장 안 됨 | 항상 보장 |
| 구현 복잡도 | 단순 | 복잡 |

## 핵심 정리

- **BST**: 왼쪽 작음 루트 오른쪽 큼 성질을 유지하는 이진트리
- 탐색/삽입/삭제 평균: $O(\log n)$, 최악(편향): $O(n)$
- 삭제 시 자식 2개인 경우 **중위 후속자**로 대체
- **AVL 트리**: 균형 인수 ±1 유지, 항상 $O(\log n)$ 보장
