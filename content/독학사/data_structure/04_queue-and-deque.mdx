## 왜 큐가 필요한가?

은행에 줄을 서는 상황을 떠올려 보세요. 먼저 온 손님이 먼저 서비스를 받습니다. 나중에 온 손님이 새치기하면 안 되겠죠. 컴퓨터에서도 이런 "공정한 순서 처리"가 필요할 때 **큐**(Queue, 큐)를 사용합니다.

생활 비유: **매표소 줄**, **프린터 인쇄 대기**, **콜센터 전화 대기** - 모두 큐의 원리입니다.

## 큐의 개념

**큐**(Queue)는 한쪽(rear, 리어)에서 삽입하고 반대쪽(front, 프론트)에서 삭제하는 선형 자료구조입니다.

먼저 들어온 데이터가 먼저 나가므로 **FIFO**(First In, First Out, 파이포)라고 합니다.

- **FIFO** = First(먼저) + In(들어온) + First(먼저) + Out(나간다)
- 쉽게 말하면: 줄 서기처럼 먼저 온 사람이 먼저 나간다
- **rear**(리어): 새 원소가 들어오는 뒤쪽
- **front**(프론트): 원소가 나가는 앞쪽

## 큐의 주요 연산

| 연산 | 설명 | 시간 복잡도 |
| --- | --- | --- |
| enqueue(x) | rear에 원소 x 삽입 | $O(1)$ |
| dequeue() | front의 원소 삭제 및 반환 | $O(1)$ |
| peek() | front 원소 조회 | $O(1)$ |
| isEmpty() | 큐가 비어있는지 확인 | $O(1)$ |

**enqueue**(인큐) = en(넣다) + queue(큐) → 큐에 넣다
**dequeue**(디큐) = de(꺼내다) + queue(큐) → 큐에서 꺼내다

## 선형 큐의 문제점

배열로 구현한 선형 큐를 사용하다 보면 문제가 생깁니다.

```
초기: front=0, rear=0, [빈, 빈, 빈, 빈]
enqueue(A): front=0, rear=1, [A, 빈, 빈, 빈]
enqueue(B): front=0, rear=2, [A, B, 빈, 빈]
dequeue():  front=1, rear=2, [빈, B, 빈, 빈]  ← A 자리가 낭비!
```

dequeue 후 front가 오른쪽으로 이동하면서 앞쪽 공간이 비어있어도 사용하지 못합니다. 배열 끝에 도달하면 실제로 공간이 있어도 꽉 찬 것으로 잘못 판단할 수 있습니다.

## 원형 큐 (Circular Queue)

**원형 큐**(Circular Queue, 서큘러 큐)는 배열을 원형(도넛 모양)으로 연결하여 공간 낭비 없이 사용합니다.

비유: 회전 초밥 벨트처럼 끝에 도달하면 다시 처음으로 이어집니다.

크기 $n$인 배열에서 인덱스를 나머지 연산(`% n`)으로 순환시킵니다.

| 조건 | 판별 식 |
| --- | --- |
| 공백 상태 | front == rear |
| 포화 상태 | (rear + 1) % n == front |

<Callout type="warning">
  원형 큐에서 포화 상태와 공백 상태를 구별하기 위해 한 칸을 비워 둡니다. 따라서 크기 n인 배열에 최대 n-1개 원소를 저장할 수 있습니다.
</Callout>

**enqueue 연산:**
```
rear = (rear + 1) % n   ← 인덱스를 원형으로 증가
queue[rear] = x         ← 새 원소 저장
```

**dequeue 연산:**
```
front = (front + 1) % n  ← 인덱스를 원형으로 증가
return queue[front]      ← 꺼낸 원소 반환
```

## 우선순위 큐 (Priority Queue)

일반 큐는 먼저 온 순서대로 처리합니다. 하지만 응급실에서는 먼저 온 순서가 아니라 상태가 위급한 환자부터 먼저 처리해야 합니다. 이처럼 **우선순위**(Priority)에 따라 처리 순서가 결정되는 것이 **우선순위 큐**(Priority Queue, 프라이어리티 큐)입니다.

쉽게 말하면: 우선순위 큐 = 번호표 대신 "긴급도"에 따라 먼저 처리되는 큐

**힙**(Heap, 힙)으로 효율적으로 구현하며 삽입/삭제 시간 복잡도는 $O(\log n)$입니다.

| 구현 방법 | 삽입 | 삭제(최우선) |
| --- | --- | --- |
| 정렬 배열 | $O(n)$ | $O(1)$ |
| 정렬 연결 리스트 | $O(n)$ | $O(1)$ |
| 힙(Heap) | $O(\log n)$ | $O(\log n)$ |

힙이 가장 효율적입니다.

## 덱 (Deque, Double-Ended Queue)

**덱**(Deque, 덱)은 앞과 뒤 양쪽에서 삽입과 삭제가 모두 가능한 자료구조입니다.

- **Deque** = Double(양쪽) + Ended(끝) + Queue(큐)
- 쉽게 말하면: 스택과 큐의 기능을 모두 갖춘 슈퍼 자료구조

| 연산 | 설명 |
| --- | --- |
| addFront(x) | 앞에 삽입 |
| addRear(x) | 뒤에 삽입 |
| deleteFront() | 앞에서 삭제 |
| deleteRear() | 뒤에서 삭제 |

덱은 스택과 큐의 기능을 모두 포함합니다.
- 앞에서만 삽입/삭제 → 스택
- 앞 삭제 + 뒤 삽입 → 큐

## 큐의 응용

| 응용 사례 | 설명 |
| --- | --- |
| 프로세스 스케줄링 | 운영체제가 CPU를 공정하게 배분 |
| 네트워크 패킷 처리 | 데이터 패킷을 받은 순서대로 처리 |
| 너비 우선 탐색(BFS) | 그래프에서 가까운 노드부터 탐색 |
| 프린터 스풀링 | 인쇄 작업을 받은 순서대로 처리 |

## 핵심 정리

- **큐**는 FIFO(First In, First Out) 구조입니다.
- **선형 큐**는 앞 공간 낭비 문제가 있으며, **원형 큐**로 해결합니다.
- 원형 큐 공백: front == rear, 포화: (rear+1)%n == front
- **우선순위 큐**는 힙으로 구현하며 삽입/삭제가 $O(\log n)$입니다.
- **덱**은 양쪽에서 삽입/삭제가 가능합니다.
