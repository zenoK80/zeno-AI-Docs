## 큐의 개념

**큐(Queue)** 는 한쪽(rear)에서 삽입하고 반대쪽(front)에서 삭제하는 선형 자료구조입니다. 먼저 들어온 데이터가 먼저 나가므로 **FIFO(First In, First Out)** 구조입니다.

은행 창구나 프린터 대기열처럼 순서대로 처리해야 하는 상황에 사용됩니다.

## 큐의 주요 연산

| 연산 | 설명 | 시간 복잡도 |
| --- | --- | --- |
| enqueue(x) | rear에 원소 x 삽입 | $O(1)$ |
| dequeue() | front의 원소 삭제 및 반환 | $O(1)$ |
| peek() | front 원소 조회 | $O(1)$ |
| isEmpty() | 큐가 비어있는지 확인 | $O(1)$ |

## 선형 큐의 문제점

배열로 구현한 선형 큐는 dequeue 후 앞쪽 공간이 낭비됩니다. front가 계속 오른쪽으로 이동하면서 실제로 사용 가능한 공간이 있어도 포화 상태로 잘못 판단할 수 있습니다.

## 원형 큐 (Circular Queue)

**원형 큐**는 배열을 원형으로 연결하여 공간 낭비 없이 사용합니다. 크기가 $n$인 배열에서 인덱스를 나머지 연산($\% n$)으로 순환시킵니다.

| 조건 | 식 |
| --- | --- |
| 공백 상태 | front == rear |
| 포화 상태 | (rear + 1) % n == front |

<Callout type="warning">
  원형 큐에서 포화 상태를 구별하기 위해 한 칸을 비워 둡니다. 따라서 크기 n인 배열에 최대 n-1개 원소를 저장할 수 있습니다.
</Callout>

**enqueue 연산:**
```
rear = (rear + 1) % n
queue[rear] = x
```

**dequeue 연산:**
```
front = (front + 1) % n
return queue[front]
```

## 우선순위 큐 (Priority Queue)

**우선순위 큐**는 원소마다 우선순위가 있어서 우선순위가 높은 원소부터 먼저 삭제됩니다. 힙(Heap)으로 효율적으로 구현하며 시간 복잡도는 $O(\log n)$입니다.

| 자료구조 | 삽입 | 삭제 |
| --- | --- | --- |
| 정렬 배열 | $O(n)$ | $O(1)$ |
| 정렬 연결 리스트 | $O(n)$ | $O(1)$ |
| 힙(Heap) | $O(\log n)$ | $O(\log n)$ |

## 덱 (Deque, Double-Ended Queue)

**덱**은 앞과 뒤 양쪽에서 삽입과 삭제가 모두 가능한 자료구조입니다.

| 연산 | 설명 |
| --- | --- |
| addFront(x) | 앞에 삽입 |
| addRear(x) | 뒤에 삽입 |
| deleteFront() | 앞에서 삭제 |
| deleteRear() | 뒤에서 삭제 |

덱은 스택과 큐의 기능을 모두 포함합니다.

## 큐의 응용

- 운영체제의 프로세스 스케줄링
- 네트워크 패킷 처리
- 너비 우선 탐색(BFS)
- 프린터 스풀링

## 핵심 정리

- 큐는 FIFO(First In, First Out) 구조입니다.
- 선형 큐는 앞 공간 낭비 문제가 있으며, 원형 큐로 해결합니다.
- 원형 큐에서 공백: front == rear, 포화: (rear+1)%n == front
- 우선순위 큐는 힙으로 구현하며 삽입/삭제가 $O(\log n)$입니다.
- 덱은 양쪽에서 삽입/삭제가 가능합니다.
