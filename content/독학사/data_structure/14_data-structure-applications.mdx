## 왜 자료구조 활용을 배우나?

자료구조를 배운 이유는 결국 **실제 문제를 효율적으로 해결**하기 위해서입니다. 이번 문서에서는 배운 자료구조들이 실전 프로그래밍에서 어떻게 쓰이는지 살펴봅니다.

- 괄호가 올바른지 검사하는 코드 — 컴파일러가 매일 하는 일
- 수식을 계산기가 이해하는 형태로 변환하는 일 — 계산기 앱의 내부
- 강의 선수과목 순서대로 나열하기 — 대학 수강 신청 시스템
- 다항식 계산 — 수학 소프트웨어의 핵심

## 스택을 이용한 괄호 검사

코드를 작성할 때 `{`, `[`, `(` 의 짝이 맞지 않으면 컴파일 에러가 납니다. 이 "짝 맞추기"를 스택으로 구현합니다.

**비유:** 중첩된 박스를 쌓아 올린다고 생각하세요. 박스를 열 때마다 스택에 올리고, 박스를 닫을 때 스택 맨 위의 박스를 꺼내서 종류가 맞는지 확인합니다.

**알고리즘:**
1. 여는 괄호 `(`, `[`, `{` 를 만나면 스택에 push
2. 닫는 괄호 `)`, `]`, `}` 를 만나면 스택에서 pop
3. pop한 여는 괄호와 닫는 괄호가 쌍이 맞는지 확인
4. 끝까지 처리 후 스택이 비어있으면 올바른 괄호

**예시: `{[()]}` 검사**
```
{ → push {         스택: {
[ → push [         스택: { [
( → push (         스택: { [ (
) → pop (,  ( == ) 짝 맞음   스택: { [
] → pop [,  [ == ] 짝 맞음   스택: {
} → pop {,  { == } 짝 맞음   스택: (비어있음)
스택 비어있음 → 올바른 괄호!
```

**잘못된 예: `([)]`**
```
( → push (    스택: (
[ → push [    스택: ( [
) → pop [,  [ != ) 짝 불일치 → 에러!
```

쉽게 말하면: 닫는 괄호를 만나면 스택 맨 위와 짝이 맞는지 확인, 안 맞으면 에러!

## 스택을 이용한 후위 표기식 변환

**왜 후위 표기식이 필요한가?**

우리가 쓰는 `A + B * C`는 **중위(Infix) 표기식**입니다. 컴퓨터는 연산자 우선순위를 처리하기 위해 **후위(Postfix) 표기식** `A B C * +`을 선호합니다. 후위 표기식은 괄호 없이도 계산 순서가 명확합니다.

- **중위(Infix, 인픽스)**: 연산자가 피연산자 사이에 위치 (사람이 읽기 좋음)
- **후위(Postfix, 포스트픽스)**: 연산자가 피연산자 뒤에 위치 (컴퓨터가 처리하기 좋음)
- **전위(Prefix, 프리픽스)**: 연산자가 피연산자 앞에 위치

**변환 예시: `A + B * C - D` 를 후위 표기식으로**

| 읽은 문자 | 스택 | 출력 |
| --- | --- | --- |
| A | (비어있음) | A |
| + | + | A |
| B | + | A B |
| * | + * | A B |
| C | + * | A B C |
| - | - | A B C * + |
| D | - | A B C * + D |
| 끝 | (비어있음) | A B C * + D - |

**결과:** `A B C * + D -`

스택에서 꺼낼 때: `*`가 `+`보다 우선순위가 높으므로 `-`를 만났을 때 `*`와 `+` 모두 꺼냅니다.

## 트리를 이용한 수식 표현

수식을 이진트리로 표현하면 순회 방법에 따라 세 가지 표기식을 자동으로 얻을 수 있습니다.

**규칙:** 내부 노드(Internal Node)는 연산자, 리프 노드(Leaf Node)는 피연산자

수식 `(A + B) * (C - D)`:

```
       *
      / \
     +   -
    / \ / \
   A  B C  D
```

| 순회 방법 | 방문 순서 | 표기식 | 결과 |
| --- | --- | --- | --- |
| 전위 순회(Preorder) | 루트 → 왼 → 오 | 전위(Prefix) | * + A B - C D |
| 중위 순회(Inorder) | 왼 → 루트 → 오 | 중위(Infix) | A + B * C - D |
| 후위 순회(Postorder) | 왼 → 오 → 루트 | 후위(Postfix) | A B + C D - * |

쉽게 말하면: 수식 트리를 어떤 순서로 방문하느냐에 따라 표기식이 달라집니다.

## 그래프를 이용한 위상 정렬

**왜 위상 정렬이 필요한가?**

대학교 수강 신청을 생각해 보세요. "자료구조" 수업을 듣기 전에 "프로그래밍 기초"를 먼저 들어야 합니다. 이런 선행 조건이 있는 항목들을 올바른 순서로 나열하는 문제가 **위상 정렬(Topological Sort, 토폴로지컬 소트)**입니다.

비유: 요리 레시피에서 "양파를 볶는다" 전에 "양파를 썬다"가 와야 하는 것처럼, 선행 작업이 끝난 후 다음 작업을 수행하는 순서를 구하는 것.

**적용 조건:** 방향 비순환 그래프(DAG, Directed Acyclic Graph). 사이클이 있으면 "A 전에 B, B 전에 A"처럼 모순이 생겨 위상 정렬이 불가능합니다.

**Kahn의 알고리즘(큐 이용):**
1. 모든 정점의 진입 차수(In-degree)를 계산
2. 진입 차수가 0인 정점을 큐에 삽입 ("선행 조건 없음!")
3. 큐에서 정점을 꺼내 결과에 추가
4. 해당 정점의 인접 정점의 진입 차수를 1 감소
5. 진입 차수가 0이 된 정점을 큐에 삽입
6. 큐가 빌 때까지 반복

**결과 검증:** 결과에 포함된 정점 수가 전체 정점 수보다 적으면 사이클이 존재합니다.

## 연결 리스트를 이용한 다항식 연산

다항식 $A(x) = 3x^4 + 2x^2 + 1$에서 각 항은 (계수, 지수) 쌍입니다. 배열로 표현하면 중간 지수가 없는 희소 다항식(Sparse Polynomial)에서 메모리 낭비가 생깁니다. 연결 리스트를 쓰면 존재하는 항만 저장할 수 있습니다.

```
[3|4] → [2|2] → [1|0] → NULL
(계수|지수)
```

**두 다항식의 덧셈 방법:**
- 지수가 같으면 계수를 더해서 결과에 추가
- 지수가 다르면 지수가 큰 쪽을 결과에 먼저 추가
- 두 리스트를 앞에서부터 함께 순회 (합병 정렬의 합병 과정과 유사)

## 자료구조 선택 가이드

| 문제 상황 | 적합한 자료구조 | 이유 |
| --- | --- | --- |
| 역순 처리, 괄호 검사, 후위 변환 | 스택 | LIFO 구조 |
| 순서대로 처리, BFS, 위상 정렬 | 큐 | FIFO 구조 |
| 빠른 최솟값/최댓값 반복 추출 | 힙(우선순위 큐) | $O(\log n)$ |
| 동적 삽입/삭제, 다항식 | 연결 리스트 | 포인터 수정 $O(1)$ |
| 계층 구조, 수식 표현 | 트리 | 부모-자식 관계 |
| 관계망, 경로 탐색, 위상 정렬 | 그래프 | 정점-간선 관계 |
| 빠른 탐색(정렬 필요) | BST, AVL 트리 | $O(\log n)$ 탐색 |
| 초고속 탐색(정렬 불필요) | 해시 테이블 | 평균 $O(1)$ 탐색 |

## 핵심 정리

- **괄호 검사**: 스택 활용 — 여는 괄호 push, 닫는 괄호는 pop 후 짝 비교
- **후위 변환**: 피연산자는 즉시 출력, 연산자는 우선순위 비교 후 스택 처리
- **수식 트리**: 전위/중위/후위 순회로 각각 전위/중위/후위 표기식 생성
- **위상 정렬**: DAG에서 선행 관계 순서 결정, 진입 차수 0인 정점부터 처리
- **자료구조 선택**: 문제의 특성(삽입/삭제/탐색 빈도, 순서 필요 여부)에 맞게 선택
