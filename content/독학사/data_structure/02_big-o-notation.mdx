<Callout type="info">
  **이번 문서의 목표:** Big-O 표기법의 의미를 이해하고, O(1)·O(n)·O(log n)·O(n²) 등 대표적인 복잡도를 구분할 수 있게 됩니다.
</Callout>

## 왜 복잡도를 알아야 하는가?

같은 문제를 푸는 방법(알고리즘)은 여러 가지가 있을 수 있습니다. 어떤 방법은 데이터가 10개일 때나 100만 개일 때나 거의 비슷한 시간이 걸리지만, 어떤 방법은 데이터가 늘어날수록 급격히 느려집니다. **Big-O 표기법**은 이 "데이터가 늘어날 때 얼마나 느려지는가"를 객관적으로 비교하는 언어입니다. 뒤에서 배울 모든 자료구조·알고리즘의 성능을 이 표기법으로 평가합니다.

## Big-O 표기법이란?

> **쉽게 말하면:** Big-O는 "데이터 개수(n)가 아주 커졌을 때, 알고리즘의 실행 시간이 대략 어떤 모양의 그래프를 그리는가"를 나타내는 표기법입니다.

**왜 정확한 시간**(초)**이 아니라 Big-O를 쓰는가?** 컴퓨터마다 성능이 다르고, 실행할 때마다 시간이 조금씩 다르기 때문에, "몇 초 걸리는지"는 공정한 비교 기준이 되지 못합니다. 대신 "데이터가 2배로 늘어나면 시간이 몇 배로 늘어나는가"라는 **증가 추세**에 집중합니다.

## 대표적인 시간복잡도

**해석:** $n=100$일 때 $O(n^2)$는 $O(n)$보다 100배나 많은 연산이 필요합니다. 데이터가 커질수록 이 차이는 훨씬 더 벌어집니다.

## O(1) — 상수 시간 예시

> **쉽게 말하면:** 데이터가 얼마나 많든, 항상 딱 한 번의 확인만으로 끝나는 연산입니다.

**예시:** 배열의 `arr[5]`처럼 인덱스로 특정 위치의 값을 바로 가져오는 연산. 05번 문서에서 배울 배열의 핵심 장점입니다.

## O(n) — 선형 시간 예시

> **쉽게 말하면:** 데이터를 처음부터 끝까지 한 번씩 다 살펴봐야 하는 연산입니다.

**예시:** 배열에서 특정 값을 찾기 위해 처음부터 하나씩 비교하는 **순차 탐색**(16번 문서에서 자세히 다룸). 데이터가 $n$개면 최악의 경우 $n$번 비교해야 합니다.

## O(log n) — 로그 시간 예시

> **쉽게 말하면:** 매번 확인할 때마다 남은 데이터가 절반씩 줄어드는 연산입니다.

**예시:** 정렬된 배열에서 **이진 탐색**(16번 문서). 100개 중에서 찾을 때, 절반씩 제외하면 최대 약 7번(=$\log_2 100$)만 비교하면 끝납니다.

<Callout type="info">
  **왜 로그가 이렇게 느리게 증가하는가?** 데이터가 100개에서 1000개(10배)로 늘어나도, $\log_2 1000 \approx 10$으로 비교 횟수는 겨우 3번 정도만 늘어납니다. 데이터가 아무리 커져도 비교 횟수는 매우 천천히 증가하기 때문에, $O(\log n)$은 매우 효율적인 복잡도로 취급됩니다.
</Callout>

## O(n²) — 이차 시간 예시

> **쉽게 말하면:** 데이터 하나마다, 나머지 데이터 전부와 비교해야 하는 연산입니다(이중 반복문).

**예시:** 15번 문서에서 배울 **버블 정렬**처럼, 모든 쌍을 비교하는 단순한 정렬 알고리즘.

<Callout type="warning">
  **자주 틀리는 점:** Big-O는 "최악의 경우"(Worst Case)를 기준으로 표기하는 것이 일반적입니다. 어떤 알고리즘이 운이 좋으면 빠를 수 있어도, Big-O는 가장 나쁜 상황에서도 보장되는 성능 한계를 나타냅니다. 이 덕분에 서로 다른 알고리즘을 "최악의 경우에도 이 정도는 보장된다"는 공정한 기준으로 비교할 수 있습니다.
</Callout>

## 공간복잡도(Space Complexity)

시간복잡도가 "얼마나 오래 걸리는가"라면, **공간복잡도**는 "얼마나 많은 메모리를 추가로 사용하는가"를 나타냅니다. 표기법은 시간복잡도와 동일하게 $O(1)$, $O(n)$ 등을 사용합니다.

> **트레이드오프:** 종종 시간을 줄이면 공간을 더 쓰고, 공간을 아끼면 시간이 더 걸리는 트레이드오프가 발생합니다. 예를 들어 17번 문서에서 배울 해싱은 추가 메모리(해시 테이블)를 사용하는 대신 매우 빠른 탐색 속도($O(1)$에 가까움)를 얻습니다.

## 핵심 정리

- **Big-O 표기법**: 데이터 개수가 커질 때 알고리즘 실행 시간이 어떻게 증가하는지 나타내는 표기법. 실제 초 단위가 아닌 증가 추세에 집중.
- **복잡도 순서**(빠름→느림): $O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2)$.
- Big-O는 보통 최악의 경우를 기준으로 표기.
- **공간복잡도**: 사용하는 추가 메모리량. 시간복잡도와 트레이드오프 관계인 경우가 많다.
