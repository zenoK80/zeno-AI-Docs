## 왜 그래프가 필요한가?

트리는 "계층" 구조를 표현했습니다. 하지만 실제 세상의 관계는 훨씬 복잡합니다.

예시:
- **소셜 네트워크**: 친구 사이는 계층이 없고 서로 연결됩니다.
- **지하철 노선도**: 역과 역이 다양한 경로로 연결됩니다.
- **도로망**: 도시들이 여러 경로로 연결됩니다.

이런 **자유로운 연결 관계**를 표현하는 자료구조가 **그래프(Graph, 그래프)**입니다.

쉽게 말하면: 그래프 = 점들(정점)을 선들(간선)로 자유롭게 연결한 구조

## 그래프의 개념

**그래프(Graph)**는 **정점(Vertex, 버텍스)**의 집합 V와 **간선(Edge, 엣지)**의 집합 E로 정의됩니다.

$$G = (V, E)$$

- **정점(Vertex/Node)**: 데이터를 저장하는 기본 단위. 지하철 역, 사람, 도시
- **간선(Edge)**: 정점 간의 연결. 지하철 노선, 친구 관계, 도로

| 용어 | 영어 | 설명 |
| --- | --- | --- |
| 정점(Vertex) | vertex/node | 그래프의 기본 단위 |
| 간선(Edge) | edge | 정점 간의 연결 |
| 인접(Adjacent) | adjacent | 간선으로 바로 연결된 정점들의 관계 |
| 차수(Degree) | degree | 정점에 연결된 간선의 수 |
| 경로(Path) | path | 정점에서 다른 정점으로 이어지는 정점들의 순서 |

## 그래프의 종류

| 종류 | 설명 | 예시 |
| --- | --- | --- |
| 무방향 그래프(Undirected Graph) | 간선에 방향이 없음. 양방향 이동 가능 | 친구 관계 (서로 친구) |
| 방향 그래프(Directed Graph) | 간선에 방향이 있음. 한쪽으로만 이동 | 팔로우 관계 (A가 B를 팔로우) |
| 가중치 그래프(Weighted Graph) | 간선에 가중치(비용, 거리)가 있음 | 도로망 (거리 표시) |
| 완전 그래프(Complete Graph) | 모든 정점 쌍이 간선으로 연결됨 | n개 정점이면 간선 n(n-1)/2개 |

**방향 그래프의 특수 용어:**
- **진입 차수(In-degree, 인디그리)**: 해당 정점으로 들어오는 간선의 수
- **진출 차수(Out-degree, 아웃디그리)**: 해당 정점에서 나가는 간선의 수

## 그래프의 표현 방법

그래프를 컴퓨터에 저장하는 방법은 두 가지가 있습니다.

### 1. 인접 행렬 (Adjacency Matrix, 어드재이선시 매트릭스)

정점 수가 $n$인 그래프를 $n \times n$ 2차원 배열로 표현합니다.

- $A[i][j] = 1$: 정점 $i$에서 $j$로 간선이 존재
- $A[i][j] = 0$: 간선 없음

예시 (정점 3개: 0, 1, 2 / 간선: 0-1, 1-2):
```
    0  1  2
0 [ 0  1  0 ]
1 [ 1  0  1 ]
2 [ 0  1  0 ]
```

| 특성 | 내용 |
| --- | --- |
| 공간 복잡도 | $O(n^2)$ - n×n 크기 |
| 간선 존재 확인 | $O(1)$ - 바로 확인 가능 |
| 단점 | 간선이 적을 때 메모리 낭비 (0이 많음) |

### 2. 인접 리스트 (Adjacency List, 어드재이선시 리스트)

각 정점마다 연결된 정점들을 연결 리스트로 저장합니다.

예시 (같은 그래프):
```
0 → [1]
1 → [0, 2]
2 → [1]
```

| 특성 | 내용 |
| --- | --- |
| 공간 복잡도 | $O(n + e)$ (e: 간선 수) |
| 간선 존재 확인 | $O(n)$ - 리스트 탐색 필요 |
| 장점 | 간선이 적은 희소 그래프에 효율적 |

**어떤 걸 사용?**
- 간선이 많은 **밀집 그래프(Dense Graph)** → 인접 행렬
- 간선이 적은 **희소 그래프(Sparse Graph)** → 인접 리스트

## 깊이 우선 탐색 (DFS)

**DFS(Depth First Search, 디에프에스, 깊이 우선 탐색)**는 한 방향으로 끝까지 탐색한 후 되돌아오는 방법입니다.

비유: 미로에서 길을 찾을 때, 막힐 때까지 계속 앞으로 가다가 막히면 뒤로 돌아와 다른 길을 탐색하는 것.

- **사용 자료구조**: 스택(Stack) 또는 재귀(Recursion)
- 재귀를 쓰면 내부적으로 스택이 자동으로 사용됩니다.

예시 그래프 (1-2, 1-3, 2-4, 2-5, 3-6 연결, 1에서 시작):
```
DFS: 1 → 2 → 4 → (되돌아옴) → 5 → (되돌아옴) → 3 → 6
탐색 순서: 1, 2, 4, 5, 3, 6
```

시간 복잡도: 인접 행렬 $O(n^2)$, 인접 리스트 $O(n+e)$

## 너비 우선 탐색 (BFS)

**BFS(Breadth First Search, 비에프에스, 너비 우선 탐색)**는 시작 정점에서 가까운 정점부터 단계적으로 탐색합니다.

비유: 돌을 물에 던지면 동심원이 퍼져나가는 것처럼, 시작점에서 점점 멀리 탐색합니다.

- **사용 자료구조**: 큐(Queue)

예시 (같은 그래프, 1에서 시작):
```
BFS: 1 → (1과 인접한 2, 3) → (2, 3과 인접한 4, 5, 6)
탐색 순서: 1, 2, 3, 4, 5, 6
```

BFS는 **가중치가 없는 그래프**에서 **최단 경로(Shortest Path)**를 보장합니다!

| 항목 | DFS | BFS |
| --- | --- | --- |
| 자료구조 | 스택/재귀 | 큐 |
| 탐색 방식 | 깊이 우선 | 너비 우선 |
| 최단 경로 | 보장 안 됨 | 보장 (비가중치 그래프) |
| 시간 복잡도 | $O(n+e)$ | $O(n+e)$ |

## 신장 트리 (Spanning Tree)

**신장 트리(Spanning Tree, 스패닝 트리)**는 그래프의 모든 정점을 포함하고 사이클(순환)이 없는 부분 그래프입니다.

- $n$개의 정점이면 항상 $n-1$개의 간선
- 같은 그래프에서 여러 종류의 신장 트리 가능

**최소 비용 신장 트리(MST, Minimum Spanning Tree)**: 모든 간선 비용의 합이 최소인 신장 트리

활용: 최소 비용으로 모든 도시를 연결하는 도로 건설

## 핵심 정리

- **그래프** $G = (V, E)$: 정점 집합 V, 간선 집합 E
- **인접 행렬**: $O(n^2)$ 공간, 간선 확인 $O(1)$, 밀집 그래프에 적합
- **인접 리스트**: $O(n+e)$ 공간, 희소 그래프에 적합
- **DFS**: 스택/재귀, 깊이 우선 탐색
- **BFS**: 큐 사용, 최단 경로 탐색(비가중치 그래프)
- **신장 트리**: $n$개 정점, $n-1$개 간선, 사이클 없음
