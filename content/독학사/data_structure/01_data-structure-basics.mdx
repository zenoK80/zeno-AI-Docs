## 왜 자료구조를 배워야 할까?

책 1,000권이 바닥에 마구 쌓여 있다고 상상해 보세요. 원하는 책을 찾으려면 한 권 한 권 뒤져야 합니다. 하지만 책을 제목 순으로 선반에 꽂아두면 훨씬 빠르게 찾을 수 있죠.

컴퓨터도 마찬가지입니다. 데이터를 어떻게 **정리**(구조화) 해두느냐에 따라 처리 속도가 수백 배 차이 납니다. 이 "데이터를 정리하는 방법"이 바로 **자료구조**(Data Structure, 데이터 스트럭처)입니다.

쉽게 말하면: 자료구조 = 데이터를 어떤 틀에 담을 것인가를 결정하는 것

## 자료구조란 무엇인가

**자료구조**(Data Structure) 는 데이터를 효율적으로 저장하고 처리하기 위한 조직화된 방법입니다. 자료구조를 올바르게 선택하면 같은 문제를 훨씬 빠르게 해결할 수 있습니다.

자료구조는 크게 두 가지로 분류됩니다.

| 분류 | 설명 | 예시 |
| --- | --- | --- |
| 선형 자료구조 | 데이터가 일렬로 나열된 구조 | 배열, 연결 리스트, 스택, 큐 |
| 비선형 자료구조 | 데이터가 계층적 또는 망형으로 연결된 구조 | 트리, 그래프 |

**선형**(線形, linear)이란 "선처럼 일자로 연결된"이라는 뜻입니다. 기차 칸처럼 앞뒤로만 이어진 구조죠.
**비선형**(非線形, non-linear)은 "선이 아닌"이라는 뜻으로, 나뭇가지처럼 여러 방향으로 뻗어나가는 구조입니다.

## 추상 자료형 (ADT)

### 왜 추상 자료형이 필요한가?

스마트폰의 "전화 걸기" 버튼을 누를 때, 안에서 어떤 회로가 동작하는지 몰라도 사용할 수 있죠? 사용자는 "기능(무엇을 할 수 있는가)"만 알면 됩니다.

자료구조도 마찬가지입니다. 내부 구현 방법을 모르더라도, "어떤 연산이 가능한가"만 정의해 두는 것이 바로 **추상 자료형**(Abstract Data Type, ADT, 애이디티)입니다.

**ADT** = Abstract(추상적인) + Data(데이터) + Type(타입/유형)
쉽게 말하면: ADT = 내부 구현 없이 "무엇을 할 수 있는가"만 정의한 설계도

예를 들어 스택(Stack, 스택) ADT는 다음과 같이 정의됩니다.

- **데이터:** 원소들의 순서 있는 집합
- **연산:** push(삽입), pop(삭제), peek(최상단 조회), isEmpty(비어있는지 확인)

이 연산들이 "어떻게 작동하는가"(배열로? 연결 리스트로?)는 ADT에서 다루지 않습니다.

## 알고리즘의 정의와 조건

**알고리즘**(Algorithm, 알고리즘)은 문제를 해결하기 위한 유한한 단계의 명령 집합입니다. 레시피(요리법)와 비슷합니다. 재료를 넣는 순서와 방법이 정해져 있고, 언제 끝나는지가 명확하죠.

올바른 알고리즘은 다섯 가지 조건을 만족해야 합니다.

| 조건 | 설명 | 예시 |
| --- | --- | --- |
| 입력(Input) | 0개 이상의 입력이 존재한다 | 정렬할 숫자들 |
| 출력(Output) | 1개 이상의 출력이 존재한다 | 정렬된 숫자들 |
| 명확성(Definiteness) | 각 명령은 모호하지 않고 명확하다 | "약간" 대신 "5g" |
| 유한성(Finiteness) | 유한한 단계 후에 반드시 종료된다 | 무한 루프 금지 |
| 유효성(Effectiveness) | 각 명령은 실행 가능한 연산이다 | 컴퓨터가 실제로 할 수 있는 것 |

## 알고리즘 복잡도와 Big-O 표기법

### 복잡도란?

알고리즘의 "좋고 나쁨"을 어떻게 측정할까요? 크게 두 가지로 측정합니다.

- **시간 복잡도(Time Complexity):** 알고리즘이 완료되는 데 필요한 연산 횟수 (속도)
- **공간 복잡도(Space Complexity):** 알고리즘이 사용하는 메모리 양 (메모리 사용량)

### Big-O 표기법이란?

**Big-O(빅-오) 표기법**은 입력 크기 $n$이 커질 때 알고리즘의 성능이 어떻게 변하는지 나타내는 점근적(Asymptotic, 점근적) 표기법입니다.

여기서 **O**는 "Order(차수)"를 의미합니다. 수학적으로는 "최악의 경우에 이 속도를 넘지 않는다"는 뜻입니다.

쉽게 말하면: Big-O = 입력이 엄청나게 커져도 얼마나 느려지는가를 나타내는 등급표

| Big-O | 이름 | 의미 | 예시 알고리즘 |
| --- | --- | --- | --- |
| $O(1)$ | 상수 시간 | 입력이 아무리 커도 똑같이 빠름 | 배열 인덱스 접근 |
| $O(\log n)$ | 로그 시간 | 입력이 2배가 되어도 1번만 더 걸림 | 이진 탐색 |
| $O(n)$ | 선형 시간 | 입력에 비례해 느려짐 | 순차 탐색 |
| $O(n \log n)$ | 선형로그 시간 | 입력보다 조금 더 느려짐 | 퀵 정렬(평균), 합병 정렬 |
| $O(n^2)$ | 이차 시간 | 입력이 2배면 4배 느려짐 | 버블 정렬, 삽입 정렬 |
| $O(2^n)$ | 지수 시간 | 입력이 조금만 늘어도 폭발적으로 느려짐 | 재귀적 피보나치 |

복잡도 크기 비교 (왼쪽일수록 빠름):

$$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n)$$

**구체적 예시:** 1억 개의 데이터를 처리할 때
- $O(1)$: 1번 연산
- $O(\log n)$: 약 27번 연산
- $O(n)$: 1억 번 연산
- $O(n^2)$: 10,000조 번 연산 (현실적으로 불가능)

## 순환(재귀) 알고리즘

**재귀**(Recursion, 리커전)는 함수가 자기 자신을 호출하여 문제를 해결하는 방법입니다.

생활 비유: 거울 두 개를 마주 보게 세우면 거울 속 거울이 끝없이 보이죠? 재귀도 그런 원리입니다. 단, 컴퓨터에서는 반드시 "끝나는 시점"인 **종료 조건**(base case, 베이스 케이스)이 있어야 합니다.

팩토리얼(Factorial) 예시: $n! = n \times (n-1)!$, 단 $0! = 1$

```
factorial(5)
= 5 × factorial(4)
= 5 × 4 × factorial(3)
= 5 × 4 × 3 × factorial(2)
= 5 × 4 × 3 × 2 × factorial(1)
= 5 × 4 × 3 × 2 × 1 = 120
```

종료 조건 `factorial(0) = 1`이 없으면 무한히 자신을 호출하다 오류가 납니다.

## 핵심 정리

- **자료구조**는 데이터를 효율적으로 조직화하는 방법이며, 선형과 비선형으로 분류됩니다.
- **ADT**(추상 자료형)는 구현 없이 데이터와 연산만 명세한 개념적 모델입니다.
- **알고리즘**의 5가지 조건: 입력, 출력, 명확성, 유한성, 유효성
- **Big-O 표기법**은 알고리즘 효율을 입력 크기 기준으로 나타냅니다.
- 복잡도 순서: $O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n)$
- **재귀**(Recursion)는 자기 자신을 호출하며, 반드시 종료 조건이 필요합니다.
