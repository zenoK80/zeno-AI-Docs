## 왜 힙이 필요한가?

병원 응급실을 생각해 보세요. 환자가 계속 들어오고, 그 중에서 가장 위급한 환자부터 처리해야 합니다. 단순한 큐(FIFO)로는 이걸 처리할 수 없습니다. 새로운 환자가 와도 현재 대기 중인 환자 중 가장 위급한 환자를 빠르게 골라내야 하니까요.

이럴 때 사용하는 것이 **힙(Heap, 힙)**입니다. 힙은 "최솟값" 또는 "최댓값"을 항상 빠르게 꺼낼 수 있는 자료구조입니다.

쉽게 말하면: 힙 = 가장 중요한 것(최댓값 또는 최솟값)이 항상 맨 위에 있는 트리

## 힙의 개념

**힙(Heap)**은 **완전 이진트리(Complete Binary Tree)** 구조에서 부모 노드와 자식 노드 사이에 특정 순서 조건을 만족하는 자료구조입니다.

| 종류 | 조건 | 특징 |
| --- | --- | --- |
| 최대 힙(Max-Heap) | 부모 노드의 키 값 >= 자식 노드의 키 값 | 루트에 최댓값이 있음 |
| 최소 힙(Min-Heap) | 부모 노드의 키 값 &lt;= 자식 노드의 키 값 | 루트에 최솟값이 있음 |

**힙의 두 가지 핵심 특성:**
1. **완전 이진트리 구조** 유지 (배열로 효율적 표현 가능)
2. **힙 성질(Heap Property)**: 부모-자식 간 크기 관계 유지

<Callout type="warning">
  주의: 힙은 BST가 아닙니다! BST는 왼쪽 작음-오른쪽 큼이지만, 힙은 단순히 부모가 자식보다 크거나(Max-Heap) 작습니다(Min-Heap). 같은 레벨의 원소들끼리는 순서가 없습니다.
</Callout>

## 힙의 배열 표현

힙은 완전 이진트리이므로 배열로 효율적으로 표현할 수 있습니다.

인덱스 1부터 시작 (인덱스 0은 사용하지 않음):

- 노드 $i$의 부모: $\lfloor i/2 \rfloor$ (내림)
- 노드 $i$의 왼쪽 자식: $2i$
- 노드 $i$의 오른쪽 자식: $2i+1$

예시 Max-Heap:
```
배열: [_, 90, 70, 60, 50, 30, 20, 10]
인덱스:  0   1   2   3   4   5   6   7

       90(1)
      /      \
   70(2)     60(3)
   /   \     /   \
 50(4) 30(5) 20(6) 10(7)
```

모든 부모가 자식보다 크므로 Max-Heap 성질 만족!

## 힙 삽입 (Sift-Up / Heapify-Up)

**Sift-Up(시프트 업)**: "체로 쳐서 올라간다"는 뜻. 새 원소가 제자리를 찾아 위로 올라가는 과정.

과정:
1. 새 원소를 배열 맨 끝(완전 이진트리의 마지막 위치)에 추가
2. 부모 노드와 비교하여 힙 성질 위반 시 교환
3. 힙 성질이 만족될 때까지 위로 이동 반복

**예시:** Max-Heap [90, 70, 60, 50, 30, 20]에 80 삽입

```
1단계: 80을 끝에 추가 → [..., 20, 80]
       80의 부모는 70 (인덱스 6의 부모 = 인덱스 3 = 60)
       실제로 인덱스 7, 부모 인덱스 3 = 60
       80 > 60 → 교환

2단계: 80이 인덱스 3으로 이동
       80의 부모는 인덱스 1 = 90
       80 < 90 → 정지!
```

시간 복잡도: $O(\log n)$ (트리 높이만큼 올라감)

## 힙 삭제 (Sift-Down / Heapify-Down)

힙에서는 항상 **루트(최댓값 또는 최솟값)**만 삭제합니다.

**Sift-Down(시프트 다운)**: "체로 쳐서 내려간다"는 뜻. 마지막 원소가 제자리를 찾아 내려가는 과정.

과정:
1. 루트를 제거하고 배열의 **마지막 원소**를 루트 자리로 이동
2. 자식 노드 중 더 큰(Max-Heap) 자식과 비교
3. 힙 성질 위반 시 교환
4. 힙 성질이 만족될 때까지 아래로 이동 반복

시간 복잡도: $O(\log n)$

## 힙 정렬 (Heap Sort)

**힙 정렬(Heap Sort, 힙 소트)**은 힙 자료구조를 이용한 정렬 알고리즘입니다.

**과정:**
1. 입력 배열 전체로 Max-Heap 구성: $O(n)$
2. 루트(최댓값)를 배열 맨 끝 원소와 교환
3. 힙 크기를 1 감소 (맨 끝 원소는 정렬 완료)
4. 새 루트에서 Sift-Down 수행
5. 2~4를 n-1회 반복

예시: [5, 3, 8, 1] 힙 정렬

```
Max-Heap 구성: [8, 3, 5, 1]
1회: 8과 1 교환 → [1, 3, 5, | 8], Sift-Down → [5, 3, 1, | 8]
2회: 5와 1 교환 → [1, 3, | 5, 8], Sift-Down → [3, 1, | 5, 8]
3회: 3과 1 교환 → [1, | 3, 5, 8], 완료!
결과: [1, 3, 5, 8]
```

시간 복잡도: $O(n \log n)$ (최선, 평균, 최악 모두 동일!)
공간 복잡도: $O(1)$ (제자리 정렬, in-place sort)

| 항목 | 힙 정렬 |
| --- | --- |
| 시간 복잡도 | $O(n \log n)$ (항상 동일) |
| 공간 복잡도 | $O(1)$ |
| 안정성 | 불안정 정렬 |
| 특징 | 최악의 경우에도 $O(n \log n)$ 보장 |

## 우선순위 큐와 힙

힙은 **우선순위 큐(Priority Queue)**의 가장 효율적인 구현체입니다.

| 연산 | 복잡도 | 설명 |
| --- | --- | --- |
| 삽입(push) | $O(\log n)$ | Sift-Up 수행 |
| 최댓값/최솟값 조회(peek) | $O(1)$ | 루트 바로 접근 |
| 최댓값/최솟값 삭제(pop) | $O(\log n)$ | Sift-Down 수행 |

## 핵심 정리

- **Max-Heap**: 부모 >= 자식, **Min-Heap**: 부모 &lt;= 자식
- 힙은 완전 이진트리이며 배열로 표현합니다.
- **삽입**: 끝에 추가 후 Sift-Up → $O(\log n)$
- **삭제**: 루트 제거, 마지막 원소를 루트로 이동 후 Sift-Down → $O(\log n)$
- **힙 정렬**: $O(n \log n)$, 제자리 정렬, 불안정 정렬
