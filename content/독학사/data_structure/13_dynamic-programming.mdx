## 왜 동적 프로그래밍이 필요한가?

피보나치 수열을 재귀로 계산해 봅시다.

```
fib(5) = fib(4) + fib(3)
fib(4) = fib(3) + fib(2)
fib(3) = fib(2) + fib(1)
```

보이시나요? `fib(3)`이 두 번, `fib(2)`가 세 번 계산됩니다. n이 커질수록 중복 계산이 폭발적으로 늘어납니다($O(2^n)$).

"이미 계산한 결과를 저장해두고 다시 쓰면 되지 않을까?" 이것이 **동적 프로그래밍(Dynamic Programming, DP, 디피)**의 핵심 아이디어입니다.

쉽게 말하면: DP = 계산 결과를 메모장에 적어두고 같은 계산이 필요할 때 메모를 참조하는 것

## 동적 프로그래밍이란?

**동적 프로그래밍(Dynamic Programming, DP)**은 큰 문제를 겹치는 작은 부분 문제들로 나누어 풀고, 그 결과를 저장(메모)하여 재사용하는 알고리즘 설계 기법입니다.

**DP가 적용되려면 두 가지 성질이 필요합니다:**

| 성질 | 설명 | 예시 |
| --- | --- | --- |
| 최적 부분 구조 (Optimal Substructure) | 최적해가 부분 문제의 최적해로 구성됨 | 최단경로의 부분 경로도 최단경로 |
| 겹치는 부분 문제 (Overlapping Subproblems) | 동일한 부분 문제가 반복적으로 등장함 | fib(3)이 여러 번 등장 |

**분할 정복(Divide and Conquer, 디바이드 앤 컨쿼)과의 차이:**
- 분할 정복: 부분 문제가 **겹치지 않음** (퀵 정렬, 합병 정렬)
- 동적 프로그래밍: 부분 문제가 **겹침** (피보나치, 배낭 문제)

## 두 가지 구현 방법

| 구분 | 메모이제이션(Memoization) | 타뷸레이션(Tabulation) |
| --- | --- | --- |
| 방향 | 큰 문제 → 작은 문제 | 작은 문제 → 큰 문제 |
| 구현 방식 | 재귀 + 캐싱(메모 저장) | 반복문 + 테이블 채우기 |
| 별명 | Top-down(탑다운) | Bottom-up(바텀업) |
| 계산 | 필요한 것만 계산 | 모든 부분 문제 계산 |

**메모이제이션(Memoization, 메모아이제이션)**: 계산 결과를 memo(메모)에 저장. "이미 풀었으면 메모 참조!"
- 메모리(Memory) + 메모(Memo)를 합친 단어

**타뷸레이션(Tabulation, 타뷸레이션)**: Table(표)에 작은 것부터 채워 올라감. "작은 것부터 차근차근!"

## 피보나치 수열

$F(n) = F(n-1) + F(n-2)$, 단 $F(0) = 0, F(1) = 1$

**방법 1 - 순수 재귀:** 지수 시간 $O(2^n)$ — 같은 계산을 반복해서 매우 느림

**방법 2 - 메모이제이션(Top-down):**

```python
memo = {}
def fib(n):
    if n in memo: return memo[n]  # 이미 계산했으면 반환
    if n <= 1: return n
    memo[n] = fib(n-1) + fib(n-2)
    return memo[n]
```

시간 복잡도: $O(n)$ (각 n을 한 번만 계산)

**방법 3 - 타뷸레이션(Bottom-up):**

```
dp[0] = 0, dp[1] = 1
i=2: dp[2] = dp[1] + dp[0] = 1
i=3: dp[3] = dp[2] + dp[1] = 2
i=4: dp[4] = dp[3] + dp[2] = 3
i=5: dp[5] = dp[4] + dp[3] = 5
```

시간 복잡도: $O(n)$

## 배낭 문제 (0/1 Knapsack Problem)

**배낭 문제(Knapsack Problem, 냅색 프라블럼)**: $n$개의 물건과 용량 $W$인 배낭이 있을 때, 가치의 합을 최대로 하는 물건 조합을 찾는 문제.

- **0/1 배낭 문제**: 각 물건은 넣거나(1) 안 넣거나(0), 즉 반만 넣을 수 없음

비유: 등산 배낭에 짐을 싸는데, 무게 제한 내에서 가장 가치 있는 것들을 골라야 합니다.

**DP 테이블 정의:** `dp[i][w]` = 처음 i개의 물건 중 무게 한도 w 이내에서 얻을 수 있는 최대 가치

**점화식:**
$$dp[i][w] = \max(dp[i-1][w],\ dp[i-1][w-w_i] + v_i)$$

- 왼쪽($dp[i-1][w]$): i번째 물건을 **안 넣는** 경우
- 오른쪽($dp[i-1][w-w_i] + v_i$): i번째 물건을 **넣는** 경우 (무게 $w_i$, 가치 $v_i$)

시간 복잡도: $O(nW)$

## 최장 공통 부분 수열 (LCS)

**LCS(Longest Common Subsequence, 롱이스트 커먼 서브씨퀀스)**: 두 문자열에 공통으로 나타나는 가장 긴 부분 수열의 길이.

- **부분 수열(Subsequence)**: 순서는 지키되 연속일 필요는 없는 부분 문자열

예시: "ABCBDAB"와 "BDCABA"의 LCS = "BCBA" 또는 "BDAB" (길이 4)

**점화식:**
$$dp[i][j] = \begin{cases} dp[i-1][j-1] + 1 & \text{if } s1[i] == s2[j] \\ \max(dp[i-1][j],\ dp[i][j-1]) & \text{otherwise} \end{cases}$$

시간 복잡도: $O(mn)$ ($m$, $n$은 두 문자열의 길이)

## 대표 DP 문제 정리

| 문제 | 시간 복잡도 | 핵심 아이디어 |
| --- | --- | --- |
| 피보나치 수열 | $O(n)$ | 이전 두 값의 합 |
| 배낭 문제 | $O(nW)$ | 넣기/안 넣기 최대 |
| 최장 공통 부분 수열(LCS) | $O(mn)$ | 문자 일치 여부 |
| 최장 증가 부분 수열(LIS) | $O(n^2)$ 또는 $O(n \log n)$ | 이전 값들과 비교 |
| 행렬 체인 곱셈 | $O(n^3)$ | 분할 위치 최적화 |

## 핵심 정리

- **DP**는 최적 부분 구조와 겹치는 부분 문제 성질이 있을 때 적용합니다.
- **메모이제이션(Top-down)**: 재귀 + 결과 캐싱, 필요한 것만 계산
- **타뷸레이션(Bottom-up)**: 작은 문제부터 테이블로 채워 올라감
- DP는 재귀의 지수 복잡도를 다항식 복잡도로 낮출 수 있습니다.
- 분할 정복과의 차이: 겹치는 부분 문제의 유무
