## 왜 알고리즘 분석이 필요한가?

전화번호부에서 "홍길동"을 찾는 두 가지 방법:
1. **순차 탐색:** 첫 페이지부터 한 명씩 확인 — 최악의 경우 수백만 번 비교
2. **이진 탐색:** 중간 페이지를 보고 앞/뒤 절반을 버리기 반복 — 약 20번만 비교하면 됩니다.

10,000,000명 중에서 찾을 때, 순차 탐색은 최대 천만 번, 이진 탐색은 최대 23번만 확인하면 됩니다. 이 차이가 알고리즘 효율성의 핵심입니다. 이를 측정하는 도구가 복잡도(complexity) 분석입니다.

## 복잡도의 종류

**시간 복잡도(Time Complexity):** 알고리즘이 완료될 때까지 수행하는 **연산 횟수**. 실제 시간이 아닌 실행 단계(step) 수를 셉니다.

**공간 복잡도(Space Complexity):** 알고리즘이 사용하는 **메모리 양**. 보통 입력 크기와의 관계로 표현합니다.

현대에는 메모리가 저렴해 시간 복잡도가 더 중요하게 다뤄집니다.

## Big-O, Big-Ω, Big-Θ 표기법

**쉽게 말하면:** 알고리즘의 성능을 "입력 크기 n이 클 때 어떻게 변하는가"로 표현하는 수학적 표기입니다.

**Big-O (빅 오) — 상한(Upper Bound):**

$$f(n) = O(g(n)) \iff \exists c > 0, n_0: \forall n \geq n_0, f(n) \leq c \cdot g(n)$$

**쉽게 말하면:** "충분히 큰 n에 대해 f(n)은 c×g(n)보다 항상 작다." 최악의 경우(worst case) 성능의 상한입니다.

<Callout type="info">
  **비유:** "이 택배는 최대 3일 안에 도착한다"처럼, Big-O는 "이 알고리즘은 최대 이 정도 시간이 걸린다"는 보장입니다.
</Callout>

**Big-Ω (빅 오메가) — 하한(Lower Bound):**

$$f(n) = \Omega(g(n)) \iff \exists c > 0, n_0: \forall n \geq n_0, f(n) \geq c \cdot g(n)$$

**쉽게 말하면:** "f(n)은 g(n)보다 항상 크거나 같다." 최선의 경우(best case) 성능의 하한, 또는 알고리즘이 이것보다 빠를 수 없다는 한계입니다.

**Big-Θ (빅 세타) — 정확한 범위(Tight Bound):**

$$f(n) = \Theta(g(n)) \iff f(n) = O(g(n)) \text{ 이고 } f(n) = \Omega(g(n))$$

**쉽게 말하면:** "f(n)은 g(n)과 같은 속도로 증가한다." 상한과 하한이 같을 때 쓰며, 알고리즘의 정확한 성능 등급을 나타냅니다.

## 복잡도의 증가 순서

| 증가율 | 표기 | 예시 | n=100일 때 |
| --- | --- | --- | --- |
| 상수 | $O(1)$ | 배열 인덱싱 | 1 |
| 로그 | $O(\log n)$ | 이진 탐색 | 7 |
| 선형 | $O(n)$ | 순차 탐색 | 100 |
| 선형 로그 | $O(n \log n)$ | 병합 정렬 | 700 |
| 이차 | $O(n^2)$ | 버블 정렬 | 10,000 |
| 삼차 | $O(n^3)$ | 행렬 곱셈 | 1,000,000 |
| 지수 | $O(2^n)$ | 브루트포스 탐색 | $10^{30}$ |
| 팩토리얼 | $O(n!)$ | 순열 생성 | $10^{157}$ |

**증가 속도 순서:** $O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$

## Big-O 계산 규칙

**상수 계수 무시:** $O(5n) = O(n)$, $O(100) = O(1)$

**지배 항만 남기기:** $O(n^2 + n + 1) = O(n^2)$ (n이 충분히 크면 n²이 나머지를 압도)

**중첩 반복문:** 이중 반복문 = $O(n^2)$, 삼중 = $O(n^3)$

## 주요 정렬 알고리즘 복잡도 비교

| 알고리즘 | 최선 | 평균 | 최악 | 공간 | 특징 |
| --- | --- | --- | --- | --- | --- |
| 버블 정렬 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 단순하지만 느림 |
| 선택 정렬 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 항상 n² |
| 삽입 정렬 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 거의 정렬된 경우 빠름 |
| 퀵 정렬 | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | 평균적으로 가장 빠름 |
| 병합 정렬 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | 안정적, 추가 메모리 필요 |
| 이진 탐색 | $O(1)$ | $O(\log n)$ | $O(\log n)$ | $O(1)$ | 정렬된 배열에서만 사용 가능 |

## 점화식과 마스터 정리

분할 정복(divide and conquer) 알고리즘의 복잡도는 점화식으로 표현됩니다.

**일반 형태:** $T(n) = aT(n/b) + f(n)$

- $a$: 재귀 호출 횟수
- $b$: 문제 크기를 나누는 비율
- $f(n)$: 분할/병합 비용

**마스터 정리(Master Theorem):**

$p = \log_b a$ (분기점 지수)라 할 때:

| 경우 | 조건 | 결론 | 직관적 의미 |
| --- | --- | --- | --- |
| Case 1 | $f(n) = O(n^{p-\epsilon})$ | $T(n) = \Theta(n^p)$ | 재귀 부분이 지배 |
| Case 2 | $f(n) = \Theta(n^p)$ | $T(n) = \Theta(n^p \log n)$ | 재귀와 분할 비용이 비슷 |
| Case 3 | $f(n) = \Omega(n^{p+\epsilon})$ | $T(n) = \Theta(f(n))$ | 분할 비용이 지배 |

**예시 — 이진 탐색:** $T(n) = T(n/2) + O(1)$

$a=1, b=2, p = \log_2 1 = 0$, $f(n) = O(1) = O(n^0)$이므로 Case 2: $T(n) = \Theta(\log n)$

**예시 — 병합 정렬:** $T(n) = 2T(n/2) + O(n)$

$a=2, b=2, p = \log_2 2 = 1$, $f(n) = O(n) = O(n^1)$이므로 Case 2: $T(n) = \Theta(n \log n)$

## 핵심 정리

- 시간 복잡도: 연산 횟수 (실제 시간 X, 입력 크기 n에 대한 함수)
- Big-O: 상한(최악), Big-Ω: 하한(최선), Big-Θ: 정확한 범위
- 증가 순서: $O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n)$
- 상수 계수, 낮은 차수 항은 무시
- 마스터 정리: 분할 정복 알고리즘의 복잡도 계산
