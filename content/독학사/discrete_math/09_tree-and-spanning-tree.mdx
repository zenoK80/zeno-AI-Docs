## 왜 트리가 필요한가?

컴퓨터의 파일 시스템(폴더 구조), 회사의 조직도, 웹페이지의 DOM 구조, 프로그래밍 언어의 파스 트리 — 모두 트리(tree) 구조입니다. 트리는 "사이클 없는 계층적 구조"를 표현하는 가장 자연스러운 방법입니다.

<Callout type="info">
  **비유:** 트리는 나무와 같습니다. 뿌리(root)에서 줄기(내부 노드)를 따라 가지치기하면 잎(리프)에 도달합니다. 나무가 고리(사이클)를 만들지 않는 것처럼, 자료구조의 트리도 사이클이 없습니다.
</Callout>

## 트리의 정의와 성질

**쉽게 말하면:** 트리(tree)는 연결되어 있고 사이클이 없는 그래프입니다. "사이클 없이 모든 점이 연결된 최소 그래프"입니다.

**트리(Tree)** 는 연결되어 있고 사이클(cycle)이 없는 단순 그래프입니다.

**트리의 성질 (n개의 정점일 때):**

| 성질 | 내용 |
| --- | --- |
| 간선 수 | 정확히 $n-1$개 |
| 경로 | 임의의 두 정점 사이에 경로가 유일하게 존재 |
| 최소 연결 | 어떤 간선을 제거해도 연결이 끊어짐 |
| 사이클 없음 | 어떤 간선을 추가해도 사이클이 생김 |

**왜 간선이 n-1개인가?** n개 정점을 연결하려면 최소 n-1개 간선이 필요하고, 사이클이 없으려면 n-1개가 최대입니다. 딱 맞게 n-1개입니다.

**동치 조건 (아래 중 하나라도 성립하면 트리):**
- 연결 그래프이고 간선 수 = n-1
- 연결 그래프이고 사이클 없음
- 사이클이 없고 간선 수 = n-1
- 임의의 두 정점 사이에 경로가 정확히 하나 있음

## 루트 트리 (Rooted Tree)

**쉽게 말하면:** 루트 트리(rooted tree)는 특정 정점을 "뿌리(root)"로 지정하여 계층 구조를 만든 트리입니다. 조직도처럼 위아래 방향이 있습니다.

특정 정점을 루트(root)로 지정한 트리입니다.

| 용어 | 영어 | 설명 |
| --- | --- | --- |
| 루트 | Root | 최상위 정점 |
| 부모 | Parent | 바로 위 정점 |
| 자식 | Child | 바로 아래 정점 |
| 형제 | Sibling | 같은 부모를 가진 정점들 |
| 리프(단말 노드) | Leaf | 자식이 없는 정점 |
| 내부 정점 | Internal Vertex | 자식이 있는 정점 |
| 레벨 | Level | 루트에서 해당 정점까지의 거리 |
| 높이 | Height | 트리의 최대 레벨 |

**이진 트리(Binary Tree):** 각 정점이 최대 2개의 자식을 가지는 트리
- **완전 이진 트리(Complete Binary Tree):** 마지막 레벨 제외 모두 가득 차 있음
- **포화 이진 트리(Full Binary Tree):** 모든 정점이 0개 또는 2개의 자식을 가짐

## 신장 트리 (Spanning Tree)

**쉽게 말하면:** 신장 트리(spanning tree)는 원래 그래프에서 일부 간선을 제거하여 트리를 만든 것입니다. 모든 도시(정점)는 유지하되 불필요한 도로(간선)를 최소화한 것입니다.

그래프 $G$의 **신장 트리**는 G의 모든 정점을 포함하는 부분 그래프이면서 트리인 것입니다.

- 연결 그래프에 항상 신장 트리가 존재합니다
- n개의 정점을 가지면 간선 수 = n-1
- 한 그래프에 신장 트리는 여러 개일 수 있습니다

## 최소 비용 신장 트리 (MST, Minimum Spanning Tree)

**쉽게 말하면:** 최소 비용 신장 트리(MST, Minimum Spanning Tree)는 가중 그래프에서 모든 정점을 연결하는 신장 트리 중 간선 가중치의 합이 가장 작은 것입니다. "가장 저렴한 전국 네트워크 설계"입니다.

**활용 예:** 도시 간 최소 비용 도로 연결, 통신 네트워크 최적화, 전력망 설계

### Kruskal 알고리즘

**쉽게 말하면:** 크루스칼(Kruskal) 알고리즘은 "가장 싼 간선부터 선택하되, 사이클이 생기면 건너뛴다"는 방식입니다. 전국 도로 중 가장 저렴한 것부터 선택하는 것과 같습니다.

**탐욕(Greedy) 방법:** 가중치가 작은 간선부터 선택하되, 사이클을 형성하면 제외합니다.

**단계:**
1. 모든 간선을 가중치 기준으로 오름차순 정렬
2. 가중치가 가장 작은 간선부터 선택
3. 선택된 간선이 사이클을 형성하면 제외
4. $n-1$개의 간선이 선택될 때까지 반복

**사이클 판별:** 유니온-파인드(Union-Find, 분리 집합) 자료구조 사용
- Find: 두 정점이 같은 집합에 있는지 확인
- Union: 두 집합을 합침

**시간 복잡도:** $O(E \log E)$ — 간선 정렬이 지배

### Prim 알고리즘

**쉽게 말하면:** 프림(Prim) 알고리즘은 "한 정점에서 시작하여 가장 가까운 정점을 하나씩 추가"하는 방식입니다. 도시 하나에서 출발하여 가장 가까운 도시를 연결하는 것과 같습니다.

**탐욕 방법:** 하나의 정점에서 시작하여 MST를 점진적으로 확장합니다.

**단계:**
1. 임의의 정점에서 시작 (MST에 포함)
2. 현재 MST에 속한 정점과 속하지 않은 정점을 연결하는 최소 가중치 간선 선택
3. 해당 간선과 연결된 새 정점을 MST에 추가
4. 모든 정점이 MST에 포함될 때까지 반복

**시간 복잡도:** $O(V^2)$ (단순 구현), $O(E \log V)$ (우선순위 큐 사용)

### Kruskal vs Prim 비교

| 항목 | Kruskal | Prim |
| --- | --- | --- |
| 선택 기준 | 간선 기준 (전체 정렬) | 정점 기준 (인접 확장) |
| 적합 그래프 | 희소 그래프 (간선이 적음) | 밀집 그래프 (간선이 많음) |
| 기본 복잡도 | $O(E \log E)$ | $O(V^2)$ |
| 사이클 판별 | Union-Find 필요 | 필요 없음 |
| 두 알고리즘의 결과 | 동일한 최소 가중치 합 (MST는 여러 개 가능) |

**희소 그래프(Sparse Graph):** 간선이 적은 그래프 (E가 V에 비해 작음)
**밀집 그래프(Dense Graph):** 간선이 많은 그래프 (E가 V²에 가까움)

## MST의 응용

- 네트워크 설계 (전화망, 인터넷망, 전력망)
- 클러스터링 (데이터 그룹화)
- 근사 알고리즘 (TSP, 순회 세일즈맨 문제 등)

## 핵심 정리

- 트리: 연결, 비순환, $n$정점 → $n-1$ 간선
- 임의의 두 정점 사이 경로가 유일하게 존재
- MST: 모든 간선 가중치 합이 최소인 신장 트리
- Kruskal: 간선을 가중치 오름차순 정렬 후 사이클 없는 최소 간선 선택
- Prim: 정점에서 시작하여 최소 가중치 간선으로 확장
