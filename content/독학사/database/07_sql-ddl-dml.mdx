## SQL의 두 갈래 — DDL과 DML

> **쉽게 말하면:** DDL은 "테이블이라는 그릇 자체를 만들고 바꾸는" 명령이고, DML은 "그 그릇 안의 데이터를 다루는" 명령입니다.

<Table>
  <thead>
    <tr><th>구분</th><th>전체 이름</th><th>역할</th></tr>
  </thead>
  <tbody>
    <tr><td>DDL</td><td>Data Definition Language(데이터 정의어)</td><td>테이블 구조(스키마) 자체를 정의·변경·삭제</td></tr>
    <tr><td>DML</td><td>Data Manipulation Language(데이터 조작어)</td><td>테이블 안의 실제 데이터를 삽입·조회·수정·삭제</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **04번 문서와의 연결:** DDL로 만드는 테이블 구조는 04번 문서의 개념 스키마에 해당하고, DML은 그 구조 안에서 실제 데이터를 다루는 작업입니다.
</Callout>

## DDL — CREATE, ALTER, DROP

### CREATE TABLE — 테이블 만들기

```sql
CREATE TABLE 학생 (
  학번 INT PRIMARY KEY,
  이름 VARCHAR(20) NOT NULL,
  학과 VARCHAR(30)
);
```

**해석:** "학생"이라는 이름의 테이블을 만들며, `학번`을 정수형(INT) 기본키(PRIMARY KEY)로, `이름`을 최대 20자 문자열(VARCHAR)이면서 반드시 값이 있어야 함(NOT NULL)으로, `학과`를 최대 30자 문자열로 정의합니다.

<Table>
  <thead>
    <tr><th>제약조건 키워드</th><th>의미</th></tr>
  </thead>
  <tbody>
    <tr><td>PRIMARY KEY</td><td>01번 문서의 기본키로 지정</td></tr>
    <tr><td>NOT NULL</td><td>이 열은 반드시 값이 있어야 함(비어있을 수 없음)</td></tr>
    <tr><td>FOREIGN KEY</td><td>01번 문서의 외래키로 지정</td></tr>
    <tr><td>UNIQUE</td><td>이 열의 값이 중복되면 안 됨(기본키는 아니지만 유일해야 하는 열)</td></tr>
  </tbody>
</Table>

**외래키를 포함한 예시:**

```sql
CREATE TABLE 수강 (
  수강번호 INT PRIMARY KEY,
  학번 INT,
  과목명 VARCHAR(30),
  FOREIGN KEY (학번) REFERENCES 학생(학번)
);
```

### ALTER TABLE — 테이블 구조 바꾸기

```sql
ALTER TABLE 학생 ADD COLUMN 이메일 VARCHAR(50);
```

**해석:** 이미 만들어진 "학생" 테이블에 "이메일"이라는 새로운 열을 추가합니다.

### DROP TABLE — 테이블 삭제

```sql
DROP TABLE 학생;
```

<Callout type="warning">
  **자주 틀리는 점:** DROP TABLE은 테이블 구조와 그 안의 모든 데이터를 **영구히 삭제**합니다. 이는 DML의 DELETE(아래에서 다룸, 특정 행만 삭제)와는 전혀 다른, 훨씬 강력하고 되돌리기 어려운 명령입니다.
</Callout>

## DML — INSERT, UPDATE, DELETE, SELECT

### INSERT — 데이터 추가

```sql
INSERT INTO 학생 (학번, 이름, 학과) VALUES (1001, '김민준', '컴퓨터공학');
```

**해석:** 학생 테이블에 학번 1001, 이름 김민준, 학과 컴퓨터공학인 새 행을 하나 추가합니다.

### UPDATE — 데이터 수정

```sql
UPDATE 학생 SET 학과 = '소프트웨어학' WHERE 학번 = 1001;
```

**해석:** 학번이 1001인 학생의 학과를 "소프트웨어학"으로 수정합니다.

<Callout type="warning">
  **자주 틀리는 점:** UPDATE 문에서 WHERE 절을 빠뜨리면, 테이블의 **모든 행**이 한꺼번에 수정되는 매우 위험한 결과를 낳습니다. `UPDATE 학생 SET 학과='소프트웨어학';`(WHERE 없음)을 실행하면 모든 학생의 학과가 한꺼번에 바뀝니다. WHERE 절은 03번 문서의 SELECT뿐 아니라 UPDATE·DELETE에서도 "대상을 정확히 좁히는" 매우 중요한 역할을 합니다.
</Callout>

### DELETE — 데이터 삭제

```sql
DELETE FROM 학생 WHERE 학번 = 1001;
```

**해석:** 학번이 1001인 행만 삭제합니다. 테이블 구조 자체는 그대로 남습니다(DROP TABLE과의 차이).

## 핵심 정리

- **DDL**(CREATE·ALTER·DROP): 테이블의 구조 자체를 정의·변경·삭제.
- **DML**(INSERT·UPDATE·DELETE·SELECT): 테이블 안의 실제 데이터를 다룸.
- **PRIMARY KEY**, **NOT NULL**, **FOREIGN KEY** 등 제약조건을 CREATE TABLE에서 함께 정의.
- UPDATE·DELETE는 WHERE 절 없이 실행하면 전체 행에 영향을 주므로 각별히 주의해야 함.
- DROP TABLE(구조+데이터 영구 삭제)과 DELETE(데이터만 삭제, 구조는 유지)는 전혀 다른 명령.
