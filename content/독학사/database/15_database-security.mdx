## 데이터베이스 보안의 목표

**CIA 트리아드(CIA Triad):**

| 목표 | 설명 |
|------|------|
| **기밀성 (Confidentiality)** | 권한 없는 사용자의 데이터 접근 방지 |
| **무결성 (Integrity)** | 데이터의 정확성과 일관성 유지 |
| **가용성 (Availability)** | 권한 있는 사용자가 언제든지 데이터에 접근 가능 |

## 접근 제어 (Access Control)

### DAC (Discretionary Access Control, 임의 접근 제어)

데이터 **소유자**가 자신의 재량(discretion)으로 접근 권한을 부여합니다.

**SQL 구현:**
```sql
-- 권한 부여 (GRANT)
GRANT SELECT, INSERT ON employees TO user_kim;
GRANT SELECT ON employees TO user_lee WITH GRANT OPTION;

-- 권한 취소 (REVOKE)
REVOKE INSERT ON employees FROM user_kim;
```

**특징:**
- 유연하고 구현이 단순
- 트로이 목마 공격에 취약 (권한을 부여받은 사용자가 악의적 프로그램 실행)
- 대부분의 RDBMS 기본 방식

### MAC (Mandatory Access Control, 강제 접근 제어)

**시스템 관리자**가 중앙에서 보안 레이블로 접근을 강제합니다.

**보안 레이블:**
- 객체(데이터): 보안 등급 부여 (기밀, 비밀, 일반 등)
- 주체(사용자): 보안 허가 등급 부여

**Bell-LaPadula 모델 규칙:**
- **No Read Up:** 낮은 등급 사용자는 높은 등급 데이터 읽기 불가
- **No Write Down:** 높은 등급 사용자는 낮은 등급에 쓰기 불가

**특징:**
- 매우 강력한 보안 (군사, 정부 시스템)
- 유연성 부족

### RBAC (Role-Based Access Control, 역할 기반 접근 제어)

사용자에게 **역할(Role)**을 부여하고, 역할에 권한을 할당합니다.

```sql
-- 역할 생성
CREATE ROLE hr_manager;
CREATE ROLE hr_viewer;

-- 역할에 권한 부여
GRANT SELECT, INSERT, UPDATE ON employees TO hr_manager;
GRANT SELECT ON employees TO hr_viewer;

-- 사용자에게 역할 부여
GRANT hr_manager TO user_kim;
GRANT hr_viewer TO user_lee;
```

**특징:**
- 사용자 수가 많을 때 관리 효율적
- 역할 변경으로 일괄 권한 변경 가능
- 최소 권한 원칙(Principle of Least Privilege) 적용 용이
- 현대 DBMS와 애플리케이션의 기본 방식

### 접근 제어 비교

| 항목 | DAC | MAC | RBAC |
|------|-----|-----|------|
| 권한 결정자 | 데이터 소유자 | 시스템 | 역할/관리자 |
| 유연성 | 높음 | 낮음 | 중간 |
| 보안 강도 | 낮음 | 매우 높음 | 높음 |
| 관리 용이성 | 어려움(대규모) | 복잡 | 쉬움 |
| 사용 환경 | 일반 DB | 군사/정부 | 기업 시스템 |

## SQL 인젝션 (SQL Injection)

사용자 입력에 악의적인 SQL 코드를 삽입하여 데이터베이스를 공격하는 기법입니다.

**공격 예시:**

```
사용자 입력 (username): admin' OR '1'='1

생성되는 SQL:
SELECT * FROM users
WHERE username = 'admin' OR '1'='1'
AND password = '...'

→ 항상 참이 되어 모든 사용자 정보 반환
```

**더 위험한 예:**
```
사용자 입력: '; DROP TABLE users; --

생성되는 SQL:
SELECT * FROM users WHERE id = '';
DROP TABLE users;
-- 나머지 쿼리 주석 처리
```

### SQL 인젝션 방어 기법

**1. 준비된 구문 (Prepared Statement) / 파라미터화 쿼리**

```java
// 취약한 코드
String query = "SELECT * FROM users WHERE id = '" + userId + "'";

// 안전한 코드 (Prepared Statement)
PreparedStatement stmt = conn.prepareStatement(
    "SELECT * FROM users WHERE id = ?");
stmt.setString(1, userId);
```

SQL 구조와 데이터를 분리하여 사용자 입력이 SQL 코드로 해석되지 않음.

**2. 저장 프로시저 (Stored Procedure) 활용**

**3. 입력값 유효성 검사 (Input Validation)**
- 허용 목록(Allowlist) 방식으로 안전한 문자만 허용
- 특수 문자 이스케이프 처리

**4. 최소 권한 원칙 (Least Privilege)**
- 애플리케이션 DB 계정에 필요한 최소한의 권한만 부여

**5. WAF (Web Application Firewall)**
- SQL 인젝션 패턴 탐지 및 차단

## 감사 추적 (Audit Trail)

데이터베이스에서 발생하는 모든 주요 활동을 **기록**합니다.

**감사 대상:**
- 로그인/로그아웃 시도
- 데이터 접근 (특히 민감 데이터)
- 데이터 변경 (INSERT/UPDATE/DELETE)
- 권한 변경 (GRANT/REVOKE)
- 스키마 변경 (DDL)

**SQL 감사 설정 예:**
```sql
-- Oracle
AUDIT SELECT ON employees BY ACCESS;
AUDIT INSERT, UPDATE, DELETE ON employees BY ACCESS;

-- 실패한 로그인 감사
AUDIT SESSION WHENEVER NOT SUCCESSFUL;
```

**감사 로그 활용:**
- 보안 사고 원인 분석 (포렌식)
- 규정 준수 (GDPR, 개인정보보호법)
- 비정상 접근 탐지

## 데이터 암호화

### 저장 데이터 암호화 (Encryption at Rest)

데이터베이스에 저장된 데이터를 암호화합니다.

- **TDE (Transparent Data Encryption):** 데이터 파일 전체를 자동으로 암호화
- **컬럼 수준 암호화:** 특정 민감 컬럼(주민번호, 카드번호 등)만 암호화

```sql
-- 컬럼 암호화 예 (개념적)
SELECT AES_DECRYPT(ssn, 'key') AS ssn FROM users;
```

### 전송 데이터 암호화 (Encryption in Transit)

클라이언트와 DB 서버 간 통신을 SSL/TLS로 암호화합니다.

### 해시와 암호화 구분

- **암호화:** 복호화 가능 (대칭/비대칭 키 사용)
- **해시:** 단방향, 복호화 불가 (비밀번호 저장에 사용)

```sql
-- 비밀번호는 해시로 저장 (복호화 불필요)
INSERT INTO users (username, password_hash)
VALUES ('user1', SHA2('password123', 256));
```

## 개인정보 보호

**데이터 마스킹:**
```sql
-- 카드번호 마스킹 (실제 데이터는 보존)
SELECT CONCAT('****-****-****-', RIGHT(card_no, 4)) AS masked_card
FROM payments;
```

**행 수준 보안 (Row-Level Security):** 사용자별로 접근 가능한 행을 제한

## 핵심 정리

- DAC: 소유자가 권한 부여, GRANT/REVOKE
- MAC: 시스템이 강제, 보안 레이블 기반, 군사/정부용
- RBAC: 역할 단위 권한 관리, 기업 표준
- SQL 인젝션: 입력에 SQL 삽입, Prepared Statement로 방어
- 감사 추적: 모든 DB 활동 기록, 사고 분석/규정 준수
- TDE: 저장 데이터 파일 투명 암호화
