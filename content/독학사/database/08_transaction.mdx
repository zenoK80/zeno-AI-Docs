## 트랜잭션이란?

**트랜잭션**(Transaction)은 데이터베이스에서 하나의 논리적 작업 단위입니다.

**예시: 은행 이체 **(A → B, 10만원)

```
BEGIN TRANSACTION;
  UPDATE 계좌 SET 잔액 = 잔액 - 100000 WHERE 계좌번호 = 'A';
  UPDATE 계좌 SET 잔액 = 잔액 + 100000 WHERE 계좌번호 = 'B';
COMMIT;
-- 중간에 오류 발생 시 → ROLLBACK; (두 UPDATE 모두 취소)
```

## ACID 특성

| 특성 | 이름 | 설명 |
|------|------|------|
| **A** | 원자성 (Atomicity) | 모두 실행되거나 모두 취소 (All or Nothing) |
| **C** | 일관성 (Consistency) | 트랜잭션 전후 데이터 무결성 유지 |
| **I** | 격리성 (Isolation) | 동시 실행 트랜잭션이 서로 간섭하지 않음 |
| **D** | 지속성 (Durability) | 완료된 트랜잭션은 영구적으로 반영 |

## 트랜잭션 상태

```
활성(Active)
  ↓ 작업 완료
부분 완료(Partially Committed)
  ↓ 커밋 성공 / 오류 발생
완료(Committed) / 실패(Failed)
                     ↓
                  철회(Aborted) → ROLLBACK
```

## 동시성 제어의 필요성

여러 트랜잭션이 동시에 실행될 때 발생하는 문제:

| 문제 | 설명 |
|------|------|
| **오손 읽기 **(Dirty Read) | 다른 트랜잭션의 미확정(아직 커밋 안 된) 데이터 읽기 |
| **비반복 읽기 **(Non-repeatable Read) | 같은 데이터를 두 번 읽었는데 값이 다름 |
| **팬텀 읽기 **(Phantom Read) | 같은 범위 쿼리를 두 번 실행했는데 행 수가 다름 |

## 트랜잭션 격리 수준

| 격리 수준 | Dirty Read | Non-repeatable Read | Phantom Read |
|---------|-----------|--------------------|----|
| **READ UNCOMMITTED** | 발생 | 발생 | 발생 |
| **READ COMMITTED** | 방지 | 발생 | 발생 |
| **REPEATABLE READ** | 방지 | 방지 | 발생 |
| **SERIALIZABLE** | 방지 | 방지 | 방지 |

- 격리 수준이 높을수록 동시성은 낮아지고 안정성은 높아집니다.
- MySQL InnoDB 기본값: REPEATABLE READ
- Oracle 기본값: READ COMMITTED

## 동시성 제어 기법

### 2단계 잠금 (2PL, Two-Phase Locking)

트랜잭션을 **확장 단계**와 **축소 단계**로 나눕니다.

```
확장 단계: 잠금 획득만 가능 (잠금 해제 불가)
축소 단계: 잠금 해제만 가능 (잠금 획득 불가)
```

- 데드락(교착 상태) 발생 가능

### 잠금 종류

| 잠금 | 설명 | 공존 |
|------|------|------|
| **공유 잠금 **(Shared Lock, S) | 읽기 잠금 | 다른 S 잠금과 공존 가능 |
| **배타 잠금 **(Exclusive Lock, X) | 쓰기 잠금 | 어떤 잠금과도 공존 불가 |

### 데드락 (Deadlock)

두 트랜잭션이 서로 상대방이 가진 잠금을 기다리는 상태입니다.

```
T1: A 잠금 보유 → B 잠금 대기
T2: B 잠금 보유 → A 잠금 대기
→ 교착 상태 발생
```

해결: 데드락 탐지 후 하나를 롤백(희생양)

### MVCC (Multi-Version Concurrency Control)

데이터의 여러 버전을 유지하여 읽기와 쓰기가 서로를 블록하지 않도록 합니다.

- **읽기:** 스냅샷(특정 시점의 버전)을 읽음 → 잠금 불필요
- **쓰기:** 새 버전 생성
- PostgreSQL, MySQL InnoDB에서 사용

## 핵심 정리

- 트랜잭션: 논리적 작업 단위, 전부 성공 또는 전부 실패
- ACID: 원자성, 일관성, 격리성, 지속성
- 격리 수준: READ UNCOMMITTED < READ COMMITTED < REPEATABLE READ < SERIALIZABLE
- 2PL: 확장 단계(잠금 획득) + 축소 단계(잠금 해제), 데드락 가능
- MVCC: 다중 버전으로 읽기-쓰기 충돌 방지
