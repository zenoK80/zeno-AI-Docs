## 조인(JOIN) — 여러 테이블을 하나로 연결

> **쉽게 말하면:** 06번 문서의 관계대수 조인(⋈)을 실제 SQL 문법으로 구현한 것입니다. 01번 문서에서 나눈 여러 테이블을, 외래키를 기준으로 다시 합쳐서 조회합니다.

**예시 테이블 — 학생:**

<Table>
  <thead><tr><th>학번</th><th>이름</th></tr></thead>
  <tbody><tr><td>1001</td><td>김민준</td></tr><tr><td>1002</td><td>이서연</td></tr></tbody>
</Table>

**예시 테이블 — 수강:**

<Table>
  <thead><tr><th>학번</th><th>과목명</th></tr></thead>
  <tbody><tr><td>1001</td><td>데이터베이스</td></tr></tbody>
</Table>

### INNER JOIN — 양쪽에 모두 있는 것만

```sql
SELECT 학생.이름, 수강.과목명
FROM 학생
INNER JOIN 수강 ON 학생.학번 = 수강.학번;
```

**결과:** 학번이 양쪽 테이블에 모두 존재하는 "1001, 김민준, 데이터베이스"만 나옵니다. 수강 기록이 없는 이서연(1002)은 결과에서 제외됩니다.

### LEFT OUTER JOIN — 왼쪽 테이블은 무조건 포함

```sql
SELECT 학생.이름, 수강.과목명
FROM 학생
LEFT JOIN 수강 ON 학생.학번 = 수강.학번;
```

**결과:** 왼쪽(학생) 테이블의 모든 행이 결과에 포함되며, 매칭되는 수강 기록이 없으면 과목명 자리에 NULL이 채워집니다.

<Table>
  <thead>
    <tr><th>이름</th><th>과목명</th></tr>
  </thead>
  <tbody>
    <tr><td>김민준</td><td>데이터베이스</td></tr>
    <tr><td>이서연</td><td>NULL</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** INNER JOIN과 LEFT (OUTER) JOIN을 혼동하기 쉽습니다. INNER JOIN은 "양쪽 모두에 매칭되는 데이터만" 남기고, LEFT JOIN은 "왼쪽 테이블은 무조건 다 남기고, 오른쪽이 없으면 빈 값(NULL)으로 채운다"는 차이가 핵심입니다. "아직 수강 신청을 하지 않은 학생까지 포함해서 보고 싶다"면 LEFT JOIN을 써야 합니다.
</Callout>

## 서브쿼리(Subquery) — 쿼리 안의 쿼리

> **쉽게 말하면:** 서브쿼리는 하나의 SQL 문 안에, 또 다른 SELECT 문을 괄호로 감싸 끼워 넣는 것입니다.

**계산 예시:** "데이터베이스" 과목을 수강하는 학생의 이름을 구합니다.

```sql
SELECT 이름 FROM 학생
WHERE 학번 IN (SELECT 학번 FROM 수강 WHERE 과목명 = '데이터베이스');
```

**해석:** 괄호 안의 서브쿼리가 먼저 실행되어 "데이터베이스를 수강하는 학번 목록"(1001)을 만들고, 바깥 쿼리는 그 목록에 포함된 학번을 가진 학생의 이름을 조회합니다.

## 뷰(View) — 가상의 테이블

> **쉽게 말하면:** 뷰는 실제 데이터를 새로 저장하지 않고, "이 SELECT 쿼리의 결과를 마치 테이블처럼 사용하겠다"고 정의해둔 가상의 테이블입니다.

```sql
CREATE VIEW 데이터베이스수강생 AS
SELECT 학생.이름 FROM 학생
INNER JOIN 수강 ON 학생.학번 = 수강.학번
WHERE 수강.과목명 = '데이터베이스';
```

**이후 사용법:** `SELECT * FROM 데이터베이스수강생;`처럼, 뷰를 마치 일반 테이블인 것처럼 간단히 조회할 수 있습니다.

<Callout type="info">
  **뷰를 사용하는 이유:** 복잡한 JOIN·서브쿼리를 매번 다시 작성하는 대신, 자주 쓰는 조회를 뷰로 미리 정의해두면 코드가 간결해집니다. 또한 뷰를 통해 특정 열만 노출시켜, 15번 문서에서 다룰 보안(민감한 열 숨기기)에도 활용할 수 있습니다.
</Callout>

## 권한 부여와 철회 — GRANT, REVOKE

> **쉽게 말하면:** GRANT는 특정 사용자에게 테이블에 대한 권한(조회, 수정 등)을 "허락"하는 명령이고, REVOKE는 그 권한을 "거둬들이는" 명령입니다.

```sql
GRANT SELECT ON 학생 TO 사용자A;
REVOKE SELECT ON 학생 FROM 사용자A;
```

**해석:** 첫 번째 문장은 "사용자A가 학생 테이블을 조회(SELECT)할 수 있게 허락"하고, 두 번째 문장은 "그 조회 권한을 다시 거둬들입니다".

## 핵심 정리

- **INNER JOIN**(양쪽 매칭되는 것만) vs. **LEFT JOIN**(왼쪽 전체 유지, 매칭 없으면 NULL).
- **서브쿼리**: SELECT 문 안에 또 다른 SELECT 문을 중첩해, 단계적으로 조건을 좁힘.
- **뷰**: 실제 데이터를 저장하지 않는 가상 테이블. 복잡한 쿼리를 재사용 가능하게 만듦.
- **GRANT/REVOKE**: 사용자에게 테이블 권한을 부여/철회.
