## 데이터베이스란?

**데이터베이스(Database, DB)**는 여러 사람이 공유하고 사용할 목적으로 통합 관리되는 데이터의 집합입니다.

### 파일 시스템 vs 데이터베이스

| 구분 | 파일 시스템 | 데이터베이스 |
|------|----------|------------|
| 데이터 중복 | 높음 | 최소화 |
| 데이터 불일치 | 발생 가능 | 일관성 유지 |
| 데이터 공유 | 어려움 | 용이 |
| 보안 | 파일 단위 | 세밀한 접근 제어 |
| 동시 접근 | 문제 발생 | 동시성 제어 |

### 데이터베이스의 특성

- **실시간 접근성(Real-time Accessibility):** 질의에 실시간 응답
- **계속적인 변화(Continuous Evolution):** 삽입, 삭제, 수정으로 현재 상태 반영
- **동시 공유(Concurrent Sharing):** 여러 사용자가 동시에 접근
- **내용에 의한 참조(Reference by Content):** 주소가 아닌 값에 의해 참조

## DBMS (Database Management System)

**DBMS**는 데이터베이스를 생성, 관리, 조작하는 소프트웨어 시스템입니다.

### DBMS의 기능

- **정의 기능:** 데이터 구조(스키마) 정의
- **조작 기능:** 데이터 삽입, 수정, 삭제, 검색
- **제어 기능:** 보안, 권한 관리, 동시성 제어, 회복

### 대표 DBMS

- **관계형 DBMS:** Oracle, MySQL, PostgreSQL, SQL Server
- **NoSQL DBMS:** MongoDB, Redis, Cassandra

## 3단계 스키마 구조

ANSI/SPARC에서 제안한 데이터베이스의 독립성을 위한 3단계 구조입니다.

```
[외부 스키마]  사용자 뷰 1 | 사용자 뷰 2 | 사용자 뷰 3
                    ↕ 외부/개념 사상
[개념 스키마]  전체 논리적 구조 (DBA가 정의)
                    ↕ 개념/내부 사상
[내부 스키마]  물리적 저장 구조 (저장 방법, 인덱스 등)
```

| 단계 | 설명 | 담당자 |
|------|------|------|
| **외부 스키마(External)** | 사용자 관점의 뷰, 서브스키마 | 일반 사용자 |
| **개념 스키마(Conceptual)** | 전체 데이터의 논리적 구조 | DBA |
| **내부 스키마(Internal)** | 물리적 저장 구조, 인덱스 | 시스템 설계자 |

### 데이터 독립성

- **논리적 독립성:** 개념 스키마 변경 시 외부 스키마(응용 프로그램) 영향 없음
- **물리적 독립성:** 내부 스키마 변경 시 개념 스키마 영향 없음

## 데이터 언어

| 언어 | 설명 | 예시 |
|------|------|------|
| **DDL (Data Definition Language)** | 스키마 정의 | CREATE, DROP, ALTER |
| **DML (Data Manipulation Language)** | 데이터 조작 | SELECT, INSERT, UPDATE, DELETE |
| **DCL (Data Control Language)** | 접근 제어 | GRANT, REVOKE |
| **TCL (Transaction Control Language)** | 트랜잭션 제어 | COMMIT, ROLLBACK |

## 핵심 정리

- 데이터베이스: 통합 관리되는 데이터 집합, 중복 최소화
- DBMS: 데이터베이스 관리 소프트웨어 (정의/조작/제어 기능)
- 3단계 스키마: 외부(사용자) - 개념(DBA) - 내부(물리)
- 데이터 독립성: 논리적 독립성, 물리적 독립성
- 데이터 언어: DDL, DML, DCL, TCL
