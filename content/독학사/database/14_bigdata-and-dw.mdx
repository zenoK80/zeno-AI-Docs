## 빅데이터 (Big Data)

전통적인 데이터베이스로 처리하기 어려운 방대한 규모의 데이터입니다.

**3V 특성:**
| 특성 | 설명 |
|------|------|
| **Volume (규모)** | 테라바이트~페타바이트 이상의 대용량 |
| **Velocity (속도)** | 실시간 또는 매우 빠른 데이터 생성/처리 |
| **Variety (다양성)** | 정형/반정형/비정형 다양한 형태 |

추가: **Veracity(정확성)**, **Value(가치)** 도 포함하는 5V 모델도 사용.

## OLTP vs OLAP

### OLTP (Online Transaction Processing)

일상적인 **업무 처리**를 위한 시스템입니다.

- 쇼핑몰 주문, 은행 거래, 재고 관리
- 특징: 빠른 응답 시간, 높은 동시성, 작은 단위 트랜잭션
- 데이터: 현재 운영 데이터, 주로 최신 데이터

### OLAP (Online Analytical Processing)

**분석/의사결정**을 위한 시스템입니다.

- 분기별 매출 분석, 고객 행동 패턴 분석
- 특징: 복잡한 집계 쿼리, 대용량 데이터, 읽기 중심
- 데이터: 역사적 데이터, 수년간의 데이터

### 비교

| 항목 | OLTP | OLAP |
|------|------|------|
| 목적 | 업무 처리 | 분석/의사결정 |
| 쿼리 유형 | 단순 INSERT/UPDATE | 복잡한 집계 SELECT |
| 데이터 크기 | 상대적으로 작음 | 매우 큼 |
| 응답 시간 | 밀리초 단위 | 초~분 단위 |
| 갱신 빈도 | 매우 자주 | 주기적(배치) |
| 최적화 | 트랜잭션 처리 | 읽기 성능 |

## 데이터 웨어하우스 (Data Warehouse, DW)

의사결정 지원을 위해 **여러 소스의 데이터를 통합, 주제 중심으로 저장**하는 중앙 저장소입니다.

**특징 (Bill Inmon):**
- **주제 지향적(Subject-Oriented):** 특정 주제(고객, 매출 등) 중심
- **통합적(Integrated):** 여러 소스 데이터를 통일된 형식으로 통합
- **비휘발성(Non-Volatile):** 한번 적재된 데이터는 수정/삭제 없이 보존
- **시간 가변적(Time-Variant):** 시간에 따른 변화 추적 (이력 데이터 보존)

## 다차원 데이터 모델

데이터 웨어하우스는 **사실 테이블(Fact Table)**과 **차원 테이블(Dimension Table)**로 구성됩니다.

- **사실 테이블:** 측정값(매출액, 수량 등)과 차원 외래키
- **차원 테이블:** 분석 관점(시간, 상품, 고객, 지역 등)의 속성

### 스타 스키마 (Star Schema)

하나의 사실 테이블이 여러 차원 테이블과 직접 연결된 단순한 구조입니다.

```
          [시간 차원]
               |
[지역 차원] -- [사실 테이블: 매출] -- [상품 차원]
               |
          [고객 차원]
```

**장점:** 쿼리가 단순하고 빠름, 이해하기 쉬움
**단점:** 차원 테이블에 중복 데이터 존재

### 눈꽃송이 스키마 (Snowflake Schema)

차원 테이블이 정규화되어 추가 테이블로 분리된 구조입니다.

```
[연도] - [분기] - [월]
                   |
[국가] - [도시] -- [사실 테이블] -- [카테고리] - [상품]
                   |
              [고객 세그먼트] - [고객]
```

**장점:** 데이터 중복 감소, 저장 공간 효율적
**단점:** 쿼리 복잡도 증가, 성능 저하 가능

### 비교

| 항목 | 스타 스키마 | 눈꽃송이 스키마 |
|------|-----------|---------------|
| 차원 테이블 정규화 | 비정규화 | 정규화 |
| 쿼리 복잡도 | 단순 | 복잡 |
| 성능 | 빠름 | 상대적으로 느림 |
| 중복 | 있음 | 없음 |

## ETL (Extract, Transform, Load)

소스 시스템에서 데이터 웨어하우스로 데이터를 이전하는 프로세스입니다.

### 단계

**1. 추출 (Extract)**
- OLTP DB, 파일, 외부 API 등에서 데이터 추출
- 전체 추출 또는 변경분만 추출(CDC: Change Data Capture)

**2. 변환 (Transform)**
- 데이터 정제: 결측값 처리, 이상치 제거
- 형식 통일: 날짜 형식, 인코딩 표준화
- 비즈니스 규칙 적용: 집계, 파생 변수 계산
- 중복 제거

**3. 적재 (Load)**
- 변환된 데이터를 데이터 웨어하우스에 적재
- 전체 갱신 또는 증분 적재

**ETL vs ELT:**
- ETL: 변환 후 적재 (전통적)
- ELT: 적재 후 변환 (클라우드 DW에서 주로 사용: Snowflake, BigQuery)

## OLAP 연산

| 연산 | 설명 |
|------|------|
| **Roll-up** | 세분화된 데이터를 더 상위 레벨로 집계 (월 → 분기 → 연) |
| **Drill-down** | 상위 레벨에서 세부 데이터로 상세화 (연 → 분기 → 월) |
| **Slice** | 특정 차원의 값으로 필터링 |
| **Dice** | 여러 차원으로 필터링 (큐브의 일부 선택) |
| **Pivot** | 행과 열의 축 전환 |

## 데이터 마이닝 (Data Mining)

대용량 데이터에서 **숨겨진 패턴과 지식을 발견**하는 과정입니다.

**주요 기법:**

| 기법 | 설명 | 알고리즘 |
|------|------|---------|
| 분류 (Classification) | 범주를 예측 | 의사결정나무, SVM |
| 군집화 (Clustering) | 유사 그룹 발견 | K-means, DBSCAN |
| 연관 규칙 (Association) | 함께 발생하는 항목 | Apriori, FP-Growth |
| 이상치 탐지 (Anomaly Detection) | 비정상 패턴 발견 | 통계적 방법, Autoencoder |

**연관 규칙 지표:**
- **지지도(Support):** 전체 거래에서 A와 B가 함께 등장하는 비율
- **신뢰도(Confidence):** A 구매 시 B도 구매하는 확률
- **향상도(Lift):** 신뢰도 / B의 지지도 (1보다 크면 양의 상관)

## 핵심 정리

- OLTP: 업무 처리, 빠른 트랜잭션 / OLAP: 분석, 복잡한 집계
- 데이터 웨어하우스: 주제 지향, 통합, 비휘발성, 시간 가변적
- 스타 스키마: 단순, 빠른 쿼리 / 눈꽃송이 스키마: 정규화, 중복 감소
- ETL: 추출(Extract) → 변환(Transform) → 적재(Load)
- OLAP 연산: Roll-up(집계), Drill-down(상세화), Slice, Dice, Pivot
