## 관계형 모델의 기본 구조

**릴레이션**(Relation)은 관계형 데이터베이스에서 테이블을 의미합니다.

```
학생 릴레이션
┌─────────┬────────┬────┬────────┐
│ 학번(PK) │ 이름   │ 나이│ 학과코드│
├─────────┼────────┼────┼────────┤
│ 2023001  │ 김철수 │ 20 │ CS     │
│ 2023002  │ 이영희 │ 21 │ EE     │
│ 2023003  │ 박민준 │ 19 │ CS     │
└─────────┴────────┴────┴────────┘
```

### 릴레이션의 구성 요소

| 용어 | 설명 | 동의어 |
|------|------|--------|
| **릴레이션**(Relation) | 테이블 전체 | 테이블 |
| **튜플**(Tuple) | 행(Row), 하나의 레코드 | 행, 레코드 |
| **속성**(Attribute) | 열(Column), 데이터 항목 | 열, 필드 |
| **도메인**(Domain) | 속성이 가질 수 있는 값의 범위 | — |
| **차수**(Degree) | 속성의 수 | — |
| **카디널리티**(Cardinality) | 튜플의 수 | — |

### 릴레이션의 특성

- **튜플의 유일성:** 중복 튜플이 없음
- **튜플의 무순서성:** 튜플 순서는 의미 없음
- **속성의 무순서성:** 속성 순서는 의미 없음
- **속성의 원자성(Atomicity):** 각 속성 값은 더 이상 분리할 수 없는 원자값

## 키 (Key)

### 슈퍼키 (Super Key)

튜플을 유일하게 식별할 수 있는 속성 또는 속성의 집합입니다.
예: `{학번}`, `{학번, 이름}`, `{학번, 이름, 나이}` 모두 슈퍼키

### 후보키 (Candidate Key)

슈퍼키 중 **최소성**을 만족하는 키입니다. 불필요한 속성이 없습니다.
예: `{학번}`, `{주민번호}`

### 기본키 (Primary Key, PK)

후보키 중 하나를 선택한 키입니다.
- NULL 값 불허 (개체 무결성)
- 중복 값 불허

### 대리키 (Alternate Key)

기본키로 선택되지 않은 나머지 후보키입니다.

### 외래키 (Foreign Key, FK)

다른 릴레이션의 기본키를 참조하는 속성입니다.
- 참조하는 테이블의 기본키에 존재하는 값이거나 NULL이어야 함 (참조 무결성)

### 복합키 (Composite Key)

두 개 이상의 속성으로 구성된 키입니다.

## 무결성 제약 조건

| 종류 | 설명 |
|------|------|
| **개체 무결성**(Entity Integrity) | 기본키는 NULL이거나 중복될 수 없음 |
| **참조 무결성**(Referential Integrity) | 외래키는 참조 테이블의 기본키 값이거나 NULL |
| **도메인 무결성**(Domain Integrity) | 속성 값은 정의된 도메인 범위 내에 있어야 함 |
| **사용자 정의 무결성** | 업무 규칙에 따른 제약 조건 |

## 핵심 정리

- 릴레이션 = 테이블, 튜플 = 행, 속성 = 열
- 속성값의 원자성: 더 이상 분리 불가
- 키 계층: 슈퍼키 ⊃ 후보키 ⊃ (기본키, 대리키)
- 외래키: 다른 릴레이션의 PK 참조
- 개체 무결성: PK는 NULL·중복 불가
- 참조 무결성: FK는 참조 PK의 값이거나 NULL
