## 이상 현상 (Anomaly)

잘못 설계된 릴레이션에서 발생하는 문제입니다.

**예시 릴레이션: 학생_수강**

| 학번 | 이름 | 학과 | 학과위치 | 과목코드 | 성적 |
|------|------|------|---------|---------|------|
| S1 | 김철수 | CS | 공학관 | C1 | A |
| S1 | 김철수 | CS | 공학관 | C2 | B |
| S2 | 이영희 | EE | 전자관 | C1 | A |

- **삽입 이상:** 과목 수강 없이는 학생 정보만 삽입 불가 (학번+과목코드가 복합 PK)
- **삭제 이상:** S2가 C1만 수강 중일 때 C1 삭제 시 S2 정보도 사라짐
- **갱신 이상:** CS 학과의 위치 변경 시 여러 행을 모두 수정해야 함

## 함수 종속성 (Functional Dependency)

속성 X가 속성 Y를 함수적으로 결정할 때: $X \to Y$

- 완전 함수 종속: Y가 X 전체에 종속 (X의 부분 집합에는 종속 안 됨)
- 부분 함수 종속: Y가 X의 일부에만 종속
- 이행적 종속: $X \to Y$이고 $Y \to Z$이면 $X \to Z$

## 정규형 (Normal Form)

### 제1정규형 (1NF)

**조건:** 모든 속성 값이 원자값(더 이상 분해 불가)이어야 합니다.

- 반복 그룹(배열, 집합 등) 제거
- 전화번호 목록을 여러 행으로 분리

### 제2정규형 (2NF)

**조건:** 1NF를 만족하고, 기본키에 대한 **완전 함수 종속**이어야 합니다.

- 부분 함수 종속을 제거합니다.
- 복합키일 때 의미 있음

```
학생_수강(학번, 과목코드, 성적, 학생이름, 학과)
기본키: (학번, 과목코드)

문제:
학생이름 → 학번에만 종속 (부분 종속)
학과 → 학번에만 종속 (부분 종속)

해결:
학생(학번, 학생이름, 학과) [학번이 PK]
수강(학번, 과목코드, 성적) [학번+과목코드가 복합 PK]
```

### 제3정규형 (3NF)

**조건:** 2NF를 만족하고, **이행적 함수 종속**이 없어야 합니다.

```
학생(학번, 이름, 학과코드, 학과위치)
기본키: 학번

문제: 학번 → 학과코드 → 학과위치 (이행적 종속)

해결:
학생(학번, 이름, 학과코드)
학과(학과코드, 학과위치)
```

### BCNF (Boyce-Codd Normal Form)

**조건:** 3NF를 만족하고, 모든 결정자가 후보키이어야 합니다.

3NF를 만족하지만 BCNF를 만족하지 않는 경우가 존재합니다.

```
수강(학생, 과목, 교수)
후보키: (학생, 과목), (학생, 교수)
결정자: 교수 → 과목 (교수가 결정자이지만 후보키가 아님)

BCNF 위반 → 분해 필요
교수_과목(교수, 과목)
수강(학생, 교수)
```

## 정규화 단계 요약

```
원래 릴레이션
  ↓ 원자값 보장
1NF: 원자값, 반복 그룹 제거
  ↓ 부분 종속 제거
2NF: 완전 함수 종속
  ↓ 이행적 종속 제거
3NF: 이행적 종속 없음
  ↓ 모든 결정자가 후보키
BCNF: 모든 결정자 = 후보키
```

## 역정규화 (Denormalization)

정규화로 성능이 저하될 때, 의도적으로 정규화를 되돌리는 것입니다.

- 조인 횟수 감소로 조회 성능 향상
- 데이터 중복 증가, 갱신 이상 발생 가능
- OLAP, 데이터 웨어하우스에서 자주 사용

## 핵심 정리

- 이상 현상: 삽입, 삭제, 갱신 이상 (함수 종속성 문제)
- 1NF: 원자값 (반복 그룹 제거)
- 2NF: 완전 함수 종속 (부분 종속 제거)
- 3NF: 이행적 종속 제거
- BCNF: 모든 결정자가 후보키
