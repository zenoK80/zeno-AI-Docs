## 데이터 모델링이란?

**데이터 모델링**은 현실 세계의 정보를 데이터베이스에 저장할 수 있도록 구조화하는 과정입니다.

### 데이터 모델링의 3단계

```
현실 세계
  ↓ 개념적 모델링
개념적 스키마 (ERD — 독립적인 개념 표현)
  ↓ 논리적 모델링
논리적 스키마 (관계형 모델 — 테이블 구조)
  ↓ 물리적 모델링
물리적 스키마 (실제 저장 구조 — 인덱스, 파티션)
```

## ER 모델 (Entity-Relationship Model)

**ER 모델**은 데이터를 엔티티, 속성, 관계로 표현하는 개념적 데이터 모델입니다.

### 엔티티 (Entity)

**엔티티**는 독립적으로 존재하는 실세계의 객체입니다.

- **강한 엔티티(Strong Entity):** 키 속성만으로 식별 가능 (예: 학생, 과목)
- **약한 엔티티(Weak Entity):** 다른 엔티티에 의존하여 식별 (예: 수강_이력은 학생에 의존)

### 속성 (Attribute)

엔티티의 특성을 나타냅니다.

| 종류 | 설명 | 예시 |
|------|------|------|
| **단순 속성** | 더 이상 분리 불가 | 나이, 학번 |
| **복합 속성** | 여러 단순 속성으로 구성 | 주소(시, 구, 동) |
| **다중값 속성** | 여러 값을 가질 수 있음 | 전화번호(여러 개) |
| **유도 속성** | 다른 속성으로 계산 | 나이(생년월일로 계산) |
| **키 속성** | 엔티티를 유일하게 식별 | 학번, 주민번호 |

### 관계 (Relationship)

엔티티 간의 연관성을 표현합니다.

**카디널리티(Cardinality):**

| 관계 | 설명 | 예시 |
|------|------|------|
| **1:1 (일대일)** | 각 엔티티가 최대 1개와 연결 | 직원 - 주차 공간 |
| **1:N (일대다)** | 한 엔티티가 여러 개와 연결 | 학과 - 학생 |
| **M:N (다대다)** | 양쪽이 여러 개와 연결 | 학생 - 과목 |

**참여 제약(Participation Constraint):**
- **전체 참여(Total):** 모든 인스턴스가 관계에 참여 (이중선)
- **부분 참여(Partial):** 일부만 관계에 참여 (단일선)

## ERD 표기법

### Chen 표기법

```
[학생] ──── 수강 ──── [과목]
 (사각형)  (마름모)  (사각형)
   학번(밑줄)   이름    과목코드(밑줄)
   (타원)      (타원)   (타원)
```

### IE(까마귀발) 표기법

현업에서 주로 사용하는 표기법입니다.

```
학생 ─|o─────o{─ 수강
(1명)  0 or 1   0 or many
```

## ER 모델에서 관계형 모델로 변환

| ER 구성요소 | 관계형 변환 |
|------------|-----------|
| 강한 엔티티 | 테이블 |
| 속성 | 열(Column) |
| 키 속성 | 기본키(PK) |
| 약한 엔티티 | 테이블 + 부모의 PK 포함 |
| 1:N 관계 | N쪽에 FK 추가 |
| M:N 관계 | 중간 테이블 생성 |

## 핵심 정리

- 데이터 모델링 3단계: 개념적 → 논리적 → 물리적
- 엔티티: 독립적으로 존재하는 객체, 강한/약한 엔티티
- 속성 종류: 단순, 복합, 다중값, 유도, 키 속성
- 관계 카디널리티: 1:1, 1:N, M:N
- M:N 관계는 관계형 모델에서 중간 테이블로 변환
