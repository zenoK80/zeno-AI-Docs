## 클라이언트/서버(Client/Server, C/S) 구조

> **쉽게 말하면:** 클라이언트/서버 구조는 "요청하는 쪽"(클라이언트)과 "응답하는 쪽"(서버)의 역할을 명확히 나눈 시스템 설계 방식입니다. 14번 문서의 웹 DB도 이 구조의 한 형태입니다.

<Table>
  <thead>
    <tr><th>역할</th><th>담당</th></tr>
  </thead>
  <tbody>
    <tr><td>클라이언트(Client)</td><td>사용자와 직접 상호작용하며 서버에 데이터를 요청</td></tr>
    <tr><td>서버(Server)</td><td>클라이언트의 요청을 받아 처리하고 결과를 응답</td></tr>
  </tbody>
</Table>

## C/S 구조의 유형 — 계층(Tier)의 개수

> **쉽게 말하면:** "계층"은 시스템이 몇 개의 독립된 층으로 나뉘어 있는지를 나타내며, 계층이 많을수록 각 층의 역할이 더 세분화됩니다.

<Table>
  <thead>
    <tr><th>유형</th><th>구성</th><th>특징</th></tr>
  </thead>
  <tbody>
    <tr><td>2계층(2-Tier)</td><td>클라이언트 ↔ 서버(DBMS)</td><td>클라이언트가 화면 표시와 일부 로직 처리까지 직접 담당. 구조는 단순하지만 클라이언트마다 부담이 큼</td></tr>
    <tr><td>3계층(3-Tier)</td><td>클라이언트 ↔ 애플리케이션 서버 ↔ DBMS</td><td>14번 문서의 웹 DB 구조. 로직 처리를 중간 서버가 담당해 클라이언트 부담을 줄임</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **왜 3계층이 더 널리 쓰이는가?** 2계층에서는 비즈니스 로직(계산, 규칙 검증 등)을 각 클라이언트 프로그램마다 똑같이 구현해야 해서, 로직이 바뀌면 모든 클라이언트를 일일이 업데이트해야 하는 불편함이 있습니다. 3계층은 이 로직을 중간의 애플리케이션 서버 한 곳에 모아두어, 로직이 바뀌어도 서버만 수정하면 되는 유지보수 이점이 있습니다.
</Callout>

## 미들웨어(Middleware)

> **쉽게 말하면:** 미들웨어는 서로 다른 시스템(예: 애플리케이션과 DBMS, 또는 서로 다른 종류의 DBMS들) 사이에서 "통역"과 "중개" 역할을 해주는 소프트웨어입니다.

**대표 역할:** 애플리케이션이 어떤 종류의 DBMS를 쓰는지 몰라도, 미들웨어를 통해 표준화된 방식으로 데이터에 접근할 수 있게 해줍니다(예: 애플리케이션 코드를 바꾸지 않고도 뒤에서 DBMS 종류를 교체 가능).

<Callout type="warning">
  **자주 틀리는 점:** 미들웨어를 "그냥 중간에 있는 아무 소프트웨어"로 막연히 이해하기 쉽습니다. 핵심은 "서로 다른(이질적인) 시스템들이 직접 연결하기 어려운 차이를 흡수해, 표준화된 방식으로 통신할 수 있게 중개한다"는 점입니다. 04번 문서의 데이터 독립성과 비슷하게, 미들웨어 덕분에 애플리케이션은 DBMS의 세부 구현을 몰라도 됩니다.
</Callout>

## 분산 데이터베이스(Distributed Database)

> **쉽게 말하면:** 분산 데이터베이스는 하나의 데이터베이스를 물리적으로 여러 대의 컴퓨터(서로 다른 위치)에 나누어 저장하면서도, 사용자에게는 마치 하나의 통합된 데이터베이스처럼 보이게 만드는 시스템입니다.

<Table>
  <thead>
    <tr><th>분산 방식</th><th>정의</th></tr>
  </thead>
  <tbody>
    <tr><td>분할(Fragmentation)</td><td>하나의 테이블을 여러 조각으로 나눠 서로 다른 위치에 저장(예: 지역별 지사의 데이터를 각 지사 서버에 저장)</td></tr>
    <tr><td>복제(Replication)</td><td>같은 데이터를 여러 위치에 동일하게 복사해 저장(장애 대비·조회 속도 향상)</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **분산 데이터베이스의 장점과 과제:** 각 지역에서 가까운 서버에 접근할 수 있어 응답 속도가 빨라지고, 한 서버에 장애가 생겨도 전체가 멈추지 않는 장점이 있습니다. 하지만 여러 위치에 흩어진 데이터를 12번 문서의 동시성 제어나 11번 문서의 트랜잭션 원자성으로 일관성 있게 관리하는 것은 단일 서버보다 훨씬 복잡한 과제가 됩니다.
</Callout>

## 핵심 정리

- **클라이언트/서버**(C/S) **구조**: 요청(클라이언트)과 응답(서버)의 역할 분리.
- **2계층**(클라이언트가 로직까지 담당) vs. **3계층**(중간 서버가 로직 담당, 유지보수에 유리).
- **미들웨어**: 서로 다른 시스템 사이를 표준화된 방식으로 중개하는 소프트웨어.
- **분산 데이터베이스**: 여러 위치에 데이터를 나누거나(분할) 복사(복제)해 저장하면서도 하나처럼 보이게 함. 응답 속도·장애 대응에 유리하지만 일관성 관리가 더 복잡함.
