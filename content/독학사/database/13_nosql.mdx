## NoSQL이란?

**Not Only SQL** — 관계형 데이터베이스(RDBMS)의 한계를 극복하기 위해 등장한 비관계형 데이터베이스의 총칭입니다.

**등장 배경:**
- 대용량 데이터(빅데이터) 처리
- 높은 확장성(Scale-out) 요구
- 비정형 데이터 저장
- 빠른 읽기/쓰기 필요

**RDBMS vs NoSQL:**

| 항목 | RDBMS | NoSQL |
|------|-------|-------|
| 스키마 | 고정 스키마 | 유연한 스키마 |
| 확장 | 수직 확장 (Scale-up) | 수평 확장 (Scale-out) |
| 일관성 | ACID | BASE (대부분) |
| 조인 | 지원 | 제한적 또는 미지원 |
| 적합 데이터 | 정형 데이터 | 정형/반정형/비정형 |

## NoSQL 유형

### 1. 키-값 저장소 (Key-Value Store)

가장 단순한 구조로 키(Key)와 값(Value) 쌍을 저장합니다.

```
"user:1001" → {"name": "홍길동", "age": 30}
"session:abc123" → "user_id=1001&login=true"
```

**특징:**
- 매우 빠른 읽기/쓰기 (O(1))
- 값의 내용을 기준으로 검색 불가 (키로만 접근)
- 단순한 데이터 모델

**대표 시스템:** Redis, Amazon DynamoDB, Riak

### 2. 문서 저장소 (Document Store)

JSON, BSON, XML 등의 형태로 **문서**(Document)를 저장합니다.

```json
{
  "_id": "order_001",
  "customer": "홍길동",
  "items": [
    {"product": "노트북", "qty": 1, "price": 1500000},
    {"product": "마우스", "qty": 2, "price": 30000}
  ],
  "total": 1560000
}
```

**특징:**
- 중첩 구조(배열, 객체) 지원
- 문서 내 임의 필드 검색 가능
- 스키마 자유로워 빠른 개발 가능

**대표 시스템:** MongoDB, CouchDB, Elasticsearch

### 3. 와이드 컬럼 저장소 (Wide Column Store)

행과 열로 구성되지만 각 행마다 **열 구성이 다를 수 있습니다**.

```
Row Key      | Column Family: profile    | Column Family: activity
-------------|---------------------------|------------------------
user:1001    | name="홍길동", age=30      | last_login="2024-01"
user:1002    | name="김영희"              | last_login="2024-02", posts=5
```

**특징:**
- 수십억 행과 수백만 열 처리 가능
- 특정 컬럼 패밀리만 조회 시 효율적
- 시계열 데이터, 로그 저장에 적합

**대표 시스템:** Apache Cassandra, HBase, Google Bigtable

### 4. 그래프 데이터베이스 (Graph Database)

**노드**(Node)와 **엣지**(Edge)로 데이터 관계를 표현합니다.

```
(홍길동) --[친구]--> (김영희)
(홍길동) --[좋아요]--> (게시글:123)
(게시글:123) --[작성자]--> (박철수)
```

**특징:**
- 복잡한 관계 표현과 탐색에 최적화
- 소셜 네트워크, 추천 시스템, 지식 그래프에 적합
- SQL보다 관계 탐색이 빠름

**대표 시스템:** Neo4j, Amazon Neptune, ArangoDB

## 대표 NoSQL 시스템

### Redis

**인메모리 키-값 저장소**

- 모든 데이터를 메모리에 저장하여 매우 빠름
- 다양한 자료 구조 지원: String, List, Set, Sorted Set, Hash
- 캐시, 세션 저장, 실시간 순위(리더보드), Pub/Sub
- 영속성 옵션: RDB 스냅샷, AOF(Append-Only File) 로그

```
SET user:1001:name "홍길동"      -- 문자열 저장
LPUSH notifications:1001 "새 메시지"  -- 리스트 push
ZADD leaderboard 1500 "홍길동"   -- 정렬 집합
```

### MongoDB

**문서 지향 데이터베이스**

- BSON(Binary JSON) 형식으로 문서 저장
- 컬렉션(Collection) = 테이블, 문서(Document) = 행
- 강력한 집계 파이프라인(Aggregation Pipeline)
- 수평 확장: 샤딩(Sharding) 지원

```javascript
// 문서 삽입
db.orders.insertOne({
  customer: "홍길동",
  items: [{product: "노트북", qty: 1}]
});

// 쿼리
db.orders.find({"customer": "홍길동"});
```

### Cassandra

**와이드 컬럼 저장소, 고가용성 분산 DB**

- 마스터 없는 P2P 아키텍처 (Single Point of Failure 없음)
- 매우 높은 쓰기 성능
- CAP에서 AP 시스템 (가용성과 분단 허용성 우선)
- 결과적 일관성 모델
- 시계열 데이터, IoT 로그에 적합

```sql
-- Cassandra Query Language (CQL)
CREATE TABLE sensor_data (
    device_id UUID,
    timestamp TIMESTAMP,
    temperature FLOAT,
    PRIMARY KEY (device_id, timestamp)
);
```

## ACID vs BASE

| 속성 | ACID (RDBMS) | BASE (NoSQL) |
|------|-------------|-------------|
| 원자성 | 모두 완료 또는 모두 취소 | 작업이 부분적으로 완료될 수 있음 |
| 일관성 | 즉각적 강한 일관성 | 결과적 일관성 (Eventual Consistency) |
| 격리성 | 트랜잭션 간 격리 | 낮은 격리 수준 |
| 지속성 | 커밋 후 영구 보존 | 상황에 따라 다름 |

**언제 무엇을 사용?**

| 상황 | RDBMS (ACID) | NoSQL (BASE) |
|------|-------------|-------------|
| 금융, 결제 | 적합 | 부적합 |
| 소셜 미디어 피드 | 부적합 | 적합 |
| 실시간 분석 | 어려움 | 적합 |
| 복잡한 조인 | 적합 | 어려움 |

## 핵심 정리

- 키-값 DB: 가장 단순, 빠른 접근, Redis
- 문서 DB: JSON/BSON, 유연한 스키마, MongoDB
- 와이드 컬럼 DB: 행별 다른 열, 대용량, Cassandra
- 그래프 DB: 노드-엣지, 관계 탐색, Neo4j
- BASE: 기본적 가용성 + 유연한 상태 + 결과적 일관성
