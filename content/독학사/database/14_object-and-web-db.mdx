## 관계형 모델의 한계

> **쉽게 말하면:** 01번 문서에서 배운 관계형 모델은 "행과 열"이라는 단순한 표 구조에 매우 적합하지만, 프로그래밍 언어의 복잡한 객체(예: 여러 부품으로 이루어진 자동차 설계도)를 표현하려면 여러 테이블로 잘게 쪼개야 해서 다루기 번거로울 수 있습니다.

## 객체지향 데이터 모델(Object-Oriented Data Model)

> **쉽게 말하면:** 객체지향 데이터베이스는 프로그래밍 언어의 "객체"(데이터+동작을 하나로 묶은 것) 개념을 그대로 데이터베이스에 저장하는 방식입니다.

<Table>
  <thead>
    <tr><th>개념</th><th>의미</th></tr>
  </thead>
  <tbody>
    <tr><td>객체(Object)</td><td>속성(데이터)과 메서드(동작)를 하나로 묶은 단위</td></tr>
    <tr><td>클래스(Class)</td><td>같은 종류의 객체들을 만들어내는 설계도</td></tr>
    <tr><td>상속(Inheritance)</td><td>기존 클래스의 속성·메서드를 새 클래스가 물려받아 재사용</td></tr>
    <tr><td>캡슐화(Encapsulation)</td><td>객체 내부의 데이터를 감추고, 정해진 메서드를 통해서만 접근하게 함</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **관계형 모델과의 핵심 차이:** 관계형 모델의 테이블은 순수한 데이터만 저장하고 "동작"(메서드)은 별도의 응용 프로그램 코드로 분리되어 있습니다. 반면 객체지향 데이터베이스는 데이터와 그 데이터를 다루는 동작을 객체 하나에 함께 저장한다는 점이 근본적으로 다릅니다.
</Callout>

## 객체 연산 — 관계형 연산과의 차이

> **쉽게 말하면:** 06번 문서의 관계대수(선택, 추출, 조인)가 "테이블 간의 관계"를 다뤘다면, 객체지향 데이터베이스의 연산은 객체가 가진 메서드를 직접 "호출"하는 방식으로 데이터를 다룹니다.

**예시:** 관계형 방식이라면 "학생" 테이블에서 SELECT로 데이터를 가져온 뒤, 별도의 프로그램 코드로 "평균 학점을 계산"해야 합니다. 객체지향 방식이라면 학생 객체 자체가 `계산평균학점()`이라는 메서드를 갖고 있어, 그 메서드를 바로 호출하면 됩니다.

## 객체-관계 데이터베이스(Object-Relational Database, ORDB)

> **쉽게 말하면:** ORDB는 익숙하고 검증된 관계형 모델의 틀을 유지하면서, 객체지향의 일부 장점(복잡한 데이터 타입, 상속 등)을 추가로 지원하는 절충안입니다.

<Callout type="warning">
  **자주 틀리는 점:** 순수 객체지향 DB와 객체-관계 DB(ORDB)를 같은 것으로 혼동하기 쉽습니다. 순수 객체지향 DB는 테이블 개념을 완전히 버리고 객체 저장에 특화된 반면, ORDB는 여전히 01번 문서의 테이블·SQL을 기본으로 사용하면서 객체지향적 확장 기능(사용자 정의 타입 등)을 추가로 지원하는 것이 차이입니다. 오늘날 널리 쓰이는 상용 DBMS 대부분은 ORDB에 가깝습니다.
</Callout>

## 웹 데이터베이스(Web Database)

> **쉽게 말하면:** 웹 DB는 웹사이트(브라우저)의 요청을 받아, 데이터베이스에 접근하고 그 결과를 다시 웹 페이지로 돌려주는 전체 연결 구조입니다.

## 웹 DB의 기본 구성요소

<Table>
  <thead>
    <tr><th>구성요소</th><th>역할</th></tr>
  </thead>
  <tbody>
    <tr><td>웹 브라우저(클라이언트)</td><td>사용자가 데이터를 요청·조회하는 화면</td></tr>
    <tr><td>웹 서버</td><td>브라우저의 요청을 받아 처리를 담당</td></tr>
    <tr><td>웹 애플리케이션 서버(WAS)</td><td>실제 비즈니스 로직(예: "이 회원의 주문 목록을 계산하라")을 처리</td></tr>
    <tr><td>DBMS</td><td>실제 데이터가 저장된 데이터베이스 관리 시스템</td></tr>
  </tbody>
</Table>

**전체 흐름**(직관적 요약):

<Steps>
### 1단계: 사용자 요청
사용자가 브라우저에서 "내 주문 내역 보기"를 클릭합니다.

### 2단계: 웹 서버·WAS 처리
요청이 웹 서버를 거쳐 WAS(애플리케이션 서버)로 전달되고, WAS는 필요한 SQL(03·07·08번 문서)을 생성합니다.

### 3단계: DBMS 조회
WAS가 생성한 SQL이 DBMS로 전달되어 실제 데이터를 조회합니다.

### 4단계: 결과 반환
DBMS의 조회 결과가 WAS → 웹 서버 → 브라우저 순서로 되돌아와, 사용자에게 화면으로 표시됩니다.
</Steps>

<Callout type="info">
  **15번 문서와의 연결:** 이 웹 DB 구조는 15번 문서에서 다룰 클라이언트/서버(C/S) 구조의 한 확장된 형태입니다. 브라우저(클라이언트)와 웹 서버·WAS·DBMS(서버 쪽 여러 계층) 사이의 역할 분담이라는 점에서 같은 원리를 공유합니다.
</Callout>

## 핵심 정리

- **객체지향 데이터 모델**: 데이터(속성)와 동작(메서드)을 객체 하나로 묶어 저장. 클래스·상속·캡슐화 등 활용.
- **객체 연산**: 관계대수 대신 객체의 메서드를 직접 호출하는 방식.
- **객체-관계 DB**(ORDB): 관계형 모델을 기본으로, 객체지향 기능을 일부 추가한 절충형. 오늘날 상용 DBMS의 주류.
- **웹 DB**: 브라우저-웹 서버-WAS-DBMS로 이어지는 구조로, 웹 요청을 실제 데이터 조회·처리로 연결.
