</Callout>

## 지도학습에서의 데이터 형태

> **쉽게 말하면:** 지도학습은 "문제(특성)와 정답(레이블)이 짝지어진 데이터"로 모델을 가르치는 방식입니다.

<Table>
  <thead>
    <tr><th>문제 유형</th><th>레이블의 형태</th><th>예시</th></tr>
  </thead>
  <tbody>
    <tr><td>회귀(Regression)</td><td>연속적인 숫자</td><td>집값(5억, 6.5억 등)</td></tr>
    <tr><td>분류(Classification)</td><td>정해진 카테고리(범주)</td><td>스팸 메일 여부(스팸/정상)</td></tr>
  </tbody>
</Table>

## 왜 데이터를 나눠야 하는가?

> **쉽게 말하면:** 시험공부를 할 때 연습문제만 계속 풀어보고 실력을 안다고 착각하면 안 되듯이, 모델도 "학습에 쓰지 않은 새로운 데이터"로 평가해야 진짜 실력을 알 수 있습니다.

<Table>
  <thead>
    <tr><th>데이터 집합</th><th>용도</th></tr>
  </thead>
  <tbody>
    <tr><td>훈련 데이터(Training Set)</td><td>모델이 실제로 학습(파라미터 조정)하는 데 사용</td></tr>
    <tr><td>검증 데이터(Validation Set)</td><td>학습 중간에 모델의 설정(하이퍼파라미터)을 조정하기 위해 사용</td></tr>
    <tr><td>테스트 데이터(Test Set)</td><td>모든 학습이 끝난 뒤, 최종 성능을 딱 한 번 평가하는 데만 사용</td></tr>
  </tbody>
</Table>

**일반적인 비율:** 전체 데이터를 훈련 60~80%, 검증 10~20%, 테스트 10~20% 정도로 나누는 것이 흔한 관례입니다.

<Callout type="warning">
  **자주 틀리는 점:** 테스트 데이터를 모델 개발 중간에 자꾸 확인하며 모델을 수정하면, 사실상 테스트 데이터에도 모델이 "맞춰지는" 셈이 되어 실제 새로운 데이터에서는 성능이 뚝 떨어질 수 있습니다(이 현상은 16번 문서의 "과적합"과 연결됩니다). 테스트 데이터는 정말 마지막에, 단 한 번만 사용하는 것이 원칙입니다.
</Callout>

## 핵심 정리

- **데이터셋**: 샘플(행)과 특성(열)으로 이루어진 표. 레이블은 예측하고자 하는 정답.
- **회귀**는 연속적인 숫자를, **분류**는 정해진 범주를 레이블로 가짐.
- **훈련/검증/테스트 데이터**: 각각 학습, 설정 조정, 최종 평가라는 서로 다른 역할을 담당하며 반드시 분리해야 함.
- 테스트 데이터는 모델 개발 중간에 참고해서는 안 되며, 최종 평가에만 단 한 번 사용한다.
