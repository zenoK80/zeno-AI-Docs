## 과적합(Overfitting)과 과소적합(Underfitting)

> **쉽게 말하면:** 과적합은 모델이 훈련 데이터를 "통째로 암기"해 새로운 데이터에 약한 상태이고, 과소적합은 모델이 데이터의 패턴조차 제대로 배우지 못한 상태입니다.

<Table>
  <thead>
    <tr><th>구분</th><th>훈련 데이터 성능</th><th>테스트 데이터 성능</th><th>원인</th></tr>
  </thead>
  <tbody>
    <tr><td>과소적합(Underfitting)</td><td>낮음</td><td>낮음</td><td>모델이 너무 단순함(패턴을 배우기에 부족)</td></tr>
    <tr><td>적절한 학습</td><td>높음</td><td>높음</td><td>훈련과 테스트 성능이 비슷하게 좋음</td></tr>
    <tr><td>과적합(Overfitting)</td><td>매우 높음</td><td>낮음</td><td>모델이 너무 복잡해 잡음까지 암기함</td></tr>
  </tbody>
</Table>

**예시:** 11번 문서의 의사결정나무를 극단적으로 깊게 만들면(가지치기 없이), 훈련 데이터는 100% 맞히지만 새 데이터에서는 오히려 성능이 떨어지는 전형적인 과적합이 발생합니다.

## 편향-분산 트레이드오프(Bias-Variance Tradeoff)

> **쉽게 말하면:** 편향은 "모델이 정답과 얼마나 체계적으로 어긋나 있는지"이고, 분산은 "훈련 데이터가 조금만 바뀌어도 모델의 예측이 얼마나 크게 흔들리는지"입니다. 이 둘은 보통 한쪽을 줄이면 다른 쪽이 커지는 트레이드오프 관계입니다.

<Table>
  <thead>
    <tr><th>개념</th><th>정의</th><th>연결되는 문제</th></tr>
  </thead>
  <tbody>
    <tr><td>편향(Bias)</td><td>모델이 너무 단순해 실제 패턴을 제대로 못 잡아 생기는 체계적 오차</td><td>과소적합</td></tr>
    <tr><td>분산(Variance)</td><td>모델이 훈련 데이터의 세부 변화에 지나치게 민감하게 반응하는 정도</td><td>과적합</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **01번 문서와의 연결:** 여기서의 "분산"은 01번 문서에서 배운 분산(데이터의 흩어짐)과 완전히 같은 수학적 개념을 다른 대상(모델의 예측 결과)에 적용한 것입니다. "훈련 데이터를 여러 번 다르게 뽑아 같은 모델을 학습시켰을 때, 예측 결과가 얼마나 들쭉날쭉한지"를 재는 것이 여기서의 분산입니다.
</Callout>

**비유**(다트 던지기): 편향이 크면 다트가 항상 과녁의 한쪽으로 치우쳐 꽂히고(정확히 어긋남), 분산이 크면 다트가 매번 완전히 다른 곳에 흩어져 꽂힙니다(예측이 불안정함). 좋은 모델은 두 문제 모두 적어야 합니다.

## 정규화(Regularization) — 과적합을 막는 방법

> **쉽게 말하면:** 정규화는 비용 함수에 "파라미터가 너무 커지면 벌점을 주는" 항을 추가해, 모델이 지나치게 복잡해지지 않도록 억제하는 기법입니다.

$$
J(\theta) = \underbrace{\frac{1}{n}\sum_{i=1}^{n}(y_i-h_\theta(x_i))^2}_{\text{기존 비용(06번 문서)}} + \underbrace{\lambda\sum_{j=1}^{m}\theta_j^2}_{\text{규제 항}}
$$

- $\lambda$(람다): **규제 강도**를 조절하는 하이퍼파라미터. 클수록 파라미터를 더 강하게 억제

## L1 정규화와 L2 정규화

<Table>
  <thead>
    <tr><th>종류</th><th>규제 항</th><th>특징</th></tr>
  </thead>
  <tbody>
    <tr><td>L1 정규화(Lasso)</td><td>$\lambda\sum|\theta_j|$</td><td>일부 파라미터를 정확히 0으로 만들어, 자동으로 특성 선택(15번 문서) 효과를 냄</td></tr>
    <tr><td>L2 정규화(Ridge)</td><td>$\lambda\sum\theta_j^2$</td><td>파라미터를 0에 가깝게는 만들지만 정확히 0으로는 잘 만들지 않음, 전반적으로 값을 고르게 축소</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** 규제 강도 $\lambda$가 너무 크면 파라미터가 지나치게 억제되어 오히려 과소적합이 발생할 수 있습니다. $\lambda$가 0이면 규제가 전혀 없는 원래 모델과 같아집니다. 즉 $\lambda$는 "편향-분산 트레이드오프를 조절하는 손잡이"와 같습니다 — $\lambda$를 늘리면 분산은 줄지만 편향은 커집니다.
</Callout>

## 하이퍼파라미터(Hyperparameter)

> **쉽게 말하면:** 하이퍼파라미터는 학습을 통해 자동으로 찾아지는 $\theta$와 달리, 학습을 시작하기 **전에 사람이 직접 정해줘야 하는** 설정값입니다.

**예시:** 06번 문서의 학습률 $\alpha$, 09번 문서의 K값, 위에서 배운 규제 강도 $\lambda$, 11번 문서의 나무 최대 깊이 등이 모두 하이퍼파라미터입니다. 이런 값들은 04번 문서에서 배운 **검증 데이터**의 성능을 보면서 가장 좋은 조합을 탐색합니다.

## 머신러닝 실무 파이프라인

> **쉽게 말하면:** 실제 머신러닝 프로젝트는 모델 학습 한 단계만으로 끝나지 않고, 여러 단계가 순환하는 하나의 파이프라인(작업 흐름)으로 진행됩니다.

<Steps>
### 1단계: 데이터 수집
문제 해결에 필요한 원본 데이터를 모읍니다.

### 2단계: 데이터 전처리
04번 문서의 결측치·이상치 처리, 정규화 등을 수행해 데이터를 모델이 학습할 수 있는 형태로 정리합니다.

### 3단계: 모델 선택
문제 유형(회귀·분류·군집화 등)에 맞는 알고리즘을 선택합니다.

### 4단계: 학습
훈련 데이터로 모델의 파라미터를 학습시킵니다.

### 5단계: 평가
16번 문서의 지표(정확도, F1, ROC-AUC 등)로 모델의 성능을 검증합니다.

### 6단계: 하이퍼파라미터 튜닝
검증 결과를 보고 하이퍼파라미터를 조정한 뒤, 4~5단계를 반복합니다.

### 7단계: 모델 배포
충분히 검증된 모델을 실제 서비스에 적용해 새로운 데이터에 대한 예측을 제공합니다.
</Steps>

<Callout type="info">
  **파이프라인은 일방통행이 아니다:** 배포 후에도 새로운 데이터가 계속 쌓이면서 모델의 성능이 시간이 지나며 떨어질 수 있습니다(데이터의 경향이 변하는 현상). 따라서 실무에서는 배포 이후에도 주기적으로 1단계로 돌아가 데이터를 갱신하고 모델을 재학습하는 순환 과정을 거칩니다.
</Callout>

## 핵심 정리

- **과적합**(훈련 성능↑, 테스트 성능↓)과 **과소적합**(둘 다 낮음)은 각각 분산이 크거나 편향이 큰 상태와 대응됨.
- **정규화**: 비용 함수에 파라미터 크기에 대한 벌점(규제 항)을 추가해 과적합을 억제. **L1**(일부를 0으로, 특성 선택 효과), **L2**(값을 고르게 축소).
- **하이퍼파라미터**: 학습 전에 사람이 정해야 하는 설정값(학습률, K값, 규제 강도 등). 검증 데이터로 최적값 탐색.
- **머신러닝 파이프라인**: 데이터 수집 → 전처리 → 모델 선택 → 학습 → 평가 → 튜닝 → 배포. 배포 이후에도 재학습이 반복되는 순환 과정.
