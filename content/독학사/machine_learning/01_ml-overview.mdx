## 왜 머신러닝이 필요한가?

프로그래머가 규칙을 일일이 코드로 짜는 전통적인 방식을 생각해 봅시다. "스팸 메일인지 판별하라"는 문제를 예로 들면, '광고', '무료', '이벤트' 같은 단어가 있으면 스팸으로 분류하는 규칙을 만들 수 있습니다. 그런데 스팸 발송자들이 단어를 조금씩 바꾸면? 규칙이 수백, 수천 개로 늘어납니다.

**머신러닝(machine learning, 기계 학습)** 은 이런 규칙을 사람이 직접 만들지 않고, **데이터에서 패턴을 스스로 학습**하게 하는 방법입니다.

> 쉽게 말하면: "규칙을 외우게 하는 게 아니라, 수많은 예시를 보여 주고 스스로 법칙을 찾아내게 한다."

**아서 사무엘(Arthur Samuel, 1959):** "명시적으로 프로그래밍하지 않고 컴퓨터가 학습할 수 있도록 하는 연구 분야"

## 머신러닝의 세 가지 패러다임

### 1. 지도 학습 (supervised learning, 지도 학습)

**왜 필요한가?** 정답이 있는 문제를 풀 때 사용합니다. 사람이 직접 정답을 달아 준 데이터(레이블, label)를 기반으로 모델이 학습합니다.

**비유:** 선생님(레이블)이 문제와 답을 함께 주면, 학생(모델)이 이를 보고 공부합니다.

입력 데이터 X와 정답 레이블(label) y가 쌍으로 제공된 훈련(training) 데이터로 학습합니다.

| 종류 | 예시 알고리즘 | 출력 |
| --- | --- | --- |
| 분류(classification, 분류) | 로지스틱 회귀, SVM, 의사결정 트리 | 클래스 레이블 |
| 회귀(regression, 연속값 예측) | 선형 회귀, 릿지, 라쏘 | 연속적인 수치 |

- **분류 예시:** 이메일이 스팸인가 아닌가(0 또는 1), 사진 속 동물이 고양이인가 개인가
- **회귀 예시:** 집 면적·위치를 보고 집값을 예측, 기온·습도로 전력 소비량 예측

### 2. 비지도 학습 (unsupervised learning, 비지도 학습)

**왜 필요한가?** 정답 레이블을 붙이는 작업은 비용이 많이 듭니다. 레이블 없이 데이터의 숨겨진 구조나 패턴을 발견할 때 사용합니다.

**비유:** 선생님 없이 학생들끼리 비슷한 애들끼리 자연스럽게 모이는 것.

| 종류 | 예시 알고리즘 |
| --- | --- |
| 군집화(clustering, 군집화) | K-means, DBSCAN |
| 차원 축소(dimensionality reduction, 차원 축소) | PCA(주성분 분석), t-SNE |
| 연관 규칙(association rule) | Apriori |

- **군집화 예시:** 비슷한 구매 패턴을 가진 고객 그룹 찾기, 문서를 비슷한 주제끼리 묶기
- **차원 축소 예시:** 100가지 특성을 2~3개로 압축해서 시각화

### 3. 강화 학습 (reinforcement learning, 강화 학습)

**왜 필요한가?** 게임처럼 행동의 결과가 보상 또는 벌칙으로 나타나는 문제에서, 보상을 최대화하는 방법을 스스로 찾게 합니다.

**비유:** 강아지를 훈련할 때 잘하면 간식(보상), 잘못하면 혼남(벌칙). 강아지는 간식을 더 받으려고 행동을 조정합니다.

- **에이전트(agent, 행동 주체):** 학습하는 주체
- **환경(environment, 환경):** 에이전트가 상호작용하는 공간
- **상태(state, 상태):** 현재 환경의 모습
- **행동(action, 행동):** 에이전트가 선택하는 행위
- **보상(reward, 보상):** 행동의 결과로 받는 피드백

**실제 예시:** 알파고(바둑 인공지능), 게임 캐릭터 자동 조종, 로봇 팔 제어

## 머신러닝 vs 딥러닝

**딥러닝(deep learning, 심층 학습)** 은 머신러닝의 한 종류입니다. 인간 뇌의 신경세포를 모방한 인공 신경망(artificial neural network)을 여러 층 쌓아서 복잡한 패턴을 학습합니다.

**관계 그림:**
```
인공지능(AI)
  └─ 머신러닝(ML)
       └─ 딥러닝(DL)
```

| 항목 | 머신러닝(ML) | 딥러닝(DL) |
| --- | --- | --- |
| 특성 추출 | 수동(사람이 직접) | 자동(신경망이 스스로) |
| 데이터 양 | 소량 가능 | 대량 필요 |
| 해석 가능성 | 높음 (화이트박스) | 낮음 (블랙박스) |
| 대표 모델 | SVM(서포트 벡터 머신), 의사결정 트리 | CNN(합성곱 신경망), RNN(순환 신경망), Transformer |
| 계산 자원 | 적게 필요 | 많이 필요(GPU 필수) |

<Callout type="warning">
  딥러닝은 머신러닝의 하위 분야입니다. 즉 모든 딥러닝은 머신러닝이지만, 모든 머신러닝이 딥러닝은 아닙니다.
</Callout>

## 머신러닝 파이프라인 (pipeline, 작업 흐름)

실제 머신러닝 프로젝트는 다음 순서로 진행됩니다.

1. **문제 정의:** 무엇을 예측할 것인가? 분류인가 회귀인가?
2. **데이터 수집 및 EDA(Exploratory Data Analysis, 탐색적 데이터 분석):** 데이터를 모으고 기본 통계와 시각화로 이해
3. **데이터 전처리 및 특성 공학(feature engineering, 특성 만들기):** 결측치 처리, 스케일링, 인코딩
4. **모델 선택 및 학습:** 알고리즘을 고르고 훈련 데이터로 학습
5. **모델 평가 및 튜닝:** 성능 측정, 하이퍼파라미터(hyperparameter) 조정
6. **배포 및 모니터링:** 실제 서비스에 적용, 지속 관찰

## 훈련/검증/테스트 데이터 분리

**왜 필요한가?** 시험 문제와 답을 미리 알고 공부하면 점수가 높아도 실력이 아닌 것처럼, 모델이 학습한 데이터로만 평가하면 실제 성능을 알 수 없습니다.

| 데이터 세트 | 역할 | 일반 비율 |
| --- | --- | --- |
| 훈련 세트(train set) | 모델 학습 | 60~70% |
| 검증 세트(validation set) | 하이퍼파라미터 튜닝, 모델 선택 | 10~20% |
| 테스트 세트(test set) | 최종 성능 평가 (딱 한 번만) | 20~30% |

**중요:** 테스트 세트는 최종 평가에만 사용해야 합니다. 반복해서 보면 테스트 데이터에 과적합(overfitting, 훈련 데이터에만 맞춰지는 현상)됩니다.

---

## 핵심 정리

- **지도 학습:** 레이블 있는 데이터, 분류/회귀
- **비지도 학습:** 레이블 없는 데이터, 군집/차원 축소
- **강화 학습:** 보상 최대화를 위한 에이전트-환경 상호작용
- **딥러닝:** 머신러닝의 하위 집합, 자동 특성 추출
- **파이프라인:** 문제 정의 → 데이터 수집 → 전처리 → 학습 → 평가 → 배포
