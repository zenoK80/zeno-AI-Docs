## 임계구역(Critical Section)

**임계구역**은 여러 프로세스가 동시에 접근하면 안 되는 **공유 자원에 접근하는 코드 영역**입니다.

```
while (true) {
    [진입 구역]        ← 임계구역 진입 허가 요청
    [임계구역]         ← 공유 자원 접근 (한 번에 하나의 프로세스만)
    [퇴출 구역]        ← 임계구역 사용 완료 알림
    [나머지 구역]      ← 그 외 코드
}
```

### 임계구역 문제의 3가지 요구조건

| 조건 | 설명 |
|------|------|
| **상호배제(Mutual Exclusion)** | 한 프로세스가 임계구역에 있으면 다른 프로세스는 진입 불가 |
| **진행(Progress)** | 임계구역을 사용 중인 프로세스가 없고 진입하려는 프로세스가 있으면, 진입 결정이 유한 시간 내에 이루어져야 함 |
| **한정 대기(Bounded Waiting)** | 프로세스가 임계구역 진입 요청 후 무한정 대기하지 않도록 보장 |

## 뮤텍스(Mutex)

**뮤텍스(Mutual Exclusion)**는 임계구역을 보호하기 위한 잠금(Lock) 메커니즘입니다.

- `acquire()`: 잠금 획득 (다른 프로세스가 사용 중이면 대기)
- `release()`: 잠금 해제

```
뮤텍스 잠금 상태: available (true/false)

acquire():
    while (!available) { /* 바쁜 대기(Busy Waiting) */ }
    available = false

release():
    available = true
```

**바쁜 대기(Busy Waiting):** CPU를 계속 사용하며 잠금을 기다리는 방식. CPU 낭비가 발생합니다. **스핀락(Spin Lock)**이라고도 합니다.

## 세마포어(Semaphore)

**세마포어**는 정수형 변수를 이용한 동기화 도구입니다. Dijkstra가 제안했습니다.

두 가지 원자적(Atomic) 연산만 허용됩니다.

| 연산 | 동작 |
|------|------|
| **P 연산 (wait)** | 세마포어 값이 0보다 크면 1 감소 후 진행; 0이면 대기 |
| **V 연산 (signal)** | 세마포어 값을 1 증가; 대기 중인 프로세스가 있으면 깨움 |

### 이진 세마포어 vs 범용 세마포어

| 종류 | 값 범위 | 용도 |
|------|---------|------|
| **이진 세마포어** | 0 또는 1 | 상호배제 (뮤텍스와 유사) |
| **범용(카운팅) 세마포어** | 0 이상 정수 | 자원 개수 관리 |

### 생산자-소비자 문제 (세마포어 해결)

```
세마포어:
- mutex = 1        (버퍼 상호배제)
- empty = N        (빈 버퍼 개수)
- full = 0         (꽉 찬 버퍼 개수)

생산자:
    P(empty)       ← 빈 공간 있을 때까지 대기
    P(mutex)       ← 버퍼 잠금
    [버퍼에 데이터 추가]
    V(mutex)       ← 버퍼 잠금 해제
    V(full)        ← 소비자에게 알림

소비자:
    P(full)        ← 데이터 있을 때까지 대기
    P(mutex)       ← 버퍼 잠금
    [버퍼에서 데이터 꺼냄]
    V(mutex)       ← 버퍼 잠금 해제
    V(empty)       ← 생산자에게 알림
```

## 모니터(Monitor)

**모니터**는 프로그래밍 언어 수준에서 동기화를 지원하는 고수준 메커니즘입니다. 세마포어보다 사용하기 안전합니다.

- 모니터 내부의 프로시저는 한 번에 하나의 프로세스만 실행 가능
- **조건 변수(Condition Variable)**를 통해 대기/깨움 처리
  - `wait()`: 현재 프로세스를 조건 큐에 넣고 모니터 양보
  - `signal()`: 조건 큐에서 대기 중인 프로세스 하나를 깨움

Java의 `synchronized` 블록이 모니터를 기반으로 합니다.

## 판독자-기록자 문제

**여러 판독자(Reader)**는 동시에 공유 데이터를 읽을 수 있지만, **기록자(Writer)**가 쓸 때는 판독자와 기록자 모두 배제해야 합니다.

| 정책 | 특징 | 문제 |
|------|------|------|
| **판독자 우선** | 판독자가 읽는 동안 새 판독자도 진입 가능 | 기록자 기아 |
| **기록자 우선** | 기록자가 대기 중이면 새 판독자 진입 불가 | 판독자 기아 |

## 핵심 정리

- 임계구역 문제는 상호배제, 진행, 한정 대기 3가지 조건을 만족해야 한다
- 뮤텍스는 이진 잠금으로 상호배제를 구현하며, 바쁜 대기(Spin Lock)가 단점이다
- 세마포어의 P 연산은 자원 획득(대기), V 연산은 자원 해제(신호)이다
- 이진 세마포어는 상호배제, 범용 세마포어는 자원 개수 관리에 사용된다
- 모니터는 고수준 동기화 도구로 Java의 synchronized 블록이 기반이다
