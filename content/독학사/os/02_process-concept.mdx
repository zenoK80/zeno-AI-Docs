## 프로그램 vs 프로세스

**프로그램(Program)**은 디스크에 저장된 정적인 실행 파일입니다. 아직 실행되지 않은 코드 덩어리입니다.

**프로세스(Process)**는 프로그램이 메모리에 올라와 실행 중인 동적인 상태입니다. 같은 프로그램을 두 번 실행하면 두 개의 프로세스가 만들어집니다.

| 구분 | 프로그램 | 프로세스 |
|------|---------|---------|
| 상태 | 정적 (디스크에 저장) | 동적 (메모리에서 실행) |
| 자원 | 없음 | CPU, 메모리, 파일 등 보유 |
| 수명 | 삭제 전까지 존재 | 생성~종료까지만 존재 |

## 프로세스의 메모리 구조

실행 중인 프로세스는 메모리에 다음과 같은 구조로 배치됩니다.

```
높은 주소
┌─────────────┐
│   스택(Stack) │ ← 함수 호출, 지역 변수 (아래로 성장)
├─────────────┤
│     ↓↑      │
├─────────────┤
│   힙(Heap)   │ ← 동적 메모리 할당 (위로 성장)
├─────────────┤
│   데이터(Data)│ ← 전역 변수, 정적 변수
├─────────────┤
│   코드(Text) │ ← 실행 코드 (읽기 전용)
└─────────────┘
낮은 주소
```

## 프로세스 상태(Process State)

프로세스는 실행되는 동안 여러 **상태**를 거칩니다.

### 5가지 기본 상태

| 상태 | 영어 | 설명 |
|------|------|------|
| **생성** | New | 프로세스가 막 만들어진 상태 |
| **준비** | Ready | CPU를 받아 실행될 수 있는 상태, 준비 큐에서 대기 |
| **실행** | Running | CPU를 점유하여 명령어를 실행 중인 상태 |
| **대기** | Waiting/Blocked | I/O 완료 등 특정 이벤트를 기다리는 상태 |
| **종료** | Terminated | 실행을 완료하고 자원이 해제된 상태 |

### 상태 전이도

```
          승인(Admit)           스케줄(Dispatch)
생성 ──────────────► 준비 ─────────────────► 실행
                     ▲                        │
                     │ I/O 완료              │ I/O 요청
                     │ (이벤트 발생)          ▼
                     └──────────────────── 대기
                                             
              타임아웃(Time-out)/선점
                준비 ◄──────────────── 실행
```

- **준비 → 실행:** 스케줄러가 해당 프로세스를 선택(Dispatch)
- **실행 → 대기:** 입출력 요청 등 이벤트를 기다려야 할 때
- **대기 → 준비:** 기다리던 이벤트(I/O 완료)가 발생하면 다시 준비 상태
- **실행 → 준비:** 할당 시간(Time Quantum) 초과로 CPU 반납

## PCB (Process Control Block)

**PCB**는 운영체제가 프로세스 하나를 관리하기 위해 유지하는 자료구조입니다. 프로세스마다 하나씩 생성되며 커널 영역에 저장됩니다.

### PCB에 저장되는 정보

| 항목 | 설명 |
|------|------|
| **프로세스 ID (PID)** | 프로세스를 식별하는 고유 번호 |
| **프로세스 상태** | 현재 상태 (준비, 실행, 대기 등) |
| **프로그램 카운터 (PC)** | 다음에 실행할 명령어의 주소 |
| **CPU 레지스터 값** | 컨텍스트 스위칭 시 저장/복원 |
| **CPU 스케줄링 정보** | 우선순위, 스케줄링 큐 포인터 |
| **메모리 관리 정보** | 페이지 테이블, 세그먼트 테이블 |
| **입출력 상태 정보** | 열린 파일 목록, I/O 장치 정보 |
| **계정 정보** | CPU 사용 시간, 프로세스 시작 시각 |

## 컨텍스트 스위칭(Context Switching)

**컨텍스트 스위칭**은 CPU가 현재 실행 중인 프로세스에서 다른 프로세스로 전환하는 과정입니다.

### 컨텍스트 스위칭 절차

1. 현재 실행 중인 프로세스 A의 상태(레지스터, PC 등)를 **PCB-A에 저장**
2. 다음에 실행할 프로세스 B의 상태를 **PCB-B에서 복원**
3. CPU가 프로세스 B를 실행 시작

```
프로세스 A 실행 중
    │
    ▼
[인터럽트/시스템 호출 발생]
    │
    ▼
PCB-A에 현재 상태 저장 (PC, 레지스터 등)
    │
    ▼
스케줄러가 프로세스 B 선택
    │
    ▼
PCB-B에서 상태 복원
    │
    ▼
프로세스 B 실행
```

<Callout type="warning">
  컨텍스트 스위칭이 일어나는 동안에는 CPU가 유용한 작업을 하지 못합니다. 이를 **오버헤드(Overhead)**라고 하며, 스위칭이 너무 자주 발생하면 성능이 저하됩니다.
</Callout>

## 프로세스 생성과 종료

### 프로세스 생성

Unix/Linux에서 새 프로세스는 **fork()** 시스템 호출로 생성됩니다.

- **부모 프로세스(Parent Process):** 새 프로세스를 생성하는 프로세스
- **자식 프로세스(Child Process):** 부모로부터 생성된 프로세스
- fork()는 부모의 주소 공간을 복사하여 자식을 만듭니다
- exec() 시스템 호출로 자식 프로세스에 새 프로그램을 적재합니다

모든 프로세스는 최초 프로세스(**init**, PID=1)로부터 파생된 트리 구조를 이룹니다.

### 프로세스 종료

- **정상 종료:** exit() 시스템 호출
- **강제 종료:** 부모 프로세스가 abort()로 자식 종료
- 종료된 프로세스가 부모가 wait()로 자원을 회수하기 전 상태를 **좀비 프로세스(Zombie Process)**라고 합니다
- 부모가 먼저 종료된 경우 자식은 **고아 프로세스(Orphan Process)**가 됩니다

## 핵심 정리

- 프로세스는 실행 중인 프로그램이며, 생성/준비/실행/대기/종료의 5가지 상태를 가진다
- PCB는 운영체제가 프로세스를 관리하는 자료구조로 PID, PC, 레지스터 값, 상태 등을 저장한다
- 컨텍스트 스위칭은 CPU가 프로세스를 전환할 때 현재 상태를 PCB에 저장하고 다음 프로세스 상태를 복원하는 과정이다
- 스위칭 중에는 CPU가 유용한 작업을 하지 못하는 오버헤드가 발생한다
