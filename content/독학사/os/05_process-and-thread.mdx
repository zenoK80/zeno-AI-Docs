## 왜 프로세스 관리가 필요한가?

04번 문서에서 배운 시분할 방식은 "CPU를 여러 작업이 번갈아 사용"하는 것이었습니다. 이를 가능하게 하려면, 운영체제가 각 작업이 "지금 어디까지 진행됐는지", "다음엔 무엇을 해야 하는지"를 정확히 기록하고 관리해야 합니다. 이 "실행 중인 작업"의 단위가 **프로세스**(Process)입니다.

## 프로세스(Process)란?

> **쉽게 말하면:** 프로세스는 03번 문서에서 배운 "실행 중인 프로그램"입니다.

프로세스는 단순히 코드만 실행하는 것이 아니라, 다음과 같은 자원들을 함께 가지고 있습니다.

<Table>
  <thead>
    <tr><th>구성 요소</th><th>내용</th></tr>
  </thead>
  <tbody>
    <tr><td>코드(Text)</td><td>실행할 프로그램 명령어</td></tr>
    <tr><td>데이터(Data)</td><td>전역 변수 등 프로그램이 사용하는 데이터</td></tr>
    <tr><td>힙(Heap)</td><td>실행 중 동적으로 할당되는 메모리</td></tr>
    <tr><td>스택(Stack)</td><td>함수 호출 정보, 지역 변수 등을 임시로 저장</td></tr>
  </tbody>
</Table>

## PCB(Process Control Block) — 프로세스의 신분증

> **쉽게 말하면:** PCB는 운영체제가 각 프로세스를 관리하기 위해 만드는 "관리 카드"입니다. 프로세스가 생성되면 운영체제는 이 프로세스의 모든 상태 정보를 PCB에 기록합니다.

<Table>
  <thead>
    <tr><th>PCB에 담기는 정보</th><th>설명</th></tr>
  </thead>
  <tbody>
    <tr><td>프로세스 ID(PID)</td><td>프로세스를 구분하는 고유 번호</td></tr>
    <tr><td>프로세스 상태</td><td>지금 실행 중인지, 대기 중인지 등</td></tr>
    <tr><td>프로그램 카운터</td><td>다음에 실행할 명령어의 주소</td></tr>
    <tr><td>레지스터 값</td><td>CPU 레지스터의 현재 상태(01번 문서 참고)</td></tr>
    <tr><td>메모리 관리 정보</td><td>이 프로세스에 할당된 메모리 위치</td></tr>
  </tbody>
</Table>

## 프로세스의 상태 전이(State Transition)

프로세스는 실행되는 동안 여러 상태를 오갑니다.

<Table>
  <thead>
    <tr><th>상태</th><th>영어</th><th>설명</th></tr>
  </thead>
  <tbody>
    <tr><td>생성</td><td>New</td><td>프로세스가 막 생성된 상태</td></tr>
    <tr><td>준비</td><td>Ready</td><td>CPU를 기다리며 대기 중인 상태(CPU만 배정받으면 바로 실행 가능)</td></tr>
    <tr><td>실행</td><td>Running</td><td>CPU를 배정받아 실제로 실행 중인 상태</td></tr>
    <tr><td>대기</td><td>Waiting/Blocked</td><td>입출력 등 다른 작업이 끝나기를 기다리는 상태</td></tr>
    <tr><td>종료</td><td>Terminated</td><td>실행이 끝난 상태</td></tr>
  </tbody>
</Table>

**상태 전이 흐름:**

<Steps>
### New → Ready
생성된 프로세스가 CPU 배정을 기다리는 큐(대기줄)에 들어감

### Ready → Running
스케줄러가 이 프로세스에 CPU를 배정(다음 문서에서 배울 CPU 스케줄링)

### Running → Waiting
입출력 요청 등으로 CPU를 계속 쓸 수 없게 됨(예: 디스크 읽기 완료를 기다림)

### Waiting → Ready
기다리던 입출력이 완료되어 다시 CPU를 받을 준비가 됨

### Running → Ready
할당된 시간이 끝나 다른 프로세스에게 CPU를 양보(시분할)

### Running → Terminated
프로세스 실행이 끝나 종료됨
</Steps>

<Callout type="warning">
  **자주 틀리는 점:** "Waiting" 상태에서 바로 "Running" 상태로 돌아갈 수 없습니다. 반드시 "Ready"를 거쳐야 합니다 — 입출력이 끝났다고 해서 곧바로 CPU를 다시 받는 것이 아니라, 일단 "준비 완료" 줄에 다시 서서 스케줄러의 선택을 기다려야 합니다.
</Callout>

## 문맥 교환(Context Switch)

> **쉽게 말하면:** 문맥 교환은 "지금 하던 일을 정확히 어디까지 했는지 메모해두고, 다른 작업으로 넘어가는" 과정입니다.

CPU가 프로세스 A에서 프로세스 B로 전환될 때, A의 현재 상태(PCB에 담긴 레지스터 값, 프로그램 카운터 등)를 저장하고, B의 저장된 상태를 CPU에 복원합니다. 이 과정을 **문맥 교환**이라 합니다.

<Callout type="info">
  **문맥 교환에는 비용**(오버헤드)**이 든다:** 문맥 교환 자체는 CPU 시간을 소모하지만 실제 작업(계산 등)을 진행하지는 않습니다. 문맥 교환이 너무 자주 일어나면, 실제 작업보다 "전환하는 데" 더 많은 시간을 쓰게 될 수 있습니다. 이는 다음 문서에서 배울 CPU 스케줄링 알고리즘 설계 시 중요한 고려사항입니다.
</Callout>

## 스레드(Thread) — 프로세스 안의 실행 흐름

> **쉽게 말하면:** 하나의 프로세스가 "회사"라면, 스레드는 그 회사에서 동시에 일하는 "직원들"입니다. 직원들은 같은 사무실(메모리)을 공유하지만, 각자 자기 할 일(실행 흐름)을 가지고 있습니다.

<Table>
  <thead>
    <tr><th>구분</th><th>프로세스</th><th>스레드</th></tr>
  </thead>
  <tbody>
    <tr><td>메모리</td><td>각 프로세스마다 독립된 메모리 공간</td><td>같은 프로세스 안의 스레드는 코드·데이터·힙을 공유</td></tr>
    <tr><td>스택</td><td>-</td><td>스레드마다 독립적인 스택을 가짐</td></tr>
    <tr><td>생성 비용</td><td>상대적으로 무거움(메모리 공간을 새로 할당)</td><td>상대적으로 가벼움(메모리를 공유하므로)</td></tr>
    <tr><td>통신</td><td>프로세스 간 통신(IPC)이 필요, 상대적으로 복잡</td><td>메모리를 공유하므로 통신이 간단</td></tr>
  </tbody>
</Table>

**왜 스레드를 쓰는가?** 예를 들어 워드프로세서 프로그램이 "문서를 화면에 표시하는 작업"과 "맞춤법을 검사하는 작업"을 동시에 수행하려 할 때, 별도의 프로세스로 만들면 메모리를 두 배로 쓰고 통신도 복잡해집니다. 같은 프로세스 안에서 스레드 두 개로 나누면, 메모리를 공유하면서도 각자 독립적으로 진행할 수 있습니다.

## 핵심 정리

- **프로세스**: 실행 중인 프로그램. 코드·데이터·힙·스택으로 구성.
- **PCB**: 프로세스의 상태 정보(PID, 상태, 프로그램 카운터, 레지스터 등)를 담은 관리 카드.
- **상태 전이**: New→Ready→Running→(Waiting↔Ready)→Terminated. Waiting에서 Running으로 직접 갈 수 없다.
- **문맥 교환**: 프로세스 전환 시 현재 상태를 저장하고 다음 프로세스 상태를 복원. 오버헤드가 있다.
- **스레드**: 프로세스 내부의 실행 흐름. 프로세스 자원을 공유하며 생성 비용이 가볍다.
