## 왜 입출력 관리가 필요한가?

CPU에 비해 키보드, 디스크 같은 입출력 장치는 속도가 훨씬 느립니다. 이 속도 차이를 잘 관리하지 못하면 CPU가 느린 장치를 기다리며 아까운 시간을 낭비하게 됩니다. 이 문서는 04번 문서에서 배운 인터럽트를 실제 입출력 장치 관리에 어떻게 적용하는지, 그리고 디스크 접근을 효율화하는 방법을 다룹니다.

## DMA(Direct Memory Access)

> **쉽게 말하면:** DMA는 "CPU를 거치지 않고, 입출력 장치가 메모리와 직접 데이터를 주고받게" 해주는 기술입니다.

**DMA 없이 데이터를 전송하면:** CPU가 장치로부터 데이터를 한 바이트씩 직접 읽어 메모리에 옮겨야 해서, 전송하는 내내 CPU가 다른 일을 못 합니다.

**DMA 컨트롤러를 사용하면:** CPU는 "이 정도 분량을 이 위치로 옮겨라"라고 DMA 컨트롤러에 지시만 하고, 실제 전송은 DMA 컨트롤러가 대신 처리합니다. CPU는 그동안 다른 작업을 수행할 수 있고, 전송이 끝나면 DMA 컨트롤러가 인터럽트로 CPU에 완료를 알립니다.

<Callout type="info">
  **DMA와 인터럽트의 관계:** DMA는 04번 문서에서 배운 인터럽트 메커니즘을 그대로 활용합니다 — 전송이 끝났다는 것을 CPU가 계속 확인(폴링)하는 대신, 끝났을 때만 인터럽트로 알리는 방식이 여기서도 적용됩니다.
</Callout>

## 디스크 스케줄링(Disk Scheduling)

> **쉽게 말하면:** 디스크는 회전하는 원반 위에서 헤드(바늘)가 움직여 데이터를 읽습니다. 여러 곳의 데이터를 읽어야 할 때, 헤드가 어떤 순서로 움직이면 이동 거리(시간)를 최소화할 수 있을지 정하는 것이 디스크 스케줄링입니다.

### FCFS(First-Come, First-Served)

06번 문서에서 배운 CPU 스케줄링의 FCFS와 같은 원리로, 요청이 들어온 순서대로 처리합니다. 구현은 단순하지만 헤드가 이리저리 오가며 이동 거리가 비효율적일 수 있습니다.

### SSTF(Shortest Seek Time First)

> **쉽게 말하면:** 지금 헤드 위치에서 가장 가까운 요청부터 처리합니다.

**예시:** 현재 헤드 위치 50, 요청 큐 [95, 180, 34, 119, 11, 123, 62, 64]

가장 가까운 것부터: 50→62→64→34→11→95→119→123→180 (매 단계 가장 가까운 다음 요청 선택)

<Callout type="warning">
  **SSTF의 문제 — 기아 상태:** SSTF는 항상 가장 가까운 요청을 우선하므로, 헤드에서 멀리 떨어진 요청은 계속 밀려 오랫동안(또는 영원히) 처리되지 못할 수 있습니다. 08번 문서의 SJF가 가진 기아 상태 문제와 정확히 같은 유형의 문제입니다.
</Callout>

### SCAN(엘리베이터 알고리즘)

> **쉽게 말하면:** SCAN은 헤드가 디스크의 한쪽 끝에서 다른쪽 끝까지 마치 엘리베이터처럼 쭉 이동하면서, 지나가는 길에 있는 모든 요청을 처리합니다.

**예시:** 헤드가 현재 50에서 큰 방향으로 이동 중이라면, 50→62→64→95→119→123→180(끝)→그 다음 반대 방향으로 34→11 순서로 처리.

### C-SCAN(Circular SCAN)

> **쉽게 말하면:** C-SCAN은 SCAN처럼 한쪽 끝까지 이동하며 처리하지만, 끝에 도달하면 반대편 끝으로 바로 이동한 뒤(그 사이는 처리하지 않고) 다시 같은 방향으로만 처리합니다.

**왜 굳이 이렇게 하는가?** SCAN은 왕복하면서 중간 영역이 양쪽에서 처리되어 대기시간이 불균등해질 수 있습니다(중간 지역은 자주 처리되고, 끝 지역은 최근에 지나간 지 오래됨). C-SCAN은 항상 한 방향으로만 처리해, 각 위치가 균등한 간격으로 서비스받도록 만듭니다.

## RAID(Redundant Array of Independent Disks)

> **쉽게 말하면:** RAID는 여러 개의 디스크를 하나처럼 묶어서, 속도를 높이거나 데이터를 안전하게 보호하는 기술입니다.

<Table>
  <thead>
    <tr><th>레벨</th><th>방식</th><th>특징</th></tr>
  </thead>
  <tbody>
    <tr><td>RAID 0</td><td>스트라이핑(데이터를 여러 디스크에 나눠 저장)</td><td>속도는 빠르지만 중복 저장이 없어 디스크 하나만 고장 나도 데이터 손실</td></tr>
    <tr><td>RAID 1</td><td>미러링(같은 데이터를 두 디스크에 동시 저장)</td><td>안정성은 높지만 저장 용량 효율은 절반</td></tr>
    <tr><td>RAID 5</td><td>스트라이핑 + 패리티(오류 복구용 정보) 분산 저장</td><td>속도와 안정성의 균형, 디스크 하나 고장까지는 복구 가능</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** RAID 0은 "안정성을 높이는 기술"이 아니라 오히려 디스크 하나만 고장 나도 전체 데이터가 손실되는 **가장 위험한** 구성입니다. RAID 0의 목적은 순전히 "속도 향상"이며, 데이터 보호가 목적이라면 RAID 1이나 RAID 5를 사용해야 합니다.
</Callout>

## 핵심 정리

- **DMA**: CPU를 거치지 않고 장치와 메모리가 직접 데이터를 주고받게 해 CPU 부담을 줄이는 기술.
- **디스크 스케줄링**: FCFS(단순), SSTF(짧은 이동거리, 기아 상태 위험), SCAN(왕복), C-SCAN(균등한 서비스 간격).
- **RAID 0**: 속도 향상(스트라이핑), 안정성 없음. **RAID 1**: 미러링, 높은 안정성. **RAID 5**: 스트라이핑+패리티, 속도와 안정성의 균형.
