## 왜 UNIX를 따로 배우는가?

지금까지 배운 프로세스, 메모리, 파일 관리 등의 개념은 특정 운영체제에 국한되지 않는 **일반 이론**이었습니다. UNIX는 이 이론들이 실제로 어떻게 하나의 완성된 시스템으로 구현되었는지 보여주는 대표적인 사례이며, 다음 문서에서 배울 Linux의 뿌리이기도 합니다.

## UNIX의 특징

> **쉽게 말하면:** UNIX는 "작은 도구를 여러 개 조합해서 큰 일을 한다"는 철학으로 만들어진 운영체제입니다.

<Table>
  <thead>
    <tr><th>특징</th><th>설명</th></tr>
  </thead>
  <tbody>
    <tr><td>다중 사용자(Multi-user)</td><td>여러 사용자가 동시에 시스템을 사용 가능</td></tr>
    <tr><td>다중 작업(Multi-tasking)</td><td>04번 문서의 시분할 방식으로 여러 프로세스 동시 실행</td></tr>
    <tr><td>이식성(Portability)</td><td>대부분 C언어로 작성되어 다양한 하드웨어에 이식 가능</td></tr>
    <tr><td>계층적 파일 시스템</td><td>11번 문서에서 배운 트리 구조 디렉터리</td></tr>
  </tbody>
</Table>

## UNIX의 계층 구조

```
사용자 프로그램
      ↓
쉘(Shell)
      ↓
커널(Kernel)
      ↓
하드웨어
```

<Table>
  <thead>
    <tr><th>계층</th><th>역할</th></tr>
  </thead>
  <tbody>
    <tr><td>커널(Kernel)</td><td>04번 문서에서 배운 커널 영역. 프로세스·메모리·파일 관리 등 핵심 기능 수행</td></tr>
    <tr><td>쉘(Shell)</td><td>사용자의 명령을 해석해 커널에 전달하는 인터페이스</td></tr>
  </tbody>
</Table>

> **쉬운 비유:** 커널이 "공장 안에서 실제로 일하는 기계"라면, 쉘은 "공장 밖에서 주문을 받아 기계에 전달하는 접수처"입니다. 사용자는 쉘에 명령어를 입력하고, 쉘이 이를 해석해 커널에게 실제 작업을 요청합니다.

## UNIX의 프로세스 관리

UNIX에서 새 프로세스를 만드는 대표적인 시스템 호출은 `fork()`입니다.

> **쉽게 말하면:** `fork()`는 지금 실행 중인 프로세스를 통째로 복제해서 새로운 프로세스(자식 프로세스)를 만드는 명령입니다.

<Table>
  <thead>
    <tr><th>용어</th><th>설명</th></tr>
  </thead>
  <tbody>
    <tr><td>부모 프로세스(Parent Process)</td><td>fork()를 호출한 원래 프로세스</td></tr>
    <tr><td>자식 프로세스(Child Process)</td><td>fork()로 새로 생성된 복제 프로세스</td></tr>
  </tbody>
</Table>

`exec()` **계열 함수**: fork로 만든 자식 프로세스가 부모와 똑같은 코드를 실행하는 대신, 완전히 다른 새 프로그램으로 바꿔치기하고 싶을 때 사용합니다. `fork()` 후 `exec()`를 호출하는 조합은 UNIX/Linux에서 새 프로그램을 실행하는 표준적인 방법입니다.

## UNIX 파일 시스템 구조

UNIX는 루트(`/`) 디렉터리를 최상위로 하는 트리 구조입니다.

<Table>
  <thead>
    <tr><th>디렉터리</th><th>용도</th></tr>
  </thead>
  <tbody>
    <tr><td>/bin</td><td>기본 실행 명령어(프로그램) 저장</td></tr>
    <tr><td>/etc</td><td>시스템 설정 파일 저장</td></tr>
    <tr><td>/home</td><td>각 사용자의 개인 디렉터리</td></tr>
    <tr><td>/dev</td><td>장치 파일(키보드, 디스크 등을 파일처럼 다룸)</td></tr>
  </tbody>
</Table>

<Callout type="info">
  **"모든 것은 파일이다"**(Everything is a File): UNIX의 핵심 철학 중 하나로, 일반 문서뿐 아니라 키보드·프린터 같은 장치, 프로세스 간 통신 통로까지도 모두 "파일"이라는 동일한 인터페이스로 다룹니다. 이 덕분에 파일을 읽고 쓰는 것과 똑같은 방식으로 장치를 제어할 수 있어, 시스템 전체가 일관된 방식으로 동작합니다.
</Callout>

## 기본 UNIX 명령어

<Table>
  <thead>
    <tr><th>명령어</th><th>기능</th></tr>
  </thead>
  <tbody>
    <tr><td>ls</td><td>현재 디렉터리의 파일 목록 표시(list의 줄임말)</td></tr>
    <tr><td>cd</td><td>디렉터리 이동(change directory)</td></tr>
    <tr><td>pwd</td><td>현재 위치한 디렉터리 경로 출력(print working directory)</td></tr>
    <tr><td>cp</td><td>파일 복사(copy)</td></tr>
    <tr><td>rm</td><td>파일 삭제(remove)</td></tr>
    <tr><td>chmod</td><td>11번 문서에서 배운 파일 권한(rwx) 변경(change mode)</td></tr>
    <tr><td>ps</td><td>현재 실행 중인 프로세스 목록 표시(process status)</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** 명령어의 정확한 철자와 기능을 혼동하기 쉽습니다. 특히 `ps`(프로세스 상태 확인)와 `pwd`(현재 경로 확인)는 이름이 비슷해 보이지만 완전히 다른 기능을 합니다. 시험에서는 이런 명령어의 정확한 기능 매칭이 자주 출제됩니다.
</Callout>

## 핵심 정리

- **UNIX**: 다중 사용자·다중 작업 지원, C언어 기반 이식성, 계층적 파일 시스템을 가진 운영체제.
- **구조**: 사용자 프로그램 → 쉘(명령 해석) → 커널(핵심 기능) → 하드웨어.
- **프로세스 생성**: `fork()`로 복제, `exec()`로 새 프로그램으로 교체. 이 조합이 표준적인 새 프로그램 실행 방법.
- **"모든 것은 파일이다"**: 장치까지도 파일 인터페이스로 통일해서 다룬다.
- 기본 명령어: ls(목록), cd(이동), pwd(현재 경로), chmod(권한 변경), ps(프로세스 확인) 등.
