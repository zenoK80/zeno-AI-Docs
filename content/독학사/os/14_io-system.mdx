## 입출력 시스템이 왜 중요한가?

CPU는 엄청나게 빠릅니다. 반면 키보드, 프린터, 하드 디스크는 CPU에 비해 수십~수백만 배 느립니다. CPU가 느린 장치를 기다리기만 한다면 엄청난 낭비입니다.

**입출력(I/O, Input/Output) 시스템**은 이 속도 차이를 극복하면서 CPU와 다양한 주변 장치(키보드, 디스크, 프린터 등) 간의 데이터 교환을 효율적으로 관리하는 체계입니다.

**쉽게 말하면:** 빠른 요리사(CPU)와 느린 배달원(I/O 장치) 사이에서 주문을 관리하고 음식을 받아두는 역할을 하는 것이 I/O 시스템입니다.

## 장치의 분류

| 분류 | 예시 | 특징 |
|------|------|------|
| **문자 장치(Character Device)** | 키보드, 마우스, 시리얼 포트 | 바이트 단위 전송 |
| **블록 장치(Block Device)** | 디스크, CD-ROM | 블록 단위 전송, 직접 접근 |
| **네트워크 장치(Network Device)** | 이더넷, Wi-Fi | 네트워크 패킷(Packet) 전송 |

## 입출력 제어 방식

CPU와 장치 사이에서 데이터를 주고받는 방법은 발전 순서에 따라 크게 4가지입니다.

### 1. 프로그램 제어 입출력 (폴링, Polling)

CPU가 직접 장치 상태를 **주기적으로 반복 검사**합니다. "준비됐니? 준비됐니? 준비됐니? ..."를 계속 물어보는 방식입니다.

```
CPU: 장치 준비됐니? → 아니오
CPU: 장치 준비됐니? → 아니오
CPU: 장치 준비됐니? → 예 → 데이터 전송
```

- **장점:** 구현이 단순합니다
- **단점:** 장치가 준비될 때까지 CPU가 계속 확인하므로 **바쁜 대기(Busy Waiting)** 발생 — CPU 시간 낭비가 심합니다

**쉽게 말하면:** 물이 끓을 때까지 계속 들여다보는 것입니다. 그 시간 동안 다른 일은 전혀 못 합니다.

### 2. 인터럽트 방식 (Interrupt-Driven I/O)

CPU가 I/O 요청을 한 후 **다른 작업을 수행**하다가, 장치가 준비되면 **인터럽트(Interrupt)**로 CPU에 알립니다.

```
CPU: I/O 요청 후 → 다른 작업 A 진행
                              ↑
장치: [준비됨] → 인터럽트 신호 → CPU가 하던 일 잠깐 중단 → 인터럽트 처리 → 원래 작업 재개
```

- **장점:** CPU가 I/O를 기다리는 동안 다른 작업 가능 → CPU 효율 향상
- **단점:** 소량 데이터를 자주 전송할 경우 인터럽트 처리 오버헤드(Overhead, 부가 비용) 발생

**쉽게 말하면:** 물을 올려놓고 다른 일 하다가, 주전자가 "삐~" 소리를 내면 그때 가서 처리합니다.

### 3. DMA (Direct Memory Access, 직접 메모리 접근)

**DMA 제어기(DMA Controller)**가 CPU 개입 없이 **직접 메모리와 장치 간에 대량 데이터를 전송**합니다. CPU는 DMA에게 "이 주소에서 저 장치로 이만큼 보내줘"라고 지시만 하고 다른 일을 합니다.

```
CPU → DMA에게 전송 요청 (시작 주소, 블록 수, 방향)
DMA → 독립적으로 메모리 ↔ 장치 간 데이터 전송
DMA → 전송 완료 시 CPU에 인터럽트 발생
CPU → 완료 통지 받고 다음 작업 처리
```

- **장점:** 대용량 데이터 전송 시 CPU 부하 최소화
- **단점:** DMA 제어기 하드웨어 추가 필요, 사이클 스틸링 발생

**쉽게 말하면:** 이사(대용량 데이터 이동)를 CEO(CPU)가 직접 박스 들고 나르는 대신 이삿짐 회사(DMA)에 맡기고 CEO는 다른 일을 하는 것입니다.

#### 사이클 스틸링 (Cycle Stealing, 사이클 가로채기)

DMA가 메모리 버스를 사용할 때 CPU도 메모리를 동시에 사용할 수 없습니다. DMA가 한 번의 버스 사이클을 "빼앗는" 현상을 **사이클 스틸링(Cycle Stealing)**이라 합니다. CPU 처리 속도가 약간 저하될 수 있습니다.

### 4. 채널 (Channel) 방식

**채널(Channel)**은 I/O 전담 소형 프로세서입니다. CPU로부터 I/O 제어를 완전히 독립적으로 처리합니다. 대형 메인프레임(Mainframe, 대형 컴퓨터)에서 사용합니다.

| 방식 | 설명 |
|------|------|
| **셀렉터 채널(Selector Channel)** | 한 번에 하나의 고속 장치와 통신 |
| **멀티플렉서 채널(Multiplexer Channel)** | 여러 저속 장치와 동시에 통신 |
| **블록 멀티플렉서 채널(Block Multiplexer Channel)** | 여러 고속 장치와 블록 단위로 통신 |

## I/O 제어 방식 비교

| 방식 | CPU 부하 | 적합한 경우 | 특징 |
|------|---------|-----------|------|
| **폴링** | 매우 높음 | 간단한 시스템 | 바쁜 대기 |
| **인터럽트** | 보통 | 소량 데이터 | 인터럽트 오버헤드 |
| **DMA** | 낮음 | 대용량 데이터 | 사이클 스틸링 |
| **채널** | 매우 낮음 | 메인프레임 | 전담 프로세서 |

## 버퍼링 (Buffering)

**버퍼(Buffer)**는 입출력 데이터를 임시 저장하는 메모리 영역입니다. CPU와 장치의 속도 차이를 완충합니다.

**쉽게 말하면:** 빠른 요리사가 만든 음식을 홀에서 손님에게 바로 전달하지 않고 서빙 대기 공간(버퍼)에 잠깐 두는 것입니다.

| 종류 | 설명 |
|------|------|
| **단일 버퍼링(Single Buffering)** | 입력 중에는 처리 불가, 처리 중에는 입력 불가 |
| **이중 버퍼링(Double Buffering)** | 버퍼 2개를 번갈아 사용하여 입력과 처리를 동시에 |
| **순환 버퍼링(Circular Buffering)** | 여러 버퍼를 원형으로 연결하여 고속 처리 |

이중 버퍼링의 동작:
```
버퍼A ← 입력 중           버퍼B → CPU가 처리 중
     ↕ 교환 (버퍼A가 가득 차면)
버퍼A → CPU가 처리 중      버퍼B ← 입력 중
```

## 스풀링 (Spooling, Simultaneous Peripheral Operations On-Line)

**스풀링(Spooling)**은 느린 출력 장치(프린터 등)를 위해 디스크를 중간 버퍼로 사용하는 기법입니다. SPOOLING은 "온라인으로 동시에 주변 장치 작업을 수행한다"는 의미입니다.

```
프로세스A ──┐
프로세스B ──┼──→ 디스크(스풀 영역) ──→ 프린터 (순서대로 처리)
프로세스C ──┘
```

- 여러 프로세스가 동시에 프린터 출력 요청 → 모두 디스크의 스풀 영역에 저장
- 프린터 스풀러(Spooler)가 스풀 파일을 순서대로 프린터로 전송
- CPU는 빠른 디스크에만 쓰면 되므로 효율적 → 프로그램이 프린터 작업 후 곧바로 다른 작업 가능

**쉽게 말하면:** 여러 사람이 프린터를 쓰려 할 때 바로 밀리지 않고, 각자의 출력물을 줄 세워두었다가 하나씩 처리하는 것입니다. 줄에 세워두고 나면 각자는 기다리지 않아도 됩니다.

## 인터럽트 처리 절차

```
1. 인터럽트(Interrupt) 발생
2. 현재 실행 중인 명령어 완료
3. 현재 프로세스 상태(PC, 레지스터) 스택(Stack)에 저장
4. 인터럽트 벡터 테이블(Interrupt Vector Table)에서 ISR 주소 검색
5. 인터럽트 서비스 루틴(ISR, Interrupt Service Routine) 실행
6. 저장된 상태 복원
7. 원래 프로세스 재개
```

## 커널 입출력 서브시스템

현대 OS의 I/O 서브시스템은 여러 계층으로 구성됩니다.

```
응용 프로그램 (Application)
     ↓  표준 API (read/write 등)
파일 시스템 / 장치 독립적 인터페이스
     ↓
장치 드라이버 (Device Driver, 커널 내)
     ↓
하드웨어 제어기 (인터럽트, DMA)
     ↓
물리적 장치 (Physical Device)
```

**장치 드라이버(Device Driver):** 특정 장치를 제어하는 소프트웨어 모듈. OS와 하드웨어 사이의 인터페이스 역할. 프린터를 교체하면 드라이버만 교체하면 OS는 그대로 사용할 수 있는 것이 이 구조 덕분입니다.

## 메모리 사상 입출력 vs 분리형 입출력

| 방식 | 설명 |
|------|------|
| **메모리 사상 입출력 (Memory-Mapped I/O)** | 장치 레지스터가 메모리 주소 공간의 일부를 차지하여 메모리 명령으로 장치 제어 |
| **분리형 입출력 (Isolated I/O)** | 장치 주소 공간이 메모리와 별도로 존재, 전용 I/O 명령 사용 |

## 핵심 정리

- 입출력 제어 방식 발전: 폴링(CPU 낭비) → 인터럽트(CPU 해방) → DMA(직접 전송) → 채널(전담 프로세서)
- DMA(Direct Memory Access)는 대용량 데이터 전송 시 CPU를 해방시키며, 완료 시 인터럽트로 알린다
- 사이클 스틸링(Cycle Stealing)은 DMA가 버스 사이클을 잠시 차지하여 CPU 속도가 약간 저하되는 현상
- 스풀링(Spooling)은 느린 장치(프린터)를 위해 디스크를 중간 버퍼로 사용하는 기법이다
- 버퍼링(Buffering)은 속도 차이를 완충하며 이중 버퍼링으로 입출력과 처리를 병행한다
