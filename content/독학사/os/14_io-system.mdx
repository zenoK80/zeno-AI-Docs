## 입출력 시스템 개요

**입출력(I/O)** 시스템은 CPU와 다양한 주변 장치(키보드, 디스크, 프린터 등) 간의 데이터 교환을 관리합니다.

### 장치의 분류

| 분류 | 예시 | 특징 |
|------|------|------|
| **문자 장치** | 키보드, 마우스, 시리얼 포트 | 바이트 단위 전송 |
| **블록 장치** | 디스크, CD-ROM | 블록 단위 전송, 직접 접근 |
| **네트워크 장치** | 이더넷, Wi-Fi | 네트워크 패킷 전송 |

## 입출력 제어 방식

### 1. 프로그램 제어 입출력 (폴링, Polling)

CPU가 직접 장치 상태를 **주기적으로 검사**합니다.

```
CPU: 장치 준비됐니? → 아니오
CPU: 장치 준비됐니? → 아니오
CPU: 장치 준비됐니? → 예 → 데이터 전송
```

**단점:** 장치가 준비될 때까지 CPU가 계속 확인하므로 CPU 낭비가 심합니다 (Busy Waiting).

### 2. 인터럽트 방식 (Interrupt-Driven I/O)

CPU가 I/O 요청을 한 후 **다른 작업을 수행**하고, 장치가 준비되면 **인터럽트로 CPU에 알립니다**.

```
CPU: I/O 요청 → 다른 작업 진행
                      ↑
장치: [준비됨] → 인터럽트 발생 → CPU가 인터럽트 처리
```

**장점:** CPU 낭비 없이 다른 작업 가능  
**단점:** 소량 데이터 전송에도 인터럽트 오버헤드 발생

### 3. DMA (Direct Memory Access)

**DMA 제어기**가 CPU 개입 없이 **직접 메모리와 장치 간에 대량 데이터를 전송**합니다.

```
CPU → DMA에게 전송 요청 (시작 주소, 블록 수, 방향)
DMA → 독립적으로 메모리 ↔ 장치 간 데이터 전송
DMA → 전송 완료 시 CPU에 인터럽트 발생
CPU → 다음 작업 처리
```

**장점:** 대용량 데이터 전송 시 CPU 부하 최소화  
**단점:** DMA 제어기 하드웨어 추가 필요

#### 사이클 스틸링(Cycle Stealing)

DMA가 메모리를 사용할 때 CPU의 메모리 버스 사이클을 일시적으로 빼앗는 현상입니다. CPU 처리 속도가 약간 저하될 수 있습니다.

### 4. 채널 (Channel) 방식

**채널**은 I/O 전담 소형 프로세서입니다. 대형 메인프레임에서 사용합니다.

| 방식 | 설명 |
|------|------|
| **셀렉터 채널** | 한 번에 하나의 고속 장치와 통신 |
| **멀티플렉서 채널** | 여러 저속 장치와 동시에 통신 |
| **블록 멀티플렉서 채널** | 여러 고속 장치와 블록 단위로 통신 |

## 버퍼링(Buffering)

**버퍼**는 입출력 데이터를 임시 저장하는 메모리 영역입니다.

| 종류 | 설명 |
|------|------|
| **단일 버퍼링** | 입력 중에는 처리 불가, 처리 중에는 입력 불가 |
| **이중 버퍼링** | 버퍼 2개를 번갈아 사용하여 입력과 처리를 동시에 |
| **순환 버퍼링** | 여러 버퍼를 원형으로 연결하여 고속 처리 |

## 스풀링(Spooling, Simultaneous Peripheral Operations On-Line)

**스풀링**은 느린 출력 장치(프린터 등)를 위해 디스크를 중간 버퍼로 사용하는 기법입니다.

```
프로세스A ──┐
프로세스B ──┼──→ 디스크(스풀) ──→ 프린터
프로세스C ──┘
```

- 프린터처럼 한 번에 한 작업만 처리하는 장치에서 여러 프로세스가 동시에 출력 요청 가능
- 실제 프린터는 스풀 파일을 순서대로 처리
- CPU가 출력을 빠른 디스크에만 쓰면 되므로 효율적

## 입출력 장치 주소 지정

| 방식 | 설명 |
|------|------|
| **메모리 사상 입출력 (Memory-Mapped I/O)** | 장치 레지스터가 메모리 주소 공간의 일부를 차지 |
| **분리형 입출력 (Isolated I/O)** | 장치 주소 공간이 메모리와 분리 |

## 인터럽트 처리 절차

```
1. 인터럽트 발생
2. 현재 실행 중인 명령어 완료
3. 현재 프로세스 상태(PC, 레지스터) 스택에 저장
4. 인터럽트 벡터 테이블에서 ISR 주소 검색
5. 인터럽트 서비스 루틴(ISR) 실행
6. 저장된 상태 복원
7. 원래 프로세스 재개
```

## 커널 입출력 서브시스템

현대 OS의 I/O 서브시스템은 여러 계층으로 구성됩니다.

```
응용 프로그램
     ↓
파일 시스템 / 장치 독립적 인터페이스
     ↓
장치 드라이버 (커널 내)
     ↓
하드웨어 제어기 (인터럽트, DMA)
     ↓
물리적 장치
```

**장치 드라이버(Device Driver):** 특정 장치를 제어하는 소프트웨어 모듈. OS와 하드웨어 사이의 인터페이스 역할.

## 핵심 정리

- 입출력 제어 방식: 폴링(CPU 낭비) → 인터럽트(CPU 해방) → DMA(직접 전송) → 채널(전담 프로세서)
- DMA는 대용량 데이터 전송 시 CPU를 해방시키며, 완료 시 인터럽트로 알린다
- 스풀링은 느린 장치(프린터)를 위해 디스크를 중간 버퍼로 사용하는 기법이다
- 버퍼링은 속도 차이를 완충하며 이중 버퍼링으로 입출력과 처리를 병행한다
