## 파일 시스템이 왜 필요한가?

컴퓨터에 사진, 문서, 음악 파일이 수만 개 있다고 생각해 보세요. 이 모든 파일을 어디에 저장하고, 어떻게 찾고, 누가 볼 수 있는지 어떻게 관리할까요?

하드 드라이브나 SSD는 그냥 0과 1이 저장되는 공간입니다. 파일의 이름, 위치, 크기, 접근 권한 등을 체계적으로 관리하는 것이 **파일 시스템**(File System)의 역할입니다.

**쉽게 말하면:** 파일 시스템은 거대한 창고(디스크)에 물건(파일)을 체계적으로 정리하고, 위치를 기록하고, 누가 꺼낼 수 있는지 관리하는 창고 관리 시스템입니다.

## 파일 시스템(File System)의 주요 기능

- 파일 생성, 삭제, 읽기, 쓰기
- 디렉터리(Directory, 폴더) 관리
- 파일 접근 제어 (권한 관리)
- 파일 공유
- 백업(Backup)과 복구(Recovery)

## 파일(File)의 개념

**파일**(File)은 관련된 정보의 집합으로 보조기억장치(Secondary Storage, 하드디스크, SSD 등)에 저장됩니다. 운영체제는 파일을 가장 작은 논리적 저장 단위로 봅니다.

### 파일 속성 (메타데이터, Metadata)

메타데이터(Metadata)란 "데이터에 대한 데이터"입니다. 파일 내용 외에 파일을 설명하는 정보입니다.

| 속성 | 설명 |
|------|------|
| **이름**(Name) | 사람이 읽을 수 있는 식별자 |
| **식별자**(Identifier) | 고유한 숫자 식별자 (inode 번호 등) |
| **유형**(Type) | 파일 종류 (텍스트, 실행파일, 이미지 등) |
| **위치**(Location) | 장치와 디스크 내 위치 포인터 |
| **크기**(Size) | 현재 파일 크기 |
| **보호**(Protection) | 접근 권한 정보 |
| **시간/날짜** | 생성, 수정, 접근 시각 |

### 파일 접근 방법

| 방법 | 설명 | 특징 |
|------|------|------|
| **순차 접근**(Sequential Access) | 처음부터 순서대로 읽음 | 테이프 장치 방식, 단순 |
| **직접 접근**(Direct Access) | 임의의 위치에 바로 접근 | 디스크에 적합 |
| **색인 접근**(Indexed Access) | 색인(Index, 인덱스)을 통해 접근 | 대용량 데이터에 유용 |

**쉽게 말하면:** 순차 접근은 카세트 테이프처럼 처음부터 감아야 하고, 직접 접근은 CD처럼 원하는 트랙으로 바로 이동할 수 있습니다.

## 디렉터리 구조

**디렉터리**(Directory)는 파일들을 묶어 관리하는 구조입니다. 운영체제마다 다양한 디렉터리 구조를 사용합니다.

### 1단계 디렉터리 (Single-Level Directory)

모든 파일이 하나의 디렉터리에 존재합니다. 구현이 간단하지만 파일 이름이 모두 달라야 하고, 파일 수가 많아지면 찾기 어렵습니다.

### 2단계 디렉터리 (Two-Level Directory)

사용자별로 별도의 디렉터리를 가집니다. 사용자 간 동일 파일명 허용, 그러나 사용자 내에서는 중복 불가.

### 트리 구조 디렉터리 (Tree-Structured Directory)

**현대 운영체제**(Windows, Linux, macOS 등)에서 사용하는 방식으로 루트 디렉터리(Root Directory, 최상위 디렉터리) 아래 계층적으로 디렉터리가 구성됩니다.

```
/ (루트 디렉터리)
├── home/
│   ├── user1/
│   └── user2/
├── etc/
└── var/
```

- 절대 경로(Absolute Path): 루트(`/`)에서 시작하는 전체 경로
- 상대 경로(Relative Path): 현재 디렉터리에서 시작하는 경로

### 비순환 그래프 디렉터리 (Acyclic-Graph Directory)

파일 및 디렉터리의 **공유**(Sharing)가 가능합니다. **링크**(Link)를 통해 구현합니다.

- **하드 링크(Hard Link):** 같은 inode를 공유하는 또 다른 이름 (원본 삭제해도 파일 유지)
- **심볼릭 링크(Symbolic Link, 소프트 링크):** 원본 파일의 경로를 저장하는 별도 파일 (원본 삭제 시 링크 끊어짐)

## 디스크 공간 할당 방법

파일을 디스크에 어떻게 저장할지 결정하는 방법입니다.

### 연속 할당 (Contiguous Allocation, 연속 배치)

파일을 연속된 블록에 저장합니다.

```
디스크:
파일A: │블록3│블록4│블록5│          (연속)
파일B: │블록8│블록9│               (연속)
빈 공간: │블록6│블록7│              (사이에 낀 빈 공간)
```

- **장점:** 순차 접근과 직접 접근 모두 빠름
- **단점:** 외부 단편화 발생, 파일 크기 미리 알아야 함, 파일 크기 변경 어려움

### 연결 할당 (Linked Allocation, 연결 리스트)

각 블록이 다음 블록의 주소를 포인터로 포함하는 체인(Chain) 구조입니다.

```
파일A 시작 블록: 3
블록3 → [데이터][다음: 8]
블록8 → [데이터][다음: 11]
블록11 → [데이터][다음: NULL]
```

- **장점:** 외부 단편화 없음, 동적 크기 변경 가능
- **단점:** 직접 접근 느림 (n번째 블록에 가려면 처음부터 따라가야 함), 포인터 저장 오버헤드(Overhead), 포인터 손상 시 파일 손실

**FAT(File Allocation Table, 파일 할당 테이블):** 연결 할당을 개선하여 연결 포인터를 디스크 앞부분의 별도 테이블(FAT)에 집중 저장합니다. Windows의 FAT, FAT32 파일 시스템이 사용합니다.

```
FAT 테이블 (예시):
블록 번호 | 다음 블록
    3     |    8
    8     |    11
   11     |   EOF (끝)
```

### 인덱스 할당 (Indexed Allocation, 색인 할당)

파일의 모든 블록 번호를 **인덱스 블록**(Index Block) 하나에 모아 저장합니다.

```
인덱스 블록 9:
[블록3, 블록8, 블록11, 블록15]
    ↓       ↓       ↓       ↓
  데이터1  데이터2  데이터3  데이터4
```

- **장점:** 직접 접근 지원, 외부 단편화 없음
- **단점:** 인덱스 블록 자체가 공간을 차지 (작은 파일에는 낭비)

## inode 구조 (Unix/Linux)

**inode**(Index Node, 인덱스 노드)는 Unix/Linux에서 사용하는 방식으로, 파일마다 하나씩 생성되는 자료구조입니다.

```
inode 구조:
┌────────────────────────┐
│ 파일 유형, 권한         │
│ 소유자, 그룹            │
│ 파일 크기              │
│ 타임스탬프(생성/수정/접근)│
├────────────────────────┤
│ 직접 포인터 12개        │ → 소형 파일 직접 접근
│ 단일 간접 포인터         │ → 중형 파일 (포인터 블록 경유)
│ 이중 간접 포인터         │ → 대형 파일 (2단계 경유)
│ 삼중 간접 포인터         │ → 초대형 파일 (3단계 경유)
└────────────────────────┘
```

**중요:** 파일 이름은 inode에 없습니다! 디렉터리가 "파일 이름 → inode 번호"를 매핑합니다.

**쉽게 말하면:** inode는 파일의 신분증과 같습니다. 이름은 신분증에 없고 (디렉터리가 이름을 관리), 신분증(inode)에는 주요 속성과 데이터 위치가 기록됩니다.

## 접근 제어 (Access Control)

**접근 제어 행렬**(Access Control Matrix, ACM)은 사용자 × 파일 형태로 권한을 저장합니다.

| | 파일1 | 파일2 | 파일3 |
|-|-------|-------|-------|
| 사용자A | r, w | r | - |
| 사용자B | r | r, w, x | r |

- `r`: 읽기(Read), `w`: 쓰기(Write), `x`: 실행(eXecute)

**ACL(Access Control List, 접근 제어 목록):** 각 파일마다 접근 가능한 사용자 목록과 권한을 저장합니다.

## 파일 할당 방법 비교

| 방법 | 외부 단편화 | 직접 접근 | 크기 변경 | 활용 예 |
|------|-----------|---------|---------|--------|
| **연속 할당** | 발생 | 빠름 | 어려움 | CD-ROM |
| **연결 할당** | 없음 | 느림 | 쉬움 | 초기 Unix |
| **FAT** | 없음 | 보통 (FAT 캐시 시) | 쉬움 | Windows FAT32 |
| **인덱스 할당 **(inode) | 없음 | 빠름 | 쉬움 | Unix/Linux ext2/4 |

## 핵심 정리

- 파일 시스템(File System)은 파일 생성/삭제/읽기/쓰기와 디렉터리 관리, 접근 제어를 담당한다
- 파일 접근 방법: 순차 접근, 직접 접근, 색인 접근
- 연속 할당은 빠르지만 외부 단편화 문제, 연결 할당은 단편화 없지만 직접 접근 느림
- FAT(File Allocation Table)는 연결 할당의 포인터를 별도 테이블에 집중 관리
- inode는 Unix/Linux에서 파일 메타데이터와 블록 포인터를 관리하며, 파일 이름은 디렉터리가 관리한다
