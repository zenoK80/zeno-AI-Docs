## 파일 시스템이란?

**파일 시스템(File System)**은 운영체제가 파일을 저장하고 관리하기 위한 체계입니다.

### 파일 시스템의 주요 기능

- 파일 생성, 삭제, 읽기, 쓰기
- 디렉터리 관리
- 파일 접근 제어(권한)
- 파일 공유
- 백업과 복구

## 파일의 개념

**파일(File)**은 관련된 정보의 집합으로 보조기억장치에 저장됩니다.

### 파일 속성(메타데이터)

| 속성 | 설명 |
|------|------|
| **이름** | 사람이 읽을 수 있는 식별자 |
| **식별자** | 고유한 숫자 식별자 (inode 번호 등) |
| **유형** | 파일 종류 (텍스트, 실행파일 등) |
| **위치** | 장치와 디스크 내 위치 포인터 |
| **크기** | 현재 파일 크기 |
| **보호** | 접근 권한 정보 |
| **시간/날짜** | 생성, 수정, 접근 시각 |

### 파일 접근 방법

| 방법 | 설명 | 특징 |
|------|------|------|
| **순차 접근** | 처음부터 순서대로 읽음 | 테이프 방식, 단순 |
| **직접 접근** | 임의의 위치에 바로 접근 | 디스크에 적합 |
| **색인 접근** | 색인(인덱스)을 통해 접근 | 대용량 데이터에 유용 |

## 디렉터리 구조

### 1단계 디렉터리

모든 파일이 하나의 디렉터리에 존재합니다. 구현이 간단하지만 파일 이름이 모두 달라야 합니다.

### 2단계 디렉터리

사용자별로 별도의 디렉터리를 가집니다. 사용자 간 동일 파일명 허용.

### 트리 구조 디렉터리

**현대 운영체제**에서 사용하는 방식으로 루트 디렉터리 아래 계층적으로 디렉터리가 구성됩니다.

```
/
├── home/
│   ├── user1/
│   └── user2/
├── etc/
└── var/
```

### 비순환 그래프 디렉터리

파일/디렉터리의 **공유**가 가능합니다. 링크(심볼릭 링크, 하드 링크)를 통해 구현합니다.

## 디스크 공간 할당

### 연속 할당 (Contiguous Allocation)

파일을 연속된 블록에 저장합니다.

- **장점:** 순차/직접 접근 모두 빠름
- **단점:** 외부 단편화, 파일 크기 변경 어려움

```
파일A: │블록3│블록4│블록5│
파일B: │블록8│블록9│
```

### 연결 할당 (Linked Allocation)

각 블록이 다음 블록의 주소를 포함하는 체인 구조입니다.

- **장점:** 외부 단편화 없음, 동적 크기 변경
- **단점:** 직접 접근 느림 (중간 블록에 접근하려면 처음부터 따라가야 함), 포인터 오버헤드

```
파일A 시작: 블록3 → 블록8 → 블록11 → NULL
```

**FAT(File Allocation Table):** 연결 할당을 개선하여 연결 포인터를 별도의 테이블(FAT)에 저장합니다. Windows의 FAT, FAT32 파일 시스템이 사용합니다.

### 인덱스 할당 (Indexed Allocation)

파일의 모든 블록 번호를 **인덱스 블록** 하나에 저장합니다.

- **장점:** 직접 접근 지원, 외부 단편화 없음
- **단점:** 인덱스 블록 자체 오버헤드

**inode (Index Node):** Unix/Linux에서 사용하는 방식으로 파일 메타데이터와 블록 포인터를 저장합니다.

## inode 구조 (Unix/Linux)

**inode**는 파일당 하나씩 생성되는 자료구조로 다음을 저장합니다.

```
inode 구조:
┌────────────────────────┐
│ 파일 유형, 권한         │
│ 소유자, 그룹            │
│ 파일 크기              │
│ 타임스탬프(생성/수정/접근)│
├────────────────────────┤
│ 직접 포인터 (12개)      │ → 소형 파일 직접 접근
│ 단일 간접 포인터         │ → 중형 파일
│ 이중 간접 포인터         │ → 대형 파일
│ 삼중 간접 포인터         │ → 초대형 파일
└────────────────────────┘
```

디렉터리는 파일 이름과 inode 번호를 매핑하는 역할을 합니다.

## 접근 제어

### 접근 제어 행렬 (Access Control Matrix)

사용자 × 파일 형태의 행렬로 권한을 저장합니다.

| | 파일1 | 파일2 | 파일3 |
|-|-------|-------|-------|
| 사용자A | r, w | r | - |
| 사용자B | r | r, w, x | r |

**ACL(Access Control List):** 각 파일마다 접근 가능한 사용자 목록과 권한을 저장합니다.

## 파일의 블록킹과 버퍼링

- **블록킹(Blocking):** 여러 레코드를 하나의 블록에 묶어 입출력 효율 향상
- **버퍼링(Buffering):** 입출력 속도 차이를 완충하기 위해 메모리의 버퍼 사용

## 핵심 정리

- 파일 시스템은 파일 생성/삭제/읽기/쓰기와 디렉터리 관리, 접근 제어를 담당한다
- 파일 접근 방법: 순차 접근, 직접 접근, 색인 접근
- 연속 할당은 빠르지만 외부 단편화 문제, 연결 할당은 단편화 없지만 직접 접근 느림
- FAT는 연결 할당의 포인터를 별도 테이블에 저장한 방식이다
- inode는 Unix/Linux에서 파일 메타데이터와 블록 포인터를 관리하는 구조다
