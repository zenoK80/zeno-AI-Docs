## 페이징(Paging)이란?

**페이징**은 논리 메모리를 **페이지(Page)** 단위로, 물리 메모리를 **프레임(Frame)** 단위로 동일한 크기로 분할하여 관리하는 기법입니다.

- **외부 단편화를 완전히 제거**합니다 (페이지 크기가 동일하므로)
- 내부 단편화는 마지막 페이지에서 소량 발생할 수 있습니다
- 논리적으로 연속된 프로세스 공간이 물리 메모리에서는 비연속적으로 배치 가능

```
논리 주소 공간                    물리 주소 공간 (프레임)
┌─────────┐                       프레임 0: [운영체제]
│ 페이지 0 │ ──────────────────→  프레임 3
│ 페이지 1 │ ──────────────────→  프레임 7
│ 페이지 2 │ ──────────────────→  프레임 1
│ 페이지 3 │ ──────────────────→  프레임 5
└─────────┘
```

## 페이지 테이블(Page Table)

**페이지 테이블**은 각 페이지 번호가 어느 프레임에 올라가 있는지 저장하는 자료구조입니다. 프로세스마다 하나씩 존재하며, 커널 메모리에 저장됩니다.

### 주소 변환 과정

논리 주소는 **페이지 번호(p)**와 **페이지 내 오프셋(d)**으로 구성됩니다.

```
논리 주소: │ 페이지 번호 (p) │ 오프셋 (d) │

변환 과정:
1. 논리 주소에서 페이지 번호 p 추출
2. 페이지 테이블에서 p → 프레임 번호 f 확인
3. 물리 주소 = f * 페이지크기 + d
```

### 주소 변환 예시

페이지 크기 = 4KB (2^12), 논리 주소 = 13312(0x3400)

- 페이지 번호 p = 13312 / 4096 = **3**
- 오프셋 d = 13312 % 4096 = **1024**
- 페이지 테이블에서 페이지 3 → 프레임 7
- 물리 주소 = 7 * 4096 + 1024 = **29696**

## TLB (Translation Lookaside Buffer)

페이지 테이블은 메모리에 저장되므로, 주소 변환마다 메모리를 한 번 더 접근해야 합니다. 이를 개선하기 위해 **TLB**라는 고속 캐시를 사용합니다.

```
CPU → [TLB 검색]
         ↓ TLB 히트(Hit)         ↓ TLB 미스(Miss)
   TLB에서 프레임 번호 획득      페이지 테이블 접근 (메모리)
         ↓                              ↓
    물리 메모리 접근           TLB에 항목 추가 후 메모리 접근
```

### 유효 접근 시간(EAT, Effective Access Time) 계산

- TLB 접근 시간: $\alpha$ ns
- 메모리 접근 시간: $m$ ns
- TLB 히트율: $h$

$$
EAT = h \times (\alpha + m) + (1 - h) \times (\alpha + 2m)
$$

**계산 예시:**
- TLB 접근 시간: 20ns, 메모리 접근 시간: 100ns, 히트율: 0.8

$$
EAT = 0.8 \times (20 + 100) + 0.2 \times (20 + 200) = 96 + 44 = 140ns
$$

TLB 없이 주소 변환하면 200ns인데, TLB로 140ns로 단축됩니다.

## 페이지 테이블의 크기 문제

주소 공간이 커질수록 페이지 테이블도 매우 커집니다.

32비트 주소 공간, 4KB 페이지: 페이지 테이블 항목 수 = 2^32 / 2^12 = **2^20 = 1M 항목**  
각 항목 4바이트: 페이지 테이블 = 4MB (프로세스마다!)

### 해결 방법

| 방법 | 설명 |
|------|------|
| **계층적 페이징** | 페이지 테이블을 여러 단계로 나눔 (2단계, 3단계 페이지 테이블) |
| **해시 페이지 테이블** | 해시 함수로 페이지 테이블 항목을 저장 |
| **역 페이지 테이블** | 프레임마다 하나의 항목 (전체 테이블 크기 고정) |

### 2단계 페이지 테이블

논리 주소를 외부 페이지 번호, 내부 페이지 번호, 오프셋으로 나눠 2단계로 참조합니다.

```
논리 주소: │ p1 (외부) │ p2 (내부) │ d (오프셋) │
          ↓                ↓
     외부 페이지 테이블 → 내부 페이지 테이블 → 프레임
```

## 페이지 테이블 보호

각 페이지 테이블 항목에는 페이지 번호 외에 **보호 비트**가 있습니다.

| 비트 | 역할 |
|------|------|
| **유효-무효 비트** | 해당 페이지가 실제 메모리에 있는지 여부 |
| **읽기/쓰기 비트** | 읽기 전용 또는 읽기-쓰기 허용 |
| **참조 비트** | 최근에 접근했는지 여부 (페이지 교체 알고리즘에 사용) |
| **수정(더티) 비트** | 페이지 내용이 수정되었는지 여부 |

## 공유 페이지

여러 프로세스가 동일한 코드(라이브러리)를 사용할 때 **공유 페이지**로 한 번만 메모리에 올릴 수 있습니다.

- 재진입 코드(순수 코드): 실행 중 자신을 수정하지 않는 코드
- 여러 프로세스의 페이지 테이블이 같은 프레임을 가리킴

## 핵심 정리

- 페이징은 고정 크기 페이지/프레임으로 분할하여 외부 단편화를 제거한다
- 논리 주소 = 페이지 번호(p) + 오프셋(d), 페이지 테이블로 프레임 번호를 찾아 물리 주소 계산
- TLB는 최근 주소 변환 결과를 캐싱하여 메모리 접근 횟수를 줄인다
- TLB 히트율이 높을수록 유효 접근 시간이 메모리 접근 시간에 가까워진다
- 페이지 테이블 크기 문제는 계층적 페이징, 해시, 역 페이지 테이블로 해결한다
