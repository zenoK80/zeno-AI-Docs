## 페이지 교체란?

요구 페이징에서 빈 프레임이 없을 때 **기존 페이지를 디스크로 내보내고** 새 페이지를 올리는 과정입니다. 어느 페이지를 내보낼지 결정하는 알고리즘이 **페이지 교체 알고리즘**입니다.

**좋은 알고리즘:** 페이지 폴트 횟수를 최소화합니다.

## FIFO (First In First Out)

메모리에 **가장 먼저 올라온 페이지**를 교체합니다.

### 참조 열 예시 (프레임 3개)

참조 열: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2

| 참조 | 프레임 1 | 프레임 2 | 프레임 3 | 폴트 |
|------|---------|---------|---------|------|
| 7 | **7** | - | - | F |
| 0 | 7 | **0** | - | F |
| 1 | 7 | 0 | **1** | F |
| 2 | **2** | 0 | 1 | F |
| 0 | 2 | 0 | 1 | - |
| 3 | 2 | **3** | 1 | F |
| 0 | 2 | 3 | **0** | F |
| 4 | **4** | 3 | 0 | F |
| 2 | 4 | **2** | 0 | F |

총 페이지 폴트 수: 9회

### Belady 이상 현상

FIFO에서는 **프레임 수를 늘려도 페이지 폴트가 증가**하는 역설적인 현상이 발생할 수 있습니다. 이를 **Belady 이상 현상**이라고 합니다.

## OPT (Optimal, 최적 알고리즘)

**앞으로 가장 오랫동안 사용되지 않을 페이지**를 교체합니다.

- 이론적으로 최소의 페이지 폴트를 보장
- 미래 참조 열을 미리 알아야 하므로 **실제 구현 불가능**
- 다른 알고리즘의 성능 기준(Upper Bound)으로 사용

## LRU (Least Recently Used)

**가장 오랫동안 사용되지 않은 페이지**를 교체합니다. 과거를 보고 미래를 예측합니다.

- 실제 구현 가능하며 성능이 좋음
- 구현 방법: 카운터, 스택, 참조 비트

### LRU 예시 (프레임 3개)

참조 열: 7, 0, 1, 2, 0, 3, 0, 4

| 참조 | 프레임 상태 | 폴트 |
|------|-----------|------|
| 7 | [7] | F |
| 0 | [7,0] | F |
| 1 | [7,0,1] | F |
| 2 | [0,1,2] | F (7 교체: 가장 오래됨) |
| 0 | [1,2,0] | - |
| 3 | [2,0,3] | F (1 교체: 가장 오래됨) |
| 0 | [2,3,0] | - |
| 4 | [3,0,4] | F (2 교체: 가장 오래됨) |

총 페이지 폴트: 6회 (FIFO의 9회보다 적음)

**장점:** 성능 우수, Belady 이상 없음  
**단점:** 하드웨어 지원 없이 구현 비용이 높음

## LFU (Least Frequently Used)

**참조 횟수가 가장 적은 페이지**를 교체합니다.

- 구현이 상대적으로 간단
- 초기에 많이 사용했지만 이후 사용하지 않는 페이지를 늦게 교체하는 문제

## MFU (Most Frequently Used)

**참조 횟수가 가장 많은 페이지**를 교체합니다. (참조 횟수가 적은 페이지는 최근에 올라온 것이므로 앞으로 사용할 가능성이 높다는 가정)

## Second Chance (NRU, Not Recently Used)

**FIFO의 개선 버전**으로 참조 비트(Reference Bit)를 활용합니다.

### 동작 원리

1. FIFO 방식으로 포인터가 가장 오래된 페이지를 가리킴
2. 참조 비트 = 1이면: 비트를 0으로 초기화하고 포인터를 다음으로 이동 (한 번의 기회 부여)
3. 참조 비트 = 0이면: 해당 페이지 교체

```
원형 큐:
→ [페이지A, 비트=0] → 교체 대상 ✓
  [페이지B, 비트=1] → 비트 0으로 초기화, 넘어감
  [페이지C, 비트=0] → 다음 기회에 교체 대상
```

Belady 이상 현상이 없으며 LRU와 유사한 성능을 보입니다.

## 페이지 교체 알고리즘 비교

| 알고리즘 | 특징 | 장점 | 단점 |
|---------|------|------|------|
| **FIFO** | 오래된 순서로 교체 | 구현 간단 | Belady 이상, 성능 보통 |
| **OPT** | 미래 기준 최적 교체 | 최소 폴트 | 구현 불가 |
| **LRU** | 최근 사용 안 한 것 교체 | 성능 우수 | 구현 비용 높음 |
| **LFU** | 참조 횟수 적은 것 교체 | 구현 용이 | 오래된 데이터 유지 |
| **Second Chance** | FIFO + 참조 비트 | LRU와 유사 성능 | FIFO보다 복잡 |

<Callout type="warning">
  독학사 시험에서 "페이지 교체 기법에서 교체될 페이지로 가장 이상적인 것은?" 유형이 자주 출제됩니다. 정답은 **이후에 가장 오랫동안 사용되지 않을 페이지** (OPT)입니다.
</Callout>

## 핵심 정리

- FIFO는 구현이 간단하지만 Belady 이상 현상이 발생할 수 있다
- OPT는 최적이지만 미래 예측이 필요하여 구현 불가능, 성능 기준으로 사용
- LRU는 가장 오래 사용 안 한 페이지를 교체하며 성능이 우수하다
- Second Chance는 FIFO에 참조 비트를 추가하여 LRU와 유사한 성능을 달성한다
- 페이지 폴트 수를 직접 계산하는 문제가 시험에 자주 출제된다
