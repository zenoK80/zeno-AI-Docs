## 페이지 교체가 왜 필요한가?

이전 문서에서 배운 요구 페이징은 필요할 때 페이지를 메모리에 올립니다. 그런데 메모리가 꽉 차면 어떻게 될까요? 새 페이지를 올리려면 **기존에 있던 페이지 중 하나를 꺼내야** 합니다.

이때 어떤 페이지를 내보낼지 결정하는 것이 **페이지 교체 알고리즘(Page Replacement Algorithm)**입니다.

**쉽게 말하면:** 책상이 꽉 찼을 때 새 책을 올려놓으려면 기존 책 한 권을 책장에 돌려놔야 합니다. 어떤 책을 돌려놓을지 결정하는 것이 페이지 교체 알고리즘입니다.

**좋은 알고리즘의 기준:** 페이지 폴트(Page Fault) 횟수를 최소화합니다. 폴트가 적을수록 디스크 접근이 줄어 성능이 향상됩니다.

## FIFO (First In First Out, 선입선출)

메모리에 **가장 먼저 올라온 페이지**를 교체합니다. 가장 오래된 것부터 내보내는 방식입니다.

**비유:** 마트 선반에서 먼저 진열된 상품을 먼저 꺼내는 것처럼, 메모리에 먼저 올라온 페이지를 먼저 내보냅니다.

### 참조 열 예시 (프레임 3개)

참조 열: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2

| 참조 | 프레임 1 | 프레임 2 | 프레임 3 | 폴트 여부 |
|------|---------|---------|---------|---------|
| 7 | **7** | - | - | F (폴트) |
| 0 | 7 | **0** | - | F |
| 1 | 7 | 0 | **1** | F |
| 2 | **2** | 0 | 1 | F (7 교체 — 가장 먼저 들어옴) |
| 0 | 2 | 0 | 1 | - (이미 있음) |
| 3 | 2 | **3** | 1 | F (0 교체) |
| 0 | 2 | 3 | **0** | F (1 교체) |
| 4 | **4** | 3 | 0 | F (2 교체) |
| 2 | 4 | **2** | 0 | F (3 교체) |

총 페이지 폴트 수: **9회**

### Belady 이상 현상(Belady's Anomaly)

FIFO에는 특이한 문제가 있습니다. 보통 프레임 수가 늘면 페이지 폴트가 줄어야 정상입니다. 그런데 **FIFO에서는 프레임 수를 늘렸는데 오히려 폴트가 증가**하는 경우가 있습니다. 이를 **Belady 이상 현상(Belady's Anomaly)**이라 합니다.

**쉽게 말하면:** 책상을 더 큰 것으로 바꿨는데(프레임 증가) 오히려 책을 더 자주 꺼내야 하는 상황이 생기는 것입니다.

## OPT (Optimal Algorithm, 최적 알고리즘)

**앞으로 가장 오랫동안 사용되지 않을 페이지**를 교체합니다.

- 이론적으로 최소의 페이지 폴트를 보장 → **가장 이상적인 알고리즘**
- 미래 참조 열(Reference String)을 미리 알아야 하므로 **실제 구현 불가능**
- 다른 알고리즘의 성능 기준(Upper Bound, 상한값)으로 활용

**쉽게 말하면:** 미래를 내다볼 수 있다면 앞으로 가장 오래 필요 없을 책을 책장에 돌려놓을 것입니다. 최선의 선택이지만 실제로는 미래를 알 수 없습니다.

<Callout type="warning">
  독학사 시험에서 "페이지 교체 기법에서 교체될 페이지로 가장 이상적인 것은?" 유형이 자주 출제됩니다. 정답은 **이후에 가장 오랫동안 사용되지 않을 페이지** (OPT)입니다.
</Callout>

## LRU (Least Recently Used, 최근 최소 사용)

**가장 오랫동안 사용되지 않은 페이지**를 교체합니다. "과거를 보고 미래를 예측"하는 방식입니다. 지역성(Locality) 원리에 기반합니다.

- 실제 구현 가능하며 성능이 좋음
- Belady 이상 현상 없음
- 구현 방법: 카운터(Counter), 스택(Stack), 참조 비트(Reference Bit) 등

**쉽게 말하면:** 가장 오래 안 꺼낸 책을 책장에 돌려놓습니다. 최근에 본 책은 곧 또 볼 가능성이 높다는 가정입니다.

### LRU 예시 (프레임 3개)

참조 열: 7, 0, 1, 2, 0, 3, 0, 4

| 참조 | 프레임 상태 (왼쪽이 오래됨) | 폴트 여부 |
|------|-----------|---------|
| 7 | [7] | F |
| 0 | [7, 0] | F |
| 1 | [7, 0, 1] | F |
| 2 | [0, 1, 2] | F (7 교체 — 가장 오래 전에 사용) |
| 0 | [1, 2, 0] | - (이미 있음) |
| 3 | [2, 0, 3] | F (1 교체) |
| 0 | [2, 3, 0] | - |
| 4 | [3, 0, 4] | F (2 교체) |

총 페이지 폴트: **6회** (FIFO의 9회보다 적음)

## LFU (Least Frequently Used, 최소 빈도 사용)

**참조 횟수(Reference Count)가 가장 적은 페이지**를 교체합니다.

- 구현이 상대적으로 간단
- 단점: 초기에 많이 사용했지만 이후 사용하지 않는 페이지를 늦게 교체 (오래된 이력이 불리하게 작용)

**쉽게 말하면:** 가장 덜 꺼낸 책을 돌려놓습니다. 하지만 오래전에 많이 봤던 책이 지금은 안 필요해도 계속 자리를 차지할 수 있습니다.

## MFU (Most Frequently Used, 최다 빈도 사용)

**참조 횟수가 가장 많은 페이지**를 교체합니다. 참조 횟수가 적은 페이지는 최근에 올라온 것이므로 앞으로 사용할 가능성이 높다는 반대 가정을 적용합니다. LFU, MFU 모두 OPT나 LRU에 비해 성능이 좋지 않습니다.

## Second Chance (NRU, Not Recently Used — 최근 미사용)

**FIFO의 개선 버전**으로 참조 비트(Reference Bit)를 활용합니다. Clock 알고리즘이라고도 합니다.

### 동작 원리

```
원형 큐(시계 방향):
→ [페이지A, 참조비트=0] → 교체 대상 (기회 없음)
  [페이지B, 참조비트=1] → 비트 0으로 초기화, 한 번 더 살아남음
  [페이지C, 참조비트=0] → 다음에 교체 대상이 됨
```

1. FIFO 방식으로 포인터가 가장 오래된 페이지를 가리킴
2. 참조 비트 = 1이면: 비트를 0으로 초기화하고 포인터를 다음으로 이동 (한 번의 기회 부여)
3. 참조 비트 = 0이면: 해당 페이지 교체

**쉽게 말하면:** 책을 돌려놓으려 할 때, 최근에 한 번이라도 열어봤다면(참조 비트 = 1) 한 번의 기회를 더 줍니다. 아무도 안 꺼내봤다면(참조 비트 = 0) 교체합니다.

- Belady 이상 현상 없음
- LRU와 유사한 성능을 낮은 비용으로 구현

## 페이지 교체 알고리즘 비교

| 알고리즘 | 교체 기준 | 장점 | 단점 |
|---------|---------|------|------|
| **FIFO** | 가장 먼저 들어온 것 | 구현 간단 | Belady 이상, 성능 보통 |
| **OPT** | 미래에 가장 오래 사용 안 할 것 | 최소 폴트 (이상적) | 구현 불가능 |
| **LRU** | 가장 오래 전에 사용된 것 | 성능 우수, Belady 이상 없음 | 구현 비용 높음 |
| **LFU** | 참조 횟수 가장 적은 것 | 구현 용이 | 오래된 데이터 불리 |
| **Second Chance** | FIFO + 참조 비트 | LRU와 유사 성능, 저비용 | FIFO보다 복잡 |

## 수정 비트(Dirty Bit)와 교체 비용

페이지 교체 시 **수정 비트(Dirty Bit, 더티 비트)**를 확인합니다.

- **수정 비트 = 0:** 메모리에 올라온 후 내용이 변경되지 않음 → 그냥 버리면 됨 (빠름)
- **수정 비트 = 1:** 메모리에서 내용이 변경됨 → 디스크에 저장 후 교체 (느림)

따라서 같은 교체 후보가 있다면 수정 비트 = 0인 페이지를 먼저 교체하는 것이 효율적입니다.

## 핵심 정리

- FIFO(선입선출)는 구현이 간단하지만 Belady 이상 현상이 발생할 수 있다
- OPT(최적)는 미래 기준 최적이지만 미래 예측 불가로 구현할 수 없으며 성능 기준으로 사용
- LRU(최근 최소 사용)는 가장 오래 사용 안 한 페이지를 교체하며 성능이 우수하다
- Second Chance(NRU)는 FIFO에 참조 비트를 추가하여 LRU와 유사한 성능을 달성한다
- 수정 비트(Dirty Bit) = 1인 페이지는 교체 전 디스크에 저장이 필요하여 교체 비용이 높다
