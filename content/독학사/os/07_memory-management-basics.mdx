## 메모리 관리가 왜 필요한가?

컴퓨터에는 여러 프로세스가 동시에 실행됩니다. 각 프로세스는 메모리(RAM, Random Access Memory)가 필요합니다. 메모리가 하나밖에 없는데 여러 프로세스가 동시에 쓰려면 규칙이 필요합니다.

**생각해야 할 문제들:**
- 어느 프로세스에게 어느 위치의 메모리를 줄 것인가?
- 한 프로세스가 다른 프로세스의 메모리를 침범하지 못하게 어떻게 막을 것인가?
- 메모리가 부족하면 어떻게 할 것인가?

이 모든 것을 관리하는 것이 **메모리 관리**(Memory Management)입니다.

**쉽게 말하면:** 메모리 관리는 아파트(메모리)를 여러 입주자(프로세스)에게 배정하고 관리하는 것입니다.

## 메모리 관리의 필요성

**메모리 관리**는 운영체제가 주기억장치(RAM)를 효율적으로 할당하고 보호하는 기능입니다.

### 메모리 관리의 기본 요구조건

| 요구조건 | 설명 |
|---------|------|
| **재배치**(Relocation) | 프로그램이 메모리 어느 위치에 올라가도 정상 실행 가능 |
| **보호**(Protection) | 각 프로세스가 다른 프로세스의 메모리를 침범하지 못하도록 보호 |
| **공유**(Sharing) | 여러 프로세스가 공통 코드(라이브러리 등)를 공유 |
| **논리적 구성** | 프로그래머가 논리 주소(Logical Address)로 프로그램 작성 |
| **물리적 구성** | 운영체제가 논리 주소를 물리 주소(Physical Address)로 변환 관리 |

### 주소 바인딩(Address Binding, 주소 결합)

프로그램의 **논리 주소**(가상 주소, Virtual Address)를 **물리 주소**(Physical Address, 실제 메모리 주소)로 변환하는 과정입니다.

**쉽게 말하면:** 프로그램은 "내 데이터는 100번 위치에 있다"고 알고 있지만, 실제 메모리에서는 5000번 위치에 저장될 수 있습니다. 이 번역 과정이 주소 바인딩입니다.

| 시점 | 이름 | 설명 |
|------|------|------|
| 컴파일 시 | 컴파일 시간 바인딩 | 절대 주소로 컴파일 (재배치 불가) |
| 적재 시 | 적재 시간 바인딩 | 메모리 적재 시 주소 결정 |
| 실행 시 | 실행 시간 바인딩 | 실행 중에 주소 변환 (MMU 사용) |

**MMU(Memory Management Unit, 메모리 관리 장치):** 논리 주소를 물리 주소로 변환하는 하드웨어 장치. CPU와 메모리 사이에 위치합니다.

## 연속 메모리 할당

초기 운영체제에서 사용한 방식으로, 프로세스를 연속된 메모리 공간에 올립니다.

### 고정 분할 (Fixed Partition, 고정 파티션)

메모리를 **고정 크기**의 파티션(Partition, 구획)으로 미리 나눕니다.

**비유:** 아파트를 모두 동일한 크기의 방으로 나누는 것. 작은 가족이 큰 방에 들어와도 방 크기는 고정입니다.

```
│ 운영체제 │ 파티션1 │ 파티션2 │ 파티션3 │ 파티션4 │
│  (4MB)  │  (8MB) │  (8MB) │ (16MB) │ (32MB) │
```

**내부 단편화(Internal Fragmentation):** 파티션보다 작은 프로세스가 올라올 때 남은 공간이 낭비되는 현상

예: 5MB 프로세스가 8MB 파티션에 올라가면 **3MB 낭비**

### 동적 분할 (Dynamic Partition, 가변 파티션)

프로세스 크기에 맞게 **가변 크기**로 메모리를 할당합니다.

**비유:** 고객이 원하는 크기의 방을 그때그때 만들어주는 맞춤 숙박 시설.

**외부 단편화(External Fragmentation):** 할당과 해제를 반복하다 보면 충분한 총 여유 공간이 있어도 연속된 공간이 없어 할당 불가한 현상

```
│OS│ 비어있음(4MB) │ P2 │ 비어있음(3MB) │ P4 │ 비어있음(2MB) │
                ↑                ↑                ↑
        4+3+2=9MB 여유공간이 있지만 연속 공간이 없어 8MB 프로세스 할당 불가
```

**쉽게 말하면:** 주차장에 빈 자리가 총 9칸 있는데, 모두 흩어져 있어서 대형 버스(8칸 필요)는 주차할 수 없는 상황입니다.

## 동적 분할 알고리즘

빈 공간(Hole, 홀)이 여러 곳 있을 때 어디에 프로세스를 배치할지 결정하는 방법입니다.

| 알고리즘 | 방법 | 특징 |
|---------|------|------|
| **최초 적합**(First Fit) | 첫 번째로 충분히 큰 빈 공간에 배치 | 빠름, 외부 단편화 발생 |
| **최적 적합**(Best Fit) | 프로세스와 가장 비슷한 크기의 빈 공간에 배치 | 작은 단편 발생 |
| **최악 적합**(Worst Fit) | 가장 큰 빈 공간에 배치 | 큰 단편 남겨 재사용 기대 |

일반적으로 **최초 적합**(First Fit)이 속도와 효율 면에서 가장 좋은 성능을 보입니다.

**비유:**
- 최초 적합: 주차장에 들어가자마자 첫 번째 빈 자리에 주차
- 최적 적합: 내 차 크기에 딱 맞는 자리를 찾아서 주차 (시간이 걸림)
- 최악 적합: 가장 넓은 자리에 주차 (나중에 큰 차가 와도 들어갈 수 있도록)

## 단편화 해결 방법

### 컴팩션(Compaction, 압축)

메모리에 흩어진 빈 공간을 한쪽으로 모아 큰 연속 공간을 만드는 기법입니다.

**비유:** 주차장에 흩어진 차들을 한쪽으로 밀어 붙여 큰 빈 공간을 만드는 것.

```
컴팩션 전:
│OS│P1│빈공간│P2│빈공간│P3│빈공간│

컴팩션 후:
│OS│P1│P2│P3│     빈 공간     │
```

**단점:** 프로세스를 이동시키는 데 많은 시간과 비용이 소요됩니다. 이사 비용이 큰 것과 같습니다.

### 스와핑(Swapping)

실행 중이 아닌 프로세스를 **보조기억장치**(스왑 공간, Swap Space)로 내보내고(스왑 아웃, Swap Out), 필요할 때 다시 메모리에 올립니다(스왑 인, Swap In).

**비유:** 방이 부족한 호텔에서 현재 체크아웃한 손님의 짐을 창고로 옮기고, 새 손님에게 방을 주는 것.

```
메모리          스왑 공간
│OS│P1│P3│  ←→  P2, P4 대기 중
```

## 경계 레지스터와 기준 레지스터

다중 프로그래밍 환경에서 메모리 보호를 위해 두 가지 레지스터(Register, CPU 내부 저장 공간)를 사용합니다.

- **기준(Base) 레지스터:** 프로세스의 시작 물리 주소
- **경계(Limit) 레지스터:** 프로세스의 크기

CPU가 생성하는 주소 = 기준 레지스터 값 + 논리 주소  
경계 레지스터 초과 시 → 메모리 접근 오류(Segmentation Fault, 세그멘테이션 오류)

**쉽게 말하면:** 기준 레지스터는 아파트 동 번호(시작 위치), 경계 레지스터는 층수(크기)입니다. 동 번호와 층수를 벗어난 곳에는 접근할 수 없습니다.

## 핵심 정리

- 메모리 관리 요구조건: 재배치, 보호, 공유, 논리/물리 구성
- 고정 분할은 내부 단편화(Internal Fragmentation), 동적 분할은 외부 단편화(External Fragmentation)를 유발한다
- 동적 분할 알고리즘: 최초 적합(빠름), 최적 적합(작은 단편), 최악 적합(큰 단편 보존)
- 컴팩션(Compaction)은 외부 단편화를 해결하지만 오버헤드가 크다
- 스와핑(Swapping)은 메모리가 부족할 때 프로세스를 디스크로 내보내는 기법이다
