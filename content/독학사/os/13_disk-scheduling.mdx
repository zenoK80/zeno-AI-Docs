## 디스크 스케줄링이 왜 필요한가?

하드 디스크(HDD, Hard Disk Drive)는 원판(플래터)이 빠르게 회전하고 그 위에서 헤드(Head)가 이리저리 이동하면서 데이터를 읽습니다. 헤드를 움직이는 데 시간이 걸립니다.

여러 프로세스가 디스크에 동시에 접근하려 한다면, 접근 요청들을 어떤 순서로 처리할지 결정해야 합니다. 무작정 온 순서대로 처리하면 헤드가 이리저리 왔다 갔다 하여 비효율적입니다.

**쉽게 말하면:** 엘리베이터가 각 층 버튼을 누른 순서대로 움직이면 비효율적입니다. 현재 올라가는 중이라면 올라가는 길에 있는 층들을 먼저 처리하는 것이 훨씬 효율적입니다. 이런 순서 결정이 디스크 스케줄링입니다.

## 디스크 구조와 접근 시간

### 디스크 기본 구조

| 용어 | 설명 |
|------|------|
| **플래터**(Platter) | 데이터를 저장하는 원판 (자성 재질) |
| **트랙**(Track) | 플래터의 동심원 (바깥쪽 원부터 0번 트랙) |
| **섹터**(Sector) | 트랙을 나눈 최소 저장 단위 |
| **실린더**(Cylinder) | 여러 플래터에서 같은 위치의 트랙 집합 |
| **헤드**(Head) | 데이터를 읽고 쓰는 장치 |

**쉽게 말하면:** 플래터는 LP 레코드판, 트랙은 그 위의 원형 홈, 섹터는 홈을 잘게 나눈 조각, 헤드는 바늘과 같습니다.

### 디스크 접근 시간

$$
\text{접근 시간} = \text{탐색 시간} + \text{회전 지연} + \text{전송 시간}
$$

| 요소 | 설명 | 비중 |
|------|------|------|
| **탐색 시간**(Seek Time) | 헤드를 원하는 트랙으로 이동 | **가장 큼** (수 ms) |
| **회전 지연**(Rotational Latency) | 원하는 섹터가 헤드 아래로 올 때까지 대기 | 보통 (평균 = 반 바퀴 시간) |
| **전송 시간**(Transfer Time) | 실제 데이터 읽기/쓰기 | 가장 작음 |

디스크 스케줄링의 목표는 **탐색 시간을 최소화**하는 것입니다.

## FCFS (First Come First Served, 선입선출)

요청이 도착한 **순서대로** 처리합니다. CPU 스케줄링의 FCFS와 동일한 개념입니다.

### 예시

현재 헤드 위치: 53, 요청 열: 98, 183, 37, 122, 14, 124, 65, 67

```
53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
```

총 탐색 거리 = |53-98| + |98-183| + |183-37| + |37-122| + |122-14| + |14-124| + |124-65| + |65-67|
= 45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = **640**

- **장점:** 구현 간단, 공평 (기아 없음)
- **단점:** 헤드가 이리저리 움직여 비효율적, 탐색 거리가 큼

## SSTF (Shortest Seek Time First, 최단 탐색 시간 우선)

현재 헤드 위치에서 **가장 가까운 트랙의 요청**을 먼저 처리합니다.

### 예시 (헤드: 53, 요청: 98, 183, 37, 122, 14, 124, 65, 67)

```
53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183
```

총 탐색 거리 = 12 + 2 + 30 + 23 + 84 + 24 + 2 + 59 = **236** (FCFS의 약 1/3)

- **장점:** 탐색 거리 크게 감소
- **단점:** **기아(Starvation) 현상** — 헤드 근처에 계속 새 요청이 오면 먼 곳 요청은 영원히 처리 못 할 수 있음

## SCAN (스캔, 엘리베이터 알고리즘)

헤드가 **한쪽 끝에서 반대쪽 끝으로 이동**하면서 경로 위의 요청을 처리합니다. 끝에 도달하면 방향을 바꿉니다.

**쉽게 말하면:** 엘리베이터가 1층에서 10층까지 올라가면서 각 층 버튼을 누른 사람을 태우고, 10층에 도달하면 다시 내려오는 방식입니다.

### 예시 (헤드: 53, 방향: 증가)

```
53 → 65 → 67 → 98 → 122 → 124 → 183 → [끝 199] → 37 → 14
```

- **장점:** SSTF보다 균등한 대기 시간, 기아 없음
- **단점:** 끝에 도달하면 반대방향으로 돌아오기 때문에 반대 방향 요청은 조금 더 기다림

## C-SCAN (Circular SCAN, 순환 스캔)

SCAN과 유사하지만 한 방향으로만 처리합니다. 끝에 도달하면 **처음으로 돌아와 다시 시작**합니다. 이 복귀 이동에는 요청을 처리하지 않습니다.

```
53 → 65 → 67 → 98 → 122 → 124 → 183 → 199(끝) → 0(처음으로 이동, 처리 없음) → 14 → 37
```

- **장점:** SCAN보다 대기 시간이 더 균등합니다. 실린더 위치에 관계없이 대기 시간이 더 일정
- **단점:** 복귀 이동 시간이 발생

## LOOK (룩)

SCAN과 유사하지만 **끝까지 가지 않고** 마지막 요청 위치에서 방향을 바꿉니다. 더 이상 처리할 요청이 없는 방향으로는 이동하지 않습니다.

```
53 → 65 → 67 → 98 → 122 → 124 → 183 [마지막 요청에서 반환] → 37 → 14
```

SCAN보다 불필요한 이동을 줄여 효율적입니다.

## C-LOOK (C-룩)

C-SCAN의 개선 버전으로 **마지막 요청에서 첫 번째 요청으로 돌아옵니다** (디스크 끝까지 가지 않음).

```
53 → ... → 183 [마지막 큰 요청] → 14 [첫 번째 작은 요청] → 37 → ...
```

## 알고리즘 비교

| 알고리즘 | 교체 기준 | 탐색 거리 | 기아 현상 |
|---------|---------|---------|---------|
| **FCFS** | 도착 순서 | 가장 큼 | 없음 |
| **SSTF** | 가장 가까운 것 | 작음 | 발생 가능 |
| **SCAN** | 왕복 스윕 | 작음 | 없음 |
| **C-SCAN** | 단방향 순환 | SCAN과 유사 | 없음 |
| **LOOK** | SCAN + 불필요 이동 제거 | SCAN보다 작음 | 없음 |
| **C-LOOK** | C-SCAN + 불필요 이동 제거 | C-SCAN보다 작음 | 없음 |

<Callout type="warning">
  일반적으로 성능 면에서 SSTF나 SCAN 계열이 FCFS보다 우수합니다. 하지만 SSTF는 기아 문제가 있으므로 실제 시스템에서는 SCAN이나 C-SCAN 계열을 주로 사용합니다.
</Callout>

## SLTF (Shortest Latency Time First)

**회전 지연 시간**(Rotational Latency)을 최소화하는 알고리즘입니다. 헤드가 현재 위치에서 가장 가까운 섹터를 먼저 처리합니다. 같은 트랙 내에서 여러 섹터를 처리할 때 사용합니다.

## 핵심 정리

- 디스크 접근 시간 = 탐색 시간 + 회전 지연 + 전송 시간; 탐색 시간이 가장 큼
- FCFS는 순서대로, SSTF는 가장 가까운 것 먼저 (기아 가능), SCAN은 왕복, C-SCAN은 단방향 순환
- LOOK과 C-LOOK은 SCAN/C-SCAN에서 불필요한 끝 이동을 제거한 버전이다
- 탐색 거리를 직접 계산하는 문제가 시험에 자주 출제된다
