<Callout type="info">
  **이번 문서의 목표:** 디스크의 기본 구조와 접근 시간을 이해하고, 각 스케줄링 알고리즘의 원리와 장단점을 비교한다. 주어진 요청 열에서 총 탐색 거리를 직접 계산할 수 있다.
</Callout>

## 디스크 구조와 접근 시간

### 디스크 기본 구조

| 용어 | 설명 |
|------|------|
| **플래터(Platter)** | 데이터를 저장하는 원판 |
| **트랙(Track)** | 플래터의 동심원 |
| **섹터(Sector)** | 트랙을 나눈 최소 저장 단위 |
| **실린더(Cylinder)** | 여러 플래터에서 같은 위치의 트랙 집합 |
| **헤드(Head)** | 데이터를 읽고 쓰는 장치 |

### 디스크 접근 시간

$$
\text{접근 시간} = \text{탐색 시간} + \text{회전 지연} + \text{전송 시간}
$$

| 요소 | 설명 | 특징 |
|------|------|------|
| **탐색 시간(Seek Time)** | 헤드를 원하는 트랙으로 이동 | 가장 큰 비중 |
| **회전 지연(Rotational Latency)** | 원하는 섹터가 헤드 아래로 올 때까지 대기 | 평균 = 반 바퀴 |
| **전송 시간(Transfer Time)** | 실제 데이터 읽기/쓰기 | 가장 빠름 |

디스크 스케줄링은 **탐색 시간을 최소화**하는 것이 목표입니다.

## FCFS (First Come First Served)

요청 순서대로 처리합니다.

### 예시

현재 헤드 위치: 53, 요청 열: 98, 183, 37, 122, 14, 124, 65, 67

```
53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
```

총 탐색 거리 = |53-98| + |98-183| + |183-37| + |37-122| + |122-14| + |14-124| + |124-65| + |65-67|
= 45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = **640**

**단점:** 헤드가 이리저리 움직여 비효율적

## SSTF (Shortest Seek Time First)

현재 헤드 위치에서 **가장 가까운 요청**을 먼저 처리합니다.

### 예시 (헤드: 53, 요청: 98, 183, 37, 122, 14, 124, 65, 67)

```
53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183
```

총 탐색 거리 = 12 + 2 + 30 + 23 + 84 + 24 + 2 + 59 = **236** (FCFS의 1/3)

**단점:** 기아 현상 (헤드 근처에만 계속 요청이 오면 멀리 있는 요청 처리 불가)

## SCAN (엘리베이터 알고리즘)

헤드가 한쪽 끝에서 반대쪽 끝으로 이동하면서 경로 위의 요청을 처리합니다. 끝에 도달하면 방향을 바꿉니다.

### 예시 (헤드: 53, 방향: 증가)

```
53 → 65 → 67 → 98 → 122 → 124 → 183 → [끝 199] → 37 → 14
```

총 탐색 거리 = (183 - 53) + (183 - 14) = 130 + 169 = **299** 정도

**특징:** SSTF보다 균등한 대기 시간, 기아 없음. 엘리베이터처럼 동작

## C-SCAN (Circular SCAN)

SCAN과 유사하지만 한 방향으로만 이동하여 처리합니다. 끝에 도달하면 **처음으로 돌아와 다시 시작**합니다.

```
53 → 65 → 67 → 98 → 122 → 124 → 183 → 199(끝) → 0(처음으로 이동) → 14 → 37
```

**장점:** SCAN보다 대기 시간이 더 균등합니다. 실린더 위치에 관계없이 대기 시간이 일정에 가까움.

## LOOK

SCAN과 유사하지만 **끝까지 가지 않고** 마지막 요청 위치에서 방향을 바꿉니다.

```
53 → 65 → 67 → 98 → 122 → 124 → 183 [최대 요청에서 반환] → 37 → 14
```

## C-LOOK

C-SCAN의 개선 버전으로 **마지막 요청에서 처음 요청으로 돌아옵니다**.

```
53 → ... → 183 [최대] → 14 [최소] → 37 → ...
```

## 알고리즘 비교

| 알고리즘 | 특징 | 탐색 거리 | 기아 |
|---------|------|---------|------|
| **FCFS** | 도착 순서 | 가장 큼 | 없음 |
| **SSTF** | 가장 가까운 것 | 작음 | 발생 가능 |
| **SCAN** | 왕복 스윕 | 작음 | 없음 |
| **C-SCAN** | 단방향 순환 | SCAN과 유사 | 없음 |
| **LOOK** | SCAN + 불필요한 이동 제거 | 더 작음 | 없음 |
| **C-LOOK** | C-SCAN + 불필요한 이동 제거 | 더 작음 | 없음 |

<Callout type="warning">
  일반적으로 성능 면에서 SSTF나 SCAN 계열이 FCFS보다 우수합니다. 하지만 SSTF는 기아 문제가 있으므로 실제 시스템에서는 SCAN이나 C-SCAN 계열을 주로 사용합니다.
</Callout>

## SLTF (Shortest Latency Time First)

회전 지연 시간을 최소화하는 알고리즘으로, 헤드가 현재 위치에서 가장 가까운 섹터를 먼저 처리합니다.

## 핵심 정리

- 디스크 접근 시간 = 탐색 시간 + 회전 지연 + 전송 시간; 탐색 시간이 가장 큼
- FCFS는 순서대로, SSTF는 가장 가까운 것 먼저, SCAN은 왕복, C-SCAN은 단방향 순환
- LOOK과 C-LOOK은 SCAN/C-SCAN에서 불필요한 끝 이동을 제거한 버전이다
- 탐색 거리를 직접 계산하는 문제가 시험에 자주 출제된다
