## 운영체제란?

**운영체제(Operating System, OS)**는 컴퓨터 하드웨어와 사용자(응용 프로그램) 사이에 위치하여 하드웨어 자원을 효율적으로 관리하고 사용자에게 편리한 환경을 제공하는 **시스템 소프트웨어**입니다.

운영체제가 없다면 사용자는 CPU 레지스터를 직접 제어하고, 메모리 주소를 직접 계산해야 합니다. 운영체제는 이런 복잡한 작업을 대신 처리해줍니다.

### 운영체제의 목적

| 목적 | 설명 |
|------|------|
| **편리성** | 사용자가 컴퓨터를 쉽게 사용할 수 있는 인터페이스 제공 |
| **효율성** | CPU, 메모리, 디스크 등 자원을 최적으로 할당·관리 |
| **신뢰성** | 프로그램 오류나 장애 발생 시 시스템 전체를 보호 |
| **확장성** | 새로운 하드웨어나 소프트웨어 추가에 유연하게 대응 |

### 운영체제의 주요 기능

운영체제가 관리하는 자원은 크게 4가지입니다.

- **프로세스 관리:** 프로세스 생성, 스케줄링, 종료, 동기화
- **메모리 관리:** 주기억장치 할당, 보호, 가상 메모리
- **파일 시스템 관리:** 파일 생성/삭제, 디렉터리 관리, 접근 제어
- **입출력 관리:** 장치 드라이버, 인터럽트 처리, 버퍼링

## 운영체제의 구성요소

### 커널(Kernel)

**커널**은 운영체제의 핵심 부분으로 항상 메모리에 상주합니다. 하드웨어를 직접 제어하고 프로세스, 메모리, 파일, 입출력을 관리합니다.

커널의 동작 모드는 두 가지입니다.

| 모드 | 설명 | 접근 가능 자원 |
|------|------|----------------|
| **커널 모드 (특권 모드)** | 운영체제 코드 실행 | 모든 하드웨어 자원 |
| **사용자 모드** | 응용 프로그램 실행 | 제한된 자원만 접근 |

응용 프로그램이 파일을 읽거나 화면에 출력하려면 **시스템 호출(System Call)**을 통해 커널에 요청해야 합니다.

### 쉘(Shell)

**쉘**은 사용자와 커널 사이의 인터페이스입니다. 사용자의 명령을 해석하여 커널에 전달합니다.

- **CLI(Command Line Interface):** bash, zsh, sh 등
- **GUI(Graphical User Interface):** Windows 탐색기, macOS Finder 등

## 운영체제의 종류

### 처리 방식에 따른 분류

| 종류 | 특징 | 예시 |
|------|------|------|
| **일괄처리 시스템** | 작업을 모아 한꺼번에 처리, 대화 불가 | 초기 IBM 메인프레임 |
| **시분할 시스템** | CPU 시간을 나눠 여러 사용자가 동시 사용하는 것처럼 보임 | UNIX, Linux |
| **실시간 시스템** | 정해진 시간 내에 반드시 처리 완료 | 항공기 제어, 의료기기 |
| **분산 시스템** | 여러 컴퓨터를 네트워크로 연결해 하나처럼 동작 | 클라우드 OS |
| **다중 처리 시스템** | 여러 CPU가 하나의 메모리를 공유 | 멀티코어 OS |

## 운영체제의 발전 과정

### 1940년대~1950년대: 운영체제 이전

컴퓨터 한 대를 한 번에 한 명의 사용자가 독점 사용했습니다. 프로그램을 **천공 카드**에 작성하여 제출하면 운영자가 수동으로 실행했습니다.

### 1960년대: 일괄처리 시스템

비슷한 작업들을 묶어 **배치(Batch)**로 처리하는 방식이 등장했습니다. **모니터(Monitor)**라는 초보적인 운영체제가 작업 전환을 자동화했습니다.

- **다중 프로그래밍(Multiprogramming):** 메모리에 여러 프로그램을 동시에 올려두어 CPU를 낭비 없이 사용

### 1970년대: 시분할 시스템과 UNIX

**시분할(Time-Sharing)** 방식으로 여러 사용자가 터미널을 통해 동시에 컴퓨터를 사용할 수 있게 되었습니다. **UNIX** 운영체제가 탄생하며 현대 OS의 기초가 마련되었습니다.

### 1980년대: 개인용 컴퓨터(PC)

**MS-DOS**, **Apple DOS** 등 개인용 OS가 등장했습니다. 1984년 Apple Macintosh가 GUI를 대중화했습니다.

### 1990년대: GUI 확산과 네트워크 OS

**Windows 95**, **Linux** 커널 등이 등장하고 인터넷 보급과 함께 네트워크 기능이 핵심 요소가 되었습니다.

### 2000년대~현재: 모바일·클라우드·임베디드

- **모바일 OS:** Android, iOS
- **클라우드 OS:** 가상화 기술 기반 서버 관리
- **임베디드 OS:** FreeRTOS, VxWorks 등 IoT 기기용

## 인터럽트(Interrupt)

**인터럽트**는 CPU가 현재 실행 중인 작업을 잠시 멈추고 긴급한 사건을 처리한 뒤 다시 원래 작업으로 돌아오는 메커니즘입니다.

| 종류 | 발생 원인 |
|------|-----------|
| **하드웨어 인터럽트** | 입출력 완료, 키보드 입력, 타이머 만료 |
| **소프트웨어 인터럽트** | 프로그램 실행 중 예외 (0으로 나누기, 메모리 접근 위반) |
| **시스템 호출** | 응용 프로그램이 커널 서비스 요청 |

인터럽트 처리 순서: 인터럽트 발생 → 현재 상태 저장 → 인터럽트 서비스 루틴(ISR) 실행 → 상태 복원 → 원래 작업 재개

## 핵심 정리

- 운영체제는 하드웨어와 사용자 사이의 중간 계층 소프트웨어로, 자원을 효율적으로 관리한다
- 커널은 항상 메모리에 상주하는 핵심 부분이며, 커널 모드와 사용자 모드로 동작이 구분된다
- 처리 방식에 따라 일괄처리, 시분할, 실시간, 분산, 다중 처리 시스템으로 분류된다
- 운영체제는 1940년대 수동 운영에서 출발해 현재 모바일·클라우드 OS까지 발전했다
- 인터럽트는 CPU가 긴급 사건을 처리하는 핵심 메커니즘이다
