## 가상 메모리가 왜 필요한가?

컴퓨터의 물리 메모리(RAM)는 한정되어 있습니다. 램이 4GB라면 4GB보다 큰 프로그램은 실행할 수 없을까요? 또한 여러 프로그램을 동시에 실행하면 금방 메모리가 꽉 차버립니다.

게다가, 프로그램 전체를 항상 메모리에 올릴 필요도 없습니다. 게임을 예로 들면, 현재 1스테이지에 있는 플레이어에게 10스테이지의 데이터는 필요 없습니다.

**가상 메모리**(Virtual Memory)는 이 문제를 해결합니다. 실제 물리 메모리보다 훨씬 큰 주소 공간을 프로세스에 제공하고, 실제 필요한 부분만 메모리에 올리고 나머지는 디스크에 두는 기법입니다.

**쉽게 말하면:** 가상 메모리는 마치 책상이 작아도 필요한 책만 꺼내 놓고 나머지는 책장에 두는 것과 같습니다. 전체 책을 다 꺼내지 않아도 공부할 수 있습니다.

## 가상 메모리(Virtual Memory)의 장점

- 프로그램이 물리 메모리보다 커도 실행 가능
- 더 많은 프로세스를 동시에 실행 (다중 프로그래밍 정도 향상)
- 로딩 시간 단축 (실제 실행에 필요한 부분만 적재)
- 프로세스 간 메모리 공간 격리 (보안, 안정성 향상)

## 요구 페이징(Demand Paging)

**요구 페이징**(Demand Paging)은 페이지(Page)가 실제로 필요할 때만 메모리에 올리는 기법입니다. "요구가 있을 때 가져온다"는 원칙입니다.

**쉽게 말하면:** 도서관에서 책을 모두 집에 가져오는 대신, 필요할 때마다 한 권씩 빌려오는 것입니다.

- 처음에는 어떤 페이지도 메모리에 없는 상태로 시작
- 페이지에 접근할 때 메모리에 없으면 → **페이지 폴트**(Page Fault) 발생

### 페이지 테이블 항목 구조

유효-무효 비트(Valid-Invalid Bit)로 현재 페이지가 메모리에 있는지 나타냅니다.

| 프레임 번호 | 유효-무효 비트 | 의미 |
|-----------|--------------|------|
| 3 | 1 (유효) | 현재 메모리(프레임 3)에 있음 |
| - | 0 (무효) | 현재 디스크에 있음 |

## 페이지 폴트(Page Fault) 처리 과정

**페이지 폴트**(Page Fault)는 CPU가 접근하려는 페이지가 현재 물리 메모리에 없을 때 발생하는 인터럽트(Interrupt)입니다.

**쉽게 말하면:** 책상에 없는 책을 찾았을 때, 책장에서 꺼내와 책상에 올려두는 과정과 같습니다.

```
1. CPU가 페이지에 접근 시도
        ↓
2. 페이지 테이블 확인 → 유효-무효 비트 = 0 (없음)
        ↓
3. 페이지 폴트 트랩(Trap) 발생 → 운영체제로 제어 이동
        ↓
4. 운영체제가 페이지 폴트 처리 루틴 실행
        ↓
5. 필요한 페이지가 디스크의 어느 위치에 있는지 확인
        ↓
6. 빈 프레임 확보 (없으면 페이지 교체 알고리즘 실행)
        ↓
7. 디스크에서 해당 페이지를 프레임으로 읽어옴 (수십 ms 소요)
        ↓
8. 페이지 테이블 업데이트 (유효-무효 비트 = 1)
        ↓
9. 페이지 폴트를 일으킨 명령어 재시작 (Restart Instruction)
```

### 페이지 폴트율과 유효 접근 시간

페이지 폴트율 $p$ (0 이상 1 이하)에서:

$$
EAT = (1 - p) \times m + p \times \text{페이지 폴트 처리 시간}
$$

페이지 폴트 처리 시간은 디스크 접근을 포함하므로 메모리 접근(수십~수백 ns)보다 수만~수백만 배 느립니다. 따라서 페이지 폴트율 $p$를 최대한 낮게 유지하는 것이 중요합니다.

## 지역성(Locality)

**지역성**(Locality)은 프로그램이 짧은 시간 동안 메모리의 **특정 영역에 집중적으로 접근**하는 경향입니다. 이 원리 덕분에 요구 페이징이 실제로 효율적으로 동작합니다.

| 종류 | 설명 | 예시 |
|------|------|------|
| **시간적 지역성**(Temporal Locality) | 최근 참조한 위치를 가까운 미래에 또 참조 | 반복문에서 같은 변수 반복 사용 |
| **공간적 지역성**(Spatial Locality) | 참조한 위치 근처의 위치를 참조 | 배열 원소 순차 접근 |

**쉽게 말하면:** 오늘 많이 쓴 책은 내일도 쓸 가능성이 높고(시간적), 1번 책을 꺼냈다면 바로 옆 2번 책도 꺼낼 가능성이 높습니다(공간적). 이 원리 때문에 미리 올려둔 페이지가 자주 재사용되어 폴트가 줄어듭니다.

## 워킹 셋(Working Set)

**워킹 셋**(Working Set)은 프로세스가 현재 활발히 사용 중인 페이지들의 집합입니다. 특정 시간 $t$에서 과거 $\Delta$ 시간 동안 참조된 페이지의 집합으로 정의합니다.

$$|W(t, \Delta)| = \text{워킹 셋 크기}$$

- 프로세스에게 워킹 셋만큼의 프레임이 할당되면 페이지 폴트가 적게 발생
- 워킹 셋보다 적은 프레임이 할당되면 페이지 폴트가 자주 발생

**쉽게 말하면:** 공부할 때 현재 단원에 필요한 교재와 참고서 몇 권(워킹 셋)이 책상 위에 있으면 OK. 이보다 책상이 좁으면 자꾸 책장에서 책을 꺼내고 다시 넣어야 해서 비효율적입니다.

## 스래싱(Thrashing)

**스래싱**(Thrashing)은 프로세스들이 페이지 폴트를 처리하는 데 대부분의 시간을 소비하여 **실제 작업 시간이 거의 없는** 현상입니다. CPU 이용률(Utilization)이 급격히 떨어집니다.

**쉽게 말하면:** 책상이 너무 좁아서 공부는 못 하고 계속 책을 꺼내고 집어넣기만 하는 상태입니다.

### 스래싱 발생 과정

```
다중 프로그래밍 정도 증가 (프로세스 수 증가)
    ↓
각 프로세스에 할당된 프레임 수 감소
    ↓
페이지 폴트 빈도 증가
    ↓
CPU 이용률 감소 (디스크 I/O 대기 시간 급증)
    ↓
운영체제가 CPU 이용률을 높이려고 프로세스를 더 추가
    ↓
더 심한 스래싱 → CPU 이용률 급격히 감소
```

### 스래싱 해결 방법

| 방법 | 설명 |
|------|------|
| **워킹 셋 모델** | 프로세스의 워킹 셋 크기만큼 프레임 확보 후 실행 |
| **페이지 폴트 빈도(PFF, Page Fault Frequency) 기법** | 폴트율이 높으면 프레임 추가, 낮으면 프레임 반환 |
| **다중 프로그래밍 정도 감소** | 프로세스 수를 줄여 남은 프로세스에 충분한 프레임 확보 |

## 프레임 할당 방식

메모리에 올라온 여러 프로세스에게 프레임을 어떻게 나눠줄지 결정합니다.

| 방식 | 설명 | 특징 |
|------|------|------|
| **균등 할당**(Equal Allocation) | 모든 프로세스에 동일한 수의 프레임 | 단순하지만 크기 차이 무시 |
| **비례 할당**(Proportional Allocation) | 프로세스 크기에 비례하여 프레임 할당 | 공평하지만 구현 복잡 |
| **우선순위 할당**(Priority Allocation) | 높은 우선순위 프로세스에 더 많은 프레임 | 중요 작업 우선 처리 |

## 전역 교체 vs 지역 교체

프레임이 부족할 때 어느 프레임을 내보낼지 범위를 결정합니다.

| 구분 | 전역 교체(Global Replacement) | 지역 교체(Local Replacement) |
|------|---------|---------|
| 교체 범위 | 모든 프로세스의 프레임 중에서 선택 | 자신의 프레임 내에서만 선택 |
| 특징 | 유연하지만 타 프로세스에 영향 가능 | 독립적이지만 프레임 부족 시 문제 |

## 핵심 정리

- 가상 메모리(Virtual Memory)는 물리 메모리보다 큰 주소 공간을 제공하며, 요구 페이징으로 필요한 페이지만 적재한다
- 페이지 폴트(Page Fault) 처리: 트랩 발생 → 빈 프레임 확보 → 디스크에서 페이지 읽기 → 페이지 테이블 업데이트 → 명령어 재시작
- 지역성(시간적/공간적)이 요구 페이징의 효율성을 보장한다
- 스래싱(Thrashing)은 프레임 부족으로 페이지 폴트가 과다하게 발생하는 현상이다
- 워킹 셋(Working Set) 모델과 PFF 기법으로 스래싱을 방지한다
