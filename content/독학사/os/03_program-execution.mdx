<Callout type="info">
  **이번 문서의 목표:** 소스코드가 실행 파일이 되고, 다시 프로세스로 실행되기까지의 전체 흐름(컴파일→링킹→로딩→실행)을 설명할 수 있게 됩니다.
</Callout>

## 왜 이 흐름을 알아야 하는가?

뒤에서 배울 "프로세스"는 "실행 중인 프로그램"입니다. 그런데 프로그램이 어떻게 "실행 중" 상태가 되는지 그 과정을 모르면, 프로세스라는 개념이 추상적으로만 느껴집니다. 이 문서는 사람이 작성한 코드가 어떻게 CPU가 실행하는 상태까지 도달하는지를 단계별로 보여줍니다.

## 전체 흐름 한눈에 보기

<Steps>
### 1단계: 소스코드 작성
사람이 읽을 수 있는 프로그래밍 언어로 코드 작성

### 2단계: 컴파일(Compile)
소스코드를 CPU가 이해할 수 있는 기계어(목적 코드)로 번역

### 3단계: 링킹(Linking)
여러 목적 코드와 라이브러리를 하나의 실행 파일로 결합

### 4단계: 로딩(Loading)
실행 파일을 디스크에서 RAM으로 적재

### 5단계: 실행(Execution)
CPU가 RAM에 적재된 명령어를 하나씩 읽어 실행
</Steps>

## 1단계: 소스코드(Source Code)

사람이 이해하기 쉬운 프로그래밍 언어(C, Java, Python 등)로 작성한 텍스트 파일입니다. 컴퓨터는 이 상태로는 직접 실행할 수 없습니다 — CPU는 오직 **기계어**(0과 1로 이루어진 명령어)만 이해합니다.

## 2단계: 컴파일(Compile) — 번역 과정

> **쉽게 말하면:** 컴파일은 사람의 언어(소스코드)를 CPU의 언어(기계어)로 통째로 번역하는 과정입니다.

**컴파일러**(Compiler)가 소스코드를 분석해 **목적 코드**(Object Code, 기계어에 가까운 중간 결과물)로 변환합니다. 이 과정에서 문법 오류가 있으면 컴파일이 실패합니다(흔히 보는 "컴파일 에러"가 바로 이 단계에서 발생).

<Callout type="info">
  **컴파일 언어 vs 인터프리터 언어:** C, Java처럼 실행 전에 전체를 미리 컴파일하는 언어를 컴파일 언어라 하고, Python, JavaScript처럼 한 줄씩 즉시 해석하며 실행하는 언어를 인터프리터 언어라고 합니다. 운영체제 시험에서는 주로 컴파일 언어의 실행 흐름을 다룹니다.
</Callout>

## 3단계: 링킹(Linking) — 조각을 하나로 합치기

> **쉽게 말하면:** 큰 프로그램은 여러 개의 소스 파일로 나눠 작성되고, 이미 만들어진 라이브러리(다른 사람이 작성한 코드 모음)를 가져다 쓰기도 합니다. 링킹은 이 흩어진 조각들을 하나의 완전한 실행 파일로 합치는 과정입니다.

**링커**(Linker)는 여러 목적 코드 파일들과, 프로그램이 사용하는 라이브러리 함수(예: 화면에 출력하는 함수)의 실제 위치를 연결해, 최종 **실행 파일**(Executable File)을 만듭니다.

<Table>
  <thead>
    <tr><th>단계</th><th>입력</th><th>출력</th><th>담당 프로그램</th></tr>
  </thead>
  <tbody>
    <tr><td>컴파일</td><td>소스코드(.c 등)</td><td>목적 코드(.o 등)</td><td>컴파일러</td></tr>
    <tr><td>링킹</td><td>목적 코드 + 라이브러리</td><td>실행 파일(.exe 등)</td><td>링커</td></tr>
  </tbody>
</Table>

## 4단계: 로딩(Loading) — 디스크에서 RAM으로

> **쉽게 말하면:** 로딩은 완성된 실행 파일을 디스크에서 RAM으로 복사해 올려놓는 과정입니다. 01번 문서에서 배운 "CPU가 빠르게 접근하려면 RAM에 있어야 한다"는 원리가 여기서 적용됩니다.

**로더**(Loader, 운영체제의 일부)가 다음 작업을 수행합니다.

<Table>
  <thead>
    <tr><th>작업</th><th>내용</th></tr>
  </thead>
  <tbody>
    <tr><td>메모리 할당</td><td>프로그램이 사용할 RAM 공간을 확보</td></tr>
    <tr><td>파일 적재</td><td>실행 파일의 내용을 그 메모리 공간에 복사</td></tr>
    <tr><td>주소 조정</td><td>02번 문서에서 배운 메모리 주소를 실제 할당된 위치에 맞게 조정</td></tr>
  </tbody>
</Table>

## 5단계: 실행(Execution) — 프로세스의 탄생

로딩이 끝나면 운영체제는 이 프로그램을 **프로세스**(Process, "실행 중인 프로그램")로 등록하고, CPU가 명령어를 순서대로 읽어 실행하기 시작합니다.

<Callout type="warning">
  **자주 틀리는 점:** "프로그램"과 "프로세스"는 다른 개념입니다. **프로그램**은 디스크에 저장된 정적인 파일(실행되지 않은 상태)이고, **프로세스**는 그 프로그램이 메모리에 로딩되어 실제로 실행 중인 상태를 가리킵니다. 같은 프로그램(예: 메모장)을 두 번 실행하면, 프로그램은 하나지만 프로세스는 두 개가 생깁니다.
</Callout>

## 핵심 정리

- **컴파일**: 소스코드를 목적 코드(기계어에 가까운 형태)로 번역.
- **링킹**: 여러 목적 코드와 라이브러리를 하나의 실행 파일로 결합.
- **로딩**: 완성된 실행 파일을 디스크에서 RAM으로 적재.
- **실행**: CPU가 RAM의 명령어를 읽어 처리 — 이 순간부터 "프로세스"라 부른다.
- **프로그램**(정적 파일) ≠ **프로세스**(실행 중인 동적 상태). 같은 프로그램도 여러 프로세스로 실행 가능.
