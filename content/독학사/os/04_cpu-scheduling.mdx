## CPU 스케줄링이 왜 필요한가?

컴퓨터에는 CPU가 1개(또는 몇 개)인데, 실행하고 싶은 프로세스는 수십 개입니다. 누가 먼저 CPU를 쓸지 결정해야 합니다. 이 규칙을 **CPU 스케줄링**(CPU Scheduling)이라고 합니다.

**쉽게 말하면:** 은행 창구(CPU)는 하나인데 손님(프로세스)은 많습니다. 어떤 순서로 손님을 처리할지 정하는 것이 스케줄링입니다.

## CPU 스케줄링이란?

**CPU 스케줄링**은 준비 큐(Ready Queue)에 있는 여러 프로세스 중 어떤 것을 CPU에 할당할지 결정하는 정책입니다.

### 스케줄링 성능 지표

| 지표 | 정의 | 목표 |
|------|------|------|
| **CPU 이용률**(CPU Utilization) | CPU가 실제로 작업하는 비율 | 최대화 |
| **처리량**(Throughput) | 단위 시간당 완료된 프로세스 수 | 최대화 |
| **반환 시간**(Turnaround Time) | 제출~완료까지의 총 시간 | 최소화 |
| **대기 시간**(Waiting Time) | 준비 큐에서 기다린 시간 | 최소화 |
| **응답 시간**(Response Time) | 요청 후 첫 응답까지의 시간 | 최소화 |

반환 시간 = 완료 시간 - 도착 시간  
대기 시간 = 반환 시간 - 실행 시간(CPU 버스트)

### 선점 vs 비선점

**선점**(Preemptive)과 **비선점**(Non-preemptive)은 현재 실행 중인 프로세스의 CPU를 강제로 빼앗을 수 있는지 여부입니다.

| 구분 | 설명 | 특징 |
|------|------|------|
| **비선점**(Non-preemptive) | 프로세스가 CPU를 받으면 완료되거나 I/O 요청까지 양보 안 함 | 간단, 오버헤드 낮음 |
| **선점**(Preemptive) | 우선순위 높은 프로세스가 현재 실행 중인 프로세스를 강제로 뺏을 수 있음 | 응답성 높음, 복잡 |

**비유:** 비선점은 식당에서 자리에 앉으면 다 먹을 때까지 자리를 뺏기지 않는 방식입니다. 선점은 VIP 손님이 오면 현재 손님의 자리를 빼앗는 방식입니다.

## FCFS (First Come First Served, 선착순)

도착한 순서대로 CPU를 할당합니다. **비선점** 방식입니다.

**쉽게 말하면:** 은행 창구에서 먼저 온 사람이 먼저 서비스받는 것입니다.

### 예시

| 프로세스 | 도착 시간 | 실행 시간 |
|---------|---------|---------|
| P1 | 0 | 24ms |
| P2 | 0 | 3ms |
| P3 | 0 | 3ms |

**간트 차트(Gantt Chart, 작업 시간표):**
```
│ P1 (24ms) │ P2 (3ms) │ P3 (3ms) │
0          24         27         30
```

- 평균 대기 시간 = (0 + 24 + 27) / 3 = **17ms**

**호위 효과(Convoy Effect):** 짧은 프로세스가 긴 프로세스 뒤에 오면 오래 기다려야 하는 문제. 마치 고속도로에서 느린 트럭 뒤에 빠른 차들이 줄줄이 막히는 상황과 같습니다.

## SJF (Shortest Job First, 최단 작업 우선)

실행 시간이 **가장 짧은 프로세스**를 먼저 실행합니다. **최적 알고리즘** (평균 대기 시간 최소). 비선점 방식입니다.

**쉽게 말하면:** 슈퍼마켓 셀프 계산대에서 물건이 적은 사람을 먼저 처리하는 방식입니다.

### 예시

| 프로세스 | 도착 시간 | 실행 시간 |
|---------|---------|---------|
| P1 | 0 | 6ms |
| P2 | 0 | 8ms |
| P3 | 0 | 7ms |
| P4 | 0 | 3ms |

**간트 차트 (SJF):**
```
│ P4 (3ms) │ P1 (6ms) │ P3 (7ms) │ P2 (8ms) │
0          3          9         16         24
```

- 평균 대기 시간 = (3 + 16 + 9 + 0) / 4 = **7ms** (FCFS보다 훨씬 적음)

**문제점:** 다음 CPU 버스트 시간을 정확히 알 수 없음 (예측 값 사용), **기아**(Starvation, 아사) 현상 — 긴 프로세스가 계속 실행 못 함

## SRT (Shortest Remaining Time, 최단 잔여 시간)

SJF의 **선점** 버전입니다. 새 프로세스가 도착할 때마다 남은 시간을 비교하여 더 짧은 것을 실행합니다. 더 짧은 새 프로세스가 오면 현재 프로세스의 CPU를 빼앗습니다.

## Round Robin (RR, 라운드 로빈)

각 프로세스에 **동일한 시간 할당량**(Time Quantum, 타임 퀀텀)을 부여합니다. 할당량이 끝나면 CPU를 반납하고 준비 큐의 맨 뒤로 이동합니다. **선점** 방식.

**쉽게 말하면:** 놀이터 그네를 정해진 시간(예: 5분)마다 교대로 타는 방식입니다. 누구도 독점하지 못합니다.

### 예시 (Time Quantum = 4ms)

| 프로세스 | 실행 시간 |
|---------|---------|
| P1 | 24ms |
| P2 | 3ms |
| P3 | 3ms |

**간트 차트:**
```
│P1│P2│P3│P1│P1│P1│P1│P1│
0  4  7 10 14 18 22 26 30
```

- 평균 대기 시간 = (6 + 4 + 7) / 3 = **5.66ms**

<Callout type="warning">
  타임 퀀텀(Time Quantum)이 너무 크면 FCFS와 동일해지고, 너무 작으면 컨텍스트 스위칭 오버헤드가 커집니다. 일반적으로 10~100ms로 설정합니다.
</Callout>

## 우선순위 스케줄링 (Priority Scheduling)

각 프로세스에 **우선순위**(Priority)를 부여하고 높은 우선순위 프로세스를 먼저 실행합니다. 선점/비선점 모두 가능.

**기아(Starvation) 문제:** 낮은 우선순위 프로세스가 영원히 실행되지 못할 수 있습니다.  
**해결책: 에이징**(Aging, 노화) — 시간이 지날수록 프로세스의 우선순위를 점진적으로 높여줍니다. 오래 기다린 사람을 VIP로 대우하는 것과 같습니다.

## HRN (Highest Response-ratio Next, 최고 응답률 우선)

비선점 스케줄링으로 우선순위를 동적으로 계산합니다.

$$
\text{우선순위} = \frac{\text{대기 시간} + \text{실행 시간}}{\text{실행 시간}}
$$

값이 클수록 먼저 실행되므로, 오래 기다린 프로세스의 우선순위가 자동으로 높아집니다. 기아 현상을 방지합니다.

**쉽게 말하면:** 기다린 시간이 길수록 더 높은 점수를 받아서 먼저 처리됩니다.

## 다단계 큐 스케줄링 (MLQ, Multi-Level Queue)

준비 큐를 **여러 단계의 큐**로 분리하고 각 큐에 서로 다른 스케줄링 알고리즘을 적용합니다.

```
우선순위 높음
┌─────────────────────┐
│  시스템 프로세스     │ → Round Robin
├─────────────────────┤
│  대화형 프로세스     │ → Round Robin
├─────────────────────┤
│  일괄처리 프로세스   │ → FCFS
└─────────────────────┘
우선순위 낮음
```

상위 큐가 비어 있어야 하위 큐를 실행합니다. 큐 간 이동이 없습니다.

## 다단계 피드백 큐 (MLFQ, Multi-Level Feedback Queue)

MLQ와 달리 **프로세스가 큐 간에 이동 가능**합니다. CPU를 많이 사용한 프로세스는 낮은 우선순위 큐로 이동하고, 오래 기다린 프로세스는 높은 우선순위 큐로 올라갑니다.

**쉽게 말하면:** MLFQ는 "CPU를 많이 쓰는 욕심쟁이는 뒤로 물러서고, 오래 기다린 사람은 앞으로 오라"는 공평한 방식입니다.

실제 운영체제(Linux, Windows)에서 널리 사용하는 방식입니다.

## 알고리즘 비교 요약

| 알고리즘 | 선점 | 특징 | 문제점 |
|---------|------|------|--------|
| FCFS | 비선점 | 구현 간단 | 호위 효과 |
| SJF | 비선점 | 최적 대기 시간 | 기아, 실행 시간 예측 불가 |
| SRT | 선점 | SJF 선점 버전 | 기아 |
| Round Robin | 선점 | 공평, 응답성 높음 | Time Quantum 설정 중요 |
| Priority | 선점/비선점 | 우선순위 반영 | 기아 → 에이징으로 해결 |
| MLQ | 선점 | 큐별 다른 알고리즘 | 큐 간 이동 불가 |
| MLFQ | 선점 | 동적 우선순위 조정 | 구현 복잡 |

## 핵심 정리

- CPU 스케줄링은 준비 큐의 프로세스 중 CPU를 할당할 프로세스를 선택하는 정책이다
- FCFS는 단순하지만 호위 효과, SJF는 최적이지만 기아 문제가 있다
- Round Robin(라운드 로빈)은 타임 퀀텀을 사용하는 선점 방식으로 응답성이 높다
- 우선순위 스케줄링의 기아 문제는 에이징(Aging)으로 해결한다
- MLFQ는 현대 OS에서 가장 널리 사용되는 방식이다
