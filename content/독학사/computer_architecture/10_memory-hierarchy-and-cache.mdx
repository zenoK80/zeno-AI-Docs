## 메모리 계층 구조

속도와 비용의 트레이드오프에 의해 메모리를 계층적으로 구성합니다.

```
          ┌──────────┐  ← 레지스터 (가장 빠름, 가장 비쌈, 가장 작음)
         ┌┤  레지스터  ├┐
        ┌┤└──────────┘├┐
       ┌┤    캐시 L1   ├┐
      ┌┤  └──────────┘ ├┐
     ┌┤      캐시 L2    ├┐
    ┌┤    └──────────┘  ├┐
   ┌┤         캐시 L3   ├┐
  ┌┤       └──────────┘ ├┐
 ┌┤           메인 메모리  ├┐
┌┤          └──────────┘ ├┐
│              보조 기억장치   │  ← HDD/SSD (가장 느림, 가장 저렴, 가장 큼)
└─────────────────────────┘
```

| 레벨 | 속도 | 용량 | 가격 | 예시 |
|------|------|------|------|------|
| 레지스터 | 수 ps | 수십~수백 바이트 | 매우 비쌈 | CPU 레지스터 |
| L1 캐시 | 수 ns | 32~64KB | 비쌈 | SRAM |
| L2 캐시 | 수 ns | 256KB~1MB | 비쌈 | SRAM |
| L3 캐시 | 수십 ns | 수~수십 MB | 보통 | SRAM |
| 메인 메모리 | 수십~수백 ns | 수~수백 GB | 보통 | DRAM |
| SSD | 수십 us | 수백 GB~수 TB | 저렴 | NAND Flash |
| HDD | 수 ms | 수 TB | 매우 저렴 | 자기 디스크 |

## 캐시 메모리 (Cache Memory)

CPU와 메인 메모리 사이의 속도 차이를 줄이는 고속 버퍼 메모리입니다.

### 지역성 원리 (Principle of Locality)

캐시가 효과적으로 동작하는 이유입니다.

| 종류 | 설명 | 예시 |
|------|------|------|
| **시간 지역성 (Temporal Locality)** | 최근에 참조된 데이터는 곧 다시 참조될 가능성이 높음 | 반복문 내 변수 |
| **공간 지역성 (Spatial Locality)** | 최근에 참조된 주소 근처의 데이터도 참조될 가능성이 높음 | 배열 순차 접근 |

### 캐시 히트와 미스

- **캐시 히트(Cache Hit):** 요청한 데이터가 캐시에 있는 경우
- **캐시 미스(Cache Miss):** 요청한 데이터가 캐시에 없어 메인 메모리에서 가져와야 하는 경우

$$
\text{히트율(Hit Rate, h)} = \frac{\text{캐시 히트 횟수}}{\text{총 메모리 접근 횟수}}
$$

### 유효 접근 시간 (Effective Access Time, EAT)

$$
EAT = h \times T_c + (1-h) \times T_m
$$

- $T_c$: 캐시 접근 시간
- $T_m$: 메인 메모리 접근 시간
- $h$: 캐시 히트율

**예시:** $T_c$ = 10ns, $T_m$ = 100ns, h = 0.9이면

$$
EAT = 0.9 \times 10 + 0.1 \times 100 = 9 + 10 = 19 \text{ns}
$$

## 캐시 매핑 방식

메인 메모리의 블록을 캐시의 어느 슬롯에 놓을지 결정하는 방식입니다.

### 1. 직접 매핑 (Direct Mapping)

각 메모리 블록이 **고정된 캐시 슬롯**에만 매핑됩니다.

```
캐시 슬롯 번호 = 메모리 블록 번호 mod 캐시 슬롯 수
```

- 장점: 구현 단순, 주소 변환 빠름
- 단점: 충돌(Conflict) 미스 발생 → 히트율 낮을 수 있음

### 2. 완전 연관 매핑 (Fully Associative Mapping)

메모리 블록이 **캐시의 어떤 슬롯에나** 자유롭게 배치됩니다.

- 장점: 충돌 미스 없음, 히트율 높음
- 단점: 모든 슬롯 검색 필요 → 복잡하고 느림, 비쌈

### 3. 집합 연관 매핑 (Set-Associative Mapping)

캐시를 여러 집합(Set)으로 나누고, 각 집합 안에서는 완전 연관 방식을 적용합니다.

```
집합 번호 = 메모리 블록 번호 mod 집합 수
```

n-Way 집합 연관: 한 집합에 n개의 슬롯

- 장점: 직접 매핑보다 히트율 높음, 완전 연관보다 구현 단순
- 단점: 복잡도 증가

| 방식 | 유연성 | 충돌 미스 | 복잡도 |
|------|--------|---------|--------|
| 직접 매핑 | 낮음 | 높음 | 낮음 |
| 완전 연관 | 높음 | 없음 | 높음 |
| 집합 연관 | 중간 | 낮음 | 중간 |

## 캐시 교체 알고리즘

캐시가 가득 찼을 때 교체할 블록을 결정하는 알고리즘입니다.

| 알고리즘 | 설명 | 특징 |
|---------|------|------|
| **LRU (Least Recently Used)** | 가장 오랫동안 사용되지 않은 블록 교체 | 시간 지역성 반영, 구현 비용 높음 |
| **FIFO (First In, First Out)** | 가장 먼저 들어온 블록 교체 | 구현 단순, 최적 아님 |
| **LFU (Least Frequently Used)** | 사용 빈도가 가장 낮은 블록 교체 | 빈도 카운터 필요 |
| **무작위 (Random)** | 무작위로 교체 | 구현 단순 |
| **최적 (OPT)** | 앞으로 가장 오랫동안 사용되지 않을 블록 교체 | 이론적 최적, 실제 구현 불가 |

## 캐시 쓰기 정책

캐시의 데이터를 메인 메모리에 쓰는 방식입니다.

| 정책 | 설명 | 장단점 |
|------|------|--------|
| **즉시 쓰기 (Write-Through)** | 캐시와 메모리를 동시에 갱신 | 일관성 보장, 느린 쓰기 |
| **지연 쓰기 (Write-Back)** | 캐시에만 쓰고, 블록 교체 시 메모리 갱신 | 빠른 쓰기, 일관성 문제 |

## 핵심 정리

- 메모리 계층: 레지스터 → L1/L2/L3 캐시 → 메인 메모리 → 보조 기억장치
- 지역성: 시간 지역성(반복 참조), 공간 지역성(인근 주소 참조)
- EAT = h×Tc + (1-h)×Tm
- 매핑: 직접(단순/충돌 미스), 완전 연관(히트율 높음/복잡), 집합 연관(절충)
- 교체: LRU(가장 오래 미사용), FIFO(먼저 들어온 것), LFU(빈도 낮은 것)
