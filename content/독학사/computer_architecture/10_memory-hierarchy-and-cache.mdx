## 왜 메모리를 계층적으로 구성하나요?

이상적인 메모리는 **빠르고, 용량이 크고, 저렴해야** 합니다. 하지만 현실에서는 이 세 가지를 동시에 만족하는 메모리가 없습니다.

- **빠른 메모리(SRAM):** 비싸고 용량이 작음
- **용량이 큰 메모리(DRAM):** 상대적으로 느리고 비쌈
- **저렴한 저장장치(HDD):** 매우 느림

**해결책:** 이 메모리들을 계층적으로 쌓아서, CPU는 가장 빠른 메모리(캐시)를 먼저 보고, 없으면 아래 계층으로 내려가도록 합니다.

---

## 메모리 계층 구조 (Memory Hierarchy)

```
속도 빠름 / 용량 작음 / 가격 비쌈
        ↑
   레지스터 (Register, CPU 내부)
        ↓
   캐시 메모리 (Cache Memory, SRAM)
        ↓
   주기억장치 (Main Memory, DRAM)
        ↓
   보조기억장치 (Storage, HDD/SSD)
        ↑
속도 느림 / 용량 큼 / 가격 저렴
```

**비유:** 요리사의 작업 공간과 같습니다.
- 레지스터 = 요리사 손 안 (가장 즉각적)
- 캐시 = 조리대 위 (바로 옆에 준비된 재료)
- 메인 메모리 = 냉장고 (잠깐 가져와야 함)
- 보조기억장치 = 창고 (멀리 가야 함)

## 지역성 (Locality)

캐시가 효과적으로 동작하는 이유는 **지역성(Locality)**이라는 프로그램의 특성 때문입니다.

### 시간적 지역성 (Temporal Locality)

**정의:** 최근에 접근한 데이터는 곧 다시 접근할 가능성이 높습니다.

**예시:** 반복문(for, while) 안의 변수는 반복마다 계속 접근됩니다.
```
for (int i = 0; i < 100; i++) {
    sum += array[i];  // sum과 i는 반복마다 계속 접근됨
}
```

### 공간적 지역성 (Spatial Locality)

**정의:** 현재 접근한 주소 근처의 데이터도 곧 접근할 가능성이 높습니다.

**예시:** 배열의 원소를 순차 접근할 때, 하나를 읽으면 그 주변 원소들도 곧 필요합니다.

**쉽게 말하면:** 책을 읽을 때 한 페이지를 펼치면 그 옆 페이지도 읽을 가능성이 높은 것과 같습니다.

## 캐시 메모리 (Cache Memory)

**캐시(Cache)**는 CPU와 주기억장치 사이에 위치하는 고속 버퍼 메모리입니다. 자주 사용하는 데이터를 캐시에 미리 복사해두어 CPU의 메모리 대기 시간을 줄입니다.

### 캐시 히트와 미스

- **히트(Hit):** CPU가 원하는 데이터가 캐시에 있는 경우. 빠르게 처리됨.
- **미스(Miss):** CPU가 원하는 데이터가 캐시에 없는 경우. 메인 메모리에서 데이터를 가져와야 하므로 느림.

### 유효 접근 시간 (Effective Access Time, EAT)

캐시가 있을 때 평균 메모리 접근 시간을 계산합니다.

$$
\text{EAT} = h \times T_c + (1-h) \times T_m
$$

- $h$: 히트율(Hit Ratio, 캐시 히트 확률)
- $T_c$: 캐시 접근 시간
- $T_m$: 메인 메모리 접근 시간

**예시:** 히트율 90%, 캐시 1ns, 메인 메모리 100ns라면

$$
EAT = 0.9 \times 1 + 0.1 \times 100 = 0.9 + 10 = 10.9 \text{ns}
$$

캐시가 없을 때 100ns에서 10.9ns로 크게 줄었습니다!

## 캐시 매핑 방식 (Cache Mapping)

메인 메모리의 데이터를 캐시의 어느 위치에 올려놓을지를 결정하는 방식입니다.

### 직접 매핑 (Direct Mapping)

**원리:** 메인 메모리의 각 블록이 캐시의 정해진 한 위치에만 올라갈 수 있습니다.

$$
\text{캐시 라인 번호} = \text{메모리 블록 번호} \mod \text{캐시 라인 수}
$$

**비유:** 학교 사물함처럼 각 학생의 번호가 정해진 사물함에만 들어갈 수 있습니다.

- 장점: 구현이 단순하고 빠름
- 단점: 같은 캐시 위치를 두 데이터가 계속 경쟁하면 캐시 충돌(Conflict Miss) 발생

### 완전 연관 매핑 (Fully Associative Mapping)

**원리:** 메인 메모리 블록이 캐시의 어느 위치에나 올라갈 수 있습니다.

- 장점: 충돌 미스 없음, 히트율 높음
- 단점: 캐시 전체를 병렬로 탐색해야 하므로 회로가 복잡하고 비쌈

### 집합 연관 매핑 (Set-Associative Mapping)

**원리:** 직접 매핑과 완전 연관 매핑의 절충안입니다. 캐시를 집합(Set)으로 나누고, 메모리 블록은 특정 집합 안에서 아무 위치에나 들어갈 수 있습니다.

- **2-way 집합 연관:** 각 집합에 2개 슬롯. 충돌 미스 줄이면서 탐색 범위 제한
- **4-way, 8-way:** 슬롯 수 늘어날수록 완전 연관 매핑에 가까워짐

| 방식 | 충돌 미스 | 회로 복잡도 | 탐색 속도 |
|------|----------|-----------|---------|
| 직접 매핑 | 많음 | 단순 | 빠름 |
| 집합 연관 | 중간 | 중간 | 중간 |
| 완전 연관 | 없음 | 복잡 | 느림 |

## 캐시 교체 알고리즘 (Cache Replacement Algorithm)

캐시가 가득 찼을 때 새 데이터를 위해 어느 캐시 라인을 제거할지 결정합니다.

| 알고리즘 | 설명 | 특성 |
|----------|------|------|
| **LRU** (Least Recently Used) | 가장 오래 사용되지 않은 블록 교체 | 히트율 높음, 구현 복잡 |
| **FIFO** (First In First Out) | 가장 먼저 들어온 블록 교체 | 구현 단순, 히트율 낮을 수 있음 |
| **LFU** (Least Frequently Used) | 사용 빈도가 가장 낮은 블록 교체 | 빈도 카운터 필요 |
| **Random** | 무작위 교체 | 단순, 예측 불가 |
| **OPT** (Optimal) | 앞으로 가장 오래 사용되지 않을 블록 교체 | 이상적, 현실에서 구현 불가(미래 예측 필요) |

**쉽게 말하면:** LRU는 "최근에 안 썼으면 버린다", FIFO는 "먼저 들어온 게 먼저 나간다", LFU는 "덜 쓴 것을 버린다"입니다.

## 캐시 쓰기 정책 (Write Policy)

CPU가 캐시에 데이터를 쓸 때 메인 메모리를 어떻게 동기화할지 결정합니다.

### Write-Through (즉시 쓰기)

- 캐시에 쓸 때 **동시에 메인 메모리에도** 씁니다.
- 장점: 일관성(Consistency) 보장, 구현 단순
- 단점: 모든 쓰기 작업마다 느린 메인 메모리 접근 발생

### Write-Back (나중 쓰기)

- 캐시에만 우선 씁니다. 캐시 라인이 교체될 때 메인 메모리에 씁니다.
- **더티 비트(Dirty Bit):** 캐시 내용이 변경됐는지 표시하는 비트. 교체 시 더티이면 메모리에 씀.
- 장점: 메모리 쓰기 횟수 줄어 빠름
- 단점: 캐시와 메모리 불일치 기간 존재, 구현 복잡

---

## 핵심 정리

- **메모리 계층:** 레지스터 → 캐시 → 메인 메모리 → 보조기억장치 (빠름/비쌈 → 느림/저렴)
- **시간적 지역성:** 최근 접근 데이터는 곧 다시 접근 가능성 높음
- **공간적 지역성:** 현재 접근 주소 근처도 곧 접근 가능성 높음
- **EAT = h × Tc + (1-h) × Tm:** 히트율이 높을수록 평균 접근 시간 빠름
- **직접 매핑:** 위치 고정, 단순, 충돌 가능
- **완전 연관:** 어디든 배치 가능, 복잡, 충돌 없음
- **집합 연관:** 절충안, 현대 CPU에서 주로 사용
- **LRU:** 가장 오래 미사용 블록 교체, 히트율 높음
- **Write-Through:** 즉시 메모리 반영, Write-Back: 교체 시 메모리 반영
