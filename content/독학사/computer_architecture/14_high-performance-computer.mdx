## RISC vs CISC

컴퓨터의 명령어 집합(ISA: Instruction Set Architecture) 설계 철학에 따라 두 가지 방향이 있습니다.

### CISC (Complex Instruction Set Computer, 복잡 명령어 집합 컴퓨터)

**언제 등장했나요?** 메모리가 매우 비쌌던 시절, 프로그램의 크기를 줄이기 위해 한 명령어로 복잡한 작업을 할 수 있는 명령어를 많이 만들었습니다.

**쉽게 말하면:** "커피 한 잔 주세요" 한 마디로 원두 갈기 → 물 끓이기 → 추출 → 잔에 담기까지 전부 해결하는 방식입니다.

- **특징:** 명령어 종류가 매우 많고, 명령어마다 실행 시간이 다름
- **예시:** x86 (인텔/AMD의 PC CPU), x86-64

### RISC (Reduced Instruction Set Computer, 축소 명령어 집합 컴퓨터)

**언제 등장했나요?** 연구를 통해 프로그램에서 실제 사용되는 명령어는 전체의 20% 정도에 불과하다는 것이 밝혀졌습니다. 간단한 명령어만을 빠르게 실행하는 설계가 등장했습니다.

**쉽게 말하면:** "원두 주세요", "물 끓여주세요", "추출해주세요", "잔에 담아주세요" 각각 따로 주문하지만, 각 단계가 매우 빠른 방식입니다.

- **특징:** 명령어 수가 적고, 모든 명령어가 동일한 시간(1 클럭)에 실행 가능
- **예시:** ARM (스마트폰, 태블릿, Apple Silicon), MIPS, RISC-V

### 현대의 x86

현재 인텔/AMD의 x86 CPU는 외부적으로는 CISC 명령어를 지원하지만, 내부에서 이를 간단한 **마이크로 연산(Micro-ops, 마이크로 옵스)**으로 분해하여 RISC처럼 처리합니다. CISC의 호환성과 RISC의 성능을 동시에 확보합니다.

### RISC vs CISC 비교

| 특성 | RISC | CISC |
|------|------|------|
| **명령어 수** | 적음 (수십~수백) | 많음 (수백~수천) |
| **명령어 길이** | 고정 (보통 32비트) | 가변 (1~15바이트) |
| **실행 시간** | 대부분 1 클럭 | 명령어마다 다름 |
| **파이프라인** | 효율적 | 복잡 |
| **레지스터** | 많음 | 적음 |
| **메모리 접근** | LOAD/STORE만 | 다양한 명령어에서 가능 |
| **컴파일러 부담** | 큼 (최적화 필요) | 작음 |
| **예시** | ARM, MIPS, RISC-V | x86, x86-64 |

## 멀티코어 프로세서 (Multi-core Processor)

**멀티코어 프로세서**는 하나의 CPU 칩에 여러 개의 처리 코어(Core)를 집적한 것입니다.

**비유:** 한 회사 건물(CPU 칩) 안에 여러 부서(코어)가 있어 각자 독립적으로 일합니다.

### 캐시 일관성 문제 (Cache Coherency Problem)

멀티코어에서 각 코어는 자신의 **L1, L2 캐시**를 가집니다. 문제는 여러 코어가 같은 메모리 주소의 데이터를 각자 캐시에 복사해두면 **캐시 내용이 서로 달라지는** 불일치(Incoherence) 문제가 생깁니다.

**예시:**
1. 코어 1이 메모리 주소 100의 값(10)을 캐시에 가져옴
2. 코어 2도 주소 100의 값(10)을 캐시에 가져옴
3. 코어 1이 자기 캐시의 값을 20으로 변경
4. 코어 2의 캐시에는 아직 10이 들어있음 → 불일치!

### MESI 프로토콜

이를 해결하기 위해 **MESI 프로토콜**을 사용합니다. 각 캐시 라인은 4가지 상태 중 하나를 갖습니다.

| 상태 | 의미 |
|------|------|
| **M (Modified, 수정됨)** | 이 코어만 해당 데이터를 가지며, 메모리와 불일치 (나중에 메모리에 반영) |
| **E (Exclusive, 독점)** | 이 코어만 해당 데이터를 가지며, 메모리와 일치 |
| **S (Shared, 공유)** | 여러 코어가 같은 데이터를 가지며, 메모리와 일치 |
| **I (Invalid, 무효)** | 다른 코어가 데이터를 수정했으므로 이 캐시 라인은 사용 불가 |

코어가 데이터를 수정하면 다른 코어의 동일 캐시 라인을 Invalid 상태로 만들어 일관성을 유지합니다.

## GPU (Graphics Processing Unit, 그래픽 처리 장치)

**GPU**는 원래 3D 그래픽 렌더링을 위해 설계된 프로세서였지만, 현재는 과학 계산, 딥러닝, 암호화폐 채굴 등 다양한 병렬 연산에 활용됩니다.

### CPU vs GPU 비교

| 특성 | CPU | GPU |
|------|-----|-----|
| **코어 수** | 수십 개 (4~64) | 수천 개 (수백~수만) |
| **코어 설계** | 복잡, 고성능 단일 코어 | 단순, 낮은 클럭의 코어 다수 |
| **적합한 작업** | 순차 처리, 복잡한 제어 흐름 | 대량 병렬 연산 |
| **캐시** | 크고 복잡 | 작음 |
| **메모리 대역폭** | 낮음 | 매우 높음 |

### GPGPU (General Purpose GPU, 범용 GPU)

그래픽이 아닌 일반 연산(딥러닝 행렬 곱셈, 물리 시뮬레이션 등)에 GPU를 사용하는 것입니다. NVIDIA의 CUDA, AMD의 ROCm 같은 프레임워크를 통해 GPU를 프로그래밍합니다.

## 클러스터 컴퓨터 (Cluster Computer)

**클러스터(Cluster)**는 여러 대의 독립적인 컴퓨터(노드)를 고속 네트워크로 연결하여 하나의 시스템처럼 사용하는 것입니다.

| 클러스터 유형 | 목적 |
|-------------|------|
| **HPC 클러스터** (High Performance Computing) | 과학 계산, 기상 예측, 물리 시뮬레이션 등 고성능 연산 |
| **부하 분산 클러스터** (Load Balancing) | 웹 서버 등에서 요청을 여러 서버에 분산 |
| **고가용성 클러스터** (High Availability, HA) | 서버 하나가 장애 나도 다른 서버가 즉시 대체 |

---

## 클라우드 컴퓨팅 (Cloud Computing)

**클라우드 컴퓨팅**은 인터넷을 통해 컴퓨팅 자원(서버, 스토리지, 소프트웨어)을 필요할 때 빌려 사용하는 모델입니다.

**비유:** 발전소 전기를 직접 만들지 않고 필요한 만큼 콘센트에서 쓰는 것처럼, 서버를 직접 구매하지 않고 필요한 만큼 빌려 씁니다.

### 클라우드 서비스 모델

| 모델 | 전체 이름 | 제공 범위 | 예시 |
|------|----------|---------|------|
| **IaaS** | Infrastructure as a Service | 하드웨어(서버, 스토리지, 네트워크) 제공 | AWS EC2, Google Compute Engine |
| **PaaS** | Platform as a Service | 개발 플랫폼(OS, 런타임, DB) 제공 | AWS Elastic Beanstalk, Google App Engine |
| **SaaS** | Software as a Service | 완성된 소프트웨어 제공 | Gmail, Office 365, Slack |

**비유:** IaaS는 빈 토지(직접 집 지음), PaaS는 건물 뼈대 제공(인테리어만 하면 됨), SaaS는 완성된 호텔 객실(바로 사용)과 같습니다.

### 가상화 (Virtualization)

클라우드의 핵심 기술로, 하나의 물리 서버에서 여러 개의 가상 컴퓨터를 실행합니다.

| 개념 | 설명 |
|------|------|
| **하이퍼바이저(Hypervisor)** | 물리 하드웨어 위에서 가상 머신을 관리하는 소프트웨어 |
| **타입 1 하이퍼바이저(Bare Metal)** | 하드웨어 위에 직접 설치 (예: VMware ESXi, Hyper-V). 성능 우수 |
| **타입 2 하이퍼바이저(Hosted)** | 기존 OS 위에 설치 (예: VMware Workstation, VirtualBox). 설치 간편 |
| **컨테이너(Container)** | OS를 공유하고 프로세스 단위로 격리. 가상 머신보다 가볍고 빠름 (예: Docker) |

## 핵심 정리

- **RISC:** 명령어 수 적고 고정 길이, 1 클럭 실행, 파이프라인 효율적 (ARM, MIPS)
- **CISC:** 명령어 수 많고 가변 길이, 복잡한 명령어 가능 (x86). 현대 x86은 내부에서 마이크로 연산으로 변환
- **캐시 일관성:** 멀티코어에서 각 코어 캐시 내용이 달라지는 문제 → MESI 프로토콜로 해결
- **GPU:** 수천 개의 단순 코어, 대량 병렬 연산에 탁월 (딥러닝, 그래픽)
- **클러스터:** 여러 컴퓨터를 네트워크로 묶어 HPC, 부하 분산, 고가용성 구현
- **클라우드 서비스:** IaaS(인프라), PaaS(플랫폼), SaaS(소프트웨어)
- **하이퍼바이저:** 가상 머신 관리, 타입 1(베어 메탈)/타입 2(호스팅)
- **컨테이너:** OS를 공유하는 경량 격리 단위 (Docker)
