## RISC vs CISC

### CISC (Complex Instruction Set Computer)

**복잡한 명령어 세트**를 가진 프로세서입니다.

- 하나의 명령어로 복잡한 작업을 수행 가능
- 가변 길이 명령어
- 마이크로프로그램 제어 방식
- 메모리 접근 명령어가 풍부
- 예: x86, x86-64 (Intel, AMD)

### RISC (Reduced Instruction Set Computer)

**단순한 명령어 세트**를 가진 프로세서입니다.

- 단순하고 고정 길이 명령어
- 하드와이어드 제어 방식
- 레지스터 기반 연산 (Load-Store 아키텍처)
- 파이프라인 처리 효율적
- 예: ARM, MIPS, RISC-V, Apple M 시리즈

### RISC vs CISC 비교

| 특성 | RISC | CISC |
|------|------|------|
| 명령어 수 | 적음 | 많음 |
| 명령어 길이 | 고정 | 가변 |
| 명령어 복잡도 | 단순 | 복잡 |
| 클럭당 명령어 | 대부분 1클럭 | 다클럭 |
| 레지스터 수 | 많음 | 적음 |
| 메모리 접근 | Load/Store만 | 다양한 방식 |
| 파이프라인 | 용이 | 어려움 |
| 제어 방식 | 하드와이어드 | 마이크로프로그램 |
| 코드 크기 | 큼 | 작음 |
| 예 | ARM, MIPS | x86, x86-64 |

<Callout type="info">
  현대 x86 프로세서(Intel, AMD)는 내부적으로 CISC 명령어를 RISC 형태의 마이크로 연산으로 변환하여 처리합니다. 즉, 외부는 CISC, 내부는 RISC 방식입니다.
</Callout>

## 멀티코어 프로세서

하나의 칩에 **여러 개의 CPU 코어**를 집적한 프로세서입니다.

```
┌──────────────────────────────────────┐
│            멀티코어 프로세서            │
│  ┌───────────┐   ┌───────────┐       │
│  │  코어 0    │   │  코어 1   │       │
│  │ L1캐시(D) │   │ L1캐시(D) │       │
│  │ L1캐시(I) │   │ L1캐시(I) │       │
│  └──────┬────┘   └──────┬────┘       │
│         │              │             │
│      ┌──┴──────────────┴──┐          │
│      │      L2 캐시       │          │
│      └──────────────────┘           │
│      ┌──────────────────────┐        │
│      │      L3 캐시 (공유)   │        │
│      └──────────────────────┘        │
└──────────────────────────────────────┘
```

### 캐시 일관성 (Cache Coherency)

멀티코어에서 각 코어의 L1/L2 캐시가 서로 다른 값을 가질 때 발생하는 문제입니다.

**예시:**
```
코어0: 메모리[100] = 5 (캐시에 저장)
코어1: 메모리[100] = 10으로 수정 (코어0의 캐시는 아직 5)
→ 코어0의 캐시 값이 최신이 아님!
```

**해결 방법:**
- **MESI 프로토콜:** Modified/Exclusive/Shared/Invalid 상태로 캐시 라인을 관리
- **스누핑(Snooping):** 모든 코어가 공유 버스의 캐시 접근을 감시
- **디렉토리 기반:** 중앙 디렉토리에서 캐시 상태 추적

## GPU (Graphics Processing Unit)

원래 그래픽 렌더링을 위해 설계된 SIMD 병렬 프로세서입니다. 현재는 GPGPU(General Purpose GPU)로 범용 병렬 계산에도 활용됩니다.

### CPU vs GPU 비교

| 항목 | CPU | GPU |
|------|-----|-----|
| 코어 수 | 수 ~ 수십 개 | 수천 ~ 수만 개 |
| 코어 성능 | 고성능 단일 코어 | 저성능 코어 多 |
| 최적화 | 복잡한 제어 흐름 | 대규모 병렬 데이터 처리 |
| 캐시 | 대용량 캐시 | 소용량, 스레드 간 공유 |
| 용도 | 일반 목적 | 그래픽, 딥러닝, HPC |

### GPGPU 활용 분야

- 딥러닝(행렬 연산의 병렬화)
- 물리 시뮬레이션
- 암호화폐 채굴
- 과학 계산

## 클러스터와 분산 컴퓨팅

### 클러스터 (Cluster)

여러 독립적인 컴퓨터(노드)를 고속 네트워크로 연결하여 하나의 시스템처럼 동작하게 합니다.

| 종류 | 목적 |
|------|------|
| **HPC 클러스터** | 고성능 계산 (슈퍼컴퓨터 대안) |
| **부하 분산 클러스터** | 웹 서버 부하 분산 |
| **고가용성 클러스터** | 장애 시 자동 전환 (HA) |

### 클라우드 컴퓨팅

인터넷을 통해 가상화된 컴퓨팅 자원을 서비스로 제공합니다.

| 서비스 모델 | 설명 | 예시 |
|-----------|------|------|
| **IaaS** | 인프라(VM, 스토리지) 제공 | AWS EC2, Azure VM |
| **PaaS** | 플랫폼(런타임, DB) 제공 | AWS Elastic Beanstalk |
| **SaaS** | 완성된 소프트웨어 제공 | Gmail, Office365 |

## 가상화 (Virtualization)

물리적 하드웨어 위에 여러 가상 머신(VM)을 실행하는 기술입니다.

- **하이퍼바이저 Type 1 (베어메탈):** 하드웨어 직접 위에서 실행 (VMware ESXi, Hyper-V)
- **하이퍼바이저 Type 2 (호스트형):** 호스트 OS 위에서 실행 (VirtualBox, VMware Workstation)
- **컨테이너 (Docker):** OS 수준 가상화, 더 가볍고 빠름

## 핵심 정리

- RISC: 단순/고정 명령어, 많은 레지스터, 파이프라인 효율적 (ARM, MIPS)
- CISC: 복잡/가변 명령어, 메모리 직접 접근 다양 (x86)
- 멀티코어: 캐시 일관성 문제 → MESI 프로토콜
- GPU: SIMD 병렬, 수천 코어, 딥러닝/그래픽
- 클라우드: IaaS/PaaS/SaaS 서비스 모델
