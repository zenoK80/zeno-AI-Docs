  **이번 문서의 목표:** 명령어의 기본 구조(연산코드+오퍼랜드)를 이해하고, 여러 주소 지정 방식과 명령어 종류를 구분할 수 있게 됩니다.

## 왜 명령어 형식을 알아야 하는가?

06번 문서에서 IR(명령어 레지스터)이 "현재 해독 중인 명령어"를 담는다고 배웠습니다. 그런데 그 명령어는 실제로 어떤 형태(구조)를 하고 있을까요? 이 문서는 명령어 자체의 구성 방식을 다룹니다.

## 명령어(Instruction)의 기본 구조

$$
\text{연산코드(Opcode)} \;|\; \text{오퍼랜드(Operand)}
$$

<Table>
  <thead>
    <tr><th>구성 요소</th><th>역할</th></tr>
  </thead>
  <tbody>
    <tr><td>연산코드(Opcode)</td><td>"무엇을 할지"를 나타냄(더하기, 빼기, 저장 등)</td></tr>
    <tr><td>오퍼랜드(Operand)</td><td>"무엇을 대상으로 할지"를 나타냄(데이터 자체 또는 데이터의 위치)</td></tr>
  </tbody>
</Table>

> **비유:** "3번 서랍의 내용을 5번 서랍에 더하라"는 명령이 있다면, "더하라"가 연산코드, "3번 서랍"과 "5번 서랍"이 오퍼랜드입니다.

## 명령어 형식 — 오퍼랜드 개수에 따른 분류

<Table>
  <thead>
    <tr><th>형식</th><th>구조</th><th>특징</th></tr>
  </thead>
  <tbody>
    <tr><td>0-주소 명령어</td><td>연산코드만 있음</td><td>스택(Stack) 구조에서 사용, 오퍼랜드는 스택의 위·아래 값 사용</td></tr>
    <tr><td>1-주소 명령어</td><td>연산코드+오퍼랜드 1개</td><td>나머지 하나는 06번 문서의 누산기(AC)를 암묵적으로 사용</td></tr>
    <tr><td>2-주소 명령어</td><td>연산코드+오퍼랜드 2개</td><td>일반적인 CPU에서 가장 흔한 형식</td></tr>
    <tr><td>3-주소 명령어</td><td>연산코드+오퍼랜드 3개</td><td>두 값을 연산해 별도의 세 번째 위치에 저장 가능, 명령어 길이가 김</td></tr>
  </tbody>
</Table>

## 주소 지정 방식(Addressing Mode)

> **쉽게 말하면:** 주소 지정 방식은 "오퍼랜드에 적힌 값을 어떻게 해석해서 실제 데이터를 찾을지"에 대한 규칙입니다.

<Table>
  <thead>
    <tr><th>방식</th><th>설명</th></tr>
  </thead>
  <tbody>
    <tr><td>즉시 주소 지정(Immediate)</td><td>오퍼랜드 자체가 데이터 값(주소를 거치지 않음). 가장 빠름</td></tr>
    <tr><td>직접 주소 지정(Direct)</td><td>오퍼랜드가 데이터가 저장된 메모리 주소를 직접 가리킴</td></tr>
    <tr><td>간접 주소 지정(Indirect)</td><td>오퍼랜드가 가리키는 위치에, 실제 데이터의 주소가 또 저장되어 있음(주소를 한 번 더 거침)</td></tr>
    <tr><td>레지스터 주소 지정(Register)</td><td>오퍼랜드가 레지스터 번호를 가리킴(메모리보다 훨씬 빠름)</td></tr>
    <tr><td>레지스터 간접 주소 지정(Register Indirect)</td><td>오퍼랜드가 가리키는 레지스터 안에, 실제 데이터의 메모리 주소가 저장</td></tr>
    <tr><td>변위 주소 지정(Displacement)</td><td>기준 레지스터 값 + 오퍼랜드(변위)를 더해 실제 주소 계산</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** 직접 주소 지정과 간접 주소 지정을 혼동하기 쉽습니다. **직접**은 오퍼랜드가 데이터의 주소를 "한 번" 가리키고, **간접**은 오퍼랜드가 가리키는 곳에 "또 다른 주소"가 들어있어 "두 번" 거쳐야 실제 데이터에 도달합니다. 간접 주소 지정은 메모리 접근을 두 번 해야 해서 직접 방식보다 느립니다.
</Callout>

**계산 예시**(간접 주소 지정): 오퍼랜드가 "주소 100"을 가리키고, 주소 100번지에는 "주소 500"이 저장되어 있으며, 주소 500번지에 실제 데이터 "42"가 있다면?

$$
\text{오퍼랜드}(100) \to \text{주소 100의 내용}(500) \to \text{주소 500의 내용}(42)
$$

실제 데이터를 얻기까지 메모리를 **두 번** 접근해야 합니다.

## 명령어의 종류

<Table>
  <thead>
    <tr><th>종류</th><th>기능</th><th>예시</th></tr>
  </thead>
  <tbody>
    <tr><td>데이터 전송</td><td>레지스터·메모리 간 데이터 이동</td><td>LOAD, STORE, MOVE</td></tr>
    <tr><td>산술·논리 연산</td><td>02번 문서의 게이트 기반 연산 수행</td><td>ADD, SUB, AND, OR</td></tr>
    <tr><td>제어 흐름</td><td>프로그램의 실행 순서 변경</td><td>JUMP, BRANCH, CALL</td></tr>
    <tr><td>입출력</td><td>외부 장치와 데이터 교환</td><td>IN, OUT</td></tr>
  </tbody>
</Table>

**제어 흐름 명령어가 왜 중요한가?** 06번 문서에서 배운 PC(프로그램 카운터)는 보통 다음 명령어로 자동 증가하지만, JUMP나 BRANCH 명령어는 PC 값을 원하는 위치로 강제로 바꿔, 반복문·조건문 같은 프로그램의 흐름 제어를 가능하게 합니다.

## 핵심 정리

- **명령어 구조**: 연산코드(무엇을 할지) + 오퍼랜드(무엇을 대상으로).
- **명령어 형식**: 오퍼랜드 개수에 따라 0~3주소 명령어로 분류.
- **주소 지정 방식**: 즉시(가장 빠름), 직접(주소 한 번), 간접(주소 두 번, 느림), 레지스터(가장 빠른 접근), 레지스터 간접, 변위.
- **명령어 종류**: 데이터 전송, 산술·논리 연산, 제어 흐름(JUMP 등), 입출력.
