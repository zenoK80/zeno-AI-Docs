## 왜 보조기억장치가 필요한가요?

**메인 메모리**(DRAM)는 빠르지만 전원이 꺼지면 내용이 사라지는 **휘발성** 메모리입니다. 또한 용량도 크지 않고 비쌉니다.

**보조기억장치**(Secondary Storage)는 전원을 꺼도 내용이 보존되고, 용량이 크고, 저렴합니다. 대신 메인 메모리보다 속도가 느립니다.

**비유:** 메인 메모리는 책상 위의 메모지(빠르지만 날아감), 보조기억장치는 서랍 속 파일 폴더(느리지만 오래 보존)와 같습니다.

## HDD (Hard Disk Drive, 하드 디스크 드라이브)

**HDD**는 자성 재료를 입힌 원형 플래터(Platter)를 고속으로 회전시키며, 헤드(Head)로 데이터를 읽고 씁니다.

### HDD의 물리적 구조

| 용어 | 설명 |
|------|------|
| **플래터**(Platter) | 데이터를 저장하는 원형 디스크. 자성 재료로 코팅됨 |
| **트랙**(Track) | 플래터의 동심원 형태의 데이터 저장 경로 |
| **섹터**(Sector) | 트랙을 조각낸 최소 저장 단위 (일반적으로 512B 또는 4KB) |
| **실린더**(Cylinder) | 여러 플래터에서 같은 번호의 트랙들의 집합 (수직으로 묶음) |
| **헤드**(Head) | 데이터를 읽고 쓰는 장치. 플래터 표면에 가까이 위치 |
| **암**(Arm) | 헤드를 안쪽/바깥쪽으로 이동시키는 장치 |
| **스핀들**(Spindle) | 플래터를 회전시키는 축 |

**비유:** CD를 생각해보세요. CD 표면의 원형 경로가 트랙이고, 그것을 잘게 나눈 것이 섹터입니다.

### HDD 접근 시간 (Access Time)

HDD에서 데이터를 읽으려면 3단계의 시간이 필요합니다.

$$
\text{접근 시간(Access Time)} = \text{탐색 시간} + \text{회전 지연} + \text{전송 시간}
$$

| 단계 | 용어 | 설명 | 일반적 시간 |
|------|------|------|-----------|
| 1단계 | **탐색 시간**(Seek Time) | 헤드가 원하는 트랙으로 이동하는 시간 | 수 ms ~ 수십 ms |
| 2단계 | **회전 지연**(Rotational Latency) | 원하는 섹터가 헤드 아래로 올 때까지 기다리는 시간. 평균적으로 회전 주기의 1/2 | 약 2~5 ms |
| 3단계 | **전송 시간**(Transfer Time) | 실제 데이터를 읽거나 쓰는 시간 | 매우 짧음 |

**가장 오래 걸리는 단계는 탐색 시간입니다.** 따라서 디스크 스케줄링으로 탐색 시간을 최소화하는 것이 중요합니다.

## 디스크 스케줄링 (Disk Scheduling)

여러 I/O 요청이 동시에 들어올 때, 헤드 이동 거리를 최소화하여 전체 처리 시간을 줄이는 방법입니다.

아래 예시에서 현재 헤드 위치는 **트랙 50**, 요청 대기열: `98, 183, 37, 122, 14, 124, 65, 67` 입니다.

### FCFS (First Come First Served, 선입선처리)

- 요청이 들어온 순서대로 처리합니다.
- 단순하지만 헤드 이동 거리가 클 수 있습니다.

처리 순서: 50 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67

### SSTF (Shortest Seek Time First, 최소 탐색 시간 우선)

- 현재 헤드 위치에서 가장 가까운 트랙의 요청을 먼저 처리합니다.
- 헤드 이동 거리는 줄지만, 멀리 있는 요청이 계속 기다리는 **기아**(Starvation) 문제가 발생할 수 있습니다.

### SCAN (스캔)

- 헤드가 한 방향으로 끝까지 이동하면서 요청을 처리하고, 끝에 도달하면 방향을 반대로 바꿉니다.
- **엘리베이터 알고리즘**(Elevator Algorithm)이라고도 합니다.

**비유:** 엘리베이터가 올라가면서 각 층에서 사람을 태우고, 꼭대기에서 내려오면서 또 태우는 것과 같습니다.

### C-SCAN (Circular SCAN, 순환 스캔)

- SCAN처럼 한 방향으로만 이동하며 처리합니다.
- 끝에 도달하면 반대 방향으로 처리하지 않고 바로 처음(0번 트랙)으로 돌아갑니다.
- 끝에 가까운 트랙과 시작에 가까운 트랙의 대기 시간이 균일해집니다.

### LOOK / C-LOOK

- SCAN/C-SCAN과 같지만, 마지막 요청 트랙까지만 이동하고 끝까지 가지 않습니다.
- **LOOK:** SCAN 개선 버전 (끝까지 안 감)
- **C-LOOK:** C-SCAN 개선 버전 (끝까지 안 감, 순환)

| 알고리즘 | 특징 | 문제점 |
|----------|------|-------|
| FCFS | 순서대로 처리 | 불필요한 이동 많음 |
| SSTF | 가까운 것 먼저 | 기아(Starvation) 가능 |
| SCAN | 왕복 처리 | 양 끝 대기 길어질 수 있음 |
| C-SCAN | 한 방향만 | 균일한 대기 시간 |
| LOOK | SCAN 최적화 | SCAN보다 효율적 |
| C-LOOK | C-SCAN 최적화 | 균일하고 효율적 |

## RAID (Redundant Array of Independent Disks)

**RAID**(레이드)는 여러 개의 하드 디스크를 하나의 논리적 드라이브처럼 묶어 사용하는 기술입니다. 목적은 크게 두 가지입니다.

1. **성능 향상:** 여러 디스크에 병렬로 읽고 써서 속도 향상
2. **안정성 향상:** 디스크가 고장 나도 데이터를 복구할 수 있도록 중복 저장

### 스트라이핑(Striping)과 미러링(Mirroring)

- **스트라이핑(Striping):** 데이터를 여러 디스크에 나누어 씁니다. 속도 향상. 디스크 하나 고장 시 데이터 손실.
- **미러링(Mirroring):** 같은 데이터를 여러 디스크에 똑같이 씁니다. 안정성 향상. 용량 효율 낮음.
- **패리티(Parity):** 오류 검출/복구를 위한 추가 정보를 저장합니다.

### RAID 0 (스트라이핑)

- 여러 디스크에 데이터를 분산 저장 (스트라이핑만)
- 성능 최고, 안정성 없음 (디스크 하나 고장 시 전체 손실)
- 용량: 디스크 수 × 개별 디스크 용량

### RAID 1 (미러링)

- 데이터를 2개 이상의 디스크에 동일하게 복사
- 안정성 최고, 용량 효율 50%
- 쓰기는 미러 수만큼 같이 써야 하므로 느릴 수 있음

### RAID 5 (분산 패리티)

- 데이터와 패리티를 모든 디스크에 분산 저장
- **최소 3개 디스크** 필요
- 디스크 1개 고장 시 패리티로 복구 가능
- 용량 효율: (n-1)/n (n = 디스크 수)
- 성능과 안정성의 균형, 가장 많이 사용

### RAID 6 (이중 분산 패리티)

- RAID 5와 같지만 패리티를 2개 저장
- **최소 4개 디스크** 필요
- 디스크 **2개** 동시 고장 시에도 복구 가능
- 용량 효율: (n-2)/n

### RAID 10 (RAID 1+0, 미러링 + 스트라이핑)

- RAID 1(미러링) 그룹을 RAID 0(스트라이핑)으로 묶음
- **최소 4개 디스크** 필요
- 성능과 안정성 모두 우수
- 용량 효율: 50%

| RAID 레벨 | 방식 | 최소 디스크 | 안정성 | 성능 | 용량 효율 |
|----------|------|-----------|-------|------|---------|
| RAID 0 | 스트라이핑 | 2 | 없음 | 최고 | 100% |
| RAID 1 | 미러링 | 2 | 높음 | 읽기 빠름 | 50% |
| RAID 5 | 분산 패리티 | 3 | 중간 | 중간 | (n-1)/n |
| RAID 6 | 이중 패리티 | 4 | 높음 | RAID 5보다 낮음 | (n-2)/n |
| RAID 10 | 미러링+스트라이핑 | 4 | 높음 | 높음 | 50% |

## 핵심 정리

- **HDD 구조:** 플래터(데이터 저장) → 트랙 → 섹터(최소 단위), 실린더(동일 트랙 집합)
- **접근 시간 = 탐색 시간 + 회전 지연 + 전송 시간** (탐색 시간이 가장 큼)
- **디스크 스케줄링:** FCFS(순서), SSTF(가까운 것 먼저), SCAN(엘리베이터), C-SCAN(순환), LOOK/C-LOOK(개선형)
- **RAID 0:** 속도 최고, 안정성 없음
- **RAID 1:** 미러링, 안정성 높음, 용량 50%
- **RAID 5:** 분산 패리티, 성능-안정성 균형, 가장 보편적
- **RAID 6:** 이중 패리티, 디스크 2개 동시 고장 복구 가능
- **RAID 10:** 미러링 + 스트라이핑, 성능과 안정성 동시 확보
