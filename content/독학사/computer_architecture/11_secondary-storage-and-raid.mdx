## HDD(Hard Disk Drive)의 구조

### 물리적 구조

```
┌─────────────────────────────────────┐
│                HDD                  │
│  ┌──────────────────────────────┐   │
│  │          플래터(Platter)       │   │
│  │                              │   │
│  │    ──────────────────────    │   │
│  │          트랙(Track)         │   │
│  │    ──────────────────────    │   │
│  │                              │   │
│  └──────────────────────────────┘   │
│                ↑                    │
│           ┌───┴───┐                 │
│           │헤드/암  │                 │
└─────────────────────────────────────┘
```

| 구성 요소 | 설명 |
|---------|------|
| **플래터(Platter)** | 데이터가 저장되는 자성 원판, 여러 장 |
| **트랙(Track)** | 플래터 위의 동심원, 각 동심원이 하나의 트랙 |
| **섹터(Sector)** | 트랙을 일정 크기로 분할한 최소 저장 단위 (일반적으로 512B 또는 4KB) |
| **실린더(Cylinder)** | 여러 플래터에서 같은 트랙 번호의 집합 |
| **헤드(Head)** | 데이터를 읽고 쓰는 장치, 플래터당 2개(위/아래) |

### 디스크 접근 시간

$$
T_{access} = T_{seek} + T_{rotation} + T_{transfer}
$$

| 구성 요소 | 설명 |
|---------|------|
| **탐색 시간(Seek Time)** | 헤드를 원하는 트랙으로 이동하는 시간 (가장 오래 걸림) |
| **회전 대기 시간(Rotational Latency)** | 원하는 섹터가 헤드 아래 올 때까지 기다리는 시간 (평균 = 반바퀴) |
| **전송 시간(Transfer Time)** | 실제 데이터를 읽거나 쓰는 시간 |

## 디스크 스케줄링

여러 I/O 요청을 효율적으로 처리하는 순서를 결정합니다.

<Callout type="warning">
  독학사 시험에서 디스크 스케줄링 알고리즘별 헤드 이동 거리 계산 문제가 출제됩니다.
</Callout>

### FCFS (First Come, First Served)

도착 순서대로 처리합니다. 구현 단순하지만 헤드 이동 거리가 길 수 있습니다.

**요청: 98, 183, 37, 122, 14, 124, 65, 67 (현재 헤드: 53)**

```
53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
이동 거리 = 45+85+146+85+108+110+59+2 = 640 실린더
```

### SSTF (Shortest Seek Time First)

현재 헤드 위치에서 가장 가까운 요청을 먼저 처리합니다.

- 장점: 평균 탐색 시간 단축
- 단점: **기아 현상(Starvation)** 발생 가능 (멀리 있는 요청이 계속 지연)

### SCAN (엘리베이터 알고리즘)

헤드가 한 방향으로 이동하면서 요청을 처리하고, 끝에 도달하면 반대 방향으로 이동합니다.

```
시작 53, 방향: 증가
53 → 65 → 67 → 98 → 122 → 124 → 183 → (끝) → 37 → 14
이동 거리 = (183-53) + (183-14) = 130 + 169 = 299
```

### C-SCAN (Circular SCAN)

SCAN과 유사하지만 한 방향으로만 요청을 처리하고, 끝에 도달하면 처음 위치(또는 첫 요청)로 이동합니다. 더 균일한 대기 시간을 제공합니다.

### LOOK / C-LOOK

SCAN/C-SCAN과 동일하지만 **실제 끝(track 0 또는 최대)까지 가지 않고** 마지막 요청 위치에서 방향을 바꿉니다.

| 알고리즘 | 특징 |
|---------|------|
| FCFS | 순서 공평, 헤드 이동 비효율 |
| SSTF | 최단 탐색, 기아 발생 가능 |
| SCAN | 엘리베이터, 균등하지 않은 대기 |
| C-SCAN | 단방향 순환, 균등한 대기 |
| LOOK/C-LOOK | SCAN/C-SCAN 최적화 |

## RAID (Redundant Array of Independent Disks)

여러 디스크를 묶어 성능 향상 또는 안정성(중복성)을 높이는 기술입니다.

### RAID 0 (스트라이핑, Striping)

데이터를 여러 디스크에 분산 저장합니다.

```
디스크1: A1  A3  A5
디스크2: A2  A4  A6
```

- 장점: 읽기/쓰기 속도 향상 (n배)
- 단점: 안정성 없음 (하나의 디스크 고장 시 모든 데이터 손실)
- 용도: 성능 우선, 임시 데이터

### RAID 1 (미러링, Mirroring)

동일한 데이터를 두 디스크에 복제합니다.

```
디스크1: A1  A2  A3
디스크2: A1  A2  A3 (동일 복사본)
```

- 장점: 안정성 최고 (하나 고장해도 데이터 보존)
- 단점: 용량 효율 50% (2배의 디스크 필요)
- 용도: 안정성 우선

### RAID 5 (분산 패리티, Distributed Parity)

데이터와 패리티를 모든 디스크에 분산합니다. 최소 3개의 디스크가 필요합니다.

```
디스크1: A1  B1  C1  P3
디스크2: A2  B2  P2  C2
디스크3: A3  P1  B3  C3
(P = 패리티)
```

- 장점: RAID 0보다 안전, RAID 1보다 효율적
- 단점: 하나의 디스크 고장만 허용
- 용도: 가장 일반적으로 사용

### RAID 6 (이중 패리티)

RAID 5의 확장으로 두 개의 패리티 블록을 사용합니다.

- 장점: **두 개의 디스크 동시 고장**도 복구 가능
- 단점: 최소 4개 디스크 필요, 쓰기 성능 저하
- 용도: 높은 안정성 요구 환경

### RAID 10 (RAID 1+0)

RAID 1(미러링)과 RAID 0(스트라이핑)을 결합합니다.

- 장점: 안정성과 속도 모두 확보
- 단점: 최소 4개 디스크, 용량 효율 50%
- 용도: 데이터베이스 서버

### RAID 레벨 비교

| RAID | 최소 디스크 수 | 속도 | 안정성 | 용량 효율 |
|------|------------|------|--------|---------|
| 0 | 2 | 빠름 | 낮음 | 100% |
| 1 | 2 | 읽기 빠름 | 높음 | 50% |
| 5 | 3 | 보통 | 1개 고장 허용 | (n-1)/n |
| 6 | 4 | 쓰기 느림 | 2개 고장 허용 | (n-2)/n |
| 10 | 4 | 빠름 | 높음 | 50% |

## 광학 디스크

| 종류 | 특징 |
|------|------|
| CD (650MB) | 읽기 전용, 음악/소프트웨어 배포 |
| DVD (4.7~17GB) | 고용량 영상 |
| Blu-ray (25GB~) | 고화질 영상 |
| CD-R/RW | 사용자 기록 가능 |

## 핵심 정리

- HDD 접근 시간 = 탐색 시간 + 회전 대기 시간 + 전송 시간 (탐색 시간이 가장 큼)
- SSTF: 최단 탐색 우선, 기아 발생 / SCAN: 엘리베이터 알고리즘
- RAID 0: 속도 향상(안정성 없음) / RAID 1: 미러링(50% 효율) / RAID 5: 분산 패리티(1개 고장 허용)
