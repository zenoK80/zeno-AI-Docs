## 왜 병렬 처리가 필요한가요?

단일 CPU의 클럭 속도는 물리적 한계(열, 전력 소비)로 인해 무작정 올릴 수 없습니다. 2000년대 초반까지는 클럭 속도를 높이는 방식으로 성능을 향상했지만, 이후에는 **여러 처리 장치를 동시에 활용하는 병렬 처리(Parallel Processing)**로 방향이 바뀌었습니다.

**비유:** 요리사 한 명이 아무리 빨라도 한계가 있으므로, 여러 요리사가 동시에 다른 요리를 만드는 것입니다.

---

## 병렬 처리 수준

병렬 처리는 얼마나 작은 단위를 동시에 처리하느냐에 따라 수준이 나뉩니다.

| 수준 | 설명 | 예시 |
|------|------|------|
| **비트 수준(Bit-level)** | 더 넓은 데이터 버스로 한 번에 처리하는 비트 수 증가 | 8비트 → 32비트 → 64비트 CPU |
| **명령어 수준(Instruction-level)** | 파이프라인, 슈퍼스칼라 등으로 여러 명령어 동시 처리 | 파이프라인, Out-of-Order 실행 |
| **태스크 수준(Task-level)** | 서로 다른 작업을 동시에 처리 | 멀티스레딩, 멀티태스킹 |
| **프로세서 수준(Processor-level)** | 여러 CPU/코어가 동시에 작업 | 멀티코어, 멀티프로세서 |

## 플린의 분류법 (Flynn's Taxonomy)

**마이클 플린(Michael Flynn)**이 1966년에 제안한 컴퓨터 시스템 분류법으로, 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 수에 따라 4가지로 분류합니다.

- **스트림(Stream):** 한 번에 처리할 수 있는 데이터 또는 명령어의 흐름

### SISD (Single Instruction, Single Data)

- **단일 명령어, 단일 데이터**
- 전통적인 폰 노이만 구조. 하나의 CPU가 하나의 데이터 흐름을 처리
- 예: 일반 단일 코어 CPU

```
명령어 스트림: ──────────────→
데이터 스트림: ──────────────→
처리 유닛: [CPU]
```

### SIMD (Single Instruction, Multiple Data)

- **단일 명령어, 복수 데이터**
- 하나의 명령어로 여러 데이터를 동시에 처리
- 예: GPU, 벡터 프로세서, CPU의 SSE/AVX 명령어

```
명령어 스트림: ────────────────────→
데이터 스트림1: ──────────────────→  동일 명령어로
데이터 스트림2: ──────────────────→  여러 데이터 처리
데이터 스트림3: ──────────────────→
```

**비유:** 같은 동작(명령어)으로 여러 색의 물감(데이터)을 동시에 칠하는 것입니다. 이미지 처리, 물리 시뮬레이션 등에 효과적입니다.

### MISD (Multiple Instruction, Single Data)

- **복수 명령어, 단일 데이터**
- 여러 처리 장치가 같은 데이터에 서로 다른 명령을 적용
- 실용적 구현이 거의 없음 (이론적 분류)
- 예: 내고장성(Fault Tolerance) 시스템 (결과 비교를 위해 같은 데이터를 여러 방법으로 처리)

### MIMD (Multiple Instruction, Multiple Data)

- **복수 명령어, 복수 데이터**
- 여러 프로세서가 각자의 명령어와 데이터를 독립적으로 처리
- 가장 일반적인 병렬 컴퓨터 구조
- 예: 멀티코어 프로세서, 클러스터 컴퓨터

| 분류 | 명령어 스트림 | 데이터 스트림 | 예시 |
|------|------------|------------|------|
| SISD | 1개 | 1개 | 단일 코어 CPU |
| SIMD | 1개 | 여러 개 | GPU, 벡터 프로세서 |
| MISD | 여러 개 | 1개 | 내고장성 시스템 |
| MIMD | 여러 개 | 여러 개 | 멀티코어, 클러스터 |

## 공유 메모리 vs 분산 메모리

여러 프로세서가 메모리를 어떻게 공유하느냐에 따라 구조가 나뉩니다.

### 공유 메모리 시스템 (Shared Memory System)

- 모든 프로세서가 **하나의 메모리 공간**을 공유합니다.
- 프로세서들이 메모리를 통해 데이터를 주고받습니다.
- 프로그래밍이 쉽지만, 메모리 접근 경쟁이 발생할 수 있습니다.

**UMA (Uniform Memory Access, 균일 메모리 접근):** 모든 프로세서가 메모리에 동일한 속도로 접근합니다.

**NUMA (Non-Uniform Memory Access, 비균일 메모리 접근):** 프로세서마다 가까운 메모리 영역이 있어, 가까운 메모리는 빠르고 먼 메모리는 느립니다.

### 분산 메모리 시스템 (Distributed Memory System)

- 각 프로세서가 **자신만의 로컬 메모리**를 가집니다.
- 프로세서들이 **메시지 전달(Message Passing)**로 통신합니다.
- 확장성이 높지만 프로그래밍이 복잡합니다.
- 예: 컴퓨터 클러스터, 슈퍼컴퓨터

## 암달의 법칙 (Amdahl's Law)

**진 암달(Gene Amdahl)**이 제안한 법칙으로, 프로그램에 병렬화할 수 없는 순차적 부분이 있을 때 프로세서 수를 늘려도 얻을 수 있는 최대 성능 향상은 제한된다는 법칙입니다.

$$
S = \frac{1}{(1-P) + \frac{P}{N}}
$$

- $S$: 전체 성능 향상(Speedup)
- $P$: 병렬화 가능한 코드 비율 (0 ~ 1)
- $N$: 프로세서 수

**예시:** 프로그램의 80%는 병렬 가능하고, 20%는 순차 실행만 가능할 때 ($P = 0.8$)

- $N=2$: $S = 1 / (0.2 + 0.8/2) = 1 / 0.6 = 1.67$배
- $N=4$: $S = 1 / (0.2 + 0.8/4) = 1 / 0.4 = 2.5$배
- $N=\infty$: $S = 1 / (0.2 + 0) = 5$배 (최대 한계!)

**핵심:** 아무리 프로세서를 많이 추가해도, 순차 실행 부분(1-P)이 성능 향상의 상한선을 결정합니다.

**쉽게 말하면:** 팀 프로젝트에서 9명이 할 수 있는 부분은 아무리 인원을 늘려도 나머지 혼자 해야 하는 1명 분의 작업 때문에 전체 단축에 한계가 있습니다.

## 슈퍼스칼라와 비순차 실행

### 슈퍼스칼라 (Superscalar)

여러 실행 파이프라인을 갖추어 클럭당 여러 명령어를 동시에 실행합니다.

### 비순차 실행 (Out-of-Order Execution, OoOE)

명령어의 프로그램 순서를 지키되, **서로 의존성이 없는 명령어는 순서를 바꿔서 먼저 실행**합니다. 데이터가 준비된 명령어를 먼저 실행하여 파이프라인 지연(Stall)을 줄입니다.

### VLIW (Very Long Instruction Word, 초장명령어)

- 여러 연산을 하나의 긴 명령어로 묶어서 발행합니다.
- 컴파일러가 병렬 실행 가능한 명령어를 찾아 묶습니다.
- 하드웨어가 단순해지는 대신 컴파일러 최적화가 중요합니다.

## 핵심 정리

- **병렬 처리:** 여러 처리 장치가 동시에 작업하여 성능 향상
- **SISD:** 단일 CPU (일반 PC)
- **SIMD:** 하나의 명령어로 여러 데이터 동시 처리 (GPU, 벡터)
- **MISD:** 복수 명령어, 단일 데이터 (실용 예 거의 없음)
- **MIMD:** 복수 명령어, 복수 데이터 (멀티코어, 클러스터)
- **UMA:** 모든 프로세서가 메모리에 동일 속도 접근
- **NUMA:** 가까운 메모리는 빠르고 먼 메모리는 느림
- **암달의 법칙:** $S = 1/((1-P) + P/N)$, 순차 부분이 최대 성능 향상을 제한
- **슈퍼스칼라:** 여러 파이프라인으로 IPC 향상
- **OoOE:** 의존성 없는 명령어를 순서 바꿔 실행, 파이프라인 활용 극대화
