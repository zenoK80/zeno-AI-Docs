## 병렬 처리의 개념

**병렬 처리(Parallel Processing)**는 여러 작업을 동시에 수행하여 전체 처리 시간을 단축하는 기법입니다.

### 병렬화의 종류

| 수준 | 예시 |
|------|------|
| **비트 수준** | 32비트 → 64비트 (넓은 데이터 경로) |
| **명령어 수준** | 파이프라인, 슈퍼스칼라 |
| **태스크 수준** | 멀티스레딩 |
| **프로세서 수준** | 멀티코어, 멀티프로세서 |

## Flynn의 분류법

명령어 흐름(Instruction Stream)과 데이터 흐름(Data Stream)의 수에 따라 컴퓨터를 분류합니다.

### SISD (Single Instruction, Single Data)

단일 명령어 흐름, 단일 데이터 흐름. **기존 폰 노이만 컴퓨터**의 순차 처리 방식입니다.

```
명령어: I1 → I2 → I3 → ...
데이터: D1 → D2 → D3 → ...
```

### SIMD (Single Instruction, Multiple Data)

**하나의 명령어**로 **여러 데이터**를 동시에 처리합니다.

```
명령어: ADD (하나의 명령)
데이터: [D1, D2, D3, D4] → 동시에 모두 ADD 연산
```

- 예시: GPU, 벡터 프로세서, CPU의 SIMD 명령어(SSE, AVX)
- 용도: 멀티미디어 처리, 과학 계산, 딥러닝

### MISD (Multiple Instruction, Single Data)

여러 명령어가 **같은 데이터**에 적용됩니다. 실용적 구현이 거의 없습니다.

- 예시: 파이프라인(느슨하게 해당), 결함 허용 시스템

### MIMD (Multiple Instruction, Multiple Data)

여러 프로세서가 **각기 다른 명령어**로 **각기 다른 데이터**를 처리합니다.

```
프로세서1: I1 + D1
프로세서2: I2 + D2
프로세서3: I3 + D3
(모두 독립적으로 동시 실행)
```

- 예시: 멀티코어 CPU, 클러스터, 분산 시스템
- 가장 일반적인 병렬 컴퓨팅 방식

| 분류 | 명령어 수 | 데이터 수 | 예시 |
|------|---------|---------|------|
| SISD | 1 | 1 | 기존 PC |
| SIMD | 1 | 多 | GPU, 벡터 프로세서 |
| MISD | 多 | 1 | 결함 허용 시스템 |
| MIMD | 多 | 多 | 멀티코어, 클러스터 |

## 벡터 처리 (Vector Processing)

배열(벡터) 데이터를 단일 명령으로 한 번에 처리합니다.

```
스칼라 처리: A[0]+B[0], A[1]+B[1], ..., A[n]+B[n] (반복문)
벡터 처리:  A[0..n] + B[0..n] (단일 벡터 명령)
```

**벡터 레지스터**에 여러 원소를 저장하고 벡터 ALU로 동시 처리합니다.

## 멀티프로세서 시스템

### 공유 메모리 방식 (Shared Memory)

여러 프로세서가 **공통 메모리**에 접근합니다.

```
프로세서1 ─┐
프로세서2 ─┼─ 공유 메모리
프로세서3 ─┘
```

- 장점: 프로세서 간 통신 용이 (메모리 통해)
- 단점: 메모리 접근 경합, 확장성 한계
- 예시: SMP (Symmetric MultiProcessing)

### 분산 메모리 방식 (Distributed Memory)

각 프로세서가 **독립적인 메모리**를 가지며, 메시지 패싱으로 통신합니다.

```
[프로세서1+메모리1] ─ 네트워크 ─ [프로세서2+메모리2]
```

- 장점: 높은 확장성
- 단점: 통신 오버헤드, 프로그래밍 복잡
- 예시: 클러스터, MPI

### UMA vs NUMA

| 방식 | 설명 | 특징 |
|------|------|------|
| **UMA (Uniform Memory Access)** | 모든 프로세서가 동일한 접근 시간으로 메모리 사용 | 구현 단순, 확장성 한계 |
| **NUMA (Non-Uniform Memory Access)** | 프로세서마다 로컬 메모리, 원격 메모리는 더 느림 | 확장성 좋음, 복잡함 |

## 암달의 법칙 (Amdahl's Law)

병렬화로 얻을 수 있는 최대 성능 향상을 제한하는 법칙입니다.

$$
S = \frac{1}{(1-P) + \frac{P}{N}}
$$

- $S$: 속도 향상(Speedup)
- $P$: 병렬화 가능한 부분의 비율
- $N$: 프로세서 수

**예시:** 프로그램의 80%가 병렬화 가능하고 프로세서가 4개이면

$$
S = \frac{1}{(1-0.8) + \frac{0.8}{4}} = \frac{1}{0.2 + 0.2} = \frac{1}{0.4} = 2.5배
$$

<Callout type="info">
  암달의 법칙: 프로그램의 일부가 반드시 순차적으로 실행되어야 한다면, 아무리 많은 프로세서를 추가해도 속도 향상에는 한계가 있습니다.
</Callout>

## CPU 명령어 수준 병렬성

### 슈퍼스칼라 (Superscalar)

여러 파이프라인을 병렬로 운영하여 클럭당 여러 명령어를 처리합니다.

### 비순서 실행 (Out-of-Order Execution)

데이터 의존성이 없는 명령어를 프로그램 순서와 다르게 실행하여 파이프라인 효율을 높입니다.

### VLIW (Very Long Instruction Word)

컴파일러가 병렬 실행 가능한 명령어들을 하나의 긴 명령어 단어로 묶어 하드웨어에 전달합니다.

## 핵심 정리

- Flynn 분류: SISD(기존PC), SIMD(GPU/벡터), MISD(거의 없음), MIMD(멀티코어/클러스터)
- 벡터 처리: 배열 데이터를 단일 명령으로 병렬 처리
- 공유 메모리: 쉬운 통신, 확장성 한계 / 분산 메모리: 확장성, 통신 복잡
- 암달의 법칙: 순차 부분이 있으면 병렬화 효과에 한계가 있음
