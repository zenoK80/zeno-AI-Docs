## 명령어(Instruction)란?

### 왜 명령어 구조를 배우나요?

CPU가 어떤 작업을 할지 지시하는 것이 **명령어**(Instruction)입니다. 명령어가 어떻게 구성되고 어떻게 데이터를 참조하는지 이해하면, CPU 설계의 핵심 원리와 RISC·CISC의 차이를 이해할 수 있습니다.

**명령어(Instruction):** CPU가 수행할 동작을 나타내는 이진 비트 패턴입니다. 메모리에 저장되어 있다가 CPU가 읽어 실행합니다.

---

## 명령어의 구조

명령어는 크게 두 부분으로 나뉩니다:

```
┌──────────────────┬──────────────────────────────┐
│   연산코드(OP)    │        오퍼랜드(Operand)       │
│  (무엇을 할지)    │  (어디서/무엇을 가져올지)       │
└──────────────────┴──────────────────────────────┘
```

### 연산코드 (Operation Code, OP Code)

**수행할 연산의 종류**를 지정하는 비트 필드입니다.

**공식:** n비트 연산코드 → 최대 2의 n승 가지 명령어 표현 가능
- 예: 4비트 연산코드 → 최대 2의 4승 = 16가지 명령어

### 오퍼랜드 (Operand)

연산에 필요한 **데이터 자체** 또는 **데이터가 있는 주소**입니다.

오퍼랜드 수에 따른 명령어 종류:

| 오퍼랜드 수 | 명칭 | 특징 | 예시 |
|-----------|------|------|------|
| 0개 | 0-주소 명령어 | 스택으로만 연산 | PUSH, POP (스택 기반 컴퓨터) |
| 1개 | 1-주소 명령어 | 누산기(AC)와 오퍼랜드 연산 | ADD 200 (AC = AC + Memory[200]) |
| 2개 | 2-주소 명령어 | 목적지와 소스 지정 (가장 일반적) | ADD R1, R2 (R1 = R1 + R2) |
| 3개 | 3-주소 명령어 | 결과, 소스1, 소스2 따로 지정 | ADD R1, R2, R3 (R1 = R2 + R3) |

## 주소 지정 방식 (Addressing Mode)

### 왜 다양한 주소 지정 방식이 필요한가요?

명령어에 직접 메모리 주소를 넣으면 비트 수가 부족합니다. 예를 들어 32비트 전체 주소를 명령어 안에 넣으면 명령어 길이가 너무 길어집니다. 다양한 주소 지정 방식으로 적은 비트로 넓은 메모리에 유연하게 접근할 수 있습니다.

**주소 지정 방식(Addressing Mode):** 명령어의 오퍼랜드 필드를 이용하여 실제 데이터의 위치(유효 주소)를 결정하는 방법입니다.

---

### 1. 즉시 주소 지정 (Immediate Addressing)

**정의:** 오퍼랜드 필드에 실제 **데이터 값 자체**가 들어있습니다.

```
ADD  #5    ; 누산기에 값 5를 더함 (#는 즉시값 표시)
```

**비유:** 친구에게 "사과 3개 사와"라고 할 때 숫자 3을 직접 말하는 것입니다.

- 장점: 메모리 접근 0회 → **가장 빠름**
- 단점: 저장할 수 있는 데이터 크기가 명령어 필드 크기로 제한됨

---

### 2. 직접 주소 지정 (Direct Addressing)

**정의:** 오퍼랜드 필드에 **실제 메모리 주소**가 들어있습니다.

```
LOAD  200    ; 메모리 200번지의 값을 읽음
```

**비유:** "서랍 3번에서 서류를 꺼내와"처럼 직접 위치를 알려주는 것입니다.

- 장점: 메모리 1번 접근으로 데이터 획득
- 단점: 접근 가능한 주소 공간이 명령어 비트 수에 제한됨

---

### 3. 간접 주소 지정 (Indirect Addressing)

**정의:** 오퍼랜드 필드에 **실제 주소를 가리키는 주소**(포인터)가 들어있습니다. 주소의 주소입니다.

```
LOAD  @200    ; 200번지에 저장된 주소로 가서 그 주소의 데이터를 읽음
```

**비유:** "3번 서랍에 있는 메모(그 메모에 실제 서랍 번호가 적혀 있음)를 보고 그 서랍을 열어"처럼 두 단계를 거칩니다.

- 장점: 더 넓은 주소 공간에 접근 가능
- 단점: 메모리를 **2번** 참조해야 함 → 느림

---

### 4. 레지스터 주소 지정 (Register Addressing)

**정의:** 오퍼랜드 필드에 **레지스터 번호**가 들어있습니다. 데이터가 레지스터에 있습니다.

```
LOAD  R1    ; 레지스터 R1의 값을 사용
```

**비유:** 손에 들고 있는 것을 바로 사용하는 것처럼, 메모리에 가지 않고 CPU 안에서 바로 처리합니다.

- 장점: 메모리 접근 0회 → 빠름
- 단점: 레지스터 수가 매우 적어 저장 공간 한계

---

### 5. 레지스터 간접 주소 지정 (Register Indirect Addressing)

**정의:** 오퍼랜드 필드에 **레지스터 번호**가 있고, 그 레지스터가 실제 데이터의 **메모리 주소**를 저장하고 있습니다.

```
LOAD  (R1)    ; R1에 저장된 주소의 메모리 값을 읽음
```

- 장점: 레지스터로 전체 메모리 주소 공간에 접근 가능
- 단점: 메모리를 1번 참조해야 함

---

### 6. 변위(Displacement) 주소 지정

**정의:** 기준 주소에 변위(offset)를 더해서 실제 주소를 계산합니다.

**유효 주소 = 기준 주소 + 변위**

| 종류 | 기준 주소 | 특징 |
|------|---------|------|
| **상대 주소 지정 **(Relative) | PC(프로그램 카운터) | 현재 위치로부터 상대적 이동. 프로그램 재배치에 유리 |
| **베이스 레지스터 주소 지정** | 베이스 레지스터(BR) | 프로그램 시작 주소 + 상대적 위치. 메모리 보호에 사용 |
| **인덱스 주소 지정** | 인덱스 레지스터(IX) | 배열 원소 접근에 주로 사용 |

```
JMP  +10    ; 현재 PC에서 10칸 앞으로 점프 (상대 주소)
```

---

## 주소 지정 방식 비교표

| 방식 | 메모리 접근 수 | 속도 | 특징 |
|------|-------------|------|------|
| 즉시 주소 지정 | 0 | 가장 빠름 | 데이터가 명령어 안에 직접 포함 |
| 레지스터 주소 지정 | 0 | 빠름 | 레지스터에서 직접 읽음 |
| 직접 주소 지정 | 1 | 보통 | 메모리 주소로 직접 접근 |
| 레지스터 간접 | 1 | 보통 | 레지스터의 주소로 접근 |
| 간접 주소 지정 | 2 | 느림 | 주소의 주소로 접근 (2단계) |
| 변위 주소 지정 | 1 | 보통 | 기준 + 변위로 계산 |

---

## RISC vs CISC와 명령어 설계

- **CISC(Complex Instruction Set Computer):** 가변 길이 명령어, 다양한 주소 지정 방식 지원. 명령어 해석이 복잡. 예: x86
- **RISC(Reduced Instruction Set Computer):** 고정 길이 명령어, 단순한 주소 지정 방식만 지원. 파이프라인 처리에 유리. 예: ARM, MIPS

---

## 핵심 정리

- **명령어 = 연산코드(OP code) + 오퍼랜드 **(0~3개)
- **즉시:** 데이터 직접 포함, 메모리 접근 0회, 가장 빠름
- **직접:** 메모리 주소 포함, 1회 접근
- **간접:** 주소의 주소, 2회 접근, 가장 느림
- **레지스터:** 레지스터 번호 포함, 메모리 접근 없음, 빠름
- **상대 주소:** PC + 변위, 프로그램 재배치에 유리
