## 명령어의 구조

**명령어(Instruction)**는 CPU가 수행할 동작을 지정하는 비트 패턴입니다.

```
┌──────────────────┬──────────────────────────────┐
│   연산코드(OP)    │        오퍼랜드(Operand)       │
│  (Operation Code)│  (주소 또는 데이터)             │
└──────────────────┴──────────────────────────────┘
```

### 연산코드 (Operation Code, OP code)

수행할 연산을 나타내는 비트 필드입니다.
- n비트 연산코드 → 최대 2^n개의 명령어 표현 가능
- 예: 4비트 OP code → 최대 16개 명령어

### 오퍼랜드 (Operand)

연산에 필요한 데이터 또는 데이터가 있는 주소입니다.

| 오퍼랜드 수 | 명칭 | 예시 |
|-----------|------|------|
| 0 | 0-주소 명령어 | 스택 기반 (PUSH, POP) |
| 1 | 1-주소 명령어 | AC 누산기 기반 |
| 2 | 2-주소 명령어 | 목적지, 소스 (가장 일반적) |
| 3 | 3-주소 명령어 | 결과, 소스1, 소스2 |

### 주소 지정 방식이 중요한 이유

명령어에 직접 주소를 넣으면 비트 수 부족 문제가 생깁니다. 다양한 주소 지정 방식으로 적은 비트로 넓은 메모리에 접근할 수 있습니다.

## 주소 지정 방식 (Addressing Mode)

### 1. 즉시 주소 지정 (Immediate Addressing)

오퍼랜드 필드에 **실제 데이터**가 직접 들어있는 방식입니다.

```
ADD  #5    ; 누산기에 5를 더함 (#는 즉시값 표시)
```

- 장점: 메모리 참조 없음 → 빠름
- 단점: 오퍼랜드 크기가 제한됨

### 2. 직접 주소 지정 (Direct Addressing)

오퍼랜드 필드에 **실제 메모리 주소**가 있는 방식입니다.

```
LOAD  200    ; 메모리 200번지의 값을 읽음
```

- 장점: 한 번의 메모리 접근으로 데이터 획득
- 단점: 주소 공간이 명령어 비트 수로 제한됨

### 3. 간접 주소 지정 (Indirect Addressing)

오퍼랜드가 **실제 주소를 가리키는 주소(포인터)**인 방식입니다.

```
LOAD  @200    ; 메모리 200번지에 저장된 주소의 값을 읽음
```

- 장점: 더 넓은 주소 공간 접근 가능
- 단점: 메모리를 **두 번** 참조해야 함 → 느림

### 4. 레지스터 주소 지정 (Register Addressing)

오퍼랜드가 **레지스터 번호**인 방식입니다.

```
LOAD  R1    ; 레지스터 R1의 값을 사용
```

- 장점: 메모리 참조 없음 → 매우 빠름
- 단점: 레지스터 수가 적어 저장 공간 제한

### 5. 레지스터 간접 주소 지정 (Register Indirect Addressing)

오퍼랜드가 **레지스터에 저장된 메모리 주소**인 방식입니다.

```
LOAD  (R1)    ; R1에 저장된 주소의 메모리 값을 읽음
```

- 장점: 레지스터로 넓은 주소 공간 접근 가능
- 단점: 메모리를 한 번 참조해야 함

### 6. 변위(Displacement) 주소 지정

**기준 주소 + 변위**로 실제 주소를 계산합니다.

| 종류 | 기준 | 실제 주소 |
|------|------|---------|
| **상대 주소 지정** | PC (Program Counter) | PC + 변위 |
| **베이스 레지스터 주소 지정** | 베이스 레지스터(BR) | BR + 변위 |
| **인덱스 주소 지정** | 인덱스 레지스터(IX) | IX + 변위 |

```
JMP  +10    ; 현재 PC에서 10 앞의 주소로 점프 (상대 주소)
LOAD  BR+5  ; 베이스 주소에 5를 더한 주소의 값 읽기
```

상대 주소 지정은 프로그램 재배치(Relocation)에 유리합니다.

## 주소 지정 방식 비교

| 방식 | 메모리 접근 수 | 속도 | 특징 |
|------|-------------|------|------|
| 즉시 | 0 | 가장 빠름 | 데이터 크기 제한 |
| 레지스터 | 0 | 빠름 | 레지스터 수 제한 |
| 직접 | 1 | 보통 | 주소 공간 제한 |
| 레지스터 간접 | 1 | 보통 | 넓은 주소 접근 |
| 간접 | 2 | 느림 | 가장 넓은 주소 접근 |
| 변위 | 1 | 보통 | 유연한 주소 계산 |

## 명령어 형식의 설계 트레이드오프

- **더 많은 오퍼랜드** → 더 짧은 프로그램, 더 긴 명령어
- **더 많은 OP code 비트** → 더 많은 명령어 종류, 오퍼랜드 비트 줄어듦
- **가변 길이 명령어** (CISC): 유연하지만 디코딩 복잡
- **고정 길이 명령어** (RISC): 단순 빠른 디코딩

## 핵심 정리

- 명령어 = 연산코드(OP) + 오퍼랜드 (0~3개)
- 즉시: 데이터 직접 포함(빠름), 직접: 메모리 주소 포함(1회 접근)
- 간접: 주소의 주소(2회 접근, 느림), 레지스터: 레지스터 번호(빠름)
- 상대 주소: PC + 변위 → 프로그램 재배치에 유리
