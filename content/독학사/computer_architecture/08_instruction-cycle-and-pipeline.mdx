## 명령어 사이클

CPU가 하나의 명령어를 처리하는 과정을 **명령어 사이클(Instruction Cycle)**이라 합니다.

### 기본 사이클 단계

```
인출(Fetch) → 해독(Decode) → 실행(Execute) → 저장(Write Back)
     ↑___________________________________________________↓
```

| 단계 | 동작 | 관련 레지스터 |
|------|------|------------|
| **인출 (Fetch)** | PC가 가리키는 주소에서 명령어를 IR로 가져옴 | PC, MAR, MBR, IR |
| **해독 (Decode)** | 제어장치가 IR의 연산코드를 해석 | IR |
| **실행 (Execute)** | ALU 연산 또는 제어 명령 수행 | ALU, AC |
| **저장 (Write Back)** | 결과를 레지스터 또는 메모리에 저장 | AC, MAR, MBR |

### 간접 사이클 (Indirect Cycle)

간접 주소 지정 방식일 때 추가되는 사이클입니다.
- 인출 → **간접** → 실행 → 저장
- 간접 단계에서 유효 주소를 구하기 위해 메모리를 추가 접근합니다.

### 인터럽트 사이클 (Interrupt Cycle)

인터럽트 발생 시 실행 사이클 후에 추가됩니다.
- 현재 PC 저장, 인터럽트 서비스 루틴(ISR)으로 점프

## 파이프라인 (Pipeline)

**파이프라인**은 명령어 실행을 여러 단계로 나눠 동시에 여러 명령어를 처리하는 기법입니다. 공장의 조립 라인과 유사합니다.

### 파이프라인 없는 순차 실행 (4단계 가정)

```
명령1: F  D  E  W
명령2:          F  D  E  W
명령3:                   F  D  E  W
```
3개 명령어 완료에 12 클럭 필요

### 4단계 파이프라인 실행

```
       1  2  3  4  5  6  7
명령1:  F  D  E  W
명령2:     F  D  E  W
명령3:        F  D  E  W
명령4:           F  D  E  W
```
4개 명령어 완료에 7 클럭 → 거의 4배 향상

### 파이프라인 성능

$$
\text{스피드업} = \frac{\text{비파이프라인 시간}}{\text{파이프라인 시간}} \approx \text{단계 수}
$$

이상적인 경우 k단계 파이프라인의 성능은 k배 향상됩니다. 단, 해저드로 인해 실제 성능은 이에 미치지 못합니다.

## 파이프라인 해저드 (Hazard)

해저드는 파이프라인 실행을 방해하는 위험 요소입니다.

### 1. 데이터 해저드 (Data Hazard)

이전 명령어의 결과가 아직 완료되지 않았는데 다음 명령어가 그 값을 필요로 하는 경우입니다.

```
ADD R1, R2, R3    ; R1 = R2 + R3 (아직 계산 중)
SUB R4, R1, R5    ; R4 = R1 - R5 (R1 값이 아직 없음!)
```

**해결 방법:**
- **포워딩(Forwarding/Bypassing):** 실행 결과를 레지스터 파일 없이 직접 다음 단계로 전달
- **파이프라인 지연(Stall/Bubble):** 의존 명령어를 몇 클럭 지연 (NOP 삽입)
- **코드 재배치:** 컴파일러가 독립적 명령어를 사이에 배치

### 2. 제어 해저드 (Control Hazard)

분기(Branch) 명령어로 인해 실제 실행 경로가 결정되기 전에 이미 다른 명령어를 파이프라인에 로드한 경우입니다.

```
BEQ  R1, R2, Label    ; R1==R2이면 Label로 점프
ADD  R3, R4, R5       ; 이미 파이프라인에 있지만 실행하면 안 될 수도 있음
```

**해결 방법:**
- **분기 예측 (Branch Prediction):**
  - **정적 예측:** 항상 분기 안 함(Not Taken) 또는 항상 분기(Taken) 가정
  - **동적 예측:** 과거 분기 이력을 BTB(Branch Target Buffer)에 저장하여 예측
- **지연 분기(Delayed Branch):** 분기 명령 뒤의 슬롯에 항상 실행할 명령어 배치
- **투기적 실행(Speculative Execution):** 예측한 경로로 실행, 틀리면 취소

### 3. 구조적 해저드 (Structural Hazard)

같은 하드웨어 자원을 두 명령어가 동시에 사용하려 할 때 발생합니다.

예: 단일 메모리를 인출 단계와 저장 단계에서 동시에 접근
**해결:** 명령어 캐시와 데이터 캐시를 분리 (하버드 구조)

## 슈퍼스칼라 (Superscalar)

여러 개의 파이프라인을 병렬로 사용하여 클럭당 여러 명령어를 처리합니다.

```
파이프라인1: 명령1 F  D  E  W
파이프라인2: 명령2 F  D  E  W
파이프라인3: 명령3 F  D  E  W
```

독립적인 명령어를 동시에 처리합니다.

## 핵심 정리

- 명령어 사이클: 인출(Fetch) → 해독(Decode) → 실행(Execute) → 저장(Write Back)
- 파이프라인: 여러 명령어를 단계별로 동시 처리, k단계 파이프라인 → 최대 k배 향상
- 데이터 해저드: 데이터 의존성 문제 → 포워딩, 지연(Stall)으로 해결
- 제어 해저드: 분기 명령어 문제 → 분기 예측(정적/동적)으로 해결
- 구조적 해저드: 자원 충돌 → 하버드 구조(명령어/데이터 캐시 분리)
