## 왜 I/O 방식을 배우나요?

CPU는 매우 빠르고, 입출력 장치(I/O Device)는 상대적으로 느립니다. 예를 들어 키보드를 누르는 사람의 속도는 CPU보다 수백만 배 느립니다. CPU가 매번 키보드 입력을 기다리면 CPU가 낭비됩니다.

**목표:** CPU가 입출력 장치를 효율적으로 다루어 전체 시스템 성능을 높이는 것입니다.

## I/O 제어 방식

### 1. 폴링 (Polling, 프로그램 제어 I/O)

**동작:** CPU가 주기적으로 입출력 장치의 상태를 직접 확인합니다.

```
CPU: "입출력 장치야, 준비됐니?"
장치: "아직요."
CPU: (잠시 후) "지금은 됐니?"
장치: "아직요."
...반복...
장치: "이제 됐어요!"
CPU: 데이터 전송
```

**비유:** 전자레인지 앞에 서서 계속 시계를 보면서 다 됐는지 확인하는 것과 같습니다.

- 장점: 구현 단순, 응답 지연 없음
- 단점: CPU가 계속 장치 상태를 확인하므로 **CPU 낭비가 심함**

### 2. 인터럽트 방식 (Interrupt-Driven I/O)

**동작:** CPU는 다른 작업을 하다가 입출력 장치가 준비되면 인터럽트 신호를 보내 CPU에게 알립니다.

```
CPU: (다른 작업 중...)
장치: "준비됐어요!" (인터럽트 신호 발생)
CPU: 하던 작업 잠시 멈춤 → 인터럽트 처리 → 다시 하던 작업 재개
```

**비유:** 전자레인지에 음식을 넣고 다른 일을 하다가 "삐~" 소리(인터럽트)가 나면 가서 꺼내는 것과 같습니다.

- 장점: CPU가 다른 작업 가능, 효율적
- 단점: 인터럽트마다 문맥 전환(Context Switch) 비용 발생

### 인터럽트 처리 순서

1. 입출력 장치에서 인터럽트 신호 발생
2. CPU가 현재 실행 중인 명령어를 완료하고 인터럽트 감지
3. 현재 상태(레지스터, PC 등)를 스택에 저장 (문맥 저장, Context Save)
4. 인터럽트 벡터 테이블(Interrupt Vector Table)에서 해당 ISR(Interrupt Service Routine, 인터럽트 서비스 루틴) 주소를 찾음
5. ISR 실행 (인터럽트 처리)
6. 저장했던 상태 복원 (문맥 복원, Context Restore)
7. 인터럽트 이전 작업 재개

### 인터럽트 종류

| 종류 | 설명 |
|------|------|
| **NMI **(Non-Maskable Interrupt, 비마스크 인터럽트) | 무조건 처리해야 하는 인터럽트. 전원 이상, 하드웨어 오류 등 |
| **마스크 가능 인터럽트 **(Maskable Interrupt) | 인터럽트 플래그로 차단(마스킹) 가능. 일반 입출력 장치 인터럽트 |
| **소프트웨어 인터럽트 **(Software Interrupt) | 프로그램 내에서 발생. 시스템 콜, 트랩(Trap) |

### 3. DMA (Direct Memory Access, 직접 메모리 접근)

**동작:** 대량의 데이터 전송 시 CPU 대신 **DMA 컨트롤러**가 직접 메모리와 입출력 장치 사이의 데이터를 전송합니다.

```
CPU: DMA 컨트롤러에게 "디스크 A에서 메모리 주소 B로 C 바이트 전송해줘"
DMA: CPU 대신 직접 데이터 전송 (CPU는 다른 작업)
DMA: 전송 완료 → CPU에 인터럽트 신호 발생
CPU: 완료 인터럽트 처리
```

**비유:** 이삿짐 운반 회사(DMA)에 짐 운반(데이터 전송)을 맡기고 집주인(CPU)은 다른 일을 하다가, 다 됐다는 연락(인터럽트)을 받는 것과 같습니다.

- 장점: CPU 부담 대폭 감소, 대용량 전송에 효율적
- 단점: DMA 컨트롤러 하드웨어 필요, 버스 경합 발생 가능

### 4. 채널 I/O (Channel I/O)

**DMA보다 발전된 방식**으로, **I/O 채널**(Channel, 입출력 전용 처리기)이 별도의 프로그램을 실행하면서 입출력을 처리합니다. 대형 컴퓨터(메인프레임)에서 사용됩니다.

### I/O 방식 비교

| 방식 | CPU 개입도 | 대용량 데이터 | 주요 사용 |
|------|----------|------------|---------|
| 폴링 | 매우 높음 | 비효율 | 단순 장치 |
| 인터럽트 | 중간 | 중간 | 일반 장치 |
| DMA | 낮음 | 효율적 | 디스크, 네트워크 |
| 채널 | 매우 낮음 | 매우 효율적 | 대형 컴퓨터 |

## 버스 (Bus)

**버스**(Bus)는 컴퓨터 내부에서 데이터를 이동시키는 공유 통신 경로입니다.

**비유:** 여러 정류장을 연결하는 시내버스처럼, 여러 장치가 하나의 버스를 공유하여 통신합니다.

### 버스의 종류

| 버스 | 역할 |
|------|------|
| **데이터 버스**(Data Bus) | 실제 데이터를 전달. 양방향 |
| **주소 버스**(Address Bus) | 메모리나 I/O 장치의 주소를 전달. CPU에서 단방향 |
| **제어 버스**(Control Bus) | 읽기/쓰기 등 제어 신호 전달. 양방향 |

### 버스 폭과 성능

- **데이터 버스 폭(Bus Width):** 한 번에 전송하는 비트 수. 32비트 버스는 한 번에 32비트(4바이트) 전송
- **버스 클럭(Bus Clock):** 버스의 동작 주파수. 높을수록 빠름
- **버스 대역폭(Bus Bandwidth) = 버스 폭 × 버스 클럭**

### I/O 포트 방식

| 방식 | 설명 |
|------|------|
| **메모리 매핑 I/O **(Memory-Mapped I/O) | 입출력 장치의 레지스터를 메모리 주소 공간의 일부로 할당. 메모리 접근 명령어로 I/O 접근 가능 |
| **독립 I/O **(Isolated I/O, I/O 매핑 I/O) | I/O 전용 주소 공간 사용. IN/OUT 같은 전용 명령어 필요 |

## 주요 인터페이스

| 인터페이스 | 특성 | 주요 용도 |
|-----------|------|---------|
| **PCIe** (PCI Express) | 고속 직렬 인터페이스, 레인(Lane) 단위 전송 | 그래픽카드, NVMe SSD, 네트워크 카드 |
| **SATA** (Serial ATA) | 저속 직렬 인터페이스 | 일반 HDD, SATA SSD |
| **NVMe** (NVM Express) | PCIe 기반 고속 SSD 프로토콜 | M.2 SSD |
| **USB** (Universal Serial Bus) | 범용 직렬 버스, 플러그앤플레이 | 키보드, 마우스, 외장 드라이브 |
| **HDMI/DisplayPort** | 디스플레이 인터페이스 | 모니터, TV |

## 핵심 정리

- **폴링:** CPU가 직접 장치 상태 계속 확인 → CPU 낭비
- **인터럽트:** 장치가 신호 보내면 CPU가 처리 → 효율적
- **인터럽트 처리 순서:** 발생 → 상태 저장 → ISR 실행 → 상태 복원 → 재개
- **NMI:** 마스킹 불가, 반드시 처리 / 마스크 가능 인터럽트: 차단 가능
- **DMA:** DMA 컨트롤러가 대량 데이터를 CPU 대신 전송, 완료 시 인터럽트
- **버스:** 데이터 버스(데이터), 주소 버스(주소), 제어 버스(제어 신호)
- **메모리 매핑 I/O:** I/O 장치를 메모리 주소로 접근 / 독립 I/O: 전용 주소 공간 사용
