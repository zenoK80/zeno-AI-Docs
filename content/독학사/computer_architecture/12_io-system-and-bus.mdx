## I/O 장치와 CPU 통신

CPU와 I/O 장치 사이에는 속도 차이가 크기 때문에 효율적인 통신 방법이 필요합니다.

## I/O 제어 방식

### 1. 프로그램 제어 I/O (Programmed I/O, 폴링)

CPU가 주기적으로 I/O 장치 상태를 확인(폴링)합니다.

```
while (장치 준비 안 됨) {
  상태 확인;  // 폴링
}
데이터 전송;
```

- 장점: 구현 단순
- 단점: CPU가 폴링하는 동안 다른 작업 불가능 → **CPU 낭비**

### 2. 인터럽트 방식 (Interrupt-Driven I/O)

CPU는 다른 작업을 수행하다가 I/O 장치가 준비되면 **인터럽트 신호**를 받아 처리합니다.

```
CPU: 다른 작업 수행
I/O 장치: 준비 완료 → 인터럽트 신호 발생
CPU: 현재 상태 저장 → ISR 실행 → 복귀
```

- 장점: CPU 낭비 없음
- 단점: 데이터 전송마다 CPU가 개입해야 함

### 3. DMA (Direct Memory Access)

DMA 컨트롤러가 CPU 개입 없이 직접 메모리와 I/O 장치 간 데이터를 전송합니다.

```
CPU → DMA에 전송 정보 전달 (소스, 목적지, 크기)
DMA: CPU 없이 메모리 ↔ I/O 장치 직접 전송
전송 완료 → DMA가 CPU에 인터럽트 발생
```

- 장점: 대용량 데이터 전송 시 CPU 부하 최소화
- 단점: DMA 컨트롤러 하드웨어 필요
- 용도: 디스크, 네트워크 카드, 사운드 카드 등

### 4. 채널 방식 (Channel I/O)

DMA의 발전형으로, 채널(I/O 프로세서)이 독립적으로 I/O를 관리합니다.

- **선택 채널:** 고속 I/O 장치와 연결
- **다중화 채널:** 여러 저속 I/O 장치와 연결

| 방식 | CPU 개입 | 전송 단위 | 효율 |
|------|---------|---------|------|
| 폴링 | 지속적 | 바이트 | 낮음 |
| 인터럽트 | 인터럽트마다 | 바이트 | 중간 |
| DMA | 시작/끝만 | 블록 | 높음 |
| 채널 | 최소 | 프로그램 단위 | 최고 |

## 인터럽트 (Interrupt)

CPU의 정상적인 프로그램 실행을 중단하고 특정 서비스 루틴으로 분기시키는 신호입니다.

### 인터럽트의 종류

| 종류 | 발생 원인 | 예시 |
|------|---------|------|
| **하드웨어 인터럽트** | 외부 장치에서 발생 | 키보드 입력, 타이머, 디스크 완료 |
| **소프트웨어 인터럽트** | 프로그램 실행 중 발생 | 시스템 콜(INT 명령어) |
| **예외(Exception)** | 오류 상황 | 0으로 나누기, 페이지 폴트, 오버플로 |

### 인터럽트 처리 순서

1. 인터럽트 신호 감지
2. 현재 PC와 레지스터 상태를 스택에 저장
3. 인터럽트 벡터 테이블(IVT)에서 ISR 주소 확인
4. ISR(Interrupt Service Routine) 실행
5. 저장된 상태 복원 후 원래 프로그램으로 복귀

### 인터럽트 우선순위

여러 인터럽트가 동시에 발생하면 우선순위에 따라 처리합니다.

- **마스크 가능 인터럽트(Maskable):** 소프트웨어로 비활성화 가능
- **비마스크 인터럽트(Non-Maskable, NMI):** 절대 무시 불가 (하드웨어 오류 등)

## 시스템 버스의 종류

### 버스 계층 구조

```
CPU ─── 프로세서 버스 ─── 메모리
             │
           브리지
             │
       PCI/PCIe 버스
       ├─ 그래픽 카드
       └─ 기타 카드
             │
          브리지
             │
       USB, SATA 버스
       ├─ 저장장치
       └─ USB 기기
```

### 주요 인터페이스

| 인터페이스 | 특징 | 용도 |
|---------|------|------|
| **PCI Express (PCIe)** | 직렬, 고속, 레인 기반 | 그래픽 카드, SSD(M.2 NVMe) |
| **SATA** | 직렬 ATA, 600MB/s | HDD, SSD |
| **USB (Universal Serial Bus)** | 범용, 핫플러그 지원 | 주변기기 |
| **NVMe (Non-Volatile Memory Express)** | PCIe 기반, 초고속 | M.2 SSD |
| **Thunderbolt** | PCIe + DisplayPort | 고성능 외부 장치 |

## 입출력 포트 매핑 방식

| 방식 | 설명 | 특징 |
|------|------|------|
| **분리형 I/O (Isolated I/O)** | I/O 포트 주소와 메모리 주소 공간 분리, IN/OUT 명령어 사용 | x86 |
| **메모리 맵 I/O (Memory-Mapped I/O)** | I/O 장치를 메모리 주소 공간에 매핑, 일반 메모리 명령어 사용 | ARM, RISC |

## 핵심 정리

- 폴링: CPU가 지속 확인, 단순하지만 CPU 낭비
- 인터럽트: I/O 완료 시 신호 발생, CPU 효율 향상
- DMA: CPU 없이 메모리↔I/O 직접 전송, 대용량 전송에 효율적
- 인터럽트 처리: 상태 저장 → ISR 실행 → 복귀
- NMI: 절대 무시 불가 인터럽트
