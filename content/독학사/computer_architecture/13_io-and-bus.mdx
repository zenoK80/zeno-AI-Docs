## 왜 입출력 방식을 구분해서 배우는가?

04번 문서에서 시스템 버스를, 운영체제 과목에서 인터럽트와 DMA를 배웠습니다. 이 문서는 그 개념들을 "입출력이 실제로 CPU에 얼마나 부담을 주는가"라는 관점에서 세 가지 방식으로 체계적으로 비교합니다.

## 장치 제어기(Device Controller)

> **쉽게 말하면:** 장치 제어기는 CPU와 각 입출력 장치(키보드, 프린터 등) 사이에서 통역을 담당하는 작은 전용 하드웨어입니다.

CPU는 모든 장치의 세세한 동작 방식을 직접 알 필요 없이, 장치 제어기가 제공하는 정해진 인터페이스(레지스터)를 통해서만 장치와 소통합니다. 이 덕분에 CPU 설계와 장치 설계가 서로 독립적으로 이루어질 수 있습니다.

## 프로그램 제어 입출력(Programmed I/O)

> **쉽게 말하면:** CPU가 "다 됐나요? 다 됐나요?"를 계속 직접 물어보며 기다리는 방식입니다(폴링, Polling).

<Table>
  <thead>
    <tr><th>장점</th><th>단점</th></tr>
  </thead>
  <tbody>
    <tr><td>구현이 단순</td><td>CPU가 입출력이 끝날 때까지 다른 일을 못 하고 계속 확인만 해야 함(CPU 낭비)</td></tr>
  </tbody>
</Table>

## 인터럽트 기반 입출력(Interrupt-Driven I/O)

> **쉽게 말하면:** CPU가 계속 확인하는 대신, 입출력 장치가 작업을 끝냈을 때 "다 됐어요!"라고 신호(인터럽트)를 보내면 그때만 반응합니다.

<Table>
  <thead>
    <tr><th>장점</th><th>단점</th></tr>
  </thead>
  <tbody>
    <tr><td>CPU가 그동안 다른 작업 수행 가능(프로그램 제어 입출력보다 효율적)</td><td>여전히 실제 데이터 전송 자체는 CPU가 직접 처리해야 함</td></tr>
  </tbody>
</Table>

## DMA(Direct Memory Access) 방식

> **쉽게 말하면:** DMA는 데이터 전송 자체를 CPU가 아닌 전용 하드웨어(DMA 컨트롤러)가 대신 처리하게 해, CPU는 시작 지시만 내리고 완전히 자유로워지는 방식입니다.

<Steps>
### 1단계: CPU가 DMA 컨트롤러에 "이 위치에서 이만큼을 저 위치로 옮겨라" 지시

### 2단계: DMA 컨트롤러가 CPU 없이 장치와 메모리 사이에서 직접 데이터 전송

### 3단계: 전송이 끝나면 DMA 컨트롤러가 CPU에 인터럽트로 완료를 알림
</Steps>

## 세 가지 입출력 방식 비교

<Table>
  <thead>
    <tr><th>방식</th><th>CPU 개입 정도</th><th>효율</th></tr>
  </thead>
  <tbody>
    <tr><td>프로그램 제어 입출력</td><td>매우 큼(계속 확인)</td><td>가장 낮음</td></tr>
    <tr><td>인터럽트 기반 입출력</td><td>중간(대기 중엔 자유롭지만 전송은 직접)</td><td>중간</td></tr>
    <tr><td>DMA</td><td>가장 적음(지시만 하면 끝)</td><td>가장 높음</td></tr>
  </tbody>
</Table>

<Callout type="warning">
  **자주 틀리는 점:** DMA를 사용해도 인터럽트가 완전히 사라지는 것은 아닙니다. DMA는 **전송 도중**의 CPU 개입만 없앨 뿐, 전송이 **끝났을 때**는 여전히 인터럽트로 CPU에 알립니다. DMA와 인터럽트는 서로 대체 관계가 아니라, DMA가 인터럽트 메커니즘을 활용하는 관계입니다.
</Callout>

## 버스의 중재(Bus Arbitration)

여러 장치가 동시에 버스를 사용하려 하면 충돌이 발생합니다. **버스 중재**는 한 시점에 하나의 장치만 버스를 사용하도록 조정하는 메커니즘입니다.

<Table>
  <thead>
    <tr><th>방식</th><th>설명</th></tr>
  </thead>
  <tbody>
    <tr><td>중앙집중식(Centralized)</td><td>버스 중재기(Arbiter)라는 중앙 장치가 누가 버스를 쓸지 결정</td></tr>
    <tr><td>분산식(Distributed)</td><td>중앙 장치 없이 각 장치가 정해진 규칙에 따라 스스로 조율</td></tr>
  </tbody>
</Table>

## 핵심 정리

- **장치 제어기**: CPU와 개별 장치 사이의 통역 담당 하드웨어.
- **프로그램 제어 입출력**: CPU가 계속 확인(폴링). 가장 비효율적.
- **인터럽트 기반 입출력**: 완료 시점에만 CPU에 알림. 대기 중 CPU 자유로움.
- **DMA**: 실제 데이터 전송까지 CPU 없이 처리. 가장 효율적. 완료 시엔 여전히 인터럽트 사용.
- **버스 중재**: 여러 장치의 버스 사용 충돌을 조정(중앙집중식/분산식).
