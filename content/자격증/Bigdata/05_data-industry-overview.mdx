## 데이터 산업을 흐름으로 보기

데이터 산업은 특정 분석 도구 하나를 뜻하지 않습니다. 데이터를 만들어 내고, 수집·저장하고, 가공·분석하며, 그 결과를 서비스와 의사결정에 쓰는 전 과정에 여러 역할이 연결됩니다.

```text
데이터 생성 -> 수집·저장 -> 가공·유통 -> 분석 -> 서비스·의사결정
```

한 조직이 모든 단계를 맡을 수도 있고, 플랫폼 기업, 공공기관, 분석 전문 기업, 솔루션 기업이 나누어 맡을 수도 있습니다.

## 주요 역할 구분하기

| 역할 | 하는 일 | 예시 |
| --- | --- | --- |
| 데이터 생산자 | 업무·서비스 과정에서 원천 데이터를 만든다 | 쇼핑몰 주문 시스템, 센서 운영자 |
| 데이터 관리·플랫폼 | 수집, 저장, 접근 제어, 제공을 담당한다 | 데이터 웨어하우스 운영 조직 |
| 데이터 가공·분석자 | 데이터를 정리하고 질문에 답한다 | 분석가, 데이터 과학자 |
| 데이터 활용자 | 분석 결과를 바탕으로 행동한다 | 마케팅, 운영, 경영 부서 |

각 역할이 분리되어도 데이터의 의미와 품질 기준을 공유하지 않으면 결과를 신뢰하기 어렵습니다. 그래서 데이터 사전, 표준 용어, 변경 이력 같은 관리 체계가 중요해집니다.

## 데이터 생명주기

데이터는 수집된 뒤 영원히 같은 모습으로 남아 있지 않습니다. 생성부터 폐기까지의 흐름을 데이터 생명주기라고 부릅니다.

<Steps>

### 생성과 수집

업무 시스템, 앱, 센서, 설문 등에서 데이터가 만들어집니다. 이때 목적 없이 과도하게 수집하지 않는 원칙이 필요합니다.

### 저장과 관리

누가 어떤 데이터에 접근할 수 있는지 정하고, 백업과 보존 정책을 마련합니다. 데이터가 어디에서 왔는지도 기록해야 합니다.

### 가공과 분석

오류·중복·누락을 점검하고 분석 목적에 맞게 변환합니다. 원본과 가공본을 구분하면 결과를 다시 검증하기 쉽습니다.

### 활용과 공유

대시보드, 추천, 예측, 보고서 등으로 활용합니다. 공유할 때는 개인정보와 민감 정보가 포함되지 않는지 확인합니다.

### 보관 또는 파기

더 이상 필요하지 않은 데이터는 보존 기준에 따라 안전하게 파기하거나 비식별 처리합니다.

</Steps>

## 데이터 거버넌스의 필요성

데이터 거버넌스는 데이터를 일관되고 책임 있게 다루기 위한 역할, 정책, 절차의 묶음입니다. 어려운 용어처럼 보이지만 실제로는 다음 질문에 답하는 장치입니다.

- 이 컬럼의 정확한 뜻은 무엇인가?
- 누가 수정할 수 있고, 누가 조회할 수 있는가?
- 값이 비정상적일 때 누가 고치는가?
- 이 데이터는 얼마나 보관해야 하는가?

<Callout type="warning">
  개인정보나 민감한 정보를 다룰 때는 "분석에 도움이 되는가"만으로 충분하지 않습니다. 수집 목적, 접근 권한, 보관 기간, 제공 범위를 관련 법령과 조직 정책에 따라 확인해야 합니다.
</Callout>

## 작은 사례로 연결하기

카페 앱의 쿠폰 사용 데이터를 생각해 봅시다.

- 주문 시스템은 사용 시각과 금액을 **생성**합니다.
- 데이터 플랫폼은 주문 데이터를 모아 **저장**합니다.
- 분석가는 쿠폰별 재방문율을 계산해 **분석**합니다.
- 마케팅 담당자는 결과를 보고 다음 쿠폰을 **활용**합니다.

이때 쿠폰 코드의 뜻이 바뀌었는데 분석가에게 공유되지 않으면 결과는 쉽게 틀어집니다. 데이터 산업의 핵심은 데이터가 이동하는 과정과 그 의미를 함께 관리하는 데 있습니다.

## 이번 편 정리

- 데이터 산업은 생성부터 활용까지 이어지는 역할과 기술의 생태계다.
- 데이터 생산자, 관리자, 분석자, 활용자는 같은 의미와 품질 기준을 공유해야 한다.
- 데이터 거버넌스는 데이터의 정의, 책임, 접근, 품질을 관리한다.
- 개인정보와 민감 정보는 활용 이전에 보호 기준을 확인한다.
