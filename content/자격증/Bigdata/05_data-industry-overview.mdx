## 이번 편의 목표

- 데이터 산업의 가치사슬을 단계별로 설명한다.
- 데이터 엔지니어, 분석가, 과학자, 관리자 역할을 구분한다.
- 데이터 거버넌스가 분석 품질과 신뢰에 필요한 이유를 이해한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 데이터 가치사슬 | 데이터가 생성되어 수집·저장·분석되고 서비스에 사용되는 전체 과정 |
| 데이터 엔지니어 | 데이터를 안정적으로 모으고 저장하고 전달하는 기반을 만드는 역할 |
| 데이터 분석가 | 데이터를 해석해 업무 질문에 답하고 의사결정을 돕는 역할 |
| 데이터 과학자 | 통계와 모델을 사용해 예측·분류 문제를 해결하는 역할 |
| 거버넌스 | 데이터를 누가 어떤 기준으로 관리하고 사용할지 정한 규칙과 책임 체계 |
| 메타데이터 | 데이터의 이름, 뜻, 형식, 위치, 만든 시점 등을 설명하는 데이터 |
| 데이터 생명주기 | 데이터가 만들어져 사용·보관되고 마지막에 폐기되는 과정 |

직무 이름은 회사마다 조금씩 다르다. 시험에서는 이름 암기보다 가치사슬의 어느 단계에서 어떤 책임을 맡는지를 구분하는 것이 중요하다.

## 주변 개념 지도

데이터를 많이 보유하는 것만으로 산업적 가치가 생기지 않는다. 품질, 보안, 개인정보 보호, 표준화가 갖춰져야 분석가가 같은 의미의 데이터를 믿고 사용할 수 있다. 거버넌스는 이 조건을 조직 차원에서 유지하는 장치다.

<Callout type="info">
메타데이터는 실제 고객 이름이나 매출액이 아니라 “고객번호 열은 무엇을 뜻하며 어떤 형식인가”처럼 데이터를 설명하는 정보다.
</Callout>

## 한 사람이 모든 일을 할 수 있을까?

고객 이탈 분석을 서비스에 적용하려면 데이터베이스에서 파일 하나를 내려받는 것으로 끝나지 않는다.

```text
서비스에서 데이터 생성
→ 수집·전송
→ 저장·관리
→ 품질 점검·가공
→ 분석·모델링
→ 시각화·서비스 적용
→ 성과와 위험 관리
```

이 흐름에 필요한 기술, 제품, 전문 서비스가 데이터 산업을 이룬다. 조직마다 직무 이름과 경계는 다르지만 책임의 종류는 구분할 수 있어야 한다.

## 데이터 가치사슬

| 단계 | 하는 일 | 고객 이탈 사례 |
| --- | --- | --- |
| 생성·수집 | 업무와 서비스에서 데이터를 만든다. | 로그인·결제·문의 이벤트 수집 |
| 저장·관리 | 데이터를 안전하고 찾기 쉽게 보관한다. | 원천 로그와 고객 테이블 관리 |
| 가공·품질 | 형식을 맞추고 오류를 점검한다. | 중복 제거, 고객 ID 연결 |
| 분석 | 통계와 모델로 질문에 답한다. | 이탈 원인 탐색과 확률 예측 |
| 활용 | 결과를 업무 시스템과 결정에 연결한다. | 상담 화면에 위험도 제공 |
| 통제 | 보안, 품질, 책임, 수명주기를 관리한다. | 접근 권한과 보존 기간 설정 |

한 단계의 오류는 뒤로 전파된다. 수집 시 고객 ID가 잘못 저장되면 정교한 모델을 써도 결과를 믿기 어렵다.

## 주요 직무 구분

### 데이터 엔지니어

데이터가 안정적으로 수집·저장·가공되도록 파이프라인과 플랫폼을 만든다. 데이터가 늦거나 중복되거나 누락되는 문제를 다룬다.

### 데이터 분석가

업무 질문을 지표와 분석 문제로 바꾸고, 데이터를 탐색해 의사결정에 필요한 설명을 만든다. SQL, 통계, 시각화를 자주 사용한다.

### 데이터 과학자

통계와 머신러닝으로 예측·분류·추천 모델을 만들고 실험한다. 모델 성능뿐 아니라 실제 적용 가능성과 편향도 검토한다.

### 데이터베이스 관리자

데이터베이스의 가용성, 권한, 백업, 복구, 성능을 관리한다. 필요한 사용자가 필요한 데이터에 안정적으로 접근하게 한다.

### 데이터 기획자·거버넌스 담당자

데이터 표준, 책임자, 품질 기준, 접근 정책과 활용 우선순위를 정한다. 조직 전체가 같은 용어와 기준으로 데이터를 사용하도록 돕는다.

<Callout type="info">
작은 조직에서는 한 사람이 여러 역할을 맡을 수 있다. 시험에서는 직함보다 "어떤 책임을 수행하는가"를 기준으로 판단한다.
</Callout>

## 데이터 거버넌스란?

데이터 거버넌스는 조직이 데이터를 일관되고 안전하며 책임 있게 관리하기 위한 원칙, 역할, 절차다.

다음 질문에 답할 수 있어야 한다.

- `이탈 고객`의 공식 정의는 무엇인가?
- 고객 연락처의 품질 책임자는 누구인가?
- 어떤 직무가 주민등록번호에 접근할 수 있는가?
- 데이터는 언제 삭제하거나 익명화해야 하는가?
- 모델에 사용한 데이터와 버전을 재현할 수 있는가?

거버넌스가 없으면 부서마다 이탈률을 다르게 계산하거나, 필요 이상으로 개인정보를 복사하거나, 모델 결과의 출처를 설명하지 못할 수 있다.

## 메타데이터와 데이터 품질

**메타데이터**는 데이터를 설명하는 데이터다. 테이블 이름, 컬럼 의미, 자료형, 생성 주기, 담당자, 품질 규칙 등이 포함된다.

예를 들어 `churned` 컬럼 설명이 단순히 "이탈 여부"라면 부족하다. 다음처럼 기준이 구체적이어야 한다.

```text
이름: churned
정의: 기준일 이후 30일 이내 유료 구독을 해지하면 1, 아니면 0
자료형: 정수
허용값: 0 또는 1
담당 부서: 고객분석팀
```

이 정의가 있어야 학습 데이터의 정답을 재현하고 부서 간 지표를 비교할 수 있다.

## 데이터 생명주기와 보호

```text
생성 → 저장 → 사용·공유 → 보관 → 파기
```

모든 데이터를 영원히 보관하는 것이 좋은 관리는 아니다. 목적에 필요한 범위만 수집하고, 접근 권한을 제한하며, 보존 기간이 끝나면 안전하게 파기해야 비용과 개인정보 위험을 줄일 수 있다.

## 정리

데이터 산업은 생성, 수집, 저장, 가공, 분석, 활용, 통제를 연결하는 생태계다. 좋은 분석은 모델만의 결과가 아니라 각 역할의 협업과 명확한 데이터 정의, 품질·보안 거버넌스에서 나온다.
