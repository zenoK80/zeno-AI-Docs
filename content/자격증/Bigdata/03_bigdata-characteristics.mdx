## 이번 편의 목표

- 빅데이터를 설명하는 Volume, Velocity, Variety, Veracity, Value를 구분한다.
- 정형·반정형·비정형 데이터의 차이를 사례로 판단한다.
- 데이터 규모보다 분석 목적과 품질이 먼저인 이유를 설명한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| Volume(규모) | 저장하고 처리해야 할 데이터의 양 |
| Velocity(속도) | 데이터가 생기고 전달되고 처리되는 빠르기 |
| Variety(다양성) | 표, 글, 이미지처럼 데이터 형태가 여러 가지인 정도 |
| Veracity(신뢰성) | 데이터가 정확하고 믿을 만한 정도 |
| Value(가치) | 데이터를 사용해 실제 문제를 개선하는 정도 |
| 정형 데이터 | 행과 열처럼 미리 정한 구조에 맞춰 저장한 데이터 |
| 비정형 데이터 | 문서, 이미지, 음성처럼 고정된 표 구조가 없는 데이터 |

5V는 무조건 외울 다섯 단어가 아니라, 어떤 저장·처리·품질 문제가 생길지 묻는 점검표다.

## 주변 개념 지도

데이터 양이 많아도 기존 도구로 안정적으로 처리할 수 있다면 규모만 큰 데이터일 수 있다. 반대로 양은 비교적 작아도 실시간 처리 속도가 매우 빠르거나 이미지·텍스트가 섞여 있으면 기존 방식으로 다루기 어려울 수 있다.

<Callout type="info">
시험에서는 사례를 주고 어떤 V가 핵심인지 묻는다. 단어 하나만 찾지 말고 “무엇 때문에 기존 방식이 어려운가”를 먼저 읽는다.
</Callout>

## 큰 파일 하나가 곧 빅데이터일까?

고객 이탈을 분석하려고 다음 데이터를 모았다고 하자.

- 5년간 고객 1억 명의 결제 이력
- 초당 들어오는 앱 클릭 이벤트
- 고객 상담 녹취와 상담 메모
- 일부 값이 누락되거나 중복된 회원 정보

이 환경이 어려운 이유는 단순히 파일 크기만이 아니다. 양, 생성 속도, 형태, 신뢰성 문제가 동시에 나타나 기존 방식만으로 처리하기 어려워진다.

## 빅데이터의 다섯 가지 V

| 특성 | 뜻 | 고객 이탈 사례 | 확인 질문 |
| --- | --- | --- | --- |
| Volume | 데이터의 규모 | 수년간 쌓인 결제·접속 이력 | 저장·처리 자원이 충분한가? |
| Velocity | 생성·처리 속도 | 실시간 클릭 이벤트 | 얼마 안에 판단해야 하는가? |
| Variety | 데이터 형태의 다양성 | 표, JSON 로그, 상담 음성 | 서로 다른 형식을 어떻게 연결할까? |
| Veracity | 데이터의 신뢰성과 품질 | 중복 회원, 누락된 연령 | 분석 결과를 믿을 수 있는가? |
| Value | 데이터가 만드는 효용 | 이탈 방지 행동과 비용 절감 | 실제 의사결정이 개선되는가? |

어떤 교재는 3V나 4V를 사용한다. 시험에서는 문제에서 제시한 분류 체계와 설명을 기준으로 판단하되, 각 V의 핵심 의미를 구분해야 한다.

<Callout type="important">
데이터가 많다고 자동으로 가치가 생기지는 않는다. 잘못 수집된 대규모 데이터는 잘못된 결론을 더 자신 있게 만들 수 있다.
</Callout>

## 데이터 형태 구분하기

### 정형 데이터

행과 열, 자료형, 제약 조건처럼 구조가 미리 정해진 데이터다. 관계형 데이터베이스의 고객 테이블과 결제 테이블이 대표적이다.

```text
customer_id | plan    | monthly_fee | churned
101         | basic   | 9900        | 0
102         | premium | 19900       | 1
```

### 반정형 데이터

고정된 표 구조는 아니지만 키와 태그 등 내부 구조를 가진다. JSON 이벤트 로그, XML 문서가 대표적이다.

```json
{
  "customer_id": 102,
  "event": "cancel_button_click",
  "occurred_at": "2026-08-01T10:15:00Z"
}
```

레코드마다 키가 다를 수 있으므로 분석 전에 스키마를 확인하고 평탄화하는 과정이 필요할 수 있다.

### 비정형 데이터

표 형태로 바로 분석하기 어려운 텍스트, 이미지, 음성, 영상이다. 고객 상담 녹취에서 불만 주제를 찾으려면 음성 인식과 자연어 처리 같은 변환이 필요하다.

## 품질 문제를 구체적으로 찾기

| 문제 | 예시 | 가능한 대응 |
| --- | --- | --- |
| 결측 | 연령이 비어 있음 | 원인 확인 후 제거·대치·별도 범주 |
| 중복 | 같은 결제가 두 번 저장됨 | 고유 키와 발생 시각으로 판별 |
| 불일치 | 성별 코드가 `M`, `male`, `1`로 혼재 | 표준 코드로 변환 |
| 이상값 | 월 이용 시간이 음수 | 입력 오류인지 실제 특이 사례인지 확인 |
| 최신성 부족 | 1년 전 고객 상태만 존재 | 분석 목적에 맞는 기준 시점 재설정 |

결측값은 무조건 평균으로 채우지 않는다. 결측 자체가 이탈과 관련된 정보일 수 있고, 범주형 변수에는 평균이 의미가 없을 수 있다.

## 5V를 이용한 설계 연습

고객의 클릭 이벤트가 초당 10만 건 들어오고 10초 안에 이탈 위험을 계산해야 한다고 하자.

- `Volume`: 하루에 쌓일 이벤트 수와 저장 비용을 계산한다.
- `Velocity`: 10초 이내 수집·처리·예측이 가능한 구조를 선택한다.
- `Variety`: 회원 테이블과 JSON 이벤트를 고객 ID로 연결한다.
- `Veracity`: 중복 이벤트와 자동화 트래픽을 제거한다.
- `Value`: 혜택 비용보다 실제 이탈 감소 효과가 큰지 측정한다.
