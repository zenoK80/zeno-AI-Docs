## 빅데이터는 단지 큰 파일이 아니다

빅데이터는 데이터의 양이 많다는 뜻만으로 설명하기 어렵습니다. 기존 방식으로 수집, 저장, 처리, 분석하기 어려울 만큼 **규모와 생성 속도, 형태가 달라진 데이터 환경**을 함께 뜻합니다.

예를 들어 매일 한 번 정리하는 매출 엑셀 파일과, 수많은 사용자의 클릭이 초 단위로 쌓이는 서비스 로그는 처리 방식이 다릅니다. 후자에서는 데이터를 빠르게 받아들이고, 여러 형태를 이해하며, 신뢰할 수 있는지 확인해야 합니다.

## 대표적인 3V와 확장 개념

빅데이터의 특징은 보통 3V로 정리합니다. 자료에 따라 4V, 5V로 확장해 설명하기도 하므로 각 단어가 의미하는 바를 이해하는 것이 더 중요합니다.

| 특징 | 의미 | 예시 |
| --- | --- | --- |
| Volume(규모) | 데이터의 양이 크다 | 수년치 거래 내역, 대량 이미지 |
| Velocity(속도) | 데이터가 빠르게 생성·전달된다 | 실시간 결제, 센서 측정값 |
| Variety(다양성) | 데이터 형식이 다양하다 | 표, JSON, 텍스트, 이미지, 음성 |
| Veracity(신뢰성) | 오류와 편향을 점검해야 한다 | 중복 고객, 누락된 위치 정보 |
| Value(가치) | 의사결정에 쓸 수 있어야 한다 | 이탈 예방, 재고 조정 |

<Callout type="info">
  3V의 이름을 외우는 것보다, 특정 사례에서 어떤 V가 문제를 만들고 있는지 구분하는 연습이 중요합니다.
</Callout>

## 데이터 형태에 따라 달라지는 접근

### 정형 데이터

행과 열이 정해진 데이터입니다. 회원 번호, 주문 일시, 결제 금액처럼 관계형 데이터베이스의 테이블로 다루기 좋습니다.

### 반정형 데이터

일정한 구조는 있지만 모든 항목이 같은 형태는 아닌 데이터입니다. 웹 API 응답의 JSON, 로그 파일, XML이 예입니다.

```json
{
  "memberId": 102,
  "event": "add_to_cart",
  "productId": "A-12",
  "coupon": null
}
```

### 비정형 데이터

고정된 표 구조로 바로 나누기 어려운 텍스트, 이미지, 음성, 영상 등이 여기에 해당합니다. 분석 목적에 맞게 텍스트를 토큰으로 나누거나, 이미지에서 특징을 추출하는 전처리가 필요할 수 있습니다.

## 데이터가 많을수록 품질이 중요하다

큰 데이터는 오류도 크게 증폭시킬 수 있습니다. 고객 ID가 중복되거나, 날짜 형식이 섞이거나, 특정 시간대 데이터가 누락되면 분석 결과가 왜곡됩니다.

| 점검 항목 | 확인 질문 | 간단한 예 |
| --- | --- | --- |
| 완전성 | 필요한 값이 빠지지 않았는가? | 주문 일시가 비어 있지 않은가 |
| 일관성 | 같은 뜻의 값이 같은 규칙인가? | 상태값이 `완료`, `complete`로 섞이지 않았는가 |
| 정확성 | 실제와 맞는가? | 금액이 음수나 비정상적으로 크지 않은가 |
| 적시성 | 필요한 시점에 갱신되는가? | 재고 데이터가 너무 오래되지 않았는가 |

## 사례로 구분하기

배달 서비스에서 주문 수가 급증하는 저녁 시간에 앱 로그가 초당 수천 건 들어온다고 가정해 봅시다.

- 짧은 시간에 계속 들어오는 로그: **Velocity**
- 주문, 위치, 리뷰 텍스트, 사진이 섞임: **Variety**
- 오래 쌓인 주문 이력과 로그: **Volume**
- GPS가 비어 있거나 중복 주문 이벤트가 존재: **Veracity**

이렇게 특징을 나누면 "어떤 저장소와 처리 방식이 필요할까", "분석 전에 무엇을 정리해야 할까"를 더 구체적으로 생각할 수 있습니다.

## 이번 편 정리

- 빅데이터는 규모, 속도, 다양성이 함께 커진 데이터 환경이다.
- 3V에 신뢰성과 가치를 더해 설명할 수 있다.
- 정형, 반정형, 비정형 데이터는 저장과 전처리 방식이 다르다.
- 분석 전 품질 점검은 결과의 신뢰도를 좌우한다.
