## 실습 환경은 시험 문제의 일부다

실기에서는 Windows Server, Linux, 라우터 CLI처럼 작업 장소가 바뀐다. 기능을 배우기 전에 어떤 환경에서 무엇을 확인할지 정해 두면 설정값을 엉뚱한 곳에 넣는 실수를 줄일 수 있다.

<Callout type="warning">
공식 시험 환경과 실습 환경은 완전히 같지 않을 수 있다. 운영체제 버전과 실습용 프로그램은 접수 전 ICQA 공지로 다시 확인한다.
</Callout>

## 준비 목록

| 항목 | 목적 | 확인 방법 |
| --- | --- | --- |
| ICQA 실습용 예제 프로그램 | 시험 화면과 작업 흐름 익히기 | 공식 자료실에서 최신 파일 확인 |
| Windows Server 환경 | IP, DNS, DHCP, IIS 작업 | 관리자 계정과 네트워크 어댑터 확인 |
| Linux 환경 | 권한, 사용자, 서비스 명령 연습 | 터미널에서 `whoami`, `pwd` 실행 |
| 라우터 연습 환경 | CLI와 라우팅 명령 연습 | 인터페이스와 `show` 명령 확인 |
| 실습 노트 | 입력값과 검증 결과 기록 | 문제별 체크리스트 작성 |

## 문제를 시작하기 전 30초

1. 문제에서 요구하는 운영체제와 작업 대상을 표시한다.
2. IP, 계정명, 비밀번호, 권한, 도메인처럼 직접 입력할 값을 따로 적는다.
3. 설정 뒤 무엇으로 확인할지 먼저 정한다.

예를 들어 사용자 생성 문제라면 `useradd`가 끝이 아니다. `id 사용자명` 또는 `/etc/passwd` 확인까지 계획해야 한다.

## 첫 확인 연습

Windows에서는 `ipconfig /all`, Linux에서는 아래 명령을 실행해 현재 위치와 사용자를 확인한다.

```bash
whoami
pwd
ip addr
```

명령어 결과를 보고 “지금 어느 환경에서 작업 중인가”를 말로 설명해 보자. 실기는 이 기본 구분에서 시작한다.

## 이번 편 정리

- 환경마다 같은 목표를 해결하는 도구가 다르다.
- 문제값, 작업 장소, 검증 방법을 먼저 분리한다.
- 다음 편에서는 모든 환경의 공통 언어인 IPv4 주소를 계산한다.
