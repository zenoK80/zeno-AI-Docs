## 이번 편의 목표
- 공식 공지에서 시험 운영체제와 도구를 확인한다.
- 실습용 가상 머신과 에뮬레이터를 안전하게 준비한다.
- 화면 암기가 아닌 기능 중심 연습법을 익힌다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 실습 환경 | 문제를 연습할 운영체제, 프로그램, 가상 장치의 전체 구성 |
| 에뮬레이터 | 실제 장비나 시험 프로그램의 동작을 비슷하게 재현한 소프트웨어 |
| 네트워크 어댑터 | 컴퓨터를 네트워크에 연결하는 하드웨어 또는 가상 장치 |
| 토폴로지 | 장치들이 어떤 모양과 관계로 연결되어 있는지 나타낸 구조 |
| 인터페이스 | 장치나 프로그램이 다른 대상과 연결되는 접점 |
| 설정값 | IP 주소, 마스크, 포트처럼 동작을 결정하는 입력값 |
| 초기 상태 | 아직 문제의 변경을 적용하기 전 기준 상태 |

화면 모양은 버전마다 달라질 수 있다. 따라서 버튼 위치만 외우지 말고 설정의 이름, 목적, 저장 후 확인 방법을 함께 익힌다.

## 주변 개념 지도

실습 환경을 준비하는 일도 문제 풀이의 일부다. 사용 중인 네트워크 어댑터와 IP 범위를 먼저 기록해야 설정 후 무엇이 바뀌었는지 판단할 수 있다.

<Callout type="warning">
실제 사용 중인 회사·학교 네트워크 설정을 연습용으로 변경하지 않는다. 별도의 가상 환경이나 연습 장치를 사용한다.
</Callout>

## 먼저 공식 환경을 확인한다

ICQA의 현재 공지에는 네트워크관리사 실기 환경으로 Windows Server 2022가 안내되어 있다. 시험 프로그램과 버전은 바뀔 수 있으므로 블로그 캡처보다 공식 공지를 우선한다.

<Callout type="warning">
인터넷에서 받은 비공식 에뮬레이터는 악성 코드 여부와 배포 권한을 확인한다. 개인 PC의 실제 네트워크 설정 대신 가상 머신이나 복구 가능한 환경을 사용한다.
</Callout>

## 권장 실습 구성

```text
호스트 PC
├─ Windows Server 2022 가상 머신: 서버 설정 실습
├─ 실기 에뮬레이터: 화면 조작과 제출 방식 연습
└─ 계산 노트: IP·서브넷 풀이 기록
```

가상 머신은 실제 시험 화면과 100% 같지 않아도 된다. DNS, DHCP, 사용자, 공유 폴더 같은 기능의 원리를 익히는 용도다.

## 준비 순서

<Steps>
### 공식 공지를 읽는다
운영체제, 시험 시간, 제공 프로그램, 변경 사항을 기록한다.

### 가상 머신을 만든다
Windows Server를 설치하고 네트워크가 정상인지 확인한 뒤 초기 스냅샷을 만든다.

### 에뮬레이터의 제출 방식을 익힌다
문제 열기, 입력, 저장, 다음 문제 이동을 연습한다. 설정 자체와 답안 저장은 별개일 수 있다.

### 기능별 반복표를 만든다
`IP 설정`, `DNS`, `DHCP`, `사용자·권한`, `라우터`, `케이블`로 나눠 걸린 시간과 오류를 기록한다.
</Steps>

## 설정 전후 확인 습관

Windows에서 네트워크 상태를 확인하는 기본 명령은 다음과 같다.

```powershell
ipconfig /all
ping 127.0.0.1
ping 192.168.10.1
nslookup example.com
```

- `ipconfig /all`: 주소, 마스크, 게이트웨이, DNS 확인
- `ping 127.0.0.1`: 로컬 TCP/IP 스택 확인
- 게이트웨이 ping: 로컬 네트워크 경로 확인
- `nslookup`: DNS 이름 해석 확인

`ping` 실패만으로 대상 장치가 꺼졌다고 단정하면 안 된다. 방화벽이 ICMP 응답을 막을 수도 있으므로 주소 설정과 서비스별 검증을 함께 본다.

## UI가 달라도 찾는 방법

DNS 서버 설정 문제라면 화면 좌표보다 다음 개념을 기억한다.

1. 서버 관리자에서 역할과 기능을 추가한다.
2. DNS 관리 도구에서 정방향 또는 역방향 조회 영역을 선택한다.
3. 요구된 레코드 종류와 이름, 값을 입력한다.
4. `nslookup`으로 이름 해석 결과를 확인한다.

메뉴 위치가 조금 바뀌어도 이 흐름은 유지된다.
