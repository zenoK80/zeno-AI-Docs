## 복습 방법

계산 문제도 감으로 고르지 말고 종이에 중간 과정을 적는다. 선택한 뒤 정답과 선지별 해설을 확인한다.

<Callout type="info">
실기에서는 설정값을 입력한 것보다 결과를 검증한 것이 중요하다. 계산 결과와 확인 명령을 한 쌍으로 연습한다.
</Callout>

## 4지선다 문제

### 문제 1

프로토콜의 뜻으로 가장 적절한 것은?

① 장치끼리 데이터를 주고받을 때 따르는 통신 약속

② 컴퓨터 케이스의 크기

③ 사용자 화면의 배경색

④ 저장장치의 물리 용량만

<Collapse title="정답 보기">

**정답: ①**

</Collapse>

<Collapse title="해설 보기">

프로토콜은 데이터 형식과 순서, 응답 방법 등 통신 당사자가 따르는 규칙이다.

- **①** 정답이다.
- **②** 폼팩터와 관련된 설명이다.
- **③** 디자인 설정이다.
- **④** 저장 용량과 다른 개념이다.

</Collapse>

### 문제 2

IP 주소의 주된 역할은?

① 네트워크에서 장치와 목적지 위치를 구분한다.

② CPU 온도를 낮춘다.

③ 파일을 압축한다.

④ 전원 전압을 바꾼다.

<Collapse title="정답 보기">

**정답: ①**

</Collapse>

<Collapse title="해설 보기">

IP 주소는 네트워크 계층에서 출발지와 목적지를 식별하고 경로를 찾는 데 사용된다.

- **①** 정답이다.
- **②** 냉각 장치 역할이다.
- **③** 압축 프로그램 역할이다.
- **④** 전원공급장치 역할이다.

</Collapse>

### 문제 3

클라이언트와 서버의 관계로 가장 적절한 것은?

① 클라이언트가 요청하고 서버가 기능이나 데이터를 제공한다.

② 서버는 항상 사람 한 명을 뜻한다.

③ 클라이언트와 서버는 통신할 수 없다.

④ 클라이언트는 케이블 이름이다.

<Collapse title="정답 보기">

**정답: ①**

</Collapse>

<Collapse title="해설 보기">

클라이언트와 서버는 장치 이름이라기보다 요청과 제공 역할을 나타낸다.

- **①** 정답이다.
- **②** 서버 프로그램이나 컴퓨터를 뜻할 수 있다.
- **③** 네트워크로 통신하는 관계다.
- **④** 프로그램 또는 장치 역할이다.

</Collapse>

### 문제 4

네트워크 문제 진단 순서로 가장 적절한 것은?

① 무작위 설정 변경 → 기록 삭제

② 증상 확인 → 현재 상태 기록 → 원인 범위 좁히기 → 한 가지 변경 → 검증

③ 운영체제 재설치 → 주소 확인

④ 결과 확인 없이 저장만

<Collapse title="정답 보기">

**정답: ②**

</Collapse>

<Collapse title="해설 보기">

기준 상태와 단계별 검증이 있어야 어떤 조치가 효과를 냈는지 판단할 수 있다.

- **①** 원인을 더 복잡하게 만든다.
- **②** 정답이다.
- **③** 재설치는 초기 진단으로 과도하다.
- **④** 설정 적용 여부를 알 수 없다.

</Collapse>

### 문제 5

IP 주소를 바꾼 뒤 가장 적절한 행동은?

① 창을 닫고 성공했다고 가정한다.

② 주소 설정을 다시 확인하고 대상과 연결 시험을 한다.

③ 다른 모든 장치 주소도 동시에 바꾼다.

④ 오류 메시지를 삭제한다.

<Collapse title="정답 보기">

**정답: ②**

</Collapse>

<Collapse title="해설 보기">

설정 화면의 저장 여부와 실제 적용 주소, 통신 가능 여부를 차례로 검증한다.

- **①** 실제 반영 여부를 모른다.
- **②** 정답이다.
- **③** 원인과 영향 범위를 키운다.
- **④** 진단 정보를 잃는다.

</Collapse>

## 직접 적용하기

‘웹 서버에 접속되지 않는다’는 증상을 물리 연결, IP 설정, 대상 도달, 서비스 상태 네 단계로 나누어 각 단계의 확인 항목을 하나씩 적어 보자.

<Collapse title="풀이 및 검증 보기">

예시: 케이블 또는 가상 어댑터의 연결 상태를 확인한다. ipconfig 또는 ip addr로 주소와 마스크를 확인한다. ping 등 허용된 도구로 대상 IP까지 도달 가능한지 본다. 마지막으로 서버 서비스가 실행 중이고 올바른 포트를 듣는지 확인한다. 각 단계 결과에 따라 다음 범위를 결정한다.

</Collapse>

## 결과 점검

- 5개 정답: 계산 또는 진단 순서를 말로 다시 설명한다.
- 3~4개 정답: 틀린 문제의 용어와 경계값을 본편에서 확인한다.
- 0~2개 정답: 용어표와 완결 예제를 다시 따라 한 뒤 재도전한다.
