## 이 문서의 목표

이 편을 읽은 뒤에는 네트워크관리사 2급 실기 문제를 봤을 때 “어느 화면을 눌러야 하지?”보다 먼저 다음을 판단할 수 있어야 한다.

1. 이 문제는 Windows, Linux, 라우터, SQL 중 어디에서 푸는가?
2. 문제에서 요구한 값은 무엇인가?
3. 설정한 결과를 어떤 명령이나 화면으로 확인하는가?

실기는 설정을 외우는 시험이 아니라, **조건을 설정값으로 바꾸고 결과를 확인하는 시험**이다.

## 실제 문제는 한 줄이 아니라 작업 묶음이다

다음과 같은 Windows Server 문제가 나왔다고 하자.

```txt
서버의 IPv4 주소를 192.168.10.20으로 설정하시오.
서브넷 마스크는 /24, 기본 게이트웨이는 192.168.10.1,
기본 DNS 서버는 192.168.10.2로 설정하시오.
```

이 문장에는 네 가지 값과 한 가지 검증 작업이 들어 있다.

| 문제 표현 | 실제 설정값 또는 작업 | 왜 필요한가 |
| --- | --- | --- |
| `192.168.10.20` | IP 주소 | 이 서버 자신의 주소 |
| `/24` | `255.255.255.0` | 같은 네트워크 범위 |
| `192.168.10.1` | 기본 게이트웨이 | 다른 네트워크로 나가는 출구 |
| `192.168.10.2` | DNS 서버 | 이름을 IP 주소로 찾는 서버 |
| 설정 후 확인 | `ipconfig /all` | 입력값이 실제 적용됐는지 검증 |

<Callout type="important">
문제 문장을 읽자마자 설정 화면을 열지 말자. 먼저 값을 표처럼 분리하면 게이트웨이와 DNS를 바꾸어 넣는 실수를 크게 줄일 수 있다.
</Callout>

## 실기 전체를 네 작업대로 나누기

실기 범위가 넓어 보여도 작업 장소로 나누면 길이 보인다.

| 작업대 | 대표 작업 | 검증의 예 |
| --- | --- | --- |
| Windows Server | IP, 계정, DNS, DHCP, IIS, FTP | `ipconfig`, 서비스 상태, 브라우저 |
| Linux | 사용자, 권한, 파일, 서비스, 네트워크 | `id`, `ls -l`, `systemctl`, `ip addr` |
| 라우터·스위치 | 인터페이스, 라우팅, ACL, NAT, VLAN | `show running-config`, `show ip route` |
| 네트워크·SQL | 서브넷 계산, 진단 명령, 쿼리 | 계산 결과, `ping`, SQL 실행 결과 |

Windows에서 DNS를 설정하는 문제와 Linux에서 사용자 권한을 바꾸는 문제는 둘 다 “설정 -> 검증” 구조지만, 사용하는 도구가 다르다. 이 구분이 실기 공부의 지도다.

## 첫 진단 과제: IP 설정값을 해석하고 검증하기

아래는 실제 장비나 Windows Server 환경에서 안전하게 해 볼 수 있는 기본 확인이다. 값을 바꾸지 않아도 된다.

<Steps>
### 현재 IP 설정을 확인한다

명령 프롬프트를 열고 아래 명령을 실행한다.

```bat
ipconfig /all
```

IPv4 주소, 서브넷 마스크, 기본 게이트웨이, DNS 서버가 어디에 표시되는지 찾는다.

### 각 값의 역할을 한 문장으로 적는다

예를 들어 기본 게이트웨이는 “내 네트워크 밖으로 통신할 때 처음 전달하는 장비”라고 적는다. 외우는 대신 자기 말로 설명한다.

### DNS 이름 해석을 확인한다

```bat
nslookup example.com
```

응답에 사용한 DNS 서버와 이름에 대응한 IP 주소가 표시되는지 확인한다. 실패했다면 인터넷 자체의 문제인지, DNS만의 문제인지 구분하는 출발점이 된다.

### 결과를 기록한다

IP 주소 전체를 공개할 필요는 없다. 사용한 명령, 확인한 항목, 성공·실패 여부만 실습 노트에 남긴다.
</Steps>

## 80분 시험에서 필요한 풀이 습관

최근 ICQA 공지는 네트워크관리사 2급 실기를 80분으로 안내한다. 시간 안에 작업하려면 어려운 문제를 오래 붙잡기보다 다음 순서를 반복하는 편이 낫다.

```txt
문제 읽기 -> 값 표시 -> 작업대 선택 -> 설정 -> 검증 -> 문제 문장 재대조
```

특히 마지막 재대조가 중요하다. 통신이 된다고 해도, 문제에서 요구한 보조 DNS나 특정 권한을 빠뜨렸을 수 있다.

## 지금부터의 학습 순서

1. IP 주소와 서브넷 계산을 먼저 익힌다. Windows, Linux, 라우터 문제의 공통 언어다.
2. Windows Server에서 IP, 계정, DNS, DHCP를 각각 따로 연습한다.
3. Linux에서는 사용자·권한·파일·서비스를 명령과 결과로 익힌다.
4. 라우터에서는 인터페이스 설정 -> 경로 -> ACL 순서로 쌓는다.
5. 설정 하나당 검증 명령 하나를 붙이고, 마지막에 통합 모의고사로 시간을 재 본다.

## 흔한 실수

- 메뉴 클릭 순서만 외우고 값을 해석하지 않기
- 설정 성공 메시지를 보고 검증을 생략하기
- Windows와 Linux에서 같은 기능의 확인 명령을 구분하지 못하기
- 오래된 실습 자료의 운영체제와 현재 공식 환경을 같은 것으로 가정하기

## 이번 편 정리

- 네트워크관리사 2급 실기는 조건 해석, 설정, 검증을 묶어서 요구한다.
- 문제의 값을 먼저 분리하면 실수를 줄일 수 있다.
- `ipconfig /all`, `nslookup`처럼 결과를 확인하는 도구부터 익힌다.
- 다음 편에서는 ICQA 에뮬레이터와 실습 환경을 준비한다.
