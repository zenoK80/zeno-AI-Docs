## 이번 편의 목표

- 실기시험이 확인하는 설정·계산·진단 능력을 설명한다.
- 문제를 읽고 설정한 뒤 검증하는 기본 순서를 익힌다.
- 앞으로 사용할 본사·지사 네트워크 실습 시나리오를 이해한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 네트워크 | 여러 장치가 정해진 규칙으로 데이터를 주고받는 연결 구조 |
| 노드 | 네트워크에 연결된 컴퓨터, 서버, 라우터 같은 장치 |
| 프로토콜 | 장치끼리 데이터를 주고받을 때 따르는 약속 |
| IP 주소 | 네트워크에서 장치를 구분하고 데이터의 목적지를 찾는 주소 |
| 서브넷 | 하나의 큰 IP 네트워크를 더 작은 범위로 나눈 것 |
| 서버 | 다른 장치의 요청을 받아 기능이나 데이터를 제공하는 컴퓨터 또는 프로그램 |
| 클라이언트 | 서버에 기능이나 데이터를 요청하는 장치 또는 프로그램 |
| 에뮬레이터 | 실제 시험 장비나 설정 화면과 비슷한 환경을 소프트웨어로 재현한 도구 |

실기에서는 화면 위치를 외우는 것보다 요구사항을 읽고 현재 상태를 확인한 뒤 설정하고 검증하는 순서가 중요하다.

## 주변 개념 지도

IP 설정, 서버 설정, 네트워크 명령은 서로 따로 보이지만 모두 “누가 누구에게 어떤 규칙으로 연결되는가”를 확인하는 작업이다. 문제가 생기면 물리 연결부터 주소, 서비스 순서로 범위를 좁힌다.

<Callout type="info">
설정값을 입력한 뒤 저장만 하고 끝내지 않는다. 주소 확인, 연결 시험, 서비스 상태 확인처럼 결과를 증명하는 단계가 실기의 핵심이다.
</Callout>

## 실기는 무엇을 평가할까?

네트워크관리사 2급 실기는 용어를 아는 데서 끝나지 않고, 주어진 조건을 주소와 설정값으로 바꾸고 결과를 확인하는 능력을 평가한다. 공식 안내 기준 시험 시간은 80분이며, 현재 시험 환경과 프로그램은 접수 전 ICQA 공지에서 다시 확인해야 한다.

```text
요구 사항 읽기 → 필요한 값 계산 → 설정 → 저장·적용 → 결과 검증
```

<Callout type="important">
화면 위치만 외우면 프로그램 버전이 바뀌었을 때 막힌다. 각 입력값의 의미와 설정 후 확인 방법을 함께 익힌다.
</Callout>

## 공통 실습 시나리오

이 시리즈에서는 본사와 지사 네트워크를 구성한다고 가정한다.

```text
본사 PC ─ 본사 스위치 ─ 본사 라우터 ═ 지사 라우터 ─ 지사 서버
```

- 본사 LAN: `192.168.10.0/24`
- 지사 LAN: `192.168.20.0/24`
- 본사 게이트웨이: `192.168.10.1`
- 지사 게이트웨이: `192.168.20.1`

실제 문제에서는 주소가 달라져도 `주소·마스크·게이트웨이·DNS`의 관계는 같다.

## 주요 학습 영역

| 영역 | 해야 하는 일 | 검증 관점 |
| --- | --- | --- |
| 케이블 | 규격에 맞게 배열과 결선을 판단한다. | 순서와 접촉 상태 |
| IP 계산 | 주소, 마스크, 네트워크 범위를 계산한다. | 네트워크·호스트·브로드캐스트 |
| Windows Server | 네트워크와 서버 역할을 설정한다. | 서비스 상태와 실제 동작 |
| 라우터 | 인터페이스, 경로, 접근 정책을 구성한다. | 설정 출력과 통신 |
| 네트워크 지식 | 명령과 프로토콜을 판별한다. | 계층과 목적 |

## 문제 해결의 다섯 단계

<Steps>
### 조건에 표시한다
IP 주소, 프리픽스, 게이트웨이, DNS, 계정, 경로처럼 입력해야 할 값을 표시한다.

### 계산과 설정을 분리한다
서브넷 계산은 메모 공간에서 끝낸 뒤 화면에 입력한다.

### 한 영역씩 설정한다
주소, 서비스, 권한을 한꺼번에 바꾸지 않는다.

### 저장과 적용을 확인한다
확인 버튼만 누른 것인지 실제 설정이 반영됐는지 구분한다.

### 명령 또는 기능으로 검증한다
`ipconfig`, `ping`, `nslookup`과 서비스 관리 화면 등으로 결과를 확인한다.
</Steps>

## 첫 진단 예시

본사 PC의 주소가 `192.168.10.25/24`, 게이트웨이가 `192.168.20.1`이다. 같은 본사 LAN 장치에는 통신되지만 외부로 나가지 못한다.

`/24`에서 PC의 네트워크는 `192.168.10.0/24`다. 게이트웨이는 같은 로컬 네트워크에서 직접 도달 가능해야 하는데 `192.168.20.1`은 다른 네트워크다. 이 경우 본사 게이트웨이 `192.168.10.1`로 수정해야 한다.

## 80분 연습 방법

- 1회차: 확실한 설정과 단답 문제부터 해결한다.
- 계산 문제: 주소를 2진수 또는 블록 크기로 검산한다.
- 마지막: 저장 누락, 오타, 인터페이스 선택을 확인한다.
- 연습 기록: 틀린 원인을 `계산`, `조건 누락`, `화면 조작`, `검증 부족`으로 나눈다.
