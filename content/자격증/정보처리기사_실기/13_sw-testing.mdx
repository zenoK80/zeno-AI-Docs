## 테스트 기법 분류

### 화이트박스 테스트 (구조적 테스트)

소스코드의 내부 구조를 알고 테스트합니다.

| 기법 | 설명 |
|------|------|
| 구문 커버리지 | 모든 구문을 한 번 이상 실행 |
| 결정 커버리지 | 모든 결정(분기)의 참/거짓 실행 |
| 조건 커버리지 | 각 조건의 참/거짓 모두 실행 |
| 경로 커버리지 | 모든 경로를 한 번 이상 실행 |

### 블랙박스 테스트 (기능적 테스트)

내부 코드를 모르고 입출력으로만 테스트합니다.

| 기법 | 설명 |
|------|------|
| 동치 분할(Equivalence Partitioning) | 입력값을 동등한 그룹으로 분할 |
| 경계값 분석(Boundary Value Analysis) | 경계 값에서 결함 발생 가능성 높음 |
| 결정 테이블(Decision Table) | 조건과 행동을 표로 표현 |
| 상태 전이 테스트 | 상태 변화를 검증 |
| 유스케이스 테스트 | 유스케이스를 기반으로 테스트 |

---

## 테스트 레벨 (4단계)

| 레벨 | 이름 | 대상 | 수행자 |
|------|------|------|--------|
| 1단계 | 단위 테스트(Unit Test) | 개별 모듈·함수 | 개발자 |
| 2단계 | 통합 테스트(Integration Test) | 모듈 간 인터페이스 | 개발팀 |
| 3단계 | 시스템 테스트(System Test) | 전체 시스템 | QA팀 |
| 4단계 | 인수 테스트(Acceptance Test) | 사용자 요구사항 | 사용자/고객 |

---

## 통합 테스트 방법

| 방법 | 설명 | 사용 더미 |
|------|------|----------|
| 하향식(Top-down) | 상위 모듈부터 테스트 | 스텁(Stub) - 하위 모듈 대체 |
| 상향식(Bottom-up) | 하위 모듈부터 테스트 | 드라이버(Driver) - 상위 모듈 대체 |
| 빅뱅(Big Bang) | 모든 모듈을 한 번에 통합 | 없음 (위험 높음) |
| 샌드위치 | 하향식 + 상향식 혼합 | 스텁 + 드라이버 |

---

## 테스트 용어

| 용어 | 설명 |
|------|------|
| 결함(Defect) | 소프트웨어의 버그나 오류 |
| 결함 밀도 | 모듈 크기 대비 결함 수 |
| 회귀 테스트 | 수정 후 기존 기능 재검증 |
| 성능 테스트 | 응답 시간, 처리량 측정 |
| 부하 테스트 | 예상 최대 부하에서 동작 확인 |
| 스트레스 테스트 | 한계 이상의 부하로 테스트 |
