## 소프트웨어 생명주기(SDLC) 모델

| 모델 | 특징 | 단점 |
|------|------|------|
| 폭포수(Waterfall) | 순차적, 단계별 완료 후 진행 | 요구사항 변경 어려움 |
| 프로토타이핑 | 원형 개발 후 요구사항 확정 | 관리 어려움 |
| 나선형(Spiral) | 위험 분석 + 반복 | 복잡, 비용 높음 |
| V 모델 | 개발-테스트 단계 대칭 | 폭포수와 유사한 경직성 |
| 반복 증분형 | 반복적 개발, 점진적 추가 | 인터페이스 문제 가능 |
| 애자일(Agile) | 짧은 스프린트, 변화 수용 | 문서화 부족 |

---

## 애자일 선언문 4대 핵심 가치

1. **프로세스와 도구**보다 **개인과 상호작용**
2. **포괄적인 문서**보다 **작동하는 소프트웨어**
3. **계약 협상**보다 **고객과의 협력**
4. **계획 따르기**보다 **변화에 대응**

## Scrum 프레임워크

### 주요 역할

| 역할 | 설명 |
|------|------|
| 제품 책임자(Product Owner) | 제품 백로그 관리, 우선순위 결정 |
| 스크럼 마스터(Scrum Master) | 팀 장애물 제거, Scrum 프로세스 지원 |
| 개발팀(Development Team) | 실제 개발 수행 |

### 주요 산출물

| 산출물 | 설명 |
|--------|------|
| 제품 백로그(Product Backlog) | 개발할 기능 전체 목록 |
| 스프린트 백로그(Sprint Backlog) | 이번 스프린트에 수행할 작업 |
| 번다운 차트(Burndown Chart) | 남은 작업량 추적 |

### 주요 이벤트

- **스프린트**(Sprint): 2-4주 반복 개발 주기
- **스프린트 계획 회의**: 스프린트 목표 및 작업 선정
- **일일 스크럼**(Daily Scrum): 매일 15분 진행 상황 공유
- **스프린트 검토**(Sprint Review): 완성된 기능 시연
- **스프린트 회고**(Sprint Retrospective): 개선사항 도출

---

## XP (eXtreme Programming)

### XP 핵심 실천법

| 실천법 | 설명 |
|--------|------|
| 페어 프로그래밍 | 두 명이 함께 코딩 |
| TDD (테스트 주도 개발) | 테스트 먼저 작성 후 코드 구현 |
| 지속적 통합(CI) | 자주 코드 통합 |
| 리팩토링 | 기능 변경 없이 코드 구조 개선 |
| 코드 공동 소유 | 누구나 코드 수정 가능 |
| 소규모 릴리스 | 짧은 주기로 배포 |

---

## 핵심 용어 암기

- 스프린트(Sprint): Scrum의 반복 개발 주기
- 번다운 차트: 잔여 작업량 시각화
- TDD: Test-Driven Development
- CI: Continuous Integration
- 페어 프로그래밍: XP 핵심 실천법
