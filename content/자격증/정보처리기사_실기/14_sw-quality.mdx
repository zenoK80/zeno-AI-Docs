## ISO/IEC 25010 소프트웨어 품질 특성

| 특성 | 영문 | 설명 |
|------|------|------|
| 기능 적합성 | Functional Suitability | 요구 기능을 정확히 제공 |
| 성능 효율성 | Performance Efficiency | 자원 대비 성능 |
| 호환성 | Compatibility | 다른 시스템과 공존/상호운용 |
| 사용성 | Usability | 사용 용이성 |
| 신뢰성 | Reliability | 지정 기간 동안 결함 없이 동작 |
| 보안성 | Security | 허가된 접근만 허용 |
| 유지보수성 | Maintainability | 수정/개선 용이성 |
| 이식성 | Portability | 다른 환경으로 이전 용이성 |

## CMMI (Capability Maturity Model Integration)

소프트웨어 프로세스 성숙도를 5단계로 평가합니다.

| 레벨 | 이름 | 설명 |
|------|------|------|
| 1 | 초기(Initial) | 프로세스 없음, 혼돈 |
| 2 | 관리(Managed) | 기본 프로세스 관리 |
| 3 | 정의(Defined) | 표준화된 프로세스 |
| 4 | 정량적 관리(Quantitatively Managed) | 성과 데이터로 관리 |
| 5 | 최적화(Optimizing) | 지속적 프로세스 개선 |

## 소프트웨어 측정 메트릭

| 메트릭 | 설명 |
|--------|------|
| LOC (Lines of Code) | 코드 라인 수 |
| McCabe의 복잡도 | V(G) = E - N + 2P (제어 흐름 복잡도) |
| 결함 밀도 | 결함 수 / 소프트웨어 크기 |
| 테스트 커버리지 | 테스트된 코드 비율 |

### 맥케이브(McCabe) 순환 복잡도

```
V(G) = E - N + 2P
  E: 엣지(간선) 수
  N: 노드(정점) 수
  P: 연결 컴포넌트 수 (보통 1)
```

복잡도가 낮을수록 테스트·유지보수가 용이합니다. 일반적으로 10 이하를 권장합니다.

---

## 소프트웨어 품질 활동

| 활동 | 설명 |
|------|------|
| SQA (소프트웨어 품질 보증) | 개발 프로세스 전반의 품질 활동 |
| 검증(Verification) | 올바르게 만들고 있는가? (개발 중 확인) |
| 확인(Validation) | 올바른 것을 만들고 있는가? (최종 요구사항 부합 확인) |
| 형상 관리(SCM) | 변경 통제, 버전 관리 |
