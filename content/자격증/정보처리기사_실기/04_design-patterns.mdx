## GoF 디자인 패턴 분류

### 생성 패턴 (Creational) — 객체 생성 방법

| 패턴 | 설명 |
|------|------|
| Singleton (싱글턴) | 인스턴스를 하나만 생성 |
| Factory Method (팩토리 메서드) | 객체 생성을 서브클래스에 위임 |
| Abstract Factory (추상 팩토리) | 관련 객체 그룹 생성 인터페이스 |
| Builder (빌더) | 복잡한 객체를 단계적으로 생성 |
| Prototype (프로토타입) | 기존 객체를 복제하여 생성 |

### 구조 패턴 (Structural) — 클래스/객체 조합

| 패턴 | 설명 |
|------|------|
| Adapter (어댑터) | 호환되지 않는 인터페이스 연결 |
| Bridge (브리지) | 추상과 구현을 분리 |
| Composite (컴포지트) | 트리 구조로 부분-전체 표현 |
| Decorator (데코레이터) | 객체에 동적으로 기능 추가 |
| Facade (파사드) | 복잡한 서브시스템에 단순 인터페이스 제공 |
| Flyweight (플라이웨이트) | 공유 객체로 메모리 효율화 |
| Proxy (프록시) | 다른 객체에 대한 대리자 제공 |

### 행위 패턴 (Behavioral) — 객체 간 알고리즘/책임

| 패턴 | 설명 |
|------|------|
| Chain of Responsibility | 처리 요청을 체인으로 전달 |
| Command (커맨드) | 요청을 객체로 캡슐화 |
| Iterator (이터레이터) | 컬렉션 순차 접근 방법 제공 |
| Mediator (미디에이터) | 객체 간 통신을 중재 |
| Memento (메멘토) | 객체 상태 저장/복원 |
| Observer (옵서버) | 상태 변화 시 의존 객체에 자동 알림 |
| State (스테이트) | 내부 상태에 따라 행동 변경 |
| Strategy (스트래티지) | 알고리즘 군을 캡슐화하여 교환 가능하게 |
| Template Method | 알고리즘 뼈대를 정의, 세부는 서브클래스가 구현 |
| Visitor (비지터) | 구조와 분리하여 새 연산 추가 |

## SOLID 원칙

| 원칙 | 영문 | 핵심 내용 |
|------|------|-----------|
| S | 단일 책임(SRP) | 클래스는 하나의 책임만 가져야 한다 |
| O | 개방-폐쇄(OCP) | 확장에는 열려 있고, 수정에는 닫혀 있어야 한다 |
| L | 리스코프 치환(LSP) | 자식 클래스는 부모 클래스를 대체할 수 있어야 한다 |
| I | 인터페이스 분리(ISP) | 클라이언트가 사용하지 않는 인터페이스에 의존 금지 |
| D | 의존 역전(DIP) | 구체 클래스보다 추상화에 의존해야 한다 |

## 주요 아키텍처 패턴

| 패턴 | 설명 |
|------|------|
| MVC | Model-View-Controller 분리 |
| MVP | Model-View-Presenter (View 수동적) |
| MVVM | Model-View-ViewModel (데이터 바인딩) |
| 파이프-필터 | 처리 단계를 파이프로 연결 |
| 레이어 | 시스템을 계층으로 분리 |
| MSA | 독립적 마이크로서비스로 구성 |
