## 요구사항 분류

| 유형 | 설명 | 예시 |
|------|------|------|
| 기능적 요구사항 | 시스템이 제공해야 할 기능 | 로그인, 결제, 검색 |
| 비기능적 요구사항 | 품질 속성 (성능, 보안, 가용성) | 응답시간 1초 이내 |
| 도메인 요구사항 | 특정 도메인의 규칙/제약 | 금융 규정, 의료법 |

---

## 요구사항 개발 프로세스

```
도출(Elicitation) → 분석(Analysis) → 명세(Specification) → 확인(Validation)
```

| 단계 | 설명 |
|------|------|
| 도출 | 인터뷰, 설문, 관찰 등으로 요구사항 수집 |
| 분석 | 요구사항 간 충돌 해결, 분류, 우선순위 설정 |
| 명세 | SRS(소프트웨어 요구사항 명세서) 작성 |
| 확인 | 요구사항 검토, 프로토타입으로 확인 |

---

## UML (Unified Modeling Language)

### 구조 다이어그램 (정적)

| 다이어그램 | 설명 | 활용 |
|------------|------|------|
| 클래스 다이어그램 | 클래스와 관계 표현 | 정적 구조 설계 |
| 객체 다이어그램 | 특정 시점의 인스턴스 | 클래스 다이어그램 예시 |
| 컴포넌트 다이어그램 | 컴포넌트와 인터페이스 | 소프트웨어 구조 |
| 배포 다이어그램 | 하드웨어-소프트웨어 배치 | 물리적 배치 설계 |
| 패키지 다이어그램 | 패키지 간 관계 | 모듈 구조 |

### 행위 다이어그램 (동적)

| 다이어그램 | 설명 | 활용 |
|------------|------|------|
| 유스케이스 다이어그램 | 사용자-시스템 상호작용 | 기능 요구사항 표현 |
| 시퀀스 다이어그램 | 시간 순서에 따른 메시지 흐름 | 동적 행위 설계 |
| 협력(통신) 다이어그램 | 객체 간 상호작용과 링크 | 구조 강조 |
| 상태 다이어그램 | 객체의 상태 변화 | 상태 기계 설계 |
| 활동 다이어그램 | 작업 흐름과 병렬 처리 | 업무 프로세스 |

---

## 클래스 다이어그램 관계

| 관계 | 기호 | 설명 |
|------|------|------|
| 연관(Association) | 실선 | 두 클래스의 관계 |
| 집합(Aggregation) | 빈 다이아몬드 | 전체-부분 (약한 소유) |
| 합성(Composition) | 채워진 다이아몬드 | 전체-부분 (강한 소유) |
| 의존(Dependency) | 점선 화살표 | 일시적 사용 관계 |
| 상속(Generalization) | 빈 삼각형 화살표 | IS-A 관계 |
| 실현(Realization) | 점선 + 빈 삼각형 | 인터페이스 구현 |

---

## 핵심 용어 암기

- SRS: Software Requirements Specification (소프트웨어 요구사항 명세서)
- 유스케이스: 사용자와 시스템 간의 상호작용 단위
- 액터(Actor): 시스템 외부의 사용자 또는 외부 시스템
- 시퀀스 다이어그램: 시간 순서에 따른 메시지 교환
