  실기에서는 정규화 단계의 정의와 이상현상(삽입, 삭제, 갱신)을 서술하는 문제, 주어진 테이블의 정규형을 판단하는 문제가 출제됩니다.
</Callout>

## 이상현상 (Anomaly)

정규화가 되어 있지 않은 테이블에서 데이터 조작 시 발생하는 문제입니다.

| 이상현상 | 설명 |
|----------|------|
| 삽입 이상(Insertion Anomaly) | 데이터 삽입 시 불필요한 데이터도 함께 삽입해야 하는 현상 |
| 삭제 이상(Deletion Anomaly) | 데이터 삭제 시 필요한 다른 데이터도 함께 삭제되는 현상 |
| 갱신 이상(Update Anomaly) | 중복 데이터 중 일부만 수정 시 데이터 불일치 발생 |

---

## 함수 종속성 (Functional Dependency)

- **완전 함수 종속**: 기본키 전체에 의존 (부분 종속 없음)
- **부분 함수 종속**: 복합키의 일부에만 의존
- **이행 함수 종속**: A → B → C (A가 B를 통해 C에 종속)

---

## 정규화 단계

### 제1정규형 (1NF)

**조건**: 모든 속성이 원자값(원자성)이어야 한다

- 반복 그룹, 다중값 속성 제거

### 제2정규형 (2NF)

**조건**: 1NF 만족 + 부분 함수 종속 제거

- 기본키가 복합키인 경우 적용
- 복합키의 일부에만 의존하는 속성을 별도 테이블로 분리

### 제3정규형 (3NF)

**조건**: 2NF 만족 + 이행 함수 종속 제거

- 기본키가 아닌 컬럼이 다른 비기본키 컬럼에 종속된 경우 분리

### 보이스-코드 정규형 (BCNF)

**조건**: 3NF 만족 + 결정자가 모두 후보키여야 함

- 3NF를 만족하지만 BCNF는 위반하는 경우 존재

---

## 정규화 단계 요약

| 정규형 | 제거하는 것 |
|--------|------------|
| 1NF | 반복 그룹, 다중값 |
| 2NF | 부분 함수 종속 |
| 3NF | 이행 함수 종속 |
| BCNF | 결정자가 후보키가 아닌 함수 종속 |

---

## 역정규화 (Denormalization)

성능 향상을 위해 의도적으로 정규화를 완화하는 것입니다.

- 조인 감소로 조회 성능 향상
- 데이터 중복 발생 (저장 공간 증가, 갱신 이상 가능)
- OLAP(분석 시스템)에서 주로 사용
