## 인터페이스 설계 방식

| 방식 | 설명 | 특징 |
|------|------|------|
| REST | HTTP 메서드 + JSON/XML | 단순, 경량, 웹 서비스 |
| SOAP | XML 기반 메시지 | 엄격한 표준, 보안 지원 |
| GraphQL | 클라이언트 정의 쿼리 | 필요한 데이터만 요청 |
| gRPC | Protocol Buffers + HTTP/2 | 고성능, 양방향 스트리밍 |

---

## REST API 설계 원칙

| 원칙 | 설명 |
|------|------|
| 자원 기반 URI | 명사로 자원 표현 (/users, /orders) |
| HTTP 메서드 활용 | GET/POST/PUT/PATCH/DELETE |
| 무상태(Stateless) | 서버가 클라이언트 상태 저장 안 함 |
| 계층 구조 | 클라이언트는 서버 구현을 몰라도 됨 |
| 캐시 가능 | 응답에 캐시 가능 여부 명시 |

### REST API URI 설계 예시

```
GET    /users          → 사용자 목록
GET    /users/1        → 사용자 1 조회
POST   /users          → 사용자 생성
PUT    /users/1        → 사용자 1 전체 수정
PATCH  /users/1        → 사용자 1 부분 수정
DELETE /users/1        → 사용자 1 삭제
GET    /users/1/orders → 사용자 1의 주문 목록
```

## EAI vs ESB

| 비교 | EAI | ESB |
|------|-----|-----|
| 이름 | Enterprise Application Integration | Enterprise Service Bus |
| 방식 | 포인트-투-포인트 통합 | 버스 기반 중앙 집중 통합 |
| 확장성 | 낮음 | 높음 |
| 활용 | 소규모 통합 | SOA 기반 대규모 통합 |

---

## 인터페이스 보안

| 기술 | 설명 |
|------|------|
| HTTPS/TLS | 전송 계층 암호화 |
| API 키(API Key) | 요청자 식별 및 인증 |
| OAuth 2.0 | 위임 권한 부여 프로토콜 |
| JWT | 토큰 기반 인증 |
| CORS | 교차 출처 리소스 공유 정책 |

---

## 인터페이스 구현 기술

| 기술 | 설명 |
|------|------|
| JSON | JavaScript 객체 표기법, REST 데이터 형식 |
| XML | 마크업 기반 데이터 형식, SOAP에서 사용 |
| Webhook | 이벤트 발생 시 서버가 클라이언트에 POST 요청 |
| Message Queue | 비동기 메시지 기반 통신 (RabbitMQ, Kafka) |
