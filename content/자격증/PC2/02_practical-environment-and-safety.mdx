## 정비는 바꾸기 전에 확인하는 일이다

PC 문제를 해결할 때 가장 위험한 실수는 원인을 모른 채 초기화, 포맷, BIOS 기본값 복원을 실행하는 것이다. 실기에서도 작업 전 상태 확인과 작업 후 검증이 중요하다.

## 작업 전 체크리스트

| 확인 항목 | 이유 |
| --- | --- |
| 문제에서 요구한 정확한 값 | 계정명, IP, 부팅 순서 등을 바꾸어 넣지 않기 위해 |
| 현재 상태 | 이미 설정된 값을 불필요하게 덮어쓰지 않기 위해 |
| 데이터 손실 가능성 | 파티션·포맷·초기화 작업의 위험을 알기 위해 |
| 되돌리는 방법 | 변경이 잘못됐을 때 복구하기 위해 |
| 검증 방법 | 작업 완료를 확인하기 위해 |

<Callout type="warning">
실제 PC에서 디스크 관리나 BIOS 설정을 연습할 때는 중요한 파일을 백업하고, 시험과 무관한 값은 바꾸지 않는다.
</Callout>

## 안전한 작업 흐름

```txt
문제 읽기 -> 현재 상태 기록 -> 필요한 값만 변경 -> 결과 확인 -> 문제와 재대조
```

예를 들어 장치 관리자의 노란 느낌표를 확인하는 작업은 드라이버를 즉시 삭제하는 문제가 아니다. 먼저 장치 이름, 오류 코드, 연결 상태를 확인해야 한다.

## 직접 확인하기

Windows에서 `Win + R` 후 `msinfo32`를 실행한다. BIOS 모드, 운영체제, 설치된 메모리를 읽고 메모장에 기록한다. 이 작업은 시스템 설정을 바꾸지 않으면서 정보를 읽는 연습이다.

## 이번 편 정리

- 작업 전 상태 기록과 작업 후 검증은 필수다.
- 복구가 어려운 작업은 마지막 선택지다.
- 다음 편에서는 PC가 켜질 때의 POST 단계를 기준으로 초기 장애를 구분한다.
