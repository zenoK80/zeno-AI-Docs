## 이번 편의 목표
- 실기에서 평가하는 하드웨어·운영체제 진단 능력을 설명한다.
- 증상, 가설, 확인, 조치, 재검증의 흐름을 익힌다.
- 데이터 손실을 막는 정비 원칙을 세운다.

## 부품 교체보다 먼저 해야 할 일

"전원은 들어오지만 화면이 나오지 않는다"는 증상만으로 메인보드 고장이라고 단정할 수 없다. 모니터 입력, 케이블, 메모리 접촉, 그래픽 장치, 전원 공급 등 여러 원인이 같은 증상을 만든다.

```text
증상 확인 → 안전 확보 → 가설 세우기 → 한 번에 하나씩 검사
→ 최소 조치 → 재검증 → 작업 기록
```

<Callout type="important">
정비의 핵심은 비싼 부품부터 바꾸는 것이 아니라, 위험이 낮고 확인 비용이 작은 항목부터 원인을 좁히는 것이다.
</Callout>

## 공식 시험과 학습 범위

ICQA 공식 안내 기준 PC정비사 2급 실기는 80분이며, 현재 공지에는 Windows 10과 Windows 11 환경이 안내되어 있다. 세부 환경은 변경될 수 있으므로 접수 전에 최신 공지를 확인한다.

| 영역 | 확인 능력 | 대표 사례 |
| --- | --- | --- |
| 안전과 도구 | 감전·정전기·데이터 손실 예방 | 전원 분리, ESD 관리 |
| 하드웨어 | 부품 역할, 호환성, 장착 상태 | CPU, RAM, 저장장치 |
| 부팅 | POST부터 OS 시작까지 진단 | 화면 없음, 부팅 장치 없음 |
| 운영체제 | 장치·디스크·서비스 상태 확인 | 장치 관리자, 디스크 관리 |
| 장애 처리 | 증상에서 원인을 체계적으로 좁힘 | 최소 구성, 교차 점검 |

## 공통 진단 시나리오

이 시리즈에서는 다음 PC를 계속 진단한다.

> 전원 버튼을 누르면 팬은 회전하지만 화면이 나오지 않거나 운영체제로 부팅되지 않는다.

먼저 증상을 더 구체화한다.

- 전원 LED와 팬은 동작하는가?
- 모니터 전원과 입력 소스는 맞는가?
- 경고음이나 진단 LED가 있는가?
- 제조사 로고 또는 UEFI 화면은 보이는가?
- 저장장치가 UEFI에 인식되는가?
- 오류 문구가 있다면 정확히 무엇인가?

## 진단 기록표

| 순서 | 관찰·조치 | 결과 | 다음 판단 |
| ---: | --- | --- | --- |
| 1 | 모니터 입력과 케이블 확인 | 정상 | 본체 POST 확인 |
| 2 | 진단 LED 확인 | DRAM LED 점등 | 메모리 장착 점검 |
| 3 | 전원 분리 후 메모리 재장착 | 화면 출력 | 메모리 접촉 문제 추정 |

기록은 같은 검사를 반복하거나 여러 부품을 동시에 바꾸는 실수를 줄인다.

## 실기 공부법

1. 부품 이름과 역할을 연결한다.
2. 증상마다 가능한 원인을 최소 세 개 적는다.
3. 위험이 낮고 빠른 검사 순서를 정한다.
4. 조치 후 원래 증상과 다른 기능까지 재확인한다.
5. 틀린 문제는 `지식`, `관찰`, `절차`, `안전`으로 분류한다.
