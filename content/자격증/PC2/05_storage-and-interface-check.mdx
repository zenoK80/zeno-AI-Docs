## 이번 편의 목표
- SATA와 NVMe, M.2의 관계를 정확히 구분한다.
- 저장장치가 UEFI와 Windows에서 인식되는 단계를 확인한다.
- 데이터 손실 위험 없이 케이블·슬롯·설정 문제를 좁힌다.

## 인터페이스와 형태를 구분하기

| 용어 | 의미 | 주의점 |
| --- | --- | --- |
| SATA | 저장장치 통신 인터페이스 | 2.5인치 장치는 데이터·전원 케이블 필요 |
| NVMe | PCIe 기반 저장장치를 위한 프로토콜 | SATA보다 병렬 처리에 적합 |
| M.2 | 카드의 물리적 형태와 커넥터 규격 | M.2라고 모두 NVMe는 아님 |

M.2 SSD는 SATA 방식일 수도, NVMe 방식일 수도 있다. 메인보드 슬롯이 해당 방식과 길이, 키를 지원하는지 설명서에서 확인한다.

<Callout type="important">
새 저장장치가 보이지 않는다고 곧바로 초기화하거나 포맷하지 않는다. 기존 데이터가 있는 장치라면 먼저 장치 정체와 백업 상태를 확인한다.
</Callout>

## SATA 장치 점검

2.5인치 SATA SSD에는 일반적으로 두 연결이 필요하다.

1. 메인보드와 연결하는 SATA 데이터 케이블
2. 파워서플라이와 연결하는 SATA 전원 케이블

인식되지 않으면 전원을 분리한 뒤 케이블 양 끝, 다른 SATA 포트, 정상 케이블을 하나씩 점검한다. 같은 케이블과 포트를 동시에 바꾸면 원인을 구분하기 어렵다.

## M.2 NVMe 장치 점검

- 슬롯이 NVMe/PCIe 방식을 지원하는가?
- SSD 길이와 고정 나사 위치가 맞는가?
- 커넥터 끝까지 비스듬히 삽입한 뒤 수평으로 고정했는가?
- 특정 SATA 포트와 대역폭을 공유해 비활성화되는 조합은 없는가?
- UEFI가 장치를 인식하는가?

대역폭 공유 조건은 메인보드마다 다르므로 공식 설명서의 저장장치 구성표를 본다.

## 인식 단계를 나눠 진단하기

```text
물리적 연결
→ UEFI 장치 인식
→ 운영체제 장치 인식
→ 파티션·파일 시스템 인식
→ 드라이브 문자와 파일 접근
```

| 관찰 | 다음 확인 |
| --- | --- |
| UEFI에도 없음 | 전원, 케이블, 슬롯, 호환성 |
| UEFI에는 있고 Windows 장치 관리자에도 있음 | 디스크 관리에서 파티션 상태 |
| 디스크 관리에는 있으나 탐색기에 없음 | 오프라인, 드라이브 문자, 파일 시스템 |
| 인식되지만 부팅되지 않음 | 부팅 순서, UEFI 방식, 부트로더 |

Windows에서는 다음 PowerShell 명령으로 읽기 전용 상태 확인을 시작할 수 있다.

```powershell
Get-Disk
Get-PhysicalDisk
```

상태를 확인하는 것과 초기화·파티션 생성은 다르다. 쓰기 작업 전에는 대상 디스크 번호를 다시 확인한다.

## 데이터 이상 신호

- 장치가 반복적으로 연결 해제된다.
- 읽기 속도가 급격히 떨어지거나 I/O 오류가 난다.
- SMART 또는 제조사 진단 도구가 경고한다.
- HDD에서 평소와 다른 반복 소음이 난다.

중요한 데이터가 있다면 반복 부팅과 대규모 검사를 멈추고 이미지 백업 또는 전문 복구를 고려한다. 장치 상태 확인 도구도 모든 고장을 미리 예측하지는 못한다.

## 사례 진단

새 NVMe SSD를 장착했는데 UEFI에는 보이고 Windows 탐색기에는 보이지 않는다.

1. 장치 관리자와 `Get-Disk`로 OS 인식 여부를 확인한다.
2. 기존 데이터가 없는 새 장치인지 확인한다.
3. 디스크 관리에서 오프라인 여부와 파티션 상태를 본다.
4. 새 빈 장치가 맞을 때만 요구 사항에 따라 초기화, 파티션, 파일 시스템, 드라이브 문자를 설정한다.

## 정리
저장장치 문제는 물리 연결, UEFI 인식, 운영체제 인식, 파티션, 파일 접근 단계로 나눠 진단한다. SATA·NVMe·M.2를 구분하고, 데이터가 있는 장치에는 파괴적인 조치를 서두르지 않는다.
