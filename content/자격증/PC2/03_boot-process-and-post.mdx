## 이번 편의 목표
- 전원, POST, UEFI, 부트로더, 운영체제 시작 단계를 구분한다.
- 화면과 진단 LED, 경고음으로 멈춘 단계를 추정한다.
- 부팅 장애를 최소 구성으로 안전하게 좁힌다.

## 부팅은 한 번에 일어나지 않는다

```text
전원 공급 → CPU 초기 실행 → POST → UEFI 장치 탐색
→ 부팅 장치 선택 → 부트로더 → 운영체제 커널 → 로그인
```

어디까지 진행됐는지 알면 조사 범위가 줄어든다.

| 증상 | 우선 의심할 단계 |
| --- | --- |
| LED와 팬 모두 반응 없음 | 전원 입력, 버튼, 파워서플라이 |
| 팬은 돌지만 화면·로고 없음 | POST, 메모리, CPU, 그래픽 출력 |
| UEFI에는 진입되나 부팅 장치 없음 | 저장장치 인식, 부팅 순서 |
| 운영체제 로고 뒤 오류 | 부트로더, 드라이버, OS 파일 |

## POST란?

POST는 전원이 켜진 뒤 펌웨어가 CPU, 메모리, 그래픽 등 기본 하드웨어를 초기화하고 점검하는 과정이다. 제조사와 보드에 따라 오류를 경고음, 숫자 코드, 진단 LED로 표시한다.

<Callout type="important">
경고음 횟수의 의미는 제조사와 펌웨어에 따라 다르다. 인터넷의 일반표로 단정하지 말고 해당 메인보드 설명서를 확인한다.
</Callout>

## 화면이 나오지 않을 때 순서

1. 모니터 전원, 입력 소스, 케이블을 확인한다.
2. 외장 그래픽 사용 시 케이블이 올바른 출력 단자에 연결됐는지 본다.
3. 메인보드 진단 LED와 경고음을 기록한다.
4. 전원을 분리하고 메모리 장착 상태를 점검한다.
5. CPU, 메모리 한 개, 필요한 그래픽, 전원만 남긴 최소 구성으로 확인한다.
6. 부품과 슬롯을 하나씩 교차 점검한다.

내장 그래픽 출력은 CPU가 내장 그래픽을 지원하고 메인보드가 해당 출력을 제공할 때만 사용할 수 있다.

## UEFI 화면이 보일 때

POST를 통과했다면 다음을 확인한다.

- CPU와 메모리 용량이 예상대로 인식되는가?
- 저장장치 모델명이 보이는가?
- 부팅 순서에 운영체제 장치가 있는가?
- 날짜와 시간이 계속 초기화되는가?
- 최근 바꾼 설정이 있는가?

저장장치가 인식되는데 "부팅 장치 없음"이 뜬다면 UEFI/Legacy 부팅 방식, 부트로더, 파티션 문제를 추가로 살펴야 한다.

## CMOS 초기화는 만능이 아니다

펌웨어 설정 오류가 의심될 때 제조사 절차에 따라 초기화를 고려할 수 있다. 하지만 RAID 모드, 보안 부팅, 사용자 지정 팬 설정 등이 바뀌어 기존 OS가 부팅되지 않을 수 있으므로 기존 설정을 먼저 기록한다.

## 정리
부팅 장애는 멈춘 단계부터 진단한다. 화면이 없으면 POST와 영상 경로, UEFI가 보이면 저장장치와 부팅 설정, OS 로고 이후면 소프트웨어 영역으로 범위를 좁힌다.
