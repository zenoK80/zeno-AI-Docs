## 분석 과제는 어떻게 찾아내는가

### 왜 필요한가

07편에서 CRISP-DM의 첫 단계가 "업무 이해"였던 것을 기억할 것이다. 그런데 그 업무 이해 단계에 들어가기 전에, 애초에 "우리가 풀어야 할 분석 과제가 무엇인가"부터 정해야 한다. 이 과제를 찾아내는 활동을 **분석 과제 발굴**이라 부르는데, 접근하는 방향에 따라 크게 두 갈래로 나뉜다. 하나는 이미 알고 있는 문제에서 출발해 위에서 아래로 좁혀가는 **하향식 접근법**(Top-Down Approach)이고, 다른 하나는 문제가 뚜렷하지 않을 때 데이터에서 아래에서 위로 통찰을 끌어올리는 **상향식 접근법**(Bottom-Up Approach)이다.

> **쉽게 말하면:** 하향식은 "문제는 이미 안다, 어떻게 풀지 찾자"이고, 상향식은 "문제가 뭔지도 모른다, 일단 데이터를 뒤져보자"이다.

## 하향식 접근법의 4단계

### 왜 필요한가

기업이 이미 겪고 있는 구체적인 문제(예: "특정 매장의 매출이 계속 떨어진다")가 있다면, 그 문제를 체계적으로 분해해 해결책을 찾아가는 절차가 필요하다. 하향식 접근법은 문제가 이미 인식된 상황에서 이를 데이터분석 문제로 정교하게 다듬어가는 4단계 절차다.

> **쉽게 말하면:** 하향식은 "큰 문제 → 작은 문제 → 해결 아이디어 → 실행 가능성 확인" 순서로 좁혀가는, 위에서 아래로 내려가는 깔때기다.

### 정의: 하향식 접근법의 4단계

<Steps>
1. **문제 탐색**(Problem Discovery): 아직 뚜렷하게 정리되지 않은 비즈니스 문제 후보들을 폭넓게 찾아내는 단계다. 크게 두 방향으로 탐색한다.
   - **비즈니스 모델 기반 탐색**: 기업의 업무 구조를 업무·제품·고객·규제와 감사·지원 인프라 등 영역으로 나눠, 각 영역에서 사회(Social)·기술(Technological)·경제(Economic)·환경(Environmental)·정치(Political) 등 거시적 관점(흔히 **STEEP** 분석이라 부른다)으로 기회 요인을 찾는다.
   - **외부 참조 모델 탐색**: 같은 업종이나 유사 업종의 경쟁사가 어떤 분석 과제를 수행했는지 **벤치마킹**(benchmarking, 우수 사례를 참고해 자기 조직에 적용하는 것)하거나, 이미 알려진 분석 유즈 케이스(use case, 활용 사례)를 참고한다.
2. **문제 정의**(Problem Definition): 문제 탐색에서 찾은 비즈니스 관점의 문제를, 데이터와 분석 알고리즘으로 풀 수 있는 형태의 **데이터 분석 문제**로 구체적으로 바꾼다. 예를 들어 "매출이 떨어진다"는 막연한 문제를 "최근 3개월간 재구매율이 낮아진 고객군의 특성은 무엇인가"처럼 분석 가능한 질문으로 다듬는다.
3. **해결방안 탐색**(Solution Search): 정의된 문제를 풀기 위한 방법을 찾는다. 이때 "이미 쓸 수 있는 분석 기법이 있는가"와 "이미 필요한 데이터가 확보되어 있는가"라는 두 기준으로 상황을 나눠 접근 방식을 결정한다.

   | 분석 기법 보유 여부 | 분석 데이터 보유 여부 | 취할 접근 |
   |---|---|---|
   | 있음 | 있음 | 기존 시스템을 개선하거나 방법을 고도화한다 |
   | 없음 | 있음 | 새로운 분석 방법을 발굴해 도입한다 |
   | 있음 | 없음 | 필요한 데이터를 추가로 확보한다 |
   | 없음 | 없음 | 전문 업체나 전문가의 도움을 받아 새로운 분석 기법 자체를 개발한다 |

4. **타당성 검토**(Feasibility Study): 선택된 해결방안이 실제로 실행 가능한지 두 측면에서 확인한다. **경제적 타당성**(비용 대비 효과, ROI)이 충분한지, **데이터 및 기술적 타당성**(필요한 데이터를 확보할 수 있고, 필요한 기술을 구현할 수 있는지)이 확보되는지를 검토한다. 타당성 검토를 통과해야 비로소 실제 프로젝트로 착수한다.
</Steps>

<Callout type="warning">
  **자주 틀리는 함정 (45회 기출)**: 4단계의 순서를 뒤섞은 보기가 반복 출제된다. 정답 순서는 **문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토**다. "문제 정의를 가장 먼저 한다"거나 "타당성 검토가 해결방안 탐색보다 앞선다"는 식으로 순서를 바꾼 보기가 오답으로 나온다. 또한 46회 기출에서는 "하향식 문제 탐색 단계의 탐색 기법이 아닌 것은?"이라는 문항에서 **데이터 기반 탐색**을 정답(하향식이 아닌 것)으로 골라야 했다. 데이터에서 출발하는 탐색은 하향식이 아니라 다음 절에서 다룰 **상향식**의 방식이기 때문이다.
</Callout>

## 상향식 접근법과 디자인 사고

### 왜 필요한가

반대로, 아직 무엇이 문제인지조차 뚜렷하지 않은 경우도 많다. 방대한 데이터는 쌓여 있는데 "이 데이터로 무엇을 할 수 있는지" 아무도 모르는 상황이다. 이럴 때는 문제를 미리 정의하고 위에서 아래로 좁혀가는 하향식 방식이 통하지 않는다. 대신 데이터 자체를 이리저리 탐색하며 "어? 이런 패턴이 있네"라는 통찰을 먼저 얻고, 그 통찰을 바탕으로 거꾸로 문제를 정의하는 방식이 필요하다. 이를 **상향식 접근법**(Bottom-Up Approach)이라 한다.

> **쉽게 말하면:** 상향식은 "일단 데이터를 파헤쳐 보고, 나온 패턴을 보면서 무슨 문제였는지 거꾸로 알아채는" 방식이다.

### 정의

상향식 접근법의 핵심 특징은 다음과 같다.

- **비지도학습**(unsupervised learning, "정답"이 미리 주어지지 않은 상태에서 데이터 자체의 구조나 패턴을 찾는 학습 방식)적 성격을 띤다. 군집분석이나 연관규칙분석처럼 "정답 레이블(label, 미리 붙여둔 정답 표시)이 없어도" 데이터 안의 패턴을 찾아내는 기법이 상향식과 잘 맞는다.
- **프로토타이핑**(prototyping, 완성품이 아닌 시제품을 빠르게 만들어 시험해 보는 방법)을 적극 활용한다. 완벽한 계획을 세우기보다 일단 작은 모델이나 시제품을 만들어 보고, 결과를 확인한 뒤 개선하는 시행착오를 반복한다.
- 문제를 명확히 정의하기 **어려운** 상황, 즉 확실한 구조나 가설이 주어지지 않은 상황에 적합하다.

이 "일단 만들어보고 시행착오를 통해 점진적으로 개선한다"는 사고방식은 **디자인 사고**(Design Thinking)와 정확히 맞닿아 있다. 디자인 사고는 원래 제품·서비스를 설계할 때 쓰이는 문제 해결 방법론으로, 사용자의 니즈를 관찰하고(공감) 아이디어를 내고(정의·구상) 시제품을 만들어(프로토타입) 실제로 테스트하는 과정을 반복한다. 상향식 접근법이 데이터 분석에 이 사고방식을 그대로 들여와, "완벽한 답을 한 번에 찾으려 하지 말고, 작게 시도하고 빠르게 검증하며 개선해 나가자"는 태도를 취하는 것이다.

### 하향식과 상향식, 무엇이 다른가

두 접근법의 가장 근본적인 차이는 "**시작할 때 무엇이 이미 정해져 있는가**"다.

| 구분 | 하향식 접근법 | 상향식 접근법 |
|---|---|---|
| 영문 표기 | Top-Down Approach | Bottom-Up Approach |
| 출발점 | 이미 인식된 비즈니스 문제 | 아직 정의되지 않은 데이터·현상 |
| 문제 정의 시점 | 분석을 시작하기 **전에** 문제를 먼저 정의한다 | 데이터를 탐색하는 **과정에서** 문제를 발견한다 |
| 진행 방식 | 문제 탐색부터 타당성 검토까지 정해진 순서로 순차 진행 | 프로토타이핑을 반복하며 시행착오로 점진 개선 |
| 학습 방식과의 연결 | 지도학습(정답이 있는 문제를 푸는 방식)적 성격에 가깝다 | 비지도학습적 성격에 가깝다 |
| 적합한 상황 | 문제와 데이터 구조가 비교적 명확할 때 | 문제 정의 자체가 어렵고 탐색이 필요할 때 |
| 관련 사고방식 | 체계적 분해(problem decomposition) | 디자인 사고(Design Thinking) |

<Callout type="warning">
  **자주 틀리는 함정 (44·46회 기출)**: "상향식 접근법은 확실한 구조와 데이터가 주어져야 한다" 또는 "이전 단계가 완성되어야만 다음 단계로 진행할 수 있다"는 보기가 오답으로 자주 나온다. 두 설명 모두 **하향식**의 특징을 상향식에 뒤바꿔 놓은 함정이다. "확실한 구조가 전제된다"는 하향식, "문제 정의가 어려운 상황에서 데이터로부터 출발한다"는 상향식이라는 대응을 정확히 구분해야 한다.
</Callout>

## 대상별 분석 기획 유형과의 연결

06편에서 다룬 것처럼, 데이터분석 기획은 **분석 대상**(무엇을 분석할지)과 **분석 방법**(어떻게 분석할지)이 각각 이미 알려져 있는지(Known) 아닌지(Unknown)에 따라 네 가지 유형(최적화, 통찰, 솔루션, 발견)으로 나뉜다(자세한 내용과 4분면 그림은 06편 참고).

이 네 유형은 지금까지 배운 하향식·상향식 접근법과 자연스럽게 짝을 이룬다.

| 분석 기획 유형 | 대상 | 방법 | 어울리는 접근법 |
|---|---|---|---|
| 최적화(Optimization) | Known | Known | 하향식 — 무엇을, 어떻게 분석할지 이미 알므로 곧바로 문제 정의로 들어간다 |
| 솔루션(Solution) | Unknown | Known | 하향식 — 방법은 알지만 어떤 대상에 적용할지가 문제 탐색의 핵심이 된다 |
| 통찰(Insight) | Known | Unknown | 상향식 — 무엇을 볼지는 알지만 어떤 방법이 통할지 모르므로 탐색적으로 시도한다 |
| 발견(Discovery) | Unknown | Unknown | 상향식 — 대상도 방법도 모르는 완전한 탐색 상황이라 데이터 자체에서 출발해야 한다 |

즉 대상과 방법이 어느 정도 정해져 있는 최적화·솔루션 유형은 하향식 절차(문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토)를 따르기 유리하고, 반대로 대상이나 방법 중 하나 이상이 불확실한 통찰·발견 유형은 상향식(데이터 탐색 → 프로토타이핑 → 반복 개선)이 더 잘 맞는다.

## 핵심 정리

- 분석 과제 발굴은 문제가 이미 정해진 하향식(Top-Down)과 문제가 정해지지 않은 상향식(Bottom-Up)으로 나뉜다.
- 하향식 접근법은 문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토의 4단계로 진행되며, 이 순서가 시험에서 자주 묻는 포인트다.
- 문제 탐색은 비즈니스 모델 기반 탐색과 외부 참조 모델(벤치마킹) 탐색으로 나뉘고, 데이터 기반 탐색은 하향식이 아니라 상향식의 방식이다.
- 상향식 접근법은 비지도학습적·탐색적 성격을 띠며, 프로토타이핑을 통한 시행착오와 디자인 사고 방법론으로 이어진다.
- 대상별 분석 기획 4유형 중 최적화·솔루션은 하향식과, 통찰·발견은 상향식과 자연스럽게 연결된다.
