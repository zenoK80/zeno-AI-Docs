## 이번 편의 목표

- NAT, 브리지, 호스트 전용 네트워크의 차이를 구분한다.
- 변경 전후를 비교하고 되돌릴 수 있는 실습 습관을 만든다.
- 명령 도움말과 로그를 스스로 찾는 기본 도구를 익힌다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 터미널 | 글자로 명령을 입력하고 결과를 확인하는 화면 |
| 관리자 계정(root) | 시스템의 거의 모든 설정과 파일을 변경할 수 있는 최고 권한 계정 |
| sudo | 허가받은 일반 사용자가 특정 명령만 관리자 권한으로 실행하게 하는 도구 |
| NAT | 가상 머신이 호스트를 거쳐 외부 네트워크를 사용하는 연결 방식 |
| 브리지 | 가상 머신을 실제 네트워크의 별도 컴퓨터처럼 연결하는 방식 |
| 호스트 전용 네트워크 | 호스트와 가상 머신끼리만 통신하도록 제한한 연결 방식 |
| 로그 | 시스템과 프로그램이 어떤 일이 있었는지 시간순으로 남긴 기록 |

좋은 실습 환경은 명령이 실행되는 것만으로 충분하지 않다. 잘못된 설정을 되돌릴 수 있고, 변경 전후 상태와 오류 메시지를 기록할 수 있어야 한다.

## 주변 개념 지도

네트워크 모드는 가상 머신이 누구와 통신할 수 있는지를 정한다. 관리자 권한은 무엇을 변경할 수 있는지를 정한다. 스냅샷과 로그는 실패했을 때 원인을 찾고 복구하는 데 사용한다.

<Callout type="info">
처음부터 root로 계속 작업하지 않는다. 일반 계정으로 상태를 확인하고 꼭 필요한 명령에만 sudo를 사용하는 습관을 들인다.
</Callout>

## 좋은 실습 환경의 조건

실습 환경은 명령이 한 번 실행되는 것보다 다음 세 가지가 중요하다.

1. 현재 상태를 명령으로 확인할 수 있다.
2. 잘못된 변경을 이전 상태로 되돌릴 수 있다.
3. 같은 작업을 처음부터 다시 반복할 수 있다.

이를 위해 가상 머신 이름은 `web01`, 일반 계정은 `labadmin`, 개인 실습 파일은 홈 디렉터리 아래에 둔다.

## 네트워크 모드 선택하기

| 모드 | 특징 | 적합한 실습 |
| --- | --- | --- |
| NAT | 가상 머신이 호스트를 통해 외부로 나간다. 외부에서 직접 접근하기는 어렵다. | 패키지 설치, 인터넷 연결 |
| 브리지 | 가상 머신이 실제 네트워크의 별도 장치처럼 보인다. | 다른 실제 장치와 통신 |
| 호스트 전용 | 호스트와 가상 머신 사이의 격리된 네트워크다. | 안전한 서버·클라이언트 실습 |

처음에는 NAT 어댑터 하나로 시작한다. 서버 간 고정 주소와 방화벽을 연습할 때 호스트 전용 어댑터를 추가하면 외부 네트워크에 영향을 덜 준다.

<Callout type="warning">
브리지 모드는 학교나 회사 네트워크 정책에 영향을 받을 수 있다. 허가 없이 DHCP, DNS 같은 서비스를 실제 네트워크에 열지 않는다.
</Callout>

## 실습 디렉터리 만들기

```bash
mkdir -p ~/lab/{files,permissions,network,services,logs}
find ~/lab -maxdepth 1 -type d | sort
```

`-p`는 필요한 상위 디렉터리까지 만들고, 이미 있어도 오류를 내지 않는다. `/etc` 같은 시스템 디렉터리는 해당 단원에서 목적과 복구 방법을 확인한 뒤 수정한다.

## 상태 기록 루틴

실습 시작 시 다음 파일을 만든다.

```bash
date -Is | tee ~/lab/logs/session.txt
whoami | tee -a ~/lab/logs/session.txt
hostnamectl --static | tee -a ~/lab/logs/session.txt
ip -br addr | tee -a ~/lab/logs/session.txt
```

`tee`는 출력을 화면에 보여 주면서 파일에도 저장한다. `-a`는 기존 내용을 지우지 않고 뒤에 추가한다.

설정 파일을 바꾸기 전에는 원본을 같은 위치에 복사하고 날짜를 붙인다.

```bash
sudo cp -a /etc/hosts /etc/hosts.bak
sudoedit /etc/hosts
diff -u /etc/hosts.bak /etc/hosts
```

`cp -a`는 가능한 한 원본 속성을 보존하고, `diff -u`는 어느 줄이 바뀌었는지 보여 준다. 실제 시험에서는 백업 요구 여부와 시간을 고려하되, 학습할 때는 변경 비교 습관을 들이는 것이 좋다.

## 스냅샷을 단계별로 나누기

| 시점 | 예시 이름 | 복구 목적 |
| --- | --- | --- |
| 설치 검증 직후 | `01-fresh-install` | 깨끗한 초기 상태 |
| 네트워크 확인 후 | `02-network-ready` | 통신 가능한 상태 |
| 서비스 실습 전 | `03-before-services` | 설정 실패 전 상태 |

스냅샷을 만들기 전에는 가능하면 가상 머신을 정상 종료한다. 이름만 보고 상태를 알 수 있도록 설명도 남긴다.

## 도움말을 찾는 세 단계

처음 보는 명령을 추측해서 실행하지 말고 로컬 도움말부터 확인한다.

```bash
ip --help
man ip
apropos "network interface"
```

- `--help`: 자주 쓰는 옵션을 빠르게 확인한다.
- `man`: 명령의 전체 설명과 옵션을 읽는다.
- `apropos`: 원하는 기능과 관련된 매뉴얼 이름을 찾는다.

매뉴얼에서 `/PATTERN`을 입력하면 검색하고, `n`으로 다음 결과로 이동하며, `q`로 종료한다.

## 작은 검증 실습

```bash
cd ~/lab/files
printf 'before\n' > config.txt
cp -a config.txt config.txt.bak
printf 'after\n' > config.txt
diff -u config.txt.bak config.txt
cp -a config.txt.bak config.txt
cat config.txt
```

이 실습은 `변경 전 백업 → 변경 → 차이 확인 → 복구 → 복구 확인`의 전체 흐름을 보여 준다. 마지막 출력은 `before`여야 한다.

좋은 실습 환경은 네트워크가 연결된 환경이 아니라 변경과 검증, 복구를 반복할 수 있는 환경이다. 다음 편에서는 이 환경 위에서 커널, 셸, 프로세스, 파일 시스템의 관계를 살펴본다.
