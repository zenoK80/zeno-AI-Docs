## 운영체제는 무엇을 하는가?

운영체제(OS)는 프로그램이 CPU, 메모리, 디스크, 네트워크 같은 하드웨어를 안전하고 효율적으로 쓰게 해 주는 시스템 소프트웨어입니다. 사용자는 보통 프로그램을 실행하지만, 실제 자원 배분은 운영체제가 맡습니다.

| 자원 | 운영체제의 역할 | 리눅스에서 확인하는 예 |
| --- | --- | --- |
| CPU | 실행할 작업의 순서와 시간을 배분 | `ps`, `top` |
| 메모리 | 프로세스별 메모리 공간 관리 | `free`, `vmstat` |
| 디스크 | 파일을 저장하고 권한을 관리 | `df`, `ls -l` |
| 장치/네트워크 | 장치와 통신을 중개 | `ip`, `lsblk` |

## 커널, 셸, 명령의 관계

리눅스를 사용할 때 자주 만나는 요소를 층으로 나누면 이해가 쉬워집니다.

```text
사용자
  -> 셸(bash 등): 명령을 해석
    -> 커널: 하드웨어와 시스템 자원 관리
      -> CPU, 메모리, 디스크, 네트워크 장치
```

### 커널

커널(Kernel)은 운영체제의 핵심입니다. 프로그램이 파일을 읽거나 프로세스를 만들거나 네트워크로 데이터를 보낼 때, 커널이 실제 자원 접근을 중개합니다.

### 셸

셸(Shell)은 사용자가 입력한 명령을 해석해 실행하도록 돕는 프로그램입니다. Rocky Linux에서 흔히 사용하는 `bash`도 셸의 하나입니다.

```bash
echo "$SHELL"
ps -p $$ -f
```

`$SHELL`은 기본 셸 정보를 보여 주고, `$$`는 현재 셸 프로세스의 번호(PID)를 뜻합니다.

### 시스템 콜

응용 프로그램이 파일 열기나 프로세스 생성 같은 운영체제 기능을 요청하는 통로를 시스템 콜이라고 합니다. 시험에서 내부 구현까지 깊게 다루지 않더라도, 프로그램이 하드웨어를 직접 제어하는 대신 운영체제에 요청한다는 흐름은 알아 두면 좋습니다.

## 프로세스와 프로그램은 다르다

프로그램은 디스크에 저장된 실행 파일이고, 프로세스는 그 프로그램이 메모리에서 실행 중인 상태입니다. 같은 프로그램을 두 번 실행하면 일반적으로 프로세스도 두 개가 됩니다.

```bash
sleep 120 &
ps -ef | grep '[s]leep'
jobs
```

`sleep 120 &`는 백그라운드에서 잠시 대기하는 프로세스를 하나 만듭니다. `ps`와 `jobs`로 확인한 뒤, 실습이 끝나면 작업 번호를 이용해 종료할 수 있습니다.

```bash
kill %1
```

프로세스 종료는 대상이 무엇인지 먼저 확인하고 실행해야 합니다. 특히 관리자 권한에서 무작정 `kill` 명령을 쓰면 중요한 서비스를 멈출 수 있습니다.

## 파일 시스템과 디렉터리

리눅스는 `/`를 최상위로 하는 하나의 디렉터리 트리로 파일을 관리합니다. 윈도우의 드라이브 문자와 달리, 다른 디스크나 장치도 특정 디렉터리에 연결(mount)해서 사용합니다.

| 경로 | 일반적인 역할 |
| --- | --- |
| `/home` | 일반 사용자 홈 디렉터리 |
| `/etc` | 시스템 설정 파일 |
| `/var` | 로그, 캐시처럼 변하는 데이터 |
| `/tmp` | 임시 파일 |
| `/usr` | 사용자 명령과 라이브러리 등 |

이 경로는 암기용 목록이 아니라 문제를 만났을 때 "설정은 어디에 있을까, 로그는 어디에서 볼까"를 추론하는 기준입니다.

## 짧은 확인 실습

```bash
uname -a
hostnamectl
pwd
ls /
ps -e | head
```

각 명령이 운영체제의 어떤 영역을 보여 주는지 말로 설명해 보세요. 커널 정보, 시스템 식별 정보, 파일 시스템, 실행 중인 프로세스가 각각 연결됩니다.

## 이번 편 정리

- 운영체제는 하드웨어 자원을 프로그램에 배분하고 보호한다.
- 커널은 핵심 관리 역할을, 셸은 사용자 명령 해석 역할을 한다.
- 프로그램은 파일이고 프로세스는 실행 중인 상태다.
- 리눅스 디렉터리 구조는 설정과 로그의 위치를 찾는 기준이 된다.
