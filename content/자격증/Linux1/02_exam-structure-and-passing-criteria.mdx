## 이번 편의 목표

- 1차와 2차 시험이 각각 무엇을 평가하는지 구분한다.
- 합격 기준과 과락을 고려해 점수 전략을 세운다.
- 이론 공부와 실습을 함께 진행하는 주간 학습법을 만든다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 1차 시험 | 기본 개념과 명령·설정 지식을 주로 확인하는 단계 |
| 2차 시험 | 더 깊은 관리 지식과 문제 해결 능력을 확인하는 단계 |
| 과락 | 전체 점수와 별개로 특정 영역의 최소 점수를 넘지 못한 상태 |
| 명령 옵션 | 같은 명령의 동작 방법을 바꾸는 추가 지정값 |
| 표준 출력 | 명령을 실행했을 때 터미널에 기본으로 표시되는 결과 |
| 종료 상태 | 명령이 성공했는지 실패했는지 프로그램이 남기는 값 |
| 검증 | 설정 후 실제 상태가 의도대로 바뀌었는지 다시 확인하는 과정 |

시험 정보는 회차별 공고가 최종 기준이다. 이 편에서는 숫자 암기보다 1차와 2차의 역할 차이, 과락을 피하는 점수 계획, 이론을 실습으로 연결하는 법을 익힌다.

## 주변 개념 지도

명령을 안다는 것은 이름을 기억하는 것보다 목적, 주요 옵션, 예상 결과, 실패할 때 확인할 위치를 설명할 수 있다는 뜻이다. 필기형 문제도 실제 시스템 상태를 떠올리면 선택지를 더 정확히 구분할 수 있다.

<Callout type="warning">
시험 일정과 합격 기준은 최신 공식 공고를 확인한다. 학습 문서의 숫자가 공고와 다르면 공고가 우선이다.
</Callout>

## 1차와 2차가 나뉘는 이유

시스템 관리자는 개념을 알아야 할 뿐 아니라 실제 환경을 확인하고 설정할 수 있어야 한다. 그래서 리눅스마스터 1급은 객관식 중심의 1차와 단답·서술 및 작업형 중심의 2차로 나뉜다.

| 구분 | 공식 안내 기준 형식 | 주로 확인하는 능력 |
| --- | --- | --- |
| 1차 | 객관식 100문항, 100분 | 넓은 범위의 개념과 명령어 판단 |
| 2차 | 단답·서술형 10문항과 작업형 5~7문항, 100분 | 상황 해석, 명령 선택, 실제 설정 |

각 시험은 100점 만점에 60점 이상이 합격 기준이다. 1차는 과목별 득점이 40% 미만이면 전체 점수가 높아도 과락이 될 수 있다.

<Callout type="warning">
시험 형식, 배점, 사용 배포판은 변경될 수 있다. 접수 전에는 반드시 KAIT의 최신 종목 안내와 공지사항을 다시 확인한다.
</Callout>

## 점수 전략 세우기

1차에서 한 영역만 깊게 파는 전략은 위험하다. 과락을 피하려면 먼저 전 영역의 기본 문제를 맞힐 수 있게 만든 뒤, 자주 틀리는 영역을 보강해야 한다.

예를 들어 세 과목 점수가 `80, 75, 35`라면 평균은 약 63.3점이지만 35점 과목이 40% 미만이므로 합격할 수 없다. 반대로 `65, 60, 55`는 평균 60점이고 과락도 없다.

### 1차 시간 배분 예시

100문항을 100분에 푼다면 문항당 평균 1분이다.

- 1회차 65분: 바로 판단되는 문제를 먼저 푼다.
- 2회차 25분: 표시해 둔 문제를 다시 검토한다.
- 마지막 10분: 답안 누락과 과목별 미응답을 확인한다.

한 문제에 오래 머물면 뒤의 쉬운 문제를 놓친다. 모르는 문제는 표시하고 넘어가는 연습이 필요하다.

## 2차는 결과가 아니라 과정까지 연습한다

작업형 준비에서는 명령이 한 번 성공한 것으로 끝내지 않는다.

<Steps>
### 요구 사항을 동작 단위로 나눈다
사용자 생성, 권한 변경, 서비스 활성화처럼 채점 가능한 결과로 분리한다.

### 변경 전 상태를 확인한다
같은 명령이라도 현재 파일, 서비스, 네트워크 상태에 따라 결과가 달라질 수 있다.

### 최소한으로 변경한다
관련 없는 설정까지 수정하면 원인을 추적하기 어려워진다.

### 명령과 설정 파일로 검증한다
서비스가 실행 중인지, 재부팅 후에도 유지되는지, 요구한 권한이 맞는지 확인한다.
</Steps>

예를 들어 `httpd` 서비스를 지금 시작하고 부팅 시에도 자동 시작하도록 하라는 문제라면 다음처럼 구분한다.

```bash
sudo systemctl enable --now httpd
systemctl is-enabled httpd
systemctl is-active httpd
```

첫 줄은 변경이고, 뒤의 두 줄은 각각 부팅 시 자동 시작 여부와 현재 실행 여부를 검증한다.

## 이론과 실습을 연결하는 주간 계획

| 요일 | 학습 | 결과물 |
| --- | --- | --- |
| 월 | 개념 읽기 | 핵심 용어 10개와 관계도 |
| 화 | 명령어 기본 실습 | 목적·명령·출력 기록 |
| 수 | 설정 파일 실습 | 원본과 변경본 비교 |
| 목 | 장애 상황 연습 | 진단 순서와 복구 기록 |
| 금 | 객관식 문제 | 오답 원인 분류 |
| 주말 | 제한 시간 종합 실습 | 걸린 시간과 재학습 목록 |

오답 노트에는 정답만 적지 않는다. `개념 부족`, `출력 해석 실수`, `명령 옵션 혼동`, `시간 부족`처럼 틀린 이유를 분류해야 다음 학습이 달라진다.
