## 01편 복습

본문을 덮고 먼저 기억나는 내용을 떠올려 보자. 답이 바로 나오지 않아도 괜찮다. 직접 답한 뒤 해설과 비교해야 무엇을 다시 볼지 알 수 있다.

<Callout type="info">
문제를 먼저 풀고 나서 정답을 확인한다. 틀린 문제는 정답만 외우지 말고, 본문의 어떤 개념을 놓쳤는지 한 줄로 기록한다.
</Callout>

## 직접 풀어보기

### 문제 1

웹 서버에 접속되지 않는다. 다음 중 가장 먼저 해야 할 행동은 무엇인가?

1. 서버를 즉시 재설치한다.
2. 관련 설정 파일을 전부 삭제한다.
3. 현재 네트워크와 서비스 상태를 확인한다.
4. 원인을 확인하지 않고 방화벽을 끈다.

### 문제 2

`systemctl --failed`에 `httpd.service`가 보인다. 다음 확인 대상으로 가장 적절한 것은 무엇인가?

1. 웹 서비스 상태와 로그
2. 키보드 배열
3. 사용자 바탕화면
4. 모니터 해상도

### 문제 3

명령 실행 결과만 복사해 두는 것보다 `목적-명령-관찰-판단`을 함께 기록해야 하는 이유를 한 문장으로 적어 보자.

## 정답과 해설

1. **3번**. 변경 전에 현재 상태를 수집해야 원인을 좁히고 불필요한 조치를 피할 수 있다.
2. **1번**. `systemctl status httpd`와 `journalctl -u httpd` 등으로 실패 원인을 확인한다.
3. 원인과 조치의 관계를 설명하고, 변경이 실패했을 때 안전하게 되돌아가기 위해서다.

## 자주 하는 실수

- 명령어 이름만 외우고 출력의 의미를 읽지 않는다.
- 오류가 나면 여러 설정을 한꺼번에 바꾼다.
- `root` 권한으로 모든 실습을 진행해 권한 차이를 놓친다.
- 변경 후 서비스 상태나 실제 접속을 다시 확인하지 않는다.
