## 왜 전처리가 필요한가

현실의 데이터는 깨끗하지 않습니다. 설문지에 빈 칸이 있고, 센서가 오작동해 -999 같은 값이 들어오고, 날짜 형식이 제각각입니다. 분석 모델은 이런 오염된 데이터를 그대로 넣으면 엉터리 결과를 냅니다. 전처리는 **원본 데이터 → 분석 가능한 깨끗한 데이터**로 만드는 과정입니다.

| 단계 | 목적 | 대표 작업 |
|------|------|-----------|
| 1. 결측치 처리 | 빠진 값 채우기 | 평균 대치, KNN 대치 |
| 2. 이상치 처리 | 극단값 제거·수정 | IQR 방법, Z-score |
| 3. 데이터 변환 | 스케일·분포 맞추기 | 정규화, 표준화, 로그 변환 |
| 4. 범주형 인코딩 | 문자 → 숫자 | Label Encoding, One-Hot Encoding |
| 5. 데이터 정제 | 형식 통일 | 중복 제거, 날짜·단위 통일 |

## 결측치 처리

결측치(Missing Value)란 값이 존재하지 않는 셀입니다. `NaN`, `NULL`, 공백 등으로 표시됩니다.

### 예시 데이터

| 고객ID | 나이 | 구매금액(만원) | 성별 |
|--------|------|---------------|------|
| A001 | 25 | 12 | 남 |
| A002 | **?** | 18 | 여 |
| A003 | 32 | **?** | 남 |
| A004 | 28 | 9 | **?** |
| A005 | 35 | 22 | 여 |

### 처리 방법 비교

| 방법 | 설명 | 장점 | 단점 | 적합 상황 |
|------|------|------|------|-----------|
| **완전 제거 **(Listwise) | 결측 있는 행 전체 삭제 | 구현 쉬움, 분석 깔끔 | 데이터 손실, 편향 발생 가능 | 결측 비율 5% 미만, 무작위 결측 |
| **평균 대치** | 연속형 변수에 평균값으로 채움 | 빠르고 간단 | 분산 감소, 이상치 영향 | 결측 적고 정규분포에 가까울 때 |
| **중앙값 대치** | 정렬 후 중앙값으로 채움 | 이상치에 강건 | 분포 왜곡 가능 | 이상치가 있는 연속형 변수 |
| **최빈값 대치** | 가장 많이 나온 범주로 채움 | 범주형에 자연스러움 | 특정 범주 과대 표현 | 범주형 변수 |
| **KNN 대치** | 유사 K개 행 평균으로 채움 | 정확도 높음 | 계산 비용 큼 | 패턴이 복잡한 데이터 |
| **다중 대치 **(MI) | 여러 값 생성 후 통합 | 통계적으로 가장 엄밀 | 구현 복잡 | 고급 분석, 결측 비율 높을 때 |

**평균 대치 예시 계산:**
- 나이 결측(A002): 알려진 나이 = 25, 32, 28, 35 → 평균 = $(25 + 32 + 28 + 35) / 4 = 120 / 4 = \mathbf{30}$
- A002의 나이를 30으로 채움

<Callout type="warning">
  **평균 대치의 함정:** 평균으로 채우면 해당 변수의 분산이 줄어듭니다. 결측이 많을수록 분포가 인위적으로 뾰족해져 통계 분석 결과가 왜곡됩니다.
</Callout>

## 이상치(Outlier) 탐지 및 처리

이상치는 다른 데이터와 동떨어진 극단값입니다. **진짜 이상한 값**(입력 실수, 센서 오류)인지 **실제 드문 케이스**(초고소득자)인지 판단이 중요합니다.

### IQR 방법 — 직접 계산

**데이터:** [4, 7, 8, 9, 10, 11, 12, 13, 14, 50]

**1단계: 정렬**
[4, 7, 8, 9, 10, 11, 12, 13, 14, 50] ← 이미 정렬됨

**2단계: 사분위수 계산 **(n=10)
- Q1(25번째 백분위): 하위 절반 [4, 7, 8, 9, 10]의 중앙값 = **8**
- Q3(75번째 백분위): 상위 절반 [11, 12, 13, 14, 50]의 중앙값 = **13**
- IQR = Q3 − Q1 = 13 − 8 = **5**

**3단계: 이상치 경계 계산**

$$\text{하한} = Q1 - 1.5 \times IQR = 8 - 1.5 \times 5 = 8 - 7.5 = 0.5$$

$$\text{상한} = Q3 + 1.5 \times IQR = 13 + 1.5 \times 5 = 13 + 7.5 = 20.5$$

**판정:** 50 > 20.5이므로 **50은 이상치**, 4 > 0.5이므로 4는 정상

### Z-score 방법

$$Z = \frac{x - \mu}{\sigma}$$

$|Z| > 3$ 이면 이상치로 판단합니다. 정규분포를 가정할 때 유효합니다.

### 이상치 처리 방법 비교

| 방법 | 설명 | 적합한 상황 |
|------|------|-------------|
| **제거** | 이상치 행 삭제 | 입력 오류가 확실할 때 |
| **평균/중앙값 대치** | 통계값으로 교체 | 데이터 손실을 피하고 싶을 때 |
| **Capping** | 상한/하한 경계값으로 대체 | 극단값을 줄이되 행을 보존할 때 |
| **별도 모델링** | 이상치만 따로 분석 | 이상치가 의미 있는 현상(사기 탐지) |

**Capping 예시:** 50 → 20.5(상한값)으로 교체

## 데이터 변환

### 정규화(Normalization) — Min-Max

$$x' = \frac{x - x_{min}}{x_{max} - x_{min}}$$

결과: 항상 **0~1** 사이 값

**예시:** 키 데이터 [150, 160, 170, 180, 190]에서 키 165의 정규화 값

$$x' = \frac{165 - 150}{190 - 150} = \frac{15}{40} = 0.375$$

**사용 시점:** KNN, 신경망 등 거리·크기에 민감한 알고리즘

### 표준화(Standardization) — Z-score

$$x' = \frac{x - \mu}{\sigma}$$

결과: **평균 0, 표준편차 1** (음수도 가능)

**예시:** 키 데이터 $\mu = 170$, $\sigma = 15.8$일 때 키 185의 표준화 값

$$x' = \frac{185 - 170}{15.8} = \frac{15}{15.8} \approx 0.95$$

**사용 시점:** 회귀분석, SVM, 이상치가 있는 데이터

### 로그 변환

$$x' = \log(x + 1)$$

오른쪽으로 치우친(positively skewed) 분포를 정규분포에 가깝게 만듭니다.

**예시:** 소득 데이터 [100, 200, 300, 5000, 10000]

| 원본 | 로그 변환 후 |
|------|-------------|
| 100 | $\log(101) \approx 2.00$ |
| 200 | $\log(201) \approx 2.30$ |
| 300 | $\log(301) \approx 2.48$ |
| 5000 | $\log(5001) \approx 3.70$ |
| 10000 | $\log(10001) \approx 4.00$ |

→ 극단값의 영향이 줄어들어 분포가 균형 잡힙니다.

## 범주형 인코딩

머신러닝 모델은 문자를 처리하지 못하므로 숫자로 변환해야 합니다.

### Label Encoding — 순서형 변수에 사용

범주를 정수로 변환합니다.

- 학점(순서 있음): A→3, B→2, C→1, D→0
- 만족도: 매우만족→4, 만족→3, 보통→2, 불만족→1, 매우불만족→0

### One-Hot Encoding — 명목형 변수에 사용

각 범주를 별도의 이진(0/1) 열로 분리합니다.

| 지역 | 서울 열 | 부산 열 | 대구 열 |
|------|---------|---------|---------|
| 서울 | 1 | 0 | 0 |
| 부산 | 0 | 1 | 0 |
| 대구 | 0 | 0 | 1 |

<Callout type="warning">
  **Label Encoding의 함정:** 혈액형에 Label Encoding을 쓰면 A=0, B=1, O=2처럼 되어 모델이 "O > B > A"라는 잘못된 순서 정보를 학습합니다. 명목형에는 반드시 One-Hot Encoding을 사용하세요.
</Callout>

## 데이터 정제

### 중복 제거

같은 데이터가 두 번 이상 들어온 경우 하나만 남기고 삭제합니다. 시스템 오류나 병합 시 발생합니다.

### 형식 통일

- **날짜:** `2024-01-15`, `2024/01/15`, `Jan 15 2024` → 하나의 형식으로 통일
- **대소문자:** `Seoul`, `seoul`, `SEOUL` → 통일
- **전화번호:** `010-1234-5678`, `01012345678` → 통일

### 단위 통일

- 키: cm와 m 혼재 → 전부 cm로 변환
- 무게: kg와 g 혼재 → 전부 kg로 변환
- 통화: 원과 달러 혼재 → 기준 환율 적용 후 통일

## 핵심 정리

- **결측치 처리 복잡도 순서:** 완전 제거 → 단순 대치(평균/중앙값/최빈값) → KNN 대치 → 다중 대치
- **연속형 결측 대치:** 이상치 없으면 평균, 이상치 있으면 중앙값
- **이상치 탐지 IQR:** 하한 = Q1 − 1.5×IQR, 상한 = Q3 + 1.5×IQR
- **이상치 탐지 Z-score:** $|Z| > 3$ 이면 이상치
- **정규화:** $[0, 1]$로 압축, Min-Max 공식
- **표준화:** 평균 0, 표준편차 1, Z-score 공식
- **로그 변환:** 오른쪽 꼬리 분포(양의 왜도)에 적용
- **인코딩:** 순서형 → Label Encoding, 명목형 → One-Hot Encoding
