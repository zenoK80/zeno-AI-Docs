## 모델링의 일반 절차

머신러닝 프로젝트는 아래 7단계를 순서대로 진행합니다. 단계를 건너뛰거나 순서가 바뀌면 결과를 신뢰할 수 없습니다.

| 단계 | 이름 | 주요 활동 |
|------|------|-----------|
| 1 | 문제 정의 | 분류인가 회귀인가, 성공 기준(KPI)은 무엇인가 |
| 2 | 데이터 수집 | 내부 DB, 크롤링, 공공 데이터, API |
| 3 | 전처리 | 결측치 처리, 이상치 제거, 스케일링, 인코딩 |
| 4 | 모델 선택 | 문제 유형·데이터 크기에 맞는 알고리즘 선택 |
| 5 | 학습 | 학습 데이터로 파라미터 추정 |
| 6 | 평가 | 테스트 데이터로 최종 성능 측정 |
| 7 | 배포 | 서비스 연동, 모니터링, 재학습 스케줄 수립 |

<Callout type="warning">
  **데이터 누수 주의:** 스케일링·인코딩 등 전처리 기준은 반드시 **학습 데이터**에서만 산출해야 합니다. 테스트 데이터의 통계를 전처리에 쓰면 **Data Leakage**(데이터 누수)가 발생해 성능이 실제보다 과대평가됩니다.
</Callout>

## 데이터 분할: 왜 세 부분으로 나누나?

전체 데이터를 하나로 쓰면 모델이 답지를 외워버립니다. 본 적 없는 데이터에 얼마나 잘 작동하는지(일반화 능력)를 알 수 없습니다.

### 세 집합의 역할

| 집합 | 권장 비율 | 역할 |
|------|-----------|------|
| 학습(Train) | 70~80 % | 모델 파라미터(가중치, 계수) 학습 |
| 검증(Validation) | 10~15 % | 하이퍼파라미터 튜닝, 조기 종료 기준 결정 |
| 테스트(Test) | 10~15 % | 최종 성능 보고 — **절대 학습·튜닝에 사용 금지** |

### 작은 예시 (1,000행 데이터)

```
전체 1,000행
  ├── 학습   800행  → 모델이 이 데이터로 회귀 계수를 구함
  ├── 검증   100행  → 학습률 0.01 vs 0.001 중 어느 것이 나은지 비교
  └── 테스트 100행  → 결정된 최종 모델로 성능 발표 (1회만 사용)
```

테스트 데이터를 한 번이라도 튜닝에 쓰면, 그 성능 수치는 실제 미래 데이터 성능을 과대평가하게 됩니다.

## 교차검증(Cross-Validation)

데이터가 적을 때 학습·검증을 고정 분할하면 **분할 방식에 따라 성능이 크게 달라집니다.** 교차검증은 여러 분할로 평균을 내어 신뢰도를 높입니다.

### K-Fold 교차검증

전체 데이터를 K등분한 뒤, 매번 한 Fold를 검증용으로 남기고 나머지로 학습해 K번 반복한 후 평균 성능을 계산합니다.

**K=5일 때 분할 및 검증 구조:**

| 회차 | 검증 Fold | 학습 Fold |
|------|-----------|-----------|
| 1 | Fold 1 | Fold 2, 3, 4, 5 |
| 2 | Fold 2 | Fold 1, 3, 4, 5 |
| 3 | Fold 3 | Fold 1, 2, 4, 5 |
| 4 | Fold 4 | Fold 1, 2, 3, 5 |
| 5 | Fold 5 | Fold 1, 2, 3, 4 |

**예시: K=5, 각 Fold 정확도 결과**

| Fold | 정확도 |
|------|--------|
| 1 | 0.82 |
| 2 | 0.85 |
| 3 | 0.80 |
| 4 | 0.84 |
| 5 | 0.83 |
| **평균** | (0.82+0.85+0.80+0.84+0.83)/5 = **0.828** |

### Stratified K-Fold

클래스 불균형(예: 불량품 5 %, 정상 95 %)이 있을 때 사용합니다.

- 일반 K-Fold: 어떤 Fold에는 불량품이 0개일 수도 있음 → 검증 신뢰도 낮음
- Stratified K-Fold: **각 Fold가 원본과 동일한 클래스 비율을 유지** → 불균형 분류 문제에 필수

### Leave-One-Out (LOO)

$$K = n \text{ (데이터 수만큼 반복)}$$

매번 딱 1개 샘플만 검증에 씁니다. 데이터가 50개 이하인 소규모 문제에서 주로 사용합니다. 계산 비용이 매우 큽니다.

## 과적합과 과소적합

### 개념 비교

| 구분 | 학습 성능 | 테스트 성능 | 원인 | 해결책 |
|------|-----------|-------------|------|--------|
| 과소적합(Underfitting) | 낮음 | 낮음 | 모델이 너무 단순, 패턴을 못 잡음 | 복잡도 증가, 특성 추가 |
| 적합(Good fit) | 높음 | 높음 | 균형 잡힌 복잡도 | 유지 |
| 과적합(Overfitting) | 높음 | 낮음 | 모델이 너무 복잡, 노이즈까지 학습 | 정규화, 데이터 추가, 가지치기 |

### 편향-분산 트레이드오프

$$\text{총 오차} = \text{편향}^2 + \text{분산} + \text{불가피한 오차(노이즈)}$$

| 개념 | 의미 | 연결 |
|------|------|------|
| 편향(Bias) | 예측값이 정답에서 체계적으로 멀어진 정도 | 편향↑ → 과소적합 |
| 분산(Variance) | 학습 데이터마다 예측값이 크게 달라지는 정도 | 분산↑ → 과적합 |

- 모델 복잡도를 높이면 편향은 줄지만 분산이 늘어납니다.
- **최적 모델은 편향²+ 분산의 합이 최소화되는 지점**입니다.

```
복잡도  낮음 ◄──────────────────────► 높음
편향(Bias)    ████████░░░░░░░
분산(Variance)        ░░░░████████
총 오차              ↑최솟값(최적점)
상태         과소적합   ↑    과적합
```

## 핵심 정리

- 모델링 절차: 문제 정의 → 수집 → 전처리 → 모델 선택 → 학습 → 평가 → 배포
- 데이터는 학습(70~80 %), 검증(10~15 %), 테스트(10~15 %)로 분할합니다.
- 테스트 데이터는 최종 평가 **단 한 번**에만 사용합니다.
- K-Fold CV: K번 학습/검증을 반복해 평균 성능을 구합니다.
- Stratified K-Fold: 각 Fold의 클래스 비율을 원본과 동일하게 유지 → 불균형 데이터에 필수
- 과적합: 학습↑ 테스트↓ / 과소적합: 학습·테스트 모두↓
- 총 오차 = 편향² + 분산 + 노이즈 (편향↑=과소적합, 분산↑=과적합)
