## 왜 방법론이 필요한가

데이터 분석은 "데이터 받아서 모델 돌리기"가 아닙니다. 비즈니스 이해에서 시작하여 배포·평가까지 이르는 체계적인 과정입니다. 방법론 없이 진행하면 다음 문제가 생깁니다.

- 목적 없이 탐색만 하다 끝나는 분석
- 모델 완성 후 "이건 우리가 원한 게 아니에요" 피드백
- 다시 처음으로 돌아가는 반복

표준화된 방법론을 따르면 **공통 언어**를 갖고, **빠짐없는 단계**를 밟을 수 있습니다.

## KDD 프로세스 5단계

**KDD**(Knowledge Discovery in Databases) 는 데이터에서 지식을 추출하는 과정을 5단계로 정의한 초기 데이터 마이닝 방법론입니다.

| 단계 | 명칭 | 내용 |
|------|------|------|
| 1 | **선택**(Selection) | 분석 목적에 맞는 데이터 식별 및 추출 |
| 2 | **전처리**(Preprocessing) | 결측치 처리, 이상치 제거, 노이즈 처리 |
| 3 | **변환**(Transformation) | 분석에 적합한 형태로 변환, 차원 축소 |
| 4 | **데이터 마이닝**(Data Mining) | 알고리즘 적용하여 패턴 추출 |
| 5 | **해석·평가**(Interpretation/Evaluation) | 발견된 패턴의 의미 해석, 유효성 평가 |

## CRISP-DM 6단계

**CRISP-DM**(CRoss Industry Standard Process for Data Mining) 은 가장 널리 사용되는 산업 표준 데이터 분석 방법론입니다. 6단계가 순환(Cycle)하는 구조가 특징입니다.

CRISP-DM은 6단계를 순서대로 거치되, 평가에서 데이터 이해로, 모델링에서 데이터 준비로, 전개에서 다시 비즈니스 이해로 되돌아갈 수 있는 반복적 순환 구조입니다.

| 단계 | 내용 | 주요 활동 |
|------|------|----------|
| **1. 비즈니스 이해** | 분석 목적과 요구사항 파악 | 비즈니스 목표 정의, 성공 기준 설정 |
| **2. 데이터 이해** | 데이터 탐색 및 품질 확인 | EDA, 데이터 프로파일링 |
| **3. 데이터 준비** | 분석 가능한 형태로 가공 | 결측치 처리, 피처 엔지니어링 |
| **4. 모델링** | 알고리즘 선택 및 적용 | 모델 훈련, 하이퍼파라미터 튜닝 |
| **5. 평가** | 비즈니스 목표 관점에서 검증 | KPI 달성 여부 확인, 재검토 |
| **6. 전개** | 운영 환경에 배포 | API 배포, 모니터링 체계 구축 |

<Callout type="warning">
  **핵심:** CRISP-DM은 **순환 구조**입니다. 평가 단계에서 문제가 발견되면 이전 단계로 돌아갑니다. "일직선"이 아닙니다.
</Callout>

## SEMMA 5단계

**SEMMA** 는 SAS Institute가 제안한 방법론으로, 각 단계의 첫 글자를 딴 약어입니다.

| 단계 | 약어 | 내용 |
|------|------|------|
| **1. 샘플링** | **S**ample | 분석 가능한 크기의 대표 샘플 추출 |
| **2. 탐색** | **E**xplore | 시각화·통계로 데이터 패턴 탐색 |
| **3. 수정** | **M**odify | 변수 변환, 파생 변수 생성, 결측치 처리 |
| **4. 모델링** | **M**odel | 통계·머신러닝 모델 구축 |
| **5. 평가** | **A**ssess | 모델 성능 평가 및 비즈니스 유효성 검증 |

## 3가지 방법론 비교

| 구분 | KDD | CRISP-DM | SEMMA |
|------|-----|----------|-------|
| **개발 주체** | 학계 | 컨소시엄(SPSS 등) | SAS Institute |
| **단계 수** | 5단계 | 6단계 | 5단계 |
| **초점** | 데이터 중심, 기술적 절차 | 비즈니스·데이터 통합 | 데이터 처리·모델링 |
| **구조** | 선형 | 순환(Cycle) | 선형 |
| **적합 상황** | 연구·탐색적 분석 | 산업 현장 프로젝트 | SAS 환경 모델링 |
| **비즈니스 이해 포함** | 약함 | 강함 | 없음 |

<Callout type="info">
  **시험에서 가장 중요:** CRISP-DM이 가장 출제 빈도가 높습니다. 6단계와 순환 구조를 반드시 기억하세요.
</Callout>

## 프로젝트 관리: WBS

**WBS**(Work Breakdown Structure, 작업 분해 구조) 는 프로젝트 전체를 작은 작업 단위로 분해한 계층적 목록입니다.

```
분석 프로젝트
├── 1. 데이터 준비
│   ├── 1.1 데이터 수집
│   ├── 1.2 데이터 전처리
│   └── 1.3 데이터 검증
├── 2. 모델 개발
│   ├── 2.1 EDA
│   ├── 2.2 피처 엔지니어링
│   └── 2.3 모델 훈련·평가
└── 3. 배포
    ├── 3.1 API 개발
    └── 3.2 모니터링 설정
```

WBS는 **무엇을 해야 하는지** 모두 나열하는 것이 목적입니다. 일정은 간트 차트로 별도 관리합니다.

## 프로젝트 관리: 간트 차트

**간트 차트**(Gantt Chart) 는 각 작업의 시작일·종료일을 막대로 표현한 일정 계획표입니다.

| 작업 | 1주 | 2주 | 3주 | 4주 | 5주 | 6주 |
|------|-----|-----|-----|-----|-----|-----|
| 데이터 수집 | ████ | ████ | | | | |
| 데이터 전처리 | | ████ | ████ | | | |
| EDA | | | ████ | | | |
| 모델 개발 | | | | ████ | ████ | |
| 배포 | | | | | | ████ |

## 프로젝트 관리: 위험 관리

분석 프로젝트에서 자주 발생하는 위험(Risk)을 사전에 식별하고 대비해야 합니다.

| 위험 유형 | 예시 | 대응 방안 |
|---|---|---|
| **데이터 가용성** | 필요 데이터가 없거나 품질 불량 | 대체 데이터 소스 탐색, 수집 기간 연장 |
| **일정 위험** | 전처리가 예상보다 오래 걸림 | 버퍼 기간 확보, 작업 병렬화 |
| **기술 위험** | 선택한 알고리즘이 성능 미달 | 다중 알고리즘 비교 검토 |
| **조직 위험** | 비즈니스 담당자의 참여 부족 | 정기 커뮤니케이션 일정 수립 |

위험 관리 사이클: **식별 → 평가**(발생 가능성 × 영향도) **→ 대응 → 모니터링**

## 애자일 vs 워터폴 비교

| 구분 | 워터폴(Waterfall) | 애자일(Agile) |
|------|-------------------|--------------|
| **진행 방식** | 단계별 순차 완료 후 다음 단계 진행 | 짧은 스프린트 반복 |
| **요구사항 변경** | 어렵고 비용이 큼 | 유연하게 반영 가능 |
| **중간 결과물** | 최종 단계에 가야 나옴 | 스프린트마다 부분 결과 확인 |
| **분석 적합도** | 요구사항이 명확한 경우 | 탐색적·반복적 분석에 유리 |

분석 프로젝트는 불확실성이 높으므로 **애자일 방식**이 더 적합한 경우가 많습니다.

## 핵심 정리

- KDD: 선택 → 전처리 → 변환 → 데이터마이닝 → 해석·평가 (학계 중심, 데이터 기술적 절차)
- CRISP-DM: 비즈니스 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개 (**순환 구조**, 산업 표준)
- SEMMA: Sample → Explore → Modify → Model → Assess (SAS Institute)
- CRISP-DM이 가장 실용적이며 시험 출제 빈도가 높다
- WBS: 작업 분해 구조 (무엇을 해야 하는지), 간트 차트: 일정 계획 (언제까지)
- 위험 관리: 식별 → 평가 → 대응 → 모니터링
