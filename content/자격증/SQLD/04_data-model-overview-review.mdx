## 04편 복습

본문을 덮고 먼저 기억나는 내용을 떠올려 보자. 답이 바로 나오지 않아도 괜찮다. 직접 답한 뒤 해설과 비교해야 무엇을 다시 볼지 알 수 있다.

<Callout type="info">
문제를 먼저 풀고 나서 정답을 확인한다. 틀린 문제는 정답만 외우지 말고, 본문의 어떤 개념을 놓쳤는지 한 줄로 기록한다.
</Callout>

## 직접 풀어보기

### 문제 1

다음 항목을 개념·논리·물리 모델에 배치한다.

```text
상품과 카테고리의 관계
상품번호를 기본 식별자로 선택
product_name을 VARCHAR(100)으로 구현
조회용 인덱스 추가
```

### 문제 2

"고객은 문의를 한 번도 하지 않을 수 있고, 문의는 반드시 한 고객에게 속한다"를 관계 수와 선택성으로 표현한다.

### 문제 3

현재 데이터에서 직원 한 명당 전화번호가 하나만 발견되었다. 이를 근거로 직원-전화번호 관계를 항상 1:1로 설계해도 되는가?

## 정답과 해설

### 문제 1

- 상품과 카테고리의 관계: 개념 모델
- 상품번호를 기본 식별자로 선택: 논리 모델
- `VARCHAR(100)` 자료형과 인덱스: 물리 모델

### 문제 2

고객 한 명에는 문의가 `0..N`, 문의 한 건에는 고객이 정확히 1명 연결된다.

### 문제 3

안 된다. 현재 데이터가 아니라 업무 규칙과 미래 요구를 확인해야 한다. 휴대전화와 회사전화처럼 여러 번호를 허용할 수 있다면 1:N 구조가 필요하다.

## 흔한 실수

- 개념 모델에 컬럼 자료형을 적는다: 구현 세부는 물리 단계에서 다룬다.
- 논리 모델을 단순한 테이블 목록으로 본다: 업무 식별자, 관계 수, 선택성도 포함한다.
- 현재 데이터 건수를 업무 최대값으로 착각한다: 관계 수는 허용 규칙이다.
- ERD 표기 모양만 외운다: 표기법보다 최소·최대 관계를 문장으로 읽는다.
