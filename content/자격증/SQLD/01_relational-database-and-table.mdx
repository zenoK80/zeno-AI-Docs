## 관계형 데이터베이스란?

**관계형 데이터베이스(Relational Database, RDB)**는 데이터를 **표(Table)** 형태로 저장하고, 표와 표 사이의 **관계(Relation)**를 이용해 데이터를 연결하는 데이터베이스입니다.

1970년 IBM 연구원 에드거 코드(Edgar F. Codd)가 제안한 **관계형 모델**을 기반으로 합니다. 오늘날 Oracle, MySQL, PostgreSQL, SQL Server 등 대부분의 기업용 데이터베이스가 이 방식을 사용합니다.

관계형 DB를 한 마디로 요약하면 이렇습니다.

> **"데이터는 표에 저장하고, 표들은 공통 값으로 연결한다."**

### 왜 관계형 방식이 좋은가?

예전에는 데이터를 하나의 거대한 파일에 모두 몰아넣었습니다. 고객 정보, 주문 정보, 상품 정보가 한 파일에 섞여 있으면 특정 고객의 주소를 바꿀 때 수백 줄을 일일이 수정해야 했습니다.

관계형 방식은 고객 정보는 고객 테이블에, 주문 정보는 주문 테이블에 따로 저장합니다. 고객 주소가 바뀌면 고객 테이블 한 줄만 수정하면 됩니다. **중복을 줄이고, 일관성을 높입니다.**

## 테이블의 구성 요소

관계형 데이터베이스에서 데이터를 담는 기본 단위는 **테이블(Table)**입니다. 테이블은 다음 4가지 요소로 구성됩니다.

| 용어 | 다른 이름 | 설명 |
|------|-----------|------|
| **테이블(Table)** | 릴레이션(Relation), 개체(Entity) | 데이터를 담는 표 전체 |
| **행(Row)** | 튜플(Tuple), 레코드(Record), 인스턴스 | 테이블의 가로 한 줄 = 한 건의 데이터 |
| **열(Column)** | 속성(Attribute), 필드(Field) | 테이블의 세로 한 줄 = 데이터의 종류 |
| **값(Value)** | 데이터 값 | 행과 열이 교차하는 칸의 실제 데이터 |

<Callout type="warning">
  SQLD 시험에서는 용어를 섞어서 출제합니다. "튜플", "속성", "릴레이션"이라는 단어가 나와도 각각 행, 열, 테이블을 가리킨다는 것을 반드시 기억하세요.
</Callout>

### 실제 테이블 예시 - 고객 테이블

아래는 쇼핑몰의 고객 정보를 저장하는 테이블입니다.

| 고객번호 | 이름 | 이메일 | 가입일 | 등급 |
|---------|------|--------|--------|------|
| 1001 | 김민준 | minjun@example.com | 2023-01-15 | GOLD |
| 1002 | 이서연 | seoyeon@example.com | 2023-03-22 | SILVER |
| 1003 | 박지호 | jiho@example.com | 2023-07-08 | BRONZE |
| 1004 | 최수아 | sua@example.com | 2024-01-10 | SILVER |

- **열(Column)**: 고객번호, 이름, 이메일, 가입일, 등급 → 총 5개의 속성
- **행(Row)**: 김민준에 관한 데이터 한 줄 전체 → 1개의 튜플
- **값(Value)**: `김민준`, `minjun@example.com` 등 개별 칸의 데이터

### 실제 테이블 예시 - 주문 테이블

| 주문번호 | 고객번호 | 상품명 | 수량 | 주문금액 | 주문일 |
|---------|---------|--------|------|---------|--------|
| 5001 | 1001 | 노트북 | 1 | 1,200,000 | 2024-02-01 |
| 5002 | 1002 | 마우스 | 2 | 60,000 | 2024-02-03 |
| 5003 | 1001 | 키보드 | 1 | 150,000 | 2024-02-05 |
| 5004 | 1003 | 모니터 | 1 | 450,000 | 2024-02-07 |

고객번호 1001(김민준)이 주문 5001과 5003 두 건을 가지고 있습니다. 고객 테이블과 주문 테이블은 **고객번호**라는 공통 값으로 연결됩니다. 이것이 바로 "관계"입니다.

## 기본키(Primary Key)란?

**기본키(Primary Key, PK)**는 테이블에서 각 행을 유일하게 식별할 수 있는 열(또는 열의 조합)입니다.

### 기본키가 없으면 어떤 문제가 생길까?

아래 상황을 생각해봅시다. 이름만으로 고객을 식별하려 한다면:

| 이름 | 이메일 | 등급 |
|------|--------|------|
| 이지원 | jiwon1@example.com | GOLD |
| 이지원 | jiwon2@example.com | BRONZE |

"이지원 고객의 등급을 GOLD로 바꿔주세요"라는 요청이 오면, **어느 이지원**을 수정해야 할지 알 수 없습니다. 동명이인이 있기 때문입니다.

이런 문제를 막기 위해 **모든 테이블에는 반드시 기본키가 있어야 합니다.**

### 기본키의 조건

기본키가 되려면 두 가지 조건을 동시에 만족해야 합니다.

1. **NOT NULL**: 값이 반드시 있어야 합니다. 비어 있으면(NULL) 식별이 불가능합니다.
2. **UNIQUE**: 테이블 내에서 중복 값이 없어야 합니다.

<Callout type="warning">
  기본키의 두 조건(NOT NULL + UNIQUE)은 SQLD 시험에서 매우 자주 출제됩니다. 반드시 암기하세요.
</Callout>

고객 테이블에서 `고객번호`는 각 고객마다 유일하게 부여되고, 반드시 값이 있으므로 기본키로 적합합니다. 반면 `이름`은 중복될 수 있고, `등급`은 여러 고객이 같은 등급을 가질 수 있으므로 기본키가 될 수 없습니다.

## SQL로 데이터 조회하기

SQL(Structured Query Language)은 관계형 DB에서 데이터를 다루는 언어입니다. 가장 기본적인 조회 명령은 `SELECT`입니다.

### 기본 SELECT 문

```sql
SELECT 고객번호, 이름, 등급
FROM 고객
WHERE 등급 = 'SILVER';
```

**결과:**

| 고객번호 | 이름 | 등급 |
|---------|------|------|
| 1002 | 이서연 | SILVER |
| 1004 | 최수아 | SILVER |

### 두 테이블 연결 (JOIN)

고객 이름과 해당 고객의 주문 금액을 함께 조회하려면 두 테이블을 연결해야 합니다.

```sql
SELECT 고객.이름, 주문.주문금액, 주문.주문일
FROM 고객
JOIN 주문 ON 고객.고객번호 = 주문.고객번호
WHERE 고객.이름 = '김민준';
```

**결과:**

| 이름 | 주문금액 | 주문일 |
|------|---------|--------|
| 김민준 | 1,200,000 | 2024-02-01 |
| 김민준 | 150,000 | 2024-02-05 |

`ON 고객.고객번호 = 주문.고객번호` 부분이 두 테이블을 연결하는 조건입니다. 고객 테이블의 `고객번호`와 주문 테이블의 `고객번호`가 같은 행끼리 묶어줍니다.

## 테이블의 특성 정리

| 특성 | 설명 |
|------|------|
| **행의 순서는 의미 없음** | 테이블에서 행의 저장 순서는 중요하지 않습니다 |
| **열의 순서는 의미 없음** | 어떤 열이 먼저 오든 데이터는 동일합니다 |
| **중복 행 없음** | 완전히 동일한 행이 두 개 존재할 수 없습니다 |
| **하나의 값** | 각 칸(행+열 교차점)에는 하나의 값만 들어갑니다 |

마지막 특성인 "하나의 값"은 중요합니다. 한 칸에 여러 전화번호를 콤마로 구분해 넣는 것은 관계형 모델의 원칙에 어긋납니다. 이런 경우 전화번호 테이블을 별도로 만들어야 합니다.

## 핵심 정리

- 관계형 데이터베이스는 데이터를 **표(테이블)** 형태로 저장하고, 공통 값으로 표들을 연결한다
- 테이블은 **행(튜플/레코드)**, **열(속성/필드)**, **값**으로 구성된다
- **기본키(Primary Key)**는 각 행을 유일하게 식별하며, **NOT NULL + UNIQUE** 조건을 만족해야 한다
- 두 테이블은 **공통 키 값**을 통해 JOIN으로 연결된다
- 각 칸에는 하나의 원자적 값만 저장해야 한다
