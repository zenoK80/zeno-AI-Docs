### 문제 1

다음 업무 규칙을 보고 ERD 관계의 차수와 선택성을 올바르게 설명한 것을 고르세요.

> **업무 규칙**
> - 하나의 강의는 반드시 하나의 강의실에서만 진행된다.
> - 하나의 강의실에서는 여러 강의가 진행될 수 있다.
> - 강의실은 현재 배정된 강의가 없을 수도 있다.

1. 강의(N, 선택) : 강의실(1, 선택)
2. 강의(1, 필수) : 강의실(N, 선택) — 강의 기준 1:N
3. 강의실(1, 선택) : 강의(N, 필수) — 강의실 기준 1:N
4. 강의(N, 필수) : 강의실(N, 필수) — N:M

<Callout type="success">
  **정답: 3번**

  분석:
  - 강의실 입장: 강의가 없을 수 있음(선택, 최솟값 0) + 여러 강의 가능(최댓값 N) → **강의실: 0 or N**
  - 강의 입장: 반드시 하나의 강의실에서 진행(필수, 최솟값 1) + 하나의 강의실만(최댓값 1) → **강의: 1**

  표현: 강의실(1, 선택적으로 0~N) : 강의(N, 강의실 기준 필수 관계) → 강의실 1 : 강의 N

  **강의실 기준**: 강의가 없을 수도 있으므로 선택적(O 표기)
  **강의 기준**: 반드시 강의실 하나에 속해야 하므로 필수(| 표기)
</Callout>

### 문제 2

다음 테이블이 위반하는 정규형과 그 이유로 올바른 것은?

```
수주내역(수주번호, 고객번호, 고객명, 고객주소, 상품코드, 수량, 단가)
기본키: (수주번호, 상품코드)
```

- 수주번호 → 고객번호
- 고객번호 → 고객명, 고객주소
- (수주번호, 상품코드) → 수량, 단가

1. 1NF 위반 — 반복 그룹이 존재한다.
2. 2NF 위반 — 수주번호만으로 고객번호가 결정된다(부분 함수 종속).
3. 3NF 위반 — 고객번호를 통해 고객명이 이행 종속된다.
4. 2NF와 3NF를 동시에 위반한다.

<Callout type="success">
  **정답: 4번**

  이 테이블은 두 가지 정규형을 동시에 위반합니다.

  **2NF 위반 (부분 함수 종속)**: 기본키 (수주번호, 상품코드) 중 수주번호만으로 고객번호가 결정됩니다.
  → 수주번호 → 고객번호 (부분 함수 종속 존재)

  **3NF 위반 (이행 함수 종속)**: 수주번호 → 고객번호 → 고객명/고객주소로 이행 종속됩니다.
  → 고객명은 기본키가 아닌 고객번호에 의해 결정

  **해결**: 수주내역(수주번호, 상품코드, 수량, 단가) + 수주(수주번호, 고객번호) + 고객(고객번호, 고객명, 고객주소)으로 분리
</Callout>

### 문제 3

다음 중 반정규화 기법에 대한 설명으로 올바르지 않은 것은?

1. 테이블 반정규화는 자주 JOIN되는 두 테이블을 하나로 합치는 방법을 포함한다.
2. 컬럼 반정규화는 자주 사용되는 집계 값을 별도 컬럼으로 저장하는 방법을 포함한다.
3. 반정규화를 적용하면 데이터 중복이 발생하여 갱신 성능이 떨어질 수 있다.
4. 반정규화는 데이터 무결성 향상을 위해 적용하는 기법이다.

<Callout type="success">
  **정답: 4번 (틀린 설명)**

  반정규화는 **조회(SELECT) 성능 향상**을 위해 적용하는 기법입니다. 정규화 과정에서 분리된 테이블을 합치거나 중복 컬럼을 추가하는 것이므로, 오히려 데이터 중복으로 인해 무결성 관리가 어려워집니다. 무결성 향상은 정규화의 목적입니다.
</Callout>

### 문제 4

다음 테이블과 쿼리를 보고 결과로 올바른 것을 고르세요.

```sql
-- 재고 테이블
-- 상품코드 | 상품명  | 재고수량 | 단가
--  A001   | 사과    |   100   | 1500
--  A002   | 배      |   NULL  | 2000
--  A003   | 포도    |    50   | NULL
--  A004   | 딸기    |   NULL  | NULL

SELECT COUNT(*), COUNT(재고수량), COUNT(단가)
FROM 재고;
```

1. 4, 4, 4
2. 4, 2, 2
3. 2, 2, 2
4. 4, 3, 3

<Callout type="success">
  **정답: 2번**

  - `COUNT(*)`: 전체 행 수 = **4**
  - `COUNT(재고수량)`: NULL 제외 → A001(100), A003(50) = **2**
  - `COUNT(단가)`: NULL 제외 → A001(1500), A002(2000) = **2**
</Callout>

### 문제 5

다음 쿼리 실행 후 결과 행 수는?

```sql
-- 부서 테이블 (4행)
-- 부서코드: D01, D02, D03, D04

-- 직원 테이블 (5행)
-- 직원번호 | 부서코드
--   E001  |   D01
--   E002  |   D01
--   E003  |   D02
--   E004  |   NULL
--   E005  |   D99   ← 부서 테이블에 없는 부서

SELECT D.부서코드, E.직원번호
FROM 부서 D LEFT OUTER JOIN 직원 E ON (D.부서코드 = E.부서코드);
```

1. 5행
2. 6행
3. 7행
4. 9행

<Callout type="success">
  **정답: 2번 (6행)**

  LEFT OUTER JOIN은 왼쪽 테이블(부서)의 모든 행을 유지합니다.

  - D01 ← E001, E002 → **2행**
  - D02 ← E003 → **1행**
  - D03 ← 매칭 없음 → **NULL로 1행** (LEFT JOIN이므로 부서는 보존)
  - D04 ← 매칭 없음 → **NULL로 1행**

  총 **6행**

  - E004(부서코드 NULL): ON 조건에서 NULL은 어떤 값과도 같지 않으므로 매칭 안 됨 → 오른쪽에만 있으므로 LEFT JOIN 결과에 미포함
  - E005(D99): 부서 테이블에 없으므로 LEFT JOIN 결과에 미포함
</Callout>

### 문제 6

다음 쿼리에서 오류가 발생하는 이유는?

```sql
SELECT 부서코드, COUNT(*) AS 직원수
FROM 직원
WHERE COUNT(*) > 3
GROUP BY 부서코드;
```

1. GROUP BY 없이 COUNT를 사용했기 때문이다.
2. WHERE 절에 집계 함수(COUNT)를 사용했기 때문이다.
3. 부서코드가 SELECT와 GROUP BY에 동시에 있기 때문이다.
4. AS 키워드를 사용했기 때문이다.

<Callout type="success">
  **정답: 2번**

  SQL 실행 순서: **FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY**

  WHERE는 GROUP BY 이전 단계에서 실행됩니다. 이 시점에는 아직 집계가 이루어지지 않았으므로, WHERE 절에 집계 함수(COUNT, SUM, AVG 등)를 사용할 수 없습니다.

  **올바른 쿼리:**
  ```sql
  SELECT 부서코드, COUNT(*) AS 직원수
  FROM 직원
  GROUP BY 부서코드
  HAVING COUNT(*) > 3;
  ```
</Callout>

### 문제 7

다음 쿼리의 결과로 올바른 것을 고르세요.

```sql
-- 주문 테이블
-- 주문번호 | 고객코드 | 금액
--   1001  |   C01   | 10000
--   1002  |   C01   | 20000
--   1003  |   C02   | 15000
--   1004  |   C02   | 25000
--   1005  |   C03   | 30000

SELECT 고객코드, SUM(금액) AS 합계
FROM 주문
GROUP BY 고객코드
HAVING SUM(금액) >= 40000
ORDER BY 합계 DESC;
```

1. C01(30000), C02(40000), C03(30000)
2. C02(40000), C03(30000)
3. C02(40000)
4. C01(30000), C02(40000)

<Callout type="success">
  **정답: 3번 (C02만)**

  각 고객의 합계:
  - C01: 10000 + 20000 = 30000 → 40000 미만 → HAVING 제외
  - C02: 15000 + 25000 = 40000 → 40000 이상 → 포함
  - C03: 30000 → 40000 미만 → HAVING 제외

  결과: **C02(40000) 1행만 반환**
</Callout>

### 문제 8

다음 윈도우 함수 쿼리의 결과에서 '이민준'의 부서내순위(DR) 값은?

```sql
-- 직원 테이블
-- 직원명  | 부서  | 급여
-- 이민준  | 영업  | 350만
-- 김서연  | 영업  | 400만
-- 박지민  | 영업  | 350만
-- 최유나  | 개발  | 500만
-- 정도현  | 개발  | 450만

SELECT 직원명, 부서, 급여,
       DENSE_RANK() OVER (PARTITION BY 부서 ORDER BY 급여 DESC) AS DR
FROM 직원;
```

1. 1
2. 2
3. 3
4. 4

<Callout type="success">
  **정답: 2번**

  DENSE_RANK()는 PARTITION BY 부서로 부서 내에서 순위를 매기고, ORDER BY 급여 DESC로 급여 높은 순 정렬합니다.

  **영업 부서 내 순위** (급여 내림차순):
  - 김서연 400만 → DR = 1
  - **이민준 350만 → DR = 2** (공동)
  - **박지민 350만 → DR = 2** (공동)

  DENSE_RANK는 동점도 같은 순위를 주되 다음 순위를 건너뛰지 않습니다. 이민준과 박지민이 공동 2위 → **DR = 2**
</Callout>

### 문제 9

다음 트랜잭션 실행 후 테이블의 최종 상태는?

```sql
-- 초기: 계좌(계좌번호, 잔액)에 A001: 500000 존재

UPDATE 계좌 SET 잔액 = 잔액 - 100000 WHERE 계좌번호 = 'A001';
SAVEPOINT S1;
UPDATE 계좌 SET 잔액 = 잔액 - 200000 WHERE 계좌번호 = 'A001';
ROLLBACK TO S1;
UPDATE 계좌 SET 잔액 = 잔액 + 50000 WHERE 계좌번호 = 'A001';
COMMIT;
```

1. 잔액 = 500000 (변경 없음)
2. 잔액 = 450000
3. 잔액 = 200000
4. 잔액 = 250000

<Callout type="success">
  **정답: 2번 (잔액 = 450000)**

  단계별 추적:
  1. `UPDATE`: 500000 - 100000 = **400000**
  2. `SAVEPOINT S1`: 현재 잔액 400000 저장
  3. `UPDATE`: 400000 - 200000 = **200000**
  4. `ROLLBACK TO S1`: S1 이후 변경 취소 → **400000으로 복원**
  5. `UPDATE`: 400000 + 50000 = **450000**
  6. `COMMIT`: 450000 확정

  최종: **450000**
</Callout>

### 문제 10

다음 서브쿼리 쿼리의 결과 행 수는?

```sql
-- 상품 테이블
-- 상품코드 | 카테고리 | 가격
--   P001  |   식품   | 5000
--   P002  |   전자   | 50000
--   P003  |   식품   | 8000
--   P004  |   의류   | 30000
--   P005  |   식품   | 3000

SELECT 상품코드, 가격
FROM 상품
WHERE 가격 > (
    SELECT AVG(가격) FROM 상품 WHERE 카테고리 = '식품'
);
```

1. 1행
2. 2행
3. 3행
4. 4행

<Callout type="success">
  **정답: 2번 (2행)**

  서브쿼리 계산:
  - 식품 카테고리 평균: (5000 + 8000 + 3000) / 3 = **5333.33...**

  메인쿼리: 가격 > 5333.33인 상품
  - P001: 5000 → 제외 (5000 < 5333.33)
  - P002: 50000 → 포함
  - P003: 8000 → 포함
  - P004: 30000 → 포함
  - P005: 3000 → 제외

  결과: P002(50000), P003(8000), P004(30000) → **3행**

  **정정**: 실제 정답은 3행 → 보기 3번
</Callout>

<Callout type="warning">
  **위 문제 정답 정정: 3번 (3행)**

  서브쿼리 결과 5333.33보다 큰 상품: P002(50000), P003(8000), P004(30000) = 3개
  
  문제를 풀 때 서브쿼리 결과를 먼저 메모장에 적고, 각 행을 하나씩 확인하는 습관을 들이세요.
</Callout>
