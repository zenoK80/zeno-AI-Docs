## 이번 편의 목표

- 데이터와 데이터베이스, DBMS를 서로 구분한다.
- 파일로 관리할 때 생기는 중복·불일치 문제를 설명한다.
- 테이블의 행, 열, 기본 키가 무엇인지 주문 사례에서 찾는다.
- SQLD에서 데이터 모델링과 SQL을 함께 배우는 이유를 설명한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 데이터 | 관찰하거나 기록한 사실과 값 |
| 데이터베이스(DB) | 여러 사용자가 필요한 데이터를 체계적으로 저장하고 함께 쓰는 저장소 |
| DBMS | 데이터베이스를 만들고 조회·수정·보호하는 관리 프로그램 |
| 테이블 | 관련 데이터를 행과 열 형태로 저장한 구조 |
| 행 | 한 회원, 한 주문처럼 하나의 대상에 대한 기록 |
| 열 | 이름, 주문일처럼 모든 행에서 같은 의미를 갖는 항목 |
| 스키마 | 어떤 테이블과 열이 있고 서로 어떻게 연결되는지 정한 구조 |
| SQL | 관계형 데이터베이스에 조회와 변경을 요청하는 언어 |

DB는 Database, DBMS는 Database Management System의 줄임말이다. 데이터베이스가 저장된 내용이라면 DBMS는 그 내용을 안전하게 관리하고 사용자의 요청을 처리하는 소프트웨어다.

## 주변 개념 지도

앱 화면은 데이터를 보여 주는 창이고, 데이터베이스는 화면 뒤에서 여러 기능이 함께 사용하는 정보를 보관한다. 서버 프로그램은 사용자의 요청을 검사한 뒤 DBMS에 SQL을 보내 데이터를 읽거나 바꾼다.

<Callout type="info">
테이블을 엑셀 시트처럼 생각하면 처음 이해하기 쉽지만 완전히 같지는 않다. DBMS는 여러 사용자의 동시 작업, 규칙 검사, 복구와 권한을 함께 관리한다.
</Callout>

## 엑셀 파일 세 개에서 시작된 문제

작은 쇼핑몰이 회원과 주문을 파일로 관리한다고 하자.

```text
회원.xlsx      : 회원번호, 이름, 전화번호
주문_7월.xlsx  : 주문번호, 회원번호, 회원이름, 전화번호, 상품명
배송.xlsx      : 주문번호, 회원이름, 전화번호, 주소
```

회원 한 명이 전화번호를 바꾸면 세 파일을 모두 수정해야 한다. 하나라도 빠뜨리면 같은 회원의 전화번호가 파일마다 달라진다. 주문 파일을 여러 직원이 동시에 수정하면 누가 입력한 값이 최종값인지도 모호해진다.

이 문제는 자료가 부족해서가 아니라, **같은 의미의 데이터를 여러 곳에서 제각각 관리하기 때문**이다.

## 데이터, 데이터베이스, DBMS

비슷하게 들리는 세 용어를 먼저 분리하자.

| 용어 | 뜻 | 쇼핑몰 예 |
| --- | --- | --- |
| 데이터 | 관찰하거나 기록한 개별 사실 | 회원번호 101, 주문금액 29,000원 |
| 데이터베이스 | 관련 데이터를 일정한 구조로 모은 집합 | 회원·상품·주문 데이터 전체 |
| DBMS | 데이터베이스를 생성·조회·변경·보호하는 소프트웨어 | Oracle Database, PostgreSQL, MySQL |

**DBMS(Database Management System)** 는 사용자가 파일 위치를 직접 찾아다니지 않아도 데이터의 저장, 검색, 동시 사용, 복구, 권한을 관리해 준다.

<Callout type="important">
  데이터베이스는 데이터의 집합이고, DBMS는 그 데이터베이스를 관리하는 프로그램이다. 시험에서는 두 용어를 바꾸어 놓은 선지가 자주 나온다.
</Callout>

## 관계형 데이터베이스의 기본 모습

SQLD에서 중심이 되는 **관계형 데이터베이스**는 데이터를 행과 열로 이루어진 테이블로 표현한다.

### 회원 테이블

| member_id | name | phone |
| ---: | --- | --- |
| 101 | 민지 | 010-1111-2222 |
| 102 | 준호 | 010-3333-4444 |

- **테이블(table)**: 같은 종류의 데이터를 행과 열로 정리한 구조
- **행(row)**: 회원 한 명처럼 하나의 대상에 대한 기록
- **열(column)**: 회원번호, 이름처럼 기록할 항목

### 주문 테이블

| order_id | member_id | ordered_at | status |
| ---: | ---: | --- | --- |
| 5001 | 101 | 2026-08-01 | 결제완료 |
| 5002 | 101 | 2026-08-03 | 배송중 |

회원 이름과 전화번호를 주문마다 반복하지 않고 `member_id`로 회원 테이블과 연결한다. 회원의 전화번호가 바뀌면 회원 행 하나만 수정하면 된다.

## 키는 행과 관계를 구분한다

`member_id`는 회원마다 달라야 한다. 이처럼 테이블에서 각 행을 유일하게 구분하는 열 또는 열의 조합을 **기본 키(Primary Key)** 라고 한다.

주문 테이블의 `member_id`는 회원 테이블의 기본 키를 가리킨다. 다른 테이블의 기본 키를 참조해 관계를 만드는 열을 **외래 키(Foreign Key)** 라고 한다.

```text
회원.member_id (기본 키) 1 ─── N 주문.member_id (외래 키)
```

회원 한 명은 여러 주문을 할 수 있으므로 1:N 관계다. 외래 키를 사용하면 존재하지 않는 회원번호로 주문을 만드는 오류를 제약조건으로 막을 수 있다.

## 데이터베이스가 해결하는 네 가지 문제

### 중복과 불일치

회원 정보를 한 곳에서 관리해 같은 사실이 서로 다르게 저장되는 문제를 줄인다.

### 동시 사용

여러 사용자가 같은 데이터를 읽고 수정할 때 작업 순서를 조정한다. 결제와 재고 차감처럼 함께 성공하거나 함께 취소해야 하는 작업은 트랜잭션으로 묶는다.

### 무결성

**무결성(integrity)** 은 데이터가 정해진 규칙에 맞고 서로 모순되지 않는 상태다. 기본 키 중복 금지, 필수값 누락 금지, 존재하는 회원만 주문 가능 같은 규칙을 DBMS에 맡길 수 있다.

### 보안과 복구

사용자별 권한을 나누고, 장애가 나면 로그와 백업을 이용해 일관된 상태로 복구할 수 있다.

## SQL은 DBMS와 대화하는 언어다

**SQL(Structured Query Language)** 은 관계형 데이터베이스의 구조와 데이터를 다루는 표준 언어다.

```sql
SELECT order_id, status
FROM orders
WHERE member_id = 101;
```

이 문장은 `orders` 테이블에서 회원번호가 101인 주문의 번호와 상태를 조회한다.

SQLD에서는 단순히 문법을 외우지 않는다. 테이블이 왜 그렇게 나뉘었는지 알아야 올바른 조인과 조건을 작성할 수 있다. 그래서 시험은 크게 **데이터 모델링**과 **SQL 기본·활용**을 함께 다룬다.

## 데이터베이스 설계 흐름 미리 보기

<Steps>

### 업무 규칙을 문장으로 적는다

회원은 여러 주문을 할 수 있고, 주문에는 여러 상품이 들어갈 수 있다.

### 관리 대상을 찾는다

회원, 주문, 상품, 주문상세처럼 독립적으로 관리할 대상을 찾는다.

### 속성과 식별자를 정한다

각 대상이 가져야 할 정보와 행을 구분하는 값을 정한다.

### 관계와 제약조건을 정한다

회원과 주문의 1:N 관계, 주문과 상품 사이의 주문상세 관계를 정의한다.

### 테이블로 구현하고 SQL로 확인한다

테이블을 생성하고 예제 데이터를 넣은 뒤 조회 결과가 업무 규칙과 맞는지 검증한다.

</Steps>

## 시험형 확인

다음 설명의 용어를 고르자.

1. 관련 데이터를 구조화해 모아 둔 집합
2. 데이터베이스의 저장·검색·권한·복구를 관리하는 소프트웨어
3. 테이블의 각 행을 유일하게 구분하는 열
4. 다른 테이블의 기본 키를 참조하는 열

정답은 각각 데이터베이스, DBMS, 기본 키, 외래 키다.

## 정리

<Callout type="default">
  - 데이터베이스는 관련 데이터의 구조화된 집합이고 DBMS는 이를 관리하는 소프트웨어다.
  - 관계형 데이터베이스는 데이터를 테이블의 행과 열로 표현한다.
  - 기본 키는 행을 구분하고 외래 키는 테이블 사이의 관계를 만든다.
  - 모델링이 올바라야 SQL의 조인과 결과도 올바르게 나온다.
</Callout>

다음 편에서는 데이터베이스가 가져야 하는 통합성·저장성·운영성·공유성과 데이터 독립성을 더 정확하게 구분한다.
