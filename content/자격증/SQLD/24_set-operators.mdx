## 이번 편의 목표

- 집합 연산자가 두 SELECT 결과를 위아래로 결합한다는 점을 설명한다.
- `UNION`, `UNION ALL`, `INTERSECT`, `EXCEPT(MINUS)`의 결과를 계산한다.
- 두 SELECT의 열 개수와 대응 데이터 타입 규칙을 적용한다.
- 중복 제거와 정렬 위치에서 발생하는 오류를 진단한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 집합 연산자 | 두 SELECT 결과의 행을 합치거나 공통·차이 행을 구하는 연산자 |
| 대응 열 | 위 SELECT의 첫 번째 열과 아래 SELECT의 첫 번째 열처럼 같은 위치에서 짝이 되는 열 |
| 중복 제거 | 모든 대응 열 값이 같은 결과 행을 하나로 합치는 처리 |
| `UNION ALL` | 중복을 제거하지 않고 두 결과를 그대로 이어 붙이는 연산 |
| `INTERSECT` | 양쪽 결과에 공통으로 존재하는 행을 구하는 연산 |
| `EXCEPT` / `MINUS` | 첫 결과에는 있고 둘째 결과에는 없는 행을 구하는 연산 |

## 선수지식과 핵심 질문

선수지식은 [15. SELECT 문](./15_select-statement)과 [12. NULL 속성의 이해](./12_null-attributes)다.

핵심 질문은 **두 결과표를 가로가 아니라 세로로 합칠 때 중복을 남길지, 공통만 볼지, 차이만 볼지**이다.

## 조인과 집합 연산자의 방향

```text
조인:        왼쪽 열 | 오른쪽 열   ← 열이 늘어나는 가로 결합
집합 연산:   첫 SELECT의 행
             둘째 SELECT의 행      ← 행이 늘어나는 세로 결합
```

집합 연산을 하려면 두 SELECT의 결과 모양이 호환되어야 한다.

1. 열 개수가 같아야 한다.
2. 같은 위치의 데이터 타입이 서로 호환되어야 한다.
3. 최종 열 이름은 일반적으로 첫 번째 SELECT의 열 이름 또는 별칭을 따른다.

## 공통 입력

서울 회원과 GOLD 회원의 번호를 각각 조회한다고 하자.

`서울 회원 결과 A`

| member_id |
| --- |
| M01 |
| M03 |
| M05 |

`GOLD 회원 결과 B`

| member_id |
| --- |
| M01 |
| M04 |
| M05 |

## UNION: 합치고 중복 제거

```sql
SELECT member_id
FROM members
WHERE city = '서울'
UNION
SELECT member_id
FROM members
WHERE grade = 'GOLD';
```

| member_id |
| --- |
| M01 |
| M03 |
| M04 |
| M05 |

M01과 M05는 양쪽에 있지만 한 번씩만 나온다. `UNION`은 두 결과를 합친 뒤 중복 행을 제거한다.

## UNION ALL: 그대로 이어 붙이기

```sql
SELECT member_id
FROM members
WHERE city = '서울'
UNION ALL
SELECT member_id
FROM members
WHERE grade = 'GOLD';
```

| member_id |
| --- |
| M01 |
| M03 |
| M05 |
| M01 |
| M04 |
| M05 |

결과는 3 + 3 = 6행이다. 중복 제거 작업이 필요하지 않고 중복 자체가 의미 있을 때 사용한다.

<Callout type="info">
  중복 제거가 필요하지 않다면 UNION ALL이 의도를 더 정확히 표현하고, 중복 비교 작업도 피할 수 있다. 다만 실제 성능은 실행계획과 데이터에 따라 확인한다.
</Callout>

## INTERSECT: 양쪽 공통 행

```sql
SELECT member_id FROM members WHERE city = '서울'
INTERSECT
SELECT member_id FROM members WHERE grade = 'GOLD';
```

| member_id |
| --- |
| M01 |
| M05 |

서울이면서 동시에 GOLD인 회원이다.

## EXCEPT와 MINUS: 왼쪽에서 오른쪽 빼기

PostgreSQL과 SQL 표준 계열에서는 `EXCEPT`, Oracle에서는 같은 목적에 `MINUS`를 사용한다.

```sql
-- PostgreSQL 등
SELECT member_id FROM members WHERE city = '서울'
EXCEPT
SELECT member_id FROM members WHERE grade = 'GOLD';
```

| member_id |
| --- |
| M03 |

A에는 있지만 B에는 없는 회원이다. 순서를 바꾸면 B에만 있는 M04가 나오므로 차집합은 교환법칙이 성립하지 않는다.

## 여러 열이면 행 전체로 중복을 판단한다

```sql
SELECT member_id, 'CITY' AS source
FROM members
WHERE city = '서울'
UNION
SELECT member_id, 'GRADE' AS source
FROM members
WHERE grade = 'GOLD';
```

M01이 두 SELECT에 있어도 `(M01, CITY)`와 `(M01, GRADE)`는 행 전체가 다르다. 따라서 둘 다 남는다.

| member_id | source |
| --- | --- |
| M01 | CITY |
| M03 | CITY |
| M05 | CITY |
| M01 | GRADE |
| M04 | GRADE |
| M05 | GRADE |

<Callout type="warning">
  UNION의 중복 기준은 특정 한 열이 아니라 SELECT 목록에 있는 **모든 열 값의 조합**이다.
</Callout>

## 열 이름과 타입 맞추기

다음은 열 개수가 달라 오류가 난다.

```sql
SELECT member_id, name FROM members
UNION ALL
SELECT order_id FROM orders;
```

두 번째 SELECT에도 대응 열이 두 개 있어야 한다. 열 이름은 달라도 위치가 중요하며 타입은 호환되어야 한다.

```sql
SELECT member_id AS id, name AS label
FROM members
UNION ALL
SELECT CAST(order_id AS VARCHAR(20)), status
FROM orders;
```

숫자 주문 번호를 문자로 변환해 첫 번째 열의 타입 계열을 맞췄다. 실제 변환 함수와 타입 이름은 DBMS별로 조금 다르다.

## ORDER BY는 전체 결과 끝에 둔다

```sql
SELECT member_id FROM members WHERE city = '서울'
UNION ALL
SELECT member_id FROM members WHERE grade = 'GOLD'
ORDER BY member_id;
```

마지막 `ORDER BY`는 결합된 전체 결과를 정렬한다. 일반적으로 각 SELECT 중간에 바로 ORDER BY를 둘 수 없으며, 개별 정렬이 꼭 필요하면 서브쿼리와 제한 절의 의미까지 함께 검토해야 한다.

ORDER BY에서 사용할 열 이름은 최종 결과, 즉 첫 번째 SELECT가 정한 열 이름을 기준으로 잡는 것이 안전하다.

## 연산 순서와 괄호

집합 연산자를 여러 개 섞으면 DBMS와 표준의 우선순위 규칙을 확인해야 한다. 의도한 순서가 중요하다면 괄호 또는 서브쿼리로 단계를 명확히 표현한다.

```sql
SELECT ...
FROM (
  SELECT ...
  UNION
  SELECT ...
) u
INTERSECT
SELECT ...;
```

## NULL과 중복 제거

일반 비교에서 `NULL = NULL`은 UNKNOWN이지만, `UNION` 같은 중복 제거에서는 대응 열의 NULL들을 같은 중복 행으로 취급해 하나로 합칠 수 있다. 일반 WHERE 비교의 3값 논리와 집합 결과의 중복 판정 규칙을 섞지 않는다.

## 시험에서는 어떻게 묻나

- 각 SELECT 결과를 주고 연산자별 최종 행을 고르게 한다.
- `UNION`과 `UNION ALL`의 행 수 차이를 묻는다.
- 여러 열 중 한 열만 다를 때 중복으로 제거되는지 묻는다.
- 차집합의 방향과 ORDER BY 위치를 함정으로 낸다.

## 짧은 확인

A가 `(1, X), (2, Y)`, B가 `(1, Z), (2, Y)`일 때 `A UNION B`는 몇 행일까?

<Collapse title="확인하기">

3행이다. `(2, Y)`만 두 열 모두 같아서 하나로 합쳐지고, `(1, X)`와 `(1, Z)`는 두 번째 열이 달라 별도 행이다.

</Collapse>

## 흔한 실수와 진단법

| 증상 | 원인 | 확인 |
| --- | --- | --- |
| 열 수 오류 | SELECT 목록 개수 불일치 | 각 SELECT 열에 1, 2, 3 번호 표시 |
| 타입 오류 | 같은 위치 타입 비호환 | 대응 열의 타입을 나란히 적기 |
| 예상보다 행이 적음 | UNION이 중복 제거 | UNION ALL 결과와 비교 |
| 차집합 결과가 반대 | SELECT 순서 뒤바뀜 | “첫째에서 둘째를 뺀다”라고 읽기 |

## 정리

<Callout type="default">
  - 집합 연산자는 호환되는 두 SELECT 결과를 세로로 결합한다.
  - UNION은 중복 제거, UNION ALL은 중복 유지, INTERSECT는 공통, EXCEPT/MINUS는 차이를 구한다.
  - 중복은 선택한 모든 열의 값 조합으로 판단한다.
  - ORDER BY는 결합된 전체 결과의 마지막에 둔다.
</Callout>
