## 모델과 SQL은 어떻게 연결되는가?

데이터 모델(ERD)은 **"무엇을 어떻게 저장할지"**의 설계도입니다. SQL은 그 설계도를 **실제로 구현하고 조작**하는 언어입니다.

모델과 SQL의 대응 관계:

| 데이터 모델 | SQL |
|------------|-----|
| 엔터티 | `CREATE TABLE` |
| 속성 | 컬럼 (`열 이름 데이터타입`) |
| 기본키 (PK) | `PRIMARY KEY` 제약 |
| 외래키 (FK) | `FOREIGN KEY ... REFERENCES` |
| 1:N 관계 | JOIN 조건 (`ON A.id = B.a_id`) |
| 엔터티 인스턴스 | `INSERT`로 추가한 행 |

## ERD를 CREATE TABLE로 변환하기

### 1단계: ERD 확인

아래 ERD를 SQL로 변환합니다.

<Table>
  <thead>
    <tr><th>엔터티</th><th>속성(타입, 구분)</th></tr>
  </thead>
  <tbody>
    <tr><td>고객</td><td>고객번호(number, PK), 이름(string), 이메일(string), 등급(string)</td></tr>
    <tr><td>주문</td><td>주문번호(number, PK), 고객번호(number, FK), 주문일(date), 총금액(number), 배송상태(string)</td></tr>
    <tr><td>주문상품</td><td>주문번호(number, PK/FK), 상품번호(number, PK/FK), 수량(number), 단가(number)</td></tr>
    <tr><td>상품</td><td>상품번호(number, PK), 상품명(string), 가격(number), 카테고리(string)</td></tr>
  </tbody>
</Table>

**관계:** 고객 1 : 주문 0–N("한다") · 주문 1 : 주문상품 1–N("포함한다") · 상품 1 : 주문상품 0–N("포함된다")

### 2단계: CREATE TABLE 변환

**규칙:**
1. 각 엔터티 → 하나의 테이블
2. 속성 → 컬럼 (데이터 타입 결정)
3. PK → `PRIMARY KEY` 제약
4. 참조 관계 → `FOREIGN KEY ... REFERENCES`
5. 부모 테이블을 자식 테이블보다 먼저 생성 (FK 참조가 있어야 하므로)

```sql
-- 1. 부모 테이블 먼저 생성
CREATE TABLE 고객 (
    고객번호  NUMBER(10)    NOT NULL,
    이름      VARCHAR2(50)  NOT NULL,
    이메일    VARCHAR2(100) UNIQUE,
    등급      VARCHAR2(10)  DEFAULT 'BRONZE',
    CONSTRAINT PK_고객 PRIMARY KEY (고객번호)
);

CREATE TABLE 상품 (
    상품번호  NUMBER(10)    NOT NULL,
    상품명    VARCHAR2(100) NOT NULL,
    가격      NUMBER(10)    NOT NULL,
    카테고리  VARCHAR2(50),
    CONSTRAINT PK_상품 PRIMARY KEY (상품번호)
);

-- 2. 자식 테이블 생성 (부모 테이블 참조)
CREATE TABLE 주문 (
    주문번호  NUMBER(10)    NOT NULL,
    고객번호  NUMBER(10)    NOT NULL,    -- FK
    주문일    DATE          DEFAULT SYSDATE,
    총금액    NUMBER(15)    DEFAULT 0,
    배송상태  VARCHAR2(20)  DEFAULT '준비중',
    CONSTRAINT PK_주문 PRIMARY KEY (주문번호),
    CONSTRAINT FK_주문_고객 FOREIGN KEY (고객번호)
        REFERENCES 고객(고객번호)
);

-- 3. 교차 테이블 생성 (두 부모 테이블 참조)
CREATE TABLE 주문상품 (
    주문번호  NUMBER(10)  NOT NULL,  -- FK이자 PK의 일부
    상품번호  NUMBER(10)  NOT NULL,  -- FK이자 PK의 일부
    수량      NUMBER(5)   NOT NULL,
    단가      NUMBER(10)  NOT NULL,
    CONSTRAINT PK_주문상품 PRIMARY KEY (주문번호, 상품번호),
    CONSTRAINT FK_주문상품_주문 FOREIGN KEY (주문번호)
        REFERENCES 주문(주문번호),
    CONSTRAINT FK_주문상품_상품 FOREIGN KEY (상품번호)
        REFERENCES 상품(상품번호)
);
```

<Callout type="info">
  테이블 생성 순서가 중요합니다. **고객, 상품 → 주문 → 주문상품** 순서로 생성해야 합니다. 자식 테이블의 FK가 참조하는 부모 테이블이 먼저 존재해야 하기 때문입니다.
</Callout>

## 관계가 JOIN 조건이 되는 원리

ERD에서 두 엔터티를 잇는 선(관계)은 SQL에서 **JOIN의 `ON` 조건**이 됩니다.

### 관계 → JOIN 변환 규칙

| ERD 관계 | 외래키 | JOIN 조건 |
|---------|--------|----------|
| 고객(1) ─ 주문(N) | 주문.고객번호 | `고객.고객번호 = 주문.고객번호` |
| 주문(1) ─ 주문상품(N) | 주문상품.주문번호 | `주문.주문번호 = 주문상품.주문번호` |
| 상품(1) ─ 주문상품(N) | 주문상품.상품번호 | `상품.상품번호 = 주문상품.상품번호` |

## 실제 SELECT + JOIN 쿼리와 결과

### 샘플 데이터

먼저 테이블에 데이터를 넣겠습니다.

```sql
INSERT INTO 고객 VALUES (1001, '김민준', 'minjun@example.com', 'GOLD');
INSERT INTO 고객 VALUES (1002, '이서연', 'seoyeon@example.com', 'SILVER');
INSERT INTO 고객 VALUES (1003, '박지호', 'jiho@example.com', 'BRONZE');

INSERT INTO 상품 VALUES (2001, '노트북', 1200000, '전자기기');
INSERT INTO 상품 VALUES (2002, '마우스', 30000, '전자기기');
INSERT INTO 상품 VALUES (2003, '책상', 250000, '가구');

INSERT INTO 주문 VALUES (5001, 1001, DATE '2024-02-01', 1230000, '배송완료');
INSERT INTO 주문 VALUES (5002, 1002, DATE '2024-02-03', 30000, '배송중');
INSERT INTO 주문 VALUES (5003, 1001, DATE '2024-02-05', 250000, '준비중');

INSERT INTO 주문상품 VALUES (5001, 2001, 1, 1200000);
INSERT INTO 주문상품 VALUES (5001, 2002, 1, 30000);
INSERT INTO 주문상품 VALUES (5002, 2002, 1, 30000);
INSERT INTO 주문상품 VALUES (5003, 2003, 1, 250000);
```

### 쿼리 1: 고객별 주문 목록 (1:N 조인)

```sql
SELECT
    c.이름,
    c.등급,
    o.주문번호,
    o.주문일,
    o.총금액,
    o.배송상태
FROM 고객 c
JOIN 주문 o ON c.고객번호 = o.고객번호
ORDER BY c.고객번호, o.주문일;
```

**결과:**

| 이름 | 등급 | 주문번호 | 주문일 | 총금액 | 배송상태 |
|------|------|---------|--------|--------|---------|
| 김민준 | GOLD | 5001 | 2024-02-01 | 1,230,000 | 배송완료 |
| 김민준 | GOLD | 5003 | 2024-02-05 | 250,000 | 준비중 |
| 이서연 | SILVER | 5002 | 2024-02-03 | 30,000 | 배송중 |

고객 테이블의 `고객번호`와 주문 테이블의 `고객번호`가 같은 행끼리 연결됩니다. 박지호(1003)는 주문이 없으므로 결과에 나타나지 않습니다 (INNER JOIN 기준).

### 쿼리 2: 주문에 포함된 상품 상세 (3개 테이블 조인)

```sql
SELECT
    o.주문번호,
    c.이름      AS 고객명,
    p.상품명,
    op.수량,
    op.단가,
    (op.수량 * op.단가) AS 소계
FROM 주문 o
JOIN 고객       c  ON o.고객번호  = c.고객번호
JOIN 주문상품   op ON o.주문번호  = op.주문번호
JOIN 상품       p  ON op.상품번호 = p.상품번호
WHERE o.주문번호 = 5001;
```

**결과:**

| 주문번호 | 고객명 | 상품명 | 수량 | 단가 | 소계 |
|---------|--------|--------|------|------|------|
| 5001 | 김민준 | 노트북 | 1 | 1,200,000 | 1,200,000 |
| 5001 | 김민준 | 마우스 | 1 | 30,000 | 30,000 |

하나의 쿼리가 4개 테이블을 거칩니다. 각 JOIN의 `ON` 조건은 ERD의 관계 선과 정확히 대응됩니다.

### 쿼리 3: 고객별 총 주문금액 (집계)

```sql
SELECT
    c.이름,
    c.등급,
    COUNT(o.주문번호) AS 주문건수,
    SUM(o.총금액)     AS 총주문금액
FROM 고객 c
LEFT JOIN 주문 o ON c.고객번호 = o.고객번호
GROUP BY c.고객번호, c.이름, c.등급
ORDER BY 총주문금액 DESC NULLS LAST;
```

**결과:**

| 이름 | 등급 | 주문건수 | 총주문금액 |
|------|------|---------|-----------|
| 김민준 | GOLD | 2 | 1,480,000 |
| 이서연 | SILVER | 1 | 30,000 |
| 박지호 | BRONZE | 0 | NULL |

`LEFT JOIN`을 사용하면 주문이 없는 박지호도 결과에 포함됩니다. `INNER JOIN`을 쓰면 박지호는 결과에서 빠집니다.

## 모델 이해가 SQL 작성을 쉽게 하는 이유

ERD를 잘 이해하면 SQL 작성이 훨씬 쉬워지는 이유를 구체적으로 살펴봅니다.

### 1. 어떤 테이블을 조인해야 하는지 바로 보인다

"고객 이름과 주문한 상품명을 함께 보고 싶다"는 요구사항이 오면:

ERD를 보면 **고객 → 주문 → 주문상품 → 상품** 경로로 연결되어 있음을 바로 알 수 있습니다. JOIN 순서와 ON 조건이 자동으로 결정됩니다.

### 2. JOIN 조건 오류를 예방한다

ERD 없이 SQL을 작성하면 잘못된 컬럼으로 조인하는 실수가 발생합니다.

```sql
-- 잘못된 조인: 아무 의미 없는 조건
FROM 고객 c JOIN 주문 o ON c.이름 = o.배송상태  -- 논리적 오류!

-- 올바른 조인: ERD의 FK 관계 그대로
FROM 고객 c JOIN 주문 o ON c.고객번호 = o.고객번호  -- 정확!
```

### 3. NULL과 OUTER JOIN을 언제 써야 하는지 안다

ERD에서 선택성(o, 원)이 표시된 쪽은 데이터가 없을 수 있습니다. 이런 경우 `INNER JOIN`을 쓰면 데이터가 누락됩니다.

`고객 ||--o{ 주문`에서 고객 쪽이 `o{`이므로 고객은 주문 없이 존재할 수 있습니다. 모든 고객을 보려면 `LEFT JOIN`이 필요합니다.

## 핵심 정리

- **엔터티 → 테이블**, **속성 → 컬럼**, **관계 → JOIN 조건**으로 변환된다
- 테이블 생성 순서는 **부모 → 자식** 순서여야 FK 참조가 가능하다
- JOIN의 `ON` 조건은 ERD에서 FK가 연결된 관계 선과 정확히 대응된다
- ERD의 **선택성**(o)이 있는 쪽은 `INNER JOIN`이 아닌 `OUTER JOIN`이 필요할 수 있다
- 데이터 모델을 이해하면 복잡한 다중 테이블 조인도 체계적으로 작성할 수 있다
