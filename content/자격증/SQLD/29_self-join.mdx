## 이번 편의 목표

- 셀프 조인이 테이블 복사가 아니라 같은 테이블의 역할 분리임을 설명한다.
- 직원·관리자처럼 한 테이블 안의 참조 관계를 조인한다.
- 같은 값·범위 조건으로 행과 행의 쌍을 만들 때 중복을 제어한다.
- 내부·외부 셀프 조인의 결과 차이를 판단한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 셀프 조인(Self Join) | 한 테이블을 서로 다른 두 역할처럼 두 번 참조해 연결하는 조인 |
| 별칭(Alias) | 같은 테이블의 역할을 구분하는 짧은 이름 |
| 자기참조 외래키 | 같은 테이블의 다른 행 식별자를 가리키는 열 |
| 대칭 중복 | A-B와 B-A처럼 같은 한 쌍이 방향만 바뀌어 두 번 나오는 현상 |

## 선수지식과 핵심 질문

선수지식은 [21. 조인](./21_joins)과 [28. 계층형 질의](./28_hierarchical-queries)다.

핵심 질문은 **같은 표의 한 행을 기준 행, 다른 행을 비교 대상으로 구분해 어떻게 연결하는가**이다.

## 같은 테이블에 두 역할 붙이기

`employees`

| employee_id | employee_name | manager_id |
| --- | --- | --- |
| E01 | 대표 | NULL |
| E02 | 민지 | E01 |
| E03 | 준호 | E01 |
| E04 | 소라 | E02 |
| E05 | 현우 | E02 |

`manager_id`는 같은 `employees` 테이블의 `employee_id`를 가리킨다.

```text
직원 역할 e.manager_id ─── 관리자 역할 m.employee_id
```

```sql
SELECT e.employee_name AS employee,
       m.employee_name AS manager
FROM employees e
LEFT JOIN employees m
  ON e.manager_id = m.employee_id
ORDER BY e.employee_id;
```

| employee | manager |
| --- | --- |
| 대표 | NULL |
| 민지 | 대표 |
| 준호 | 대표 |
| 소라 | 민지 |
| 현우 | 민지 |

물리적으로 테이블을 복사한 것이 아니다. 같은 테이블을 `e`와 `m`이라는 두 참조로 읽고, 각 참조가 담당하는 행을 조인한다.

<Callout type="info">
  셀프 조인에서는 거의 모든 열 이름이 양쪽에 같으므로 `e.employee_name`, `m.employee_name`처럼 별칭을 생략하지 않는다.
</Callout>

## 왜 LEFT JOIN인가

대표의 `manager_id`는 NULL이므로 관리자 짝이 없다. 내부 조인을 쓰면 대표 행이 사라진다. 모든 직원을 보여 주고 관리자 없는 최상위 직원도 남기려면 직원 역할 `e`를 왼쪽에 둔 LEFT JOIN이 알맞다.

| 조인 | 대표 행 |
| --- | --- |
| INNER JOIN | 제거 |
| LEFT JOIN | 보존, manager는 NULL |

## 같은 도시 회원 쌍 찾기

`members`

| member_id | name | city |
| --- | --- | --- |
| M01 | 민지 | 서울 |
| M02 | 준호 | 부산 |
| M03 | 소라 | 서울 |
| M04 | 현우 | 서울 |

```sql
SELECT a.name AS member_a,
       b.name AS member_b,
       a.city
FROM members a
JOIN members b
  ON a.city = b.city
 AND a.member_id < b.member_id
ORDER BY a.member_id, b.member_id;
```

| member_a | member_b | city |
| --- | --- | --- |
| 민지 | 소라 | 서울 |
| 민지 | 현우 | 서울 |
| 소라 | 현우 | 서울 |

`a.member_id < b.member_id`에는 두 역할이 있다.

1. 같은 행끼리 M01-M01로 연결되는 것을 막는다.
2. M01-M03과 M03-M01 중 한 방향만 남긴다.

단순히 `a.member_id <> b.member_id`를 쓰면 방향만 다른 쌍이 모두 나와 결과가 두 배가 된다.

## 이전·다음 행을 셀프 조인으로 찾기

주문 번호가 연속이라고 단순 가정하면 이전 주문을 다음처럼 연결할 수 있다.

```sql
SELECT cur.order_id,
       cur.total_amount,
       prev.total_amount AS prev_amount
FROM orders cur
LEFT JOIN orders prev
  ON prev.order_id = cur.order_id - 1;
```

하지만 실제 주문 번호가 건너뛰면 “번호 - 1” 행이 없을 수 있다. 정렬상 바로 이전 행이 필요하면 [26. 윈도우 함수](./26_window-functions)의 `LAG`가 더 정확하고 읽기 쉽다.

## 범위가 겹치는 행 찾기

예약 시간 충돌도 셀프 조인으로 찾을 수 있다.

`reservations`

| reservation_id | room_id | start_at | end_at |
| --- | --- | --- | --- |
| R1 | A | 10:00 | 11:00 |
| R2 | A | 10:30 | 12:00 |
| R3 | A | 12:00 | 13:00 |

두 반개 구간 `[start, end)`이 겹치는 조건은 `a.start_at < b.end_at AND b.start_at < a.end_at`이다.

```sql
SELECT a.reservation_id, b.reservation_id
FROM reservations a
JOIN reservations b
  ON a.room_id = b.room_id
 AND a.reservation_id < b.reservation_id
 AND a.start_at < b.end_at
 AND b.start_at < a.end_at;
```

결과는 R1-R2 한 쌍이다. R2가 12:00에 끝나고 R3가 12:00에 시작하므로 반개 구간 기준으로 겹치지 않는다.

## 계층형 질의와 셀프 조인의 차이

| 목적 | 적합한 방식 |
| --- | --- |
| 직원과 직접 관리자 한 단계 | 셀프 조인 한 번 |
| 모든 상위 관리자 또는 모든 하위 직원 | 계층형 질의·재귀 CTE |
| 같은 도시 회원 쌍 | 셀프 조인 |
| 정렬상 이전 행 | 대개 LAG |

셀프 조인을 여러 번 이어 붙이면 조부모처럼 고정된 단계는 구할 수 있지만, 깊이가 정해지지 않은 트리 전체에는 재귀 방식이 알맞다.

## 시험에서는 어떻게 묻나

- 같은 테이블에 두 별칭이 필요한 이유를 묻는다.
- 최상위 행을 보존할 때 외부 조인을 선택하게 한다.
- `a.id < b.id`가 자기 자신과 대칭 중복을 동시에 제거함을 묻는다.
- 직접 한 단계와 전체 계층 탐색을 구분하게 한다.

## 짧은 확인

같은 팀의 두 직원 쌍을 찾는 조건이 `a.team_id = b.team_id AND a.employee_id <> b.employee_id`라면 어떤 문제가 생길까?

<Collapse title="확인하기">

A-B와 B-A가 모두 나오는 대칭 중복이 생긴다. 순서 없는 한 쌍만 필요하면 고유 식별자에 `a.employee_id < b.employee_id`를 사용한다.

</Collapse>

## 흔한 실수와 진단법

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 열이 모호하다는 오류 | 별칭 누락 | 모든 열에 역할 별칭 지정 |
| 같은 쌍이 두 번 나옴 | `<>`만 사용 | 고유키 `<` 조건 검토 |
| 최상위 직원이 사라짐 | INNER JOIN 사용 | 기준 역할을 LEFT JOIN으로 보존 |
| 깊은 계층이 일부만 나옴 | 고정 횟수 셀프 조인 | 계층형 질의 또는 재귀 CTE 사용 |

## 정리

<Callout type="default">
  - 셀프 조인은 한 테이블을 서로 다른 역할의 별칭으로 두 번 참조한다.
  - 자기참조 관계의 직접 부모 이름을 찾을 때 유용하다.
  - 순서 없는 행 쌍은 고유키 `<` 조건으로 자기 연결과 대칭 중복을 막는다.
  - 깊이가 가변적인 전체 계층은 재귀 질의를 사용한다.
</Callout>
