  **이번 문서의 목표:** WHERE 조건을 빠뜨렸을 때의 위험성을 이해하고, MERGE로 조건에 따라 INSERT/UPDATE를 자동으로 선택하는 방법을 익힙니다.
</Callout>

## DML이란?

DML(Data Manipulation Language)은 테이블 안의 **행 데이터**를 다루는 SQL 명령입니다.

| 명령    | 기능             |
| ------- | ---------------- |
| INSERT  | 새 행 추가       |
| UPDATE  | 기존 행 수정     |
| DELETE  | 기존 행 삭제     |
| MERGE   | 조건에 따라 INSERT 또는 UPDATE |

<Callout type="warning">
  DML은 **자동 커밋(Auto Commit)이 되지 않습니다.** COMMIT을 실행해야 다른 세션에서 변경 내용을 볼 수 있습니다. ROLLBACK으로 취소도 가능합니다.
</Callout>

## INSERT: 데이터 삽입

### 단일 행 INSERT

```sql
INSERT INTO EMP (사원번호, 이름, 부서번호, 직급, 급여)
VALUES (1006, '한지수', 30, '사원', 2700000);
```

**실행 후 EMP 테이블**

| 사원번호 | 이름   | 부서번호 | 직급 | 급여    |
| -------- | ------ | -------- | ---- | ------- |
| 1001     | 김민준 | 10       | 과장 | 4500000 |
| 1002     | 이서연 | 20       | 대리 | 3200000 |
| 1003     | 박지훈 | 10       | 부장 | 6000000 |
| 1004     | 최수아 | 30       | 사원 | 2500000 |
| 1005     | 정도윤 | 20       | 과장 | 4800000 |
| **1006** | **한지수** | **30** | **사원** | **2700000** |

컬럼 목록을 생략하면 테이블 정의 순서대로 값을 넣어야 합니다. NULL을 넣을 때는 명시적으로 `NULL`을 쓰거나, 컬럼 목록에서 해당 컬럼을 생략합니다.

```sql
-- 관리자번호를 NULL로 삽입 (두 가지 방법)
INSERT INTO EMP (사원번호, 이름, 부서번호, 관리자번호)
VALUES (1007, '오태양', 40, NULL);  -- 방법 1: 명시적 NULL

INSERT INTO EMP (사원번호, 이름, 부서번호)
VALUES (1008, '윤하늘', 40);  -- 방법 2: 컬럼 생략 (관리자번호 자동 NULL)
```

### 서브쿼리를 이용한 다중 행 INSERT

다른 테이블의 데이터를 조회하여 한 번에 여러 행을 삽입합니다.

```sql
-- EMP_BACKUP 테이블에 급여 400만 이상 사원 복사
INSERT INTO EMP_BACKUP (사원번호, 이름, 급여)
SELECT 사원번호, 이름, 급여
FROM   EMP
WHERE  급여 >= 4000000;
```

이 방식에서는 `VALUES` 절 없이 `SELECT` 결과가 바로 삽입됩니다.

## UPDATE: 데이터 수정

```sql
-- 1004번 최수아의 급여를 300만으로 올리고 직급을 대리로 변경
UPDATE EMP
SET    급여 = 3000000, 직급 = '대리'
WHERE  사원번호 = 1004;
```

**실행 전 → 실행 후**

| 사원번호 | 이름   | 직급 | 급여    |
| -------- | ------ | ---- | ------- |
| 1004     | 최수아 | 사원 → **대리** | 2500000 → **3000000** |

<Callout type="warning">
  **WHERE 없는 UPDATE는 전체 행을 수정합니다!**
  ```sql
  UPDATE EMP SET 급여 = 0;  -- 모든 사원 급여가 0이 됨!
  ```
  SQLD 시험에서 WHERE 없이 UPDATE/DELETE 했을 때 영향받는 행 수를 묻는 문제가 자주 출제됩니다.
</Callout>

서브쿼리를 SET 절에 사용할 수도 있습니다.

```sql
-- 개발팀(10) 사원 급여를 개발팀 평균으로 일괄 변경
UPDATE EMP
SET    급여 = (SELECT AVG(급여) FROM EMP WHERE 부서번호 = 10)
WHERE  부서번호 = 10;
```

## DELETE: 데이터 삭제

```sql
-- 사원번호 1006인 행 삭제
DELETE FROM EMP
WHERE 사원번호 = 1006;
```

<Callout type="warning">
  **WHERE 없는 DELETE는 전체 행을 삭제합니다!**
  ```sql
  DELETE FROM EMP;  -- EMP 테이블의 모든 행이 삭제됨!
  ```
  DELETE는 ROLLBACK이 가능합니다. TRUNCATE는 ROLLBACK이 불가능합니다.
</Callout>

### DELETE vs TRUNCATE 비교

| 항목               | DELETE                     | TRUNCATE                  |
| ------------------ | -------------------------- | ------------------------- |
| 종류               | DML                        | DDL                       |
| WHERE 조건         | 사용 가능                  | 사용 불가 (전체 삭제)     |
| ROLLBACK           | 가능                       | 불가능 (자동 COMMIT)      |
| 로그 기록          | 행 단위 기록               | 최소화 (빠름)             |
| 처리 속도          | 느림                       | 빠름                      |

## MERGE: 조건부 INSERT/UPDATE

원본 테이블과 대상 테이블을 비교하여, 일치하는 행은 UPDATE, 없는 행은 INSERT합니다.

```sql
MERGE INTO EMP_BACKUP T           -- 대상 테이블
USING EMP S                        -- 원본 테이블
ON (T.사원번호 = S.사원번호)       -- 비교 조건
WHEN MATCHED THEN                  -- 일치: UPDATE
  UPDATE SET T.급여 = S.급여,
             T.직급 = S.직급
WHEN NOT MATCHED THEN              -- 불일치: INSERT
  INSERT (사원번호, 이름, 급여)
  VALUES (S.사원번호, S.이름, S.급여);
```

MERGE는 **UPSERT(Update + Insert)** 패턴을 구현할 때 사용합니다. ETL 작업이나 데이터 동기화에서 자주 씁니다.

## SQLD 시험 자주 출제 포인트

1. **NULL 삽입**: 컬럼 목록 생략 또는 명시적 `NULL` 사용
2. **WHERE 없는 UPDATE/DELETE**: 영향받는 행 = 테이블 전체 행 수
3. **DELETE vs TRUNCATE**: ROLLBACK 가능 여부, DDL vs DML 구분
4. **COMMIT 전 가시성**: 변경한 세션 본인만 볼 수 있음, 다른 세션은 COMMIT 후
5. **MERGE**: WHEN MATCHED(UPDATE), WHEN NOT MATCHED(INSERT) 구분

## 핵심 정리

- **INSERT**: 단일 행 `VALUES`, 다중 행은 `SELECT` 서브쿼리 활용
- **UPDATE**: `SET 컬럼=값`, WHERE 없으면 전체 행 수정
- **DELETE**: WHERE 없으면 전체 행 삭제, ROLLBACK 가능
- **TRUNCATE**: DDL, 전체 삭제만 가능, ROLLBACK 불가
- **MERGE**: 대상 테이블과 원본 비교 → 일치 시 UPDATE, 불일치 시 INSERT
- **DML 공통**: 자동 COMMIT 없음, COMMIT/ROLLBACK으로 트랜잭션 관리
