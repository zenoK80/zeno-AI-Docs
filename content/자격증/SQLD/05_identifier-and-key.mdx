## 식별자(Identifier)란?

**식별자**(Identifier)는 엔터티에서 각 **인스턴스**(행)**를 유일하게 구별**할 수 있게 해주는 속성 또는 속성의 조합입니다.

현실 세계에서 주민등록번호가 각 사람을 유일하게 식별하듯, 데이터베이스에서는 식별자가 각 행을 구별합니다.

## 키의 종류

### 수퍼키 (Super Key)

**유일성**만 만족하는 속성의 집합입니다. 중복 값이 없으면 됩니다.

예시 - 고객 테이블 `(고객번호, 이름, 이메일)`:
- `{고객번호}` → 수퍼키 (유일)
- `{이메일}` → 수퍼키 (이메일은 중복 없다고 가정)
- `{고객번호, 이름}` → 수퍼키 (유일하긴 하지만 이름이 불필요)
- `{이름}` → 수퍼키가 아님 (동명이인 가능)

### 후보키 (Candidate Key)

**유일성 + 최소성**을 모두 만족하는 속성의 집합입니다.

- **유일성**: 중복 값이 없어야 합니다
- **최소성**: 키를 구성하는 속성 중 하나라도 빼면 유일성이 깨집니다

위 예시에서:
- `{고객번호}` → 후보키 (유일 + 최소)
- `{이메일}` → 후보키 (유일 + 최소)
- `{고객번호, 이름}` → **후보키 아님** (이름을 빼도 고객번호만으로 유일하므로 최소성 위반)

### 기본키 (Primary Key, PK)

**후보키 중에서 하나를 선택**하여 테이블의 대표 식별자로 지정한 것입니다.

기본키의 조건:
1. **NOT NULL**: 값이 반드시 있어야 합니다 (NULL 불가)
2. **UNIQUE**: 테이블 내에서 중복 값이 없어야 합니다
3. **변경 불가**: 한번 정해지면 바뀌지 않아야 합니다 (안정성)
4. **단순**: 가능한 속성 개수가 적어야 합니다

<Callout type="warning">
  "기본키는 NOT NULL이고 UNIQUE해야 한다"는 조건은 SQLD 시험에서 매우 자주 출제됩니다. NULL이 허용되는 열은 절대 기본키가 될 수 없습니다.
</Callout>

### 대체키 (Alternate Key)

후보키가 여러 개일 때, **기본키로 선택되지 않은 나머지 후보키**들입니다.

예시: 고객 테이블에서
- 후보키: `{고객번호}`, `{이메일}`
- 기본키로 `{고객번호}` 선택
- `{이메일}`은 → **대체키** (유니크 제약은 유지됨)

### 외래키 (Foreign Key, FK)

다른 테이블의 기본키를 **참조**하는 속성입니다. 두 테이블 간의 관계를 물리적으로 구현합니다.

```sql
CREATE TABLE 주문 (
    주문번호  NUMBER(10)  NOT NULL,
    고객번호  NUMBER(10)  NOT NULL,   -- 고객 테이블의 기본키를 참조
    주문일    DATE        NOT NULL,
    CONSTRAINT PK_주문 PRIMARY KEY (주문번호),
    CONSTRAINT FK_주문_고객 FOREIGN KEY (고객번호)
        REFERENCES 고객(고객번호)     -- 외래키 선언
);
```

## 참조 무결성 (Referential Integrity)

외래키는 **참조 무결성**을 보장합니다. 참조 무결성이란 외래키 값이 항상 참조 대상 테이블에 존재해야 한다는 규칙입니다.

예시:
- 주문 테이블의 고객번호 `9999`가 있다면, 고객 테이블에도 `9999`가 반드시 있어야 합니다
- 존재하지 않는 고객번호를 가진 주문은 입력할 수 없습니다 → **무결성 위반**
- 주문이 있는 고객을 고객 테이블에서 삭제하면 참조 무결성 위반이 발생합니다

```sql
-- 이 INSERT는 실패합니다 (고객번호 9999가 고객 테이블에 없으면)
INSERT INTO 주문 (주문번호, 고객번호, 주문일)
VALUES (6001, 9999, SYSDATE);
-- ORA-02291: 무결성 제약조건 위반 - 부모 키가 없습니다
```

## 식별 관계 vs 비식별 관계

관계형 DB 설계에서 중요한 개념이 **식별 관계**와 **비식별 관계**입니다.

### 식별 관계 (Identifying Relationship)

**부모 엔터티의 기본키가 자식 엔터티의 기본키**(PK)**로 포함**되는 관계입니다.

- 자식 엔터티는 부모 없이 독립적으로 존재할 수 없습니다
- ERD에서 **실선**으로 표현합니다

<Table>
  <thead>
    <tr><th>엔터티</th><th>속성</th></tr>
  </thead>
  <tbody>
    <tr><td>주문</td><td>주문번호(PK), 고객번호(FK), 주문일</td></tr>
    <tr><td>주문상품</td><td>주문번호(PK/FK), 상품번호(PK/FK), 수량, 단가</td></tr>
  </tbody>
</Table>

**관계**(식별)**:** 주문 1 : 주문상품 1–N("포함한다")

**주문상품** 테이블의 기본키는 `(주문번호, 상품번호)` 복합키입니다. 주문번호는 주문 테이블의 PK이자 주문상품 테이블의 PK 일부입니다. 주문 없이는 주문상품도 없으므로 식별 관계입니다.

### 비식별 관계 (Non-Identifying Relationship)

**부모 엔터티의 기본키가 자식 엔터티의 일반 속성**(외래키)**으로만 포함**되는 관계입니다.

- 자식 엔터티는 부모와 독립적으로 존재할 수 있습니다 (FK가 선택사항인 경우)
- ERD에서 **점선**으로 표현합니다

<Table>
  <thead>
    <tr><th>엔터티</th><th>속성</th></tr>
  </thead>
  <tbody>
    <tr><td>고객</td><td>고객번호(PK), 이름, 이메일</td></tr>
    <tr><td>주문</td><td>주문번호(PK), 고객번호(FK), 주문일, 총금액</td></tr>
  </tbody>
</Table>

**관계**(비식별)**:** 고객 1 : 주문 0–N("한다")

**주문** 테이블의 기본키는 `주문번호`만입니다. 고객번호는 외래키(FK)지만 기본키의 일부가 아닙니다. 주문은 독립적인 주문번호로 식별됩니다.

### 식별 관계 vs 비식별 관계 비교

| 구분 | 식별 관계 | 비식별 관계 |
|------|-----------|-------------|
| 부모PK의 위치 | 자식의 **PK에 포함** | 자식의 **일반 FK** |
| 자식 독립성 | 부모 없이 존재 불가 | 부모 없어도 될 수 있음 |
| ERD 표기 | 실선 | 점선 |
| 예시 | 주문-주문상품 | 고객-주문 |
| 자식 PK | 복합키 (부모PK 포함) | 독자적인 단일 PK |

<Callout type="info">
  실무에서는 비식별 관계를 더 많이 사용합니다. 식별 관계는 계층이 깊어질수록 PK가 복잡해지는 단점이 있습니다.
</Callout>

## 복합키 (Composite Key)

두 개 이상의 속성을 조합하여 만든 키입니다. 주문상품 테이블처럼 단일 속성으로는 유일성을 보장할 수 없을 때 사용합니다.

```sql
CREATE TABLE 주문상품 (
    주문번호  NUMBER(10)  NOT NULL,
    상품번호  NUMBER(10)  NOT NULL,
    수량      NUMBER(5)   NOT NULL,
    단가      NUMBER(10)  NOT NULL,
    CONSTRAINT PK_주문상품 PRIMARY KEY (주문번호, 상품번호),
    CONSTRAINT FK_주문상품_주문 FOREIGN KEY (주문번호) REFERENCES 주문(주문번호),
    CONSTRAINT FK_주문상품_상품 FOREIGN KEY (상품번호) REFERENCES 상품(상품번호)
);
```

주문번호 혼자로는 여러 행이 같을 수 있고, 상품번호 혼자로도 여러 행이 같을 수 있습니다. 하지만 `(주문번호, 상품번호)` 조합은 하나의 주문에서 같은 상품이 두 번 담기지 않으므로 유일합니다.

## 핵심 정리

- **수퍼키**: 유일성만 만족
- **후보키**: 유일성 + 최소성 만족
- **기본키**: 후보키 중 선택된 대표 식별자, **NOT NULL + UNIQUE** 필수
- **대체키**: 기본키가 되지 못한 나머지 후보키
- **외래키**: 다른 테이블의 PK를 참조, 참조 무결성 보장
- **식별 관계**: 부모 PK가 자식 PK에 포함 (실선)
- **비식별 관계**: 부모 PK가 자식의 일반 FK (점선)
