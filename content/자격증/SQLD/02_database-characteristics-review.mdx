## 02편 복습

본문을 덮고 먼저 기억나는 내용을 떠올려 보자. 답이 바로 나오지 않아도 괜찮다. 직접 답한 뒤 해설과 비교해야 무엇을 다시 볼지 알 수 있다.

<Callout type="info">
문제를 먼저 풀고 나서 정답을 확인한다. 틀린 문제는 정답만 외우지 말고, 본문의 어떤 개념을 놓쳤는지 한 줄로 기록한다.
</Callout>

## 직접 풀어보기

### 문제 1

고객 앱과 상담 시스템이 같은 주문 상태를 조회하지만 상담원은 카드번호 전체를 볼 수 없다. 데이터베이스의 어떤 특징과 관리 기능이 함께 적용된 것인가?

### 문제 2

조회 속도를 높이기 위해 인덱스를 추가했지만 응용프로그램 SQL은 바꾸지 않았다. 어떤 독립성의 사례인가?

### 문제 3

상품명 표기가 시스템마다 `노트북`, `Laptop`, `랩탑`으로 달라 분석 결과가 세 상품으로 나뉘었다. 네 가지 특징 중 무엇이 부족한가?

## 정답과 해설

### 문제 1

여러 시스템이 같은 주문 데이터를 사용한다는 점은 공용 데이터의 특징이다. 상담원의 카드정보 접근을 제한한 것은 보안과 권한 관리다.

### 문제 2

물리적 데이터 독립성이다. 내부 저장·접근 구조가 바뀌었지만 외부 SQL과 논리 구조는 유지되었다.

### 문제 3

통합된 데이터의 의미 일관성이 부족하다. 공통 코드와 표준 용어를 정해 같은 상품을 하나로 식별해야 한다.

## 흔한 실수

- 공용과 공개를 같은 뜻으로 본다: 공용 데이터도 권한에 따라 접근을 제한한다.
- 저장된 데이터와 백업을 같은 뜻으로 본다: 저장은 지속성, 백업은 복구를 위한 별도 사본과 관련된다.
- 논리적·물리적 독립성의 방향을 바꾼다: 인덱스와 파일 배치는 물리, 테이블·속성 변화는 논리에 가깝다.
- 실시간을 무조건 즉시로 해석한다: 업무가 요구하는 시간 안에 접근할 수 있다는 의미다.
