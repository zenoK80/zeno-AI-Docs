## 이상현상 (Anomaly)

**이상현상**(Anomaly)은 데이터베이스 설계가 잘못되어 데이터를 삽입·수정·삭제할 때 발생하는 **의도치 않은 문제**입니다.

이상현상이 발생하는 근본 원인은 **하나의 테이블에 관련 없는 정보들을 함께 저장**하기 때문입니다.

### 문제 있는 테이블: 수강 정보

아래 테이블은 학생, 강좌, 교수 정보를 한 테이블에 모두 저장한 예입니다.

| 학생번호 | 학생명 | 강좌번호 | 강좌명 | 교수명 | 성적 |
|---------|--------|---------|--------|--------|------|
| S001 | 김민준 | C001 | 데이터베이스 | 이교수 | A |
| S001 | 김민준 | C002 | 알고리즘 | 박교수 | B+ |
| S002 | 이서연 | C001 | 데이터베이스 | 이교수 | A+ |
| S003 | 박지호 | C003 | 운영체제 | 최교수 | B |

### 삽입 이상 (Insertion Anomaly)

새 강좌 `C004 자료구조 (김교수)`를 추가하려 합니다. 그런데 이 테이블은 학생번호와 강좌번호가 함께 기본키입니다. **수강 학생이 없으면 강좌를 추가할 수 없습니다.**

```
-- 강좌만 추가하려 했지만 학생번호가 NULL이 되어 PK 위반
(NULL, NULL, C004, 자료구조, 김교수, NULL)  -- 불가능!
```

### 수정 이상 (Update Anomaly)

`C001 데이터베이스` 강좌의 교수를 `이교수`에서 `정교수`로 바꾸려 합니다. 이 강좌를 수강하는 학생이 여러 명이므로 여러 행을 모두 수정해야 합니다.

만약 일부 행만 수정하면 같은 강좌에 교수가 두 명이 되는 **데이터 불일치**가 발생합니다.

### 삭제 이상 (Deletion Anomaly)

`S003 박지호` 학생이 `C003 운영체제` 강좌를 취소합니다. 이 행을 삭제하면 `C003 운영체제 (최교수)` 강좌 정보도 **함께 사라집니다.**

## 함수 종속 (Functional Dependency)

**함수 종속**이란 속성 A의 값이 정해지면 속성 B의 값이 하나로 결정되는 관계입니다. `A → B`로 표기하고 "A가 B를 함수적으로 결정한다"고 읽습니다.

위 수강 테이블에서의 함수 종속:
- `강좌번호 → 강좌명`: 강좌번호가 같으면 강좌명도 같다
- `강좌번호 → 교수명`: 강좌번호가 같으면 교수명도 같다
- `(학생번호, 강좌번호) → 성적`: 학생과 강좌가 결정되면 성적이 결정된다

강좌명과 교수명이 기본키 전체`(학생번호, 강좌번호)`가 아닌 **강좌번호 하나**에만 종속되는 것이 문제입니다. 이것이 **부분 함수 종속**입니다.

## 1NF: 제1정규형

**제1정규형**(1NF)은 테이블의 모든 셀이 **원자값**(Atomic Value)을 가져야 하는 조건입니다.

원자값이란 더 이상 분해할 수 없는 하나의 값입니다.

### 1NF 위반 예시

| 학생번호 | 학생명 | 수강강좌 |
|---------|--------|---------|
| S001 | 김민준 | 데이터베이스, 알고리즘 |
| S002 | 이서연 | 데이터베이스 |

`수강강좌` 열에 여러 값이 쉼표로 구분되어 있습니다 → **1NF 위반**

### 1NF 변환 결과

| 학생번호 | 학생명 | 수강강좌 |
|---------|--------|---------|
| S001 | 김민준 | 데이터베이스 |
| S001 | 김민준 | 알고리즘 |
| S002 | 이서연 | 데이터베이스 |

각 행의 모든 셀이 원자값을 갖게 되었습니다. 하지만 여전히 학생명이 중복됩니다.

## 2NF: 제2정규형

**제2정규형**(2NF)은 1NF를 만족하면서 **부분 함수 종속을 제거**한 상태입니다.

**부분 함수 종속**이란 기본키가 복합키일 때, 기본키의 **일부**에만 종속되는 속성이 있는 것입니다.

### 2NF 변환 과정

문제 있는 수강 테이블 (1NF만 만족):

**기본키**: `(학생번호, 강좌번호)`

```
(학생번호, 강좌번호) → 성적         ← 완전 함수 종속 (정상)
강좌번호            → 강좌명        ← 부분 함수 종속 (문제!)
강좌번호            → 교수명        ← 부분 함수 종속 (문제!)
```

강좌명과 교수명이 기본키 전체가 아닌 강좌번호 하나에만 종속됩니다.

**해결**: 부분 함수 종속된 속성들을 별도 테이블로 분리합니다.

| 학생번호 | 강좌번호 | 성적 |
|---------|---------|------|
| S001 | C001 | A |
| S001 | C002 | B+ |
| S002 | C001 | A+ |
| S003 | C003 | B |

▲ **수강 테이블** (기본키: 학생번호+강좌번호, 완전 함수 종속만 남음)

| 강좌번호 | 강좌명 | 교수명 |
|---------|--------|--------|
| C001 | 데이터베이스 | 이교수 |
| C002 | 알고리즘 | 박교수 |
| C003 | 운영체제 | 최교수 |

▲ **강좌 테이블** (기본키: 강좌번호)

이제 강좌 교수를 바꾸면 강좌 테이블 한 행만 수정하면 됩니다.

## 3NF: 제3정규형

**제3정규형**(3NF)은 2NF를 만족하면서 **이행 함수 종속을 제거**한 상태입니다.

**이행 함수 종속**이란 `A → B → C` 형태로, A가 C를 직접 결정하는 것이 아니라 B를 통해 간접적으로 결정하는 것입니다.

### 3NF 위반 예시

| 학생번호 | 학과코드 | 학과명 | 학과위치 |
|---------|---------|--------|---------|
| S001 | D01 | 컴퓨터공학과 | 공학관 |
| S002 | D01 | 컴퓨터공학과 | 공학관 |
| S003 | D02 | 경영학과 | 경영관 |

**기본키**: `학생번호`

```
학생번호 → 학과코드        ← 정상
학과코드 → 학과명          ← 이행 종속! (학생번호 → 학과코드 → 학과명)
학과코드 → 학과위치        ← 이행 종속!
```

학과명과 학과위치는 학생번호가 아닌 학과코드에 종속됩니다. 같은 학과의 위치를 바꾸면 여러 행을 수정해야 합니다.

### 3NF 변환 결과

| 학생번호 | 학과코드 |
|---------|---------|
| S001 | D01 |
| S002 | D01 |
| S003 | D02 |

▲ **학생 테이블** (기본키: 학생번호)

| 학과코드 | 학과명 | 학과위치 |
|---------|--------|---------|
| D01 | 컴퓨터공학과 | 공학관 |
| D02 | 경영학과 | 경영관 |

▲ **학과 테이블** (기본키: 학과코드)

이제 공학관 위치가 바뀌면 학과 테이블 한 행만 수정하면 됩니다.

## 정규화 전체 흐름 정리

| 단계 | 조건 | 제거 대상 |
|------|------|-----------|
| **1NF** | 모든 속성이 원자값 | 다중값, 반복 그룹 |
| **2NF** | 1NF + 부분 함수 종속 제거 | 복합 PK의 일부에만 종속된 속성 |
| **3NF** | 2NF + 이행 함수 종속 제거 | PK가 아닌 일반 속성에 종속된 속성 |

<Callout type="info">
  SQLD 시험에서는 "이 테이블은 몇 정규형인가?" 또는 "다음 중 3NF를 위반하는 것은?" 형태로 출제됩니다. 각 정규형의 위반 조건을 명확히 암기하세요.
</Callout>

## 반정규화 (Denormalization)

정규화를 충분히 했다고 해서 끝이 아닙니다. 지나친 정규화는 **조인(JOIN)이 많아져 성능이 저하**될 수 있습니다.

**반정규화**는 성능 향상을 위해 의도적으로 정규화 원칙을 어기는 것입니다.

반정규화가 필요한 경우:
- 조회가 매우 빈번하고, 조인이 너무 많아 성능 문제가 발생할 때
- 집계 데이터(합계, 평균)를 자주 조회해야 할 때
- 배치 처리나 보고서용 테이블이 필요할 때

반정규화 방법:
- **테이블 합치기**: 자주 조인하는 두 테이블을 하나로 합침
- **컬럼 중복 추가**: 자주 필요한 컬럼을 다른 테이블에도 복사

<Callout type="warning">
  반정규화는 데이터 중복을 의도적으로 허용하므로, 수정 이상의 위험이 있습니다. 반드시 성능 문제가 실제로 있을 때만 적용하고, 데이터 동기화 방안을 마련해야 합니다.
</Callout>

## 핵심 정리

- **이상현상**: 잘못된 설계로 인한 삽입·수정·삭제 시 데이터 불일치 문제
- **1NF**: 모든 속성이 원자값 (다중값, 반복 그룹 제거)
- **2NF**: 1NF + 부분 함수 종속 제거 (복합키의 일부에만 종속된 속성 분리)
- **3NF**: 2NF + 이행 함수 종속 제거 (비키 속성 간 종속 제거)
- **반정규화**: 성능 향상을 위해 의도적으로 정규화를 일부 포기
