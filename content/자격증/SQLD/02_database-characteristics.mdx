## 이번 편의 목표

- 데이터베이스의 네 가지 고전적 특징을 사례에 적용한다.
- 데이터 독립성이 왜 필요한지 논리적·물리적 관점에서 설명한다.
- 무결성, 동시성, 보안, 회복의 역할을 구분한다.
- "실시간 접근"과 "항상 즉시 처리"를 혼동하지 않는다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 통합 | 같은 의미의 데이터를 중복·충돌 없이 한 기준으로 관리하는 것 |
| 공유 | 여러 사용자와 프로그램이 같은 데이터를 함께 사용하는 것 |
| 트랜잭션 | 하나의 업무로 묶여 전부 성공하거나 전부 취소되어야 하는 작업 단위 |
| 동시성 | 여러 사용자가 같은 시점에 데이터를 사용하거나 변경하는 성질 |
| 무결성 | 데이터가 정한 규칙에 맞고 서로 모순되지 않는 상태 |
| 백업 | 장애에 대비해 별도 위치에 저장한 데이터 사본 |
| 복구 | 장애 전의 올바른 상태로 데이터를 되돌리는 작업 |
| 데이터 독립성 | 저장 방식이나 구조의 일부가 바뀌어도 다른 계층의 영향을 줄이는 성질 |

파일도 데이터를 저장하지만, 데이터베이스는 저장뿐 아니라 동시 사용, 규칙 검사, 권한, 장애 복구를 하나의 관리 체계로 제공한다.

## 주변 개념 지도

여러 사용자가 같은 재고를 동시에 주문하면 단순 파일 수정은 값이 꼬이기 쉽다. DBMS는 트랜잭션과 동시성 제어로 작업 순서와 결과의 일관성을 지킨다.

<Callout type="info">
“저장되어 있다”는 데이터베이스의 한 특징일 뿐이다. 시험에서는 통합·운영·공유, 실시간 접근과 변화, 독립성 같은 특징을 사례에 연결해 구분한다.
</Callout>

## 파일 묶음과 데이터베이스는 무엇이 다를까

여러 파일을 한 폴더에 모았다고 데이터베이스가 되는 것은 아니다. 데이터베이스는 조직의 업무에 필요한 데이터를 중복과 충돌을 줄이도록 통합하고, 여러 사용자가 계속 활용할 수 있게 관리한다.

교재에서는 데이터베이스의 특징을 다음 네 가지로 정리한다.

```text
통합된 데이터 · 저장된 데이터 · 운영 데이터 · 공용 데이터
```

각 단어를 주문 시스템에 적용해 보자.

## 통합된 데이터

**통합된 데이터(integrated data)** 는 여러 곳의 데이터를 모으되 불필요한 중복을 통제하고 의미를 일관되게 만든 데이터다.

마케팅팀은 고객번호를 `C-101`, 배송팀은 `101`, 상담팀은 전화번호로 고객을 구분하고 있었다고 하자. 그대로 합치면 한 사람이 여러 사람처럼 보인다. 통합하려면 공통 식별자와 용어를 정해야 한다.

<Callout type="warning">
  통합은 중복을 무조건 0으로 만드는 일이 아니다. 성능이나 이력 보존을 위해 의도적으로 중복할 수 있지만, 중복 이유와 갱신 규칙이 관리되어야 한다.
</Callout>

## 저장된 데이터

**저장된 데이터(stored data)** 는 컴퓨터가 접근할 수 있는 저장 매체에 지속적으로 보관된 데이터다.

프로그램 변수에 잠깐 들어 있다가 종료와 함께 사라지는 값이 아니라, DBMS가 디스크 등의 저장장치에 기록해 다음 작업에서도 사용할 수 있어야 한다.

```text
메모리의 장바구니 임시 계산값 → 프로그램 종료 시 사라질 수 있음
데이터베이스의 확정 주문       → 재시작 후에도 남아야 함
```

## 운영 데이터

**운영 데이터(operational data)** 는 조직이 실제 업무를 수행하는 데 계속 필요한 데이터다.

주문 상태, 재고 수량, 배송지처럼 현재 업무에 직접 사용되는 데이터가 해당한다. 단순히 한 번 모으고 끝나는 자료가 아니라 조회와 변경이 반복된다.

## 공용 데이터

**공용 데이터(shared data)** 는 여러 사용자와 응용프로그램이 공동으로 사용하는 데이터다.

같은 주문을 고객 앱, 물류 시스템, 상담 화면이 함께 사용한다. 공용이라는 말은 누구나 모든 값을 볼 수 있다는 뜻이 아니다. 각 사용자의 역할에 맞춰 권한을 나누면서 같은 기준 데이터를 공유한다.

| 특징 | 핵심 질문 | 잘못된 해석 |
| --- | --- | --- |
| 통합 | 같은 사실을 일관되게 관리하는가? | 중복이 절대 존재하지 않는다 |
| 저장 | 이후에도 사용할 수 있게 보관되는가? | 백업과 같은 뜻이다 |
| 운영 | 실제 업무에 계속 쓰이는가? | 과거 데이터는 모두 불필요하다 |
| 공용 | 여러 주체가 같은 기준으로 사용하는가? | 모두에게 모든 권한을 준다 |

## 실시간 접근성

사용자가 질의하면 업무가 요구하는 시간 안에 결과를 제공해야 한다. 이를 **실시간 접근성**이라고 설명한다.

여기서 실시간은 모든 질의가 0초 안에 끝난다는 뜻이 아니다. 결제 승인과 월간 통계 보고서는 필요한 응답 시간이 다르다. 중요한 것은 필요한 시점에 최신 상태에 접근할 수 있다는 점이다.

## 계속 변화하는 데이터

운영 데이터는 삽입, 수정, 삭제를 통해 계속 변한다.

```text
주문 생성 → 결제완료 → 배송중 → 배송완료
```

DBMS는 변화 중에도 규칙을 지키고 여러 사용자가 일관된 결과를 보도록 관리해야 한다.

## 동시 공유와 트랜잭션

재고가 1개 남은 상품을 두 사람이 동시에 주문하면 어떻게 될까? 두 요청이 모두 "재고 1개"를 읽고 각각 결제를 완료하면 실제 재고보다 더 많이 판매된다.

DBMS는 동시성 제어와 트랜잭션을 이용해 이런 충돌을 줄인다.

```text
트랜잭션 A: 재고 확인 → 1개 차감 → 주문 저장
트랜잭션 B: A의 처리와 충돌하지 않도록 순서 또는 격리를 조정
```

**트랜잭션(transaction)** 은 논리적으로 하나의 작업으로 처리해야 하는 연산 묶음이다. 자세한 ACID 성질은 뒤에서 다룬다.

## 데이터 독립성

데이터베이스의 중요한 목표 중 하나는 저장 방식이 바뀌어도 사용자와 프로그램의 변경을 최소화하는 것이다.

### 물리적 데이터 독립성

인덱스를 추가하거나 파일 배치와 저장장치를 바꾸어도 테이블을 조회하는 SQL이 그대로 동작하는 성질이다.

```sql
SELECT name FROM members WHERE member_id = 101;
```

DBA가 내부 저장 구조를 바꾸더라도 응용프로그램은 이 SQL을 계속 사용할 수 있다.

### 논리적 데이터 독립성

논리 스키마가 일부 바뀌어도 사용자 관점이나 응용프로그램의 변경을 최소화하는 성질이다. 예를 들어 테이블을 분리한 뒤 기존 화면이 사용할 수 있도록 뷰를 제공할 수 있다.

일반적으로 논리적 구조 변경은 응용프로그램 의미에 영향을 주기 쉬워 물리적 독립성보다 달성하기 어렵다.

## 품질을 지키는 관리 기능

| 기능 | 지키려는 것 | 주문 사례 |
| --- | --- | --- |
| 무결성 | 값과 관계의 정확성 | 없는 회원의 주문 금지 |
| 보안 | 허가된 사용자만 접근 | 상담원은 결제정보 일부만 조회 |
| 동시성 제어 | 동시에 작업해도 일관성 유지 | 마지막 재고 중복 판매 방지 |
| 회복 | 장애 전의 일관된 상태 복원 | 결제 중 서버 장애 시 미완료 작업 취소 |

## 시험형 선지 분석

다음 선지를 판단해 보자.

1. "공용 데이터이므로 모든 사용자가 모든 데이터에 같은 권한으로 접근한다." → 거짓
2. "물리적 저장 구조가 바뀌어도 응용프로그램의 변경을 최소화하는 성질은 물리적 데이터 독립성이다." → 참
3. "통합된 데이터에는 어떤 형태의 중복도 허용되지 않는다." → 거짓
4. "운영 데이터는 조직의 현재 업무 수행을 위해 지속적으로 사용된다." → 참

시험에서는 정의의 핵심 단어를 `모든`, `절대`, `같은 권한`처럼 과도한 표현으로 바꿔 오답을 만든다.

## 정리

<Callout type="default">
  - 데이터베이스는 통합·저장·운영·공용 데이터의 성격을 가진다.
  - 데이터는 계속 변화하며 여러 사용자가 동시에 접근할 수 있다.
  - 물리적 독립성은 저장 방식 변화, 논리적 독립성은 논리 구조 변화의 영향을 줄인다.
  - 무결성·보안·동시성·회복은 데이터의 신뢰성을 지키는 핵심 기능이다.
</Callout>
