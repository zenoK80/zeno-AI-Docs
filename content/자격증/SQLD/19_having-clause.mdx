## 이번 편의 목표

- WHERE와 HAVING의 적용 대상과 순서를 구분한다.
- 집계 결과를 조건으로 그룹을 필터링한다.
- 같은 조건을 WHERE에 둘 때와 HAVING에 둘 때의 의미 차이를 설명한다.
- 그룹이 만들어지고 제거되는 과정을 결과표로 예측한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 행 조건 | 개별 입력 행을 검사하는 조건 |
| 그룹 조건 | 묶인 행의 COUNT·SUM·AVG 결과를 검사하는 조건 |
| HAVING | GROUP BY로 만든 그룹을 걸러내는 절 |
| 집계 결과 | 그룹의 개수·합계·평균·최댓값 같은 요약값 |

## 선수지식과 핵심 질문

18편에서 WHERE가 먼저 행을 거르고 GROUP BY가 남은 행을 묶는다고 배웠다.

> 회원별 합계가 100,000원 이상인 회원만 남기려면 WHERE와 HAVING 중 어디에 조건을 둘까?

## 입력 주문 데이터

| order_id | member_id | status | total_amount |
| ---: | --- | --- | ---: |
| 1001 | M01 | PAID | 106,000 |
| 1002 | M01 | SHIPPED | 30,000 |
| 1003 | M02 | PAID | 250,000 |
| 1004 | M03 | CANCELED | 70,000 |
| 1005 | M03 | PAID | 50,000 |

## HAVING은 그룹 결과를 검사한다

```sql
SELECT member_id,
       SUM(total_amount) AS total
FROM orders
GROUP BY member_id
HAVING SUM(total_amount) >= 130000;
```

먼저 세 그룹의 합계를 계산한다.

| 그룹 | 합계 | HAVING 통과? |
| --- | ---: | --- |
| M01 | 136,000 | 예 |
| M02 | 250,000 | 예 |
| M03 | 120,000 | 아니오 |

| member_id | total |
| --- | ---: |
| M01 | 136,000 |
| M02 | 250,000 |

`SUM(total_amount)`은 그룹이 만들어진 뒤에야 알 수 있으므로 HAVING에서 검사한다.

## WHERE와 HAVING 처리 흐름

```text
FROM      : 주문 5행 준비
WHERE     : 개별 주문 행 제거
GROUP BY  : 남은 행을 회원별로 묶음
HAVING    : 회원별 그룹 제거
SELECT    : 결과 열 계산
ORDER BY  : 결과 정렬
```

취소 주문을 제외하고, 정상 주문 합계가 100,000원 이상인 회원만 찾자.

```sql
SELECT member_id,
       SUM(total_amount) AS valid_total
FROM orders
WHERE status <> 'CANCELED'
GROUP BY member_id
HAVING SUM(total_amount) >= 100000;
```

### 1단계: WHERE 뒤

| 남은 주문 | 회원 | 금액 |
| ---: | --- | ---: |
| 1001 | M01 | 106,000 |
| 1002 | M01 | 30,000 |
| 1003 | M02 | 250,000 |
| 1005 | M03 | 50,000 |

### 2단계: GROUP BY와 HAVING

| 회원 그룹 | 정상 주문 합계 | 100,000 이상? |
| --- | ---: | --- |
| M01 | 136,000 | 예 |
| M02 | 250,000 | 예 |
| M03 | 50,000 | 아니오 |

최종 결과는 M01과 M02 두 행이다.

## 같은 열 조건도 위치에 따라 의미가 다르다

그룹 기준 열 조건은 WHERE와 HAVING 양쪽에 쓸 수 있는 경우가 있지만 적용 시점이 다르다.

```sql
-- 그룹 전에 M01 행만 남김
WHERE member_id = 'M01'
GROUP BY member_id
```

```sql
-- 모든 회원 그룹을 만든 뒤 M01 그룹만 남김
GROUP BY member_id
HAVING member_id = 'M01'
```

이 단순 예의 최종 결과는 같을 수 있지만, 그룹 전에 줄일 수 있는 행 조건은 WHERE에 두는 편이 의미가 분명하고 처리 대상도 줄일 수 있다.

## 집계함수 조건은 HAVING

다음 SQL은 일반적으로 잘못됐다.

```sql
SELECT member_id, COUNT(*)
FROM orders
WHERE COUNT(*) >= 2
GROUP BY member_id;
```

WHERE 시점에는 회원별 COUNT가 아직 만들어지지 않았다. 올바른 형태는 다음과 같다.

```sql
SELECT member_id, COUNT(*) AS order_count
FROM orders
GROUP BY member_id
HAVING COUNT(*) >= 2;
```

| member_id | order_count |
| --- | ---: |
| M01 | 2 |
| M03 | 2 |

## HAVING만 있는 집계

GROUP BY가 없어도 집계함수와 HAVING을 사용할 수 있다. 전체 입력이 한 그룹이다.

```sql
SELECT SUM(total_amount) AS grand_total
FROM orders
HAVING SUM(total_amount) > 500000;
```

전체 합계 506,000이 조건을 만족하므로 한 행이 나온다.

| grand_total |
| ---: |
| 506,000 |

조건이 거짓이면 이 한 그룹이 제거되어 0행이다.

## 별칭 사용은 DBMS 차이를 확인한다

일부 DBMS는 HAVING에서 SELECT 별칭을 허용하고 일부는 제한한다.

```sql
SELECT member_id, SUM(total_amount) AS total
FROM orders
GROUP BY member_id
HAVING SUM(total_amount) >= 100000;
```

시험과 이식성을 위해 집계 표현식을 HAVING에 직접 쓰는 형태를 우선 익힌다.

## 흔한 실수와 진단법

| 실수 | 문제 | 확인 |
| --- | --- | --- |
| WHERE에 SUM·COUNT 조건 | 집계 전이라 오류 | 그룹 결과인가? |
| 모든 조건을 HAVING에 둠 | 불필요한 행까지 그룹화 | 개별 행 조건은 WHERE |
| 취소 행 제거를 HAVING에서 처리 | 합계에 취소 금액이 먼저 섞임 | WHERE 단계 확인 |
| HAVING 뒤 행 수를 원본 행 수로 예측 | 그룹 단위 제거를 놓침 | 그룹표 먼저 작성 |

## 시험 연결

1. WHERE는 그룹 전에 행, HAVING은 그룹 뒤에 그룹을 필터링한다.
2. SUM·COUNT 같은 집계 결과 조건은 HAVING에 둔다.
3. GROUP BY가 없어도 전체를 한 그룹으로 보는 HAVING 쿼리가 가능하다.
4. WHERE와 HAVING이 함께 있으면 WHERE 결과만 그룹에 참여한다.

## 짧은 확인

취소 주문을 포함한 합계가 120,000원이고 취소를 제외하면 50,000원인 M03은 정상 주문 합계 100,000원 조건을 통과할까?

<Collapse title="확인하기">

통과하지 않는다. WHERE가 취소 주문을 먼저 제거하므로 M03 그룹 합계는 50,000원이다. HAVING은 이 50,000원을 검사한다.

</Collapse>

## 정리

<Callout type="default">
  - WHERE는 입력 행, HAVING은 집계 그룹을 거른다.
  - 집계 결과는 그룹 생성 뒤에 알 수 있으므로 HAVING에서 검사한다.
  - WHERE 결과만 GROUP BY와 HAVING 계산에 참여한다.
  - 그룹 조건은 그룹별 중간표를 만든 뒤 판단한다.
</Callout>
