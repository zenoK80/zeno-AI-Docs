  **이번 문서의 목표:** LEFT JOIN, RIGHT JOIN, FULL OUTER JOIN의 차이를 이해하고, Oracle 전용 조인과 ANSI 표준 조인을 비교합니다.
</Callout>

## 예시 테이블 구성

이번 문서에서는 아래 두 테이블을 사용합니다.

**사원(EMP) 테이블**

| 사원번호 | 이름   | 부서번호 | 직급 | 급여    |
| -------- | ------ | -------- | ---- | ------- |
| 1001     | 김민준 | 10       | 과장 | 4500000 |
| 1002     | 이서연 | 20       | 대리 | 3200000 |
| 1003     | 박지훈 | 10       | 부장 | 6000000 |
| 1004     | 최수아 | 30       | 사원 | 2500000 |
| 1005     | 정도윤 | 20       | 과장 | 4800000 |

**부서(DEPT) 테이블**

| 부서번호 | 부서명   | 위치 |
| -------- | -------- | ---- |
| 10       | 개발팀   | 서울 |
| 20       | 영업팀   | 부산 |
| 30       | 기획팀   | 서울 |
| 40       | 인사팀   | 대구 |

사원 테이블의 부서번호에 `40`은 없고, 부서 테이블의 부서번호 `40`(인사팀)에는 소속 사원이 없습니다. 이 점이 조인 종류에 따라 결과를 다르게 만듭니다.

## INNER JOIN (내부 조인)

두 테이블에서 **조인 조건을 만족하는 행만** 반환합니다. 부서번호 40인 인사팀은 소속 사원이 없으므로 결과에 나타나지 않습니다.

```sql
-- ANSI 표준 문법
SELECT E.사원번호, E.이름, D.부서명, D.위치
FROM   EMP E
       INNER JOIN DEPT D ON E.부서번호 = D.부서번호;
```

| 사원번호 | 이름   | 부서명 | 위치 |
| -------- | ------ | ------ | ---- |
| 1001     | 김민준 | 개발팀 | 서울 |
| 1002     | 이서연 | 영업팀 | 부산 |
| 1003     | 박지훈 | 개발팀 | 서울 |
| 1004     | 최수아 | 기획팀 | 서울 |
| 1005     | 정도윤 | 영업팀 | 부산 |

<Callout type="warning">
  부서번호 40(인사팀)은 소속 사원이 없어 INNER JOIN 결과에서 제외됩니다.
</Callout>

## LEFT OUTER JOIN (왼쪽 외부 조인)

왼쪽 테이블의 **모든 행**을 결과에 포함합니다. 오른쪽 테이블에 일치하는 행이 없으면 NULL로 채웁니다.

```sql
-- DEPT를 왼쪽에 놓으면 인사팀(40)도 결과에 포함됨
SELECT D.부서번호, D.부서명, E.이름
FROM   DEPT D
       LEFT OUTER JOIN EMP E ON D.부서번호 = E.부서번호;
```

| 부서번호 | 부서명 | 이름   |
| -------- | ------ | ------ |
| 10       | 개발팀 | 김민준 |
| 10       | 개발팀 | 박지훈 |
| 20       | 영업팀 | 이서연 |
| 20       | 영업팀 | 정도윤 |
| 30       | 기획팀 | 최수아 |
| 40       | 인사팀 | NULL   |

인사팀(40)은 소속 사원이 없지만 왼쪽 테이블(DEPT)에 있으므로 결과에 남고, 이름은 NULL이 됩니다.

## RIGHT OUTER JOIN (오른쪽 외부 조인)

오른쪽 테이블의 **모든 행**을 결과에 포함합니다. LEFT JOIN의 테이블 순서를 바꾼 것과 동일한 결과를 냅니다.

```sql
SELECT D.부서번호, D.부서명, E.이름
FROM   EMP E
       RIGHT OUTER JOIN DEPT D ON E.부서번호 = D.부서번호;
```

결과는 LEFT OUTER JOIN 예시와 동일합니다. LEFT와 RIGHT는 테이블 순서만 다를 뿐입니다.

## FULL OUTER JOIN (전체 외부 조인)

두 테이블의 **모든 행**을 반환합니다. 양쪽 중 하나에만 있는 행은 나머지 쪽을 NULL로 채웁니다.

```sql
SELECT D.부서번호, D.부서명, E.이름
FROM   DEPT D
       FULL OUTER JOIN EMP E ON D.부서번호 = E.부서번호;
```

| 부서번호 | 부서명 | 이름   |
| -------- | ------ | ------ |
| 10       | 개발팀 | 김민준 |
| 10       | 개발팀 | 박지훈 |
| 20       | 영업팀 | 이서연 |
| 20       | 영업팀 | 정도윤 |
| 30       | 기획팀 | 최수아 |
| 40       | 인사팀 | NULL   |

<Callout type="info">
  FULL OUTER JOIN은 Oracle에서 지원하지만, MySQL은 기본적으로 지원하지 않아 `UNION`으로 구현해야 합니다.
</Callout>

## CROSS JOIN (교차 조인, 카테시안 곱)

조인 조건 없이 두 테이블의 **모든 행 조합**을 반환합니다. 사원 5명 × 부서 4개 = **20행**이 결과로 나옵니다.

```sql
SELECT E.이름, D.부서명
FROM   EMP E
       CROSS JOIN DEPT D;
```

실무에서는 거의 쓰지 않지만, SQLD 시험에서 행 수 계산 문제로 자주 출제됩니다.

## USING 절 vs ON 절

두 테이블에 같은 이름의 컬럼이 있을 때 `USING`으로 간단하게 쓸 수 있습니다.

```sql
-- ON 절
SELECT E.이름, D.부서명
FROM   EMP E JOIN DEPT D ON E.부서번호 = D.부서번호;

-- USING 절 (컬럼명이 같을 때)
SELECT E.이름, D.부서명
FROM   EMP E JOIN DEPT D USING (부서번호);
```

<Callout type="warning">
  `USING` 절을 쓰면 해당 컬럼에 테이블 별칭을 붙일 수 없습니다. `E.부서번호`가 아닌 그냥 `부서번호`로 참조해야 합니다.
</Callout>

## Oracle 전통 조인 vs ANSI 표준 비교

Oracle에서는 과거에 `(+)` 기호를 사용해 외부 조인을 표현했습니다.

```sql
-- Oracle 전통 문법 (LEFT OUTER JOIN 효과)
SELECT D.부서명, E.이름
FROM   DEPT D, EMP E
WHERE  D.부서번호 = E.부서번호(+);

-- ANSI 표준 문법 (동일한 결과)
SELECT D.부서명, E.이름
FROM   DEPT D
       LEFT OUTER JOIN EMP E ON D.부서번호 = E.부서번호;
```

`(+)` 기호는 **데이터가 없는(NULL이 될) 쪽**에 붙입니다. ANSI 표준이 가독성이 높아 현재는 ANSI 문법 사용을 권장합니다.

## 핵심 정리

- **INNER JOIN**: 양쪽 모두 조건을 만족하는 행만 반환 (기본 조인)
- **LEFT OUTER JOIN**: 왼쪽 테이블 전체 + 오른쪽은 일치하면 값, 없으면 NULL
- **RIGHT OUTER JOIN**: 오른쪽 테이블 전체 + 왼쪽은 일치하면 값, 없으면 NULL
- **FULL OUTER JOIN**: 양쪽 테이블 전체, 일치하지 않는 쪽은 NULL
- **CROSS JOIN**: 조인 조건 없음, 행 수 = 왼쪽 행 수 × 오른쪽 행 수
- **USING**: 컬럼명이 같을 때 간단하게 사용, 해당 컬럼에 별칭 금지
- **Oracle **(+ ): LEFT JOIN은 `오른쪽(+)`, RIGHT JOIN은 `왼쪽(+)`
