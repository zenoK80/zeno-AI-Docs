## 이번 편의 목표

- 리터럴 문자와 메타문자를 구분해 정규식 패턴을 왼쪽부터 해석한다.
- 앵커, 문자 클래스, 수량자의 의미를 적용한다.
- Oracle의 `REGEXP_LIKE`, `REGEXP_SUBSTR`, `REGEXP_REPLACE`, `REGEXP_INSTR`를 구분한다.
- 데이터 검증에서 정규식만으로 해결하면 안 되는 범위를 설명한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 정규 표현식(Regular Expression) | 문자열의 모양을 기호로 표현한 패턴 언어 |
| 리터럴 | 패턴에서 문자 자체를 뜻하는 일반 문자 |
| 메타문자 | 위치·반복·선택처럼 특별한 규칙을 뜻하는 문자 |
| 앵커(Anchor) | 문자열의 시작 `^`과 끝 `$`처럼 위치를 나타내는 기호 |
| 문자 클래스 | `[0-9]`처럼 한 자리에서 허용할 문자 집합 |
| 수량자(Quantifier) | 앞 요소가 몇 번 반복되는지 나타내는 `*`, `+`, `{n}` 등 |
| 이스케이프 | 특별한 기호를 문자 자체로 해석하게 만드는 처리 |

## 선수지식과 핵심 질문

선수지식은 [16. 함수](./16_sql-functions)와 [17. WHERE 절](./17_where-clause)다.

핵심 질문은 **문자열 전체 또는 일부가 어떤 순서와 반복 규칙을 만족하는가**이다.

## LIKE로 부족한 패턴

`LIKE '010-%'`는 010-으로 시작하는지 볼 수 있지만 뒤가 정확히 숫자 4자리-숫자 4자리인지 확인하기 어렵다.

정규식으로 전화번호 모양을 표현하면 다음과 같다.

```text
^010-[0-9]{4}-[0-9]{4}$
```

왼쪽부터 읽는다.

| 조각 | 의미 |
| --- | --- |
| `^` | 문자열 시작 |
| `010-` | 문자 010- 그대로 |
| `[0-9]{4}` | 숫자 정확히 네 자리 |
| `-` | 하이픈 한 개 |
| `[0-9]{4}` | 숫자 정확히 네 자리 |
| `$` | 문자열 끝 |

| 입력 | 일치 여부 | 이유 |
| --- | --- | --- |
| `010-1234-5678` | 일치 | 전체 모양 충족 |
| `010-123-5678` | 불일치 | 가운데가 세 자리 |
| `A010-1234-5678` | 불일치 | 시작 앵커 위반 |
| `010-1234-5678 메모` | 불일치 | 끝 앵커 위반 |

## 핵심 메타문자

### 위치와 한 문자

| 패턴 | 의미 | 예시 |
| --- | --- | --- |
| `^A` | A로 시작 | `Apple` 일치 |
| `A$` | A로 끝 | `KOREA` 일치 |
| `.` | 줄바꿈 등을 제외한 임의의 한 문자 | `a.c`는 `abc`와 일치 가능 |

점 자체를 찾으려면 정규식 수준에서 `\.`처럼 이스케이프한다. SQL 문자열에서 백슬래시 처리 방식은 DBMS 설정에 따라 추가 이스케이프가 필요할 수 있다.

### 문자 클래스

| 패턴 | 의미 |
| --- | --- |
| `[ABC]` | A, B, C 중 한 문자 |
| `[A-Z]` | 영문 대문자 한 문자 |
| `[0-9]` | 숫자 한 문자 |
| `[^0-9]` | 숫자가 아닌 한 문자 |

대괄호 안의 `^`는 맨 앞에 있을 때 “제외”를 뜻한다. 대괄호 밖의 `^`는 문자열 시작이다.

### 반복 수량자

| 패턴 | 반복 수 |
| --- | --- |
| `A*` | A가 0번 이상 |
| `A+` | A가 1번 이상 |
| `A?` | A가 0번 또는 1번 |
| `A{3}` | A가 정확히 3번 |
| `A{2,4}` | A가 2~4번 |
| `A{2,}` | A가 2번 이상 |

`*`는 0번도 허용한다. 따라서 `[0-9]*`는 빈 문자열도 만족할 수 있지만 `[0-9]+`는 숫자가 최소 한 자리 있어야 한다.

### 그룹과 선택

```text
^(cat|dog)s?$
```

`()`는 패턴을 묶고 `|`는 둘 중 하나를 뜻한다. `s?`는 s가 없거나 한 번 있으므로 cat, cats, dog, dogs와 일치한다.

## REGEXP_LIKE: 일치 여부 검사

```sql
SELECT member_id, phone
FROM members
WHERE REGEXP_LIKE(phone, '^010-[0-9]{4}-[0-9]{4}$');
```

| member_id | phone | 결과 |
| --- | --- | --- |
| M01 | 010-1234-5678 | 선택 |
| M02 | 010-12-3456 | 제외 |
| M03 | NULL | 제외 |

NULL 문자열은 패턴과 일치한다고 확정되지 않는다. NULL도 별도 대상으로 보고 싶다면 `phone IS NULL OR ...`처럼 조건을 명시한다.

Oracle에서는 일치 옵션으로 `'i'`를 주면 대소문자를 구분하지 않는 검색을 할 수 있다.

```sql
REGEXP_LIKE(name, '^kim$', 'i')
```

## REGEXP_SUBSTR: 일치 부분 추출

```sql
SELECT REGEXP_SUBSTR(
         '주문번호 ORD-2026-0042 완료',
         'ORD-[0-9]{4}-[0-9]{4}'
       ) AS order_code
FROM dual;
```

| order_code |
| --- |
| ORD-2026-0042 |

문자열 전체가 아니라 패턴과 일치하는 부분을 반환한다. 일치하는 부분이 없으면 NULL이 될 수 있다.

## REGEXP_REPLACE: 패턴 부분 바꾸기

전화번호의 가운데 네 자리를 가린다.

```sql
SELECT REGEXP_REPLACE(
         '010-1234-5678',
         '^(010)-([0-9]{4})-([0-9]{4})$',
         '\1-****-\3'
       ) AS masked_phone
FROM dual;
```

| masked_phone |
| --- |
| 010-****-5678 |

괄호로 잡은 그룹을 역참조해 첫 번째와 세 번째 부분을 재사용한다. 역참조 표기와 SQL 문자열 이스케이프는 DBMS별 문서를 확인한다.

## REGEXP_INSTR: 위치 찾기

```sql
SELECT REGEXP_INSTR('abc123xyz', '[0-9]+') AS start_pos
FROM dual;
```

숫자 덩어리는 네 번째 문자에서 시작하므로 결과는 4다. 시작 위치를 반환하며 일치하지 않으면 일반적으로 0을 반환하는 등 제품 함수 규칙을 확인한다.

## REGEXP_COUNT: 일치 횟수

```sql
SELECT REGEXP_COUNT('A12 B345 C6', '[0-9]+') AS number_groups
FROM dual;
```

숫자 한 자리 수가 아니라 연속된 숫자 덩어리는 `12`, `345`, `6` 세 개이므로 결과는 3이다.

## 정규식 설계 순서

<Steps>

### 전체 일치인지 일부 검색인지 정한다

전화번호 검증처럼 전체 모양이면 `^...$`, 문장 안 코드 추출이면 앵커를 생략한다.

### 예시와 반례를 먼저 적는다

통과해야 할 값과 반드시 막아야 할 값을 각각 세 개 이상 만든다.

### 패턴을 작은 조각으로 나눈다

시작, 접두사, 숫자 자리 수, 구분자, 끝을 따로 확인한다.

### NULL과 빈 문자열 정책을 정한다

형식이 맞는지와 값이 필수인지 여부는 다른 규칙일 수 있다.

</Steps>

## 정규식만으로 충분하지 않은 검증

`^[0-9]{4}-[0-9]{2}-[0-9]{2}$`는 `2026-99-99`도 모양상 통과시킨다. 실제 달력 날짜인지 확인하려면 날짜 변환과 유효성 검사가 필요하다.

이메일, URL, 국제 전화번호처럼 표준과 예외가 복잡한 데이터도 짧은 정규식 하나로 완벽히 검증하려 하지 않는다. 정규식은 **문자 모양 검사**에 강하고, 업무 의미와 참조 무결성은 타입·제약조건·애플리케이션 검증이 함께 맡는다.

<Callout type="warning">
  길고 복잡한 정규식은 읽기 어렵고 성능 비용이 커질 수 있다. 단순 접두사·정확한 값은 `LIKE`, `=`, 전용 타입과 제약조건이 더 명확할 수 있다.
</Callout>

## DBMS별 차이

Oracle은 `REGEXP_LIKE` 계열 함수를 제공하고, PostgreSQL은 `~`, `~*`, `regexp_match`, `regexp_replace` 등 자체 연산자·함수를 제공한다. 정규식 문법 자체도 POSIX 계열, 플래그, 백슬래시 처리에 차이가 있다. 시험 문제에서 DBMS가 지정되면 해당 문법을 기준으로 읽는다.

## 시험에서는 어떻게 묻나

- `*`와 `+`, `^`의 위치별 의미를 비교한다.
- 전체 문자열 검증에 시작·끝 앵커가 빠진 패턴을 찾게 한다.
- LIKE보다 정규식이 적합한 복잡한 패턴을 고르게 한다.
- REGEXP_SUBSTR·REPLACE·INSTR의 반환 목적을 바꿔 낸다.

## 짧은 확인

패턴 `^[A-Z][0-9]{2}$`와 일치하는 값은 `A12`, `AA12`, `a12`, `A123` 중 무엇인가?

<Collapse title="확인하기">

`A12`만 일치한다. 영문 대문자 한 자리 다음 숫자 정확히 두 자리이며 문자열 전체가 그 모양이어야 한다.

</Collapse>

## 흔한 실수와 진단법

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 앞뒤 다른 문자도 통과 | `^`, `$` 누락 | 전체 검증이면 양쪽 앵커 추가 |
| 빈 값도 통과 | `*` 사용 | 최소 한 번이면 `+` 사용 |
| 점이 임의 문자와 일치 | `.` 이스케이프 누락 | 문자 점은 `\.` 검토 |
| 패턴은 맞는데 업무값이 잘못됨 | 모양만 검사 | 날짜·참조·범위 검증 추가 |

## 정리

<Callout type="default">
  - 정규식은 문자열의 위치, 허용 문자, 반복 횟수를 패턴으로 표현한다.
  - 전체 검증은 보통 `^`와 `$`로 범위를 고정한다.
  - LIKE·SUBSTR·REPLACE·INSTR는 검사·추출·치환·위치 반환 역할이 다르다.
