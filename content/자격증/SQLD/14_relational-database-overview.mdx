## 이번 편의 목표

- 관계형 모델의 릴레이션, 튜플, 속성과 도메인을 표에서 찾는다.
- 차수와 카디널리티를 관계의 1:N과 혼동하지 않는다.
- 후보키·기본키·외래키가 릴레이션에서 하는 역할을 설명한다.
- 선택·투영·조인이 SQL 결과에 어떻게 대응하는지 이해한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 릴레이션 | 같은 종류의 데이터를 행과 열로 나타낸 관계형 모델의 구조 |
| 튜플 | 릴레이션 안의 한 행 |
| 속성 | 릴레이션의 한 열 |
| 도메인 | 속성이 가질 수 있는 값의 범위 |
| 차수 | 릴레이션의 속성 개수, 즉 열 수 |
| 카디널리티 | 여기서는 릴레이션의 튜플 개수, 즉 행 수 |
| 선택 | 조건에 맞는 행을 고르는 관계 연산 |
| 투영 | 필요한 열을 고르는 관계 연산 |

## 선수지식과 핵심 질문

01편부터 테이블·행·열이라는 구현 용어를 사용했다. 이번 편은 같은 구조를 관계형 모델의 정식 용어와 연결한다.

> 회원 표에서 릴레이션·튜플·속성은 각각 어디이며, 행과 열을 고르는 SQL은 어떻게 읽을까?

## 한 표에서 정식 용어 찾기

### MEMBERS 릴레이션

| member_id | member_name | city | grade |
| --- | --- | --- | --- |
| M01 | 민지 | 서울 | GOLD |
| M02 | 준호 | 부산 | SILVER |
| M03 | 소라 | 서울 | GOLD |

| 정식 용어 | 위 표에서의 의미 |
| --- | --- |
| 릴레이션 | MEMBERS 전체 구조 |
| 튜플 | `M01, 민지, 서울, GOLD` 한 행 |
| 속성 | `member_id`, `member_name`, `city`, `grade` 열 |
| 도메인 | city에 허용할 도시명, grade에 허용할 등급값 |
| 차수 | 열이 4개이므로 4 |
| 카디널리티 | 행이 3개이므로 3 |

<Callout type="warning">
  릴레이션의 카디널리티는 현재 행 수를 뜻한다. 관계 모델링에서 말한 1:N 카디널리티는 엔터티 사이 최대 연결 수다. 같은 단어가 문맥에 따라 다르게 쓰인다.
</Callout>

## 릴레이션의 기본 성질

이론적인 릴레이션은 다음 성질을 가진다.

- 같은 튜플이 중복되지 않는다.
- 튜플과 속성의 순서는 본질적인 의미가 없다.
- 한 속성의 값은 같은 도메인에서 나온다.
- 각 칸은 현재 모델 기준에서 하나의 값으로 다룬다.

실제 SQL 테이블은 기본키가 없으면 중복 행을 저장할 수도 있고 출력 순서도 `ORDER BY` 없이는 보장되지 않는다. **관계형 이론과 SQL 제품의 구현 차이**를 구분한다.

## 키로 튜플과 릴레이션을 연결하기

### ORDERS 릴레이션

| order_id | member_id | order_status | total_amount |
| ---: | --- | --- | ---: |
| 1001 | M01 | PAID | 106,000 |
| 1002 | M01 | SHIPPED | 30,000 |
| 1003 | M02 | PAID | 250,000 |

- `order_id`는 각 주문 튜플을 구분하는 기본키다.
- `member_id`는 MEMBERS의 기본키를 가리키는 외래키다.
- 회원 M01 한 튜플과 주문 1001·1002 두 튜플이 연결된다.

```text
MEMBERS.M01 민지 1 ─┬─ N ORDERS.1001
                     └─ N ORDERS.1002
```

## 선택: 조건에 맞는 행 고르기

관계 대수의 **선택(selection)** 은 행을 고르는 연산이다. SQL에서는 주로 WHERE가 이 역할을 한다.

```sql
SELECT member_id, member_name, city, grade
FROM members
WHERE city = '서울';
```

| member_id | member_name | city | grade |
| --- | --- | --- | --- |
| M01 | 민지 | 서울 | GOLD |
| M03 | 소라 | 서울 | GOLD |

입력 3행 중 city가 서울인 2행만 남았다. 열은 그대로 네 개다.

## 투영: 필요한 열 고르기

관계 대수의 **투영(projection)** 은 열을 고르는 연산이다. SQL에서는 SELECT 목록에 필요한 열을 적는다.

```sql
SELECT member_name, grade
FROM members;
```

| member_name | grade |
| --- | --- |
| 민지 | GOLD |
| 준호 | SILVER |
| 소라 | GOLD |

행은 3개로 유지되고 열이 두 개로 줄었다. SQL에서 중복을 제거하려면 이론적 투영과 달리 `DISTINCT`를 명시해야 할 수 있다.

```sql
SELECT DISTINCT grade
FROM members;
```

| grade |
| --- |
| GOLD |
| SILVER |

## 조인: 관련 튜플 연결하기

회원 이름과 주문을 함께 보려면 같은 의미의 키를 연결한다.

```sql
SELECT o.order_id,
       m.member_name,
       o.total_amount
FROM orders AS o
JOIN members AS m
  ON m.member_id = o.member_id
ORDER BY o.order_id;
```

| order_id | member_name | total_amount |
| ---: | --- | ---: |
| 1001 | 민지 | 106,000 |
| 1002 | 민지 | 30,000 |
| 1003 | 준호 | 250,000 |

결과 한 행은 주문 한 건이다. M01 회원 튜플은 연결된 주문이 두 건이라 결과에서 두 번 보인다.

## 무결성 제약 다시 연결하기

| 제약 | 지키는 것 | 예 |
| --- | --- | --- |
| 개체 무결성 | 기본키가 NULL이거나 중복되지 않음 | order_id 필수·유일 |
| 참조 무결성 | 외래키가 존재하는 부모를 가리킴 | orders.member_id가 실제 회원 참조 |
| 도메인 무결성 | 열 값이 허용 범위를 만족 | total_amount 0 이상 |

키와 제약은 릴레이션에 아무 값이나 들어오는 것을 막아 관계 연산 결과를 믿을 수 있게 한다.

## SQL 처리 흐름 미리 보기

작성 순서와 논리적 처리 순서는 다르다.

```text
작성: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
처리 이해: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
```

DBMS 내부 최적화는 이 순서를 그대로 기계적으로 실행한다는 뜻이 아니다. SQL 결과를 해석할 때의 논리적 순서다. 15~20편에서 각 절을 자세히 배운다.

## 흔한 실수와 진단법

| 실수 | 바로잡기 |
| --- | --- |
| 차수를 행 수라고 함 | 차수는 열 수 |
| 릴레이션 카디널리티를 1:N이라고 함 | 이 문맥에서는 현재 행 수 |
| SELECT가 행을 고른다고만 외움 | SELECT 목록은 열, WHERE는 조건 행 |
| SQL 결과 순서가 항상 저장 순서라고 생각 | ORDER BY 없이는 순서 보장 없음 |

## 시험 연결

1. 릴레이션의 튜플은 행, 속성은 열에 대응한다.
2. 차수는 속성 수, 릴레이션 카디널리티는 튜플 수다.
3. 선택은 행, 투영은 열, 조인은 관련 튜플을 결합한다.
4. SQL 테이블은 이론적 릴레이션과 달리 제약이 없으면 중복을 허용할 수 있다.

## 짧은 확인

MEMBERS에서 GOLD 등급 회원의 이름만 조회했다. 선택과 투영은 각각 어디에 적용됐는가?

<Collapse title="확인하기">

`WHERE grade = 'GOLD'`가 GOLD인 행을 선택하고, `SELECT member_name`이 이름 열만 투영한다. 결과는 민지와 소라 두 행, 한 열이다.

</Collapse>

## 정리

<Callout type="default">
  - 릴레이션은 표 구조, 튜플은 행, 속성은 열, 도메인은 값의 범위다.
  - 차수는 열 수, 릴레이션 카디널리티는 행 수다.
  - 선택은 행, 투영은 열, 조인은 관련 행을 연결한다.
  - 기본키·외래키·도메인 제약이 관계형 데이터의 신뢰성을 지킨다.
