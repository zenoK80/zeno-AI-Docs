## 이번 편의 목표

- PIVOT이 행의 분류 값을 열 머리글로 바꾸는 과정을 설명한다.
- Oracle PIVOT의 집계 열, 피벗 열, 암묵적 그룹 열을 구분한다.
- 조건부 집계로 같은 결과를 표현한다.
- 누락 조합의 NULL과 입력 중복을 올바르게 처리한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 피벗(Pivot) | 세로로 나열된 분류 값을 가로 열로 펼치는 변환 |
| 교차표(Cross Tabulation) | 행 분류와 열 분류가 만나는 칸에 집계값을 놓은 표 |
| 피벗 열 | 값이 새 열 머리글이 되는 분류 열 |
| 집계 열 | 각 교차 칸에서 합계·건수 등을 계산할 값 |
| 암묵적 그룹 | PIVOT 입력에서 집계 열과 피벗 열을 제외한 나머지 열로 자동 형성되는 그룹 |
| 조건부 집계 | CASE와 SUM 등을 조합해 조건별 열을 직접 만드는 방식 |

## 선수지식과 핵심 질문

선수지식은 [18. GROUP BY 절](./18_group-by)과 [16. 함수](./16_sql-functions)다.

핵심 질문은 **어떤 열의 값이 새 머리글이 되고, 각 칸에는 어떤 집계값이 들어가는가**이다.

## 입력은 길고 세로인 표

`monthly_sales`

| city | quarter | amount |
| --- | --- | ---: |
| 서울 | Q1 | 100 |
| 서울 | Q1 | 50 |
| 서울 | Q2 | 80 |
| 부산 | Q1 | 200 |
| 부산 | Q3 | 120 |

원하는 보고서는 지역 한 행에 분기별 합계를 열로 펼친 표다.

| city | Q1 | Q2 | Q3 |
| --- | ---: | ---: | ---: |
| 서울 | 150 | 80 | NULL |
| 부산 | 200 | NULL | 120 |

서울 Q1 입력은 두 행이므로 단순히 돌려 놓는 것이 아니라 `SUM`으로 150을 집계한다.

```mermaid
flowchart LR
  A["세로 입력: city·quarter·amount"] --> B["city별로 그룹화"]
  B --> C["quarter 값을 Q1·Q2·Q3 열로 펼침"]
  C --> D["같은 칸의 amount를 SUM"]
  D --> E["지역별 가로 교차표"]
```

PIVOT은 단순한 행·열 회전이 아니라, 새 교차 칸마다 여러 입력 행을 집계하는 과정이다.

## Oracle PIVOT 문법

```sql
SELECT city, q1_amount, q2_amount, q3_amount
FROM monthly_sales
PIVOT (
  SUM(amount)
  FOR quarter IN (
    'Q1' AS q1_amount,
    'Q2' AS q2_amount,
    'Q3' AS q3_amount
  )
)
ORDER BY city;
```

세 부분으로 읽는다.

1. `SUM(amount)`: 각 칸에 넣을 값과 집계 방법이다.
2. `FOR quarter`: 값이 새 열 머리글이 될 피벗 열이다.
3. `IN ('Q1', 'Q2', 'Q3')`: 만들 열 값과 이름을 지정한다.

## 암묵적 GROUP BY가 생긴다

PIVOT 입력 열 중 다음 두 종류가 아닌 열은 자동으로 결과 행의 그룹 기준이 된다.

- 집계에서 참조한 `amount`
- 피벗에 사용한 `quarter`

남은 `city`가 결과의 행 기준이다.

<Callout type="warning">
  입력에 `sale_id`처럼 행마다 다른 불필요한 열이 남아 있으면 그 열까지 암묵적 그룹이 되어 지역별 한 행으로 모이지 않을 수 있다. PIVOT 전에 필요한 열만 선택한 인라인 뷰를 만드는 습관이 안전하다.
</Callout>

```sql
SELECT *
FROM (
  SELECT city, quarter, amount
  FROM monthly_sales
) src
PIVOT (
  SUM(amount)
  FOR quarter IN ('Q1' AS q1, 'Q2' AS q2, 'Q3' AS q3)
);
```

## 없는 조합은 NULL

서울 Q3 입력 행이 없으므로 `SUM`할 대상 자체가 없어 결과가 NULL이다. 실제 합계가 0인 것과 데이터가 없는 것은 다르다.

표시 목적으로 0이 필요하면 바깥 SELECT에서 변환한다.

```sql
SELECT city,
       COALESCE(q1, 0) AS q1,
       COALESCE(q2, 0) AS q2,
       COALESCE(q3, 0) AS q3
FROM (... PIVOT 결과 ...);
```

0으로 바꾸기 전에는 “판매 없음”과 “판매 합계 0”을 업무상 구분해야 하는지 확인한다.

## 여러 집계 사용하기

```sql
SELECT *
FROM monthly_sales
PIVOT (
  SUM(amount) AS amount_sum,
  COUNT(*) AS sale_count
  FOR quarter IN ('Q1' AS q1, 'Q2' AS q2)
);
```

각 피벗 값과 집계 별칭이 조합되어 Q1_AMOUNT_SUM, Q1_SALE_COUNT 같은 열이 만들어질 수 있다. 정확한 열 이름 규칙은 DBMS와 별칭 작성에 따라 확인한다.

## 조건부 집계로 같은 결과 만들기

PIVOT 문법을 지원하지 않거나 열 이름을 세밀하게 통제하려면 CASE를 사용한다.

```sql
SELECT city,
       SUM(CASE WHEN quarter = 'Q1' THEN amount END) AS q1,
       SUM(CASE WHEN quarter = 'Q2' THEN amount END) AS q2,
       SUM(CASE WHEN quarter = 'Q3' THEN amount END) AS q3
FROM monthly_sales
GROUP BY city
ORDER BY city;
```

Q1이 아닌 행에서 CASE 결과는 NULL이고 SUM은 NULL을 제외한다. Q1 행만 합계에 참여한다.

### ELSE 0을 넣을 때

```sql
SUM(CASE WHEN quarter = 'Q1' THEN amount ELSE 0 END)
```

일치하는 행이 없어도 그룹 안의 다른 행들이 0을 제공하므로 0이 될 수 있다. `ELSE`가 없는 방식과 없는 조합의 의미가 달라진다.

## 열 값은 보통 미리 알아야 한다

정적 PIVOT의 `IN` 목록에는 Q1, Q2처럼 만들 열을 미리 적는다. 데이터에 새로운 Q4가 들어와도 목록에 없으면 자동 열이 되지 않는다. 동적 열 생성은 DBMS별 동적 SQL이나 전용 기능이 필요하며, 고정된 결과 구조를 기대하는 애플리케이션에는 별도 설계가 필요하다.

## PIVOT을 쓰기 전 점검

1. 결과 한 행을 만드는 기준은 무엇인가? `city`
2. 새 열이 될 값은 무엇인가? `quarter`
3. 칸에 들어갈 값은 무엇인가? `amount`
4. 같은 칸에 여러 입력 행이 오면 어떻게 합칠 것인가? `SUM`
5. 없는 칸을 NULL로 둘 것인가 0으로 표시할 것인가?

## 시험에서는 어떻게 묻나

- 집계 열과 피벗 열을 바꿔 놓은 문법을 찾게 한다.
- 나머지 열이 암묵적 그룹 기준이 된다는 점을 묻는다.
- 같은 분류 입력이 여러 행일 때 반드시 집계된다는 점을 묻는다.
- PIVOT과 UNPIVOT의 방향을 비교한다.

## 짧은 확인

입력에 `city, quarter, amount, sale_id` 네 열이 있고 PIVOT에서 amount와 quarter만 사용했다. 예상보다 결과 행이 많아질 수 있는 이유는?

<Collapse title="확인하기">

남은 city뿐 아니라 sale_id도 암묵적 그룹 기준이 되기 때문이다. PIVOT 입력 인라인 뷰에서 city, quarter, amount만 선택한다.

</Collapse>

## 흔한 실수와 진단법

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 지역별 여러 행 생성 | 불필요한 입력 열이 그룹 기준 | 입력 인라인 뷰 열 축소 |
| 새 분기 열이 없음 | IN 목록에 미지정 | 고정 목록 갱신 또는 동적 방식 검토 |
| 없는 조합이 NULL | 집계할 입력 행 없음 | 의미 확인 후 바깥에서 COALESCE |
| 합계가 예상보다 큼 | 원본에 중복 행 | PIVOT 전 원본 키와 건수 확인 |

## 정리

<Callout type="default">
  - PIVOT은 분류 열의 값을 새 열 머리글로 펼치고 교차 칸을 집계한다.
  - 집계 열과 피벗 열을 제외한 입력 열은 암묵적 그룹 기준이 된다.
  - 없는 조합은 NULL이며 0과 의미를 구분한다.
  - CASE를 이용한 조건부 집계로도 같은 형태를 만들 수 있다.
</Callout>
