## 같은 모델도 보는 높이가 다르다

데이터 모델은 한 번에 완성된 그림 하나가 아닙니다. 업무를 이해하는 단계에서 시작해 데이터베이스에 실제로 구현할 수 있는 단계까지 점차 구체화됩니다.

| 구분 | 주로 답하는 질문 | 예시 |
| --- | --- | --- |
| 개념 데이터 모델 | 무엇을 관리해야 하는가? | 회원, 주문, 상품 |
| 논리 데이터 모델 | 어떤 속성과 관계가 필요한가? | 회원 번호, 주문 일시, 회원-주문 1:N |
| 물리 데이터 모델 | DB에 어떻게 구현할 것인가? | 테이블, 컬럼 타입, 인덱스, 제약조건 |

<Callout type="info">
  단계가 다르다고 앞 단계가 버려지는 것은 아닙니다. 개념 모델의 업무 의미가 논리 모델과 물리 모델에서도 유지되어야 합니다.
</Callout>

## 개념 데이터 모델: 업무의 뼈대

개념 모델에서는 세부 컬럼보다 중요한 대상과 관계를 확인합니다. 쇼핑몰이라면 회원, 주문, 상품, 결제처럼 업무에서 반복해서 언급되는 대상을 찾습니다.

이 단계에서 확인할 질문은 간단합니다.

- 주문은 회원 없이 존재할 수 있는가?
- 상품 하나는 여러 주문에 들어갈 수 있는가?
- 결제와 주문은 항상 1:1인가, 재시도가 가능한가?

정답은 기술이 아니라 업무 정책에서 나옵니다. 그래서 현업 담당자와 대화하며 검증하는 과정이 중요합니다.

## 논리 데이터 모델: 규칙을 명확하게

논리 모델에서는 엔터티에 속성을 붙이고 관계의 수를 정합니다. DBMS 종류에 덜 묶인 상태에서 "회원 한 명은 주문을 여러 건 할 수 있다" 같은 업무 규칙을 정확히 표현하는 단계입니다.

```text
회원
- 회원번호
- 이름
- 이메일

주문
- 주문번호
- 주문일시
- 주문상태

회원 1명 : 주문 여러 건
```

여기서 `회원번호`와 `주문번호`는 각각을 구분하는 후보 식별자입니다. `주문상태`는 주문에 속하지만, 회원 이름은 회원에 속합니다. 속성이 어디에 속하는지를 분명히 하는 것이 논리 모델의 중요한 역할입니다.

## 물리 데이터 모델: 구현 가능한 형태로

물리 모델에서는 DBMS에 맞는 테이블명, 컬럼명, 자료형, 기본 키, 외래 키, 인덱스 등을 정합니다. 예를 들면 논리 모델의 주문번호를 `order_id BIGINT`로 구현하고, 회원과의 연결에 외래 키를 둘 수 있습니다.

```sql
CREATE TABLE orders (
  order_id BIGINT PRIMARY KEY,
  member_id BIGINT NOT NULL,
  ordered_at TIMESTAMP NOT NULL,
  status VARCHAR(20) NOT NULL
);
```

이 SQL은 물리 구현의 예시일 뿐입니다. 실제 자료형과 명명 규칙은 사용하는 DBMS, 데이터 양, 팀 규칙에 따라 달라질 수 있습니다.

## ERD를 읽는 순서

<Steps>

### 엔터티 이름을 먼저 읽는다

무엇을 관리하는지 확인합니다. 명사 형태의 이름이 많습니다.

### 각 엔터티의 식별자를 찾는다

행을 구분하는 값이 무엇인지 봅니다. 보통 PK로 표시됩니다.

### 관계선을 따라간다

한 건에 여러 건이 연결되는지, 선택 관계인지 확인합니다.

### 관계에 붙은 속성을 점검한다

수량, 신청일, 배점처럼 연결 자체에 속한 정보가 있으면 연결 엔터티가 필요한지 생각합니다.

</Steps>

## 확인 문제

"학생은 여러 과목을 수강할 수 있고, 과목도 여러 학생이 수강할 수 있다. 수강신청일과 성적을 기록한다."라는 요구사항이 있습니다.

- 학생과 과목은 N:M 관계입니다.
- 수강신청일과 성적은 학생만의 값도, 과목만의 값도 아닙니다.
- 따라서 `수강신청` 엔터티를 두고 학생, 과목과 각각 연결하는 방식이 적절합니다.

이 판단 과정을 말로 설명할 수 있으면 ERD 문제에서도 관계를 외우기보다 이해로 풀 수 있습니다.

## 이번 편 정리

- 개념 모델은 업무 대상과 관계의 뼈대를 다룬다.
- 논리 모델은 속성, 식별자, 관계 규칙을 구체화한다.
- 물리 모델은 DBMS에서 실행할 테이블과 제약조건으로 구현한다.
- ERD는 엔터티, 식별자, 관계 순서로 읽는다.
