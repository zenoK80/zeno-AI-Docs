## DDL이란?

DDL(Data Definition Language)은 **데이터베이스 객체의 구조**를 정의하고 변경하는 명령입니다.

| 명령     | 기능                        |
| -------- | --------------------------- |
| CREATE   | 객체 생성 (테이블, 인덱스 등) |
| ALTER    | 객체 구조 변경              |
| DROP     | 객체 삭제                   |
| TRUNCATE | 테이블 데이터 전체 삭제     |
| RENAME   | 객체 이름 변경              |

<Callout type="warning">
  **DDL은 실행 시 자동 COMMIT(묵시적 커밋)됩니다.** DDL 실행 전에 아직 COMMIT하지 않은 DML 변경 사항이 있다면, DDL 실행과 함께 그 DML도 자동 COMMIT됩니다.
</Callout>

## CREATE TABLE과 제약조건

```sql
CREATE TABLE EMP (
  사원번호  NUMBER(4)     CONSTRAINT PK_EMP PRIMARY KEY,
  이름      VARCHAR2(20)  NOT NULL,
  부서번호  NUMBER(2),
  직급      VARCHAR2(10),
  급여      NUMBER(10)    CHECK (급여 > 0),
  이메일    VARCHAR2(50)  UNIQUE,
  관리자번호 NUMBER(4),
  CONSTRAINT FK_EMP_DEPT
    FOREIGN KEY (부서번호) REFERENCES DEPT(부서번호)
);
```

### 주요 제약조건 정리

| 제약조건    | 의미                                          | NULL 허용 |
| ----------- | --------------------------------------------- | --------- |
| PRIMARY KEY | 행을 유일하게 식별, NOT NULL + UNIQUE 효과    | 불가      |
| FOREIGN KEY | 다른 테이블의 PK를 참조, 참조 무결성 유지     | 가능      |
| UNIQUE      | 중복 값 불허, 여러 개 설정 가능              | 가능      |
| NOT NULL    | NULL 값 불허                                  | 불가      |
| CHECK       | 특정 조건을 만족하는 값만 허용               | 가능      |

<Callout type="info">
  PRIMARY KEY는 테이블당 **1개만** 설정할 수 있습니다. UNIQUE는 여러 개 설정 가능합니다. PRIMARY KEY는 자동으로 인덱스가 생성됩니다.
</Callout>

### 복합 PRIMARY KEY

여러 컬럼을 합쳐 기본키로 설정하려면 테이블 레벨 제약조건을 사용합니다.

```sql
CREATE TABLE 수강(
  학번    NUMBER(8),
  과목코드 VARCHAR2(10),
  성적    NUMBER(3),
  CONSTRAINT PK_수강 PRIMARY KEY (학번, 과목코드)  -- 복합 PK
);
```

## ALTER TABLE: 구조 변경

### 컬럼 추가

```sql
ALTER TABLE EMP ADD (입사일 DATE);
```

### 컬럼 수정

```sql
-- 컬럼 크기 변경 (데이터가 없거나 크기를 늘릴 때만 가능)
ALTER TABLE EMP MODIFY (이름 VARCHAR2(30));
```

### 컬럼 삭제

```sql
ALTER TABLE EMP DROP COLUMN 이메일;
```

### 제약조건 추가/삭제

```sql
-- 제약조건 추가
ALTER TABLE EMP ADD CONSTRAINT UK_EMAIL UNIQUE (이메일);

-- 제약조건 삭제
ALTER TABLE EMP DROP CONSTRAINT UK_EMAIL;

-- NOT NULL 제약조건 변경 (MODIFY 사용)
ALTER TABLE EMP MODIFY (이름 VARCHAR2(20) NOT NULL);
```

## DROP TABLE

```sql
-- 테이블 삭제
DROP TABLE EMP;

-- 연관된 외래키 제약조건까지 함께 삭제
DROP TABLE DEPT CASCADE CONSTRAINTS;
```

`CASCADE CONSTRAINTS`를 사용하면 해당 테이블을 참조하는 다른 테이블의 FOREIGN KEY 제약조건도 함께 삭제됩니다.

## DCL이란?

DCL(Data Control Language)은 데이터베이스 객체에 대한 **접근 권한**을 관리합니다.

| 명령   | 기능                     |
| ------ | ------------------------ |
| GRANT  | 권한 부여                |
| REVOKE | 권한 회수                |

### 권한의 종류

**시스템 권한**: 데이터베이스 전반에 걸친 권한

```sql
-- user01에게 테이블 생성 권한 부여
GRANT CREATE TABLE TO user01;

-- DBA 역할(role) 부여
GRANT DBA TO user01;
```

**객체 권한**: 특정 객체(테이블, 뷰 등)에 대한 권한

```sql
-- user01에게 EMP 테이블 SELECT, INSERT 권한 부여
GRANT SELECT, INSERT ON EMP TO user01;

-- user02에게 EMP 테이블 UPDATE 권한 부여하고, 재부여 가능하게 설정
GRANT UPDATE ON EMP TO user02 WITH GRANT OPTION;
```

`WITH GRANT OPTION`을 사용하면 권한을 받은 사용자가 다른 사용자에게 해당 권한을 다시 부여할 수 있습니다.

### REVOKE: 권한 회수

```sql
-- user01의 EMP 테이블 SELECT 권한 회수
REVOKE SELECT ON EMP FROM user01;
```

<Callout type="warning">
  `WITH GRANT OPTION`으로 부여한 권한을 회수하면, 그 권한을 받은 사용자가 다른 사람에게 부여한 권한도 **연쇄적으로 회수(Cascade Revoke)**됩니다.
</Callout>

## DDL vs DML vs DCL 비교

| 구분 | 명령            | 자동 COMMIT |
| ---- | --------------- | ----------- |
| DDL  | CREATE, ALTER, DROP, TRUNCATE, RENAME | **예** |
| DML  | SELECT, INSERT, UPDATE, DELETE, MERGE | 아니오 |
| DCL  | GRANT, REVOKE   | **예**      |
| TCL  | COMMIT, ROLLBACK, SAVEPOINT | - |

## 핵심 정리

- **PRIMARY KEY**: NOT NULL + UNIQUE, 테이블당 1개, 자동 인덱스 생성
- **FOREIGN KEY**: 참조 테이블의 PK 값만 허용, NULL 가능
- **UNIQUE**: 중복 불허, NULL 가능, 여러 개 설정 가능
- **CHECK**: 조건식으로 값의 범위/형식 제한
- **ALTER TABLE**: 컬럼 추가(ADD), 수정(MODIFY), 삭제(DROP COLUMN), 제약조건 관리
- **DDL 자동 COMMIT**: CREATE, ALTER, DROP, TRUNCATE 실행 시 자동 커밋
- **CASCADE CONSTRAINTS**: 참조 관계에 있는 제약조건 연쇄 삭제
- **WITH GRANT OPTION**: 권한을 재부여할 수 있는 권리도 함께 부여
