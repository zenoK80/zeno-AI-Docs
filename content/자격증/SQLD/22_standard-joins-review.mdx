## 복습 방법

외부 조인은 SQL을 읽자마자 **보존되는 쪽에 밑줄**을 긋고, 짝 없는 행의 반대쪽 열에 `NULL`을 적는다.

## 직접 적용하기

다음 데이터에서 아래 두 쿼리의 결과 차이를 적어 보자.

`members`: M01 민지, M02 준호, M03 소라
`orders`: M01 PAID, M02 CANCELED

```sql
-- A
SELECT m.name, o.status
FROM members m
LEFT JOIN orders o
  ON m.member_id = o.member_id
 AND o.status = 'PAID';

-- B
SELECT m.name, o.status
FROM members m
LEFT JOIN orders o
  ON m.member_id = o.member_id
WHERE o.status = 'PAID';
```

<Collapse title="풀이">

A는 세 회원을 모두 보존한다.

| name | status |
| --- | --- |
| 민지 | PAID |
| 준호 | NULL |
| 소라 | NULL |

B는 조인 후 `status = 'PAID'`가 참인 민지만 남긴다. 준호의 CANCELED와 소라의 NULL은 WHERE를 통과하지 못한다.

</Collapse>

## 오류 진단 체크리스트

- LEFT·RIGHT 방향을 테이블 작성 순서와 함께 읽었는가?
- 보존해야 할 행을 제거하는 WHERE 조건은 없는가?
- USING의 열 이름이 양쪽에 실제로 같은가?
- NATURAL JOIN이 자동 선택한 공통 열을 모두 확인했는가?
