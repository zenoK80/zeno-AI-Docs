## 트랜잭션이란?

트랜잭션(Transaction)은 **하나의 논리적 작업 단위**로 처리되어야 하는 일련의 SQL 문장 집합입니다. 트랜잭션은 모두 성공하거나 모두 실패해야 합니다.

**예시: 계좌 이체**

```
1. A 계좌에서 10만원 차감  (UPDATE)
2. B 계좌에 10만원 추가    (UPDATE)
```

1번만 성공하고 2번이 실패하면 10만원이 사라집니다. 이 두 작업은 반드시 하나의 트랜잭션으로 묶어야 합니다.

## ACID 속성

트랜잭션이 보장해야 하는 4가지 성질입니다.

| 속성             | 영문              | 의미                                                |
| ---------------- | ----------------- | --------------------------------------------------- |
| **원자성**       | Atomicity         | 트랜잭션의 모든 작업이 완전히 실행되거나 전혀 실행되지 않음 |
| **일관성**       | Consistency       | 트랜잭션 전후로 데이터베이스는 항상 일관된 상태를 유지 |
| **고립성(격리성)** | Isolation       | 동시에 실행되는 트랜잭션이 서로 영향을 주지 않음    |
| **영속성(지속성)** | Durability      | COMMIT된 트랜잭션 결과는 영구적으로 저장됨          |

## TCL 명령어

TCL(Transaction Control Language)은 트랜잭션을 제어하는 명령입니다.

| 명령       | 기능                              |
| ---------- | --------------------------------- |
| COMMIT     | 트랜잭션 변경 내용을 영구 저장    |
| ROLLBACK   | 마지막 COMMIT 이후 변경 취소      |
| SAVEPOINT  | 트랜잭션 내 부분 롤백 기준점 설정 |

## COMMIT

```sql
UPDATE EMP SET 급여 = 5000000 WHERE 사원번호 = 1001;
INSERT INTO EMP VALUES (1006, '한지수', 30, '사원', 2700000, 1001);
COMMIT;  -- 두 변경 사항 모두 확정
```

COMMIT을 실행하면:
- 변경 내용이 데이터베이스에 영구 저장됩니다.
- 다른 세션(다른 사용자)에서도 변경 내용을 볼 수 있습니다.
- 이전 COMMIT 이후의 모든 LOCK이 해제됩니다.

## ROLLBACK

```sql
UPDATE EMP SET 급여 = 0;  -- 실수로 전체 급여를 0으로 변경
ROLLBACK;                  -- 마지막 COMMIT 이후로 되돌림
```

ROLLBACK을 실행하면:
- 마지막 COMMIT 이후의 모든 변경이 취소됩니다.
- 변경 전 상태로 완전히 되돌아갑니다.

## SAVEPOINT: 부분 롤백

트랜잭션 중간에 저장점을 만들어 일부만 롤백할 수 있습니다.

```sql
-- 1단계: 사원 추가
INSERT INTO EMP (사원번호, 이름, 급여) VALUES (1006, '한지수', 2700000);
SAVEPOINT SP1;  -- 저장점 SP1 설정

-- 2단계: 급여 수정
UPDATE EMP SET 급여 = 9999999 WHERE 사원번호 = 1001;
SAVEPOINT SP2;  -- 저장점 SP2 설정

-- 3단계: 부서 추가
INSERT INTO DEPT VALUES (50, '해외팀', '뉴욕');

-- 2단계 이후 내용만 취소 (SP2로 롤백)
ROLLBACK TO SAVEPOINT SP2;
-- 이제 3단계(부서 추가)만 취소됨
-- 1단계(사원 추가), 2단계(급여 수정)는 유지됨

-- 전체 취소
ROLLBACK;
-- 또는 확정
COMMIT;
```

**SAVEPOINT 활용 흐름**

```
BEGIN TRANSACTION
  ↓
  INSERT 사원      → SAVEPOINT SP1
  ↓
  UPDATE 급여      → SAVEPOINT SP2
  ↓
  INSERT 부서
  ↓
  ROLLBACK TO SP2  → 부서 추가만 취소
  ↓
  COMMIT           → 사원 추가, 급여 수정 확정
```

<Callout type="info">
  `ROLLBACK TO SAVEPOINT 이름`은 해당 저장점 이후의 변경만 취소합니다. 저장점 이전 변경 내용은 유지됩니다.
</Callout>

## 트랜잭션 시작과 종료

| 시작 조건                   | 종료 조건              |
| --------------------------- | ---------------------- |
| DML(INSERT/UPDATE/DELETE) 첫 실행 | COMMIT 실행            |
| 이전 트랜잭션 종료 직후    | ROLLBACK 실행          |
|                             | DDL/DCL 실행 (자동 COMMIT) |
|                             | 정상 종료 (자동 COMMIT) |
|                             | 비정상 종료 (자동 ROLLBACK) |

## DDL/DCL 실행 시 자동 COMMIT

```sql
UPDATE EMP SET 급여 = 5000000 WHERE 사원번호 = 1001; -- 미커밋 상태

CREATE TABLE TEMP (id NUMBER);  -- DDL 실행 → 자동 COMMIT 발생!
-- 위의 UPDATE도 함께 COMMIT됨 → ROLLBACK 불가!
```

<Callout type="warning">
  DDL(CREATE, ALTER, DROP, TRUNCATE) 또는 DCL(GRANT, REVOKE)을 실행하면 **그 시점까지 미커밋 DML이 자동으로 COMMIT**됩니다. 이는 SQLD 시험의 단골 함정 문제입니다.
</Callout>

## 잠금(LOCK)과 동시성

한 세션이 DML로 행을 변경하면, 그 행에 **행 수준 잠금(Row-Level Lock)**이 걸립니다.

- 다른 세션은 잠금된 행을 수정할 수 없음 (대기 상태)
- COMMIT 또는 ROLLBACK 시 잠금 해제
- 다른 세션의 **SELECT(읽기)는 잠금에 영향받지 않음** (Oracle 기준, MVCC 적용)

## 핵심 정리

- **원자성(A)**: 트랜잭션은 전부 성공 or 전부 실패
- **일관성(C)**: 트랜잭션 전후 DB 무결성 유지
- **고립성(I)**: 동시 트랜잭션 간 간섭 없음
- **영속성(D)**: COMMIT 후 결과는 영구 보존
- **COMMIT**: 변경 확정, 다른 세션도 볼 수 있음, LOCK 해제
- **ROLLBACK**: 마지막 COMMIT 이후 모든 변경 취소
- **SAVEPOINT**: 중간 저장점, `ROLLBACK TO SAVEPOINT`로 부분 취소
- **자동 COMMIT 발생**: DDL 실행, DCL 실행, 정상 세션 종료
