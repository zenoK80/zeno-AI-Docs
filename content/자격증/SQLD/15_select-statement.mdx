## 이번 편의 목표

- `SELECT`와 `FROM`의 역할을 구분해 읽는다.
- 필요한 열, 계산식과 열 별칭을 결과표로 확인한다.
- `DISTINCT`가 한 열이 아니라 선택한 열 조합의 중복을 제거함을 설명한다.
- SQL 작성 순서와 논리적 처리 순서를 구분한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| SELECT 목록 | 결과에 보여 줄 열과 계산식을 적는 부분 |
| FROM 절 | 데이터를 가져올 출발 테이블을 정하는 부분 |
| 별칭 | 결과 열이나 테이블에 붙이는 임시 이름 |
| 리터럴 | SQL에 직접 적은 숫자·문자·날짜 값 |
| 표현식 | 열과 연산자·함수를 조합해 계산한 식 |
| DISTINCT | 결과에서 선택한 열 조합의 중복을 제거하는 키워드 |

## 선수지식과 핵심 질문

14편에서 투영은 필요한 열을 고르는 연산이라고 배웠다.

> 회원 표에서 이름만 보거나, 포인트를 원화처럼 계산한 새 열을 만들려면 어떻게 쓸까?

## 이번 SQL에서 사용할 회원 데이터

| member_id | member_name | city | grade | points |
| --- | --- | --- | --- | ---: |
| M01 | 민지 | 서울 | GOLD | 1,200 |
| M02 | 준호 | 부산 | SILVER | 500 |
| M03 | 소라 | 서울 | GOLD | 800 |
| M04 | 현우 | 대구 | BRONZE | 0 |

앞으로 15~27편에서 이 회원·주문 데이터를 반복 사용한다. 매번 결과가 어디에서 나왔는지 이 입력 표와 대조한다.

## SELECT 문을 말로 읽기

```sql
SELECT member_id, member_name
FROM members;
```

| SQL 부분 | 읽는 말 |
| --- | --- |
| `SELECT member_id, member_name` | 결과에 회원번호와 이름을 보여 줘 |
| `FROM members` | 회원 테이블에서 가져와 |

결과는 입력 4행을 유지하고 두 열만 보여 준다.

| member_id | member_name |
| --- | --- |
| M01 | 민지 |
| M02 | 준호 |
| M03 | 소라 |
| M04 | 현우 |

세미콜론 `;`은 한 SQL 문장의 끝을 나타낸다. 도구에 따라 생략할 수 있지만 문서를 읽을 때 문장 경계를 보여 준다.

## 별표와 열 이름

```sql
SELECT *
FROM members;
```

`*`는 현재 테이블의 모든 열을 뜻한다. 학습할 때는 편하지만 실제 서비스 쿼리에서는 필요한 열을 명시하는 편이 의도와 결과 구조를 분명하게 만든다.

| 방식 | 장점 | 주의점 |
| --- | --- | --- |
| `SELECT *` | 빠르게 전체 확인 | 불필요한 열, 테이블 변경 영향, 이름 충돌 가능 |
| 열 이름 명시 | 필요한 결과가 분명 | 열을 직접 적어야 함 |

## 표현식으로 새 결과 열 만들기

SELECT 목록에는 저장된 열뿐 아니라 계산식도 쓸 수 있다.

```sql
SELECT member_name,
       points,
       points * 10 AS point_value
FROM members;
```

| member_name | points | point_value |
| --- | ---: | ---: |
| 민지 | 1,200 | 12,000 |
| 준호 | 500 | 5,000 |
| 소라 | 800 | 8,000 |
| 현우 | 0 | 0 |

`points * 10`은 테이블에 새 열을 저장한 것이 아니다. 조회할 때 각 행의 포인트에 10을 곱해 결과 열을 만든다.

## 열 별칭

`AS point_value`는 계산 결과에 읽기 쉬운 이름을 붙인다.

```sql
SELECT member_name AS name,
       points AS current_points
FROM members;
```

| name | current_points |
| --- | ---: |
| 민지 | 1,200 |
| 준호 | 500 |
| 소라 | 800 |
| 현우 | 0 |

대부분의 DBMS에서 열 별칭의 `AS`는 생략할 수 있다. 공백이나 특수문자, 대소문자를 그대로 유지해야 하는 별칭은 DBMS 규칙에 맞는 따옴표를 사용한다.

<Callout type="warning">
  별칭은 이 조회 결과에서만 사용하는 이름이다. 원래 테이블의 열 이름을 변경하지 않는다.
</Callout>

## 문자 리터럴과 연결

Oracle과 PostgreSQL에서는 `||`로 문자열을 연결할 수 있다.

```sql
SELECT member_name || ' 회원' AS display_name
FROM members;
```

| display_name |
| --- |
| 민지 회원 |
| 준호 회원 |
| 소라 회원 |
| 현우 회원 |

`' 회원'`은 열 이름이 아니라 SQL에 직접 적은 문자 리터럴이다. SQL Server는 문자열 연결에 `+`를 사용하는 등 제품 차이가 있다.

## DISTINCT는 열 조합의 중복을 제거한다

```sql
SELECT city
FROM members;
```

| city |
| --- |
| 서울 |
| 부산 |
| 서울 |
| 대구 |

서울이 두 번 나온다. `DISTINCT`를 붙이면 동일한 결과 행을 한 번만 남긴다.

```sql
SELECT DISTINCT city
FROM members;
```

| city |
| --- |
| 서울 |
| 부산 |
| 대구 |

두 열을 선택하면 두 열의 **조합 전체**가 같을 때만 중복이다.

```sql
SELECT DISTINCT city, grade
FROM members;
```

| city | grade |
| --- | --- |
| 서울 | GOLD |
| 부산 | SILVER |
| 대구 | BRONZE |

현재 데이터에서는 서울 회원 두 명의 등급도 GOLD라 한 행으로 줄었다. 서울 GOLD와 서울 SILVER가 있었다면 서로 다른 조합이라 두 행 모두 남는다.

## 산술식과 NULL

표현식에 NULL이 들어가면 보통 결과도 NULL이다.

| member_name | bonus_points |
| --- | ---: |
| 민지 | 100 |
| 준호 | NULL |

```sql
SELECT member_name,
       points + bonus_points AS total_points
FROM members;
```

준호의 `total_points`는 NULL이다. 값을 모르는 보너스를 더하면 합계도 알 수 없기 때문이다. NULL을 0으로 보아도 된다는 업무 규칙이 있을 때만 `COALESCE`나 `NVL`을 사용한다.

## 작성 순서와 결과 이해 순서

SQL은 SELECT부터 쓰지만 결과를 이해할 때는 FROM에서 시작한다.

```mermaid
flowchart LR
  A["FROM: 출발 행"] --> B["WHERE: 행 필터"]
  B --> C["GROUP BY: 그룹 생성"]
  C --> D["HAVING: 그룹 필터"]
  D --> E["SELECT: 결과 열 계산"]
  E --> F["ORDER BY: 최종 정렬"]
```

```text
1. FROM: 출발 행을 만든다.
2. WHERE: 조건에 맞는 행만 남긴다.
3. GROUP BY: 같은 값끼리 그룹을 만든다.
4. HAVING: 그룹을 걸러낸다.
5. SELECT: 보여 줄 열과 식을 계산한다.
6. ORDER BY: 마지막 결과를 정렬한다.
```

실제 DBMS의 옵티마이저는 같은 결과를 더 효율적으로 만들기 위해 물리 실행 순서를 바꿀 수 있다. 위 순서는 문법 결과를 이해하기 위한 논리적 순서다.

## 흔한 실수와 진단법

| 실수 | 결과 | 확인 |
| --- | --- | --- |
| 별칭이 원본 열 이름을 바꾼다고 생각 | 스키마와 결과 이름 혼동 | SELECT 결과에서만 사용 |
| DISTINCT가 첫 열에만 적용된다고 생각 | 행 수 예측 오류 | SELECT 열 조합 전체 비교 |
| ORDER BY 없이 출력 순서를 가정 | 실행마다 순서가 달라질 수 있음 | 순서가 필요하면 명시 |
| NULL 산술 결과를 0으로 예상 | 계산 결과 오류 | NULL 규칙 확인 |

## 시험 연결

1. SELECT 목록은 결과 열을 정하고 FROM은 출발 테이블을 정한다.
2. 표현식과 별칭은 원본 데이터를 바꾸지 않고 조회 결과를 만든다.
3. DISTINCT는 SELECT 목록 전체 조합의 중복을 제거한다.
4. ORDER BY가 없으면 결과 행의 순서를 보장하지 않는다.

## 짧은 확인

`SELECT DISTINCT city, grade`에서 city만 같고 grade가 다르면 한 행으로 합쳐질까?

<Collapse title="확인하기">

합쳐지지 않는다. DISTINCT는 city와 grade 조합 전체를 비교한다. `(서울, GOLD)`와 `(서울, SILVER)`는 서로 다른 결과 행이다.

</Collapse>

## 정리

<Callout type="default">
  - SELECT는 결과 열, FROM은 출발 테이블을 정한다.
  - 계산식과 별칭은 조회 결과에서만 새 값을 만든다.
  - DISTINCT는 선택한 열 조합의 중복을 제거한다.
  - 결과 순서는 ORDER BY가 있을 때만 요구할 수 있다.
</Callout>
