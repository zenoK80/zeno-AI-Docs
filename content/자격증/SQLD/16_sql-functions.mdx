## 이번 편의 목표

- 단일행 함수와 다중행 함수를 결과 행 수로 구분한다.
- 문자·숫자·날짜 함수의 입력과 출력을 예측한다.
- 명시적 형 변환과 암시적 형 변환의 차이를 설명한다.
- NULL 함수와 CASE를 업무 의미에 맞게 사용한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 함수 | 입력값을 받아 정해진 처리를 하고 결과값을 반환하는 기능 |
| 단일행 함수 | 입력 한 행마다 결과 한 값을 만드는 함수 |
| 다중행 함수 | 여러 행을 한 그룹으로 보고 요약값 하나를 만드는 함수 |
| 형 변환 | 문자·숫자·날짜처럼 값의 자료형을 바꾸는 것 |
| 명시적 변환 | `TO_DATE`, `CAST`처럼 변환 규칙을 직접 적는 것 |
| 암시적 변환 | DBMS가 비교를 위해 자료형을 자동 변환하는 것 |

## 선수지식과 핵심 질문

15편에서 SELECT 목록에 계산식을 쓸 수 있다고 배웠다.

> 이름 일부를 자르거나 금액을 반올림하고 날짜 형식을 바꿀 때 매번 직접 계산해야 할까?

## 단일행과 다중행을 먼저 구분하기

| member_name | points |
| --- | ---: |
| 민지 | 1,200 |
| 준호 | 500 |
| 소라 | 800 |

```sql
SELECT UPPER(member_name), points * 2
FROM members;
```

입력 3행마다 결과가 하나씩 나와 3행이다. 이것이 단일행 처리다.

```sql
SELECT SUM(points)
FROM members;
```

| sum |
| ---: |
| 2,500 |

세 행을 합쳐 한 결과를 만들었으므로 다중행 집계다. GROUP BY는 18편에서 자세히 다룬다.

## 문자 함수

제품마다 함수 이름과 위치 기준이 조금 다르다. SQLD에서 자주 보는 Oracle 형태를 중심으로 읽는다.

```sql
SELECT UPPER('sqld') AS upper_text,
       LOWER('SQLD') AS lower_text,
       LENGTH('SQLD') AS text_length,
       SUBSTR('DATABASE', 1, 4) AS first_four
FROM dual;
```

| upper_text | lower_text | text_length | first_four |
| --- | --- | ---: | --- |
| SQLD | sqld | 4 | DATA |

- `UPPER`, `LOWER`는 대소문자를 바꾼다.
- `LENGTH`는 문자 길이를 반환한다.
- Oracle `SUBSTR(text, 시작, 길이)`에서 위치는 1부터 시작한다.
- Oracle의 `DUAL`은 계산식 한 행을 조회할 때 쓰는 한 행짜리 특수 테이블이다.

공백 제거도 자주 나온다.

```sql
SELECT TRIM('  SQLD  ') AS trimmed,
       REPLACE('SQL-D', '-', '') AS replaced
FROM dual;
```

| trimmed | replaced |
| --- | --- |
| SQLD | SQLD |

## 숫자 함수

```sql
SELECT ROUND(1234.567, 2) AS rounded,
       TRUNC(1234.567, 2) AS truncated,
       CEIL(12.1) AS ceiling_value,
       FLOOR(12.9) AS floor_value,
       MOD(17, 5) AS remainder
FROM dual;
```

| rounded | truncated | ceiling_value | floor_value | remainder |
| ---: | ---: | ---: | ---: | ---: |
| 1234.57 | 1234.56 | 13 | 12 | 2 |

`ROUND`는 다음 자리로 반올림하고 `TRUNC`는 지정 자리 아래를 버린다. `CEIL`은 같거나 큰 최소 정수, `FLOOR`는 같거나 작은 최대 정수다.

음수 자리도 확인하자.

| 식 | 결과 | 뜻 |
| --- | ---: | --- |
| `ROUND(1537, -2)` | 1,500 | 백의 자리까지 반올림 |
| `TRUNC(1537, -2)` | 1,500 | 백의 자리 아래 버림 |
| `ROUND(1567, -2)` | 1,600 | 십의 자리 6이라 올림 |

## 날짜 함수와 날짜 연산

Oracle에서 날짜에 숫자를 더하면 일수가 더해진다.

```sql
SELECT DATE '2026-08-10' + 7 AS next_week,
       ADD_MONTHS(DATE '2026-08-10', 1) AS next_month,
       LAST_DAY(DATE '2026-02-10') AS month_end
FROM dual;
```

| next_week | next_month | month_end |
| --- | --- | --- |
| 2026-08-17 | 2026-09-10 | 2026-02-28 |

날짜끼리 빼면 Oracle에서는 일수 차이를 얻는다. `CURRENT_DATE`, `SYSDATE` 같은 현재 시각 함수는 세션 시간대와 DBMS에 따라 의미가 다를 수 있다.

## 명시적 형 변환

문자 `'2026-08-10'`과 날짜는 겉모양이 비슷해도 자료형이 다르다. 형식 모델을 직접 적으면 의도가 분명하다.

```sql
SELECT TO_DATE('2026-08-10', 'YYYY-MM-DD') AS converted_date,
       TO_CHAR(DATE '2026-08-10', 'YYYY/MM/DD') AS display_date,
       TO_NUMBER('1200') + 300 AS total
FROM dual;
```

| converted_date | display_date | total |
| --- | --- | ---: |
| 2026-08-10 | 2026/08/10 | 1,500 |

암시적 변환에 맡기면 세션 날짜 형식이나 잘못된 문자 때문에 오류·성능 문제가 생길 수 있다. 시험에서도 문자와 숫자의 자동 변환 방향을 주의한다.

## NULL 함수

| member_name | bonus_points |
| --- | ---: |
| 민지 | 100 |
| 준호 | NULL |

Oracle의 `NVL(value, 대체값)`과 표준적인 `COALESCE`는 NULL을 대체할 수 있다.

```sql
SELECT member_name,
       NVL(bonus_points, 0) AS bonus_or_zero
FROM members;
```

| member_name | bonus_or_zero |
| --- | ---: |
| 민지 | 100 |
| 준호 | 0 |

`COALESCE(a, b, c)`는 왼쪽부터 첫 번째 NULL이 아닌 값을 반환한다. `NULLIF(a, b)`는 두 값이 같으면 NULL, 다르면 a를 반환한다.

<Callout type="warning">
  NULL을 대체하면 원래 “모름” 상태가 사라진다. 업무에서 NULL을 0이나 기본값으로 보아도 되는 경우에만 사용한다.
</Callout>

## CASE로 조건별 결과 만들기

```sql
SELECT member_name,
       points,
       CASE
         WHEN points >= 1000 THEN 'HIGH'
         WHEN points >= 500 THEN 'MID'
         ELSE 'LOW'
       END AS point_level
FROM members;
```

| member_name | points | point_level |
| --- | ---: | --- |
| 민지 | 1,200 | HIGH |
| 준호 | 500 | MID |
| 소라 | 800 | MID |
| 현우 | 0 | LOW |

CASE는 위에서부터 조건을 확인하고 처음 TRUE인 결과에서 멈춘다. 따라서 더 구체적이거나 높은 기준을 먼저 두어야 한다.

Oracle의 `DECODE`는 값의 동등 비교를 간단히 표현하지만 범위 조건과 이식성에서는 CASE가 더 유연하다.

## 함수 중첩

함수 안에 다른 함수를 넣으면 안쪽부터 계산한다.

```sql
SELECT UPPER(SUBSTR('database', 1, 4)) AS result
FROM dual;
```

```text
1. SUBSTR('database', 1, 4) → 'data'
2. UPPER('data') → 'DATA'
```

| result |
| --- |
| DATA |

## 흔한 실수와 진단법

| 실수 | 문제 | 확인 |
| --- | --- | --- |
| ROUND와 TRUNC를 같은 것으로 봄 | 경계값 결과 오류 | 올림 여부 직접 계산 |
| 날짜 문자열 형식을 생략 | 세션 설정 의존 | TO_DATE 형식 명시 |
| CASE의 넓은 조건을 먼저 둠 | 뒤 조건에 도달하지 못함 | 위에서부터 TRUE 검사 |
| 단일행과 집계를 혼용 | GROUP BY 오류 | 결과가 입력 행마다 나오는지 확인 |

## 시험 연결

1. 단일행 함수는 입력 행마다 결과를 만들고 집계함수는 여러 행을 요약한다.
2. 함수 중첩은 가장 안쪽부터 바깥쪽으로 계산한다.
3. 명시적 형 변환은 자료형과 형식 모델을 드러낸다.
4. NULL 함수와 CASE는 결과값뿐 아니라 업무 의미와 조건 순서를 확인한다.

## 짧은 확인

`CASE WHEN points >= 500 THEN 'MID' WHEN points >= 1000 THEN 'HIGH' ...`에서 1200점의 결과는 무엇일까?

<Collapse title="확인하기">

`MID`다. 첫 조건 `points >= 500`이 이미 TRUE라 다음 조건을 검사하지 않는다. HIGH를 원하면 `>= 1000` 조건을 먼저 둔다.

</Collapse>

  - 명시적 형 변환은 세션 설정에 따른 모호함을 줄인다.

</Callout>
