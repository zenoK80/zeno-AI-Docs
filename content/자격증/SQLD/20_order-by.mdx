## 이번 편의 목표

- ORDER BY가 최종 결과 순서를 요구하는 절임을 설명한다.
- ASC·DESC와 여러 정렬 열의 우선순위를 적용한다.
- SELECT 별칭과 열 번호 정렬의 장단점을 구분한다.
- NULL의 정렬 위치가 DBMS와 옵션에 따라 달라질 수 있음을 이해한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 정렬 | 결과 행을 지정한 값의 크기·문자·날짜 순으로 배치하는 것 |
| ASC | 오름차순. 작은 값에서 큰 값 |
| DESC | 내림차순. 큰 값에서 작은 값 |
| 정렬 키 | 행 순서를 결정하는 열 또는 표현식 |
| NULLS FIRST | NULL 행을 먼저 배치 |
| NULLS LAST | NULL 행을 마지막에 배치 |

## 선수지식과 핵심 질문

19편까지 필요한 행과 그룹을 만들었다. ORDER BY는 그 최종 행들의 표시 순서를 정한다.

> 등급별로 묶지 않고 회원 목록을 포인트가 높은 순서로 보여 주려면 어떻게 할까?

## 입력 회원 데이터

| member_id | member_name | grade | points | joined_at |
| --- | --- | --- | ---: | --- |
| M01 | 민지 | GOLD | 1,200 | 2025-01-10 |
| M02 | 준호 | SILVER | 500 | 2025-03-15 |
| M03 | 소라 | GOLD | 800 | 2025-05-20 |
| M04 | 현우 | BRONZE | 0 | 2025-07-01 |

## 오름차순과 내림차순

```sql
SELECT member_name, points
FROM members
ORDER BY points DESC;
```

| member_name | points |
| --- | ---: |
| 민지 | 1,200 |
| 소라 | 800 |
| 준호 | 500 |
| 현우 | 0 |

DESC가 포인트 큰 행부터 배치한다. ASC는 생략 가능하며 기본값이다.

```sql
SELECT member_name, joined_at
FROM members
ORDER BY joined_at ASC;
```

날짜가 빠른 민지부터 늦은 현우 순으로 나온다.

## 여러 열 정렬은 왼쪽부터

```sql
SELECT member_name, grade, points
FROM members
ORDER BY grade ASC, points DESC;
```

1. 먼저 grade로 전체를 정렬한다.
2. grade가 같은 행 안에서 points를 내림차순 정렬한다.

| member_name | grade | points |
| --- | --- | ---: |
| 현우 | BRONZE | 0 |
| 민지 | GOLD | 1,200 |
| 소라 | GOLD | 800 |
| 준호 | SILVER | 500 |

GOLD 두 행만 두 번째 기준을 비교해 민지가 소라보다 먼저다.

<Callout type="info">
  여러 정렬 열은 모두 동시에 같은 중요도로 비교하지 않는다. 첫 열이 같을 때만 다음 열로 넘어간다.
</Callout>

## 별칭으로 정렬

ORDER BY는 논리적으로 SELECT 결과가 만들어진 뒤 적용되므로 SELECT 별칭을 사용할 수 있다.

```sql
SELECT member_name,
       points * 10 AS point_value
FROM members
ORDER BY point_value DESC;
```

| member_name | point_value |
| --- | ---: |
| 민지 | 12,000 |
| 소라 | 8,000 |
| 준호 | 5,000 |
| 현우 | 0 |

WHERE에서는 일반적으로 같은 SELECT 별칭을 바로 쓸 수 없다. WHERE 시점에는 SELECT 결과 별칭이 아직 만들어지지 않았기 때문이다.

## 열 번호 정렬

```sql
SELECT member_name, grade, points
FROM members
ORDER BY 3 DESC, 1 ASC;
```

`3`은 SELECT 목록의 세 번째 열 points, `1`은 첫 번째 열 member_name을 뜻한다. 짧지만 SELECT 열 순서를 바꾸면 정렬 의미도 바뀌어 유지보수에 불리하다. 시험에서는 번호가 어떤 열을 가리키는지 정확히 센다.

## SELECT에 없는 열 정렬

일반 SELECT에서는 결과에 표시하지 않은 열로도 정렬할 수 있는 DBMS가 많다.

```sql
SELECT member_name
FROM members
ORDER BY joined_at;
```

그러나 DISTINCT와 함께 쓸 때는 정렬 표현식이 SELECT 목록에 있어야 하는 등 DBMS 제약이 생길 수 있다. 시험 문제의 DBMS와 구문을 확인한다.

## NULL 정렬

| member_name | last_login_at |
| --- | --- |
| 민지 | 2026-08-10 |
| 준호 | NULL |
| 소라 | 2026-08-09 |

NULL이 작은 값인지 큰 값인지는 일반 값 비교로 정하지 않으며 기본 배치가 DBMS와 정렬 방향에 따라 다를 수 있다. 지원하는 DBMS에서는 의도를 명시한다.

```sql
SELECT member_name, last_login_at
FROM members
ORDER BY last_login_at DESC NULLS LAST;
```

| member_name | last_login_at |
| --- | --- |
| 민지 | 2026-08-10 |
| 소라 | 2026-08-09 |
| 준호 | NULL |

Oracle은 기본적으로 ASC에서 NULL을 뒤, DESC에서 앞에 두는 특성이 있다. SQL Server 등은 기본 동작이 다르므로 `NULLS FIRST/LAST` 지원 여부와 함께 구분한다.

## 문자열 정렬

문자열 순서는 문자 집합과 정렬 규칙(collation)에 영향을 받는다. 단순히 사람이 기대하는 한글 사전순과 항상 같다고 가정하지 않는다. 대소문자·악센트 처리도 DBMS 설정에 따라 달라질 수 있다.

## GROUP BY와 ORDER BY는 목적이 다르다

```sql
SELECT member_id, SUM(total_amount) AS total
FROM orders
GROUP BY member_id
ORDER BY total DESC;
```

| member_id | total |
| --- | ---: |
| M02 | 250,000 |
| M01 | 136,000 |
| M03 | 120,000 |

GROUP BY는 세 회원 그룹을 만들고 ORDER BY는 이미 만들어진 세 결과 행의 순서만 바꾼다. GROUP BY가 정렬을 보장한다고 생각하면 안 된다.

## 동점 순서를 안정적으로 만들기

포인트가 같은 회원의 순서까지 일정해야 한다면 추가 정렬 키를 둔다.

```sql
ORDER BY points DESC, member_id ASC
```

첫 기준이 같을 때 고유한 member_id로 순서를 결정하면 페이지 나누기와 Top N 결과가 안정적이다.

## 흔한 실수와 진단법

| 실수 | 문제 | 확인 |
| --- | --- | --- |
| GROUP BY가 자동 정렬한다고 생각 | 결과 순서 보장 없음 | ORDER BY 명시 |
| 여러 열 우선순위를 반대로 읽음 | 동점 행 순서 오류 | 왼쪽 열부터 비교 |
| ORDER BY 번호를 테이블 열 번호로 해석 | 다른 열 정렬 | SELECT 목록 위치 |
| NULL 기본 위치를 모든 DBMS에서 같다고 봄 | 결과 예측 오류 | DBMS·옵션 확인 |

## 시험 연결

1. ORDER BY는 논리적으로 최종 결과에 적용된다.
2. ASC는 기본 오름차순, DESC는 내림차순이다.
3. 여러 정렬 키는 왼쪽부터 적용하고 동점일 때 다음 키를 본다.
4. 별칭과 SELECT 목록 번호를 사용할 수 있지만 번호는 유지보수에 취약하다.

## 짧은 확인

`ORDER BY grade, points DESC`에서 grade가 다른 두 회원의 포인트를 먼저 비교할까?

<Collapse title="확인하기">

아니다. grade가 첫 정렬 키이므로 먼저 등급 순서를 정한다. points는 grade가 같은 회원 사이에서만 내림차순을 결정한다.

</Collapse>

<Callout type="default">

  - SELECT 별칭과 열 번호를 쓸 수 있지만 번호는 열 위치를 뜻한다.
