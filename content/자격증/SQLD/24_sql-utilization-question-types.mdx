## 유형 1. 서브쿼리 결과 — 단일행 vs 다중행

서브쿼리는 실행 결과에 따라 연산자를 구분합니다.

**핵심 구분**

| 서브쿼리 종류 | 반환 행 수 | 사용 가능 연산자 |
|--------------|-----------|-----------------|
| 단일행 서브쿼리 | 1행 | =, &gt;, &lt;, &gt;=, &lt;=, &lt;&gt; |
| 다중행 서브쿼리 | N행 | IN, ANY, ALL, EXISTS |
| 다중컬럼 서브쿼리 | N행, N컬럼 | IN과 함께 (컬럼, 컬럼) 형태 |

---

직원 테이블 데이터:

| 직원번호 | 부서코드 | 급여 |
|----------|----------|------|
| E001 | D01 | 3000000 |
| E002 | D01 | 4000000 |
| E003 | D02 | 2500000 |
| E004 | D02 | 3500000 |

쿼리:
```sql
SELECT 직원번호, 급여
FROM 직원
WHERE 급여 > (SELECT AVG(급여) FROM 직원);
```

## 유형 2. UNION vs UNION ALL — 결과 행 수 차이

**핵심 차이**

| 구분 | 중복 제거 | 정렬 | 속도 |
|------|----------|------|------|
| UNION | O (제거) | 내부 정렬 발생 | 느림 |
| UNION ALL | X (유지) | 정렬 없음 | 빠름 |
| INTERSECT | 교집합 | - | - |
| MINUS/EXCEPT | 차집합 | - | - |

## 유형 3. 윈도우 함수 — RANK vs DENSE_RANK vs ROW_NUMBER

**핵심 차이**

| 함수 | 동점 처리 | 다음 순위 |
|------|----------|----------|
| RANK() | 동점에 같은 순위 | 건너뜀 (1,1,3) |
| DENSE_RANK() | 동점에 같은 순위 | 건너뛰지 않음 (1,1,2) |
| ROW_NUMBER() | 동점도 다른 번호 | 연속 (1,2,3) |

---

성적 테이블 데이터:

| 학번 | 점수 |
|------|------|
| S001 | 95 |
| S002 | 88 |
| S003 | 95 |
| S004 | 80 |

쿼리:
```sql
SELECT 학번, 점수,
       RANK() OVER (ORDER BY 점수 DESC) AS R,
       DENSE_RANK() OVER (ORDER BY 점수 DESC) AS DR,
       ROW_NUMBER() OVER (ORDER BY 점수 DESC) AS RN
FROM 성적;
```

## 유형 4. ROLLUP/CUBE — 소계 행 수 계산

**ROLLUP 소계 행 수**: n개 컬럼 → n+1 레벨의 소계 생성

```sql
GROUP BY ROLLUP(A, B)
-- 생성: (A,B)별 합계 + A별 소계 + 전체 합계
```

**CUBE 소계 행 수**: 2^n 가지 조합

```sql
GROUP BY CUBE(A, B)
-- 생성: (A,B), A, B, 전체 = 4가지
```

---

판매 테이블: 지역(서울, 부산), 분기(1분기, 2분기), 각 조합당 1행 → 기본 4행 존재

쿼리:
```sql
SELECT 지역, 분기, SUM(매출)
FROM 판매
GROUP BY ROLLUP(지역, 분기);
```

## 유형 5. TCL — SAVEPOINT와 ROLLBACK TO

**TCL(Transaction Control Language) 명령어**

| 명령어 | 설명 |
|--------|------|
| COMMIT | 트랜잭션 확정, 영구 반영 |
| ROLLBACK | 트랜잭션 취소, COMMIT 이전 상태로 복원 |
| SAVEPOINT 이름 | 트랜잭션 내 중간 저장점 생성 |
| ROLLBACK TO 이름 | 해당 저장점까지만 취소 |

---

초기 상태: 직원 테이블에 급여 3000000인 E001 존재

트랜잭션:
```sql
UPDATE 직원 SET 급여 = 3500000 WHERE 직원번호 = 'E001';
SAVEPOINT SP1;
UPDATE 직원 SET 급여 = 4000000 WHERE 직원번호 = 'E001';
SAVEPOINT SP2;
UPDATE 직원 SET 급여 = 5000000 WHERE 직원번호 = 'E001';
ROLLBACK TO SP1;
COMMIT;
```

## 유형 6. DDL 특성 — TRUNCATE vs DELETE와 자동 COMMIT

| 속도 | 느림 | 빠름 | - |

## 유형 7. MERGE 문 — WHEN MATCHED / NOT MATCHED

MERGE는 SOURCE 테이블의 데이터를 TARGET 테이블에 "있으면 UPDATE, 없으면 INSERT"하는 문법입니다.

```sql
MERGE INTO TARGET T
USING SOURCE S ON (T.키 = S.키)
WHEN MATCHED THEN
    UPDATE SET T.컬럼 = S.컬럼
WHEN NOT MATCHED THEN
    INSERT (컬럼) VALUES (값);
```

---

TARGET(상품재고): P001-100, P002-30

SOURCE(입고내역): P001-50, P003-20

```sql
MERGE INTO 상품재고 T
USING 입고내역 S ON (T.상품코드 = S.상품코드)
WHEN MATCHED THEN
    UPDATE SET T.재고수량 = T.재고수량 + S.입고수량
WHEN NOT MATCHED THEN
    INSERT (상품코드, 재고수량) VALUES (S.상품코드, S.입고수량);
```
