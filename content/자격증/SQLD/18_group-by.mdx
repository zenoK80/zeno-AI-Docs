## 이번 편의 목표

- 집계함수와 GROUP BY의 역할을 구분한다.
- 그룹 기준값 하나당 결과 한 행이 만들어지는 과정을 설명한다.
- SELECT 목록에 그룹 열과 집계되지 않은 열을 섞을 때의 규칙을 적용한다.
- COUNT·SUM·AVG에서 NULL이 제외되는 방식을 예측한다.

## 먼저 알아둘 말

| 용어 | 쉬운 뜻 |
| --- | --- |
| 집계함수 | 여러 행을 세거나 합쳐 요약값 하나를 만드는 함수 |
| 그룹 | GROUP BY 기준값이 같은 행들의 묶음 |
| 그룹 열 | 어떤 기준으로 행을 묶을지 정한 열 |
| COUNT | 행 또는 NULL이 아닌 값을 세는 함수 |
| SUM | NULL이 아닌 숫자의 합계를 구하는 함수 |
| AVG | NULL이 아닌 숫자의 평균을 구하는 함수 |

## 선수지식과 핵심 질문

16편에서 SUM은 여러 입력 행을 한 요약값으로 만든다고 배웠다.

> 주문 5행을 회원별 주문 건수와 총액 3행으로 어떻게 줄일까?

## 입력 주문 데이터

| order_id | member_id | status | total_amount |
| ---: | --- | --- | ---: |
| 1001 | M01 | PAID | 106,000 |
| 1002 | M01 | SHIPPED | 30,000 |
| 1003 | M02 | PAID | 250,000 |
| 1004 | M03 | CANCELED | 70,000 |
| 1005 | M03 | PAID | 50,000 |

## GROUP BY가 없으면 전체가 한 그룹

```sql
SELECT COUNT(*) AS order_count,
       SUM(total_amount) AS total_sales,
       AVG(total_amount) AS avg_amount
FROM orders;
```

| order_count | total_sales | avg_amount |
| ---: | ---: | ---: |
| 5 | 506,000 | 101,200 |

다섯 행 전체를 한 그룹으로 보고 결과 한 행을 만들었다. 취소 주문도 WHERE로 제외하지 않았으므로 합계에 포함됐다.

## 회원번호로 그룹 만들기

```sql
SELECT member_id,
       COUNT(*) AS order_count,
       SUM(total_amount) AS total_amount
FROM orders
GROUP BY member_id;
```

먼저 입력 행이 세 묶음으로 나뉜다.

```text
M01 그룹: 1001(106000), 1002(30000)
M02 그룹: 1003(250000)
M03 그룹: 1004(70000), 1005(50000)
```

| member_id | order_count | total_amount |
| --- | ---: | ---: |
| M01 | 2 | 136,000 |
| M02 | 1 | 250,000 |
| M03 | 2 | 120,000 |

그룹 기준값 M01·M02·M03 하나당 결과 한 행이 만들어졌다.

## 여러 열로 그룹 만들기

```sql
SELECT member_id,
       status,
       COUNT(*) AS order_count
FROM orders
GROUP BY member_id, status;
```

| member_id | status | order_count |
| --- | --- | ---: |
| M01 | PAID | 1 |
| M01 | SHIPPED | 1 |
| M02 | PAID | 1 |
| M03 | CANCELED | 1 |
| M03 | PAID | 1 |

`member_id`만 같은 것이 아니라 `member_id + status` 조합이 같은 행끼리 묶는다.

## SELECT 목록의 규칙

다음 SQL은 일반적으로 오류다.

```sql
SELECT member_id, order_id, SUM(total_amount)
FROM orders
GROUP BY member_id;
```

M01 그룹에는 order_id가 1001과 1002 두 개다. DBMS는 결과 한 행에 어느 주문번호를 보여 줘야 할지 결정할 수 없다.

| SELECT 항목 | 허용 여부 | 이유 |
| --- | --- | --- |
| `member_id` | 허용 | GROUP BY 기준 열 |
| `SUM(total_amount)` | 허용 | 그룹을 하나의 값으로 요약 |
| `order_id` | 일반적으로 불가 | 그룹 안에 여러 값이 존재 |

그룹 쿼리의 SELECT에는 GROUP BY에 적은 열 또는 집계한 표현식을 둔다. DBMS별 함수 종속 확장 규칙은 다를 수 있으므로 시험에서는 기본 원칙을 따른다.

## WHERE는 그룹 전에 행을 거른다

취소 주문을 제외한 회원별 합계를 구해 보자.

```sql
SELECT member_id,
       SUM(total_amount) AS paid_total
FROM orders
WHERE status <> 'CANCELED'
GROUP BY member_id;
```

| member_id | paid_total |
| --- | ---: |
| M01 | 136,000 |
| M02 | 250,000 |
| M03 | 50,000 |

처리 흐름은 다음과 같다.

```text
FROM 5행
→ WHERE에서 취소 주문 1004 제거: 4행
→ member_id로 3그룹
→ SUM 계산: 결과 3행
```

## COUNT와 NULL

| order_id | coupon_code |
| ---: | --- |
| 1001 | NEW10 |
| 1002 | NULL |
| 1003 | VIP20 |
| 1004 | NULL |
| 1005 | NEW10 |

```sql
SELECT COUNT(*) AS all_orders,
       COUNT(coupon_code) AS coupon_orders,
       COUNT(DISTINCT coupon_code) AS coupon_types
FROM orders;
```

| all_orders | coupon_orders | coupon_types |
| ---: | ---: | ---: |
| 5 | 3 | 2 |

- `COUNT(*)`는 5행을 센다.
- `COUNT(coupon_code)`는 NULL이 아닌 3개 값을 센다.
- `COUNT(DISTINCT coupon_code)`는 NULL을 제외하고 NEW10·VIP20 두 종류를 센다.

## SUM과 AVG의 NULL

집계함수는 일반적으로 NULL을 제외한다. `(100, NULL, 300)`의 평균은 `(100+300)/2 = 200`이지 400/3이 아니다.

NULL을 0으로 포함하려면 업무상 그렇게 해석해도 되는지 확인한 뒤 `AVG(COALESCE(value, 0))`처럼 명시한다.

## GROUP BY의 NULL

GROUP BY 열의 NULL들은 하나의 그룹으로 묶인다.

| city | 회원 수 |
| --- | ---: |
| 서울 | 2 |
| 부산 | 1 |
| NULL | 2 |

NULL 값끼리 등호 비교는 UNKNOWN이지만 그룹화에서는 NULL들을 같은 그룹으로 취급한다는 차이를 기억한다.

## 흔한 실수와 진단법

| 실수 | 결과 | 확인 |
| --- | --- | --- |
| 그룹하지 않은 일반 열을 SELECT | 오류 또는 비결정적 의미 | 그룹당 값이 하나인가? |
| WHERE로 집계값 조건 작성 | 집계 전에는 값이 없음 | HAVING 사용 |
| COUNT(column)을 행 수로 봄 | NULL 행 누락 | 전체는 COUNT(*) |
| AVG에서 NULL을 0으로 계산 | 분모 예측 오류 | 실제 값 개수 확인 |

## 시험 연결

1. GROUP BY가 없고 집계함수만 있으면 전체 행이 한 그룹이다.
2. 그룹 기준값 조합 하나당 결과 한 행이 만들어진다.
3. WHERE는 그룹 전에 행을 필터링한다.
4. COUNT(*)와 COUNT(column), COUNT(DISTINCT column)의 NULL·중복 처리가 다르다.

## 짧은 확인

M01 주문이 PAID 2건, SHIPPED 1건이면 `GROUP BY member_id, status`에서 M01은 몇 행일까?

<Collapse title="확인하기">

2행이다. `(M01, PAID)` 그룹과 `(M01, SHIPPED)` 그룹이 각각 한 결과 행을 만든다. PAID 주문 두 건은 COUNT가 2인 한 행으로 요약된다.

</Collapse>

## 정리

<Callout type="default">
  - GROUP BY는 기준값이 같은 행을 묶고 그룹마다 결과 한 행을 만든다.
  - SELECT에는 그룹 열과 집계 결과를 둔다.
  - WHERE는 그룹을 만들기 전에 입력 행을 거른다.
  - 집계함수별 NULL·DISTINCT 처리 차이를 확인한다.
</Callout>
