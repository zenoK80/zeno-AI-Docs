## 연결 확인

### ping

ICMP 에코 요청으로 대상 호스트의 응답 여부를 확인합니다.

```bash
# 4번 ping 후 종료
ping -c 4 192.168.1.1

# 출력 예시
PING 192.168.1.1 (192.168.1.1) 56(84) bytes of data.
64 bytes from 192.168.1.1: icmp_seq=1 ttl=64 time=0.412 ms
64 bytes from 192.168.1.1: icmp_seq=2 ttl=64 time=0.398 ms
64 bytes from 192.168.1.1: icmp_seq=3 ttl=64 time=0.421 ms
64 bytes from 192.168.1.1: icmp_seq=4 ttl=64 time=0.409 ms

--- 192.168.1.1 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3059ms
rtt min/avg/max/mdev = 0.398/0.410/0.421/0.008 ms

# 패킷 크기 지정 (단편화 테스트)
ping -c 4 -s 1472 192.168.1.1

# 무한 ping (Ctrl+C로 중단)
ping 192.168.1.1
```

### traceroute / tracepath

목적지까지의 경로(홉)를 추적합니다.

```bash
# 경로 추적
traceroute google.com

# 출력 예시
traceroute to google.com (142.250.196.110), 30 hops max, 60 byte packets
 1  192.168.1.1 (192.168.1.1)   0.456 ms  0.423 ms  0.431 ms
 2  10.0.0.1 (10.0.0.1)         3.123 ms  3.098 ms  3.115 ms
 3  * * *                        (응답 없음, 방화벽 차단)
 4  142.250.196.110 (google.com) 12.456 ms 12.431 ms 12.445 ms

# UDP 대신 TCP 사용 (방화벽 우회)
traceroute -T -p 80 google.com
```

### mtr (My TraceRoute)

ping과 traceroute를 결합한 실시간 네트워크 경로 모니터링 도구입니다.

```bash
# 실시간 경로 모니터링
mtr google.com

# 100개 패킷 후 리포트 출력
mtr --report --report-cycles 100 google.com

# 출력 예시 (리포트 모드)
Start: 2026-08-23T10:00:00+0900
HOST: server                Loss%   Snt   Last   Avg  Best  Wrst StDev
  1.|-- 192.168.1.1          0.0%   100    0.4   0.4   0.3   0.8   0.1
  2.|-- 10.0.0.1             0.0%   100    3.1   3.2   2.9   4.1   0.2
  3.|-- 142.250.196.110      0.0%   100   12.4  12.5  12.1  13.2   0.3
```

## 포트와 소켓 확인

### ss (Socket Statistics)

현재 열려 있는 포트와 연결 상태를 확인합니다. (netstat의 현대적 대체)

```bash
# TCP/UDP 리스닝 포트 확인
ss -tuln

# 출력 예시
Netid  State   Recv-Q  Send-Q  Local Address:Port   Peer Address:Port
tcp    LISTEN  0       128     0.0.0.0:22            0.0.0.0:*
tcp    LISTEN  0       128     0.0.0.0:80            0.0.0.0:*
tcp    LISTEN  0       128     0.0.0.0:443           0.0.0.0:*
udp    UNCONN  0       0       0.0.0.0:53            0.0.0.0:*

# 프로세스 정보 포함 (루트 권한 필요)
ss -tulnp

# 출력 예시
Netid  State   Recv-Q  Send-Q  Local Address:Port  Peer Address:Port  Process
tcp    LISTEN  0       128     0.0.0.0:22            0.0.0.0:*        users:(("sshd",pid=1234,fd=3))
tcp    LISTEN  0       128     0.0.0.0:80            0.0.0.0:*        users:(("nginx",pid=5678,fd=6))

# 특정 포트 필터링
ss -tnp sport = :80

# 현재 TCP 연결 상태 확인
ss -tn state established
```

<Callout type="info">
  **옵션 기억법:** -t(TCP), -u(UDP), -l(LISTEN 포트만), -n(숫자로 표시, DNS 조회 안 함), -p(프로세스 정보)
</Callout>

## DNS 조회

### nslookup

```bash
# 도메인 A 레코드 조회
nslookup google.com

# 출력 예시
Server:         8.8.8.8
Address:        8.8.8.8#53

Non-authoritative answer:
Name:   google.com
Address: 142.250.196.110
```

### dig (Domain Information Groper)

더 상세한 DNS 정보를 조회하는 고급 도구입니다.

```bash
# A 레코드 조회
dig google.com A

# 출력 예시
; <<>> DiG 9.18.1 <<>> google.com A
;; QUESTION SECTION:
;google.com.                    IN      A

;; ANSWER SECTION:
google.com.             300     IN      A       142.250.196.110

;; Query time: 12 msec
;; SERVER: 8.8.8.8#53(8.8.8.8)

# MX 레코드 조회 (메일 서버)
dig google.com MX

# 역방향 조회 (IP → 도메인)
dig -x 142.250.196.110

# 특정 DNS 서버에 쿼리
dig @8.8.8.8 google.com A

# 짧은 출력
dig +short google.com A
# 출력: 142.250.196.110
```

### host

```bash
# 간단한 도메인 조회
host google.com

# 출력 예시
google.com has address 142.250.196.110
google.com mail is handled by 10 smtp.google.com.
```

## 패킷 캡처: tcpdump

네트워크 트래픽을 실시간으로 캡처하고 분석합니다.

```bash
# eth0 인터페이스에서 HTTP 트래픽 캡처
tcpdump -i eth0 port 80

# 출력 예시
10:00:01.123456 IP 192.168.1.100.54321 > 93.184.216.34.80: Flags [S], seq 1234567890
10:00:01.145678 IP 93.184.216.34.80 > 192.168.1.100.54321: Flags [S.], seq 987654321

# 특정 호스트와의 패킷만 캡처
tcpdump -i eth0 host 192.168.1.100

# 출발지 IP 필터
tcpdump -i eth0 src 192.168.1.100

# 목적지 IP 필터
tcpdump -i eth0 dst 8.8.8.8

# 파일로 저장 (-w: write)
tcpdump -i eth0 port 80 -w /tmp/capture.pcap

# 저장된 파일 읽기 (-r: read)
tcpdump -r /tmp/capture.pcap

# 패킷 내용을 ASCII로 출력 (-A)
tcpdump -i eth0 -A port 80

# 수집할 패킷 수 제한 (-c)
tcpdump -i eth0 -c 100 port 443
```

## 인터페이스와 ARP

```bash
# 인터페이스 정보 확인
ip addr show
ip link show

# 출력 예시
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP
    link/ether 00:11:22:33:44:55 brd ff:ff:ff:ff:ff:ff
    inet 192.168.1.100/24 brd 192.168.1.255 scope global eth0

# ARP 캐시 확인 (IP ↔ MAC 매핑)
ip neigh show

# 출력 예시
192.168.1.1 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
192.168.1.200 dev eth0 lladdr 11:22:33:44:55:66 STALE

# 구버전 명령 (참고)
arp -n
```

## 진단 흐름 정리

```bash
# 1단계: 로컬 네트워크 연결 확인
ping -c 4 192.168.1.1

# 2단계: 인터넷 연결 확인
ping -c 4 8.8.8.8

# 3단계: DNS 동작 확인
dig +short google.com

# 4단계: 경로 추적
traceroute google.com

# 5단계: 포트 리스닝 확인
ss -tulnp

# 6단계: 패킷 레벨 분석
tcpdump -i eth0 -c 50 port 80
```

## 핵심 정리

- ping -c 4: 4회 연결 테스트, traceroute: 경로 추적, mtr: 실시간 경로+손실률
- ss -tuln: TCP/UDP 리스닝 포트 확인, -p 추가 시 프로세스 정보 포함
- dig 도메인 A: A 레코드 조회, dig -x IP: 역방향 조회, dig @서버: 서버 지정
- tcpdump -i eth0 port 80: 실시간 캡처, -w 파일명: 저장, -r 파일명: 파일 읽기
- ip neigh show: ARP 캐시(IP-MAC 매핑) 확인
