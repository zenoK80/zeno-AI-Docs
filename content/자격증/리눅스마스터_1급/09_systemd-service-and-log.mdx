## systemd란?

systemd는 리눅스 시스템의 **PID 1** 프로세스로, 부팅 시 가장 먼저 실행되어 모든 프로세스를 관리하는 init 시스템입니다. 기존의 SysVinit 방식을 대체하며 **유닛**(Unit) 기반으로 서비스, 소켓, 타겟 등을 관리합니다.

### 주요 유닛 타입

| 유닛 타입 | 확장자 | 설명 |
|----------|--------|------|
| Service | .service | 데몬 프로세스 관리 |
| Socket | .socket | 소켓 기반 활성화 |
| Target | .target | 유닛 그룹(런레벨 대체) |
| Timer | .timer | 주기적 작업(cron 대체) |
| Mount | .mount | 파일시스템 마운트 |

## systemctl 명령어

systemctl은 systemd를 제어하는 핵심 명령어입니다.

### 서비스 상태 확인

```bash
# 서비스 상태 확인
systemctl status nginx

# 출력 예시
● nginx.service - A high performance web server and a reverse proxy server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled; vendor preset: enabled)
     Active: active (running) since Sat 2026-08-23 10:00:00 KST; 2h 30min ago
    Process: 1234 ExecStartPre=/usr/sbin/nginx -t (code=exited, status=0/SUCCESS)
   Main PID: 1235 (nginx)
      Tasks: 3 (limit: 4572)
     Memory: 8.2M

# 활성 여부만 확인
systemctl is-active nginx
# 출력: active

# 자동 시작 여부 확인
systemctl is-enabled nginx
# 출력: enabled
```

### 서비스 제어

```bash
# 서비스 시작
systemctl start nginx

# 서비스 중지
systemctl stop nginx

# 서비스 재시작 (중지 후 시작)
systemctl restart nginx

# 서비스 재로드 (설정 파일만 다시 읽기, 중단 없음)
systemctl reload nginx

# 부팅 시 자동 시작 등록
systemctl enable nginx

# 자동 시작 해제
systemctl disable nginx

# 즉시 시작 + 자동 시작 동시 설정
systemctl enable --now nginx
```

### 유닛 목록 조회

```bash
# 실행 중인 서비스 목록
systemctl list-units --type=service

# 출력 예시
  UNIT                     LOAD   ACTIVE SUB     DESCRIPTION
  cron.service             loaded active running Regular background program processing daemon
  nginx.service            loaded active running A high performance web server
  ssh.service              loaded active running OpenBSD Secure Shell server
  systemd-journald.service loaded active running Journal Service

# 실패한 유닛 확인
systemctl list-units --state=failed
```

## 런레벨과 systemd 타겟

SysVinit의 런레벨은 systemd에서 **타겟**(target) 으로 대체됩니다.

| SysVinit 런레벨 | systemd 타겟 | 설명 |
|---------------|-------------|------|
| 0 | poweroff.target | 시스템 종료 |
| 1 | rescue.target | 단일 사용자 모드 |
| 2, 3, 4 | multi-user.target | 다중 사용자, CLI |
| 5 | graphical.target | 다중 사용자, GUI |
| 6 | reboot.target | 재부팅 |

### 타겟 관리 명령어

```bash
# 현재 기본 타겟 확인
systemctl get-default
# 출력: graphical.target

# 기본 타겟 변경 (CLI 모드로 부팅)
systemctl set-default multi-user.target

# 현재 세션만 특정 타겟으로 전환 (재부팅 없이)
systemctl isolate rescue.target
```

## journalctl 로그 조회

systemd는 **journald** 데몬으로 로그를 중앙 관리합니다. journalctl로 이 로그를 조회합니다.

### 기본 조회

```bash
# 전체 로그 조회 (최신 로그가 아래)
journalctl

# 최신 로그 50줄 조회
journalctl -n 50

# 실시간 로그 모니터링
journalctl -f

# 특정 서비스 로그
journalctl -u nginx

# 출력 예시
Aug 23 10:00:01 server nginx[1235]: 2026/08/23 10:00:01 [notice] 1235#1235: signal process started
Aug 23 10:00:01 server nginx[1235]: 2026/08/23 10:00:01 [notice] 1235#1235: reload config
```

### 시간 기반 필터링

```bash
# 1시간 전부터 nginx 로그 조회
journalctl -u nginx --since "1 hour ago"

# 특정 시간 범위
journalctl --since "2026-08-23 09:00:00" --until "2026-08-23 10:00:00"

# 오늘 로그
journalctl --since today

# 어제 로그
journalctl --since yesterday --until today
```

### 우선순위 필터링

```bash
# 에러 이상 로그만 조회 (-p 0~7, 0=emerg, 3=err, 6=info, 7=debug)
journalctl -p err

# 커널 로그만 조회
journalctl -k

# 출력 예시 (에러 로그)
Aug 23 09:15:23 server kernel: EXT4-fs error (device sdb1): ext4_validate_block_bitmap
Aug 23 09:30:11 server nginx[1235]: connect() failed (111: Connection refused)
```

## /var/log/ 전통 로그 파일

journald 외에도 파일 기반 로그가 병행 사용됩니다.

| 로그 파일 | 배포판 | 내용 |
|----------|--------|------|
| /var/log/syslog | Debian/Ubuntu | 일반 시스템 로그 |
| /var/log/messages | RHEL/CentOS | 일반 시스템 로그 |
| /var/log/auth.log | Debian/Ubuntu | 인증 및 권한 로그 |
| /var/log/secure | RHEL/CentOS | 인증 및 권한 로그 |
| /var/log/kern.log | 공통 | 커널 로그 |
| /var/log/dmesg | 공통 | 부팅 시 커널 메시지 |

```bash
# 인증 실패 로그 확인
tail -f /var/log/auth.log

# 출력 예시
Aug 23 10:45:12 server sshd[2341]: Failed password for root from 192.168.1.100 port 54321 ssh2
Aug 23 10:45:15 server sshd[2341]: Failed password for root from 192.168.1.100 port 54322 ssh2
```

## 실전 활용 예시

```bash
# nginx 서비스 상태 점검 및 로그 확인 흐름
systemctl status nginx
journalctl -u nginx --since "1 hour ago" -p err

# 부팅 시 실패한 서비스 원인 파악
systemctl list-units --state=failed
journalctl -u 실패한서비스명 -n 100

# 시스템 전체 에러 로그 실시간 모니터링
journalctl -f -p err
```

## 핵심 정리

- systemd는 PID 1로 유닛 기반으로 시스템을 관리하며, 기존 init 시스템을 대체합니다
- systemctl start/stop/restart/reload 로 서비스를 제어하고, enable/disable 로 부팅 자동 시작을 설정합니다
- 런레벨 대신 타겟을 사용: 3=multi-user.target(CLI), 5=graphical.target(GUI)
- journalctl -u 서비스명 으로 서비스별 로그를, --since/--until 로 시간 범위를, -p err 로 에러만 필터링합니다
- /var/log/auth.log(Ubuntu) 또는 /var/log/secure(RHEL)에서 인증 관련 로그를 확인합니다
