## 프로세스란?

프로세스(Process)는 메모리에 올라가 실행 중인 프로그램이다. 각 프로세스는 고유한 PID(Process ID)를 가지며, 부모 프로세스의 PID인 PPID도 있다.

- 모든 프로세스의 최초 조상: **PID 1** (init 또는 systemd)
- 프로세스는 `fork()`로 복제되어 `exec()`로 새 프로그램을 실행

## ps - 프로세스 상태 확인

```bash
# BSD 스타일: 모든 프로세스 상세 출력 (가장 많이 사용)
ps aux
# 출력 예시
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1  22356 11440 ?        Ss   Jan13   0:05 /sbin/init
root       234  0.0  0.2  15632  9876 ?        Ss   Jan13   0:01 sshd
zenok     1234  0.1  0.3  25678 15432 pts/0    Ss   09:30   0:00 bash
zenok     5678  0.0  0.1   6432  3456 pts/0    R+   10:00   0:00 ps aux
```

`ps aux` 출력 필드:

| 필드 | 의미 |
|------|------|
| USER | 프로세스 소유자 |
| PID | 프로세스 ID |
| %CPU | CPU 사용률 |
| %MEM | 메모리 사용률 |
| VSZ | 가상 메모리 크기(KB) |
| RSS | 실제 사용 메모리(KB) |
| TTY | 터미널 (`?`는 터미널 없음) |
| STAT | 프로세스 상태 코드 |
| START | 시작 시간 |
| TIME | 누적 CPU 시간 |
| COMMAND | 실행 명령어 |

```bash
# UNIX 스타일: 부모-자식 관계 포함 모든 프로세스
ps -ef
# 출력 예시
UID        PID  PPID  C STIME TTY          TIME CMD
root         1     0  0 Jan13 ?        00:00:05 /sbin/init
root       234     1  0 Jan13 ?        00:00:01 sshd: /usr/sbin/sshd
root      1100   234  0 09:30 ?        00:00:00 sshd: zenok [priv]
zenok     1234  1100  0 09:30 pts/0    00:00:00 -bash

# 특정 프로세스 검색
ps aux | grep nginx
# 출력 예시
www-data  2345  0.0  0.2  ... nginx: worker process
root      2344  0.0  0.1  ... nginx: master process
zenok     5679  0.0  0.0  ... grep --color=auto nginx
```

## 프로세스 상태 코드(STAT)

| 코드 | 이름 | 의미 |
|------|------|------|
| `R` | Running | 실행 중이거나 실행 대기 중 |
| `S` | Sleeping | 인터럽트 가능한 수면 상태 (이벤트 대기) |
| `D` | Uninterruptible sleep | 인터럽트 불가 수면 (I/O 대기). 강제 종료 불가 |
| `Z` | Zombie | 종료됐으나 부모가 wait() 하지 않은 상태 |
| `T` | Stopped | 시그널에 의해 정지됨 (Ctrl+Z) |

추가 플래그:

| 플래그 | 의미 |
|--------|------|
| `s` | 세션 리더 |
| `+` | 포그라운드 프로세스 그룹 |
| `<` | 높은 우선순위 |
| `N` | 낮은 우선순위 |

## top - 실시간 프로세스 모니터링

```bash
top
# 출력 예시
top - 10:30:15 up 2 days,  3:45,  2 users,  load average: 0.08, 0.05, 0.03
Tasks: 156 total,   1 running, 155 sleeping,   0 stopped,   0 zombie
%Cpu(s):  1.3 us,  0.7 sy,  0.0 ni, 97.7 id,  0.3 wa,  0.0 hi,  0.0 si
MiB Mem :  15956.4 total,   8234.5 free,   4523.8 used,   3198.1 buff/cache
MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.  11007.8 avail Mem

  PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
 1234 www-data  20   0  132456  23456  12345 S   2.3   0.1   0:05.23 nginx
 5678 zenok     20   0   25432  15432   8765 S   0.3   0.1   0:00.12 bash
```

`top` 주요 단축키:

| 키 | 동작 |
|----|------|
| `q` | 종료 |
| `k` | 프로세스 종료 (PID 입력) |
| `r` | 우선순위(nice) 변경 |
| `M` | 메모리 사용량 순 정렬 |
| `P` | CPU 사용량 순 정렬 |
| `1` | CPU 코어별 사용률 표시 |

```bash
# pstree: 프로세스 트리 형태로 표시
pstree
# 출력 예시
systemd─┬─ModemManager───2*[{ModemManager}]
        ├─NetworkManager───2*[{NetworkManager}]
        ├─sshd───sshd───sshd───bash───pstree
        └─systemd-journal
```

## 포그라운드/백그라운드 작업 제어

```bash
# 백그라운드에서 실행 (&)
sleep 100 &
# 출력 예시
[1] 6789
# [작업번호] PID

# 백그라운드 작업 목록 확인
jobs
# 출력 예시
[1]+  Running    sleep 100 &
[2]-  Stopped    vim notes.txt

# 백그라운드 작업을 포그라운드로 가져오기
fg %1
# [1] 번 작업을 포그라운드로

# 포그라운드 작업을 백그라운드로 보내기 (먼저 Ctrl+Z로 중지)
# Ctrl+Z 입력
# 출력 예시
[1]+  Stopped    sleep 100

# 중지된 작업을 백그라운드에서 재시작
bg %1
# 출력 예시
[1]+ sleep 100 &

# 실행 중인 프로세스를 백그라운드로 전환
# 1. Ctrl+Z → 프로세스 일시 정지
# 2. bg %번호 → 백그라운드에서 재실행
```

| 명령 | 설명 |
|------|------|
| `명령 &` | 처음부터 백그라운드 실행 |
| `jobs` | 백그라운드 작업 목록 |
| `fg %n` | n번 작업을 포그라운드로 |
| `bg %n` | n번 작업을 백그라운드로 재시작 |
| `Ctrl+Z` | 현재 포그라운드 작업 일시 정지 |
| `Ctrl+C` | 현재 포그라운드 작업 종료 |

## 시그널(Signal)과 kill

시그널은 프로세스 간 통신의 비동기 알림이다. `kill` 명령은 이름과 달리 프로세스에 시그널을 보내는 명령이다.

### 주요 시그널 번호

| 번호 | 이름 | 설명 | 처리 |
|------|------|------|------|
| 1 | SIGHUP | Hang Up. 터미널 연결 끊김 또는 **설정 재읽기** | 재시작 |
| 2 | SIGINT | Interrupt. **Ctrl+C** | 종료 |
| 9 | SIGKILL | **강제 종료**. 무시 불가, 블록 불가 | 강제 종료 |
| 15 | SIGTERM | **정상 종료** 요청. kill 기본값. 프로세스가 무시할 수 있음 | 정상 종료 |
| 18 | SIGCONT | 정지된 프로세스 재개 | 재개 |
| 19 | SIGSTOP | 프로세스 정지. 무시 불가 | 정지 |
| 20 | SIGTSTP | **Ctrl+Z** | 정지 |

```bash
# kill: PID로 시그널 전송 (기본: SIGTERM = -15)
kill 1234

# 강제 종료 (SIGKILL)
kill -9 1234
kill -SIGKILL 1234

# 정상 종료 요청 (SIGTERM, 기본값)
kill -15 1234

# 설정 재읽기 (데몬 재시작 없이 설정 반영)
kill -1 1234
kill -HUP 1234

# 모든 시그널 목록
kill -l
# 출력 예시 (일부)
 1) SIGHUP    2) SIGINT    3) SIGQUIT   4) SIGILL    5) SIGTRAP
 6) SIGABRT   7) SIGBUS    8) SIGFPE    9) SIGKILL  10) SIGUSR1
11) SIGSEGV  12) SIGUSR2  13) SIGPIPE  14) SIGALRM  15) SIGTERM
```

```bash
# killall: 프로세스명으로 시그널 전송 (동일한 이름의 모든 프로세스)
killall nginx
killall -9 httpd

# pkill: 패턴으로 프로세스 검색하여 종료
pkill nginx
pkill -9 -f "python script.py"

# pgrep: 프로세스 검색 (PID만 반환)
pgrep nginx
# 출력 예시
2344
2345
```

## nice / renice - 프로세스 우선순위

**nice 값**(NI): 프로세스 우선순위를 조정하는 값. **-20(최고 우선순위) ~ 19**(최저 우선순위)

<Callout type="info">
  nice 값이 **낮을수록** 더 많은 CPU 시간을 받는다 (우선순위가 높다). 헷갈리지 않도록 주의: nice 값 -20 = 우선순위 최고, nice 값 19 = 우선순위 최저
</Callout>

```bash
# nice 값 지정하여 프로세스 시작 (기본값 0)
nice -n 10 backup.sh
# CPU 자원을 적게 받도록 시작 (우선순위 낮춤)

nice -n -5 important.sh
# 우선순위 높여서 시작 (root 권한 필요, 음수 지정 시)

# 실행 중인 프로세스의 nice 값 변경
renice -n 15 -p 1234
# PID 1234의 nice값을 15로 변경 (우선순위 낮춤)
# 출력 예시
1234 (process ID) old priority 0, new priority 15

# 특정 사용자의 모든 프로세스 nice 값 변경
renice -n 5 -u zenok

# top에서 PR(Priority)과 NI(Nice) 열 확인
top
# 출력 예시 (일부)
  PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM
 1234 zenok     20   0  ...   S   0.0   0.1       bash
 5678 root      15  -5  ...   S   0.0   0.1       important
 9012 zenok     35  15  ...   S   0.0   0.0       backup
```

| 명령 | 설명 |
|------|------|
| `nice -n N 명령` | nice 값 N으로 새 프로세스 시작 |
| `renice -n N -p PID` | 실행 중 프로세스 nice 값 변경 |
| `renice -n N -u user` | 사용자의 모든 프로세스 변경 |

## 좀비(Zombie) 프로세스

```bash
# 좀비 프로세스 확인
ps aux | grep Z
# 출력 예시
user      1234  0.0  0.0      0     0 ?        Z    10:00   0:00 [defunct]

# 좀비 프로세스는 직접 kill로 종료 불가
# 부모 프로세스를 종료하거나, SIGCHLD 시그널로 해결
kill -SIGCHLD 부모PID
```

좀비 프로세스: 실행이 끝났지만 부모 프로세스가 `wait()` 시스템 콜로 종료 상태를 수집하지 않아 프로세스 테이블에 남아 있는 상태. PID를 점유하지만 실제 리소스는 소모하지 않는다.

## 핵심 정리

- `ps aux`: 모든 프로세스 (BSD), `ps -ef`: 부모-자식 관계 포함
- 프로세스 상태: R(실행), S(수면), D(I/O 대기), Z(좀비), T(정지)
- `Ctrl+Z`: 일시 정지, `jobs`: 목록, `fg/bg %번호`: 전환
- SIGHUP(1): 설정 재읽기, SIGINT(2): Ctrl+C, SIGKILL(9): 강제, SIGTERM(15): 정상 종료
- `killall 프로세스명`: 이름으로 종료, `pkill 패턴`: 패턴으로 종료
- nice 값: -20(최고 우선순위) ~ 19(최저 우선순위). 낮을수록 CPU를 더 받음
- `renice -n N -p PID`: 실행 중 프로세스 우선순위 변경
