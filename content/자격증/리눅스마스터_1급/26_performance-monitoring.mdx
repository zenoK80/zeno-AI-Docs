## CPU 성능 분석

### top - 실시간 프로세스 모니터링

```bash
# top 실행
top

# 1초 간격 갱신, 배치 모드(스크립트에서 활용)
top -d 1
top -b -n 3    # 비대화형(-b), 3번 출력 후 종료(-n 3)
```

**top 헤더 읽기:**

```
top - 14:32:01 up 5 days, 3:21,  2 users,  load average: 1.24, 0.87, 0.65
Tasks: 215 total,   1 running, 214 sleeping,   0 stopped,   0 zombie
%Cpu(s):  23.5 us,  4.2 sy,  0.0 ni, 70.1 id,  1.8 wa,  0.0 hi,  0.4 si,  0.0 st
MiB Mem :  15823.6 total,   2341.2 free,   8942.1 used,   4540.3 buff/cache
MiB Swap:   4096.0 total,   4096.0 free,      0.0 used.   6312.4 avail Mem
```

| 항목 | 설명 |
|------|------|
| `us` | 사용자 공간 CPU 사용률 |
| `sy` | 커널(시스템) CPU 사용률 |
| `id` | 유휴(idle) CPU - 낮을수록 CPU 부하 높음 |
| `wa` | I/O 대기 - 높으면 디스크 병목 의심 |
| `si` | 소프트웨어 인터럽트 |

**top 인터랙티브 키:**

| 키 | 동작 |
|----|------|
| `1` | CPU 코어별 사용률 표시 |
| `M` | 메모리 사용량 순 정렬 |
| `P` | CPU 사용률 순 정렬 |
| `k` | 프로세스 종료 (PID 입력) |
| `q` | 종료 |

### htop - 개선된 대화형 모니터링

```bash
# htop 실행 (설치 필요: dnf install htop)
htop

# 특정 사용자의 프로세스만 표시
htop -u nginx
```

htop은 컬러 막대 그래프로 CPU·메모리를 시각적으로 보여주며 마우스 조작도 지원합니다.

### mpstat - CPU 코어별 통계

```bash
# 모든 CPU 코어의 1초 간격 통계 (sysstat 패키지 필요)
mpstat -P ALL 1

# 5회 측정
mpstat -P ALL 1 5
```

출력 예시:

```
09:00:01 AM  CPU    %usr   %sys  %iowait  %idle
09:00:02 AM  all   25.4    3.2     1.1    70.3
09:00:02 AM    0   48.5    5.1     0.5    45.9
09:00:02 AM    1    2.3    1.3     1.7    94.7
```

코어 0만 과부하이고 코어 1이 여유 있다면 **단일 스레드 프로그램이 병목**일 가능성이 높습니다.

### sar - 시스템 활동 보고서

```bash
# CPU 사용률 1초 간격 5회 측정
sar -u 1 5

# 모든 통계 출력
sar -A

# 특정 날짜의 기록 데이터 조회 (/var/log/sa/ 에 저장됨)
sar -u -f /var/log/sa/sa15    # 이달 15일 데이터
```

### uptime - 로드 애버리지 확인

```bash
uptime
# 출력: 14:32:01 up 5 days, 3:21,  2 users,  load average: 1.24, 0.87, 0.65
```

**로드 애버리지 해석:**

- 세 숫자는 각각 **1분, 5분, 15분** 평균 실행 대기 프로세스 수입니다.
- **CPU 코어 수 = 부하 한계**: 4코어 시스템에서 로드 4.0이면 100% 사용 중
- **코어 수 초과 시 과부하**: 4코어에서 로드 8.0이면 200% 과부하
- 1분 > 15분이면 부하가 증가 중, 1분 < 15분이면 부하가 줄어드는 중

```bash
# CPU 코어 수 확인
nproc
grep -c processor /proc/cpuinfo
```

<Callout type="warning">
  **시험 포인트:** 로드 애버리지가 CPU 코어 수를 지속적으로 초과하면 과부하 상태입니다. 예: 2코어 시스템에서 load average가 4.0이면 프로세스가 CPU를 기다리며 대기하고 있습니다.
</Callout>

## 메모리 성능 분석

### free - 메모리 사용량 개요

```bash
# 사람이 읽기 쉬운 단위로 출력
free -h

# MB 단위
free -m

# 1초 간격 3회 반복
free -h -s 1 -c 3
```

출력 예시:

```
              total        used        free      shared  buff/cache   available
Mem:           15Gi        8.7Gi       2.2Gi       512Mi       4.4Gi       6.1Gi
Swap:         4.0Gi          0B       4.0Gi
```

| 항목 | 설명 |
|------|------|
| `total` | 전체 물리 메모리 |
| `used` | 실제 사용 중인 메모리 |
| `free` | 완전히 비어 있는 메모리 |
| `buff/cache` | 버퍼·캐시로 사용 중 (필요 시 반환 가능) |
| `available` | 실제로 새 프로세스가 사용 가능한 메모리 |

<Callout type="info">
  **중요:** `free`가 작아도 `available`이 충분하면 메모리 부족이 아닙니다. Linux는 남는 메모리를 디스크 캐시로 활용하므로 `free`가 항상 작습니다.
</Callout>

### vmstat - 가상 메모리 통계

```bash
# 1초 간격 5회 측정
vmstat 1 5
```

출력 예시:

```
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 2  0      0 2287944  98312 4529124    0    0     5    12  142  287 23  4 72  1  0
```

| 항목 | 설명 |
|------|------|
| `r` | 실행 대기 중인 프로세스 수 (CPU 코어 수 초과 시 병목) |
| `b` | I/O 대기로 블록된 프로세스 수 |
| `si/so` | 스왑 in/out (0이 아니면 메모리 부족) |
| `wa` | CPU I/O 대기 비율 |

### /proc/meminfo - 상세 메모리 정보

```bash
cat /proc/meminfo

# 주요 항목만 확인
grep -E 'MemTotal|MemFree|MemAvailable|SwapTotal|SwapFree' /proc/meminfo
```

### 스왑 관리

```bash
# 스왑 사용 현황
swapon -s
swapon --show    # 현대적 문법

# 스왑 비활성화 (메모리 여유 있을 때)
swapoff -a

# 스왑 재활성화
swapon -a

# 스왑 파일 생성 및 활성화
dd if=/dev/zero of=/swapfile bs=1M count=2048
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
```

<Callout type="warning">
  **스왑 경보:** vmstat에서 `si`(swap in) 또는 `so`(swap out)이 지속적으로 0이 아니면 메모리가 부족하여 스왑을 사용하고 있는 것입니다. 이는 성능 저하의 주요 원인입니다.
</Callout>

## 디스크 I/O 분석

### iostat - 디스크 I/O 통계

```bash
# 확장 통계 (-x), 1초 간격 반복
iostat -x 1

# 특정 횟수만 측정
iostat -x 1 5

# 특정 디바이스만
iostat -x sda 1 5
```

주요 출력 필드:

| 필드 | 설명 |
|------|------|
| `%util` | 디스크 사용률 - **100%에 가까우면 I/O 병목** |
| `await` | 평균 I/O 대기 시간 (ms) - 낮을수록 좋음 |
| `r/s`, `w/s` | 초당 읽기/쓰기 요청 수 |
| `rkB/s`, `wkB/s` | 초당 읽기/쓰기 처리량 (KB) |
| `svctm` | 평균 I/O 서비스 시간 (ms) |

### iotop - 프로세스별 I/O 사용량

```bash
# 실시간 I/O 사용 프로세스 (root 권한 필요)
iotop

# 실제 I/O 발생 프로세스만 표시
iotop -o
```

### 디스크 용량 확인

```bash
# 파일 시스템별 사용량
df -h

# 특정 경로의 파일 시스템 정보
df -h /var

# 아이노드(inode) 사용량 (inode 고갈도 df -h에서는 안 보임)
df -i

# 디렉토리별 사용량 (대용량 소비 경로 찾기)
du -sh /*
du -sh /var/*

# 상위 10개 대용량 디렉토리 찾기
du -sh /* 2>/dev/null | sort -rh | head -10
```

<Callout type="info">
  **inode 고갈 주의:** 디스크 용량이 남아 있어도 inode가 고갈되면 파일을 생성할 수 없습니다. 소형 파일이 수백만 개 있는 경우 `df -i`로 inode 사용률을 반드시 확인하세요.
</Callout>

## 네트워크 성능 분석

### sar -n DEV - 네트워크 인터페이스 통계

```bash
# 네트워크 인터페이스별 1초 간격 측정
sar -n DEV 1 5

# TCP 소켓 통계
sar -n TCP 1 5
```

### nethogs - 프로세스별 네트워크 사용량

```bash
# 설치: dnf install nethogs
# 어떤 프로세스가 대역폭을 소비하는지 확인
nethogs eth0
```

### iftop - 연결별 네트워크 대역폭

```bash
# 설치: dnf install iftop
# 인터페이스별 송수신 대역폭 실시간 확인
iftop -i eth0
```

### nload - 네트워크 트래픽 그래프

```bash
# 설치: dnf install nload
nload eth0
```

## sar 종합 활용

`sar`(System Activity Reporter)는 가장 강력한 종합 성능 분석 도구입니다.

```bash
# sysstat 서비스 활성화 (자동 수집 설정)
systemctl enable sysstat
systemctl start sysstat

# /var/log/sa/ 에 일별 데이터 저장됨
ls /var/log/sa/

# CPU 사용률 과거 데이터 조회
sar -u -f /var/log/sa/sa20    # 이달 20일

# 메모리 통계
sar -r 1 5

# 디스크 I/O
sar -d 1 5

# 네트워크
sar -n DEV 1 5

# 모든 통계 출력
sar -A
```

## dstat - 종합 통계 도구

```bash
# 설치: dnf install dstat
# CPU, 메모리, 디스크, 네트워크를 한 화면에
dstat

# 1초 간격, 10회
dstat 1 10

# 특정 항목만 (cpu + memory + disk + net)
dstat -cdmn

# 프로세스 정보 포함
dstat --top-cpu --top-mem --top-io
```

## 성능 분석 체계적 접근법

병목(bottleneck)을 찾을 때는 **CPU → 메모리 → 디스크 → 네트워크** 순으로 분석합니다.

```bash
# 1단계: CPU 확인
uptime                    # 로드 애버리지 확인
top                       # CPU 사용률 높은 프로세스 파악
mpstat -P ALL 1 3         # 코어별 사용률

# 2단계: 메모리 확인
free -h                   # 메모리/스왑 사용량
vmstat 1 5                # si/so(스왑 I/O) 확인

# 3단계: 디스크 I/O 확인
iostat -x 1 5             # %util, await 확인
iotop -o                  # I/O 유발 프로세스

# 4단계: 네트워크 확인
sar -n DEV 1 5            # 대역폭 사용량
ss -s                     # 소켓 통계 요약
```

| 증상 | 의심 원인 | 확인 명령 |
|------|---------|---------|
| 로드 애버리지 높음 + CPU idle 낮음 | CPU 병목 | `top`, `mpstat` |
| 로드 애버리지 높음 + wa 높음 | 디스크 병목 | `iostat -x`, `iotop` |
| si/so 지속 발생 | 메모리 부족 | `free -h`, `vmstat` |
| 네트워크 응답 느림 | 대역폭 포화 | `sar -n DEV`, `iftop` |

## 핵심 정리

- **uptime 로드 애버리지:** 1분/5분/15분, CPU 코어 수 초과 = 과부하
- **top %wa:** I/O 대기 - 높으면 디스크 병목
- **free -h available:** 실제 사용 가능 메모리 (buff/cache는 반환 가능)
- **vmstat si/so:** 0이 아니면 스왑 사용 중 → 메모리 부족
- **iostat %util:** 100% 근접 = 디스크 I/O 포화
- **sar:** /var/log/sa/에 기록, 과거 데이터 분석 가능
- **dstat:** CPU·메모리·디스크·네트워크 종합 통계
- **분석 순서:** CPU → 메모리 → 디스크 → 네트워크
