## 시나리오 1: 공격 IP 탐지 및 차단

**상황:** SSH 브루트포스 공격이 의심되어 공격 IP를 파악하고 즉시 차단해야 한다.

### 공격 IP 탐지

```bash
# /var/log/secure에서 실패한 패스워드 시도 IP 추출
grep "Failed password" /var/log/secure | awk '{print $11}' | sort | uniq -c | sort -rn | head -20
```

출력 예시:

```
    523 192.168.1.105
    312 10.0.0.55
     87 203.0.113.42
      3 192.168.100.10
```

523회 시도한 `192.168.1.105`가 가장 의심스럽습니다.

```bash
# 최근 1시간 이내 공격 IP 확인
grep "Failed password" /var/log/secure | awk '{print $1,$2,$3,$11}' | \
  grep "$(date +'%b %d')" | awk '{print $4}' | sort | uniq -c | sort -rn

# 공격 IP의 실제 시도 로그 확인
grep "192.168.1.105" /var/log/secure | tail -20

# 현재 SSH 연결 확인
ss -antp | grep :22
```

### 공격 IP 차단

```bash
# firewalld로 특정 IP 영구 차단 (drop: 패킷 응답 없이 버림)
firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.1.105" drop' --permanent
firewall-cmd --reload

# 여러 IP 동시 차단
for ip in 192.168.1.105 10.0.0.55; do
    firewall-cmd --add-rich-rule="rule family=\"ipv4\" source address=\"$ip\" drop" --permanent
done
firewall-cmd --reload

# 등록된 rich rule 확인
firewall-cmd --list-rich-rules

# iptables로 차단 (firewalld 미사용 환경)
iptables -I INPUT -s 192.168.1.105 -j DROP
iptables -I INPUT -s 10.0.0.55 -j DROP

# /etc/hosts.deny 에 추가 (TCP Wrapper)
echo "sshd: 192.168.1.105" >> /etc/hosts.deny
```

### fail2ban으로 자동 차단

```bash
# fail2ban 설치 및 설정
dnf install fail2ban -y

# /etc/fail2ban/jail.local 설정
cat > /etc/fail2ban/jail.local << 'EOF'
[sshd]
enabled = true
port = ssh
filter = sshd
logpath = /var/log/secure
maxretry = 5
bantime = 3600
findtime = 600
EOF

systemctl enable fail2ban
systemctl start fail2ban

# 차단된 IP 목록 확인
fail2ban-client status sshd
```

<Callout type="info">
  **drop vs reject 차이:**
  - `DROP`: 패킷을 조용히 버림. 공격자가 서버 존재를 모름 (선호)
  - `REJECT`: 거부 응답을 전송. 공격자가 서버 존재를 알 수 있음
</Callout>

## 시나리오 2: SSL/TLS 인증서 적용

**상황:** HTTP만 지원하던 웹 서버에 HTTPS를 적용하고 HTTP를 443으로 리다이렉트해야 한다.

### 자체 서명 인증서 생성 (테스트용)

```bash
# RSA 2048비트 키와 365일 유효 자체 서명 인증서 생성
openssl req -x509 -nodes -days 365 \
    -newkey rsa:2048 \
    -keyout /etc/pki/tls/private/server.key \
    -out /etc/pki/tls/certs/server.crt

# 인증서 정보 확인
openssl x509 -in /etc/pki/tls/certs/server.crt -text -noout | grep -E "Subject:|Not After"
```

옵션 설명:
- `-x509`: 자체 서명 인증서 생성 (CSR 없이)
- `-nodes`: 개인키에 암호 설정 안 함 (No DES)
- `-newkey rsa:2048`: 2048비트 RSA 키 생성
- `-keyout`: 개인키 저장 경로
- `-out`: 인증서 저장 경로

### Apache SSL 설정

```bash
# mod_ssl 설치
dnf install mod_ssl -y

# /etc/httpd/conf.d/ssl.conf 수정
cat > /etc/httpd/conf.d/ssl.conf << 'EOF'
<VirtualHost *:443>
    ServerName www.example.com
    DocumentRoot /var/www/html

    SSLEngine on
    SSLCertificateFile /etc/pki/tls/certs/server.crt
    SSLCertificateKeyFile /etc/pki/tls/private/server.key

    # 강력한 암호화 설정
    SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1
    SSLCipherSuite HIGH:!aNULL:!MD5
</VirtualHost>
EOF

# HTTP → HTTPS 리다이렉트 (/etc/httpd/conf/httpd.conf 또는 가상호스트)
cat >> /etc/httpd/conf/httpd.conf << 'EOF'
<VirtualHost *:80>
    ServerName www.example.com
    Redirect permanent / https://www.example.com/
</VirtualHost>
EOF

# 방화벽에 443 포트 허용
firewall-cmd --add-service=https --permanent
firewall-cmd --reload

# 설정 검사 및 재시작
apachectl configtest
systemctl restart httpd
```

### 인증서 유효성 확인

```bash
# 원격에서 인증서 정보 확인
openssl s_client -connect www.example.com:443 -showcerts 2>/dev/null | \
    openssl x509 -noout -dates

# curl로 HTTPS 접속 테스트
curl -v -k https://www.example.com
```

## 시나리오 3: SSH 터널로 내부 서비스 접근

**상황:** 직접 접근할 수 없는 내부 네트워크의 웹 서버에 SSH 점프 서버를 통해 접근해야 한다.

### 로컬 포트 포워딩 (Local Forward)

```bash
# 형식: ssh -L 로컬포트:목적지호스트:목적지포트 점프서버
# 내 로컬 8080 → 점프서버를 통해 → 내부웹서버:80
ssh -L 8080:내부웹서버:80 user@점프서버

# 백그라운드 실행 (-f: 백그라운드, -N: 명령 실행 없이 터널만)
ssh -f -N -L 8080:내부웹서버:80 user@점프서버

# 이후 로컬 브라우저에서 http://localhost:8080 으로 내부 웹 서버 접근
```

### 원격 포트 포워딩 (Remote Forward)

```bash
# 형식: ssh -R 원격포트:로컬호스트:로컬포트 원격서버
# 점프서버의 9090 포트 → 내 로컬 3000 포트로 연결
ssh -R 9090:localhost:3000 user@점프서버

# 점프서버에서 localhost:9090 으로 내 로컬 3000에 접근 가능
```

### 동적 포트 포워딩 (SOCKS 프록시)

```bash
# SOCKS5 프록시 생성 (로컬 1080 포트)
ssh -D 1080 user@점프서버

# 브라우저 SOCKS5 프록시를 localhost:1080으로 설정하면
# 점프서버 네트워크를 통해 내부 서비스 전체에 접근 가능
```

<Callout type="info">
  **SSH 터널 용어 정리:**
  - **-L **(Local): 로컬 포트 → 원격 서버를 통해 → 목적지
  - **-R **(Remote): 원격 서버의 포트 → 원격 서버를 통해 → 로컬
  - **-D **(Dynamic): SOCKS 프록시로 동적 포워딩
  - **-N**: 원격 명령 실행 없이 포워딩만 (터널 전용)
  - **-f**: 백그라운드로 SSH 실행
</Callout>

## 시나리오 4: 침해 사고 대응

**상황:** 서버가 해킹됐다는 의심이 들어 초동 대응과 증거 수집을 해야 한다.

### Step 1: 네트워크 연결 상태 확인

```bash
# 현재 모든 연결 (의심 외부 연결 확인)
ss -antp

# ESTABLISHED 연결만 확인
ss -antp state established

# netstat으로 확인 (구형 시스템)
netstat -antp | grep ESTABLISHED
```

의심 IP로의 연결이 있으면 해당 프로세스 PID를 기록합니다.

### Step 2: 프로세스 트리 확인

```bash
# 전체 프로세스 트리 (부모-자식 관계)
ps auxf

# 특정 PID의 상세 정보
ls -la /proc/<PID>/exe    # 실행 파일 경로
ls -la /proc/<PID>/fd/    # 열린 파일 목록
cat /proc/<PID>/cmdline   # 실행 명령 전체

# 비정상적인 이름의 프로세스 찾기
ps aux | grep -v '\[' | awk '{print $11}' | sort -u
```

### Step 3: 최근 변경된 파일 확인

```bash
# 최근 24시간 내에 수정된 파일 (시스템 파일 포함)
find / -mtime -1 -type f 2>/dev/null | grep -v /proc | grep -v /sys

# /etc, /bin, /usr 등 중요 경로만 확인
find /etc /bin /usr/bin /usr/local -mtime -1 -ls 2>/dev/null

# SUID/SGID 파일 목록 (권한 상승 악성 코드 탐지)
find / -perm /4000 -o -perm /2000 2>/dev/null | grep -v proc

# 최근 생성된 파일
find /tmp /var/tmp /dev/shm -type f -ls 2>/dev/null
```

### Step 4: 접근 기록 확인

```bash
# 성공한 로그인 기록 (/var/log/wtmp)
last | head -30

# 실패한 로그인 기록 (/var/log/btmp)
lastb | head -30

# 현재 로그인된 사용자
who
w

# su/sudo 사용 기록
grep -E 'su:|sudo:' /var/log/secure | tail -30
```

### Step 5: 감사 로그 확인 (auditd)

```bash
# 인증 실패 이벤트
ausearch -m USER_AUTH_FAIL -ts recent

# 파일 접근 감사 (특정 파일 설정 필요)
ausearch -f /etc/passwd -ts today

# 실행 파일 감사
ausearch -m EXECVE -ts recent | head -50

# 전체 최근 이벤트
aureport --summary
aureport -l -ts today    # 오늘 로그인 이벤트
```

### Step 6: 크론탭 및 지속성 확인

```bash
# 모든 사용자의 crontab 확인
for user in $(cut -f1 -d: /etc/passwd); do
    echo "=== $user ==="; crontab -u $user -l 2>/dev/null
done

# 시스템 cron 디렉토리 확인
ls -la /etc/cron.* /var/spool/cron/

# systemd 타이머 확인
systemctl list-timers

# /etc/rc.local, ~/.bashrc 등 자동 실행 확인
cat /etc/rc.local
ls -la /etc/profile.d/
```

<Callout type="warning">
  **침해 사고 대응 원칙:**
  1. **증거 보존 우선:** 재부팅이나 서비스 재시작 전에 메모리 덤프, 로그, 프로세스 목록을 저장하세요.
  2. **네트워크 격리:** 추가 피해 방지를 위해 의심 서버를 네트워크에서 분리하는 것을 고려합니다.
  3. **기록 유지:** 모든 조사 명령과 결과를 타임스탬프와 함께 기록합니다.
</Callout>

## 시나리오 5: SYN 플러드(Flood) 방어

**상황:** SYN 플러드 DDoS 공격을 받아 서버 접속이 불가능한 상황이다.

### SYN 플러드 탐지

```bash
# SYN_RECV 상태 연결 수 확인 (비정상적으로 많으면 SYN 플러드 의심)
ss -s

# SYN_RECV 상태 연결 상세 확인
ss -antp state syn-recv | wc -l
ss -antp state syn-recv | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head

# netstat으로 확인
netstat -n | awk '{print $6}' | sort | uniq -c | sort -rn
```

### iptables로 SYN 플러드 방어

```bash
# SYN 패킷 속도 제한 (1초에 최대 1개, 버스트 3개 허용)
iptables -A INPUT -p tcp --syn -m limit --limit 1/s --limit-burst 3 -j ACCEPT
# 제한 초과 SYN 패킷 차단
iptables -A INPUT -p tcp --syn -j DROP

# 연결 추적을 이용한 새 연결 제한
iptables -A INPUT -p tcp --dport 80 -m state --state NEW \
    -m limit --limit 20/minute --limit-burst 50 -j ACCEPT
iptables -A INPUT -p tcp --dport 80 -m state --state NEW -j DROP

# 특정 IP의 연결 수 제한
iptables -A INPUT -p tcp --syn --dport 80 \
    -m connlimit --connlimit-above 50 -j DROP
```

### 커널 파라미터로 SYN 쿠키 활성화

```bash
# SYN 쿠키 활성화 (즉시 적용)
echo 1 > /proc/sys/net/ipv4/tcp_syncookies

# 영구 적용 (/etc/sysctl.conf)
cat >> /etc/sysctl.conf << 'EOF'
# SYN Flood 방어
net.ipv4.tcp_syncookies = 1
net.ipv4.tcp_syn_retries = 2
net.ipv4.tcp_synack_retries = 2
net.ipv4.tcp_max_syn_backlog = 4096
EOF

sysctl -p    # 즉시 적용
```

<Callout type="info">
  **SYN 쿠키(SYN Cookie) 원리:**
  서버가 SYN-ACK 응답 시 연결 상태를 저장하지 않고 쿠키(암호화된 시퀀스 번호)를 보냅니다. 정상 클라이언트만 ACK에 올바른 쿠키를 포함해 응답할 수 있어 SYN 플러드를 방어합니다.
</Callout>

### firewalld로 연결 제한

```bash
# 특정 포트에 IP당 연결 수 제한
firewall-cmd --add-rich-rule='rule service name="http" limit value="20/m" accept' --permanent
firewall-cmd --reload

# IP당 SSH 연결 제한 (1분에 3번)
firewall-cmd --add-rich-rule='rule service name="ssh" limit value="3/m" accept' --permanent
```

## 핵심 정리

- **공격 IP 탐지:** `grep "Failed password" /var/log/secure | awk '{print $11}' | sort | uniq -c | sort -rn`
- **firewall-cmd 차단:** `--add-rich-rule='rule family="ipv4" source address="IP" drop'`
- **SSL 인증서:** `openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout key -out crt`
- **SSH 로컬 터널:** `ssh -L 로컬포트:목적지:목적지포트 점프서버`
- **침해 사고:** ss -antp → ps auxf → find -mtime -1 → last/lastb → ausearch
- **SYN 플러드 방어:** `iptables --syn -m limit --limit 1/s` + `tcp_syncookies = 1`
- **DROP vs REJECT:** DROP은 응답 없이 버림(공격자에게 서버 존재 노출 안 됨)
