## LVM 개요

**LVM**(Logical Volume Manager) 은 물리 디스크를 추상화하여 크기를 동적으로 조절할 수 있는 논리 볼륨을 제공하는 기술입니다.

### LVM의 3단계 구조

```
물리 디스크 → 물리 볼륨(PV) → 볼륨 그룹(VG) → 논리 볼륨(LV)
/dev/sdb         pvcreate          vgcreate           lvcreate
/dev/sdc    ───────────────────────────────────────────────────→ /dev/vg0/lv_data
```

| 계층 | 이름 | 설명 |
|------|------|------|
| 물리 볼륨 (PV) | Physical Volume | 실제 디스크 파티션을 LVM에 등록 |
| 볼륨 그룹 (VG) | Volume Group | 여러 PV를 묶어 하나의 스토리지 풀로 구성 |
| 논리 볼륨 (LV) | Logical Volume | VG에서 원하는 크기만큼 할당받은 가상 파티션 |

## LVM 구성 5단계

### 1단계: 물리 볼륨(PV) 생성

```bash
# 디스크 파티션을 PV로 초기화
pvcreate /dev/sdb /dev/sdc

# 출력 예시
  Physical volume "/dev/sdb" successfully created.
  Physical volume "/dev/sdc" successfully created.
```

### 2단계: 볼륨 그룹(VG) 생성

```bash
# sdb와 sdc를 묶어 vg0 볼륨 그룹 생성
vgcreate vg0 /dev/sdb /dev/sdc

# 출력 예시
  Volume group "vg0" successfully created
```

### 3단계: 논리 볼륨(LV) 생성

```bash
# vg0에서 10GB 크기의 lv_data 논리 볼륨 생성
lvcreate -L 10G -n lv_data vg0

# 출력 예시
  Logical volume "lv_data" created.

# 생성된 LV 경로: /dev/vg0/lv_data 또는 /dev/mapper/vg0-lv_data
```

### 4단계: 파일시스템 생성

```bash
# 논리 볼륨에 ext4 파일시스템 생성
mkfs.ext4 /dev/vg0/lv_data

# 출력 예시
mke2fs 1.46.5 (30-Dec-2021)
Creating filesystem with 2621440 4k blocks and 655360 inodes
```

### 5단계: 마운트

```bash
# 마운트 포인트 생성 및 마운트
mkdir -p /mnt/data
mount /dev/vg0/lv_data /mnt/data

# /etc/fstab에 영구 등록
echo '/dev/vg0/lv_data  /mnt/data  ext4  defaults  0  2' >> /etc/fstab
```

## LVM 확장

LVM의 가장 큰 장점은 서비스 중단 없이 볼륨 크기를 확장할 수 있다는 점입니다.

```bash
# 논리 볼륨을 5GB 더 확장
lvextend -L +5G /dev/vg0/lv_data

# 출력 예시
  Size of logical volume vg0/lv_data changed from 10.00 GiB (2560 extents) to 15.00 GiB (3840 extents).
  Logical volume vg0/lv_data successfully resized.

# ext4 파일시스템 크기 조정 (마운트 상태에서 가능)
resize2fs /dev/vg0/lv_data

# xfs의 경우
xfs_growfs /mnt/data
```

<Callout type="warning">
  VG에 여유 공간이 없으면 lvextend가 실패합니다. 이 경우 새 디스크를 PV로 만들어 VG에 추가(vgextend)해야 합니다.
</Callout>

## LVM 확인 명령어

```bash
# 물리 볼륨 요약 정보
pvs

# 출력 예시
  PV         VG   Fmt  Attr PSize   PFree
  /dev/sdb   vg0  lvm2 a--  <50.00g 40.00g
  /dev/sdc   vg0  lvm2 a--  <50.00g     0

# 볼륨 그룹 요약 정보
vgs

# 출력 예시
  VG   #PV #LV #SN Attr   VSize    VFree
  vg0    2   1   0 wz--n- <100.00g 40.00g

# 논리 볼륨 요약 정보
lvs

# 출력 예시
  LV      VG   Attr       LSize  Pool Origin Data%
  lv_data vg0  -wi-ao---- 15.00g

# 상세 정보
pvdisplay /dev/sdb
vgdisplay vg0
lvdisplay /dev/vg0/lv_data
```

## RAID 개요

**RAID**(Redundant Array of Independent Disks) 는 여러 디스크를 묶어 성능 향상 또는 데이터 안정성(중복성)을 제공하는 기술입니다.

### RAID 레벨 비교

| RAID 레벨 | 방식 | 최소 디스크 | 특징 | 장점 | 단점 |
|----------|------|-----------|------|------|------|
| RAID 0 | 스트라이핑 | 2개 | 데이터를 분산 저장 | 빠른 읽기/쓰기 | 1개 고장 시 전체 손실 |
| RAID 1 | 미러링 | 2개 | 동일 데이터 2벌 저장 | 1개 고장 시 복구 가능 | 디스크 효율 50% |
| RAID 5 | 스트라이핑+패리티 | 3개 | 패리티 1벌 분산 | 1개 고장 시 복구 가능 | 쓰기 속도 저하 |
| RAID 6 | 스트라이핑+패리티×2 | 4개 | 패리티 2벌 분산 | 2개 동시 고장 복구 | 더 느린 쓰기 |
| RAID 10 | 미러링+스트라이핑 | 4개 | RAID 1+0 결합 | 성능+안정성 모두 | 디스크 효율 50% |

<Callout type="info">
  **시험 핵심:** RAID 5는 최소 3개 디스크, RAID 6은 최소 4개 디스크가 필요합니다. RAID 5는 1개까지, RAID 6은 2개까지 동시 고장을 허용합니다.
</Callout>

## mdadm으로 소프트웨어 RAID 구성

리눅스에서는 **mdadm** 으로 소프트웨어 RAID를 구성합니다.

```bash
# RAID 5 생성 (3개 디스크 사용)
mdadm --create /dev/md0 --level=5 --raid-devices=3 /dev/sdb /dev/sdc /dev/sdd

# 출력 예시
mdadm: Defaulting to version 1.2 metadata
mdadm: array /dev/md0 started.

# RAID 상태 확인
cat /proc/mdstat

# 출력 예시
Personalities : [raid5]
md0 : active raid5 sdd[2] sdc[1] sdb[0]
      209584128 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/3] [UUU]

# 상세 정보 확인
mdadm --detail /dev/md0

# 출력 예시 (일부)
/dev/md0:
        Version : 1.2
  Creation Time : Sat Aug 23 10:00:00 2026
     Raid Level : raid5
     Array Size : 209584128 (199.88 GiB 214.61 GB)
  Used Dev Size : 104792064 (99.94 GiB 107.31 GB)
   Raid Devices : 3
  Total Devices : 3
    Array State : clean

# RAID 파일시스템 생성 및 마운트
mkfs.ext4 /dev/md0
mkdir -p /mnt/raid
mount /dev/md0 /mnt/raid
```

## 핵심 정리

- LVM 3단계: 물리 볼륨(PV) → 볼륨 그룹(VG) → 논리 볼륨(LV)
- LVM 구성: pvcreate → vgcreate → lvcreate -L -n → mkfs.ext4 → mount
- LVM 확장: lvextend -L +5G 후 resize2fs(ext4) 또는 xfs_growfs(xfs)
- 확인 명령: pvs, vgs, lvs (요약) / pvdisplay, vgdisplay, lvdisplay (상세)
- RAID 0: 스트라이핑(빠름, 무결성 없음), RAID 1: 미러링(50% 효율), RAID 5: 최소 3개+패리티 1, RAID 6: 최소 4개+패리티 2, RAID 10: 최소 4개(성능+안정성)
