## 서비스 중인 데이터 영역의 용량을 늘리고 싶은 상황

리눅스 문제는 명령 하나를 외우는 것보다 **대상, 현재 상태, 바꿀 결과**를 순서대로 보는 편이 안전합니다. 이 상황에서 먼저 확인할 것은 무엇이 문제인지, 어떤 권한과 서비스가 관여하는지입니다.

| 확인 순서 | 질문 | 이 문서에서 보는 것 |
| --- | --- | --- |
| 1 | 대상은 무엇인가? | 파일, 계정, 서비스, 네트워크 중 대상을 고릅니다. |
| 2 | 현재 상태는 어떤가? | 명령 결과와 로그를 먼저 확인합니다. |
| 3 | 무엇을 바꿀까? | 필요한 설정만 최소 범위로 바꿉니다. |

## 핵심 뜻

LVM은 물리 볼륨을 묶어 논리 볼륨을 유연하게 관리합니다. RAID는 여러 디스크로 성능 또는 장애 대응을 높이는 방식입니다.

여기서 중요한 것은 **명령의 이름**보다 실행 뒤에 무엇이 바뀌는지입니다. 명령은 상태를 확인하는 명령과 실제로 변경하는 명령으로 나누어 기억하면 실수가 줄어듭니다.

## 직접 확인해 봅니다

```bash
pvs
vgs
lvs
lvextend -L +10G /dev/vgdata/lvapp
```

위 예시는 시험에서 자주 나오는 기본 흐름입니다. 실습 환경에서는 먼저 읽기 전용 확인 명령을 실행하고, 그 다음에 변경 명령을 실행하세요. 변경 전후 결과를 비교하면 옵션의 의미가 더 잘 남습니다.

<Callout type="warning">
  **헷갈리기 쉬운 점:** RAID가 백업을 완전히 대신한다고 생각하는 실수입니다. 운영 환경에서는 명령을 실행하기 전에 대상 경로·서비스 이름·권한 범위를 한 번 더 확인하세요.
</Callout>

## 시험에서는 이렇게 판단합니다

- 보기에 나온 명령이 **조회**인지 **변경**인지 먼저 구분합니다.
- 경로나 옵션이 하나라도 다르면 결과가 달라질 수 있으므로 끝까지 읽습니다.
- 권한·보안 문제는 "무엇을 허용하고 무엇을 막는가"로 설명합니다.
- 서술형은 명령만 적지 말고 실행 목적과 기대 결과를 한 문장으로 붙입니다.

## 핵심 정리

- LVM은 물리 볼륨을 묶어 논리 볼륨을 유연하게 관리합니다. RAID는 여러 디스크로 성능 또는 장애 대응을 높이는 방식입니다.
- 상태 확인 후 필요한 변경만 적용합니다.
- RAID가 백업을 완전히 대신한다고 생각하는 실수을 피하고, 결과로 다시 검증합니다.
