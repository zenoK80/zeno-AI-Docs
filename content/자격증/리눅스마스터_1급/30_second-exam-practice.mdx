## 단답형 문제 (각 5점)

### 단답 1

**fdisk로 `/dev/sdb`에 파티션을 생성한 후 ext4 파일 시스템으로 포맷하는 명령은?**

<details>
<summary>모범 답안 보기</summary>

```bash
mkfs.ext4 /dev/sdb1
```

또는

```bash
mkfs -t ext4 /dev/sdb1
```

**채점 포인트:**
- `mkfs.ext4` 또는 `mkfs -t ext4` 정확히 작성 (1점)
- 장치 경로 `/dev/sdb1` 포함 (파티션 번호 포함) (2점)

**관련 지식:**
```bash
# fdisk로 파티션 생성 절차
fdisk /dev/sdb
# 대화형으로 n(new) → p(primary) → 1 → Enter → Enter → w(write)

# ext4 포맷
mkfs.ext4 /dev/sdb1

# 파일 시스템 유형 확인
blkid /dev/sdb1
file -s /dev/sdb1
```
</details>

### 단답 2

**NFS 클라이언트에서 NFS 서버(192.168.1.10)의 공유 목록을 확인하는 명령은?**

<details>
<summary>모범 답안 보기</summary>

```bash
showmount -e 192.168.1.10
```

**채점 포인트:**
- `showmount` 명령 작성 (2점)
- `-e` 옵션 (exports 목록) 작성 (2점)
- 서버 IP 또는 호스트명 포함 (1점)

**관련 지식:**
```bash
# NFS 서버 공유 목록 확인
showmount -e 192.168.1.10
# 출력 예시:
# Export list for 192.168.1.10:
# /data    192.168.1.0/24
# /backup  *

# NFS 마운트
mount -t nfs 192.168.1.10:/data /mnt/nfs

# /etc/fstab에 영구 등록
# 192.168.1.10:/data  /mnt/nfs  nfs  defaults,_netdev  0  0
```
</details>

### 단답 3

**systemd에서 기본 부팅 타겟을 `multi-user.target`으로 영구 설정하는 명령은?**

<details>
<summary>모범 답안 보기</summary>

```bash
systemctl set-default multi-user.target
```

**채점 포인트:**
- `systemctl set-default` 작성 (3점)
- `multi-user.target` 정확히 작성 (2점)

**관련 지식:**
```bash
# 현재 기본 타겟 확인
systemctl get-default

# 기본 타겟 변경 (영구)
systemctl set-default multi-user.target    # CLI 모드 (구: runlevel 3)
systemctl set-default graphical.target     # GUI 모드 (구: runlevel 5)

# 현재 세션만 일시 변경 (재부팅 시 원래대로)
systemctl isolate multi-user.target

# 심볼릭 링크로 직접 설정
ln -sf /lib/systemd/system/multi-user.target /etc/systemd/system/default.target
```
</details>

### 단답 4

**SELinux 컨텍스트를 기본값(정책 기본값)으로 복원하는 명령은?**

<details>
<summary>모범 답안 보기</summary>

```bash
restorecon -Rv /경로
```

또는 특정 파일:

```bash
restorecon -v /var/www/html/index.html
```

**채점 포인트:**
- `restorecon` 명령 작성 (3점)
- `-R`(재귀) 또는 `-v`(상세) 옵션 또는 경로 포함 (2점)

**관련 지식:**
```bash
# 파일 SELinux 컨텍스트 확인
ls -Z /var/www/html/

# 컨텍스트 수동 변경
chcon -t httpd_sys_content_t /var/www/html/index.html

# 정책 기본값으로 복원
restorecon -Rv /var/www/html/

# 전체 시스템 재레이블링 (부팅 시)
touch /.autorelabel
reboot
```
</details>

### 단답 5

**GRUB2 설정 파일(`/etc/default/grub`)을 수정한 후 변경 사항을 `/boot/grub2/grub.cfg`에 반영하는 명령은?**

<details>
<summary>모범 답안 보기</summary>

```bash
grub2-mkconfig -o /boot/grub2/grub.cfg
```

UEFI 시스템의 경우:

```bash
grub2-mkconfig -o /boot/efi/EFI/centos/grub.cfg
```

**채점 포인트:**
- `grub2-mkconfig` 명령 작성 (3점)
- `-o /boot/grub2/grub.cfg` 출력 경로 지정 (2점)

**관련 지식:**
```bash
# GRUB2 설정 편집
vi /etc/default/grub
# GRUB_TIMEOUT=5
# GRUB_CMDLINE_LINUX="..."

# 설정 반영
grub2-mkconfig -o /boot/grub2/grub.cfg

# 현재 부팅 항목 확인
grep menuentry /boot/grub2/grub.cfg

# 부팅 순서 변경
grub2-set-default 0    # 첫 번째 항목을 기본으로
```
</details>

## 서술형 문제 (각 15점)

### 서술 1

**`/dev/sdb`에 LVM을 이용하여 10GB 논리 볼륨을 생성하고 `/data`에 xfs 파일 시스템으로 마운트하는 전체 과정을 명령어와 함께 설명하시오.**

<details>
<summary>모범 답안 보기</summary>

**LVM 구성 3단계: 물리 볼륨(PV) → 볼륨 그룹(VG) → 논리 볼륨(LV)**

**1단계: 물리 볼륨(PV) 생성**

```bash
# /dev/sdb를 LVM 물리 볼륨으로 초기화
pvcreate /dev/sdb

# 확인
pvdisplay /dev/sdb
pvs
```

**2단계: 볼륨 그룹(VG) 생성**

```bash
# vg_data라는 이름의 볼륨 그룹 생성
vgcreate vg_data /dev/sdb

# 확인
vgdisplay vg_data
vgs
```

**3단계: 논리 볼륨(LV) 생성**

```bash
# 10GB 논리 볼륨 lv_data 생성
lvcreate -L 10G -n lv_data vg_data

# 확인
lvdisplay /dev/vg_data/lv_data
lvs
```

**4단계: 파일 시스템 생성**

```bash
# xfs 파일 시스템으로 포맷
mkfs.xfs /dev/vg_data/lv_data
```

**5단계: 마운트**

```bash
# 마운트 포인트 생성
mkdir -p /data

# 임시 마운트
mount /dev/vg_data/lv_data /data

# 마운트 확인
df -h /data
```

**6단계: 영구 마운트 설정 (/etc/fstab)**

```bash
# /etc/fstab에 추가 (편집기로 또는 명령으로)
echo "/dev/vg_data/lv_data  /data  xfs  defaults  0  0" >> /etc/fstab

# 또는 UUID로 (더 안전)
blkid /dev/vg_data/lv_data
# UUID=xxxxxxxx-xxxx-xxxx  /data  xfs  defaults  0  0

# fstab 오류 확인
mount -a
```

**채점 포인트 (15점):**
- PV 생성 (`pvcreate`) (3점)
- VG 생성 (`vgcreate`) (3점)
- LV 생성 (`lvcreate -L 10G -n`) (3점)
- 파일 시스템 생성 (`mkfs.xfs`) (2점)
- 마운트 포인트 생성 및 마운트 (2점)
- /etc/fstab 영구 등록 (2점)
</details>

### 서술 2

**SSH 키 기반 인증을 설정하는 전체 과정을 설명하시오. 클라이언트에서 키 생성, 서버에 공개키 등록, 서버 설정 확인을 포함하시오.**

<details>
<summary>모범 답안 보기</summary>

**클라이언트 측 작업**

**1단계: SSH 키 쌍 생성**

```bash
# RSA 4096비트 키 생성 (-t: 알고리즘, -b: 비트수, -C: 코멘트)
ssh-keygen -t rsa -b 4096 -C "user@client.example.com"
# 기본 저장 위치: ~/.ssh/id_rsa (개인키), ~/.ssh/id_rsa.pub (공개키)

# 또는 Ed25519 알고리즘 (최신 권장)
ssh-keygen -t ed25519 -C "user@client.example.com"
```

**2단계: 공개키를 서버에 복사**

```bash
# 방법 1: ssh-copy-id 사용 (가장 간단)
ssh-copy-id -i ~/.ssh/id_rsa.pub user@서버IP
# 서버의 ~/.ssh/authorized_keys에 자동 추가

# 방법 2: 수동 복사
cat ~/.ssh/id_rsa.pub | ssh user@서버IP \
    "mkdir -p ~/.ssh && chmod 700 ~/.ssh && \
     cat >> ~/.ssh/authorized_keys && \
     chmod 600 ~/.ssh/authorized_keys"
```

**서버 측 작업**

**3단계: authorized_keys 권한 확인**

```bash
# 서버에서 권한 확인
ls -la ~/.ssh/
# drwx------ 2 user user 4096 ...  .ssh/         (700)
# -rw------- 1 user user  572 ...  authorized_keys (600)

# 권한 수정 (중요: 권한이 틀리면 키 인증이 동작하지 않음)
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

**4단계: sshd 설정 확인**

```bash
# /etc/ssh/sshd_config 주요 항목 확인
grep -E 'PubkeyAuthentication|AuthorizedKeysFile|PasswordAuthentication' /etc/ssh/sshd_config

# 키 기반 인증 활성화 설정
PubkeyAuthentication yes
AuthorizedKeysFile  .ssh/authorized_keys

# (선택) 패스워드 인증 비활성화 (키만 허용)
PasswordAuthentication no

# 설정 적용
systemctl reload sshd
```

**5단계: 키 기반 접속 테스트**

```bash
# 클라이언트에서 접속 테스트
ssh -i ~/.ssh/id_rsa user@서버IP

# 상세 디버그 정보 확인
ssh -vvv user@서버IP
```

**채점 포인트 (15점):**
- `ssh-keygen`으로 키 쌍 생성 (3점)
- 공개키를 서버 `~/.ssh/authorized_keys`에 등록 (4점)
- `.ssh` 디렉토리와 `authorized_keys` 파일 권한 (700, 600) (3점)
- `/etc/ssh/sshd_config`의 `PubkeyAuthentication yes` 확인 (3점)
- 서비스 리로드 및 테스트 (2점)
</details>

### 서술 3

**cron을 이용하여 매주 일요일 오전 2시에 `/home` 디렉토리를 `/backup`으로 rsync 백업하는 방법을 설명하시오. 실제 crontab 항목을 포함하여 작성하시오.**

<details>
<summary>모범 답안 보기</summary>

**1단계: 백업 디렉토리 생성**

```bash
mkdir -p /backup
```

**2단계: rsync 백업 스크립트 작성 (선택적이지만 권장)**

```bash
cat > /usr/local/bin/backup-home.sh << 'EOF'
#!/bin/bash
# /home 백업 스크립트

BACKUP_DIR="/backup"
SOURCE_DIR="/home"
LOG_FILE="/var/log/backup-home.log"
DATE=$(date +%Y%m%d_%H%M%S)

echo "[$DATE] 백업 시작" >> $LOG_FILE

rsync -avz --delete \
    --log-file=$LOG_FILE \
    $SOURCE_DIR/ $BACKUP_DIR/

echo "[$(date +%Y%m%d_%H%M%S)] 백업 완료" >> $LOG_FILE
EOF

chmod +x /usr/local/bin/backup-home.sh
```

**3단계: crontab 설정**

```bash
# root의 crontab 편집
crontab -e

# 또는 /etc/cron.d/ 에 파일 생성
```

**crontab 항목:**

```
# 매주 일요일(0) 오전 2시(2)에 /home을 /backup으로 rsync 백업
0 2 * * 0 rsync -avz --delete /home/ /backup/ >> /var/log/backup-home.log 2>&1
```

스크립트를 사용하는 경우:

```
0 2 * * 0 /usr/local/bin/backup-home.sh
```

**crontab 필드 설명:**

```
0   2   *   *   0   rsync ...
분  시  일  월  요일(0=일요일)
```

**4단계: 설정 확인**

```bash
# 현재 root crontab 확인
crontab -l

# /etc/cron.d/ 방식으로 저장 시 확인
cat /etc/cron.d/backup-home

# cron 서비스 실행 확인
systemctl status crond

# 첫 실행 전 수동 테스트
rsync -avz --delete --dry-run /home/ /backup/
```

**5단계: 로그 확인 (실행 후)**

```bash
# cron 실행 기록 확인
grep CRON /var/log/cron | grep backup

# 백업 로그 확인
tail -f /var/log/backup-home.log

# 백업 결과 확인
ls -lh /backup/
du -sh /backup/
```

**채점 포인트 (15점):**
- crontab 형식 및 필드 의미 설명 (3점)
- 올바른 시간 설정 `0 2 * * 0` (5점: 각 필드 1점)
- rsync 명령 및 주요 옵션 (`-avz --delete`) (4점)
- 원본(`/home/`)과 대상(`/backup/`) 경로 (2점)
- 로그 파일 리다이렉션 또는 cron 확인 방법 (1점)
</details>
