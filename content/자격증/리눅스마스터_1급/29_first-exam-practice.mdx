### 문제 1

**chmod 754 파일명** 명령을 실행했을 때 설정되는 권한으로 올바른 것은?

1. 소유자: rwx, 그룹: r-x, 기타: r--
2. 소유자: rwx, 그룹: r--, 기타: r-x
3. 소유자: r-x, 그룹: rwx, 기타: r--
4. 소유자: rwx, 그룹: r-x, 기타: ---

<details>
<summary>정답 및 해설 보기</summary>

**정답: 1번**

8진수 권한 표기법에서 각 자리는 순서대로 소유자(user), 그룹(group), 기타(others)입니다.

| 숫자 | 2진수 | 권한 |
|------|-------|------|
| 7 | 111 | rwx |
| 5 | 101 | r-x |
| 4 | 100 | r-- |

따라서 754 = 소유자(7=rwx), 그룹(5=r-x), 기타(4=r--) 입니다.

```bash
# 확인
chmod 754 파일명
ls -l 파일명
# -rwxr-xr-- 1 user group ...
```

2번 오류: 그룹과 기타 순서가 뒤바뀜
3번 오류: 소유자와 그룹 순서가 뒤바뀜
4번 오류: 기타 권한이 ---이 되려면 4가 아닌 0이어야 함
</details>

### 문제 2

**/etc/fstab**의 각 필드 순서로 올바른 것은?

1. 장치명 - 마운트포인트 - 파일시스템 - 옵션 - dump - pass
2. 마운트포인트 - 장치명 - 파일시스템 - pass - dump - 옵션
3. 파일시스템 - 장치명 - 마운트포인트 - 옵션 - dump - pass
4. 장치명 - 파일시스템 - 마운트포인트 - 옵션 - dump - pass

<details>
<summary>정답 및 해설 보기</summary>

**정답: 1번**

/etc/fstab의 6개 필드 순서:

```
장치명(또는UUID)  마운트포인트  파일시스템  옵션  dump  pass
/dev/sda1        /            xfs         defaults  0   1
/dev/sda2        /home        ext4        defaults  0   2
UUID=xxxx        /data        xfs         defaults  0   2
tmpfs            /tmp         tmpfs       defaults  0   0
```

| 필드 | 설명 |
|------|------|
| 장치명 | /dev/sdXN, UUID=..., LABEL=... |
| 마운트포인트 | /, /home, /data 등 |
| 파일시스템 | xfs, ext4, tmpfs, nfs 등 |
| 옵션 | defaults, ro, noexec, _netdev 등 |
| dump | 0(덤프 안 함), 1(덤프) |
| pass | 0(검사 안 함), 1(/루트 먼저), 2(이후 검사) |
</details>

### 문제 3

**crontab 항목 `0 3 * * 0 /usr/bin/backup.sh`**의 의미로 올바른 것은?

1. 매일 오전 3시 0분에 실행
2. 매주 일요일 오전 3시 0분에 실행
3. 매월 3일 자정에 실행
4. 매시간 0분과 3분에 실행

<details>
<summary>정답 및 해설 보기</summary>

**정답: 2번**

crontab 필드 순서: **분 시 일 월 요일**

```
0   3   *   *   0
분  시  일  월  요일(0=일요일, 7=일요일, 1=월요일)
```

- `0` (분): 0분에
- `3` (시): 오전 3시에
- `*` (일): 매일
- `*` (월): 매월
- `0` (요일): 일요일에

따라서 **매주 일요일 오전 3시 0분**에 실행됩니다.

```
*    *    *    *    *    실행명령
분   시   일   월   요일
0-59 0-23 1-31 1-12 0-7(0,7=일)
```

자주 출제되는 예시:
- `0 0 * * *` : 매일 자정
- `0 */6 * * *` : 6시간마다
- `0 9 * * 1-5` : 평일 오전 9시
- `0 0 1 * *` : 매월 1일 자정
</details>

### 문제 4

**RAID 5**를 구성하기 위해 필요한 최소 디스크 수는?

1. 1개
2. 2개
3. 3개
4. 4개

<details>
<summary>정답 및 해설 보기</summary>

**정답: 3번**

RAID 유형별 최소 디스크 수:

| RAID 레벨 | 최소 디스크 | 특징 |
|-----------|------------|------|
| RAID 0 | 2개 | 스트라이핑, 장애 허용 없음 |
| RAID 1 | 2개 | 미러링, 1개 장애 허용 |
| RAID 5 | 3개 | 분산 패리티, 1개 장애 허용 |
| RAID 6 | 4개 | 이중 패리티, 2개 장애 허용 |
| RAID 10 | 4개 | RAID 1+0, 미러 스트라이핑 |

RAID 5는 최소 3개 디스크에 데이터를 스트라이핑하고 패리티 정보를 순환 분산 저장합니다. 1개 디스크 장애 시 패리티로 복구가 가능합니다.

실제 사용 가능 용량 = (n-1) × 디스크 1개 용량
- 디스크 3개 × 1TB = 총 3TB, 사용 가능 2TB
</details>

### 문제 5

**`ss -tuln`** 명령 출력에서 **LISTEN** 상태의 의미로 올바른 것은?

1. 현재 데이터 전송 중인 활성 연결
2. 원격 측의 연결 종료를 기다리는 상태
3. 특정 포트에서 들어오는 연결 요청을 기다리는 상태
4. 연결이 완전히 종료된 상태

<details>
<summary>정답 및 해설 보기</summary>

**정답: 3번**

소켓 상태 설명:

| 상태 | 의미 |
|------|------|
| LISTEN | 포트를 열고 연결 요청 대기 중 (서버 소켓) |
| ESTABLISHED | 연결이 수립되어 데이터 통신 중 |
| TIME_WAIT | 연결 종료 후 남은 패킷 처리를 위한 대기 |
| CLOSE_WAIT | 상대방이 종료했고 내 측 종료 대기 |
| SYN_RECV | SYN 패킷 수신 후 ACK 대기 중 |

`ss -tuln` 옵션:
- `-t`: TCP 소켓
- `-u`: UDP 소켓
- `-l`: LISTEN 상태만 표시
- `-n`: 이름 대신 숫자로 표시 (서비스명→포트번호)

```bash
ss -tuln
# LISTEN 상태 + 포트 번호로 어떤 서비스가 동작 중인지 확인
```
</details>

### 문제 6

**SELinux Enforcing 모드와 Permissive 모드**의 차이로 올바른 것은?

1. Enforcing은 SELinux를 완전히 비활성화하고, Permissive는 로그만 기록한다
2. Enforcing은 정책 위반을 차단하고 로그를 기록하며, Permissive는 차단 없이 로그만 기록한다
3. Enforcing과 Permissive 모두 정책을 강제 적용하지만, Permissive는 경고만 표시한다
4. Permissive는 정책을 강제 적용하고, Enforcing은 로그만 기록한다

<details>
<summary>정답 및 해설 보기</summary>

**정답: 2번**

SELinux 세 가지 모드:

| 모드 | 정책 적용 | 로그 기록 | 사용 시기 |
|------|---------|---------|---------|
| Enforcing | O (차단) | O | 운영 환경 |
| Permissive | X (허용) | O | 디버깅, 정책 개발 |
| Disabled | X | X | SELinux 완전 비활성화 |

```bash
# 현재 모드 확인
getenforce
sestatus

# 임시 변경 (재부팅 시 초기화)
setenforce 0    # Permissive로 전환
setenforce 1    # Enforcing으로 전환

# 영구 변경 (/etc/selinux/config)
SELINUX=enforcing   # 또는 permissive, disabled
```

**시험 포인트:** Permissive 모드는 SELinux를 비활성화한 것이 아닙니다. 정책 위반이 일어나더라도 차단하지 않고 `/var/log/audit/audit.log`에 기록만 합니다.
</details>

### 문제 7

**`tar -cjvf archive.tar.bz2 /data`** 명령에서 **`j`** 옵션의 의미는?

1. gzip으로 압축
2. bzip2로 압축
3. xz로 압축
4. 압축 없이 아카이브만 생성

<details>
<summary>정답 및 해설 보기</summary>

**정답: 2번**

tar 압축 옵션 비교:

| 옵션 | 압축 방식 | 확장자 | 속도/압축률 |
|------|---------|-------|-----------|
| `-z` | gzip | .tar.gz, .tgz | 빠름/중간 |
| `-j` | bzip2 | .tar.bz2 | 느림/높음 |
| `-J` | xz | .tar.xz | 가장 느림/가장 높음 |
| 없음 | 없음 | .tar | 가장 빠름/없음 |

tar 주요 옵션:
- `-c`: create (새 아카이브 생성)
- `-x`: extract (압축 해제)
- `-t`: list (목록 확인)
- `-v`: verbose (파일 목록 출력)
- `-f`: file (아카이브 파일 지정, 마지막에 위치)

```bash
# bzip2 압축 생성
tar -cjvf archive.tar.bz2 /data

# bzip2 압축 해제
tar -xjvf archive.tar.bz2

# 목록 확인
tar -tjvf archive.tar.bz2
```
</details>

### 문제 8

**좀비(Zombie, Z) 프로세스**에 대한 설명으로 올바른 것은?

1. CPU를 100% 사용하며 시스템을 느리게 만드는 프로세스
2. 실행이 완료됐지만 부모 프로세스가 exit 상태를 수거하지 않아 PCB가 남아있는 프로세스
3. 백그라운드에서 실행 중인 데몬 프로세스
4. 메모리 누수를 일으키는 비정상적인 프로세스

<details>
<summary>정답 및 해설 보기</summary>

**정답: 2번**

**좀비 프로세스(Zombie Process):**

- 프로세스 실행이 완료됐지만, **부모 프로세스가 `wait()` 시스템 콜로 종료 상태를 수거하지 않은 상태**
- 실제 CPU나 메모리는 거의 사용하지 않지만, **PID와 PCB(Process Control Block)는 차지**
- `ps` 출력의 STAT 컬럼에 `Z`로 표시
- 좀비가 많이 쌓이면 PID가 고갈될 수 있음

```bash
# 좀비 프로세스 확인
ps aux | awk '$8=="Z" {print $0}'
ps aux | grep -w Z

# top에서 zombie 개수 확인 (헤더)
# Tasks: 215 total,   1 running, 214 sleeping,   0 stopped,   1 zombie

# 좀비 처리: 부모 프로세스를 종료하거나 재시작
# 부모 PID 확인
ps -o ppid= -p 좀비PID
# 부모 프로세스에 SIGCHLD 신호 전송
kill -SIGCHLD 부모PID
```

**주의:** 좀비는 직접 kill로 종료할 수 없습니다. 이미 종료된 상태이기 때문입니다.
</details>

### 문제 9

**`rsync --delete` 옵션**의 동작으로 올바른 것은?

1. 동기화 완료 후 원본 파일을 삭제
2. 대상 디렉토리에만 있고 원본에 없는 파일을 대상에서 삭제
3. 대상 디렉토리를 완전히 삭제하고 원본으로 교체
4. 삭제된 파일을 복구하여 원본과 동일하게 만듦

<details>
<summary>정답 및 해설 보기</summary>

**정답: 2번**

`rsync --delete`는 **대상(destination)에만 있고 원본(source)에는 없는 파일을 삭제**하여 완전한 미러링을 수행합니다.

```bash
# 기본 rsync (삭제 없이 복사/업데이트만)
rsync -avz /source/ /destination/

# 완전 미러링 (원본에 없는 파일은 대상에서도 삭제)
rsync -avz --delete /source/ /destination/

# 주의: 원본 경로 끝의 슬래시(/) 여부
# /source/  → source 디렉토리의 내용을 복사
# /source   → source 디렉토리 자체를 복사 (destination/source/로 복사)
```

rsync 주요 옵션:

| 옵션 | 의미 |
|------|------|
| `-a` | 아카이브 모드 (-rlptgoD 의 묶음) |
| `-v` | 상세 출력 |
| `-z` | 전송 중 압축 |
| `--delete` | 원본에 없는 파일을 대상에서 삭제 |
| `--dry-run`, `-n` | 실제 실행 없이 테스트 |
| `--exclude=패턴` | 제외 파일 지정 |
| `-e ssh` | SSH로 전송 |
</details>

### 문제 10

**`useradd -G wheel,developers user1`** 명령에서 **`-G`** 옵션의 의미는?

1. user1의 기본 그룹(primary group)을 wheel로 설정
2. user1을 wheel과 developers 그룹에 보조 그룹(supplementary group)으로 추가
3. wheel과 developers 그룹을 새로 생성하면서 user1을 추가
4. user1의 GID를 wheel 그룹의 GID로 변경

<details>
<summary>정답 및 해설 보기</summary>

**정답: 2번**

| 옵션 | 의미 |
|------|------|
| `-g 그룹명` | 기본 그룹(primary group) 지정 - `/etc/passwd`에 GID로 기록 |
| `-G 그룹명[,그룹명]` | 보조 그룹(supplementary group) 지정 - `/etc/group`에 기록 |

```bash
# 기본 그룹 설정 (소문자 g)
useradd -g developers user1
# /etc/passwd: user1:x:1001:1002:...  (GID=1002 = developers)

# 보조 그룹 설정 (대문자 G)
useradd -G wheel,developers user1
# /etc/group: wheel:x:10:user1
#             developers:x:1002:user1

# 기존 사용자에게 보조 그룹 추가
usermod -aG wheel user1  # -a(append)가 없으면 기존 보조 그룹 초기화!

# 사용자의 그룹 확인
id user1
groups user1
```

**시험 포인트:** `usermod -G`로 보조 그룹을 설정할 때 `-a(append)` 없이 사용하면 기존 보조 그룹이 모두 제거됩니다. 기존 그룹을 유지하면서 추가하려면 반드시 `-aG`를 함께 써야 합니다.
</details>
