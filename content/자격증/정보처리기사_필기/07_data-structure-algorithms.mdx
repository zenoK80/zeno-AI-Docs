## 시간복잡도(Big-O)란?

알고리즘을 공부하면 $O(1)$, $O(n)$, $O(\log n)$ 같은 표기가 계속 등장합니다. 이것은 **데이터 개수($n$)가 늘어날 때 작업 시간이 얼마나 늘어나는지**를 나타내는 표기법입니다.

> **쉽게 말하면:** $O(\cdots)$는 "데이터가 2배로 늘어나면, 이 작업은 몇 배나 느려지는가?"에 대한 답입니다.

| 표기 | 읽는 법 | 뜻 | 데이터 100배 증가 시 |
|------|---------|-----|---------------------|
| $O(1)$ | "오 원" | 데이터 개수와 무관하게 항상 일정한 시간 | 그대로 |
| $O(\log n)$ | "오 로그 엔" | 데이터가 늘어도 아주 느리게 증가 | 약간만 증가 |
| $O(n)$ | "오 엔" | 데이터 개수에 비례해서 증가 | 100배 느려짐 |
| $O(n \log n)$ | "오 엔 로그 엔" | n보다 약간 더 느리게 증가 | 100배보다 조금 더 |
| $O(n^2)$ | "오 엔 제곱" | 데이터 개수의 제곱에 비례 | 10,000배 느려짐 |

> **비유:** 전화번호부에서 이름을 찾는다고 합시다. 책 전체를 처음부터 한 장씩 넘기며 찾으면($O(n)$), 페이지가 2배로 늘면 시간도 2배로 늘어납니다. 하지만 가나다순으로 정렬된 책의 중간을 펼쳐서 절반씩 좁혀가며 찾으면($O(\log n)$), 페이지가 아무리 늘어도 몇 번만 더 펼치면 됩니다.

## 선형 자료구조

### 배열 (Array)

같은 타입의 데이터를 메모리에 **연속으로** 나란히 저장합니다.

> **비유:** 배열은 아파트처럼 각 세대(칸)마다 정확한 호수(인덱스)가 매겨져 있습니다. "3층 5호"를 바로 찾아가듯, 배열은 인덱스로 어떤 칸이든 즉시 접근합니다.

- **접근**: 인덱스로 바로 찾아가므로 $O(1)$ — 데이터가 몇 개든 상관없이 즉시 접근
- **삽입·삭제**: 중간에 데이터를 넣으려면 뒤의 모든 데이터를 한 칸씩 밀어야 하므로 $O(n)$

### 연결 리스트 (Linked List)

각 노드가 "자기 데이터"와 "다음 노드의 위치(포인터)"를 함께 저장합니다.

> **비유:** 연결 리스트는 보물찾기와 같습니다. 각 힌트 쪽지(노드)에 "다음 힌트는 여기 있다"는 정보만 적혀 있어, 처음부터 하나씩 따라가야만 원하는 곳에 도달할 수 있습니다.

- **삽입·삭제**: 앞뒤 포인터만 바꾸면 되므로 $O(1)$ (위치를 이미 알고 있을 때)
- **탐색**: 몇 번째인지 알려면 처음부터 하나씩 따라가야 하므로 $O(n)$

| 자료구조 | 접근 | 삽입·삭제 | 언제 유리한가 |
|---------|------|-----------|--------------|
| 배열 | $O(1)$ | $O(n)$ | 조회가 잦을 때 |
| 연결 리스트 | $O(n)$ | $O(1)$ | 삽입·삭제가 잦을 때 |

### 스택 (Stack) — LIFO

**LIFO(Last In, First Out, 후입선출)**: 마지막에 넣은 것이 가장 먼저 나옵니다.

> **비유:** 접시를 쌓아 올린 더미와 같습니다. 맨 위에 올린 접시를 가장 먼저 빼서 씁니다. 아래쪽 접시를 먼저 꺼내려면 위의 접시를 전부 치워야 합니다.

- 연산: `push`(맨 위에 삽입), `pop`(맨 위에서 삭제), `peek`(맨 위 값 확인만)
- 활용: 함수를 호출하면 스택에 쌓였다가 반환될 때 역순으로 빠짐(함수 호출 스택), 괄호 짝 검사, 웹 브라우저의 "뒤로 가기"

### 큐 (Queue) — FIFO

**FIFO(First In, First Out, 선입선출)**: 먼저 넣은 것이 먼저 나옵니다.

> **비유:** 은행 창구 대기줄과 같습니다. 먼저 줄을 선 사람이 먼저 처리됩니다.

- 연산: `enqueue`(뒤에 삽입), `dequeue`(앞에서 삭제)
- 활용: 프린터 인쇄 대기열(먼저 요청한 문서가 먼저 인쇄), 그래프의 BFS 탐색

### 덱 (Deque)

**Deque(Double-Ended Queue)**는 양쪽 끝에서 모두 삽입·삭제가 가능한 큐입니다. 스택과 큐의 기능을 모두 가진 자료구조라고 볼 수 있습니다.

## 비선형 자료구조

### 트리 (Tree)

트리는 부모-자식 관계로 데이터를 계층적으로 표현하는 구조입니다. 가계도나 회사 조직도를 떠올리면 됩니다.

| 용어 | 설명 |
|------|------|
| 루트(Root) | 최상위 노드 (부모가 없는 노드) |
| 단말 노드(Leaf) | 자식이 없는 노드 (트리의 "끝") |
| 높이(Height) | 루트에서 가장 먼 단말까지의 단계 수 |
| 차수(Degree) | 한 노드가 가진 자식의 수 |

### 이진 트리 순회

**이진 트리(Binary Tree)**는 각 노드가 자식을 최대 2개(왼쪽, 오른쪽)만 가지는 트리입니다. 트리의 모든 노드를 한 번씩 방문하는 방법이 세 가지 있습니다.

| 순서 | 방문 순서 | 특징 |
|------|-----------|------|
| 전위(Pre-order) | 루트 → 왼쪽 → 오른쪽 | 루트를 가장 먼저 처리해야 할 때 |
| 중위(In-order) | 왼쪽 → 루트 → 오른쪽 | **이진 탐색 트리에서 오름차순 출력** |
| 후위(Post-order) | 왼쪽 → 오른쪽 → 루트 | 자식을 모두 처리한 후 루트를 정리할 때 |

**작은 예시:** 트리가 `루트=5, 왼쪽자식=3, 오른쪽자식=8`이라면

- 전위: 5 → 3 → 8
- 중위: 3 → 5 → 8 (오름차순!)
- 후위: 3 → 8 → 5

### 이진 탐색 트리 (BST)

**왼쪽 자식 < 부모 < 오른쪽 자식** 규칙을 지키는 이진 트리입니다.

> **왜 이 규칙이 중요한가?** 찾으려는 값이 현재 노드보다 작으면 무조건 왼쪽으로, 크면 무조건 오른쪽으로만 내려가면 됩니다. 매 단계마다 탐색 범위가 절반으로 줄어들어(마치 이진 탐색처럼) 평균 $O(\log n)$에 원하는 값을 찾을 수 있습니다.

- 탐색·삽입·삭제: 평균 $O(\log n)$ (단, 한쪽으로 치우쳐 자라면 최악의 경우 $O(n)$까지 나빠질 수 있습니다)

### 그래프 (Graph)

**정점(Vertex, 노드)**과 **간선(Edge, 정점을 잇는 선)**으로 이루어진 구조입니다. 트리와 달리 순환(사이클)이 있을 수 있고, 부모-자식 같은 계층 관계가 없습니다.

- **BFS(너비 우선 탐색, Breadth-First Search)**: 가까운 정점부터 순서대로 방문. **큐**를 사용합니다.
- **DFS(깊이 우선 탐색, Depth-First Search)**: 한 방향으로 갈 수 있는 데까지 깊이 들어간 뒤 되돌아옵니다. **스택 또는 재귀**를 사용합니다.

> **비유:** 미로를 탐험할 때, BFS는 "출발점에서 가까운 곳부터 한 걸음씩 골고루" 살펴보는 방식이고, DFS는 "한 길을 끝까지 가보고 막히면 돌아와서 다른 길을 시도"하는 방식입니다.

## 정렬 알고리즘

### 버블 정렬로 감을 잡기

정렬 알고리즘의 원리를 감 잡기 위해, 가장 단순한 **버블 정렬**을 손으로 따라가 봅니다. 데이터 `[5, 2, 4, 1]`을 오름차순 정렬합니다.

```
1회전: (5,2) 비교 → 교환 → [2,5,4,1]
       (5,4) 비교 → 교환 → [2,4,5,1]
       (5,1) 비교 → 교환 → [2,4,1,5]  ← 가장 큰 값 5가 맨 뒤로 "떠오름"(bubble)

2회전: (2,4) 비교 → 그대로 → [2,4,1,5]
       (4,1) 비교 → 교환 → [2,1,4,5]

3회전: (2,1) 비교 → 교환 → [1,2,4,5]  ← 정렬 완료
```

인접한 두 값을 계속 비교·교환하며 큰 값이 거품처럼 뒤로 떠오른다고 해서 "버블 정렬"입니다. 이해하기는 쉽지만, 데이터가 많아지면 $n \times n$번 가까이 비교해야 해서 느립니다($O(n^2)$).

### 정렬 알고리즘 비교

| 알고리즘 | 평균 | 최악 | 특징 |
|----------|------|------|------|
| 버블 정렬 | $O(n^2)$ | $O(n^2)$ | 인접 요소 비교·교환, 구현 간단하지만 느림 |
| 선택 정렬 | $O(n^2)$ | $O(n^2)$ | 매 회전마다 최솟값을 찾아 맨 앞에 배치 |
| 삽입 정렬 | $O(n^2)$ | $O(n^2)$ | 이미 거의 정렬된 데이터에는 매우 빠름 |
| 퀵 정렬 | $O(n \log n)$ | $O(n^2)$ | 기준값(피벗)으로 분할, 평균적으로 가장 실용적 |
| 합병 정렬 | $O(n \log n)$ | $O(n \log n)$ | 절반씩 나눠 정렬 후 합침(분할정복), **안정 정렬** |
| 힙 정렬 | $O(n \log n)$ | $O(n \log n)$ | 힙 구조로 최솟값·최댓값을 반복 추출 |

> **안정 정렬(Stable Sort)이란?** 값이 같은 두 데이터의 **원래 순서가 정렬 후에도 유지**되는 정렬을 말합니다. 예를 들어 이름이 같은 학생 두 명이 있을 때, 원래 순서(등록 순서 등)가 정렬 후에도 그대로 유지되면 안정 정렬입니다.

<Callout type="warning">
  **자주 틀리는 점:** 퀵 정렬은 평균적으로 빠르지만(운이 나쁘면 피벗이 계속 한쪽으로 치우쳐) 최악의 경우 $O(n^2)$까지 느려질 수 있습니다. 반면 합병 정렬은 항상 $O(n \log n)$을 보장합니다. "평균이 빠른 것"과 "항상 보장되는 것"을 구분해서 기억해야 합니다.
</Callout>

## 탐색 알고리즘

| 알고리즘 | 시간복잡도 | 전제 조건 |
|----------|-----------|-----------|
| 순차 탐색 | $O(n)$ | 없음 (처음부터 하나씩 확인) |
| 이진 탐색 | $O(\log n)$ | 데이터가 **정렬**되어 있어야 함 |
| 해시 탐색 | $O(1)$ 평균 | 해시 테이블 구조 필요 |

**이진 탐색 동작 과정 예시:** 정렬된 배열 `[1, 3, 5, 7, 9, 11, 13]`에서 `7`을 찾습니다.

```
1단계: 전체 범위의 중간(4번째, 값=7) 확인 → 7 == 7 → 찾음!
```

값이 `11`이었다면:

```
1단계: 중간(값=7) 확인 → 11 > 7 → 오른쪽 절반만 남김 [9, 11, 13]
2단계: 중간(값=11) 확인 → 11 == 11 → 찾음!
```

매 단계마다 탐색 범위가 절반으로 줄어들기 때문에 $O(\log n)$입니다.

## 핵심 정리

- **Big-O**: 데이터가 늘어날 때 작업 시간이 얼마나 늘어나는지 나타내는 표기. $O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2)$ 순으로 느려짐.
- **배열**: 접근 $O(1)$, 삽입·삭제 $O(n)$. **연결 리스트**: 접근 $O(n)$, 삽입·삭제 $O(1)$.
- **스택**: LIFO(후입선출). **큐**: FIFO(선입선출).
- **BST**: 왼쪽 < 부모 < 오른쪽, 중위 순회 시 오름차순 출력.
- **BFS**: 큐 사용, 가까운 곳부터. **DFS**: 스택/재귀 사용, 깊이 먼저.
- **퀵 정렬**: 평균 빠름($O(n\log n)$)이나 최악은 $O(n^2)$. **합병 정렬**: 항상 $O(n\log n)$ + 안정 정렬.
- **이진 탐색**: 반드시 정렬된 데이터에서만 $O(\log n)$으로 동작.
