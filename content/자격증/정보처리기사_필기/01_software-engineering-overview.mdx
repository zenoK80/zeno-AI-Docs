## 소프트웨어 생명주기 (SDLC)

소프트웨어 생명주기(Software Development Life Cycle)는 소프트웨어를 개발·운영·유지보수하는 전 과정을 단계별로 정의한 프레임워크입니다.

### 주요 단계

| 단계 | 설명 | 산출물 |
|------|------|--------|
| 요구사항 분석 | 사용자 요구 수집·정의 | 요구사항 명세서(SRS) |
| 설계 | 시스템 구조·모듈 설계 | 설계 문서, ERD, UML |
| 구현 | 코드 작성 | 소스코드 |
| 테스트 | 결함 발견·수정 | 테스트 케이스, 결함 보고서 |
| 배포·유지보수 | 운영 환경 배포 및 관리 | 릴리스 노트 |

---

## 폭포수 모델 (Waterfall)

각 단계를 순차적으로 진행하며 이전 단계로 되돌아가지 않는 선형 모델입니다.

```
요구사항 → 설계 → 구현 → 테스트 → 유지보수
```

**장점:** 단계가 명확하고 문서화가 체계적  
**단점:** 요구사항 변경에 취약, 후반부 오류 발견 시 비용 큼

---

## 애자일 모델 (Agile)

반복적이고 점진적인 개발 방식으로, 짧은 스프린트(Sprint) 단위로 작동하는 실행 가능한 소프트웨어를 지속 제공합니다.

### 애자일 핵심 가치 (Agile Manifesto)

1. **프로세스·도구**보다 **개인·상호작용**
2. **포괄적인 문서**보다 **작동하는 소프트웨어**
3. **계약 협상**보다 **고객 협력**
4. **계획 준수**보다 **변화에 대응**

### 스크럼(Scrum) 주요 용어

| 용어 | 설명 |
|------|------|
| Product Backlog | 개발할 기능 전체 목록 |
| Sprint | 보통 2~4주의 반복 개발 단위 |
| Sprint Backlog | 스프린트에서 수행할 작업 목록 |
| Daily Scrum | 매일 15분 진행 상황 공유 회의 |
| Velocity | 스프린트당 처리할 수 있는 작업량 |

---

## 나선형 모델 (Spiral)

위험 분석을 중심으로 계획·위험분석·개발·평가를 반복하는 모델입니다.

```
계획 → 위험 분석 → 개발(프로토타입) → 평가 → 계획 → ...
```

**특징:** 대규모·고위험 프로젝트에 적합, Boehm이 제안

---

## 기타 방법론

| 방법론 | 특징 |
|--------|------|
| RAD (빠른 애플리케이션 개발) | 짧은 개발 주기, 재사용·시각 도구 활용 |
| 프로토타이핑 | 요구 불명확 시 시제품을 만들어 확인 |
| XP (익스트림 프로그래밍) | 페어 프로그래밍, TDD, 지속적 통합 강조 |
| 칸반(Kanban) | 작업 흐름 시각화, WIP 제한 |

---

## 핵심 정리

- **폭포수:** 순차적, 단계 명확, 변경에 취약
- **애자일:** 반복적, 변화 수용, 고객 협력 강조
- **나선형:** 위험 분석 중심, 대형 프로젝트 적합
- SDLC 단계: 요구사항 → 설계 → 구현 → 테스트 → 배포
