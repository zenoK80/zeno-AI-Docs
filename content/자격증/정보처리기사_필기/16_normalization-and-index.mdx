## 이상 현상 (Anomaly)

정규화가 이루어지지 않은 테이블에서 발생하는 문제입니다.

| 이상 현상 | 설명 |
|-----------|------|
| 삽입 이상 | 원하지 않는 데이터도 함께 삽입해야 하는 경우 |
| 삭제 이상 | 특정 데이터 삭제 시 다른 유용한 데이터도 삭제 |
| 갱신 이상 | 일부만 수정하여 데이터 불일치 발생 |

---

## 정규화 단계

### 1NF (제1정규형)
- 모든 속성이 원자값(Atomic Value)을 가져야 함
- 반복 그룹과 다중값 속성 제거

### 2NF (제2정규형)
- 1NF 만족 + **부분 함수 종속 제거**
- 기본키가 복합키일 때 기본키의 일부에만 종속된 속성 제거

### 3NF (제3정규형)
- 2NF 만족 + **이행적 함수 종속 제거**
- A → B, B → C 이면 A → C의 이행적 종속 제거

### BCNF (보이스-코드 정규형)
- 3NF 만족 + **모든 결정자가 후보키**여야 함
- 3NF보다 강한 조건

### 함수 종속 개념

| 개념 | 설명 |
|------|------|
| 완전 함수 종속 | 기본키 전체에 종속 |
| 부분 함수 종속 | 기본키의 일부에 종속 (2NF 위반) |
| 이행적 함수 종속 | A→B, B→C (3NF 위반) |

## 역정규화 (Denormalization)

성능 향상을 위해 의도적으로 정규화를 되돌리는 기법입니다.

- 조인 연산 감소로 성능 향상
- 데이터 중복 증가, 무결성 관리 어려움

---

## 인덱스 (Index)

데이터 검색 속도를 향상시키는 데이터 구조입니다.

### 인덱스 유형

| 유형 | 설명 |
|------|------|
| 클러스터형 인덱스 | 인덱스 순서대로 실제 데이터 저장 (테이블당 1개) |
| 비클러스터형 인덱스 | 인덱스와 실제 데이터 위치 분리 (다수 가능) |
| 유일 인덱스 | 중복 값 허용 안 함 |
| 복합 인덱스 | 여러 컬럼으로 구성 |

### 인덱스 특징

- 검색(SELECT) 속도 향상
- 삽입(INSERT)·수정(UPDATE)·삭제(DELETE) 성능 저하
- B-트리 구조를 주로 사용

```sql
CREATE INDEX idx_emp_name ON employee(name);
CREATE UNIQUE INDEX idx_emp_email ON employee(email);
DROP INDEX idx_emp_name ON employee;
```

## 뷰 (View)

실제 데이터를 저장하지 않는 가상 테이블입니다.

### 뷰 특징

| 특징 | 설명 |
|------|------|
| 독립성 | 기반 테이블 변경에도 응용 프로그램 영향 최소화 |
| 편의성 | 복잡한 쿼리를 단순화 |
| 보안성 | 민감 데이터 접근 제한 |

```sql
-- 뷰 생성
CREATE VIEW emp_dept AS
SELECT e.name, d.dept_name
FROM employee e
JOIN department d ON e.dept_id = d.dept_id;

-- 뷰 삭제
DROP VIEW emp_dept;
```

---

## 핵심 정리

- 1NF: 원자값 / 2NF: 부분 종속 제거 / 3NF: 이행적 종속 제거 / BCNF: 결정자=후보키
- 클러스터형 인덱스: 데이터 정렬 저장, 테이블당 1개
- 뷰: 가상 테이블, 실제 데이터 미저장
- 이상 현상: 삽입, 삭제, 갱신 이상
