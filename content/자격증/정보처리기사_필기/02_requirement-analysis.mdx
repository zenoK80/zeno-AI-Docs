## 요구사항의 분류

### 기능적 요구사항 vs 비기능적 요구사항

| 구분 | 설명 | 예시 |
|------|------|------|
| 기능적 요구사항 | 시스템이 수행해야 할 기능 | 로그인, 결제, 검색 |
| 비기능적 요구사항 | 시스템의 품질·제약 조건 | 응답 시간, 보안, 가용성 |

---

## 요구사항 분석 기법

### 인터뷰와 설문

- **인터뷰:** 이해관계자와 직접 대화로 요구 파악
- **설문:** 다수 사용자 의견을 정형화된 질문으로 수집

### 프로토타이핑

요구사항이 불명확할 때 시제품(프로토타입)을 만들어 사용자 피드백을 반영합니다.

### 유스케이스 분석

사용자(Actor)와 시스템의 상호작용을 유스케이스(Use Case)로 표현합니다.

### SVAC 요구사항 속성

| 속성 | 의미 |
|------|------|
| 검증 가능성 (Verifiable) | 테스트를 통해 충족 여부를 확인할 수 있어야 함 |
| 추적 가능성 (Traceable) | 요구사항 출처를 추적할 수 있어야 함 |
| 이해 가능성 (Understandable) | 이해관계자가 이해할 수 있어야 함 |
| 완전성 (Complete) | 필요한 정보를 모두 포함해야 함 |

---

## UML (Unified Modeling Language)

UML은 소프트웨어 시스템을 시각적으로 모델링하기 위한 표준 표기법입니다.

### UML 다이어그램 분류

| 구분 | 다이어그램 종류 |
|------|----------------|
| 구조 다이어그램 | 클래스, 객체, 컴포넌트, 배치, 패키지, 복합 구조 |
| 행위 다이어그램 | 유스케이스, 활동, 상태, 시퀀스, 통신, 타이밍, 상호작용 개요 |

### 주요 다이어그램 용도

| 다이어그램 | 설명 |
|------------|------|
| 유스케이스 다이어그램 | 시스템과 Actor의 상호작용 표현 |
| 클래스 다이어그램 | 클래스 간 정적 관계(속성, 메서드, 관계) 표현 |
| 시퀀스 다이어그램 | 객체 간 메시지 교환 순서 표현 (시간 축) |
| 활동 다이어그램 | 업무 흐름이나 알고리즘 흐름 표현 |
| 상태 다이어그램 | 객체의 상태 변화와 전이 표현 |
| 컴포넌트 다이어그램 | 시스템 구성요소(모듈) 간 관계 표현 |
| 배치 다이어그램 | 하드웨어와 소프트웨어의 물리적 배치 표현 |

---

## 클래스 다이어그램 관계

| 관계 | 기호 | 설명 |
|------|------|------|
| 연관(Association) | 실선 화살표 | 두 클래스가 연관됨 |
| 의존(Dependency) | 점선 화살표 | 한 클래스가 다른 클래스를 사용 |
| 일반화(Generalization) | 빈 삼각형 화살표 | 상속 관계 (is-a) |
| 실체화(Realization) | 점선 빈 삼각형 | 인터페이스 구현 |
| 집합(Aggregation) | 빈 마름모 | 전체-부분 관계 (약한 결합) |
| 합성(Composition) | 채운 마름모 | 전체-부분 관계 (강한 결합) |

---

## 핵심 정리

- 기능적 요구사항: 시스템이 해야 할 일 / 비기능적: 품질·제약
- UML 구조 다이어그램 대표: 클래스, 컴포넌트, 배치
- UML 행위 다이어그램 대표: 유스케이스, 시퀀스, 활동
- 시퀀스 다이어그램: 메시지 교환 순서 (시간 흐름)
