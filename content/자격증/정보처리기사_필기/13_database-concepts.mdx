## DBMS 개념

데이터베이스 관리 시스템(DBMS)은 데이터를 체계적으로 저장·관리·검색할 수 있도록 하는 소프트웨어입니다.

### DBMS 기능

| 기능 | 설명 |
|------|------|
| 데이터 정의 | DDL로 스키마 정의 |
| 데이터 조작 | DML로 CRUD 수행 |
| 데이터 제어 | DCL로 접근 권한 관리 |
| 동시성 제어 | 여러 사용자의 동시 접근 관리 |
| 무결성 유지 | 데이터의 정확성·일관성 보장 |
| 회복 | 장애 발생 시 데이터 복구 |

### 대표 DBMS

| 유형 | 제품 |
|------|------|
| 관계형(RDBMS) | Oracle, MySQL, PostgreSQL, SQL Server |
| NoSQL | MongoDB, Redis, Cassandra |
| NewSQL | CockroachDB, Google Spanner |

## 3단계 스키마 구조

ANSI/SPARC 3단계 스키마는 데이터 독립성을 보장합니다.

| 단계 | 스키마 | 설명 |
|------|--------|------|
| 외부 단계 | 외부 스키마 (External) | 사용자·응용 프로그램 관점 (뷰) |
| 개념 단계 | 개념 스키마 (Conceptual) | 전체 데이터베이스 논리 구조 |
| 내부 단계 | 내부 스키마 (Internal) | 물리적 저장 구조 |

### 데이터 독립성

- **논리적 독립성:** 개념 스키마 변경 시 외부 스키마 영향 없음
- **물리적 독립성:** 내부 스키마 변경 시 개념 스키마 영향 없음

## ERD (Entity-Relationship Diagram)

### ERD 구성요소

| 요소 | 표기 | 설명 |
|------|------|------|
| 개체(Entity) | 사각형 | 독립적으로 존재하는 데이터 집합 |
| 속성(Attribute) | 타원 | 개체의 특성 |
| 관계(Relationship) | 마름모 | 개체 간 연관성 |
| 기본키 속성 | 밑줄 타원 | 개체를 고유 식별 |
| 다중값 속성 | 이중 타원 | 여러 값을 가지는 속성 |

### 카디널리티 (Cardinality)

| 관계 | 설명 | 예시 |
|------|------|------|
| 1:1 | 일대일 | 사람 - 여권 |
| 1:N | 일대다 | 부서 - 직원 |
| N:M | 다대다 | 학생 - 과목 |

---

## 관계형 모델 (Relational Model)

### 기본 용어

| 용어 | 설명 |
|------|------|
| 릴레이션(Relation) | 테이블 |
| 튜플(Tuple) | 행(Row) |
| 속성(Attribute) | 열(Column) |
| 도메인(Domain) | 속성의 허용 값 범위 |
| 카디널리티(Cardinality) | 튜플 수 |
| 차수(Degree) | 속성 수 |

### 키의 종류

| 키 | 설명 |
|----|------|
| 슈퍼키(Super Key) | 유일성을 만족하는 속성 집합 |
| 후보키(Candidate Key) | 슈퍼키 중 최소성 만족 |
| 기본키(Primary Key) | 후보키 중 선택된 대표 키 |
| 대체키(Alternate Key) | 기본키가 아닌 후보키 |
| 외래키(Foreign Key) | 다른 릴레이션의 기본키 참조 |

---

## 핵심 정리

- 3단계 스키마: 외부 → 개념 → 내부
- ERD 개체: 사각형 / 속성: 타원 / 관계: 마름모
- 기본키: 중복 없음(유일성) + NULL 없음
- 외래키: 다른 테이블 기본키 참조
