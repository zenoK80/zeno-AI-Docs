## 인터페이스 설계 개념

인터페이스는 시스템과 시스템, 또는 시스템과 사용자 간의 연결 지점입니다.

### 인터페이스 설계 절차

1. 인터페이스 대상 식별
2. 인터페이스 방식 결정 (API, 파일, DB 등)
3. 인터페이스 명세서 작성
4. 인터페이스 구현
5. 인터페이스 테스트

---

## UI 설계 원칙

### 닐슨(Nielsen)의 10가지 휴리스틱

| 원칙 | 설명 |
|------|------|
| 시스템 상태 가시성 | 사용자에게 시스템 상태를 항상 알려줌 |
| 실세계 부합 | 사용자 언어와 개념을 사용 |
| 사용자 통제권 | 실수 취소·재실행 가능 |
| 일관성과 표준 | 동일 개념에 동일 단어·동작 사용 |
| 오류 예방 | 오류 발생 전에 방지 |
| 인식보다 기억 최소화 | 사용자 기억 부담 줄이기 |
| 유연성과 효율성 | 숙련자를 위한 단축키 제공 |
| 심미적·단순한 디자인 | 불필요한 정보 제거 |
| 오류 인식·진단·복구 | 명확한 오류 메시지 제공 |
| 도움말과 문서 | 검색 가능한 도움말 제공 |

### WIMP 인터페이스

- **W**indow, **I**con, **M**enu, **P**ointer로 구성되는 GUI 환경

---

## 프로토타입 종류

| 유형 | 특징 |
|------|------|
| 종이 프로토타입 | 손으로 그린 스케치, 빠르고 저렴 |
| 디지털 와이어프레임 | 레이아웃 구조만 표현 (Figma, Sketch) |
| 목업(Mockup) | 시각 디자인이 적용된 정적 화면 |
| 프로토타입(High-fidelity) | 실제와 유사한 인터랙션 포함 |

### 충실도(Fidelity) 수준

| 수준 | 설명 |
|------|------|
| Low-fidelity | 종이 스케치, 빠른 탐색 |
| Mid-fidelity | 와이어프레임, 기능 구조 확인 |
| High-fidelity | 실제 UI와 유사, 사용성 테스트 적합 |

---

## 시스템 인터페이스 방식

| 방식 | 설명 | 예시 |
|------|------|------|
| REST API | HTTP 기반 RESTful API | JSON/XML 응답 |
| SOAP | XML 기반 웹 서비스 프로토콜 | 엔터프라이즈 시스템 |
| 파일 연계 | CSV, XML 파일로 데이터 교환 | 배치 처리 |
| DB 연계 | 공유 데이터베이스로 연동 | ERP 통합 |
| 메시지 큐 | 비동기 메시지 전달 | RabbitMQ, Kafka |

---

## 핵심 정리

- UI 설계 원칙: 가시성, 일관성, 오류 예방, 피드백
- Low-fidelity: 종이 스케치 / High-fidelity: 실제 유사 프로토타입
- REST API: HTTP 기반 / SOAP: XML 기반
- WIMP: Window, Icon, Menu, Pointer
