## 소프트웨어 아키텍처 패턴

| 패턴 | 특징 |
|------|------|
| 계층형(Layered) | 기능을 계층으로 분리 (UI → 비즈니스 → 데이터) |
| 클라이언트-서버 | 서비스 제공자(서버)와 소비자(클라이언트) 분리 |
| MVC | Model(데이터) - View(화면) - Controller(로직) 분리 |
| 파이프-필터 | 데이터를 단계별 필터로 변환 처리 |
| 이벤트 기반 | 이벤트 발생 시 핸들러 실행 |
| 마이크로서비스 | 독립적으로 배포 가능한 소규모 서비스들의 집합 |
| 저장소(Repository) | 공유 데이터 저장소를 중심으로 구성요소가 연결 |

---

## 모듈화 (Modularity)

시스템을 독립적인 기능 단위(모듈)로 분리하는 설계 원칙입니다.

**장점:** 유지보수 용이, 재사용성 향상, 병행 개발 가능

---

## 결합도 (Coupling)

모듈 간의 의존 정도를 나타냅니다. **결합도는 낮을수록 좋습니다.**

| 유형 | 강도 | 설명 |
|------|------|------|
| 내용 결합 | 가장 강함 | 한 모듈이 다른 모듈 내부 코드를 직접 수정 |
| 공통 결합 | 강함 | 공통 전역 변수를 함께 사용 |
| 외부 결합 | 강함 | 외부 선언 변수나 규약을 공유 |
| 제어 결합 | 중간 | 제어 신호(플래그)를 주고받아 실행 순서를 제어 |
| 스탬프 결합 | 중간 | 구조체·레코드 전체를 매개변수로 전달 |
| 자료 결합 | 가장 약함 | 단순 자료형 매개변수만 교환 (최선) |

> 암기 팁: **내공외제스자** (내 → 자 순으로 결합도 약해짐)

---

## 응집도 (Cohesion)

모듈 내부 요소들의 관련 정도를 나타냅니다. **응집도는 높을수록 좋습니다.**

| 유형 | 강도 | 설명 |
|------|------|------|
| 기능적 응집 | 가장 강함 | 단일 기능만 수행 (최선) |
| 순차적 응집 | 강함 | 이전 처리 결과를 다음 처리에서 사용 |
| 교환적 응집 | 강함 | 동일 데이터에 여러 기능 수행 |
| 절차적 응집 | 중간 | 순서는 있으나 관련성이 낮은 기능 |
| 시간적 응집 | 중간 | 같은 시간에 실행되는 기능 묶음 |
| 논리적 응집 | 약함 | 논리적으로 유사 기능을 묶음 |
| 우연적 응집 | 가장 약함 | 관련 없는 기능의 임의 집합 |

> 암기 팁: **기순교절시논우** (기 → 우 순으로 응집도 약해짐)

---

## 팬인(Fan-in)과 팬아웃(Fan-out)

| 개념 | 설명 | 좋은 설계 |
|------|------|-----------|
| 팬인(Fan-in) | 해당 모듈을 호출하는 상위 모듈 수 | 높을수록 재사용성 좋음 |
| 팬아웃(Fan-out) | 해당 모듈이 호출하는 하위 모듈 수 | 낮을수록 좋음 (4 이하 권장) |

---

## 핵심 정리

- 결합도: **낮을수록** 좋음, 자료 결합이 가장 좋음
- 응집도: **높을수록** 좋음, 기능적 응집이 가장 좋음
- MVC: Model(데이터) + View(화면) + Controller(로직)
- 마이크로서비스: 독립 배포 가능한 소규모 서비스 집합
