## 형상관리 (SCM)

소프트웨어 형상관리(Software Configuration Management)는 소프트웨어의 변경을 체계적으로 관리하는 활동입니다.

### 형상관리 주요 활동

| 활동 | 설명 |
|------|------|
| 형상 식별 | 관리 대상(형상 항목) 식별 |
| 형상 통제 | 변경 요청 검토·승인·기록 |
| 형상 상태 보고 | 변경 내역과 현황 보고 |
| 형상 검사 | 형상 항목이 요구사항과 일치하는지 확인 |

### 대표 형상관리 도구

| 도구 | 유형 | 특징 |
|------|------|------|
| Git | 분산형 | 로컬 저장소 + 원격 저장소 |
| SVN (Subversion) | 중앙 집중형 | 단일 중앙 서버 |
| CVS | 중앙 집중형 | 구형 도구 |
| Mercurial | 분산형 | Git과 유사 |

## Git 핵심 개념

### 저장소 구조

```
Working Directory → Staging Area (Index) → Local Repository → Remote Repository
```

| 영역 | 설명 |
|------|------|
| Working Directory | 실제 파일 수정 공간 |
| Staging Area (Index) | 커밋할 파일을 준비하는 공간 |
| Local Repository | 로컬 커밋 저장소 (.git 폴더) |
| Remote Repository | GitHub, GitLab 등 원격 저장소 |

### 주요 Git 명령어

| 명령어 | 설명 |
|--------|------|
| git init | 저장소 초기화 |
| git clone | 원격 저장소 복제 |
| git add | 스테이징 영역에 추가 |
| git commit | 변경 사항 로컬 저장 |
| git push | 원격 저장소에 업로드 |
| git pull | 원격에서 가져와 병합 |
| git fetch | 원격에서 가져오기만 (병합 없음) |
| git merge | 브랜치 병합 |
| git rebase | 커밋을 다른 브랜치 위에 재적용 |
| git branch | 브랜치 목록·생성·삭제 |
| git checkout | 브랜치 전환 또는 파일 복원 |
| git stash | 임시 저장 |

### 브랜치 전략

| 전략 | 설명 |
|------|------|
| Git Flow | main/develop/feature/hotfix 브랜치 구조 |
| GitHub Flow | main + feature 브랜치의 간단한 구조 |
| Trunk-based Development | 단일 main 브랜치, 짧은 수명 브랜치 |

## CI/CD (지속적 통합/배포)

| 단계 | 설명 |
|------|------|
| CI (지속적 통합) | 코드 변경 시 자동 빌드·테스트 |
| CD (지속적 제공) | 테스트 통과 후 스테이징 환경 자동 배포 |
| CD (지속적 배포) | 프로덕션까지 자동 배포 |

**도구:** Jenkins, GitHub Actions, GitLab CI, CircleCI

---

## 핵심 정리

- Git: 분산형 / SVN: 중앙 집중형
- git add → git commit → git push 흐름
- CI: 자동 빌드·테스트 / CD: 자동 배포
- Staging Area: 커밋 전 대기 공간
