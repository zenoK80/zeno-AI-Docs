## 소프트웨어 규모 산정

### 기능 점수(FP: Function Point)

소프트웨어의 기능 규모를 측정하는 방법으로 사용자 관점에서 측정합니다.

| 기능 유형 | 설명 |
|----------|------|
| 외부 입력(EI) | 시스템 외부에서 입력되는 데이터 |
| 외부 출력(EO) | 시스템 외부로 출력되는 데이터 |
| 외부 조회(EQ) | 입력 없이 조회만 수행 |
| 내부 논리 파일(ILF) | 시스템 내부에서 유지하는 데이터 |
| 외부 인터페이스 파일(EIF) | 다른 시스템에서 유지하는 참조 데이터 |

## COCOMO 모델

Barry Boehm이 제안한 비용 산정 모델입니다.

| 유형 | 특징 | 예시 |
|------|------|------|
| 기본(Basic) | LOC(코드 라인 수)만으로 산정 | 단순 계산 |
| 중간(Intermediate) | 비용 유발 인자 고려 | 일반적 사용 |
| 발전(Detailed) | 개발 단계별 상세 산정 | 대형 프로젝트 |

### COCOMO 프로젝트 유형

| 유형 | 설명 | 규모 |
|------|------|------|
| 조직형(Organic) | 소규모, 단순 | 50KDSI 이하 |
| 반분리형(Semi-detached) | 중간 규모, 중간 복잡도 | 300KDSI 이하 |
| 임베디드형(Embedded) | 복잡한 요구사항 | 제한 없음 |

## 일정 관리: CPM과 PERT

### CPM (Critical Path Method, 임계 경로법)

- 프로젝트 내 **가장 긴 경로** = 임계 경로
- 임계 경로 상의 작업 지연 = 전체 일정 지연
- 여유 시간(Slack Time) = 0

### PERT (Program Evaluation and Review Technique)

3점 추정법을 사용합니다:

```
기대 시간 = (낙관치 + 4 × 최빈값 + 비관치) / 6
```

| 구분 | 설명 |
|------|------|
| 낙관치(O) | 모든 것이 잘 풀릴 경우 |
| 비관치(P) | 최악의 경우 |
| 최빈값(M) | 가장 가능성 높은 시간 |

---

## WBS (Work Breakdown Structure)

프로젝트를 계층적으로 분해한 작업 구조도입니다.

- 목적: 프로젝트 범위 명확화, 작업 식별
- 최하위 단위: 작업 패키지(Work Package)

---

## 위험 관리 (Risk Management)

| 단계 | 설명 |
|------|------|
| 위험 식별 | 잠재적 위험 목록 작성 |
| 위험 분석 | 발생 확률 및 영향도 평가 |
| 위험 계획 | 대응 전략 수립 |
| 위험 모니터링 | 지속적 추적 및 관리 |

### 위험 대응 전략

| 전략 | 설명 |
|------|------|
| 회피(Avoidance) | 위험을 일으키는 활동 제거 |
| 전가(Transfer) | 위험을 제3자에게 이전 (보험, 외주) |
| 완화(Mitigation) | 발생 확률 또는 영향 감소 |
| 수용(Acceptance) | 위험 발생 시 결과 수용 |

---

## 핵심 정리

- COCOMO: LOC 기반 비용 산정 / 기본-중간-발전
- CPM: 임계 경로 = 여유 시간 0인 경로
- PERT: 기대시간 = (O + 4M + P) / 6
- 위험 대응: 회피, 전가, 완화, 수용
