## 객체지향의 4대 특성

| 특성 | 설명 |
|------|------|
| 캡슐화(Encapsulation) | 데이터와 메서드를 하나의 단위로 묶고 내부를 숨김 |
| 상속(Inheritance) | 부모 클래스의 속성·메서드를 자식 클래스가 물려받음 |
| 다형성(Polymorphism) | 동일 인터페이스로 다양한 형태 동작 가능 |
| 추상화(Abstraction) | 공통 특성만 추출하여 복잡성 감소 |

---

## 오버로딩 vs 오버라이딩

| 구분 | 오버로딩(Overloading) | 오버라이딩(Overriding) |
|------|----------------------|----------------------|
| 위치 | 같은 클래스 내 | 상속 관계의 자식 클래스 |
| 조건 | 메서드명 동일, 매개변수 다름 | 메서드명·매개변수 모두 동일 |
| 다형성 | 컴파일 타임 다형성 | 런타임 다형성 |

---

## SOLID 원칙

| 약자 | 원칙 | 설명 |
|------|------|------|
| S | 단일 책임 원칙(SRP) | 클래스는 하나의 책임만 가져야 함 |
| O | 개방-폐쇄 원칙(OCP) | 확장에 열려 있고 수정에 닫혀 있어야 함 |
| L | 리스코프 치환 원칙(LSP) | 자식 클래스는 부모 클래스를 대체 가능해야 함 |
| I | 인터페이스 분리 원칙(ISP) | 클라이언트에 필요한 인터페이스만 제공 |
| D | 의존 역전 원칙(DIP) | 고수준 모듈이 저수준 모듈에 의존하지 않아야 함 |

## GoF 디자인 패턴

### 생성 패턴 (Creational)

| 패턴 | 설명 |
|------|------|
| 싱글톤(Singleton) | 클래스 인스턴스가 오직 하나만 존재 |
| 팩토리 메서드(Factory Method) | 객체 생성을 서브클래스에 위임 |
| 추상 팩토리(Abstract Factory) | 관련 객체 집합을 일관된 방식으로 생성 |
| 빌더(Builder) | 복잡한 객체를 단계별로 생성 |
| 프로토타입(Prototype) | 기존 객체를 복사하여 생성 |

### 구조 패턴 (Structural)

| 패턴 | 설명 |
|------|------|
| 어댑터(Adapter) | 호환되지 않는 인터페이스 연결 |
| 데코레이터(Decorator) | 객체에 동적으로 기능 추가 |
| 파사드(Facade) | 복잡한 서브시스템에 단순한 인터페이스 제공 |
| 프록시(Proxy) | 대상 객체에 대한 접근 제어 |

### 행위 패턴 (Behavioral)

| 패턴 | 설명 |
|------|------|
| 옵저버(Observer) | 상태 변화 시 의존 객체에 자동 알림 |
| 전략(Strategy) | 알고리즘을 캡슐화하여 교체 가능하게 함 |
| 커맨드(Command) | 요청을 객체로 캡슐화 |
| 이터레이터(Iterator) | 컬렉션 순회를 표준화 |
| 템플릿 메서드(Template Method) | 알고리즘 구조 정의 후 세부 단계를 서브클래스에 위임 |

---

## 핵심 정리

- 오버로딩: 같은 클래스, 매개변수 다름 (컴파일 타임)
- 오버라이딩: 상속 관계, 완전히 동일한 시그니처 (런타임)
- 싱글톤: 인스턴스 1개만 / 팩토리: 객체 생성 위임
- 옵저버: 상태 변화 알림 / 전략: 알고리즘 교체
