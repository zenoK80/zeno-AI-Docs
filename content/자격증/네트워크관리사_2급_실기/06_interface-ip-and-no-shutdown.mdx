## 0. 실기에서 가장 자주 나오는 라우터 문제

기출 8회분에서 라우터 3문항 중 최소 한 문항은 거의 언제나 인터페이스 IP 설정입니다.

| 회차 | 인터페이스 | 요구된 IP | 특이사항 |
|------|-----------|----------|---------|
| 2023-1 | FastEthernet 0/0 | 192.168.1.1 / 255.255.255.0 | 기본형 |
| 2023-3 | FastEthernet 0/0 | 192.168.10.1 / 255.255.255.0 | 기본형 |
| 2023-4 | GigabitEthernet 0/0 | 192.168.1.1 주 IP, 192.168.2.1 보조 IP | secondary |
| 2024-2 | Serial 0/0 | 192.168.100.1 / 255.255.255.0 | 시리얼 포트 |
| 2024-3 | FastEthernet 0/0 | 192.168.10.1/24 | 정적 라우팅과 결합 |
| 2026-3 | FastEthernet 0/0 | 192.168.10.100 주, 192.168.10.101 보조 | secondary |

이 표에서 세 가지 사실을 읽어야 합니다.

1. **인터페이스 이름이 회차마다 다릅니다.** FastEthernet, GigabitEthernet, Serial이 번갈아 나옵니다.
2. **보조 IP 문제가 두 번이나 나왔습니다.** `secondary` 키워드를 반드시 알아야 합니다.
3. **모든 정답에 `no shutdown`과 저장 명령이 붙어 있습니다.**

## 1. 인터페이스 이름 읽는 법

### 이름은 속도와 위치를 담고 있다

인터페이스 이름은 **종류 + 슬롯/포트 번호** 구조입니다.

| 이름 | 뜻 | 속도 | 축약 |
|------|-----|------|------|
| Ethernet 0/0 | 이더넷 | 10Mbps | `e0/0` |
| FastEthernet 0/0 | 빠른 이더넷 | 100Mbps | `f0/0` 또는 `fa0/0` |
| GigabitEthernet 0/0 | 기가비트 이더넷 | 1Gbps | `g0/0` 또는 `gi0/0` |
| TenGigabitEthernet 0/0 | 10기가 이더넷 | 10Gbps | `te0/0` |
| Serial 0/0/0 | 직렬 (WAN 회선) | 회선 계약에 따름 | `s0/0/0` |

슬래시로 나뉜 숫자의 의미는 이렇습니다.

- `0/0` — 앞이 **슬롯**(slot, 장비에 꽂힌 모듈 자리) 번호, 뒤가 그 슬롯 안의 **포트** 번호
- `0/3/0` — 앞이 슬롯, 가운데가 **서브슬롯**(모듈 안의 카드 자리), 뒤가 포트

2026년 3회 기출에 나온 `Serial 0/3/0`이 세 칸짜리 예입니다. 숫자를 하나라도 빼면 다른 포트가 되어 버립니다.

> **쉽게 말하면:** 인터페이스 이름은 "몇 번 서랍, 몇 번 칸, 몇 번째 구멍"이라는 주소입니다. 하나만 틀려도 엉뚱한 구멍입니다.

**자주 틀리는 점:** 문제지에 `GigabitEthernet 0/0`이라 되어 있는데 손에 익은 `fastethernet 0/0`을 입력하는 실수가 가장 흔합니다. **문제지의 이름을 눈으로 다시 확인**한 뒤 입력하십시오.

### 인터페이스 목록 확인하기

어떤 인터페이스가 있는지 모르겠다면 특권 모드에서 이 명령을 칩니다.

```text
Router# show ip interface brief
```

출력은 이런 형태입니다.

```text
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0     unassigned      YES unset  administratively down down
GigabitEthernet0/1     unassigned      YES unset  administratively down down
Serial0/0/0            unassigned      YES unset  administratively down down
```

- **Interface**: 인터페이스 이름. 여기 적힌 이름이 정답의 기준입니다.
- **IP-Address**: 설정된 IP. `unassigned`는 아직 없다는 뜻입니다.
- **Status**: 물리 계층 상태 (1계층)
- **Protocol**: 데이터링크 계층 상태 (2계층)

## 2. IP 주소 설정 — 명령 한 줄의 해부

### 기본 문법

```text
Router(config-if)# ip address 192.168.1.1 255.255.255.0
```

이 한 줄은 세 부분입니다.

- `ip address` — 명령어 본체
- `192.168.1.1` — 이 인터페이스에 부여할 IP 주소
- `255.255.255.0` — 서브넷 마스크

**시험에서 가장 중요한 형식 규칙:** 서브넷 마스크는 **점 십진 표기로 풀어서** 씁니다. 시스코 IOS의 `ip address` 명령은 `/24` 같은 CIDR 표기를 받지 않습니다.

| 문제에 적힌 표기 | 실제로 입력할 값 |
|----------------|----------------|
| 192.168.10.1/24 | `ip address 192.168.10.1 255.255.255.0` |
| 192.168.1.1/25 | `ip address 192.168.1.1 255.255.255.128` |
| 210.100.100.14/28 | `ip address 210.100.100.14 255.255.255.240` |
| 200.10.10.1/30 | `ip address 200.10.10.1 255.255.255.252` |

2024년 3회 기출은 "FastEthernet 0/0 IP: 192.168.10.1/24"라고 CIDR로 제시했고, 정답 명령은 `ip address 192.168.10.1 255.255.255.0`이었습니다. **변환은 응시자 몫**입니다. 01편에서 익힌 계산이 여기서 바로 쓰입니다.

### 전체 명령 흐름

<Steps>

### 1단계 — 특권 모드로 올라간다

```text
Router> enable
```

### 2단계 — 전역 설정 모드로 들어간다

```text
Router# configure terminal
```

### 3단계 — 대상 인터페이스로 진입한다

```text
Router(config)# interface fastethernet 0/0
```

프롬프트가 `Router(config-if)#`로 바뀝니다. 이 변화를 답안에도 반영해야 합니다.

### 4단계 — IP와 마스크를 넣는다

```text
Router(config-if)# ip address 192.168.1.1 255.255.255.0
```

### 5단계 — 인터페이스를 활성화한다

```text
Router(config-if)# no shutdown
```

이 줄이 없으면 IP는 설정되지만 포트가 꺼진 채로 남습니다.

### 6단계 — 특권 모드로 복귀한다

```text
Router(config-if)# exit
Router(config)# exit
```

### 7단계 — 저장한다

```text
Router# copy running-config startup-config
```

</Steps>

전체를 이어 붙이면 이렇습니다. 2023년 1회 기출 16번의 정답 그대로입니다.

```text
Router> enable
Router# configure terminal
Router(config)# interface fastethernet 0/0
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# exit
Router# copy running-config startup-config
```

## 3. no shutdown — 왜 이 줄이 없으면 안 되는가

### 시스코 라우터의 기본값

시스코 **라우터**의 인터페이스는 공장 초기 상태에서 **꺼져 있습니다**(shutdown). 반면 시스코 **스위치**의 포트는 기본적으로 켜져 있습니다. 이 차이가 실기 감점의 단골 원인입니다.

> **쉽게 말하면:** 라우터의 포트는 기본이 "잠긴 문"입니다. IP를 붙여 놓아도 문이 잠겨 있으면 아무도 드나들 수 없습니다.

왜 이렇게 만들었을까요? 라우터는 회사와 외부를 잇는 관문입니다. 설정이 끝나지 않은 포트가 저절로 켜져 외부와 연결되면 위험합니다. 그래서 **관리자가 명시적으로 켜라고 말할 때까지 꺼 둡니다.**

### 명령의 정체

IOS에서 어떤 설정을 취소할 때는 그 명령 앞에 `no`를 붙입니다.

| 명령 | 뜻 |
|------|-----|
| `shutdown` | 인터페이스를 끈다 |
| `no shutdown` | 끄기를 취소한다, 즉 켠다 |
| `ip address 1.1.1.1 255.0.0.0` | IP를 설정한다 |
| `no ip address` | IP 설정을 지운다 |

`no shutdown`은 흔히 `no shut`으로 축약합니다. **답안에는 정식 표기인 `no shutdown`을 쓰십시오.**

### 실행 후 나타나는 메시지

`no shutdown`을 치면 몇 초 뒤 이런 로그가 뜹니다.

```text
%LINK-5-CHANGED: Interface FastEthernet0/0, changed state to up
%LINEPROTO-5-UPDOWN: Line protocol on Interface FastEthernet0/0, changed state to up
```

두 줄이 모두 `up`으로 뜨면 정상입니다. 첫 줄은 1계층(전기적 연결), 둘째 줄은 2계층(프로토콜)이 살아났다는 뜻입니다.

**자주 틀리는 점:** 이 로그가 입력 중인 명령 줄 사이에 끼어들어 화면이 지저분해집니다. 당황해서 명령을 다시 치면 오히려 꼬입니다. 엔터를 한 번 누르고 프롬프트를 확인한 뒤 이어가면 됩니다.

## 4. 보조 IP 설정 — secondary

### 왜 필요한가

한 인터페이스에 두 개 이상의 IP 대역을 붙여야 할 때가 있습니다. 예를 들어 한 층에 원래 `192.168.1.0/24`를 쓰던 사무실이 있는데, 주소가 모자라 `192.168.2.0/24`를 추가로 쓰고 싶지만 라우터 포트는 하나뿐인 상황입니다.

이때 같은 물리 포트에 두 번째 대역을 얹는 것이 **보조 IP**(secondary IP)입니다.

> **쉽게 말하면:** 한 대문에 두 개의 문패를 다는 것입니다. 어느 문패로 찾아와도 같은 집으로 들어옵니다.

### 문법과 순서

```text
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# ip address 192.168.2.1 255.255.255.0 secondary
```

**순서가 결정적입니다.**

- 먼저 입력한, `secondary`가 없는 줄이 **주 IP**(primary)가 됩니다.
- 뒤에 `secondary`를 붙인 줄이 보조 IP입니다.
- 만약 `secondary` 없이 두 번째 IP를 입력하면, **첫 번째 IP가 조용히 교체됩니다.** 추가가 아니라 덮어쓰기입니다.

**자주 틀리는 점:** 두 번째 줄에 `secondary`를 빠뜨리는 실수입니다. 오류 메시지도 없이 주 IP가 사라지므로 알아채기도 어렵습니다. 보조 IP 문제를 만나면 `secondary` 다섯 글자를 먼저 종이에 적어 두십시오.

### 기출 완성 답안

2023년 4회 기출 17번(GigabitEthernet 0/0에 주 192.168.1.1/24, 보조 192.168.2.1/24)입니다.

```text
Router> enable
Router# configure terminal
Router(config)# interface gigabitethernet 0/0
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# ip address 192.168.2.1 255.255.255.0 secondary
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# exit
Router# copy running-config startup-config
```

2026년 3회 기출 17번(FastEthernet 0/0에 주 192.168.10.100/24, 보조 192.168.10.101/24)입니다.

```text
Router> enable
Router# configure terminal
Router(config)# interface fastethernet 0/0
Router(config-if)# ip address 192.168.10.100 255.255.255.0
Router(config-if)# ip address 192.168.10.101 255.255.255.0 secondary
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# exit
Router# copy running-config startup-config
```

두 기출의 구조가 완전히 같다는 점에 주목하십시오. **인터페이스 이름과 IP 값만 바뀝니다.** 뼈대를 통째로 외워 두면 실전에서 값만 갈아 끼우면 됩니다.

## 5. 시리얼 인터페이스의 특수 사항

### clock rate — 시리얼 구간의 박자

시리얼 회선은 두 라우터를 직접 잇는 WAN 링크로, 한쪽이 **박자를 만들어 줘야** 통신이 됩니다. 박자를 만드는 쪽을 **DCE**(Data Circuit-terminating Equipment), 받는 쪽을 **DTE**(Data Terminal Equipment)라고 합니다.

실습 환경에서 케이블의 DCE 쪽에 연결된 라우터에는 이 명령이 필요합니다.

```text
Router(config-if)# clock rate 64000
```

숫자 64000은 초당 비트 수(bps)입니다. **실제 시험에서는 요구되지 않는 경우가 많지만**, 시뮬레이터로 연습할 때 시리얼 링크가 살아나지 않는다면 이 명령을 의심하십시오.

### 기출 답안 — Serial 0/0

2024년 2회 기출 17번입니다.

```text
Router> enable
Router# configure terminal
Router(config)# interface serial 0/0
Router(config-if)# ip address 192.168.100.1 255.255.255.0
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# exit
Router# copy running-config startup-config
```

이더넷과 명령 구조가 똑같습니다. 인터페이스 이름만 `serial 0/0`으로 바뀌었을 뿐입니다.

## 6. 상태 확인 — up과 down 조합 읽기

설정을 마쳤으면 확인합니다.

```text
Router# show ip interface brief
```

```text
Interface              IP-Address      OK? Method Status                Protocol
FastEthernet0/0        192.168.1.1     YES manual up                    up
FastEthernet0/1        unassigned      YES unset  administratively down down
```

**Status**(1계층)와 **Protocol**(2계층) 두 열의 조합이 진단표입니다.

| Status | Protocol | 상태 해석 | 원인과 조치 |
|--------|----------|----------|-----------|
| up | up | 완전 정상 | 조치 불필요 |
| up | down | 선은 연결됐으나 2계층 협상 실패 | 캡슐화 방식 불일치, 시리얼의 clock rate 누락 |
| down | down | 물리적 연결 없음 | 케이블 미연결, 케이블 불량, 상대 포트가 꺼짐 |
| administratively down | down | 관리자가 꺼 놓음 | `no shutdown` 미실행. 실기 최대 감점 원인 |

> **쉽게 말하면:** `administratively down`은 "고장이 아니라 사람이 꺼 놨다"는 뜻입니다. 이 글자를 보면 곧바로 `no shutdown`을 떠올리십시오.

**Method** 열도 알아 두면 좋습니다. `manual`은 손으로 직접 설정했다는 뜻, `DHCP`는 자동으로 받았다는 뜻, `unset`은 아직 설정이 없다는 뜻입니다.

### 더 자세히 보기

```text
Router# show interfaces fastethernet 0/0
```

이 명령은 해당 인터페이스의 MAC 주소, MTU, 대역폭, 오류 통계까지 보여 줍니다. **MTU**(Maximum Transmission Unit, 최대 전송 단위)는 한 번에 보낼 수 있는 최대 크기로 이더넷의 기본값은 1500바이트입니다.

```text
Router# show running-config interface fastethernet 0/0
```

이 명령은 해당 인터페이스에 들어간 설정만 뽑아 보여 줍니다. 답안을 제출하기 전 검산에 유용합니다.

## 7. 문제 유형별 답안 뼈대 정리

시험장에서 바로 꺼내 쓸 수 있게 뼈대를 정리합니다.

### 뼈대 A — 인터페이스 IP 설정과 활성화

```text
Router> enable
Router# configure terminal
Router(config)# interface [인터페이스이름] [번호]
Router(config-if)# ip address [IP주소] [서브넷마스크]
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# exit
Router# copy running-config startup-config
```

### 뼈대 B — 주 IP와 보조 IP

```text
Router> enable
Router# configure terminal
Router(config)# interface [인터페이스이름] [번호]
Router(config-if)# ip address [주IP] [마스크]
Router(config-if)# ip address [보조IP] [마스크] secondary
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# exit
Router# copy running-config startup-config
```

### 답안 제출 전 자가 점검 목록

| 점검 항목 | 확인 방법 |
|----------|----------|
| 인터페이스 이름이 문제지와 같은가 | 문제지 글자와 한 글자씩 대조 |
| 서브넷 마스크를 점 십진으로 풀었는가 | 슬래시 표기가 남아 있지 않은지 확인 |
| `no shutdown`을 넣었는가 | 인터페이스 모드 안에 있는지 확인 |
| 보조 IP에 `secondary`가 붙었는가 | 해당 문제일 때만 |
| 저장 명령이 특권 모드에 있는가 | 프롬프트가 우물 정 기호로 끝나는지 확인 |

## 핵심 정리

- 인터페이스 이름은 종류와 슬롯·포트 번호로 이루어지며, 문제지의 표기를 그대로 입력해야 한다.
- `ip address` 명령은 CIDR 표기를 받지 않는다. `/24`는 반드시 255.255.255.0으로 풀어서 입력한다.
- 시스코 라우터의 인터페이스는 기본이 꺼진 상태이므로 `no shutdown`이 없으면 IP를 넣어도 동작하지 않는다.
- 보조 IP는 두 번째 `ip address` 줄 끝에 `secondary`를 붙인다. 빠뜨리면 주 IP가 조용히 덮어써진다.
- `show ip interface brief`의 Status와 Protocol 조합으로 상태를 진단한다. `administratively down`은 `no shutdown` 누락 신호다.
- 모든 답안의 마지막 줄은 특권 모드에서의 `copy running-config startup-config`다.
