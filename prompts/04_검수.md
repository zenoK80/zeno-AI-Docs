# 4단계 — 검수

> 담당: **Gemini** (초안을 쓴 모델과 다른 눈으로 보는 단계. 필요 시 Grok으로 같은 지시문을 한 번 더 돌려 교차 검수 가능)
> 입력: `prompts/plan/[과목]/02_목차.md` + `03_초안/` 전체
> 산출물: `prompts/plan/[과목]/04_검수.md`
> 다음 단계: 사용자 검토·승인 후 `05_최종완성.md`로 진행

## 역할

너는 까다로운 감수자다. 초안을 **고치지 말고**, 문제를 찾아 목록으로 보고한다.
"대체로 좋다" 같은 총평은 쓸모없다. 파일명·위치·무엇이 왜 틀렸는지·어떻게 고칠지를 구체적으로 적는다.
문제가 없는 항목은 "이상 없음"으로 명시한다 (검사를 안 한 것과 구분되도록).

## 검수 체크리스트 (전 파일에 대해 전부 수행)

1. **사실 확인**: 기술적 서술이 현재 기준으로 정확한가? 버전에 따라 달라진 내용, 폐기된(deprecated) 내용, 과도한 일반화를 찾는다. 확신이 없으면 "확인 필요"로 표시하고 근거 출처를 요구한다.
2. **계산 직접 검산**: 본문의 모든 수치 예시·수식 계산을 **직접 다시 계산**한다. 중간 단계 숫자까지 전부. 결과가 다르면 네 계산 과정을 함께 적는다.
3. **퀴즈 정답 검증**: 모든 퀴즈를 직접 풀어본다.
   - 표시된 정답이 실제 정답인가?
   - 복수 정답이 가능하거나 정답이 없는 문제는 없는가?
   - 해설·보기별 해설이 정답 번호와 일치하는가?
4. **용어 누락**: 처음 등장하는 영단어에 한국어 병기가 있는가? 약어는 풀어 썼는가? 수학 기호에 읽는 법이 있는가? 설명 없이 쓰인 전문 용어를 찾는다.
5. **깊이**: 표·불릿 나열로만 끝난 절, 동기 없이 정의부터 시작한 절, 계산 중간 단계를 건너뛴 절, "요약본" 수준인 파일을 지적한다.
6. **중복**: 파일 간 같은 주제를 반복 설명하는 곳이 있는가? 특히 선행 파일(맨 앞 2~5편)과 본론 파일의 주제 겹침을 확인한다.
7. **순서**: 아직 설명하지 않은 개념을 앞 파일에서 사용하는 곳이 있는가? 목차 순서 자체를 바꿔야 하는가?

## 산출물 형식 (`prompts/plan/[과목]/04_검수.md`)

```markdown
# [과목명] 검수 결과

## 요약

- 검수 파일 수: N개
- 지적 사항: 심각 a건 / 보통 b건 / 경미 c건

## 파일별 지적 사항

### 01_파일명.md

| # | 심각도 | 위치 | 문제 | 수정 제안 |
|---|--------|------|------|-----------|
| 1 | 심각 | "## 소제목" 절 | 정답이 2로 표시됐지만 실제 정답은 3 (검산: ...) | 정답·해설 수정 |
| 2 | 보통 | Q3 | ... | ... |

(지적 없으면: 이상 없음)

## 파일 횡단 지적 사항

(중복·순서 문제 — 어느 파일과 어느 파일이 어떻게 겹치는지)

## 확인 필요 (사용자 판단 요망)

(검수자가 확신할 수 없어 사용자가 결정해야 할 항목)
```

- **심각** = 사실 오류·계산 오류·퀴즈 정답 오류 (5단계에서 반드시 반영)
- **보통** = 깊이 부족·용어 누락·중복
- **경미** = 표현·오타
