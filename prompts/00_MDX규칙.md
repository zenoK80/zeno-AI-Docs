# 공통 — MDX 작성 규칙 (3단계 본문 작성·5단계 보강 모두 필수 준수)

이 문서는 MDX 파일을 생성·수정하는 모든 단계에 system 프롬프트로 함께 제공된다.
어기면 빌드가 깨지거나 렌더링이 깨진다.

## MDX 파일 구조

```mdx
---
title: 'NN. 제목'
description: '한 줄 설명'
---

<Callout type="info">
  **이번 문서의 목표:** 이 파일을 다 읽으면 무엇을 할 수 있는지 한 문장.
</Callout>

## 소제목

> **쉽게 말하면:** 개념 한 줄 요약.

[본문]

## 핵심 정리

[3~5줄 불릿]

## 마무리 복습

<Quiz ... /> (일반 편 5~8개, 기출·모의 편 15~25개)

## 참고 자료

- [자료 이름](URL)
```

- frontmatter는 `title`, `description`만.
- **모든 파일은 반드시 `## 참고 자료` 섹션으로 끝난다** (실제 참고한 링크만, 최소 1개, 링크 필수).
- 기출·모의 편은 본문 대신 `<Callout type="warning">`(기출 복제 아님 고지) + Quiz 15~25개 + 참고 자료.
- 컴포넌트는 전역 등록되어 있으므로 **import 문을 쓰지 않는다.**

## 컴포넌트 사용 기준

- 값을 바꿔가며 결과를 관찰할 가치가 있는 JS·React 예제 → `<CodePlayground>`. 단순 문법 표시는 정적 코드블록 유지.
- 흐름·관계·계층 → ` ```mermaid ` 코드펜스 (내장, import 불필요). 사용자가 노드를 직접 움직여야 의미 있을 때만 `ConceptFlow`.
- 데이터 비교 → `DataBarChart`, 단계 과정 → `Steps`. 억지로 넣지 않는다.

## Quiz 컴포넌트 규칙

```mdx
<Quiz
  questionNumber={1}
  question="문제 내용"
  options={['①보기1', '②보기2', '③보기3', '④보기4']}
  correctAnswer={2}
  explanation="정답 근거와 오답 이유"
  optionExplanations={['오답 이유', '정답 근거', '오답 이유', '오답 이유']}
/>
```

- `correctAnswer`: **1-indexed** 정수 (1~4)
- `question`, `explanation`: **큰따옴표**로 감싼다
- `options`, `optionExplanations` 배열 원소: **작은따옴표**로 감싼다. **원소 안에 작은따옴표 절대 금지**
- 해설은 정답 근거와 각 오답이 틀린 이유를 함께 설명

## CodePlayground 규칙

```mdx
<CodePlayground
  template="react"
  activeFile="/App.js"
  showConsole
  label="설명"
  files={{
    '/App.js': `코드...`,
  }}

```

- `template`: `"vanilla"` 또는 `"react"`
- 코드 안에서 JS 템플릿 리터럴이 필요하면 백틱은 `` \` ``, 달러중괄호는 `\${`로 **이스케이프**한다

## MDX 금지 규칙 (어기면 빌드 또는 렌더링이 깨짐)

### 1. JSX prop 배열 원소 안 작은따옴표 금지 (빌드 에러)

```mdx
❌ options={['변수를 'let'으로 선언한다']}
✅ options={['변수를 let으로 선언한다']}
```

### 2. 볼드가 문장부호로 끝나고 바로 글자가 오면 금지 (렌더링 깨짐 — 빌드는 통과함)

닫는 `**` 바로 앞이 문장부호(`)` `"` `%` `.` 등)이고 바로 뒤에 글자가 붙으면, CommonMark가 그 `**`를 닫는 기호로 인정하지 않아 볼드 전체가 `**텍스트**` 그대로 노출된다.
(실측 검증: insight/01_mdx-볼드-렌더링-깨짐.md)

```mdx
❌ **용어(English)**입니다      ❌ **"인용문"**이라는      ❌ **약 8.8%**에
✅ **용어**(English)입니다      ✅ "**인용문**"이라는      ✅ 약 **8.8퍼센트**(8.8%)에
```

괄호가 볼드 **안에** 있는 것 자체는 문제가 아니다. `**용어(English)** 뒤에 공백`은 정상이고, `**용어**입니다`처럼 문장부호 없이 끝나고 조사가 붙는 것도 정상이다. 문제는 **문장부호 + 바로 글자** 조합뿐이다.

### 3. 표 셀 안 `~`·raw `*` 금지 (빌드 에러)

서로 다른 셀의 `~`가 취소선 쌍으로, 셀 안 `*` 하나가 emphasis로 오인되어 빌드가 깨진다.
범위는 **en dash(`–`)**, 기호 자체는 **백틱 코드 스팬**으로.

```mdx
❌ <tr><td>0~2</td><td>2~4</td></tr>     ✅ <tr><td>0–2</td><td>2–4</td></tr>
❌ <tr><td>*</td><td>0개 이상</td></tr>   ✅ <tr><td>`*`</td><td>0개 이상</td></tr>
```

### 4. JSX prop 안 `<`, `>` 금지 (빌드 에러)

백틱으로 감싸도 소용없다 — prop 문자열 자체가 JSX 파서를 거친다. HTML entity(`&lt;` `&gt;`)를 쓰거나 꺾쇠 없이 표현한다.

```mdx
❌ question="T<string>이란?"           ❌ question="`<h1>제목</h1>`은?"
✅ question="T&lt;string&gt;이란?"     ✅ question="제네릭 T(string)이란?"
```

### 5. 산문(코드블록 밖)에 raw `{`, `}`, `<`, `>` 금지 (빌드 에러)

`{}`는 JSX 표현식으로, `<>`는 태그로 해석된다. 인라인 코드 스팬으로 감싸거나 괄호로 바꾼다.

```mdx
❌ 프로세스 ID는 {pid}로 확인합니다.     ✅ 프로세스 ID는 `{pid}`로 확인합니다.
❌ 0.0.0.0 ~ 255.255.255.255 <클래스 A>  ✅ 0.0.0.0 ~ 255.255.255.255 (클래스 A)
```

### 6. 큰따옴표 prop 안 `\"` 이스케이프 금지 (빌드 에러)

```mdx
❌ explanation="브라우저에서 \"module\" 속성이 필요합니다."
✅ explanation="브라우저에서 module 속성이 필요합니다."
```

### 7. 수식 한 줄에 `\quad`로 여러 계산 금지 (모바일 가로 스크롤)

```mdx
❌ $$\bar{x} = \frac{10+20+30}{3} = 20, \quad \bar{y} = \frac{60+90}{3} = 50$$

✅ $$
   \bar{x} = \frac{10+20+30}{3} = 20
   $$

   $$
   \bar{y} = \frac{60+90}{3} = 50
   $$
```

수식 바로 아래에는 각 변수의 뜻을 항목별로 쓴다.
